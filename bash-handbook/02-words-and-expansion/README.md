# 一行命令被切成几段：引号、`${}`、IFS、通配

> 这一章只回答一件事：**你敲进去的那一行，bash 在执行前把它切成了几段、每段变成了什么。**
> 下面每一段带 `$ ` 的输出都是这台机器（bash 5.3.9(1)-release，Ubuntu 26.04 LTS）上真实跑出来的，
> 出自同一次 `bash demo.sh > ~/.cache/handbook-captures/bash02.txt 2>&1`（1017 行，退出码 0）。
> 每次会变的只有**进程号**和 `mktemp` 的沙箱目录名 `/tmp/bash02-XXXXXX`，其余逐字一致。
> 本章是第 03 章（条件测试与 `[[ ]]`）和第 04 章（循环、函数、重定向）的前提，
> 因为那两章里 90% 的「为什么这里要加引号」都靠这里解释。

---

## 你会遇到的场景

先对上号，下面这些是不是你的现场：

1. `rm *.tmp` 一个文件都没删掉，却抱怨 `rm: cannot remove '*.tmp': No such file or directory`；
   你以为是 `rm` 坏了，其实是 `*.tmp` 没匹配上、被原样交给了 `rm`。
2. `for f in $(ls)` 遇到 `my file.txt` 这种合法文件名，就把它当成两个文件 `my` 和 `file.txt`，
   两个都不存在 —— 而且**一行报错都没有**。
3. 把命令存进变量再执行：`cmd="bash seg.sh \"a b\" c"; $cmd`，结果程序收到的第一个参数是 `"a`
   —— 引号变成了内容的一部分。
4. `echo $dir/*.txt` 目录里有文件时正常，目录空的时候把字面的 `*.txt` 传给了后面的程序。
5. `${v#*.}` 和 `${v##*.}`、`${v%.*}` 和 `${v%%.*}` 四个长得一样，分不清哪个是哪个；
   `${v%%/*}` 用在 `/tmp/a/b` 上给你一个空字符串。
6. `${v: -3}` 少打一个空格变成 `${v:-3}`，语义从「取后三个字符」滑成「v 没设就用 3」，且不报错。
7. `"$@"` 和 `"$*"` 背了无数遍还是写错，函数转发参数时时有「少了一个」的幽灵。
8. 变量名打错一个字母（`$TARGET_DI`），脚本不报错，安安静静把空字符串传下去。
9. `((i++))` 让开了 `set -e` 的脚本在 `i=0` 时当场退出，而 `((++i))` 不会。

这 9 个现场不是 9 个知识点，它们是**同一台机器的 9 个出口**。这台机器就是下面那张图。

## 一句话版本

> **bash 先把「你写的那些字符」切成语法上的词，再把每个词里的 `$`、反引号、花括号、通配符换成别的东西，
> 换出来的新内容还要再过一遍「按空格切」和「问文件系统有没有这个文件」两道手续，最后才交命令执行。
> 引号的作用不是「标记一段文本」，而是「让这块内容跳过后面那两道手续」。**

所以本章所有问题都只有一个问法：**「这一步之后，还剩几个词？」**
demo 里的 `seg.sh` 就是专门回答这句话的量尺 —— 它只打印「我拿到几个参数、每个是什么」。

- **带 `$ ` 开头的代码块 = 本机实跑原文**，一字不改地抄自那一次捕获；块里最后一行
  `[退出码 N]` 是 demo 自己打的总结，不是 shell 的输出。
- **不带 `$ ` 的代码块 = 讲解用的片段**（伪代码、结构图、或者你在别处会敲的写法），没在这一章跑过。
- 个别说法是写 demo 之前的**补测**（同一台机器当场跑过，但没进那 1017 行的捕获）：
  出现的地方会写明「补测」。补测清单在文末「本章没演 / 没验证」里逐条列了命令和结果。
- demo 里所有会写的操作都发生在 `mktemp -d "${TMPDIR:-/tmp}/bash02-XXXXXX"` 里，退出时 `trap` 删掉自己那一个；
  所以你在仓库里看不到任何中间文件（第 23 节用 `find` 自证）。
- 本章**不碰**你的 `~/.bashrc`、`~/.profile`、`/etc`，不改任何已有文件，不装任何包。
- 报错文本统一在 `LC_ALL=C.UTF-8` + `LANGUAGE=C` 下取证 —— 为什么要钉死，第 0 节有实测对比。
- 全书统一用 `printf` 不用 `echo`：这台机器上 `echo` 有三种实现（bash 内建、dash 内建、`/usr/bin/echo`），
  行为不一样（第 01 章实测）。本章只在复现「网上常见写法」时才用 `echo`，用的都是 bash 内建那一个。

## 心智模型：一行命令要过的六道工序

把 bash 想成一条流水线。你的命令行从左到右、按固定顺序过六道闸，每道闸都可能改变「词的个数」：

```text
你敲下：  rm $dir/*.tmp
   │
   │  源码层面先按空格、引号、运算符切成「语法词」：rm / $dir/*.tmp
   │
   ├─ 工序 1  花括号   {a,b} {1..9}
   │     只认你写在源码里的字面文本；最先做，且只做一次
   ├─ 工序 2  波浪线   ~ ~root
   │     只在词的首部、且没被引号包住时生效
   ├─ 工序 3  参数/命令/算术展开   $v  ${v#..}  $(..)  `..`  $((..))
   │     三兄弟同一轮做；重点是：它们的「结果」不是终点，还要继续往下走
   ├─ 工序 4  分词 word splitting   ← IFS 在这里登场
   │     拿 IFS（默认 空格+tab+换行）把工序 3 的结果**再切一刀**
   ├─ 工序 5  通配 filename globbing
   │     每个词里的 * ? [..] 去问文件系统：有匹配的文件吗？
   │     有 → 换成所有匹配（按 locale 给的顺序）；一个都没有 → 原样留着
   ├─ 工序 6  引号删除 quote removal
   │     把你写的引号本身抹掉；被引号保护过的内容，工序 4/5 直接跳过
   │
   └─ 最后才：第 1 个词拿去当命令名找（函数 → 内建 → PATH 里的外部命令），
              剩下的词原封不动作为参数递进去
```

三条推论，比图本身有用：

1. **引号加在「源码」上，不加在「值」里。** 变量值里的引号只是普通字符，它已经错过了工序 6，
   不会再被当语法（第 9 节实测：程序收到 `["a]`）。
2. **工序 3 的结果要再过工序 4 和 5。** 所以「值里有空格」和「值里有 `*`」是两类独立事故，
   都不是靠肉眼检查值能发现的（第 3、9 节）。
3. **花括号在工序 1，通配在工序 5。** 前者不需要文件存在，后者必须去问文件系统 —— 
   这就是 `mkdir {a,b}` 能建目录、`mkdir a*` 不能的原因（第 14 节）。

一张「谁在什么时候登场」的对照表（**每一行都能在 demo 第 2/3/14 节找到原文**）：

| 写法 | 需要文件真的存在吗 | 会被谁处理 | 没匹配上时的表现 |
|---|---|---|---|
| `{a,b}` | ❌ 不需要 | 工序 1 | 不存在「没匹配」这回事，照切 |
| `{1..9}` | ❌ 不需要 | 工序 1 | 变量插不进序列（实测 `{1..3}` 由 `$n` 造不出来） |
| `~/x`、`~root/x` | ❌ 不需要（只查家目录） | 工序 2 | 加引号就不换 |
| `$v`、`${v#..}`、`$(..)`、`$((..))` | ❌ 不需要 | 工序 3 | 变量没设 → 空字符串，不报错 |
| `*.txt`、`[a-z]x`、`?` | ✅ 必须去问文件系统 | 工序 5 | **原样留下字面量**（祸根） |
| `"..."` `'...'` `\x` | 与文件无关 | 工序 6 | 引号本身被删掉 |

### 第 00 节 · 先把这台机器的发言权确认一遍

本章讲的是 bash **自己**的规则，几乎不依赖外部命令，但有两件事必须先钉下来：
bash 的版本（关联数组、`${!prefix@}` 这些是版本相关的）和语言环境（决定报错长什么样）。

```
$ bash --version | head -1
GNU bash, version 5.3.9(1)-release (x86_64-pc-linux-gnu)
[退出码 0]

$ echo "demo 已把自己改成：LC_ALL=[$LC_ALL] LANG=[$LANG]（你原来的终端是 LANG=$ORIG_LANG，LC_ALL=$ORIG_LC_ALL）"
demo 已把自己改成：LC_ALL=[C.UTF-8] LANG=[C.UTF-8]（你原来的终端是 LANG=，LC_ALL=）
[退出码 0]

$ printf "默认 IFS = %q\n" "$IFS"
默认 IFS = $' \t\n'
[退出码 0]
```

第二行是 demo 开头那三句 `export` 的现场交代：方括号里 `C.UTF-8` 是改完之后的值，
后面那两个空的 `LANG=`、`LC_ALL=` 是**改之前**的环境。demo 用 `${LANG-（未设）}` 这种写法读它们，
结果打出来是空而不是「（未设）」—— 说明这台机器上跑 demo 时 `LANG` 是「设了但是空」，
而**不带冒号的短横只看设没设**（第 16 节那张表的活教材）。

`%q` 是 `printf` 的「可重新敲回终端」格式，它把默认的 `IFS` 显式写成三个字符：空格、制表符、换行。
**本章所有的「切」都默认对着这三个字符。**

然后是语言环境。这台机器的默认 locale 是 `zh_CN.UTF-8`，所以 bash 的报错默认是中文；
demo 在开头把自己钉成 `C.UTF-8`。同一条不存在的命令，三种环境下跑出来是这样：

```
$ nosuchcommand02
bash: line 1: nosuchcommand02: command not found
[退出码 127]

$ LANGUAGE= LC_ALL=zh_CN.UTF-8 LANG=zh_CN.UTF-8 bash -c nosuchcommand02
bash: 行 1: nosuchcommand02: 未找到命令
[退出码 127]

$ LC_ALL=zh_CN.UTF-8 LANG=zh_CN.UTF-8 bash -c nosuchcommand02
bash: line 1: nosuchcommand02: command not found
[退出码 127]
```

第二条就是你终端里中文报错的样子（`未找到命令`）。**第三条和第二条只差一个 `LANGUAGE=`，
却退回英文** —— 因为 demo 开头 `export` 了 `LANGUAGE=C`。本机实测的优先级是
**`LANGUAGE` 最先，其次 `LC_ALL`，最后 `LANG`**（空值按未设处理）。
这一点很实用：你在脚本里 `export LC_ALL=zh_CN.UTF-8` 却发现报错还是英文时，先 `echo $LANGUAGE`。

这也是本章取证为什么钉死在 `C.UTF-8`：报错文本固定，README 才能逐行核对；
否则同一份 README 在中文终端和英文终端「看起来不一样」。

```
$ command -v shellcheck || echo "shellcheck: 本机没有（本章只做实跑取证，不装它）"
shellcheck: 本机没有（本章只做实跑取证，不装它）
[退出码 0]
```

本机没有 `shellcheck`，所以本章**不引用任何静态检查结论**，全部靠实跑。

> ★ 结论 1：本章的规则是 **bash 5.3.9** 的实测结果；换版本（尤其换 dash）别照抄。
> ★ 结论 2：报错文本属于「环境」，不属于「语法」。取证前先固定 `LANGUAGE`/`LC_ALL`。

### 第 01 节 · 本章的量尺：`seg.sh` 把「到底几个词」直接打出来

后面每一节都要问「几个词」，所以先造一把尺子。`seg.sh` 里只有两句
（完整源码在章目录里，注释比代码长，值得读一遍）：

```bash
printf '参数个数=%d\n' "$#"
i=1
for a in "$@"; do
    printf '  %d: [%s]\n' "$i" "$a"
    i=$((i + 1))
done
```

关键在于：**它拿到几个词，完全由调用它的那个 shell 在把它调起来之前决定。**
它能看到的，就是 bash 最终递出去的那些参数 —— 这正是我们要观测的量。

```
$ bash seg.sh a b c
参数个数=3
  1: [a]
  2: [b]
  3: [c]
[退出码 0]

$ bash seg.sh "a b" c
参数个数=2
  1: [a b]
  2: [c]
[退出码 0]

$ bash seg.sh
参数个数=0
[退出码 0]

$ v="a b c"; bash seg.sh $v
参数个数=3
  1: [a]
  2: [b]
  3: [c]
[退出码 0]

$ v="a b c"; bash seg.sh "$v"
参数个数=1
  1: [a b c]
[退出码 0]
```

最后两条**只差一对引号**：一条 3 个词、一条 1 个词。整章就是这一件事的展开。
注意 `[ ]` 的作用：`[a b]` 是一个词里面有空格，`[a][b]` 是两个词 —— 视觉上不允许你骗自己。

> ★ 结论：任何「参数个数不对」的 bug，都可以用 `printf '[%s]\n' "$@"` 这类尺子在**被调方**量一次，
> 立刻区分「是我切多了」还是「是你没接住」。

### 第 02 节 · 展开的顺序：一行命令把六步全撞出来

与其背顺序表，不如把六种写法塞进同一行 `echo`，让输出自己交代：

```
$ mkdir -p dir; touch dir/one.txt dir/two.txt; v=dir; echo ~root/x {a,b} $v/*.txt $(printf CMD) *.nope "a b" $v
/root/x a b dir/one.txt dir/two.txt CMD *.nope a b dir
[退出码 0]
```

逐字读法（左边是你写的，右边是实际递出去的）：

| 你写的 | 输出里变成 | 说明了什么 |
|---|---|---|
| `~root/x` | `/root/x` | 工序 2 生效，且不需要该路径真的存在 |
| `{a,b}` | `a` `b` | 工序 1 生效，也不需要文件存在 |
| `$v/*.txt` | `dir/one.txt` `dir/two.txt` | **先**换 `$v`→`dir`，**再**拿 `dir/*.txt` 去问文件系统 |
| `$(printf CMD)` | `CMD` | 命令替换的结果当普通文本贴进来 |
| `*.nope` | `*.nope` | 一个都没匹配上 → 字面量原样留着（第 13 节的祸根） |
| `"a b"` | `a b`（1 个词） | 引号保住了空格，工序 4 跳过它 |
| `$v` | `dir` | 变量单独成词 |

`$v/*.txt` 那一格是本节最重要的一条：**变量先展开、结果再通配**。顺序反过来就完全解释不通。

再看花括号和别的展开谁在前面：

```
$ v=dir; echo "花括号排第一，所以能带着变量的结果走：{a,b}$v =>"; echo {a,b}$v
花括号排第一，所以能带着变量的结果走：{a,b}dir =>
adir bdir
[退出码 0]

$ b="{x,y}"; echo "但反过来不行：变量里的花括号不会被再展开一次 =>"; echo $b
但反过来不行：变量里的花括号不会被再展开一次 =>
{x,y}
[退出码 0]

$ echo "命令替换出来的花括号同理："; echo $(printf "%s" "{x,y}")
命令替换出来的花括号同理：
{x,y}
[退出码 0]

$ n=1; m=3; echo "序列 {n..m} 用变量造不出来：{$n..$m}"; echo {$n..$m}
序列 {n..m} 用变量造不出来：{1..3}
{1..3}
[退出码 0]
```

第三、四条是同一个道理的两种表现：**花括号是工序 1，它只执行一次，且不认「后面才换出来的文本」。**
所以：

- `echo {a,b}$v` ✅ 可以 —— 花括号先切出 `{a}$v {b}$v`，`$v` 在工序 3 才被换掉；
- `echo $b`（`b` 里存着 `{x,y}`）❌ 不会展开 —— 等工序 1 干完活了，花括号才作为内容出现；
- `n=1; m=3; echo {$n..$m}` ❌ 得到字面 `{1..3}` —— 序列 `{1..3}` 需要在工序 1 就长得像序列。
  想变量造序列，用 `$(seq "$n" "$m")`（外部命令）或 `for ((i=n; i<=m; i++))`（工序 3 的算术）。

最后是波浪线的一个易错点：

```
$ d=~root/x; echo "赋值里不加引号时 ~ 会换掉：[$d]"; d="~root/x"; echo "加了引号就不换：[$d]"
赋值里不加引号时 ~ 会换掉：[/root/x]
加了引号就不换：[~root/x]
[退出码 0]
```

`~` 只在「词的首部且未被引号包住」时才换。`d="~root/x"` 之后 `cd $d` 会去一个叫 `~root` 的目录（不存在），
这是很多人 `cd` 失败的真正原因。

> ★ 结论：顺序记不住就记三句 ——
> ① 花括号只认源码里的字面文本，最先做、只做一次；
> ② 变量/命令/算术的结果还要再过「分词」和「通配」；
> ③ 引号是最后一道手续，它保护的内容不参与前面任何一步。

### 第 03 节 · 变量和命令替换的结果，还要再过一次通配

这是本章事故率最高的一节：**glob 来自变量**。沙箱 `files/` 里放了七个名字（故意带空格和 `*`，
全部是本章自己在沙箱里造的）：

```
$ mkdir -p files; touch files/aa.txt files/ab.txt files/b1.log files/A.txt files/B.txt "files/my file.txt" "files/we*ird.txt"; cd files; ls
A.txt
B.txt
aa.txt
ab.txt
b1.log
my file.txt
we*ird.txt
[退出码 0]
```

（这里 `ls` 一行一个，是因为 demo 把输出重定向了 —— 输出不是终端时 `ls` 就不排版成列。
`safeloop.sh` 里我干脆写成 `ls -1`，不去依赖这个判断。）

现在把模式放进变量：

```
$ cd files; v="*.txt"; echo "裸用：把 v 的值当模式用"; echo $v
裸用：把 v 的值当模式用
A.txt B.txt aa.txt ab.txt my file.txt we*ird.txt
[退出码 0]

$ cd files; v="*.txt"; echo "带引号：模式变成普通文本"; echo "$v"
带引号：模式变成普通文本
*.txt
[退出码 0]
```

同一对字符 `*`，加引号是文本、不加引号是模式。**值本身没有变，变的是它有没有参加工序 5。**

命令替换的结果同理：

```
$ cd files; echo "命令替换的结果也一样被通配："; echo $(printf "we*")
命令替换的结果也一样被通配：
we*ird.txt
[退出码 0]
```

注意这个例子有多阴：`printf "we*"` 输出的就是 `we*` 三个字符，但因为没加引号，`*` 又被当模式用了一次，
刚好命中那个名字里真带 `*` 的文件，于是你看到 `we*ird.txt` ——
**你以为程序会收到 `we*`，其实它收到的是 `we*ird.txt`。**

花括号的结果也要过通配，而且没命中的词各自留字面量：

```
$ cd files; echo "花括号的结果也要过通配：{a,b}* =>"; echo {a,b}*
花括号的结果也要过通配：{a,b}* =>
aa.txt ab.txt b1.log
[退出码 0]

$ cd files; echo "两个词都没命中就都留字面量：{zz,yy}* =>"; echo {zz,yy}*
两个词都没命中就都留字面量：{zz,yy}* =>
zz* yy*
[退出码 0]
```

第二条尤其重要：花括号先造出 `zz*` 和 `yy*` 两个词，两个都去问文件系统，都没命中，于是**两个词都原样留着**。
所以「一次展开里多个词」时，通配是逐词判定的，不存在「整体失败」。

> ★ 结论：裸用 `$v` 等于「把 `v` 的值当模式用」。这跟「值里有没有空格」是两套独立事故：
> 空格在工序 4 出事，`* ? [ ]` 在工序 5 出事。想只当文本 —— 加引号；一个字符都不要多想。

### 第 04 节 · `set -x`：跟踪里那对引号是 bash 现加的，不是你写的那对

调试展开问题就一个工具：`set -x`。但它有个坑：**它显示的引号是它自己加的。**

```
$ set -x; echo "a b"; echo 'a b'; echo a\ b
+ echo 'a b'
a b
+ echo 'a b'
a b
+ echo 'a b'
a b
[退出码 0]
```

三种完全不同的写法 —— 双引号、单引号、反斜杠 —— 在跟踪里长得一模一样。
`+` 后面那对单引号是 bash 为了「让你能照着敲回终端」现场生成的转义格式。
**它只告诉你：这里有 1 个词，内容是 `a b`。你源码里用的是哪种引号，它不显示。**

真正有用的是这个对比：

```
$ set -x; v="a b"; printf "[%s]\n" "$v"
+ v='a b'
+ printf '[%s]\n' 'a b'
[a b]
[退出码 0]

$ set -x; v="a b"; printf "[%s]\n" $v
+ v='a b'
+ printf '[%s]\n' a b
[a]
[b]
[退出码 0]
```

`+ printf` 那一行就是「切没切」的铁证：带引号那行的跟踪里 `a b` 被引号包住（1 个词），
不带引号那行是两个词分开站着。调「莫名其妙少了一个参数」时先看这里，比猜快得多。

再补一刀，证明引号确实是重新加的：

```
$ set -x; printf "[%s]\n" "a b" "c*d" *.nope
+ printf '[%s]\n' 'a b' 'c*d' '*.nope'
[a b]
[c*d]
[*.nope]
[退出码 0]
```

你写的格式串是 `"[%s]\n"`（双引号），跟踪里打成 `'[%s]\n'`（单引号那版）；
而 `*.nope` 没匹配上，所以它的字面量在跟踪里也被引号包起来了 —— 这是 bash 在提示你：
**这个词现在是「内容」，不是「模式」。**

> ★ 结论：`set -x` 的引号读法是「这里有 1 个词」，不是「我源码里写了引号」。
> 想知道源码里的引号有没有生效，看的是**词的个数**，不是引号本身。

### 第 05 节 · 单引号：进去之后什么都不发生

单引号是最强的一道锁：里面的 `$`、反引号、`\`、`*`、空格全部是普通字符。

```
$ v=hi; echo "$v"; echo '$v'
hi
$v
[退出码 0]

$ echo '$v 反引号也安静 "双引号" 反斜杠 \n 全部原样'
$v 反引号也安静 "双引号" 反斜杠 \n 全部原样
[退出码 0]
```

代价是：**单引号里唯一不能出现的字符就是单引号本身。** 想写 `it's` 会当场语法错：

```
$ echo it's 这样写会当场报错
bash: -c: line 1: unexpected EOF while looking for matching `''
[退出码 2]
```

这条报错值得逐字读：`bash: -c:` 说明是 `-c` 传进来的字符串有问题（demo 用 `bash -c` 跑每条命令）；
`unexpected EOF while looking for matching `''` 说它在找**配对的单引号**，找到行尾没找到；
退出码 `2` 是语法错误类，**整条命令一个字都没执行** —— 和「跑了一半失败」是两种病。

正解有两种，demo 生成一个 `quote_fix.sh` 先 `cat` 再跑，让源码和输出同时在场：

```
$ cat quote_fix.sh
echo "双引号包着：it's 想写几个单引号写几个"
echo '单引号出关再进关：it'\''s 也能成'
[退出码 0]

$ bash quote_fix.sh
双引号包着：it's 想写几个单引号写几个
单引号出关再进关：it's 也能成
[退出码 0]
```

第二种的读法（新手最容易在这里卡住，所以拆成三段）：

```text
'单引号出关再进关：it'  \'\''  s 也能成'
   └─ 第一段单引号到此结束 ┘ │  └─ 重新开始一段，直到行尾
                        反斜杠转义的那个单引号字符
```

也就是：先用单引号包住前半句，**出来**，用一个转义的单引号补上那个字符，**再进去**包住后半句。
`it'\''s` 这五个字符里，`'\''` 是「关-转义引号-开」三件事，不是四个字符的魔法。

实用建议（不改变事实，只是让你少写这种串）：文本里要单引号就整段改用双引号包住；
只有当这段内容里同时有 `$` 且你**不想**它展开时，才值得写 `'\''`。

> ★ 结论：单引号 = 「这段内容跳过工序 1~5」。它没有「部分生效」的余地，所以也不能在里面放自己。

### 第 06 节 · 双引号：只有四个字符还特殊

双引号不是「弱化版单引号」，它是**白名单**：在双引号里面仍然特殊的只有
`$`、反引号、`"`、`\`（而且 `\` 只在它管着这四个 + 换行时才算转义）。其余一律是普通字符。

```
$ v=hi; echo "反斜杠组：\" 是一个引号、\\ 是一个反斜杠、\n 和 \t 原样保留；而 $v 会展开"
反斜杠组：" 是一个引号、\ 是一个反斜杠、\n 和 \t 原样保留；而 hi 会展开
[退出码 0]

$ echo "双引号里的单引号就是普通字符：it's，不用转义"
双引号里的单引号就是普通字符：it's，不用转义
[退出码 0]

$ echo 双引号外的反斜杠管住空格：a\ b   还有星号：\*
双引号外的反斜杠管住空格：a b 还有星号：*
[退出码 0]

$ v=hi; echo "想显示美元符号要转义：\$v；不转义就展开成值：$v；反引号照样执行：`printf BT`；但星号和空格不参与通配与分词：* a b"
想显示美元符号要转义：$v；不转义就展开成值：hi；反引号照样执行：BT；但星号和空格不参与通配与分词：* a b
[退出码 0]
```

四条要分别记住：

1. **`\n`、`\t` 在双引号里不是换行和制表符**，是「反斜杠 + 字母」两个字符（第一行输出里它们原样站着）。
   想要真控制字符，用 `printf` 或 ANSI-C 引用（第 08 节）。这是从 C 语言过来的人最常踩的一脚：
   C 里 `"a\nb"` 是三个字符，bash 里它是四个字符。
2. **`\` 只在双引号里管 `$ ` " \` 和换行**，管不到 `n`。所以 `"a\nb"` 里的 `\` 是字面字符。
3. **反斜杠在引号外面才是「万能单字符保护」**（第三行）：`a\ b` 是一个词 `a b`，
   `\*` 是一个字面星号，不参与工序 4、5。它等价于「只给下一个字符加引号」。
   顺带一说：`a\ b` 后面那三个连续空格是**bash 的分词符**（连续的 IFS 空白算一个分隔符），
   所以 `echo` 只收到 2 个词，它自己用一个空格把词拼起来打印 —— 屏幕上就只剩一个空格。
   结论：排版靠 `printf`，别靠空格。
4. **单引号在双引号里是普通字符**（第二行）：`it's` 直接写，不用转义。

> ★ 结论：判断「要不要转义」只问一句 —— 这个字符在不在 `{ $ \` " }` 里？
> 在，双引号里还得转义；不在，双引号里就是它自己。

### 第 07 节 · 反引号 vs `$( )`：退出码一样，嵌套和转义差很多

先说一个容易看漏的事实：反引号在**单引号里**是纯文本，在**双引号里**照样执行。

```
$ echo "反引号必须成对；在单引号里它才是纯文本：'`printf HI`' 原样打印"
反引号必须成对；在单引号里它才是纯文本：'HI' 原样打印
[退出码 0]

$ x=hi; echo "双引号里的反引号还是会被执行：`echo $x`"
双引号里的反引号还是会被执行：hi
[退出码 0]

$ echo "转义过的反引号是字面字符：\$ 和 \`，都不执行"
转义过的反引号是字面字符：$ 和 `，都不执行
[退出码 0]
```

少一个反引号，就是语法错误，整条不执行（退出码 2）：

```
$ echo 少了一个反引号：`
bash: -c: line 1: unexpected EOF while looking for matching ``'
[退出码 2]
```

（报错原文里那两个反引号是 bash 自己在说「我在找配对的这个字符」。）

嵌套是两者的分水岭。反引号套反引号必须手工转义，可读性为零：

```
$ echo 反引号套反引号要这样转义：`echo `内层``
反引号套反引号要这样转义：内层
[退出码 0]

$ echo $(echo "$(echo 第三层)")
第三层
[退出码 0]

$ echo "同一件事，套几层写几层：$(echo 外面 $(echo 里面))"
同一件事，套几层写几层：外面 里面
[退出码 0]
```

`$( )` 想套几层写几层，因为括号是自匹配的；反引号是自相似的（两个相同字符配对），
所以嵌套必须靠转义来区分「哪个反引号闭合哪个」。**这是本书只用 `$( )` 的唯一理由**，
不是为了好看。

退出码这一格很多人讲错。实测两种写法**都一样**：命令替换本身的退出码是「替换里最后一条命令的退出码」，
而你能接住它的时间窗口只有一瞬间：

```
$ r=$(nosuchcmd02); echo "紧跟的 \$? = [$?]"
bash: line 1: nosuchcmd02: command not found
紧跟的 $? = [127]
[退出码 0]

$ q=`nosuchcmd02`; echo "反引号版紧跟的 \$? = [$?]"
bash: line 1: nosuchcmd02: command not found
反引号版紧跟的 $? = [127]
[退出码 0]

$ r=$(printf ok); echo 隔了一条命令; echo "再读 \$? = [$?]（已经被上面那个 echo 覆盖成 0）"
隔了一条命令
再读 $? = [0]（已经被上面那个 echo 覆盖成 0）
[退出码 0]
```

第二条的标签里 `127` 出现两次，是因为 `$?` 在双引号里被展开了**两次**（标签那次也是）——
这正好是第 06 节规则的现场复习：想让 `$?` 当字面文本写，就得写成 `\$?`（第一条就是这么做的）。

> ★ 结论：命令替换失败不会让「整条命令」失败，它只留下一个退出码，且立刻被下一条命令覆盖。
> 所以「替换里失败了」只有你**紧跟一句**读 `$?`（或者把赋值写成 `if ! out=$(cmd); then`）才知道。

### 第 08 节 · `$'...'`（ANSI-C 引用）：把反斜杠序列变成真字符

第 06 节说双引号里的 `\n` 不是换行。想要真换行、真制表符，用 `$'...'`：

```
$ echo $'a\nb'
a
b
[退出码 0]

$ printf "普通单引号对比：[%s]\n" 'a\nb'
普通单引号对比：[a\nb]
[退出码 0]

$ v=$'a\tb'; echo "长度=${#v}（一个 tab 只算 1 个字符）"; printf "%s\n" "$v" | sed -n l
长度=3（一个 tab 只算 1 个字符）
a\tb$
[退出码 0]

$ echo $'\x41\101B'
AAB
[退出码 0]

$ v=hi; echo $'v=$v 变量不展开，它只管反斜杠'
v=$v 变量不展开，它只管反斜杠
[退出码 0]

$ IFS=$'\n'; v=$(printf "a b\nc d"); for w in $v; do echo "词=[$w]"; done
词=[a b]
词=[c d]
[退出码 0]
```

读第三、四行：

- `${#v}` 得到 3，说明 `a\tb` 这个值里真的是「a、一个制表符、b」三个字符。
- `sed -n l` 是**交叉验证**：`sed` 打印时会把不可打印字符再转义回去，所以你看到 `a\tb$`
  （行尾那个 `$` 是 `sed -n l` 表示行结束，不是 shell 的提示符）。
  自己造的值、别人渲染的值，两头一对，就不需要靠信仰。
- `$'\x41\101B'` → `AAB`：`\x41` 是十六进制的 A，`\101` 是八进制的 A，`B` 是它自己。
  这套记法在你需要 `\e`（转义序列、写颜色时）时同样管用。

最后一行是本章的一个转折点：把 `IFS` 设成**真的换行符**，`for` 就按行切，
行内的空格不再被切开 —— 这是「按行处理文本」的标准写法，第 12 节还会用到。

为什么不认变量（第五行）：`$'...'` 处理的是**反斜杠转义**这一件事，它的行为和单引号一样不展开 `$`。
它不认变量、在 dash 里也不工作 —— 第 01 章实测 dash 会原样留下 `$'a\nb'` 这一串（不报错但不展开）。

> ★ 结论：需要「一个真控制字符」的三个地方 —— `IFS`、`printf` 的参数、`sed`/`awk` 的分隔 —— 都用 `$'...'`，
> 不要用双引号里的 `\n`（那是两个字符），也不要用反斜杠不加引号（那会被工序 4 拆走）。

### 第 09 节 · word splitting：不带引号的变量是被「切」的

工序 4 的规则（本机实测）：拿 `IFS` 里的字符去切**展开的结果**；
`IFS` 里的空白字符（空格、tab、换行）连续算一个分隔符、首尾丢弃。

```
$ v="a  b   c"; bash seg.sh $v
参数个数=3
  1: [a]
  2: [b]
  3: [c]
[退出码 0]

$ v="  a b  "; bash seg.sh $v
参数个数=2
  1: [a]
  2: [b]
[退出码 0]

$ v="a b"; bash seg.sh "$v"
参数个数=1
  1: [a b]
[退出码 0]

$ v="a b"; echo "拼接前后加字也还是两个词：前${v}后"; bash seg.sh 前${v}后
拼接前后加字也还是两个词：前a b后
参数个数=2
  1: [前a]
  2: [b后]
[退出码 0]
```

第一、二行说明「值里有几个空格」和「程序拿到几个词」对不上：`a  b   c` 是 3 个词、
`  a b  ` 首尾空白直接蒸发。所以**永远不要用空格排版来传参数**。

第四行是很多人没想到的：`${v}` 前后粘了字，切出来的词是 `前a` 和 `b后` —— 
分词发生在**整词展开之后**，切点在原值的空格处，粘上的前后缀跟着各自的半边走了。

最阴的一种用法是把整条命令存进变量：

```
$ cmd="bash seg.sh \"a b\" c"; echo "整串是：[$cmd]"; $cmd
整串是：[bash seg.sh "a b" c]
参数个数=3
  1: ["a]
  2: [b"]
  3: [c]
[退出码 0]
```

`$cmd` 裸用 → 工序 3 换成那串文本 → 工序 4 按空格切 → 工序 5 → 执行。
**引号在这一条链上早就没地方了**（工序 6 只删源码里的引号，而这里的引号是「内容」），
于是 `seg.sh` 收到 3 个词，第一个是 `"a`。这不是 bug，是流水线没有「重来一遍」的入口。

正解不是「多转义一层」，而是换机制：

```bash
# 要「一段可复用的命令」→ 用函数，它接的是参数、不是文本
seg() { bash seg.sh "$@"; }
seg "a b" c
```

> ★ 结论：变量可以存**数据**（记得加引号），也可以存**单个命令名或单个参数**，
> 但不能存「一条带引号的命令」。后者请写成函数或数组。

### 第 10 节 · `IFS`：切分规则本身就是个变量

四条规则，全部实测。

规则 ①：`IFS` 里的空白字符 —— 连续算一个、首尾丢弃（第 09 节已演）。
规则 ②：非空白字符 —— 一个字符切一次，相邻两个切出**空字段**，首尾不丢弃。

```
$ v="a:b:c"; IFS=:; set -- $v; echo "IFS 是冒号时：词数=$# 三格=[$1][$2][$3]"
IFS 是冒号时：词数=3 三格=[a][b][c]
[退出码 0]

$ v="a::b"; IFS=:; set -- $v; echo "词数=$# 三格=[$1][$2][$3] ← 中间那个空字段保住了"
词数=3 三格=[a][][b] ← 中间那个空字段保住了
[退出码 0]

$ v="  a  b  "; IFS=x; set -- $v; echo "IFS=x（不含空格）词数=$# 第一格=[$1]"
IFS=x（不含空格）词数=1 第一格=[  a  b  ]
[退出码 0]
```

第三条最反直觉：`IFS=x` 之后**空格不再是分隔符**，所以 `  a  b  ` 整串是一个词，首尾空格也留下来了。
「切不切空格」取决于 `IFS` 里有没有空格，不取决于空格长什么样。

规则 ③：`IFS=`（空字符串）和 `unset IFS`（回默认）**是两件事**：

```
$ IFS=; v="a b c"; bash seg.sh $v
参数个数=1
  1: [a b c]
[退出码 0]

$ unset IFS; v="a b c"; bash seg.sh $v
参数个数=3
  1: [a]
  2: [b]
  3: [c]
[退出码 0]
```

`IFS=` → 完全不切（`read` 那套「保住整行」的写法就靠它，见第 12 节写法 D）；
`unset IFS` → 不是「没有分隔符」，而是**回到默认的空格 tab 换行**。

常用的 PATH 遍历是规则 ② 的实战：

```
$ p="/usr/bin:/bin:/usr/local/bin"; IFS=:; for d in $p; do echo "[$d]"; done
[/usr/bin]
[/bin]
[/usr/local/bin]
[退出码 0]
```

规则 ④：**前缀赋值不影响这一条命令自己的分词** —— 网上教程讲错最多的一条：

```
$ v="a b c"; IFS=: bash seg.sh $v
参数个数=3
  1: [a]
  2: [b]
  3: [c]
[退出码 0]

$ v="a b c"; IFS= bash seg.sh $v
参数个数=3
  1: [a]
  2: [b]
  3: [c]
[退出码 0]
```

两条都还是按默认空格切成 3 个词。原因回到流水线：**分词发生在把 `bash seg.sh` 调起来之前**，
那一刻用的是当前 shell 的 `IFS`；前缀的 `IFS=` 只对「被调命令的环境」生效，
而 `seg.sh` 里根本没有用到 `IFS`。想改分词，就得单独一句 `IFS=…`（或者放进子 shell `( IFS=…; ... )`）。

> ★ 结论：改 `IFS` 只有两种正确姿势 —— ① 影响当前 shell 的展开：`IFS=x` 单独一句，用完 `unset IFS`；
> ② 只在一段范围内改：`( IFS=x; ... )` 或 `while IFS= read -r ...`。**不要**指望 `IFS=x 命令`。

### 第 11 节 · `"$*"` 和 `"$@"`：四格矩阵逐项实测

这一格是本书最容易写错的地方，所以不背口诀，直接测。
`args_matrix.sh` 用「子 shell 里 `set --` 再接数」的办法量每种写法变成几个词：

```
$ bash args_matrix.sh "a b" c "" d
传进来的参数个数=4（前两个是 "a b" 和 c，看调用方怎么写）
当前 IFS 是：$' \t\n'

== IFS 为默认（空格 tab 换行）时 ==
  "$@"   词数=4：[a b][c][][d]
  "$*"   词数=1：[a b c  d]
  $@     词数=4：[a][b][c][d]
  $*     词数=4：[a][b][c][d]

== 换成 IFS=: 之后（同一次调用，只是 IFS 变了）==
  "$@"   词数=4：[a b][c][][d]
  "$*"   词数=1：[a b:c::d]
  $@     词数=4：[a b][c][][d]
  $*     词数=4：[a b][c][][d]

== IFS=（空字符串）：四格全测一遍，看带引号的两格动不动 ==
  "$@"   词数=4：[a b][c][][d]
  "$*"   词数=1：[a bcd]
  $@     词数=3：[a b][c][d]
  $*     词数=3：[a b][c][d]
[退出码 0]
```

四个格子读成四句话：

- **`"$@"`：永远是一格不少地原样转发**，三个 `IFS` 环境下都是 4 个词，连那个空参数（`[]`）都保住。
  这是它唯一该出现的场合 —— 转发参数。
- **`"$*"`：粘成一格**，粘的时候用 `IFS` 的**第一个字符**当胶水：默认空格 → `a b c  d`
  （注意中间那两个连续空格：空的那格也在，只是它是空的）；`IFS=:` → `a b:c::d`；
  `IFS=` → `a bcd`（胶水是空字符串，直接焊死）。
- **裸 `$@` / `$*`：粘成一格之后还要再过工序 4**，所以空格那格会被切开、空的那格掉地上：
  默认 `IFS` 下 4 格变 4 个词但内容丢了（`[a][b][c][d]`，`a b` 被劈成两半）；
  `IFS=:` 下反而保住了内容（因为 `IFS` 里没有空格，切不开）；
  `IFS=` 下只剩 3 个词（空参数在展开后没有内容可切，直接消失）。
- 第二块里 `$@`/`$*` 和 `"$@"` 输出一样，**不代表裸用安全**，只代表这次的 `IFS`（冒号）里没空格。

把「收到的参数」转发给函数时的四格实测（`forward.sh` 就是这四句）：

```
$ cat forward.sh
f() { printf '收到词数=%d：' $#; printf '[%s]' "$@"; printf '\n'; }
set -- "a b" "c d"
printf '%s\n' '转发 "$@" 时：'
f "$@"
printf '%s\n' '转发 "$*" 时：'
f "$*"
printf '%s\n' '裸转发 $@ 时：'
f $@
printf '%s\n' '裸转发 $* 时：'
f $*
[退出码 0]

$ bash forward.sh
转发 "$@" 时：
收到词数=2：[a b][c d]
转发 "$*" 时：
收到词数=1：[a b c d]
裸转发 $@ 时：
收到词数=4：[a][b][c][d]
裸转发 $* 时：
收到词数=4：[a][b][c][d]
[退出码 0]
```

同一层里还有一个函数侧的观察（`f` 接的是参数，所以变量进函数**之前**就已经切好了）：

```
$ f() { printf "词数=%d：" $#; printf "[%s]" "$@"; printf "\n"; }; v="a b c"; echo "传给函数时："; f $v; f "$v"; f "${v% *}" "${v#* }"
传给函数时：
词数=3：[a][b][c]
词数=1：[a b c]
词数=2：[a b][b c]
[退出码 0]
```

第三句顺手演示了「想主动切成两段」的正确做法：不是裸用变量，而是用第 17/18 节的剥皮/截取语法
按你自己的规则切（`${v% *}` 去掉最后一个空格及其后面、`${v#* }` 去掉第一个空格及其前面）。

> ★ 结论（本章唯一必须背下来的一格）：**转发参数用 `"$@"`，一个字符都不要改。**
> 需要「把所有参数拼成一句话」显示给人看时才用 `"$*"`。裸的 `$@`/`$*` 在这两个用途里都不是你想要的。

### 第 12 节 · 真实事故：文件名带空格、带 `*` 的时候会发生什么

还是第 03 节那个 `files/` 目录（`my file.txt`、`we*ird.txt`，全是沙箱里本章自己造的）。
`safeloop.sh` 四种写法一次跑完，它只读文件名、不写不删：

```
$ bash safeloop.sh files
目录里的文件（ls 一行一个）：
A.txt
B.txt
aa.txt
ab.txt
b1.log
my file.txt
we*ird.txt

== 写法 A（坏）：先用 ls 塞进变量，再裸用 $files ==
  一个词=[A.txt]   存在
  一个词=[B.txt]   存在
  一个词=[aa.txt]   存在
  一个词=[ab.txt]   存在
  一个词=[b1.log]   存在
  一个词=[my]   不存在（名字被切坏了）
  一个词=[file.txt]   不存在（名字被切坏了）
  一个词=[we*ird.txt]   存在

== 写法 B（好）：glob 直接写在 for 后面，一个词一个文件 ==
  一个文件=[A.txt]
  一个文件=[B.txt]
  一个文件=[aa.txt]
  一个文件=[ab.txt]
  一个文件=[my file.txt]
  一个文件=[we*ird.txt]

== 写法 C（好）：先收进数组，再用 "${arr[@]}" 展开 ==
  数组里的元素个数 -> 6（这一格是用 ${#list[@]} 数出来的）
  一个文件=[A.txt]
  一个文件=[B.txt]
  一个文件=[aa.txt]
  一个文件=[ab.txt]
  一个文件=[my file.txt]
  一个文件=[we*ird.txt]

== 写法 C 的下游验证：把数组原样转发给 seg.sh ==
参数个数=6
  1: [A.txt]
  2: [B.txt]
  3: [aa.txt]
  4: [ab.txt]
  5: [my file.txt]
  6: [we*ird.txt]

== 写法 D（好，要跨命令传清单时）：find -print0 + IFS= read -r -d "" ==
  一条=[we*ird.txt]
  一条=[my file.txt]
  一条=[B.txt]
  一条=[A.txt]
  一条=[ab.txt]
  一条=[aa.txt]
[退出码 0]
```

写法 A 是本节的全部教训：

- `[my]` 和 `[file.txt]` 都「不存在」，因为真名字是 `my file.txt` —— 一个文件被切成两个词，
  **两个都是假文件名**。
- 更妙的是 `[we*ird.txt]   存在`：`$files` 裸用还顺手过工序 5，`*` 被当模式用了一次，
  这次刚好匹配上那个真带 `*` 的文件，于是它「看起来是对的」。
  这类「运气正确的输出」比明显的错误危险一百倍。
- 全程退出码 0。事故没有一行报错。

四种写法的判定：

| 写法 | 代码 | 空格 | `*` | 换行 | 什么时候用 |
|---|---|---|---|---|---|
| A（坏） | `files=$(ls); for f in $files` | ❌ 切坏 | ❌ 二次通配 | ❌ | 永远不用 |
| B（好） | `for f in *.txt` | ✅ | ✅ | ✅ | 就在当前目录、当场用 |
| C（好） | `list=( *.txt )` + `"${list[@]}"` | ✅ | ✅ | ✅ | 要先存清单、多次用、传给别的命令 |
| D（好） | `find ... -print0 \| while IFS= read -r -d '' f` | ✅ | ✅ | ✅ | 清单跨命令/跨进程传，或目录很深 |

D 里三个细节都是必要的，缺一不可：`-print0` 用 NUL 当分隔符（文件名里不能有 NUL，所以绝对安全）、
`IFS=` 不让 `read` 把行首行尾空白切掉、`-r` 让反斜杠不被 `read` 吃掉。
`-d ""` 是把 `read` 的行分隔符改成 NUL。
D 的输出顺序和第 11 节 `ls` 不一样 —— 那是 `find` 按目录项顺序给的，**不是排序**；
真要顺序自己排：`... | sort -z`（`-z` 配 `-print0`）。

> ★ 结论：只要涉及「一批文件」，就三选一 —— glob 直接写在 `for` 后面、数组 + `"${arr[@]}"`、
> `find -print0` + `IFS= read -r -d ''`。**任何**把文件名装进普通变量再裸用的写法都不行。

### 第 13 节 · glob 一个都没匹配上时：bash 默认留下字面量

沙箱里造一个空目录 `empty/`，然后什么都不放：

```
$ mkdir -p empty; cd empty; ls; echo "目录里一个文件都没有，现在跑：echo 星号点 tmp"; echo *.tmp
目录里一个文件都没有，现在跑：echo 星号点 tmp
*.tmp
[退出码 0]
```

`echo` 打印了字面量 `*.tmp` —— 这就是工序 5 的默认行为：**不匹配就原样留着，退出码还是 0**。
把它换成 `rm`：

```
$ cd empty; rm *.tmp
rm: cannot remove '*.tmp': No such file or directory
[退出码 1]
```

报错原文里的引号是铁证：`rm` 收到的参数**内容是 `*.tmp`**（`rm` 自己给它加了引号），不是「所有 tmp 文件」。
抱怨的是外部命令 `rm`，不是 bash。

循环和数组同样中招：

```
$ cd empty; for f in *.tmp; do echo "循环体拿到了 [$f]"; done; echo "循环结束了（注意它跑了一次！）"
循环体拿到了 [*.tmp]
循环结束了（注意它跑了一次！）
[退出码 0]

$ cd empty; arr=( *.tmp ); echo "数组长度=${#arr[@]} 内容=[${arr[*]}]"
数组长度=1 内容=[*.tmp]
[退出码 0]
```

这就是「脚本没报错、循环体却拿着一个字面量乱跑」的完整链条：**不命中 → 留字面量 → 交给命令**。
如果循环体里是 `rm -f "$f"`，`-f` 会压掉报错，你的脚本于是安静地做了什么也没干的事。

两个开关。`nullglob`：不匹配的词直接消失。

```
$ cd empty; shopt -s nullglob; echo "开了 nullglob 之后 echo 得到：[$(echo *.tmp)]"; for f in *.tmp; do echo "不该出现"; done; echo "循环一次都没跑"
开了 nullglob 之后 echo 得到：[]
循环一次都没跑
[退出码 0]

$ cd empty; shopt -s nullglob; arr=( *.tmp ); echo "nullglob 下数组长度=${#arr[@]}（不匹配的 glob 直接消失了）"
nullglob 下数组长度=0（不匹配的 glob 直接消失了）
[退出码 0]
```

`failglob`：不匹配就当场报错，**整条命令不执行**。

```
$ cd empty; shopt -s failglob; rm *.tmp
bash: line 1: no match: *.tmp
[退出码 1]
```

对比第 536 行那条 `rm` 的报错：这里抱怨的是 `bash`（`no match`），不是 `rm` —— 因为 `rm` 根本没被调起来。
「谁在抱怨」是判断「失败发生在哪一层」的最快线索，这个习惯第 03 章会继续用。

怎么选：**「没有文件」是正常情况 → `nullglob`；「没有文件」必须立刻停下 → `failglob`。**
两个都是 shell 开关，只在当前 shell 有效（demo 里每条命令都是一个新 `bash -c`，
所以上面每条都自己 `shopt -s` 了一次 —— 这本身也是「shell 选项不外传」的现场演示）。
把它们写进 rc 文件会影响你终端的每一次 `rm`/`cp`（本章不动你的 rc，
想试就开一个临时终端试完关掉）。

> ★ 结论：不演开关时的默认行为是「留字面量」，所以 glob 后面**永远要有兜底**：
> 要么 `shopt -s nullglob`，要么先判断 `[ -e "$f" ] || continue`，要么用 `failglob` 让它当场响。

### 第 14 节 · 花括号 vs 通配的本质差别 + 字符类、问号、嵌套、排列顺序

本质差别一句话：**花括号造词，通配查词。** 花括号不需要任何东西真的存在，通配必须去问文件系统。

```
$ cd empty; echo "空目录里花括号照样展开：{a,b} =>"; echo {a,b}; echo "同一个目录里的通配："; echo *.nothere
空目录里花括号照样展开：{a,b} =>
a b
同一个目录里的通配：
*.nothere
[退出码 0]
```

同一个空目录里，`{a,b}` 造出两个词，`*.nothere` 一个都没查到、留下字面量。这一对同时证明了两件事。

花括号支持嵌套和并列，笛卡尔积是它全部的把戏：

```
$ echo {a,b}/{1,2}.txt; echo "嵌套：x{a,b{1,2}}y =>"; echo x{a,b{1,2}}y
a/1.txt a/2.txt b/1.txt b/2.txt
嵌套：x{a,b{1,2}}y =>
xay xb1y xb2y
[退出码 0]

$ echo {1..5}; echo {1..10..3}; echo "花括号和通配混着写：{a,b}星号.txt（在 files 目录里）"; cd files; echo {a,b}*.txt
1 2 3 4 5
1 4 7 10
花括号和通配混着写：{a,b}星号.txt（在 files 目录里）
aa.txt ab.txt b*.txt
[退出码 0]
```

第三条是流水线的完美示范：`{a,b}*.txt` 先由工序 1 造出 `a*.txt`、`b*.txt` 两个词，
再分别交给工序 5 —— `a*.txt` 命中 `aa.txt`、`ab.txt`；`b*.txt` 一个都没命中，于是留下字面量 `b*.txt`。
**同一个词组里，命中的展开、没命中的留字面，两件事同时发生。**

`{1..10..3}` 的步长写法只在花括号里有效，且第 02 节已经演过它插不进变量。

字符类：`?` 是一个字符，`[ ]` 是一个字符的集合。

```
$ cd files; echo "[a-z]星号.txt =>"; echo [a-z]*.txt; echo "[A-Z]星号.txt =>"; echo [A-Z]*.txt; echo "[[:alpha:]]星号.txt =>"; echo [[:alpha:]]*.txt; echo "问号.txt（只一个字符）=>"; echo ?.txt
[a-z]星号.txt =>
aa.txt ab.txt my file.txt we*ird.txt
[A-Z]星号.txt =>
A.txt B.txt
[[:alpha:]]星号.txt =>
A.txt B.txt aa.txt ab.txt my file.txt we*ird.txt
问号.txt（只一个字符）=>
A.txt B.txt
[退出码 0]
```

（`?.txt` 命中的是 `A.txt`、`B.txt`：`?` 只吃**一个**字符，`aa.txt` 有两个字符打头，所以不被匹配。
顺便解释 `my file.txt`、`we*ird.txt` 为什么在 `[a-z]` 结果里 —— 首字符 `m`、`w` 是小写，
后面的空格和 `*` 由剩下的 `*.txt` 负责，模式不再管首字符之后是什么。）

这里必须纠一个网上教程最常见的错。四种语言环境各跑一次，**每个 `==` 块的第一行是 `[a-z]*.txt`，
第二行是 `*.txt`**：

```
$ cd files; for L in C C.UTF-8 en_US.UTF-8 zh_CN.UTF-8; do printf "%s\n" "== $L =="; LC_ALL=$L bash -c "echo [a-z]*.txt; echo *.txt"; done
== C ==
aa.txt ab.txt my file.txt we*ird.txt
A.txt B.txt aa.txt ab.txt my file.txt we*ird.txt
== C.UTF-8 ==
aa.txt ab.txt my file.txt we*ird.txt
A.txt B.txt aa.txt ab.txt my file.txt we*ird.txt
== en_US.UTF-8 ==
aa.txt ab.txt my file.txt we*ird.txt
aa.txt ab.txt A.txt B.txt my file.txt we*ird.txt
== zh_CN.UTF-8 ==
aa.txt ab.txt my file.txt we*ird.txt
aa.txt ab.txt A.txt B.txt my file.txt we*ird.txt
[退出码 0]
```

- 四种 locale 下 `[a-z]*.txt` 的结果**完全相同**，都只有小写开头那几个。
  所以「UTF-8 语言环境里 `[a-z]` 会连大写一起吞」在这台 bash 5.3.9 上**不成立**。
  （这个说法流传极广，来源是 glibc 的 `regcomp`/`fnmatch` 在个别 locale 下的历史行为；
  写教程的人往往是在别的机器、别的版本上看到的。）
- 变的是**第二行的排列顺序**：`C`/`C.UTF-8` 按字节序（大写在前），`en_US.UTF-8`/`zh_CN.UTF-8` 按本地化
  排序规则（`aa.txt ab.txt A.txt B.txt …`，大小写交错、按词排）。

这条差别很实用：**如果你的脚本靠 glob 结果的先后顺序做事（取「最后一个」、取「最新的」），
换 locale 就会换结果。** 需要确定顺序，就自己 `sort`（并显式指定 `LC_ALL=C`）。

再往下是「通配不越过斜杠」这个硬规则，和 `**`：

```
$ cd files; mkdir -p sub; touch sub/inner.txt; echo "通配不越过斜杠：星号.txt =>"; echo *.txt; echo "跨一层要写 斜杠前加星号：*/inner.txt =>"; echo */inner.txt; echo "不开 globstar 时两个星号等同一个星号："; echo **/inner.txt
通配不越过斜杠：星号.txt =>
A.txt B.txt aa.txt ab.txt my file.txt we*ird.txt
跨一层要写 斜杠前加星号：*/inner.txt =>
sub/inner.txt
不开 globstar 时两个星号等同一个星号：
sub/inner.txt
[退出码 0]

$ cd files; shopt -s globstar; echo "开了 globstar：两个星号递归 =>"; echo **/inner.txt
开了 globstar：两个星号递归 =>
sub/inner.txt
[退出码 0]
```

`*` 永远不跨过 `/`，这是文件系统层面的规则，跟 locale 无关。
`**` 在**不开** `globstar` 时和 `*` 完全等价（`sub/inner.txt` 只有一层，两种写法看不出来）；
开了 `globstar` 才是「递归」。本节沙箱里只造了一层目录，
所以「两层以上才显出差别」这一点本章**没有演到**（见文末「本章没演/没验证」）。

> ★ 结论：`{}` 造词（不需要存在）、`*?[]` 查词（必须存在、不越斜杠、无匹配留字面量、顺序随 locale）。
> 想「同时建 a/b、a/c、b/c」用 `mkdir {a,b}/{c,d}`；想「找到现有文件」用 glob —— 两者的失败模式不同。

### 第 15 节 · `${!...}`：前缀展开与间接取值，长得像但是两回事

```
$ BOOK_A=1 BOOK_B=2 OTHER=3; echo "前缀展开得到变量名列表：[${!BOOK_@}]"
前缀展开得到变量名列表：[BOOK_A BOOK_B]
[退出码 0]

$ BOOK_A=内容; name=BOOK_A; echo "间接取值：[${!name}]（name 里存的是变量名）"
间接取值：[内容]（name 里存的是变量名）
[退出码 0]

$ a=(x y z); echo "下标列表：[${!a[@]}] 值列表：[${a[@]}] 长度=${#a[@]}"
下标列表：[0 1 2] 值列表：[x y z] 长度=3
[退出码 0]

$ echo ${!P*_}
bash: line 1: ${!P*_}: bad substitution
[退出码 1]
```

三个合法形状，各干一件事：

| 写法 | 意思 | 实测给的是 |
|---|---|---|
| `${!prefix@}` / `${!prefix*}` | 列出**名字**以 prefix 开头的变量 | `BOOK_A BOOK_B`（不需要 export，普通 shell 变量也算） |
| `${!name}` | 间接取值：`name` 里存的是变量名 | `BOOK_A` 的值 `内容` |
| `${!arr[@]}` / `${!arr[*]}` | 列出数组已赋值的**下标** | `0 1 2`（稀疏数组只给真实存在的下标，见第 19 节） |

`${!P*_}` 报 `bad substitution`：前缀展开不接受模式，`*` 只能出现在整个词的最末位
（`${!BOOK_*}` 是合法的，因为 `*` 在最后）。注意 `bad substitution` 是 bash 在**展开阶段**说的，
退出码 1，`echo` 根本没跑。

`!` 在 `${!...}` 里和「历史扩展」的 `!`（`!!`、`!$`）毫无关系 —— 一个是参数展开的子语法，
一个是交互 shell 的输入预处理，非交互脚本里历史扩展默认关闭（第 01 章演过 `alias` 同理）。

> ★ 结论：`${!x}` 的 `!` 读作「拿 x 当名字再查一次」。前缀展开用来做「按前缀收集变量」的小工具，
> 顺序不要当排序用（本机是按定义顺序给的，但文档没保证顺序）。

### 第 16 节 · 默认值家族：`-` / `:-` / `:=` / `:+` / `:?` / `${#v}`

先把最像的两个用一行分清：`-` 只看「有没有被设过」，`:-` 还看「是不是空串」。

```
$ v=; echo "v 是空串时三个格子：[\${v-兜底}] [${v:-兜底}] [${v+有值}] [${v:+有值}]"
v 是空串时三个格子：[${v-兜底}] [兜底] [有值] []
[退出码 0]

$ v=x; echo "v=x 时三个格子：[\${v-兜底}] [${v:-兜底}] [${v+有值}] [${v:+有值}]"
v=x 时三个格子：[${v-兜底}] [x] [有值] [有值]
[退出码 0]
```

两行里第一格 `${v-兜底}` 是**打给你看的字面语法**（命令里把它写成了 `\$`，第 06 节那条规则），
不是它的展开结果；真正有信息量的是后面三格：`v=`（设了但空）时 `:-` 给 `兜底`、`+` 给 `有值`、`:+` 给空。

| 语法 | `v=`（设了但是空串） | `v=x` | `v` 从没设过 | 会写你的变量吗 |
|---|---|---|---|---|
| `${v-字面}` | 算设过 → 给**空串** | `x` | 用后面那串 | ❌ |
| `${v:-字面}` | 空串也算没值 → `兜底` | `x` | 用后面那串 | ❌ |
| `${v+内容}` | 设过 → `有值` | `有值` | 给空串 | ❌ |
| `${v:+内容}` | 空串不算有值 → 给空串 | `有值` | 给空串 | ❌ |
| `${v:=字面}` | 用字面，**并真的写回 `v`** | `x` | 用字面并写回 | ✅ |
| `${v:?消息}` | 报错并停下 | `x` | 报错并停下 | 停下 |

一句话读完这张表：**带冒号看「空不空」，不带冒号看「设没设」；只有 `:=` 会写你的变量，只有 `:?` 会停你的脚本。**

不赋值、不改环境是这一家的默认美德，实测：

```
$ echo "[\${UNSET_A-兜底}] [${UNSET_B:-兜底}] 都读到兜底；而且 UNSET_A 仍然没设：[\${UNSET_A-仍然没设}]"
[${UNSET_A-兜底}] [兜底] 都读到兜底；而且 UNSET_A 仍然没设：[${UNSET_A-仍然没设}]
[退出码 0]
```

例外是 `:=`，它会真的给变量装上值：

```
$ echo "第一步：[${NEW:=现装上去的}]"; echo "第二步：NEW 现在是 [$NEW] ← 冒号等号真的给它赋了值"; echo "第三步：${NEW+已经有值才显示这句} 和 ${NEW:+有值才显示这句}"
第一步：[现装上去的]
第二步：NEW 现在是 [现装上去的] ← 冒号等号真的给它赋了值
第三步：已经有值才显示这句 和 有值才显示这句
[退出码 0]

$ NEW=; echo "NEW 是空串时第一步：[${NEW:=兜底}]；第二步 NEW=[$NEW]（空串也算没值，所以照样赋值）"
NEW 是空串时第一步：[兜底]；第二步 NEW=[兜底]（空串也算没值，所以照样赋值）
[退出码 0]
```

第三步是「同一个值已经设过」之后 `+` 和 `:+` 一起显示 —— 这一格里 `NEW` 已经有值，两个都给内容，
说明它们只在「有值」时开口，跟 `:-` 的「没值时兜底」方向相反。

`:=` 的用处是「给配置变量装默认值并且留住」，脚本里等价于「只赋值一次的 `if [ -z ]`」。

`:-`/`:=` 都算「空串也没值」；如果你要的是「只有未设才兜底，空串照样用」，用不带冒号的 `-`。

`:?` 是唯一会把命令干掉的一个，两种场景的报错原文不一样：

```
$ echo ${UNSET_C:?未设就要停}
bash: line 1: UNSET_C: 未设就要停
[退出码 127]

$ bash qmark.sh
这行能打印出来（说明报错之前的代码已经执行了）
这行也能打印出来，紧接着下一行就要炸
qmark.sh: line 15: v: v 必须有值，否则这里不能跑
[退出码 1]
```

逐字读第二段的报错：`qmark.sh`（**文件名**）`: line 15:`（**行号**）`v:`（**变量名**）
`v 必须有值，否则这里不能跑`（**你自己写的那句消息**，bash 原样转述）。
脚本里从这一行起**一行都不再执行**，退出码 1。

第一段是 `bash -c` 的场景，所以前缀是 `bash: line 1:`，**退出码 127**；第二段在脚本里，**退出码 1**。
两次都是「报错 + 当前这个 shell 立刻停」，差别只在退出码给的是哪个数字。
（为什么 `bash -c` 场景是 127 而不是 1 —— 本章没有从 bash 内部去查，只按实测数字记录，
见文末「本章没演 / 没验证」。你在实际代码里只需要知道：**`:?` 失败 = 这个 shell 已经死了**，
所以别把它放在你还想继续跑的函数里。）
同一个语法在交互终端里只会让你那一行失败，不会退出你的终端。

`:?` 的定位是「配置检查」：`LOG_DIR=${LOG_DIR:?请先设 LOG_DIR}` 一行胜过五行的 `if`。
但它只保护**这一个词**，不会替你检查别的变量。

`${#v}` 是长度，不是「取反」也不是注释：

```
$ v=hello; echo "长度 ${#v}；未设变量的长度 ${#NOPE} 是 0，不是报错"
长度 5；未设变量的长度 0 是 0，不是报错
[退出码 0]

$ v=中文abc; echo "长度=${#v}（按字符数，不是字节数）"; printf "%s" "$v" | wc -c
长度=5（按字符数，不是字节数）
9
[退出码 0]
```

`中文abc` 长度是 5（两个汉字各算一个字符），`wc -c` 给 9（每个汉字 3 字节 + 3 个 ASCII）。
**`${#v}` 按字符数、`wc -c` 按字节数**，两者在不同 locale 下的差别就是你「字符串长度」bug 的来源。
（`${#arr[@]}` 是数组元素个数，同一个 `#` 换了上下文，第 19 节。）

> ★ 结论：这张表只有两个记忆点 ——
> ① **带冒号的看「空」，不带冒号的看「设没设」**；② 这一家里只有 `:=` 会写你的变量、只有 `:?` 会停你的脚本。

### 第 17 节 · 剥皮四件套：`#` / `##` / `%` / `%%`

方向由符号位置决定，贪婪程度由数量决定：

```text
${v# patt}   从左剥，最短匹配      ${v## patt}  从左剥，最长匹配
${v% patt}   从右剥，最短匹配      ${v%% patt}  从右剥，最长匹配
                     └─ patt 里可以写 * ? [..]，是 glob，不是正则
```

同一个路径一次对照，八个格子全打出来：

```
$ v=/tmp/a/b/c.tar.gz; echo "[${v#*.}] [${v##*.}] [${v%.*}] [${v%%.*}]"
[tar.gz] [gz] [/tmp/a/b/c.tar] [/tmp/a/b/c]
[退出码 0]

$ v=/tmp/a/b/c.tar.gz; echo "[${v#*/}] [${v##*/}] [${v%/*}] [${v%%/*}]"
[tmp/a/b/c.tar.gz] [c.tar.gz] [/tmp/a/b] []
[退出码 0]

$ v=/tmp/a/b/c.tar.gz; echo "[${v#/tmp}] [${v#/}] [${v%gz}] ← 锚定错了就什么都不剥"
[/a/b/c.tar.gz] [tmp/a/b/c.tar.gz] [/tmp/a/b/c.tar.] ← 锚定错了就什么都不剥
[退出码 0]
```

第二行是本章最实用的两个日常写法：`${v##*/}` = 「 basename 」（`c.tar.gz`），
`${v%/*}` = 「 dirname 」（`/tmp/a/b`）。
第一格 `${v#*/}` 只剥到**第一个**斜杠，得到 `tmp/a/b/c.tar.gz` —— 因为 `#` 是最短匹配。

最后一格 `[ ]` 是空串，这是本节最容易翻车的一格：`v` 以 `/` 开头，
`${v%%/*}` 从**右边**找「斜杠加任意内容」的最长匹配 —— 最左边那个 `/` 也算「右边的一大块」，
于是整个字符串被吃掉。想要「去掉最后一个斜杠及其之后」，用 `${v%/*}`（单个 `%`）。

第三行讲「锚定」：`#` 是从**开头**算的，所以 `${v#/tmp}` 剥掉了开头的 `/tmp`；
`${v#/}` 想剥开头那个 `/`，成功；`${v%gz}` 从结尾剥，但结尾不是 `gz`（是 `.gz`），
所以什么都没剥，原样给你。**匹配失败不报错，只是不剥** —— 于是你的路径里多留了一段扩展名。

最短/最长在中间的字符上差别更直观：

```
$ v=abc.tar.gz; echo "[${v#*a}] [${v##*a}] [${v%a*}] [${v%%a*}]"
[bc.tar.gz] [r.gz] [abc.t] []
[退出码 0]

$ v=hello.txt; echo "[${v%.txt}] [${v#*.}] [${v%%o*}]"
[hello] [txt] [hell]
[退出码 0]
```

第一行四个格子全是「最短 vs 最长」的对照：`*a` 从左最短匹配到第一个 `a`、最长匹配到最后一个 `a`
（所以 `##` 给 `r.gz`）；`a*` 从右最短匹配到最后一个 `a` 起的那个尾巴（`abc.tar.gz` 里最后一个 `a`
是 `tar` 那个，所以 `%a*` 留下 `abc.t`），`%%a*` 则从第一个 `a` 起全吃光 → 空串。
第二行是日常三件套：去扩展名 `${v%.txt}`、取扩展名 `${v#*.}`。

> ★ 结论：记「**`#` 在左（从开头剥）、`%` 在右（从结尾剥）、单个最短、双个最长**」，
> 再记两条失败模式：匹配不上就原样返回、`%%` 在开头/结尾同字符的路径上能吃出空串。
> 拿到不确定的字符串，先把四个都 `echo` 一遍再决定用哪个 —— 这一节本身就是这么写的。

### 第 18 节 · 替换 `/` `//` 与截取 `:off:len`

```
$ v=one-two-three; echo "[${v/-/X}] [${v//-/X}] [${v//o/0}] [${v/2/T}]"
[oneXtwo-three] [oneXtwoXthree] [0ne-tw0-three] [one-two-three]
[退出码 0]

$ v=hello; echo "[${v:1:2}] [${v:2}] [${v:0:99}] [${v:6:2}] ← 越界得到空串，不报错"
[el] [llo] [hello] [] ← 越界得到空串，不报错
[退出码 0]

$ v=abcdef; echo "[${v: -3}] 少一个空格变成 [${v:-3}]（那是默认值语法！）"
[def] 少一个空格变成 [abcdef]（那是默认值语法！）
[退出码 0]

$ v=abcdef; echo "[${v:0-3}] [${v:3:0}] [${v:( 1 + 1 ):2}]"
[def] [] [cd]
[退出码 0]

$ v=a.b.c; echo "[${v//./_}] [${v/./}]（只删第一个点）[${v//./}]（全删）"
[a_b_c] [ab.c]（只删第一个点）[abc]（全删）
[退出码 0]
```

要点：

- `/` 换**第一个**、`//` 换**全部**：`${v/-/X}` 只动了第一个 `-`（`oneXtwo-three`），
  `${v//-/X}` 两个都动（`oneXtwoXthree`），`${v//o/0}` 把两个 `o` 都换成 `0`。
  第四个 `${v/2/T}` 原样返回 —— 因为 `2` 在字符串里没有出现（`one-two-three` 里没有数字），
  替换语法同样「匹配不上就什么都不做，且不报错」。
- `${v:off:len}` 越界给空串（`${v:6:2}`，`hello` 只有 5 个字符），不报错。
  这跟 C 里数组越界是两种世界观：bash 这里**没有 UB**，最坏结果是「空字符串」，
  而空字符串传下去就是你的命令少了一个参数（第 22 节）。
- **`${v: -3}` 里那个空格是语法的一部分。** 少打一个空格就是 `${v:-3}`，
  第 16 节的默认值语法，于是 `v` 有值就给你整个 `abcdef`（实测第二格）。
  这是本章最贵的一类 bug：语法完全合法、结果完全不同、一行报错都没有。
- 想要「从倒数第 N 个开始」又嫌空格容易丢，可以写算术形式 `${v:0-3}`（实测第一格 `def`），
  或直接塞表达式 `${v:( 1 + 1 ):2}`（`cd`）—— 冒号后面的位置本来就是算术上下文，
  所以 `$(( ))` 在这里是多余的。
- `${v:3:0}` 给空串（长度 0），说明 len 可以是 0，而不是「不给 len 就取到末尾」的另一种拼错。
- 删除就是「替换成空」：`${v/./}` 删掉第一个点、`${v//./}` 删掉所有点。

> ★ 结论：三套花括号语法长得像但互不相干 —— 短横是默认值、斜杠是替换、冒号加数是截取。
> 写负数偏移永远留那个空格，或者干脆用 `${v:0-3}`。

### 第 19 节 · 数组与关联数组：`[@]`、`${!arr[@]}`、`${#arr[@]}`、切片

```
$ a=(零 一 二); echo "[${a[@]}] 长度=${#a[@]} 下标=[${!a[@]}] a1=[${a[1]}] a9=[${a[9]-没赋这个值}] 而 ${a}=[${a}]"
[零 一 二] 长度=3 下标=[0 1 2] a1=[一] a9=[没赋这个值] 而 零=[零]
[退出码 0]

$ a=(零 一 二); a[5]=五; echo "[${a[@]}] 长度=${#a[@]} 下标=[${!a[@]}] ← 稀疏数组"
[零 一 二 五] 长度=4 下标=[0 1 2 5] ← 稀疏数组
[退出码 0]

$ a=(x "" z); bash seg.sh "${a[@]}"
参数个数=3
  1: [x]
  2: []
  3: [z]
[退出码 0]

$ a=(x "" z); bash seg.sh ${a[@]}
参数个数=2
  1: [x]
  2: [z]
[退出码 0]

$ a=(a b c d); printf "<%s>" "${a[@]:1:2}"; echo "   ← 数组切片"
<b><c>   ← 数组切片
[退出码 0]

$ a=(1 2); b=("${a[@]}" 3); echo "拼接：[${b[*]}] 长度=${#b[@]}"
拼接：[1 2 3] 长度=3
[退出码 0]

$ e=(); echo "空数组长度=${#e[@]}"; set -u; echo "[${e[@]}] 在 set -u 下也不炸（bash 4.4 以后修好了这个坑）"
空数组长度=0
[] 在 set -u 下也不炸（bash 4.4 以后修好了这个坑）
[退出码 0]
```

四个必记点，都在上面的原文里：

1. **光秃秃的 `${a}` 只是 `a[0]`**（第一行最后一格给 `零`）。很多人以为它等于 `${a[*]}`，
   实测差很远。`${a}` 和 `${a[0]}` 同值。
2. **数组是稀疏的**：`a[5]=五` 之后长度是 4（不是 6），`${!a[@]}` 给 `0 1 2 5`。
   所以「遍历数组」应该遍历 `"${!a[@]}"`（下标）或 `"${a[@]}"`（值），不要 `for ((i=0;i<=${#a[@]};i++))`
   这种按序号数法 —— 它会撞上没赋值的洞。
3. **`"${a[@]}"` 是「一个元素一个词」的唯一写法**：第三、四行只差引号，
   带引号保住那个空元素（3 个词，第二格 `[]`），不带引号空元素直接掉地上（2 个词）。
   这就是第 11 节 `"$@"` 规则的数组版。
4. **切片 `"${a[@]:1:2}"` 从下标 1 取 2 个**，输出 `<b><c>`。
   注意是「个数」不是「结束下标」（跟 C 的指针算术不一样，跟 Python 的 `[1:3]` 也不一样）。

关联数组（`declare -A`，bash 4+，本章是 5.3）：

```
$ declare -A m; m[苹果]=1; m[香蕉]=2; echo "取值=[${m[苹果]}] 键=[${!m[@]}] 数量=${#m[@]}"
取值=[1] 键=[香蕉 苹果] 数量=2
[退出码 0]

$ declare -A m; m[乙]=2; m[甲]=1; for k in "${!m[@]}"; do echo "键=[${k}] 值=[${m[$k]}]"; done | sort
键=[乙] 值=[2]
键=[甲] 值=[1]
[退出码 0]

$ declare -A m; m["带 空 格"]=ok; echo "[${m[带 空 格]}] 下标里的空格不用转义"
[ok] 下标里的空格不用转义
[退出码 0]
```

- `${!m[@]}` 给的是**键**，`${#m[@]}` 给的是**键的个数** —— 和索引数组同一套语法。
- **键的顺序不保证**（第一行 `香蕉 苹果` 就是你插入顺序的反面之一；bash 内部是哈希表）。
  要顺序遍历就自己排：第二行 `| sort`（demo 的 locale 是 `C.UTF-8`，所以按字节序排，
  中文键的顺序是按 UTF-8 字节比的，不是拼音/笔画 —— 需要中文顺序请换思路，比如自己编号）。
- 下标里的空格在关联数组里是**普通字符**（第三行），不需要转义或加引号；
  但**取值时**要写 `${m[$k]}`，这里 `$k` 是变量，值是 `带 空 格` 也不会被切开 ——
  算术/下标上下文和分词是两回事（工序 4 只切命令行里的词，不切 `${m[...]}` 里面的下标）。

> ★ 结论：`[@]` 系列永远配 `"..."` 一起写 —— `"${arr[@]}"`、`"${!arr[@]}"`；
> `${#arr[@]}` 是元素数、`${!arr[@]}` 是下标/键、`${arr}` 只是第 0 个。
> 关联数组无序，要顺序自己 `sort`。

### 第 20 节 · 算术：`$(( ))` 是文本，`(( ))` 是命令且有退出码

```
$ echo "整除、取模、负数、进制：$((7/2)) $((7%3)) $((-7/2)) $((16#ff)) $((2#1010)) $((0x1f))"
整除、取模、负数、进制：3 1 -3 255 10 31
[退出码 0]

$ a=2; b=3; echo "里面写变量不用带美元符：$((a*b))；带上也一样能算：$(( $a + $b ))"
里面写变量不用带美元符：6；带上也一样能算：5
[退出码 0]
```

只有整数。`7/2` 得 3（截断不是四舍五入），`-7/2` 得 -3（向零截断）。
进制三种写法：`16#ff`（任意 2~36 进制）、`2#1010`、`0x1f`（C 风格十六进制）。
`$(( $a + $b ))` 那种带美元符的写法能跑，但多余：算术上下文里名字直接用，值自动代入。

**本节的核心是退出码**，因为它和 C 的直觉完全相反：

```
$ ((0)); echo "((0)) 的退出码=[$?]"
((0)) 的退出码=[1]
[退出码 0]

$ [ 0 ]; echo "[ 0 ] 的退出码=[$?]"
[ 0 ] 的退出码=[0]
[退出码 0]

$ i=0; ((i++)); echo "i=[$i]，但 ((i++)) 的退出码=[$?]"
i=[1]，但 ((i++)) 的退出码=[1]
[退出码 0]

$ i=0; ((++i)); echo "i=[$i]，((++i)) 的退出码=[$?]"
i=[1]，((++i)) 的退出码=[0]
[退出码 0]
```

- `((表达式))` 是**命令**，退出码规则是「表达式的值不等于 0 → 返回 0（成功）；等于 0 → 返回 1（失败）」。
  而 C 里 `0` 是 false、非 0 是 true；bash 退出码里 `0` 是成功。**两者刚好反着。**
- `[ 0 ]` 是另一条命令（`test`）：参数「0」是个非空字符串 → 真 → 退出码 0。
  所以「同一个字面量 0，`(( ))` 退 1、`[ ]` 退 0」，这是本节唯一「看起来同形、结果相反」的一对。
- 后置自增 `((i++))` 的值是**自增前**的 `i`（0）→ 退出码 1；前置 `((++i))` 的值是自增后的 `i`（1）→ 退出码 0。
  `i` 两次都变成了 1，**只有退出码不一样**。所以在 `set -e` 的脚本里 `((i++))` 从 0 开始会当场把脚本带走。
  三种活法：`((i++)) || true`、`i=$((i+1))`、`((++i))`。第 08 章讲错误处理时还会回到这一格。

非数字与错误文本：

```
$ x=abc; echo "非数字的变量在算术里当 0：结果 $((x + 1))"
非数字的变量在算术里当 0：结果 1
[退出码 0]

$ echo $((1/0))
bash: line 1: 1/0: division by 0 (error token is "0")
[退出码 1]

$ echo $((3 + ))
bash: line 1: 3 + : arithmetic syntax error: operand expected (error token is "+ ")
[退出码 1]

$ let "y = 3 * 2"; echo "let 也能算：y=[$y]（但 let 的引号和空格规则更绕，本书不推荐）"
let 也能算：y=[6]（但 let 的引号和空格规则更绕，本书不推荐）
[退出码 0]
```

`x=abc` 参与算术被当 0 —— 这是「安静错误」的又一例：如果你的数字来自一个拼错的名字（第 22 节），
算术不会告诉你，它直接当 0。
除零和语法错误都会停下**这一条命令**（不是整个脚本，除非 `set -e`），报错文本里
`error token is "…"` 会把出事的那一段引出来，很有用。
`let` 也支持，但它的参数还要再过分词（`let a=1+2` 和 `let "a = 1 + 2"` 行为不同），
本书统一用 `(( ))` 和 `$(( ))`。

> ★ 结论：bash 的 `(( ))` 把「真值」和「退出码」绑在一起且方向相反。
> 写算术时想「值」，写 `if`/`&&` 时想「退出码」，`((i++))` 是唯一一个两者会咬人的表达式。

### 第 21 节 · 自动变量逐个实测

```
$ true; echo "成功的问号值是 [$?]"; false; echo "失败的问号值是 [$?]"; nosuchcommand02; echo "命令不存在的问号值是 [$?]"
成功的问号值是 [0]
失败的问号值是 [1]
bash: line 1: nosuchcommand02: command not found
命令不存在的问号值是 [127]
[退出码 0]

$ echo "bash -c 起的这个进程：双美元=[$$] BASHPID=[$BASHPID]"
bash -c 起的这个进程：双美元=[58455] BASHPID=[58455]
[退出码 0]

$ echo "外层双美元=[$$]；子 shell 里的双美元=[ $( (echo $$) ) ]；子 shell 里的 BASHPID=[ $( (echo $BASHPID) ) ]"
外层双美元=[58456]；子 shell 里的双美元=[ 58456 ]；子 shell 里的 BASHPID=[ 58460 ]
[退出码 0]

$ sleep 0.05 & pid=$!; echo "后台进程的叹号值是 [$pid]（本脚本自己 fork 的，收尾用 wait）"; wait $pid; echo "wait 它的退出码是 [$?]"
后台进程的叹号值是 [58462]（本脚本自己 fork 的，收尾用 wait）
wait 它的退出码是 [0]
[退出码 0]

$ printf "%s\n" alpha beta; echo "上一条命令的最后一个词（下划线变量）是 [$_]"
alpha
beta
上一条命令的最后一个词（下划线变量）是 [beta]
[退出码 0]
```

进程号这一格是本章唯一一个和第 01 章（谁在跑）连起来的地方：

- `$$` 是**当初启动的那个 shell** 的进程号，子 shell 里读它**不变**（第三段实测：外层 58456、
  子 shell 里的 `$$` 还是 58456）。
- `$BASHPID` 是**当前这个** bash 实例的真进程号，子 shell 里就变了（58460）。
  所以「给临时文件起名要用进程号」时，`$$` 够用；跨 `()`/管道还要各自唯一，就得用 `$BASHPID`。
- `$!` 是「最近一个放到后台的作业的 pid」，实测配合 `wait $pid` 收尸；
  demo 只 `sleep`，只碰自己 fork 的进程。
- `$_` 是**上一条命令展开后的最后一个参数**（不是「本脚本」，也不是「上一个字符」）。
  它跟着上一条命令走，取值随时变 —— 想用它做判断前先 `echo` 一次。

脚本内部这一堆：

```
$ bash vars.sh alpha "beta gamma"
$0      = [vars.sh]
$1      = [alpha]
${2-}   = [beta gamma]
$#      = [2]
$*     = [alpha beta gamma]
$@     = [alpha beta gamma ]
$-      = [hB]（脚本：非交互，所以字母串里没有 i）
$$     = [58464]  本进程 $BASHPID = [58464]  $PPID = [58248]
$LINENO 走到这里 = [20]
$BASH_VERSION = [5.3.9(1)-release]
[退出码 0]

$ echo "bash -c 里：0=[$0] 井号=[$#] 短横=[$-]"
bash -c 里：0=[bash] 井号=[0] 短横=[hBc]
[退出码 0]

$ bash --norc --noprofile -ic 'echo 同一个开关在交互 shell 里=[$-]' 2>/dev/null
同一个开关在交互 shell 里=[hiBHc]
[退出码 0]

$ echo "版本=[$BASH_VERSION] 系统类型=[$OSTYPE] 机器类型第一段=[${MACHTYPE%%-*}]"
版本=[5.3.9(1)-release] 系统类型=[linux-gnu] 机器类型第一段=[x86_64]
[退出码 0]
```

- `beta gamma` 带引号传给脚本 → `$#` 是 2 而不是 3：引号在调用方生效，参数边界就固定下来了。
  这是第 09 节规则的「正面用例」。
- `$*` 那格是 `alpha beta gamma`（3 个词粘成 1 个字符串），`$@` 那格我用
  `printf '%s '` 逐个打印，所以尾巴上多一个空格 —— 两种打印方式的区别，别当成数据不同。
- `$0` 在脚本里是 `vars.sh`（**你怎么被叫起来的**，不是常量；第 01 章实测 `./x.sh` 时它是 `./x.sh`），
  在 `bash -c` 里是 `bash`。
- `$-` 是「当前 shell 的开关字母串」：`bash -c` 实测 `hBc`，脚本里 `hB`，加了 `-i` 才有 `i`（还有 `m`）。
  想知道自己是不是交互模式，看 `$-` 比看 tty 更直接。
- `${MACHTYPE%%-*}` 顺手复习第 17 节：从右剥最长 `-*` 匹配，把 `x86_64-pc-linux-gnu` 收成 `x86_64`。

> ★ 结论：三个最容易讲错的一一实测过 —— `$_` 是「上一条命令最后一个参数」；
> `$-` 是「开关字母串」；`$$` 在子 shell 里不变，要真进程号用 `$BASHPID`。

### 第 22 节 · 什么时候安静得让你踩坑：拼错名字、空 glob、传参变形记

```
$ TARGET_DIR=data; echo "设过的是 [$TARGET_DIR]；拼错名字得到 [$TARGET_DI]，一句报错都没有"
设过的是 [data]；拼错名字得到 []，一句报错都没有
[退出码 0]

$ bash unbound.sh
设过的变量读得到：[data]
unbound.sh: line 18: TARGET_DI: unbound variable
[退出码 1]
```

同一个 bug，两种世界：默认 `bash` 把未设变量当空字符串（第 16 节表里那一行），
`set -u` 之后立刻 `unbound variable` + 停在那一行（退出码 1）。
注意报错文本的三段结构：**文件: 行号: 变量名: unbound variable** —— 
它是 bash 自己造的（跟 `command not found` 同一族），所以固定、可核对。

`set -u` 的正确用法（本章的 demo 里没全局开，因为它会让一些演示故意失败）：
放在子 shell 里只测一段，或者只在脚本开头开、并且知道空数组在 bash 5.3 是安全的
（第 19 节实测 `set -u` + `"${e[@]}"` 不炸，这个坑在 4.4 之前是真的会炸）。

传参变形记 —— `passing.sh` 用同一个值 `my file.txt` 走七种写法，全部量给 `seg.sh`：

```
$ bash passing.sh
原始值：v=[my file.txt]（里面有一个空格，文件名在真实世界里完全合法）

① bash seg.sh $v     —— 裸用，会被切
参数个数=2
  1: [my]
  2: [file.txt]

② bash seg.sh "$v"  —— 整体加引号，一个词
参数个数=1
  1: [my file.txt]

③ bash seg.sh ${v}  —— 只加花括号不加引号：和 ① 完全一样
参数个数=2
  1: [my]
  2: [file.txt]

④ bash seg.sh "${v}" —— 花括号 + 引号：和 ② 完全一样
参数个数=1
  1: [my file.txt]

⑤ 中间转一手：set -- $v 把它切成参数，再用 "$@" 原样转发
   set -- 之后参数个数 = 2（切成了几段就固定成几段了）
参数个数=2
  1: [my]
  2: [file.txt]

⑥ 命令替换也一样：替换结果先分词，再进命令行
参数个数=2
  1: [a]
  2: [b]
参数个数=1
  1: [a b]

⑦ 想要「一个词」就加引号，想要「多个词」才裸写 —— 反过来越界就会出事：
参数个数=2
  1: [my]
  2: [file.txt]
[退出码 0]
```

这张表就是本章的总结算：

- ① vs ②：一对引号改变词数 —— 全章的核心事实。
- ③ vs ①：**花括号不改变任何东西**，`${v}` 和 `$v` 在分词/通配面前完全等价。
  加花括号只是为了「把边界写清楚」（后面紧跟字符时）和配合 `:-`/`#`/`%`/`:off` 这些语法。
- ⑤：`set -- $v` 先切，切成几段就固定成几段了；再 `"$@"` 转发，转发的是**已经切好的两段**。
  所以「用 `"$@"` 就安全」只在**边界已定之后**成立 —— 定边界那一步用了裸变量一样出事。
- ⑥：命令替换的结果同样过分词（`$(printf 'a b')` 两个词），加引号才是一个词。
- ⑦：`${v% *}` + `${v##* }` 主动切成两个词（`my` 和 `file.txt`）—— 
  这证明「多个词」是可以**明确要**的，靠的是剥皮语法，不是靠裸变量碰运气。

最后一个「空字符串陷阱」，写测试时天天见：

```
$ v="a b"; [ -n $v ] && echo "第一个：真"; x=""; [ -n $x ] && echo "x 明明是空字符串，但裸写时空判断却说它是真 ← 空字符串被切没了，只剩一个参数"
bash: line 1: [: a: binary operator expected
x 明明是空字符串，但裸写时空判断却说它是真 ← 空字符串被切没了，只剩一个参数
[退出码 0]

$ x=""; [ -n "$x" ] || echo "带引号时才是正常的假"
带引号时才是正常的假
[退出码 0]
```

两条合起来才是完整教训：

- `[ -n $v ]`（`v="a b"`）展开成 `[ -n a b ]` → 三个参数 → `test` 看不懂 → 
  `bash: line 1: [: a: binary operator expected`（**外部命令 `[` 在抱怨**，退出码非 0，
  于是 `&&` 后面那句没跑，屏幕上少一行）。
- `[ -n $x ]`（`x=""`）展开成 `[ -n ]` → **一个参数** → `test` 的规则是「只有一个参数时，
  参数非空即为真」，`-n` 本身是非空的 → 判真。这就是「明明是空却说是真」。
- `[ -n "$x" ]` → `[` 收到两个参数，走「判断字符串长度」的正路 → 假。

所以第 03 章会直接告诉你：**测试的变量一律加引号**，或者改用 `[[ ]]`（它自己处理词数）。
同一节还留了一条：glob 没命中时循环照跑一次，拿到字面量 ——

```
$ cd empty; for f in *.tmp; do echo "glob 没命中也进循环，拿到的是 [$f]"; done
glob 没命中也进循环，拿到的是 [*.tmp]
[退出码 0]
```

> ★ 结论：本章三条「安静」的根源 —— 变量没设 → 空字符串；glob 没命中 → 字面量；
> 空字符串裸用 → 参数变少。它们凑在一起就是那句「脚本没报错，但结果不对」。

## 这章的坑（照单全收版）

按「症状 → 根因 → 修法」写，全部对应上面演过的原文。

| # | 症状 | 根因（工序） | 修法 |
|---|---|---|---|
| 1 | `rm *.tmp` 抱怨 `cannot remove '*.tmp'` | 工序 5：无匹配留字面量（13 节） | `shopt -s nullglob`，或 `for f in *.tmp; do [ -e "$f" ] && rm -- "$f"; done`，或 `find -maxdepth 1 -name '*.tmp' -delete` |
| 2 | `for f in $(ls)` 把 `my file.txt` 当两个文件 | 工序 4（12 节写法 A） | `for f in *.txt` / 数组 / `find -print0 \| IFS= read -r -d ''` |
| 3 | `$cmd` 里的引号变成参数内容 | 工序 6 只处理源码（09 节） | 用函数，或数组 + `"${arr[@]}"` |
| 4 | `echo $v` 把变量值当模式用了 | 工序 5（03 节） | `echo "$v"` |
| 5 | `${v: -3}` 写成 `${v:-3}`，拿到整个字符串 | 默认值 vs 截取（18 节） | 留空格，或用 `${v:0-3}` |
| 6 | `${v%%/*}` 给空串 | 从右最长匹配 + 路径以 `/` 开头（17 节） | 用 `${v%/*}` |
| 7 | 函数/脚本转发参数少一个 | 用了 `"$*"` 或裸 `$@`（11 节） | 一律 `"$@"` |
| 8 | `IFS=:` 前缀赋值不生效 | 分词在当前 shell、调用前（10 节规则④） | 单独一句 `IFS=:`，或 `( IFS=:; ... )`，或 `while IFS=: read` |
| 9 | 变量名打错，空字符串一路传到底 | 默认不设 `set -u`（22 节） | 脚本开头 `set -u`（注意数组在 bash 4.4+ 安全，19 节） |
| 10 | `((i++))` 让 `set -e` 脚本退出 | `(( ))` 是命令、0→退 1（20 节） | `((++i))` / `i=$((i+1))` / `((i++)) \|\| true` |
| 11 | `${arr}` 以为拿到整个数组 | 它只是 `${arr[0]}`（19 节） | `"${arr[@]}"` |
| 12 | glob 结果的顺序换机器就变 | 工序 5 按 locale 排序（14 节） | 需要顺序自己 `sort`，必要时 `LC_ALL=C` |
| 13 | `echo "a\nb"` 打出反斜杠 n | 双引号里 `\n` 不是换行（06 节） | `printf 'a\nb\n'` 或 `$'a\nb'`（08 节） |
| 14 | 把 `~` 存进变量后 `cd` 失败 | 工序 2 只在词首且未加引号时生效（02 节） | 存 `$HOME`，不要存 `~/...` |
| 15 | 反引号嵌套报错难查 | 自相似字符（07 节） | 全用 `$( )` |
| 16 | `[ -n $x ]` 对空串判真 | 空值被切没，`test` 只剩 1 个参数（22 节） | `[ -n "$x" ]` 或 `[[ -n $x ]]` |
| 17 | 报错文本忽中忽英，README 核对不上 | `LANGUAGE` 优先于 `LC_ALL`（00 节） | 固定 `LANGUAGE`/`LC_ALL`，或按语言环境分别取证 |

三个**常见误判**（我自己写 demo 时也差点踩）：

1. 「加了花括号就安全」—— 错，③ 和 ① 完全一样（22 节）。花括号是给语法用的，不是给保护用的。
2. 「`set -x` 里看到引号 = 我源码里有引号」—— 错，引号是 bash 现加的（04 节）。
3. 「`IFS=x 命令` 会让命令按 x 分词」—— 错，它只影响被调命令的环境（10 节规则④）。

## 自检问题

每题都能在本章找到原文；答不出来就回到对应节再看一次那一段输出。

1. 同一条命令行里，`echo {a,b}$v` 和 `echo $v`（`v='{x,y}'`）为什么后者不打散成两个词？
   <details><summary>答案</summary>花括号是工序 1，只认源码里的字面文本且只做一次；
   `$v` 在工序 3 才换成 `{x,y}`，那时花括号的机会已经过去了（第 02 节实测 `{x,y}` 原样输出）。
   同理 `{$n..$m}` 造不出序列。</details>

2. `v="a b c"`，`bash seg.sh $v`、`bash seg.sh "$v"`、`bash seg.sh ${v}` 各拿到几个词？
   <details><summary>答案</summary>3、1、3 —— `${v}` 和 `$v` 完全等价，
   花括号不提供任何保护（第 22 节 passing.sh ①②③）。</details>

3. `IFS` 里放了冒号，`IFS=: 命令 $v` 这种前缀写法能让 `$v` 按冒号分词吗？
   <details><summary>答案</summary>不能。分词发生在当前 shell 把命令调起来**之前**，
   用的是当前 shell 的 `IFS`（第 10 节规则④，两条实测都还是按空格切成 3 个词）。
   要改就单独一句 `IFS=:`，或 `( IFS=:; ... )`。</details>

4. `"$*"` 在 `IFS=:` 下把 `a b`、`c`、空串、`d` 四个参数粘成什么？
   <details><summary>答案</summary>`a b:c::d`（1 个词）。用 `IFS` 的**第一个字符**当胶水，
   空的那格也在，只是空的（第 11 节第二块）。</details>

5. 为什么 `for f in $(ls)` 比 `for f in *.txt` 危险？危险在哪一步？
   <details><summary>答案</summary>`$(ls)` 的结果要过分词（工序 4）和通配（工序 5），
   带空格的文件名被切成两个词、带 `*` 的名字被当模式再匹配一次；全程退出码 0
   （第 12 节写法 A 的 `[my]`、`[file.txt]`）。</details>

6. 目录里一个 `.tmp` 都没有，`for f in *.tmp; do echo "$f"; done` 循环体跑几次？打印什么？
   <details><summary>答案</summary>1 次，打印字面量 `*.tmp`（第 13 节）。
   开 `nullglob` 才变成 0 次，开 `failglob` 则整条命令当场报错、`rm` 根本没被调起来。</details>

7. `${v%%/*}` 作用在 `/tmp/a/b/c.tar.gz` 上给什么？为什么？
   <details><summary>答案</summary>空串（第 17 节实测）。`%%` 从**右**剥「`/` 加任意内容」的最长匹配，
   而字符串以 `/` 开头，最左边那个斜杠也能当起点 → 整个被吃掉。想要 dirname 用 `${v%/*}`。</details>

8. `${v: -3}` 和 `${v:-3}` 的区别？写错会怎样？
   <details><summary>答案</summary>前者取后 3 个字符，后者是「v 没设就用 3」的默认值语法（第 18 节实测：
   `abcdef` 全给你）。语法都合法、都不报错，所以是最贵的一类 bug。</details>

9. `((0))` 和 `[ 0 ]` 的退出码分别是多少？`((i++))`（`i=0`）呢？
   <details><summary>答案</summary>1、0、1（第 20 节）。`(( ))` 是命令：值≠0 → 退 0，值=0 → 退 1；
   后置自增的值是自增前的 0，所以退 1，`i` 却已经变成 1。`set -e` 脚本里这一步会带走脚本。</details>

10. `$$` 和 `$BASHPID` 在子 shell 里表现有什么不同？
    <details><summary>答案</summary>`$$` 不变（始终是最初那个 shell 的 pid），`$BASHPID` 变
    （第 21 节实测 58456 / 58456 / 58460）。要「每个子进程都不同」只能用后者。</details>

11. `set -u` 之后 `${e[@]}`（`e=()` 空数组）会炸吗？
    <details><summary>答案</summary>bash 5.3 上不会（第 19 节实测），这个坑在 bash 4.4 之前是真的。
    版本相关 —— 所以第 00 节要先确认版本。</details>

12. `bash seg.sh "$@"` 和 `bash seg.sh $@` 在参数里有空串时差在哪？
    <details><summary>答案</summary>带引号保住空参数（一格不少），裸用时空的那格展开成空文本、
    被分词吃掉，参数个数直接少 1（第 11 节第一块：`[a b][c][][d]` vs `[a][b][c][d]`）。</details>

## 本章没演 / 没验证

诚实清单。下面这些**要么本机没跑到、要么只跑了一种情形**，不要当成结论抄走：

1. **`**` 的递归能力**：第 14 节沙箱里只造了一层 `sub/`，所以 `**/inner.txt` 开 `globstar` 前后
   输出一模一样（都是 `sub/inner.txt`）。**两层以上目录里 `**` 到底给出什么、怎么排序，本章没演。**
2. **`${v:?}` 在 `bash -c` 里退 127、在脚本里退 1**：两个数字都是实测，
   「为什么 `bash -c` 场景是 127」没有从 bash 内部机制去查，只按现象记录。
3. **`${!prefix@}` 的输出顺序**：本机给的是定义顺序（`BOOK_A BOOK_B`），
   但 bash 文档没保证顺序，所以本章没验证「换一种定义顺序/换机器会不会变」。别拿它当排序用。
4. **关联数组的键序**：第 19 节只演了「不保证顺序」（`香蕉 苹果` 一例），
   哈希内部怎么排、什么时候会变，本章没验证；要顺序请自己 `sort`。
5. **`LANG`/`LC_ALL`/`LANGUAGE` 的完整优先级**：第 00 节只测了「`LANGUAGE=C` 能把 `LC_ALL=zh_CN.UTF-8` 顶回英文」
   这一条，其余组合（`LANGUAGE=zh_CN`、`LC_MESSAGES` 单独设）没测。
6. **`${var@Q}`（bash 4.4+ 的引用展开）与 `@U`/`@P` 这一族**：本章一个字都没跑，纯没验证。
7. **`shopt -s expand_aliases` 和 rc 的联动**：那是第 01 章的内容，本章只用到 `nullglob`/`failglob`/`globstar` 三个开关。
8. **`$'...'` 在 dash 下的行为**：本章只写了「第 01 章实测：dash 原样留下这一串（不报错但不展开）」，
   原文在那一章的捕获里，本章没重跑。
9. **`16#ff` 之类进制的上限、非法进制的报错文本**：只演了成功的 `16#ff`、`2#1010`、`0x1f`，没演失败样例。
10. **`IFS` 含多个非空白字符（例如 `IFS=",:"`）时的行为**：只演了单一字符 `:`。
11. **`read -r -d ''` 在别的 `find` 实现上的差异**：本机 `find` 是 **GNU findutils 4.10.0**
    （`find --version` 当场可查，本机 `ls`/`wc` 那批才是 uutils），`-print0` 正常；
    uutils 那套 Rust 实现里的 `find`（如果哪台机器装了）本章没交叉验证过。
12. **换 bash 版本（比如 4.2、5.0）后哪些结论会变**：只知道 `set -u` + 空数组那条在 4.4 前后不同，
    其余没做版本矩阵。

## 怎么跑这章的 demo

```bash
cd bash-handbook/02-words-and-expansion
bash -n demo.sh          # 只看语法过不过（第 01 章讲过它不执行任何命令）
bash demo.sh             # 全跑一遍，跑完自动删沙箱
bash demo.sh --keep      # 跑完保留沙箱并打印路径，可以进去接着敲
bash demo.sh > out.txt   # 重定向时自动关颜色（demo 里判 [ -t 1 ]）
```

安全边界（写在 `demo.sh` 头注释里，逐条对应）：

- 所有写操作只在 `mktemp -d "${TMPDIR:-/tmp}/bash02-XXXXXX"` 里；`trap cleanup EXIT` 只删自己刚建的这一个。
  仓库目录**只读**，第 23 节用 `find . -maxdepth 1 -type f | sort` 自证。
- 碰的 `rm` 全部是沙箱里本章自己 `touch` 出来的 `*.tmp`（而且故意让它不命中，见第 13 节）。
- 不改 `~/.bashrc`、`~/.profile`、`~/.config`、`/etc`。需要「另一种 shell 环境」时用
  `bash -c`（非交互）或 `bash --norc --noprofile -ic`（第 21 节）起新进程，不碰你的 rc。
- 不起监听端口、不联网、不装包：`shellcheck` 本机没有，就如实打印「本机没有」（第 00 节）。
- 唯一的后台进程是第 21 节那个 `sleep 0.05`，用 `$!` 记下、`wait` 收尾；不 kill 任何别人 fork 的进程。
- 屏幕上不打印你机器上的绝对路径：要列真实目录用的是 `runc_at`，它只打目录名 + 相对命令（第 23 节）。
- **demo 故意没有 `set -e`**：本章要看的就是「报错原文 + 后面继续跑」；
  `set -u` 的价值单独放在第 22 节，用子进程跑 `unbound.sh` 演示，不污染 demo 主体。

## 术语小抄

| 术语 | 本章的人话定义 |
|---|---|
| 词（word） | bash 语法上切开的一段，最终可能变成一个参数。「几个词」= 程序拿到几个参数 |
| 展开（expansion） | 把 `$v`、`$(..)`、`{a,b}`、`*.txt` 这些「写法」换成「内容」的总称 |
| 工序/步（step） | 上面那张流水线图里的六道闸，顺序固定 |
| 分词（word splitting） | 工序 4：用 `IFS` 把展开结果再切一刀；只切「展开出来的内容」 |
| `IFS` | 内建变量，默认空格+tab+换行；空字符串=不切；`unset IFS`=回默认 |
| 通配 / glob（pathname expansion） | 工序 5：把带 `* ? [..]` 的词拿去问文件系统；不命中则原样留着 |
| 引号删除（quote removal） | 工序 6：把源码里的引号本身抹掉；被保护的内容不参与 4、5 |
| 字面量（literal） | 「这串字符就是它自己」，不含语法作用 |
| 模式（pattern） | 含 `* ? [..]` 的、可以被文件系统匹配的那类字符串 |
| 参数展开（parameter expansion） | `${...}` 这一大家族：默认值、剥皮、替换、截取、长度、间接、`@`/`*` |
| 位置参数 | `$1 $2 … $9 ${10}`；`$#` 个数、`$*`/`$@` 全部、`set --` 可以重写它们 |
| 特殊参数 | `$?` 上一条退出码、`$$` 启动 shell 的 pid、`$!` 最后一个后台 pid、`$_` 上一条最后参数 |
| 稀疏数组 | 下标可以不连续（`a[5]=五` 后长度 4，下标 `0 1 2 5`） |
| 关联数组 | `declare -A`，键是任意字符串、**无序** |
| ANSI-C 引用 | `$'...'`：把 `\n \t \xHH \e` 换成真字符，且不认变量 |
| 跟踪（`set -x`） | 打印「展开分词之后、真正执行之前」的那一行；引号是它现加的 |
| `nullglob`/`failglob` | glob 不命中时的两种改法：消失 / 当场报错 |
| `globstar` | 打开后 `**` 才表示递归跨目录 |

## 章末一页纸

### ① 展开顺序表（背这一张就够，其余都能推）

| 顺序 | 做什么 | 需要文件存在吗 | 结果还会被后面几步处理吗 |
|---|---|---|---|
| 1 | 花括号 `{a,b}`、`{1..9}`、步长 `{1..10..3}` | ❌ | ✅ 会被分词 + 通配 |
| 2 | 波浪线 `~`、`~user` | ❌（只查家目录） | ✅ 同上 |
| 3 | 参数/命令/算术展开 `$v` `${v#..}` `$(..)` `` `..` `` `$((..))` | ❌ | ✅ 会被分词 + 通配 |
| 4 | 分词（按 `IFS`） | ❌ | — |
| 5 | 通配 `* ? [..]` | ✅ 必须问文件系统 | — |
| 6 | 引号删除 | ❌ | 它自己是最后一道 |
| 7 | （之后才是）找命令、传参数 | — | 不再有任何「重来」 |

三条最容易忘的：**第 3 步的结果要过第 4、5 步**；**第 5 步不命中就留字面量**；**第 6 步只管源码里的引号**。

### ② 该不该加引号

| 你手上的东西 | 写法 | 为什么 |
|---|---|---|
| 变量（值可能是文件名/路径/任意文本） | `"$v"` | 裸用会过分词（第 09 节实测 3 vs 1） |
| 数组全部元素 | `"${arr[@]}"` | 只有它保住空元素和带空格的下标（第 19 节 3 vs 2） |
| 数组切片 | `"${arr[@]:1:2}"` | 同上，切片也要带引号（第 19 节） |
| 参数转发 | `"$@"` | 唯一「一格不少」的写法（第 11 节四格矩阵） |
| 命令替换结果 | `"$(cmd)"` | 结果照样过分词（第 22 节 passing ⑥）；顺手读 `$?` 才知道成没成 |
| **故意**要当模式用 | `$pat` 或 `"${!arr[@]}"` 之外裸写 `*.txt` | glob 写在**源码**里才有意义：`for f in *.txt`（第 12 节写法 B） |
| 你确实想切成多个词 | `${arr[*]}` 之外，用剥皮/截取主动切：`"${v% *}" "${v#* }"` | 别靠裸变量碰运气（第 22 节 passing ⑦） |
| `[[ ]]` 右边的模式 | `[[ $f == *.txt ]]`（`*.txt` **不加**引号） | 加了引号就变字面比较（第 03 章细讲） |
| 单个词的排版/缩进 | 交给 `printf` | 空格在工序 4 里活不下来（第 09 节） |

一句话版：**90% 的情况一律加引号；只有「源码里直接写的 glob」和「故意要切多个词」这两类才裸写。**

### ③ 三条铁律

1. **引号加在源码上，不加在值里。** 变量值里的引号只是普通字符（第 09 节的 `["a]`）。
2. **「几个词」是可以当场量的，不用猜。** `printf '[%s]\n' "$@"` 或 `set -x` 各看一眼（第 01、04 节）。
3. **失败要响。** glob 不命中默认留字面量、未设变量默认给空串 —— 两个都是安静的，
   所以主动开 `nullglob`/`failglob`、`set -u`（第 13、22 节）。

### ④ 常见误判纠正（这一章实测打脸的清单）

| 网上常见说法 | 本机实测 |
|---|---|
| 「UTF-8 locale 下 `[a-z]` 会连大写一起吞」 | 不成立：`C`/`C.UTF-8`/`en_US.UTF-8`/`zh_CN.UTF-8` 四种下 `[a-z]*.txt` 全都只给小写开头那几个；locale 改的是**排列顺序**（第 14 节） |
| 「`set -x` 里能看到我写的引号」 | 引号是 bash 现加的，三种写法显示完全一样（第 04 节） |
| 「前缀赋值 `IFS=: cmd` 能改这条命令的分词」 | 不改，分词在调用前由当前 shell 完成（第 10 节规则④） |
| 「加花括号等于加保护」 | `${v}` 与 `$v` 在分词/通配上完全等价（第 22 节） |
| 「`echo -e` 到处能解释反斜杠」 | 这本书不用它：本机 `echo` 有三种实现，统一 `printf`（引用约定 + 第 08 节） |
| 「空数组在 `set -u` 下会炸」 | bash 5.3 实测不炸（4.4 之前才炸，第 19 节） |
| 「命令替换里失败了外面能感觉得到」 | 只有立刻读 `$?` 才知道；结果本身只是文本（第 07 节） |
