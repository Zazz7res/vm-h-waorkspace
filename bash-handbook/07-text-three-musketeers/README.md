# 第 07 章 · grep / sed / awk —— 单位是行、码是三态、方言不止一套

> 这一章只管三件事：**这三个工具手里拿的单位各是什么**、**它们交回来的退出码各自表不表结果**、
> **同一个写法换一套引擎会变成什么**。
> 下面每一行屏幕输出都不是人打的：它出自同一次 `bash demo.sh > ~/.cache/handbook-captures/bash07c.txt`
> （1339 行、25 节），正文里每一格都由脚本从那份**已定稿的捕获**里按行号原样搬出来 ——
> 人只负责写正文和选区间，所以严格校验天然为 0。
> 这台机器的底细：bash 5.3.9(1)-release，GNU grep 3.12，GNU sed 4.9，**awk 的真身是 mawk 1.3.4**，

> demo 一进来就把自己钉成 `LC_ALL=C.UTF-8`，所以**报错全是英文原文**（第 1 节当场钉给你看）。
>

## 本章在讲什么，以及为什么是这三条

前面几章你已经拿到两条规矩：**每句话只有一个退出码**（第 03 章）、
**展开与词表是看不见的手**（第 02、04 章）。现在把它们用到「处理文本」这三个工具上，
就会长出三条反直觉：

> **一、三个工具的单位是三种不同的东西，而它们的共同点是「一次只看得见一行」。**
> grep 给你**整行**（你要的是那一小段，它把整行连皮带骨端上来），`-c` 数的是**行**、`-o` 才数**段**；
> sed 手里的是一条**模式空间**，默认一行一条，被换行劈开的文本它一眼看不到 —— 没换成、退 0、文件一字未动；
> awk 手里的是一条**记录 + 一堆字段**，所以它是三家里唯一会「比大小、求和、按 key 拼表」的那个。
> 「明明写了却什么都没发生」的案发现场，九成在单位错位上。
>
> **二、三家只有 grep 的码表结果。** 命中 0、没命中 1、真出错 2 —— 三态；
> 而 sed 和 awk 的「没命中」照样是 **0**。于是「跑成功了」和「活干了」是两件事：
> 本章第 23 节把三张码表并排钉在屏幕上，第 20 节更狠 ——
> `FIELDWIDTHS` 在 mawk 上整行塞进 `$1`、`NF=1`、**rc=0**，一声不响。
>
> **三、同一个写法在四套引擎里是四种语言。** BRE / ERE / PCRE 装在一个 grep 里，靠开关选；
> `grep/sed` 是 GNU 的，`wc/sort/tr/cat` 是另一家（uutils）的，`awk` 是 mawk 的。
> 换方言时最大的坑**不是报错**，是安静地给你 0 行；比 0 行更阴的是给你**一行的错答案**
> （`\d` 在 ERE 里是字母 d，第 3 节第 4 格当场命中 `no digits here` 给你看）。

还有一条是这一章自己的方法论，贯穿全章：**屏幕上印的标签是人写的，命令真正吃进去的开关不会说谎**。
本章第 3 节的每一格都额外印一列「开关」，就是这个原因 —— 这一章在定稿前被抓到过一次
「标签写着 ERE、实际没传 `-E`」的假证据（作废的那份捕获留在原处当反面样本），
判据见第 3 节第 7 格和「这章的坑」第 0 条。

三条各成套，所以本章的排版也是三条线：第 3~8 节走 **grep**（方言 → 单位 → 用在管道和判断里）；
第 9~14 节走 **sed**（流水线 → 就地改的四个代价 → 管道里的单位错位）；
第 15~21 节走 **awk 与三家分工**（选型 → 数组与两份文件 → 字段与整行重建 → mawk 的缺件）；
第 22~25 节把三条线拧成一次综合演练、三张码表并排、对账、自证。

| 你想搞清楚的东西 | 本章用哪一节回答 | 一句话答案 |
|---|---|---|
| 这些结论换台机器还成立吗 | 第 1 节 | 先验明工具真身：awk 是 mawk，`wc/tr/cat` 是 uutils，不是 GNU 全家 |
| 三个工具各自手里拿的是什么 | 第 2 节 | grep 整行、sed 模式空间（一行）、awk 字段；最小证据各一条 |
| 抄来的一行命令为什么不响 | 第 3 节 | 九成是开关和方言不匹配：BRE 的 `\|` 到 ERE 变字面竖线，全是 0 行 0 句报错 |
| `\d` `\b` `\<` 到底谁认 | 第 3、5 节 | 本机 `\b` 三家都认；`\< \>` 只有 BRE/ERE 认；`\d` 到 ERE 是字母 d |
| 要「命中的那一段」怎么拿 | 第 5 节 | `grep` 给整行，`-o` 才给段；段永远不跨行、也不回头重叠 |
| 一行里出现三次，`-c` 报几 | 第 5 节 | 报 1。数行用 `-c`，数次数用 `-o \| wc -l`，两数之差就是同行多出来的次数 |
| 明明文件里有，grep 说没有 | 第 5 节 | 两种：跨行了（一次只看得见一行）、或者行尾有个 `\r` 把 `$` 占了 |
| `grep -c` 塞进 `[ ]` 为什么炸 | 第 7 节 | 数字是 stdout 上的**数据**：多文件变多行、文件不存在时 `[` 拿到空串，真错被翻成「没有命中」 |
| `|| echo 没找到` 错在哪 | 第 7 节 | 它把码 2（出错）和码 1（没有）一起接住，CI 绿着漏检 |
| 管道里 grep 上游报错，整条为什么退 0 | 第 7、13、14 节 | 默认只有**最后一环**的码说了算；`pipefail` 取最右非 0，也不是「每段都报」 |
| sed 为什么把每行都打了两遍 | 第 9 节 | 它默认每行结尾自动打印，`p` 是「再打一遍」；`-n` 才是「只打我说的」 |
| 一段话被换行劈开了怎么办 | 第 9 节 | sed 看不到跨行；`N` 主动把下一行拉进模式空间，或 `-z` 换个分隔符 |
| `sed -i` 到底动没动我的文件 | 第 11 节 | 它**换新文件**（inode 变），mode/属主可能变；备份还会被第二遍覆盖成上一版 |
| 没命中时 `-i` 退几 | 第 11 节 | 退 0。动手前先用不带 `-i` 的那一趟数一遍命中（这道守卫要先故意弄响一次） |
| `sed "s/a/A/" f > f` 为什么把文件清空 | 第 11 节 | 重定向先把 `f` 截成 0 字节，sed 才去读它 —— 而且整条退 0 |
| 管道三段各拿到什么 | 第 13 节 | 同一条管道，三环手里根本不是同一种东西；少一个换行符，下一环就把两行当一行 |
| 这个任务该给谁 | 第 15 节 | 挑「长得像」给 grep，改文给 sed，比大小/求和/两份文件拼给 awk |
| `NR==FNR` 是什么意思 | 第 16 节 | 两台计数器：`NR` 数总行，`FNR` 每换一个文件归零，相等就是「正在读第一个文件」 |
| 只是读一下不存在的键也会出事 | 第 16 节 | 会自己长出一个空元素，数组凭空 +1；只查不建要用 `(k in a)` |
| `a["x","1"]` 是二维数组吗 | 第 17 节 | 不是，是一个被 SUBSEP 粘起来的字符串键；姓名里带那个字节就撞键 |
| 改了 `$2` 为什么整行空白全没了 | 第 18 节 | 给字段赋值 = 标记整行待重建，打印时按 `OFS` 拼；`cat -A` 当场看得见 |
| gawk 的写法在 mawk 上 | 第 20 节 | `gensub/asort/strtonum` 会叫（rc=2）；`FIELDWIDTHS`、`/\s/` **不会叫**（rc=0 而活没干） |
| awk 能数大整数吗 | 第 20、21 节 | 走 double：过了 2^53 加 1 被吞；18 位 ID 一进算术就变尾数 |
| 同一件事三家各给什么码 | 第 23 节 | 三张表并排：「没命中」grep 给 1、sed 给 0、awk 给 0 |

## 1. 先把这三个工具的身份钉死

这一章所有「本机实测」都挂在这一节上。为什么先把工具的真身摊开？因为本章最容易骗人的就是 awk：
`/usr/bin/awk` 只是一个**别人家的马甲**，它背后是谁，得屏幕上见。

围栏第一行先给 bash 本身：

```
$ bash --version | head -1
GNU bash, version 5.3.9(1)-release (x86_64-pc-linux-gnu)
[退出码 0]
```

然后是本章真正关心的那一条 —— **每个命令名背后到底是哪个文件**：

```
$ for t in grep sed awk sort cat wc tr head find xargs; do printf "  %-6s → %s\n" "$t" "$(readlink -f "$(command -v "$t")")"; done
  grep   → /usr/bin/grep
  sed    → /usr/bin/sed
  awk    → /usr/bin/mawk
  sort   → /usr/lib/cargo/bin/coreutils/sort
  cat    → /usr/lib/cargo/bin/coreutils/cat
  wc     → /usr/lib/cargo/bin/coreutils/wc
  tr     → /usr/lib/cargo/bin/coreutils/tr
  head   → /usr/lib/cargo/bin/coreutils/head
  find   → /usr/bin/find
  xargs  → /usr/bin/xargs
[退出码 0]
# ★ 看第二列：本章的 grep/sed/awk 来自 /usr/bin，而 sort/cat/wc/tr/head 来自 coreutils 的另一套。
#   所以「GNU 家怎么行为」不能整体外推：三剑客是 GNU 的，配套的切行数字工具不是。
```

屏幕上第二列分成两拨：`grep / sed / awk / find / xargs` 在 `/usr/bin`，
而 `sort / cat / wc / tr / head` 在 `/usr/lib/cargo/bin/coreutils`。
这不是 trivia：本章后半段「`wc -l` 数的是换行符个数」「`tr` 按字节切中文」这些结论，
都发生在**另一家**的工具身上。

> **直觉以为「Linux 上这些命令都是 GNU 家的一套」**：屏幕上 awk 那一行写的是 `/usr/bin/mawk`，
> `wc` 那一行写的是 `coreutils/wc`。所以「GNU 文档怎么说」不能整体外推 —— 三剑客是 GNU 的，配套的切行数字工具不是。

版本号那一格，三家各报一次自己的身份：

```
$ grep --version | head -1; sed --version | head -1; awk --version | head -1
grep (GNU grep) 3.12
sed (GNU sed) 4.9
mawk 1.3.4 20260129
[退出码 0]
# 这几样本章一律按「本机没有」处理（装不装是另一件事，本章不装东西）：

$ for t in gawk sponge pcre2grep shellcheck; do printf "  %-11s %s\n" "$t" "$(command -v "$t" || echo 本机没有)"; done
  gawk        本机没有
  sponge      本机没有
  pcre2grep   本机没有
  shellcheck  本机没有
[退出码 0]
```

**屏幕上为什么是这些字**：`grep (GNU grep) 3.12`、`sed (GNU sed) 4.9` 两家都按 GNU 的格式报，
而 awk 报的是 `mawk 1.3.4 20260129` —— 它连「GNU awk」这四个字都不出现。
下面那四行是本章按「本机没有」处理的工具：`gawk`、`sponge`、`pcre2grep`、`shellcheck`。
没装就是没装，本章不装东西，所以凡是「gawk 才有的写法」都会被单独拿出来验它在不响的情况下能干出什么（第 20 节）。

`/bin/sh` 的真身也要钉，因为第 14 节要让同一根管道去撞它：

```
$ printf "  /bin/sh 的真身=%s\n" "$(readlink -f /bin/sh)"; echo "  ★ 第 14 节要让同一根管道去撞一下它"
  /bin/sh 的真身=/usr/bin/dash
  ★ 第 14 节要让同一根管道去撞一下它
[退出码 0]

$ echo "  dash 想要 --version 的话，原话是："; dash --version 2>&1 | head -1
  dash 想要 --version 的话，原话是：
dash: 0: Illegal option --
[退出码 0]
```

**屏幕上为什么是这些**：`/bin/sh → /usr/bin/dash`，而 dash 连 `--version` 都不认，
原话是 `dash: 0: Illegal option --`。这一行不是笑话，是判据：**dash 的报错格式和 bash 完全不同**，
以后你在脚本里看到 `dash: 0:` 开头，就该想到自己踩进了 POSIX sh 的地界。

最后两件现场条件 —— 语言环境和别名：

```
$ printf "  语言环境：demo 已把自己钉成 LC_ALL=[%s] LANG=[%s]（你原来的终端是 LANG=%s、LC_ALL=%s）\n" "$LC_ALL" "$LANG" "$ORIG_LANG" "$ORIG_LC_ALL"
  语言环境：demo 已把自己钉成 LC_ALL=[C.UTF-8] LANG=[C.UTF-8]（你原来的终端是 LANG=zh_CN.UTF-8、LC_ALL=（未设））
[退出码 0]

$ printf "  umask=%s ｜ 沙箱里的样本文件权限都从这个数长出来\n" "$(umask)"
  umask=0022 ｜ 沙箱里的样本文件权限都从这个数长出来
[退出码 0]

$ printf "  交互 shell 里有 grep 的 --color alias，但脚本里没有：shopt expand_aliases → %s\n" "$(shopt -q expand_aliases && echo on || echo off)"
  交互 shell 里有 grep 的 --color alias，但脚本里没有：shopt expand_aliases → off
[退出码 0]
```

`LC_ALL` 和 `LANG` 被 demo 钉成 `C.UTF-8`，所以本章屏幕上所有报错都是**英文原文**；
你终端原本是 `zh_CN.UTF-8` 时会看到中文报错，**退出码不变**（这条判据在第 3 节第 6 格和第 5 节第 7 格各撞一次）。
`umask=0022` 决定第 11 节里 `sed -i` 造出来的新文件是什么权限。
最后一行 `expand_aliases → off` 是说：你交互 shell 里那个 `alias grep='grep --color=auto …'`
**在脚本里不存在** —— 所以第 7 节递归 grep 会老老实实扫进 `.git`，而不是你以为的被 alias 排除掉。

## 2. 一张地图：三条主线各一条最小证据

正式开跑前，先把三笔账各亮一次，后面 22 节都在把它们放大到「为什么会这样」。

第一条：grep 的单位是**行** —— 你要的是「90」那一小段，它给你的是整行。

```
$ printf "Ada 90\nAlan 88\n" | grep 90
Ada 90
[退出码 0]
```

第二条：sed 不写 `-n` 时**每行都原样打印**，所以你在 `s` 之后会看到它把整份文本又端一遍。

```
$ printf "a\nb\n" | sed "s/a/A/"
A
b
[退出码 0]

$ printf "a\nb\n" | sed -n "s/a/A/p"
A
[退出码 0]
```

屏幕上为什么是这三格：第一格 `sed "s/a/A/"` 打出 `A` 和 `b` 两行 —— 你没让它打印，它自己打了；
第二格加了 `-n` 只剩 `A` 一行 —— `b` 那行被 `-n` 扣住了。
**「p 是打印」这个直觉的错处不在 p 会打印，而在「不 p 的行会消失」**：默认那趟循环每一行结尾都自动打印。

第三条：awk 的单位是**字段**，默认按空白切 —— 所以它是三家里唯一能干「比大小、求和」的。

```
$ printf "Ada 90\nAlan 88\n" | awk "{ s += \$2 } END { print s }"
178
[退出码 0]
```

**屏幕上为什么是 178**：`90 + 88`。grep 和 sed 在这一格上根本无从下手（第 15 节把这三个任务并排演一遍）。

主线②：同一件事三个码。命中 / 没有 / 出错，三家报得不一样。

```
$ printf "error here\nplain\n" > zz-map.txt
printf "  grep 命中码=%s ｜ grep 没命中码=%s ｜ sed 没命中也码=%s\n" \
  "$(grep -c error zz-map.txt >/dev/null; echo $?)" "$(grep -c zzz zz-map.txt >/dev/null; echo $?)" \
  "$(sed -n "s/zzz/X/p" zz-map.txt; echo $?)"
rm -f zz-map.txt
  grep 命中码=0 ｜ grep 没命中码=1 ｜ sed 没命中也码=0
[退出码 0]
```

屏幕上为什么是 `0 ｜ 1 ｜ 0`：grep 没命中报 1（这是**答案**），sed 没命中报 0（这是「我没崩」）。
这一格是全章判据的种子：**跑成功 ≠ 活干了**，`sed` 那一路的 0 里既包含「改了」也包含「一行都没改」。

主线③：本机 awk 是 mawk，gawk 的写法在它这里可以**一声不响**。

```
$ printf "abcdefgh\n" | awk "BEGIN{ FIELDWIDTHS=\"3 3\"; } { print \"  屏幕上=[\" \$0 \"][\" \$2 \"] NF=\" NF }"; printf "  ↑ 这条 awk 自己的码=%s（★ gawk 文档里这一刀该切成 NF=3）\n" "$?"
  屏幕上=[abcdefgh][] NF=1
  ↑ 这条 awk 自己的码=0（★ gawk 文档里这一刀该切成 NF=3）
[退出码 0]
```

屏幕上为什么最刺眼：`awk` 自己那条命令的码是 **0**，而 `$2` 是空的、`NF=1` —— 整行八个小字符全塞进了 `$1`。
gawk 文档里这一刀该切成 `NF=3` 起步。这一格只是预告，第 20 节把「会叫的缺件」和「不会叫的缺件」两张清单并排摊开。

## 3. grepdialect.sh 完整跑：一个 grep 里装着三套正则引擎

一个 grep 里面装着**三套**正则引擎：不带开关是 BRE，`-E` 是 ERE，`-P` 是 PCRE。
你从网上抄的一行命令，多半是 ERE 的写法；把它抄进一个不带 `-E` 的脚本，它不会报错，
它会安静地什么都不给你 —— 或者更糟，给你**错的东西**。

这一节每一格都印三列：**标签**（这格想演什么）、**实际开关**（命令真正吃进去的那串）、**结果**。
中间那一列是本章自己的护栏：标签是人写的，会写错；开关是从命令里拿出来的，不会。

第 1 格，先把现场摊开：本机 grep 是谁、`-P` 到底能不能用、样本长什么样。

```
$ bash grepdialect.sh

=== 1. 现场：一个 grep 里装着三套正则引擎，开关决定用哪一套 ===
  本机 grep：grep (GNU grep) 3.12
  -P（PCRE 引擎）在本机可用吗 → 可用（rc≠2 就说明引擎在，只是没匹配）
  沙箱样本：p.txt=5 行 ｜ quant.txt=6 行 ｜ pc.txt=4 行 ｜ meta.txt=5 行 ｜ w.txt=4 行
  p.txt 内容：
      ab
      abc
      axb
      a.b
      hello
  → 三种方言：不带开关 = BRE（POSIX 基础型，反斜杠才是元字符），-E = ERE（网上抄的一行命令多半是它），-P = PCRE（另一套语言）。
  → 抄来的命令换一台机器就不响，九成是「开关和方言不匹配」，不是「样本里没有」——下面一格一格数给你看。
```

屏幕上为什么先看这两行：`grep (GNU grep) 3.12` 说明 `-P` 有希望；
下一行问「`-P` 可用吗」，判据不是「有没有命中」而是 **rc 等不等于 2** ——
`grep -P x /dev/null` 报 rc=2 才意味着引擎真的不在。这一格给的是「可用（rc≠2 就说明引擎在，只是没匹配）」。
**这一格顺手也把本章的通用判据立了：先分清码，再看数字。**

第 2 格，「或」：`\|` 和 `|` 在 BRE 里正好相反。

```
=== 2. 「或」：\| 和 | 在 BRE 里正好相反 ===
  样本 p.txt，找「ab 或 axb」：
  BRE 默认  ab\|axb        开关[(无开关=BRE)] 命中 3   行 ｜ rc=0  ｜ 匹配
  BRE 默认  ab|axb         开关[(无开关=BRE)] 命中 0   行 ｜ rc=1  ｜ 静默不匹配(1)
  ERE -E      ab|axb         开关[-E            ] 命中 3   行 ｜ rc=0  ｜ 匹配
  ERE -E      ab\|axb        开关[-E            ] 命中 0   行 ｜ rc=1  ｜ 静默不匹配(1)
  PCRE -P     ab|axb         开关[-P            ] 命中 3   行 ｜ rc=0  ｜ 匹配
  → 同一串字符，BRE 里 | 是字面竖线、ERE 里 \| 是字面竖线：两格都是 0 行、rc=1，一句报错都没有。
  → 也就是说「抄来的 -E 命令加了 \|」不会失败，只会**安静地**一行都不给你。这是本章最贵的一课。
```

屏幕上为什么是这五个数：样本 `p.txt` 是 `ab / abc / axb / a.b / hello` 五行，
「ab 或 axb」能命中 3 行（`ab`、`abc`、`axb`）。
- BRE 的 `ab\|axb` → **3**（`\|` 才是「或」）；BRE 的 `ab|axb` → **0**（裸 `|` 是字面竖线，样本里没有竖线）。
- ERE 反过来：`ab|axb` → **3**；`ab\|axb` → **0**（ERE 里 `\|` 成了字面竖线）。
- PCRE `ab|axb` → **3**。

**直觉以为「写反了至少会报错」**：屏幕上四行有结果、两行是 0 行 + rc=1，一句抱怨都没有。
「抄来的 `-E` 命令加了 `\|`」不会失败，只会安静地一行都不给你 —— 这是全章最贵的一课，
因为它在 CI 里的表现和「这个模式本来就没有命中」一模一样。

第 3 格，分组和量词：`+ ? {n,m}` 在 BRE 里都要戴反斜杠。

```
=== 3. 分组和量词：+ ? {n,m} 在 BRE 里都要戴反斜杠 ===
  样本 quant.txt（aaa/aab/ab/color/coloor）：
  BRE 默认  a\{2,3\}       开关[(无开关=BRE)] 命中 2   行 ｜ rc=0  ｜ 匹配
  BRE 默认  a{2,3}         开关[(无开关=BRE)] 命中 0   行 ｜ rc=1  ｜ 静默不匹配(1)
  ERE -E      a{2,3}         开关[-E            ] 命中 2   行 ｜ rc=0  ｜ 匹配
  ERE -E      a\{2,3\}       开关[-E            ] 命中 0   行 ｜ rc=1  ｜ 静默不匹配(1)
  BRE 默认  a\+b           开关[(无开关=BRE)] 命中 2   行 ｜ rc=0  ｜ 匹配
  BRE 默认  a+b            开关[(无开关=BRE)] 命中 0   行 ｜ rc=1  ｜ 静默不匹配(1)
  ERE -E      a+b            开关[-E            ] 命中 2   行 ｜ rc=0  ｜ 匹配
  BRE 默认  colou\?r       开关[(无开关=BRE)] 命中 1   行 ｜ rc=0  ｜ 匹配
  BRE 默认  colou?r        开关[(无开关=BRE)] 命中 0   行 ｜ rc=1  ｜ 静默不匹配(1)
  ERE -E      colou?r        开关[-E            ] 命中 1   行 ｜ rc=0  ｜ 匹配
  → 数一下上面的 rc：所有「少戴/多戴一个反斜杠」的格子全是 rc=1 而不是 rc=2。
  ★ BRE 里裸 { ( ? 是**字面字符**（不是语法错），所以它照样跑完、照样返回「没匹配」——写反了没人告诉你。
```

屏幕上为什么值得逐行数 rc：所有「少戴或多戴一个反斜杠」的格子 —— `a{2,3}` 在 BRE、`a\{2,3\}` 在 ERE、
`a+b` 在 BRE、`colou?r` 在 BRE —— **全是 rc=1，没有一个 rc=2**。
因为 BRE 里裸的 `{`、`+`、`?` 是**字面字符**，不是语法错：
`a+b` 在 BRE 里意思是「一个 a、一个加号、一个 b」，样本里没有这个串，于是「没匹配」。
`-E` 那三行给 **2、2、1**（`a{2,3}` 命中 aaa/aab 两行、`a+b` 命中 aab/ab、`colou?r` 命中 color 一行），
和 BRE 那几行的 0 一对照，就是同一句话的两种方言读法。

第 4 格，只有 PCRE 认的写法和只有 GNU 认的写法：**不认的那边一句报错都没有**。

```
=== 4. 只有 PCRE 认的，和只有 GNU 认的：不认的那边一句报错都没有 ===
  样本 pc.txt（含中文与数字），找数字：
  ERE -E      \d+            开关[-E            ] 命中 1   行 ｜ rc=0  ｜ 匹配
  BRE 默认  [0-9]\{1,\}    开关[(无开关=BRE)] 命中 2   行 ｜ rc=0  ｜ 匹配
  ERE -E      [0-9]+         开关[-E            ] 命中 2   行 ｜ rc=0  ｜ 匹配
  PCRE -P     \d+            开关[-P            ] 命中 2   行 ｜ rc=0  ｜ 匹配
  → ★ 同一串 \d+ 在两边的下场：ERE 读成「字母 d 一个以上」（命中 1 行，rc=0），PCRE 读成数字（命中 2 行）。
    ERE 那一格命中的原文=[no digits here ] ← 它不是「没匹配」，是**匹配了错的东西**，而且一声不响。
  前瞻 (?= ) 这种写法：
  PCRE -P     A(?=[0-9])     开关[-P            ] 命中 1   行 ｜ rc=0  ｜ 匹配
  ERE -E      A(?=[0-9])     开关[-E            ] 命中 0   行 ｜ rc=1  ｜ 静默不匹配(1)
  ERE 那一格 -c 看不到报错，把两路输出和退出码分开捞出来看：
      stderr=[warning: ? at start of expression] ｜ stdout=[0] ｜ rc=1
      ← ★ 有警告、退 1，不是退 2：grep 认为「这写法我能懂，只是样本里没有」。警告不改变结论，所以只看 rc 会漏，只看文本也会漏。
  反过来：GNU 的 \< \>（整词）搬到 -P 上会怎样（样本 p.txt，只有一行 hello）：
  BRE 默认  \<hello\>      开关[(无开关=BRE)] 命中 1   行 ｜ rc=0  ｜ 匹配
  ERE -E      \<hello\>      开关[-E            ] 命中 1   行 ｜ rc=0  ｜ 匹配
  PCRE -P     \<hello\>      开关[-P            ] 命中 0   行 ｜ rc=1  ｜ 静默不匹配(1)
  BRE 默认  \bhello\b      开关[(无开关=BRE)] 命中 1   行 ｜ rc=0  ｜ 匹配
  ERE -E      \bhello\b      开关[-E            ] 命中 1   行 ｜ rc=0  ｜ 匹配
  PCRE -P     \bhello\b      开关[-P            ] 命中 1   行 ｜ rc=0  ｜ 匹配
  → PCRE 里 \< 是「字面 <」，于是 GNU 的写法搬到 -P 变成 0 行、rc=1，还是不报错。
  ★ 本机实测（别信二手话）：\b 在 BRE/ERE/PCRE 三边都能当词边界，但 \< \> 只有前两边认。同一份脚本要跨 -P 时，用 \b 或干脆用 -w。
```

屏幕上为什么这格要盯三处：
1. **`\d+` 在 ERE 里命中 1 行、在 PCRE 里命中 2 行**。这 1 行不是「差不多对了」，它错得离谱：
   ERE 把 `\d` 读成**字母 d**，`+` 读成「一个以上」，于是它命中的是 `no digits here` 这行 ——
   一行**根本没有数字**的文本。比 0 行更阴的就是这种：rc=0、有命中、命中的是错的东西。
2. **前瞻 `(?=)`**：`-P` 给 1 行（`订单号 A123`），`-E` 给 0 行 —— 但把两路输出分开捞，
   stderr 里躺着一句 `warning: ? at start of expression`，而 rc 是 **1 不是 2**。
   grep 的态度是「这写法我能读懂（`?` 放在开头我按字面处理），只是样本里没有」。
   所以**只看 rc 会漏掉警告，只看 stdout 会漏掉「其实是写错了」**。
3. **GNU 的 `\< \>` 搬到 `-P`**：BRE/ERE 各命中 1 行，PCRE 给 **0 行 rc=1**；
   而 `\b` 在三家都命中 1 行（屏幕上 BRE、ERE、PCRE 三行都在）。
   判据就落在这一格上：**跨 `-P` 时用 `\b`，或者干脆用 `-w`**。

第 5 格，元字符陷阱：`.` 是「任意字符」，`-F` 才是「这个串」，`-w` 只管整词。

```
=== 5. 元字符陷阱：. 是「任意字符」，-F 才是「这个串」；-w 只管整词 ===
  样本 meta.txt（5 行，其中有字面 a.b 的，也有 axb / a--b 的）：
      a.b
      axb
      配置 a.b 生效
      a--b
      版本a.b中文

  → 上面两格差 1 行，多出来的那行原样列在这里：[axb ] —— 这就是「. 被当元字符」的代价。
    顺带一格：a--b 两把尺都没命中，因为 . 只吃**一个**字符，a 和 b 中间隔着两个。

```

屏幕上为什么是 4 和 3：样本五行里，正则 `a.b` 命中 `a.b`、`axb`、`配置 a.b 生效`、`版本a.b中文` 四行，

顺带补的那条也算数：`a--b` **两把尺都没命中**，因为 `.` 只吃**一个**字符，`a` 和 `b` 中间隔着两个。
下半格 `-w`：`hello` 不加 `-w` 命中 3 行，加了命中 2 行，差的那 1 行是 `helloworld` ——
子串算命中，整词不算。**搜 error / warn / id 这类短词时，`-w` 经常是把假阳性砍掉大半的那个开关。**

第 6 格，把「0 / 1 / 2 三态」当场各撞一次。

```
=== 6. ★ 通用判据：报错(2) ≠ 不匹配(1) ≠ 成功(0) —— 三个码各撞一次 ===

## 4. 小证据：模式自己以 `-` 开头时，grep 把它当成开关

第 3 节教的是「开关决定方言」，这一节补一刀更常见的：**你要匹配的串自己以减号开头**。
直觉是「`grep -f file` 就是找 `-f` 这两个字符」—— 错，`-f` 的意思是「模式在这个文件里」。

```
$ printf -- "-f flag\nfoo bar\n" > zz-sw.txt
printf "  样本两行都含 -f 这两个字符\n"
printf "  grep -f zz-sw.txt（想匹配 -f）→ 命中 %s 行，rc=%s\n" \
  "$(grep -f zz-sw.txt < zz-sw.txt | wc -l)" "$(grep -f zz-sw.txt < zz-sw.txt >/dev/null; echo $?)"
printf "  ★ 它把你的文件名吞成了 -f 的参数，然后开始读 stdin —— 一个字的报错都没有\n"
printf "  正确写法一：grep -e \"-f\" 文件 → 命中 %s 行\n" "$(grep -e "-f" zz-sw.txt | wc -l)"
printf "  正确写法二：grep -- \"-f\" 文件 → 命中 %s 行\n" "$(grep -- "-f" zz-sw.txt | wc -l)"
printf "  对照：把 stdin 换成空设备，同一道命令就谁都不匹配（rc=%s）→ 静默失败全套形状\n" "$(grep -f zz-sw.txt < /dev/null >/dev/null; echo $?)"
rm -f zz-sw.txt
  样本两行都含 -f 这两个字符
  grep -f zz-sw.txt（想匹配 -f）→ 命中 2 行，rc=0
  ★ 它把你的文件名吞成了 -f 的参数，然后开始读 stdin —— 一个字的报错都没有
  正确写法一：grep -e "-f" 文件 → 命中 1 行
  正确写法二：grep -- "-f" 文件 → 命中 1 行
  对照：把 stdin 换成空设备，同一道命令就谁都不匹配（rc=1）→ 静默失败全套形状
[退出码 0]
```

屏幕上为什么这一串最该抄进笔记：
- `grep -f zz-sw.txt < zz-sw.txt` 命中 **2 行、rc=0**。它没找 `-f`，它把**你的文件名吞成了 `-f` 的参数**，
  然后从 stdin 读 —— 一个字的报错都没有，还给出一堆「命中」，看起来完全像成功了。
- `grep -e "-f"` 和 `grep -- "-f"` 各命中 **1 行**（只有第一行真的含 `-f`）—— 这才是你想要的答案。
- 最后那行对照把 stdin 换成空设备：`grep -f zz-sw.txt < /dev/null` → **rc=1，零报错**，
  这就是「静默失败的全套形状」：不匹配、不解释、码长得像答案。

**直觉以为「`-` 开头的串只要加引号就安全」**：引号救不了它，因为它根本不是被当字符串解析的 ——
`-f` 在 getopt 那一层就被吞走了。判据跨工具通用：**sed、awk 也认 `--`**，
凡是可能以减号开头的串（用户输入、变量、文件名）一律放到 `--` 后面，或者用 `-e` 显式起一个模式。

## 5. greppat.sh 完整跑：grep 给的是整行，数的是行

这一节钉的是 grep 的**单位**：它打印的是整行，`-c` 数的是行，`-o` 才给片段，
而片段永远不越过行界。八格，一次跑完。

第 1 格是全章最贵的一格：直觉「把命中的那段给我」，屏幕上它给的是整行。

```
$ bash greppat.sh

=== 1. 直觉「把命中的那段给我」→ 它给的是整行（全章最贵的一格） ===

      error: disk full on node-3 error: retry later error: gave up
      info: everything ok
      error: only one here
      nothing to see
  error        命中 2   行 ｜ grep -o 切出 4   段 ｜ 两数差 2
  ★ 形状对账：整行版第 1 条 61 个字符，片段版第 1 条 6 个，pattern 本身 5 个
    → 整行版长度等于 pattern 长度吗：不相等 ｜ 片段版等于「pattern 长度 + 1」吗：是（多的 1 是行尾换行）
  ★ 不能跨行：gp/kv.txt 里 foo= 命中 1 行、bar 命中 1 行，但 foo=bar 命中 0 行
    → 两段字面明明都在文件里，★ grep 一次只看得见一行，所以它一口咬定「没有」；要跨行得换工具（sed 的 N、awk 的多行记录），不是换写法。
  ★ -o 也不是你想多短就多短：grep -o e.*r 第一条切出来是 [error: disk full on node-3 error: retry later error]
    → 它是「这一行里能匹配的最长一段」，把两个 error 之间的字全吞了，但★ 一个字符都没越过行界。
```

屏幕上为什么是 2 行 4 段：样本 `svc.log` 第一行里 `error` 出现了 **3 次**，
所以「行」口径是 2（第一行和第三行），「段」口径是 4。
下面那两行「形状对账」更狠：整行版第一条 **61 个字符**、片段版第一条 **6 个**、pattern 本身 **5 个**。
61 就是那一整行的长度（含行尾换行是 62，屏幕上打的是去掉换行后的 61），
而 6 = 5 + 1 —— **多的那个字符是行尾换行，不是内容**。
判据：**整行版长度等于 pattern 长度吗？不相等。** 这就是「我只要那一小段」和「grep 给你整行」的分界线。

同一格后半还钉了两条边界：
- `foo=` 命中 1 行、`bar` 命中 1 行，但 `foo=bar` 命中 **0 行** —— 两段字面明明都在文件里，
  可 grep 一次只看得见**一行**，所以它一口咬定「没有」。要跨行得**换工具**（sed 的 `N`、awk 的多行记录），不是换写法。
- `-o` 也不是你想多短就多短：`grep -o e.*r` 切出来的第一段是
  `error: disk full on node-3 error: retry later error` —— 它把两个 `error` 之间的字全吞了（`.*` 贪婪），
  但**一个字符都没越过行界**。

第 2 格，一行里命中两次：`-c` 数的是行，`-o | wc -l` 数的是次数。

```
=== 2. 一行里命中两次：-c 数的是行，-o | wc -l 数的是次数 ===

  附：grep -o 扫的是**不重叠**片段 —— printf aaaa | grep -o aa → 2 段（不是 3 段）
  → 数「几行中招」用 -c，数「出现几次」用 -o | wc -l；两数差几个，就是同一行里多出来的那几次。

屏幕上为什么这一格有「先弄响」这一步：`svc.log` 差 2、`one.log` 差 0，
但如果两个计数器本来就是死的，这两个数也长这样。所以先把 pattern 放宽成单个字母 `e`，
得到「行 4 / 段 15，差 11」—— **两个计数器都在动**。再归零：`one.log` 每行至多一处命中，

最后一行附带一条口径：`printf aaaa | grep -o aa` 切出 **2 段，不是 3 段** —— 第 6 节专门放大它。

## 6. 小证据：`-o` 不回头重叠

第 5 节第 2 格数了「行 vs 次」，这一节补一把尺：**同一份文本里，`-o` 的段数会比你数少**。

```
$ printf "aaaa\n" > zz-oo.txt
printf "  四个连续 a：-o 取 aa → %s 段 ｜ -c → %s 行\n" "$(grep -o aa zz-oo.txt | wc -l)" "$(grep -c aa zz-oo.txt)"
printf "  为什么不是 3 段：吃完第 1、2 个 a 之后，扫描指针停在第 3 个 a，从这里起算\n"
printf "  换个写法就换个数：-o \"aa*\"（贪婪吃掉整串）→ %s 段\n" "$(grep -o "aa*" zz-oo.txt | wc -l)"
rm -f zz-oo.txt
  四个连续 a：-o 取 aa → 2 段 ｜ -c → 1 行
  为什么不是 3 段：吃完第 1、2 个 a 之后，扫描指针停在第 3 个 a，从这里起算
  换个写法就换个数：-o "aa*"（贪婪吃掉整串）→ 1 段
```

屏幕上为什么是 2 段：`aaaa` 里 `aa` 出现了三次（1-2、2-3、3-4），
但 grep 吃完第 1、2 个 `a` 之后，**扫描指针停在第 3 个 `a`**，从这里起算 —— 所以是 2 段。
换个写法就换个数：`-o "aa*"` 贪婪吃掉整串，只有 **1 段**。
判据一句话：**段数跟着「你怎么写正则」走，不跟着「文本里实际有几个 `aa`」走** —— 数次数之前先定死模式。

## 7. grepfix.sh 完整跑：把 grep 用在管道和判断里

- `-q` 的 stdout 是 **0 字节**（真静默），命中 rc=0、找不到 rc=1；
  `-c` 的 stdout 是那一串 `[2]` —— **数字是打印出来的数据，不只是码**。
- 「污染现场」那行把 `-c` 和别的输出拼成一段报告，屏幕上得到 `[2/报告结束/]`：数字混在中间，下游数行就多数一行。
- **现场一**是本章最像线上事故的一格：`if [ "$(grep -c x 不存在的文件)" -gt 0 ]` 跑完，屏幕按顺序是
  `grep: gf/nosuch.log: No such file or directory` → `[: : integer expected` → 分支=**没有命中**。
  `grep` 自己的码是 **2（出错）**，可 `if` 只看得到 `[` 那一层的码 ——
  **真错在这一步被翻译成了「没有命中」**。注意那两行 `line 57 / line 60` 是被缩进打印出来的**证据**，
  不是脚本崩了（脚本继续跑完了后面的格）。
- **现场二**：多个文件时 `-c` 的 stdout 变成 `gf/app.log:2|gf/app2.log:0`（一行一个「文件名:数字」），
  `[` 直接罢工，那一层的 rc=**2**。

第 2 格，把三态写成**能用的结构**：0 命中 / 1 没有 / 2 出错。

```
=== 2. 三态要写成能用的结构：0 命中 / 1 没有 / 2 出错 ===
  ① 有东西的文件 rc=0 ｜ 命中，数字=2（码 0：这是答案）
  ② 真没有的串 rc=1 ｜ 一行都没有，数字=0（码 1：这也是答案，不是故障）
  ③ 文件不存在 rc=2 ｜ 出错，别看数字，原文[grep: gf/nosuch.log: No such file or directory]
  ④ 坏正则      rc=2 ｜ 出错，别看数字，原文[grep: Invalid regular expression]
  ★ 事故写法 grep 模式 文件 || echo 没找到 —— 把 ③ 喂进去，屏幕上按顺序出现：
      grep: gf/nosuch.log: No such file or directory
      没找到
  → 合起来读就是「没找到」，可它的码是 2 —— CI 会绿着漏检。|| 只能挂在「码正好是 1」那一支，写法见上面 three() 的 case。
```

屏幕上为什么这四行是可以抄的模板：①② 各带数字并标明「这是答案」，③④ 写的是「别看数字，原文[…]」。
也就是**只在 rc=2 那一支去读报错文本**。
下面那格「事故写法」把 `grep 模式 文件 || echo 没找到` 喂了个不存在的文件，屏幕上是两行：
先 `grep: gf/nosuch.log: No such file or directory`，再 `没找到` ——
合起来读像「确实没有」，可它的码是 **2**。判据：**`||` 只能挂在「码正好是 1」那一支。**

第 3 格，`grep -v`：滤干净了退 1，还在管道里把上游的码吃掉。

```
=== 3. grep -v：滤干净了退 1，还在管道里把上游的码吃掉 ===
  整份文件都被 -v 滤掉 → 输出 0 行，rc=1 ｜ 空输入（printf 空串 | grep -v x）→ rc=1
  ★ -v 的 1 =「一行都没剩下」，和「没找到」共用同一个码 —— 日志被滤干净时它就是在报 1
  甲（上游 2、下游也非 0）：不开 pipefail → [grep: Invalid regular expression PIPESTATUS=2 1 整条rc=1]｜开了 → [grep: Invalid regular expression PIPESTATUS=2 1 整条rc=1]
  ★ pipefail 取的是**最右边那个非 0**：甲这两支的整条码都是 1，上游那个 2 照样看不见 —— 它不是「每段都报」开关
  乙（上游 2、下游 0）：不开 pipefail → [grep: gf/nosuch.log: No such file or directory PIPESTATUS=2 0 整条rc=0]｜开了 → [grep: gf/nosuch.log: No such file or directory PIPESTATUS=2 0 整条rc=2]
  ★ 乙才是事故本体：报错原文仍在屏幕上，整条管道却报**成功**；开关只在那个 bash -c 里活着，本脚本不开（不然前面几格早停了）
  → 想留住每一段的码只有 PIPESTATUS；grep -v 在 CI 里的正确姿势是把 1 当「没有剩下」，别当崩溃。
```

屏幕上为什么这一格要说「甲乙两支」：
- `-v` 把整份文件滤掉 → 输出 0 行、**rc=1**；连空输入也是 rc=1。
  所以 `-v` 的 1 意思是「一行都没剩下」，它和「没找到」**共用同一个码**。
- 甲（上游坏正则 rc=2、下游也非 0）：开不开 `pipefail` 整条都是 **1**，
  `PIPESTATUS=2 1` 看得见上游那个 2，但 `pipefail` 取的是**最右边那个非 0** —— 它不是「每段都报」开关。
- 乙（上游文件不存在 rc=2、下游 `wc` 正常 rc=0）：不开 pipefail 整条 **rc=0**，开了才 **rc=2**。
  **乙才是事故本体**：报错原文大剌剌在屏幕上，整条管道却报**成功**。
  屏幕最后一行还补了一句：那个开关只活在包它的那个 `bash -c` 里，本脚本自己没开 —— 不然前面几格早停了。

第 4 格，多 pattern 的三种写法：`-e`、`-E` 的 `|`、`-f` 文件（空行和 `#` 行会怎样）。

```
=== 4. 多 pattern 的三种写法：-e、-E 的 |、-f 文件（空行和 # 行会怎样）===
  样本 gf/mp.txt 共 7 行（其中一行是空行，一行以 # 开头）
  -e error -e warning → 3 行 ｜ -E error|warning → 3 行 ｜ 相等吗：是
  -f gf/pats.txt（三行：error、空行、# 这是配置行）→ 命中 7 行；文件总行数 7 → 相等吗：是
  ★ 空行 = 空 pattern = **匹配每一行**；# 那行不是注释、是字面 pattern（单独放它只命中 1 行）；-e 后面给空串同样下场（7 行）
  两种「rc=1 / rc=1」摆一起：空 pattern 文件 → stdout=[（一个字符都没打）] ｜ 正常「没有」 → stdout=[0] —— 码一样、stdout 不一样，前者连 0 都不打
  → 从别处生成的 pattern 文件，先数它有几行（gf/pats.txt=3 行）再上生产线：多一个空行 = 全放行。
```

屏幕上为什么必须亲手跑一次才记得住：
- `-e error -e warning` 和 `-E 'error|warning'` 各 3 行，相等。
- **`-f pats.txt`（三行：`error`、空行、`# 这是配置行`）命中 7 行 —— 文件一共就 7 行**。
  空行 = 空 pattern = **匹配每一行**；而 `#` 那行**不是注释**，是字面 pattern（单独放它只命中 1 行）。
  `-e` 后面给空串同样下场：7 行全放行。
- 最后那行把两种「rc=1」摆在一起：空 pattern 文件的 `-c` stdout 是**一个字符都没打**，
  正常「没有」的 `-c` stdout 是 `[0]` —— **码一样、stdout 不一样**，前者连 0 都不打。
  判据：从别处生成的 pattern 文件，先数它有几行再上生产线。

第 5 格，`-A/-B/-C` 是给人看的：那个 `--` 会被下游当成数据。

```
=== 5. -A/-B/-C 是给人看的：那个 -- 会被下游当成数据 ===
  样本 gf/ctx.txt：6 行，ERROR 命中 2 行
  -A1 → 5 行 ｜ -B1 → 5 行 ｜ -C1 → 6 行 ｜ 不带上下文 → 2 行
  ★ -A1 比命中行数多出 3 行，其中有 1 行是分隔符（屏幕上就是那个 --）—— 它是排版，不是数据
  -C1 输出 6 行等于整个文件 6 行吗 → 是（两组上下文粘在一起了，此时分隔符有 0 条）
  --group-separator 不是删掉那一行，是换掉内容：钉成 #### 出现 [####]；钉成空串仍 5 行（分隔位变成空行）
  → 要统计就在**没有** -A/-B/-C 的那一步数；上下文只加在给人看的那一条命令上。
```

屏幕上为什么这格专治「统计偏多」：样本 6 行、`ERROR` 命中 2 行，
`-A1` 输出 **5 行**、`-B1` **5 行**、`-C1` **6 行**、不带上下文 **2 行**。
`-A1` 比命中行数多出 3 行，其中**有 1 行是分隔符**，屏幕上就是那个孤零零的 `--` —— 它是排版，不是数据。
`-C1` 输出的 6 行正好等于整个文件的 6 行（两组上下文粘在一起了，此时分隔符 0 条）。
补的那条也实用：`--group-separator` **不是删掉那一行，是换掉内容** —— 钉成 `####` 就出现 `####`，
钉成空串仍是 5 行（分隔位变成空行）。判据：**要统计就在没有 `-A/-B/-C` 的那一步数。**

第 6 格，递归与文件名：`-l` 的单位是文件，带空格的名字在 xargs 里散架。

```
=== 6. 递归与文件名：-l 的单位是文件，带空格的名字在 xargs 里散架 ===
  gf/tree 共 5 个文件；grep -rl 列出 4 个（单位=文件）｜命中行一共 5 行（有个文件中了 2 行）
  --include=*.txt → 3 个 ｜ --exclude=*.md → 3 个 ｜ 相等吗：是（名单比文件总数少 1 个 = 那个 b.log）
  ★ 散架现场 grep -rl ... | xargs grep -c（本机 xargs：xargs (GNU findutils) 4.10.0）：按空白切名字，带空格那个被切成 4 段

屏幕上为什么这格是全章最像真实事故的一格：

第 7 格，早停：`-m 1` 和 `-q` 各自少做了什么（只演屏幕上看得见的）。

=== 7. 早停：-m 1 和 -q 各自少做了什么（只演屏幕上看得见的）===

  -m 1 的 rc=0 ｜ -q 的 rc=0 ｜ 找不到时 -m 1 的 rc=1（和「没有」同一个码）｜ 本机 -m 0：打印 0 行 rc=1
  ★ 最狠的一条：grep -c 报 2，grep -m1 -c 报 1 —— 早停改的是**数字**本身，不只是输出长短

屏幕上为什么只报行数和码，不报耗时：样本 `big.txt` 共 4002 行，`needl` 在第 1 行和第 4002 行。

=== 8. 收口：码的分工 + 当场自证 ===

  -l/-r   单位是文件；文件名交给下游必须 -Z 配 -0

屏幕上这张五行小表把 grep 的码与单位合到一处：

凡是 `||`、`[ "$(grep -c …)" ]`、管道 rc，都在把 2 往 1 上糊。**

## 8. 小证据：递归时「挑哪些文件」是另一套开关

第 7 节第 6 格演的是「`-l` 的单位是文件」，这一节补挑文件的三把钥匙，顺带一个意外。

```
$ mkdir -p zz-tree/sub zz-tree/.git
printf "hit\n" > zz-tree/a.txt; printf "hit\n" > zz-tree/b.log; printf "hit\n" > zz-tree/sub/c.txt; printf "hit\n" > zz-tree/.git/d.txt
printf "  含 hit 的文件（不分类型、不进任何排除）：%s 个\n" "$(grep -rl hit zz-tree | wc -l)"
printf "  --include=*.txt → %s 个 ｜ 再加 --exclude-dir=.git → %s 个\n" \
  "$(grep -rl --include=*.txt hit zz-tree | wc -l)" \
  "$(grep -rl --include=*.txt --exclude-dir=.git hit zz-tree | wc -l)"
printf "  ★ 第一行那 %s 个里有版本库里的：grep -r 不会替你排 .git\n" "$(grep -rl hit zz-tree | wc -l)"
printf "  反过来，把目录名写进模式里是没用的：grep -r \"sub/c\" zz-tree → 命中 %s 个文件\n" \
  "$(grep -rl "sub/c" zz-tree | wc -l)"
rm -rf zz-tree
  含 hit 的文件（不分类型、不进任何排除）：4 个
  --include=*.txt → 3 个 ｜ 再加 --exclude-dir=.git → 2 个
  ★ 第一行那 4 个里有版本库里的：grep -r 不会替你排 .git
  反过来，把目录名写进模式里是没用的：grep -r "sub/c" zz-tree → 命中 0 个文件
[退出码 0]
```

屏幕上为什么这四个数是三档：建了 4 个含 `hit` 的文件，其中两个在 `.git/` 里、一个在 `sub/` 子目录里、一个是 `.log`。
- 不带任何挑选开关 → **4 个**。★ 里面有版本库里的：`grep -r` **不会替你排 `.git`**。
- `--include=*.txt` → **3 个**（`.log` 被剔掉，但 `.git/d.txt` 还在）；再加 `--exclude-dir=.git` → **2 个**。
- 最后一行是那个意外：把目录名写进模式里 —— `grep -r "sub/c" zz-tree` → 命中 **0 个文件**。
  模式管的是**行里的内容**，`sub/c.txt` 这一串从没出现在任何一行文本里，所以它当然什么都找不到。

**直觉以为「模式里带上路径就能限定到某个子目录」**：屏幕上给了 0 个文件，而且 rc 那一路静悄悄。
判据：**模式管「行里的内容」，`--include/--exclude/--exclude-dir` 管「文件名」，两套开关不能互相代劳。**

## 9. sedflow.sh 完整跑：sed 每一行都过一遍流水线

sed 的模型是一台循环：读一条记录进**模式空间** → 依次跑你写的命令 → 结尾自动打印 → 换下一条。
这一节八格，全部挂在这台循环的四个旋钮上：打印、替换范围、跨行、地址。

第 1 格，默认 sed 每行都原样打印：`p` 是「额外再打一遍」，不是「改成只打这个」。

```
$ bash sedflow.sh
=== 1. 默认 sed 每行都原样打印：p 是「额外再打一遍」，不是「改成只打这个」 ===
  sed s/x/y/（一次都没命中） → 输出 3 行 ｜ rc=0
      | first
      | second
      | third
  sed 1p → 输出 4 行 ｜ rc=0
      | first
      | first
      | second
      | third
  sed -n 1p → 输出 1 行 ｜ rc=0
      | first
  → 直觉「p = 打印这行，别的行就该消失」，屏幕上 1p 把 3 行打成 4 行（first 出现两次）：sed 每轮循环结尾
    自带一次「自动打印」，p 是在它之外**再多打一次」。所以「只打命中行」= -n 配 p；只写 p 不写 -n 的脚本输出
    行数翻倍，拿去数行数就是假账。
```

屏幕上为什么先看第一格：`sed s/x/y/` **一次都没命中**，却照样把 `first / second / third` 三行原样吐出来，rc=0 ——
这就是那台循环的默认行为：**没改也会打印**。
第二格 `sed 1p` 把 3 行打成 **4 行**（`first` 出现两次）：一次是 `p` 打的，一次是循环结尾自动打的。
第三格 `-n 1p` 才是你想要的 **1 行**。

**直觉以为「`p` = 打印这行，别的行就该消失」**：屏幕上恰恰相反 —— `p` 只会**加**打印，不会**减**。
「只打命中行」= `-n` 配 `p`。只写 `p` 不写 `-n` 的脚本输出行数直接翻倍，拿去数行数就是假账。

第 2 格，同一行里换几个：不写 `g` 只换第一个，`g` 全换，`2` 只换第二个，`&` 是整段命中。

```
=== 2. 同一行里换几个：不写 g 只换第一个，g 全换，2 只换第二个，& 是整段命中 ===
  s/a/A/ → 输出 1 行 ｜ rc=0
      | Aaa foo foo foo
  s/a/A/g → 输出 1 行 ｜ rc=0
      | AAA foo foo foo
  s/a/A/2 → 输出 1 行 ｜ rc=0
      | aAa foo foo foo
  s/foo/F&F/ → 输出 1 行 ｜ rc=0
      | aaa FfooF foo foo
  s/foo/\&X/ → 输出 1 行 ｜ rc=0
      | aaa &X foo foo
  → 尾巴那个数字是「第几个命中」不是「第几行」（行归地址管，第 5 格）；& = 整段命中的副本，打字面的 & 得写
    \& —— 少一个反斜杠就变成「把原文又贴一遍」。
```

屏幕上为什么这五格是同一行文本（`aaa foo foo foo`）的五种下场：
`s/a/A/` → `Aaa …`（只换第一个）；`s/a/A/g` → `AAA …`（全换）；
`s/a/A/2` → `aAa …`（**只换第二个**）；`s/foo/F&F/` → `aaa FfooF foo foo`（`&` 是整段命中的副本）；
`s/foo/\&X/` → `aaa &X foo foo`（打字面的 `&` 得写 `\&`）。

**直觉以为尾巴那个数字是「第几行」**：屏幕上 `2` 动的是**同一行里的第二个命中**。行归地址管（第 5 格）。
少一个反斜杠也不会报错，它只是把 `&` 当成「把原文又贴一遍」。

第 3 格，★ 被换行劈开的文本，sed 一眼看不到：没换成、退 0、文件也一字未动。

```
=== 3. ★ 被换行劈开的文本，sed 一眼看不到：没换成、退 0、文件也一字未动 ===
  sed s/foo bar/X/（样本里这段被拆在两行） → 输出 2 行 ｜ rc=0
      | setting foo
      | bar = 1
  输出和输入逐字节【一样】｜ rc=0 ｜ 进去 2 行、出来 2 行 —— 「换成 0 处」在 sed 里不算事故
  sed -n s/foo bar/X/p（p 只在命中时打，0 行 = 一次都没命中） → 输出 0 行 ｜ rc=0
  同一条模式交给 grep：命中 0 行 ｜ rc=1 ← grep 退 1 告诉你「真没有」，sed 连这个都不告诉你
  sed N;s/foo\nbar/X/（N 先把下一行拉进模式空间） → 输出 1 行 ｜ rc=0
      | setting X = 1
  ★ 主线①落点：grep 和 sed 的单位都是**整行**，换行是边界不是字符。跨行写法两个工具都不报错，但 sed 连退码
    都给 0；加了 N（两条行拼成一条记录）才换得到，代价是 2 行进去、1 行出来 —— 行数本身就是证据。
```

屏幕上为什么这是本章「静默失败」的标准形状：样本里 `foo` 和 `bar` 分在两行，`s/foo bar/X/` 跑完 ——
**输出和输入逐字节一样**、rc=0、进去 2 行出来 2 行。
对照三行更清楚：加 `-n … p` 后输出 **0 行**（`p` 只在命中时打，0 行 = 一次都没命中），
而同一条模式交给 grep 是「命中 0 行 + **rc=1**」—— **grep 退 1 告诉你「真没有」，sed 连这个都不告诉你**。
最后一行给了解药：`sed 'N;s/foo\nbar/X/'` 用 `N` 先把下一行拉进模式空间，于是换成 `setting X = 1`，
代价写在屏幕上：**2 行进去、1 行出来** —— 行数本身就是证据。

第 4 格，主动把整文件拼成一条：循环读到底，以及 `-z`（NUL 分隔）把整文件当「一行」。

```
=== 4. 主动把整文件拼成一条：循环读到底，以及 -z（NUL 分隔）把整文件当「一行」 ===
  sed :loop;N;$!bloop;p（每轮 N 一条，没到末行就跳回去） → 输出 6 行 ｜ rc=0
      | first
      | second
      | third
      | first
      | second
      | third
    最后一轮手里是整个文件；p 打一遍 + 自动打印再打一遍 → 3 行的文件出 6 行。
  错示范：同一条脚本改用双引号包住 → 输出 3 行 ｜ rc=0
      | first
      | second
      | third
    双引号里 $! 归 bash 解释（本脚本没后台任务 → 展开成空），sed 收到的是**另一条脚本**：6 行变 3 行、rc 还是 0、
    零报错；有后台任务时那位置会被换成进程号（屏幕上多一个 pid，脚本再变一次样）→ sed 脚本一律单引号。
  sed 眼里的记录条数：普通模式 2 条（sed -n "=" 打几个号就是几条）｜ -z 模式 1 条（-z 每条记录以 NUL 收尾，数 NUL 就是数记录）
  同一条 s/foo.bar/X/：左边的行数是 -z 的 → 输出 1 行 ｜ rc=0
      | setting X = 1
    普通模式下同一条一个字都没换（. 撞不到换行，输出 0 行、rc 照样 0），-z 下它命中了 —— 点号能不能吃换行跟着分隔符走。
  -z 下 sed 2d（删第 2 条记录）→ 出来 2 行、rc=0：整个文件只剩 1 条记录，这地址谁也打不着
  ★ 换 -z 不是换个口味：地址、范围、$、行号、. 一起跟着变，而它一个字都不报。用之前先数「sed 眼里有几条」。
```

屏幕上为什么这格信息量最大：
- `:loop;N;$!bloop;p` 输出 **6 行**（3 行的文件）：最后一轮手里是整个文件，`p` 打一遍、自动打印再打一遍。
- **错示范那一格是本节的核心**：同一条脚本改用**双引号**包住 → 输出 **3 行**、rc=0、零报错。
  因为双引号里 `$!` 归 bash 解释（本脚本没有后台任务 → 展开成空串），sed 收到的是**另一条脚本**。
  有后台任务时那个位置还会被换成进程号，脚本再变一次样。判据：**sed 脚本一律单引号** ——
  这条和第 02 章「展开是看不见的手」是同一件事，只是这次手伸进了 sed 的脚本里。
- 接下来那行给了「数记录」的方法：普通模式下 `sed -n "="` 打 **2 条**号（跨行那格）｜`-z` 模式 **1 条**。
- 同一条 `s/foo.bar/X/`：普通模式一个字都没换（`.` 撞不到换行，输出 0 行、rc 照样 0），
  `-z` 下**命中了**。也就是**点号能不能吃换行，跟着分隔符走**。
- 最后一刀：`-z` 下 `sed 2d` 出来 2 行、rc=0 —— 整个文件只剩 1 条记录，这个地址谁也打不着。

**直觉以为「`-z` 只是换个口味（拿 NUL 当分隔符）」**：屏幕上地址、范围、`$`、行号、`.` 全跟着变，而它一个字都不报。
用之前先数「sed 眼里有几条记录」。

第 5 格，地址：范围打到「结束」那行就关门，关门后才会重新起算；等不到结束就一路打到文件尾。

```
=== 5. 地址：范围打到「结束」那行就关门，关门后才会重新起算；等不到结束就一路打到文件尾 ===
  sed -n 2,4p → 输出 3 行 ｜ rc=0
      | one
      | end
      | skip
  sed -n /start/,/end/p（start 在样本里出现两次） → 输出 5 行 ｜ rc=0
      | start
      | one
      | end
      | start
      | end
  sed -n /one/,/never/p（结束地址永远不会出现） → 输出 5 行 ｜ rc=0
      | one
      | end
      | skip
      | start
      | end
  sed -n $p → 输出 1 行 ｜ rc=0
      | end
  → /start/,/end/ 那格：第一段的 end 一命中就关门，skip 不被打；第 5 行再撞 start 才**重新起算** —— 「起始模式
    出现两次」既不是只打第一段、也不是全打，得按开关几次数。/one/,/never/ 那格等不到结束就一直打到文件尾、
    rc=0：范围没收口不是语法错。$ 是「最后一条记录」，写 5,$ 才是「从第 5 行到结尾」。
```

屏幕上为什么三格合起来才是「地址」：
- `sed -n 2,4p` → **3 行**（按行号，最直白）。
- `/start/,/end/p` → **5 行**。样本里 `start` 出现两次，屏幕上打的是
  `start one end` + `start end`：第一段在 `end` 命中那刻**关门**，`skip` 没被打；
  第 5 行再撞 `start` 才**重新起算**。所以「起始模式出现两次」既不是只打第一段、也不是全打，得按开关几次数。
- `/one/,/never/p` → **5 行**，即从 `one` 一路打到文件尾。★ 范围没收口**不是语法错**，rc=0。
- `sed -n $p` → 1 行 `end`：`$` 是「最后一条记录」，写 `5,$` 才是「从第 5 行到结尾」。

第 6 格，分隔符与方言：`s|…|…|` 只是少写反斜杠；`-E` 和 BRE 的 `+` 正好互为反面。

```
=== 6. 分隔符与方言：s|…|…| 只是少写反斜杠；-E 和 BRE 的 + 正好互为反面 ===
  s/\/usr\/bin/\/bin/ → 输出 1 行 ｜ rc=0
      | /bin/env
  s|/usr/bin|/bin| → 输出 1 行 ｜ rc=0
      | /bin/env
  两条输出逐字节一样吗 → 一样 ｜ 分隔符换成 | # @ 都行：命中内容不变，只是不用再堆反斜杠
  BRE  s/a\+b/Z/ → 输出 3 行 ｜ rc=0
      | aaa
      | Z
      | a+b
  ERE  -E s/a+b/Z/ → 输出 3 行 ｜ rc=0
      | aaa
      | Z
      | a+b
  BRE  s/a+b/Z/（就是少写那个反斜杠的写法） → 输出 3 行 ｜ rc=0
      | aaa
      | ab
      | Z
  ★ 最后一格最贵：BRE 里裸 + 是**字面加号**，这条命令不报错、也不空转 —— 它换了 a+b 那一行，而真正想换的 ab
    那行原地不动、rc=0。反斜杠写串位 sed 不会提醒你，它只会换个地方动手（分组 () 写反了倒是会当场报错，因为
    \1 引用了一个不存在的组 —— 元字符和引用是两类错，一类安静、一类响。）
```

屏幕上为什么前两格要对账「逐字节一样」：`s/\/usr\/bin/\/bin/` 和 `s|/usr/bin|/bin|` 都给 `/bin/env`，
**一样** —— 换分隔符纯粹是为了少写反斜杠，`|`、`#`、`@` 都行，命中内容不变。
后三格才是要命的：`BRE s/a\+b/Z/` 和 `ERE -E s/a+b/Z/` 输出**完全相同**（中间那行变成 `Z`），
而 `BRE s/a+b/Z/`（少写那个反斜杠）输出的是第三种样子：`aaa / ab / Z` ——
它换了 `a+b` **那一行**，而真正想换的 `ab` 那行原地不动、**rc=0**。

**直觉以为「写反了 sed 会提醒我」**：屏幕上它不报错、也不空转，它**换个地方动手**。
同一格末尾还补了一条对照：分组 `()` 写反了倒是会当场报错（`\1` 引用了一个不存在的组）——
**元字符和引用是两类错，一类安静、一类响。**

第 7 格，`d` / `D` / `=` / `w`：四种「下场」各长什么样。

```
=== 7. d / D / = / w：四种「下场」各长什么样 ===
  sed /second/d（丢掉整条记录） → 输出 2 行 ｜ rc=0
      | first
      | third
  sed N 之后 /foo\nbar/D（只删模式空间的第一行） → 输出 1 行 ｜ rc=0
      | bar = 1
  → d 丢掉整条记录（3 行变 2 行）；D 只丢**模式空间里的第一行**、剩下那条带着重开一轮 —— setting foo 没了、
    bar = 1 还在（2 行变 1 行）。这俩不是同义词，差着一整行。
  sed =（行号 + 自动打印） → 输出 6 行 ｜ rc=0
      | 1
      | first
      | 2
      | second
      | 3
      | third
  → = 打的是**记录号**不是把行换成号：3 行的文件出 6 行；配 -n 就只剩 3 个号（那 3 个号就是「几条记录」）。
  w 的下场：stdout 只有 0 行（-n 且没写 p），磁盘上却多出 keep.txt（1 行）：
      | second
  当场清掉了吗 → 不在了（w 是「顺手写文件」的副作用：路径写错时，它就把东西稳稳落到那个错地方）
```

屏幕上为什么这四个字母不能互相代劳：
- `/second/d` → 2 行（`first`、`third`）：**丢掉整条记录**。
- `N` 之后 `/foo\nbar/D` → 1 行 `bar = 1`：**只丢模式空间里的第一行**，剩下那条带着重开一轮。
  `setting foo` 没了、`bar = 1` 还在。这俩不是同义词，差着一整行。
- `sed =` → **6 行**（`1 first 2 second 3 third`）：`=` 打的是**记录号**，不是「把行换成号」；
  配 `-n` 就只剩 3 个号 —— 那 3 个号就是「几条记录」。
- `w`：stdout **0 行**（`-n` 且没写 `p`），磁盘上却多出 `keep.txt`（1 行 `second`）。
  屏幕上还当场把它清掉并自证「不在了」—— 因为 **`w` 是「顺手写文件」的副作用**：路径写错时，
  它就把东西稳稳落到那个错地方。

第 8 格，收口：sed 手里的单位（一张表）+ 报错原文一格 + 自证。

```
=== 8. 收口：sed 手里的单位（一张表）+ 报错原文一格 + 自证 ===
  工具 ｜ 手里拿着什么          ｜ 一段话被换行劈开时          ｜ 「没换成」时的退出码
  grep ｜ 整行（要片段得 -o）    ｜ 一样看不见，得换记录分隔符   ｜ 没命中 1，真出错 2
  sed  ｜ 一行（模式空间）       ｜ 自己 N 拼，或 -z 换分隔符     ｜ 0，和改成功完全没区别
  awk  ｜ 一行里的字段           ｜ 改 RS（本章 awk 那支脚本演）  ｜ 0
  故意写一条没闭合的 s，报错原文上屏（不改写不翻译）：sed ｜ 原文[sed: -e expression #1, char 4: unterminated `s' command] ｜ rc=1
  同一条样本交给 grep 的语法错对照：grep｜ 原文[grep: Invalid regular expression] ｜ rc=2
  ★ 同一类「写错了」：本机 sed 退 1、grep 退 2 —— 退出码不跨工具通用。判据只有：0 才算跑成、非 0 一律去读原文；
    而 sed 的「什么都没改」也给 0，所以改文件必须自己数着对账（-i 那本账在 sedinplace.sh）。
  本章没演：-i 的真相（另支脚本）、--sandbox 下的 e/r/w、1~2 这类 GNU 步进地址、--posix 少哪些扩展、多文件时
  $ 与文件边界怎么纠缠、以及一切跟耗时和内存有关的表现。
  自证：沙箱里此刻有 9 个条目（样本 + 中间产物），sfdemo 在吗 → 在
  删掉之后 → sfdemo 在吗：不在 ｜ 本目录里叫 sfdemo 的残留条目 = 0 个（必须是 0）
[退出码 0]
```

屏幕上这张三行表就是全章的单位总表：grep 拿**整行**（要片段得 `-o`）、sed 拿**一行（模式空间）**、
awk 拿**一行里的字段**；被换行劈开时 grep 得换记录分隔符、sed 自己 `N` 拼或 `-z`、awk 改 `RS`；
而「没换成/没命中」的退出码：grep 是 **1（真出错 2）**，sed 和 awk 都是 **0**。
紧接的两格把这条钉死：**同一种「写错了」，本机 sed 退 1、grep 退 2** ——
屏幕原文分别是 `sed: -e expression #1, char 4: unterminated \`s' command` 和
`grep: Invalid regular expression`。**退出码不跨工具通用**，判据只剩「0 才算跑成、非 0 一律去读原文」。
末尾那行「本章没演」是这一节的边界：`-i` 的真相在下一支脚本，`--sandbox` 下的 `e/r/w`、`1~2` 步进地址、

## 10. 小证据：`s` 的地址后面还能挂 `I` —— GNU 认，POSIX 不保证

第 9 节演了 `g` 与 `2` 与 `&`，这一节补最后一个常用标志：忽略大小写。

```
$ printf "ERROR error eRRoR plain\n" | sed "s/error/E/g"
ERROR E eRRoR plain
[退出码 0]

$ printf "ERROR error eRRoR plain\n" | sed "s/error/E/gI"
E E E plain
[退出码 0]
```

屏幕上为什么这两行值得并排看：**同一份输入 `ERROR error eRRoR plain`，两个输出**。
不写 `I` 只剩 `ERROR E eRRoR plain`（只换了小写那个 `error`），写了 `I` 变成 `E E E plain`（三种大小写全认出来）。

`I`（以及小写 `i`）在 **POSIX 里没有定义**，所以它属于「各家自己决定要不要给」的那一类：

```
$ printf "  本机 busybox 的 sed 认不认 I → "; printf "ERROR\n" | busybox sed "s/error/E/I" 2>&1 || true
  本机 busybox 的 sed 认不认 I → E
[退出码 0]
```

本机恰好两台 sed 都给 —— 上面是 GNU sed 4.9，这一行是 busybox 的 sed，两者都把 `ERROR` 换成了 `E`。
判据回指第 20 节：**跨工具的写法（标志、转义、扩展）必须在每一台引擎上单独验一遍**，
不能凭「这一台认」推「那台认」，更不能凭「文档里有」推「本机有」。

## 11. sedinplace.sh 完整跑：就地改的四个代价

`-i` 这四个字符是本章最容易带进生产环境的一把刀。八格，四个代价：
**它换的是 inode、它要的是目录能写、它的幂等取决于你写的模式、它没命中也退 0**。

第 1 格，`-i.bak` / `-i` / `-i 空格 .bak`：三种写法三种下场。

```
$ bash sedinplace.sh
=== 1. -i.bak / -i / -i 空格 .bak：三种写法三种下场 ===
  -i.bak ｜ rc=0 ｜ 备份文件在吗 在 ｜ 备份里就是改前那份吗 是 ｜ 主文件现在是：
      | key=new
      | port=80
  -i（不带后缀）｜ rc=0 ｜ 多出任何备份了吗 没有 ｜ 目录里跟 b2 有关的文件 1 个 —— 改坏了当场没有任何退路
  -i .bak（带空格）｜ rc=1 ｜ 原文[sed: -e expression #1, char 1: unknown command: `.']
      主文件动了吗 没动 ｜ 有没有真留下一个叫 .bak 的东西 0 个
  → 直觉「-i 后面跟备份名，空格无所谓」：错。GNU sed 的 -i 只认**贴在一起**的后缀，分开写时 `.bak` 被当成
    sed 脚本、`s/key=old/key=new/` 被当成文件名 —— 上面那行英文就是它的原话，一个字节都没改。
```

屏幕上为什么三种写法要各演一遍：
- `-i.bak` → rc=0、备份在、**备份里就是改前那份**、主文件 `key=new / port=80`。
- 裸 `-i` → rc=0，但「多出任何备份了吗 → **没有**」，目录里跟这个文件有关的还是 1 个 ——
  **改坏了当场没有任何退路**。
- `-i .bak`（带空格）→ **rc=1**，原文 `sed: -e expression #1, char 1: unknown command: \`.'`，
  主文件**没动**，也没有真留下一个叫 `.bak` 的东西。

**直觉以为「`-i` 后面跟备份名，空格无所谓」**：GNU sed 的 `-i` 只认**贴在一起**的后缀。
分开写时 `.bak` 被当成了 sed 脚本、`s/key=old/key=new/` 被当成了文件名 —— 屏幕上那行英文就是它的原话。

第 2 格，★ `-i` 到底是「改这个文件」还是「换个文件」：改前改后是不是同一个。

```
=== 2. ★ -i 到底是「改这个文件」还是「换个文件」：改前改后是不是同一个 ===

屏幕上为什么这一格决定了好几件实务：`名字没变、内容变了 —— 改前改后是同一个 inode 吗 → **不同**`

## 12. 小证据：BSD 的 `sed -i ""` 撞本机 GNU sed，以及 sed 不补换行

网上大量教程写 `sed -i "" s/a/A/ file` —— 那是 BSD/macOS 的要求（`-i` 后面必须跟一个后缀串）。
把它原样敲进本机 GNU sed：

```
$ printf "alpha beta\n" > zz-bsd.txt
out=$(sed -i "" "s/a/A/" zz-bsd.txt 2>&1); rc=$?
printf "  sed -i \"\" 撞 GNU sed ｜ rc=%s ｜ 原文[%s]\n" "$rc" "$out"
printf "  文件动了吗 → [%s]（★ 那个空串被当成了 sed 脚本，真正的脚本被当成了文件名）\n" "$(head -1 zz-bsd.txt)"
rm -f zz-bsd.txt
  sed -i "" 撞 GNU sed ｜ rc=2 ｜ 原文[sed: can't read s/a/A/: No such file or directory]
  文件动了吗 → [alpha beta]（★ 那个空串被当成了 sed 脚本，真正的脚本被当成了文件名）
[退出码 0]
```

屏幕上为什么这两个数配在一起才叫完整：rc=**2**，原文 `sed: can't read s/a/A/: No such file or directory`。
那行英文自己把事故讲完了：**那个空串被当成了 sed 脚本，真正的脚本 `s/a/A/` 被当成了文件名**。
第二行同样重要 —— 文件动了吗 → `alpha beta`，**一字未动**。

**直觉以为「`-i ""` 大不了不生效」**：它不生效，而且退 2。
这条和第 11 节第 1 格（`-i .bak` 带空格退 1）是同一族：**`-i` 的后缀是「贴在一起」还是「分开」，
在不同家的 sed 里含义正好相反**，而两家的报错都发生在参数解析层，不是脚本层。

顺带回指第 11 节第 7 格：既然重定向会截断，那就地改完的另一个疑问是「末尾换行会不会被补回来」。

```
$ printf "x\ny" > zz-nl.txt
printf "  改前 %s 字节，最后一个字符是 [%s]（没有换行）\n" "$(wc -c < zz-nl.txt)" "$(tail -c 1 zz-nl.txt)"
sed -i "s/y/Z/" zz-nl.txt
printf "  sed -i 之后 %s 字节，最后一个字符是 [%s] —— ★ 它不替你补末尾换行\n" "$(wc -c < zz-nl.txt)" "$(tail -c 1 zz-nl.txt)"
printf "  所以下游的 wc -l 还是比 grep 少 1 行（回看 greppat 第 6 格）：现在 wc -l=%s ｜ grep -c \"\"=%s\n" \
  "$(wc -l < zz-nl.txt)" "$(grep -c "" zz-nl.txt)"
rm -f zz-nl.txt
  改前 3 字节，最后一个字符是 [y]（没有换行）
  sed -i 之后 3 字节，最后一个字符是 [Z] —— ★ 它不替你补末尾换行
  所以下游的 wc -l 还是比 grep 少 1 行（回看 greppat 第 6 格）：现在 wc -l=1 ｜ grep -c ""=2
[退出码 0]
```

屏幕上为什么这一格专门伺候下游：`printf "x\ny"` 造出的文件是 **3 字节**、最后一个字符是 `y`（没有换行）；
`sed -i "s/y/Z/"` 之后还是 **3 字节**、最后一个字符变成 `Z` —— ★ **它不替你补末尾换行**。
于是下游那两把尺立刻分家：`wc -l` = **1**（本机 uutils 数的是换行符个数），`grep -c ""` = **2**（grep 数的是它见过的记录）。
这和第 5 节第 6 格是同一件事，只是这次是「就地改」把无换行状态原样传了下去。

## 14. 小证据：同一根「前失败后成功」的管道，四个环境四个码

第 13 节在本机 bash 里演了开关，这一节把「换个 shell 就等于换了一套规矩」摊开。

```
$ printf "a\n" > zz-pf.txt
bash -c "grep nomatch zz-pf.txt | cat; echo \"  bash 默认              管道码=\$?\""
bash -c "set -o pipefail; grep nomatch zz-pf.txt | cat; echo \"  bash + pipefail         管道码=\$?\""
dash  -c "grep nomatch zz-pf.txt | cat; echo \"  dash（/bin/sh 真身）    管道码=\$?\""
dash  -c "set -o pipefail; grep nomatch zz-pf.txt | cat; echo \"  dash + pipefail         管道码=\$?\""
rm -f zz-pf.txt
  bash 默认              管道码=0
  bash + pipefail         管道码=1
  dash（/bin/sh 真身）    管道码=0
  dash + pipefail         管道码=1
[退出码 0]
```

屏幕上为什么四个数要一起看：`bash 默认` = 0、`bash + pipefail` = 1、`dash（/bin/sh 真身）` = 0、
`dash + pipefail` = **1**。

★ 反直觉的那行是**最后一行**：本机 dash 0.5.12 竟然认 `pipefail`。
写脚本时「这个 sh 认不认」必须**当场问**，不能按「POSIX 没有这个开关」的老印象下结论 ——
本章的判据是屏幕上那四个数，不是记忆。（这一格同时是本手册的一次公开改判：
早先的检查单里写着「dash 静默不认 pipefail」，屏幕上证明它是错的，见「这章的坑」。）

同一个 dash 换一个问题，它就不认了：

```
$ printf "  dash 有没有数组："; dash -c "a=1; echo \${a[@]}" 2>&1 | head -1
  dash 有没有数组：dash: 1: Bad substitution
[退出码 0]
```

`dash -c 'a=1; echo ${a[@]}'` 的原话是 `dash: 1: Bad substitution` —— **数组没有**。
两格合起来的判据：**「这个 shell 支持什么」是一问一答的事，不是一个标签的事**。

`awk` 一行给出：行数 **6**、总分 **459**、平均 **76.5**。

## 17. 小证据：`a[x,1]` 里没有二维数组，只有一个被粘起来的字符串键

第 16 节讲了「下标先变字符串」，这一节讲它的孪生坑：**逗号下标其实是 `SUBSEP` 拼接**。

```
$ awk "BEGIN{
  a[\"Ada\",1]=90; a[\"Alan\",2]=88
  for (k in a) { n=split(k,p,SUBSEP); printf \"第一段=%s 第二段=%s 值=%s 整键字符数=%s 切开份数=%s\n\", p[1], p[2], a[k], length(k), n }
}" | sort
第一段=Ada 第二段=1 值=90 整键字符数=5 切开份数=2
第一段=Alan 第二段=2 值=88 整键字符数=6 切开份数=2
[退出码 0]
```

屏幕上为什么键长那两列是证据：两行的整键字符数分别是 **5** 和 **6** ——
`Ada`（3 字符）+ 一个不可见的 `SUBSEP` + `1`（1 字符）= 5；`Alan`（4）+ 1 + 1 = 6。
`split(k, p, SUBSEP)` 又能把它们切回 **2 段**。所以「二维数组」是**一条拼出来的字符串**。

第二行给出那个分隔符的尺寸：

```
$ awk "BEGIN{ printf \"  SUBSEP 占几个字符=%s ｜ 用它粘出来的 a SUBSEP b 长度=%s（三个字符）\n\", length(SUBSEP), length(\"a\" SUBSEP \"b\") }"
  SUBSEP 占几个字符=1 ｜ 用它粘出来的 a SUBSEP b 长度=3（三个字符）
[退出码 0]
```

`length(SUBSEP)` = **1**、用它粘出来的 `a SUBSEP b` 长度 = **3**。
（这一格顺便解释了一个常见误解：`printf "%d", SUBSEP` 在 awk 里给的是 **0**，
因为那是「字符串转数字」的结果 —— 想知道它占几只能问 `length`。）

第三行把「同一件事」钉死：

```
$ awk "BEGIN{ k1 = \"x\" SUBSEP \"1\"; a[\"x\",\"1\"] = 90
  printf \"  逗号下标建出来的键，拿手写拼接的 k1 能查到吗 → %s ｜ 数组里元素数=%s（★ 它们本来就是同一个键）\n\", (k1 in a ? \"能\" : \"不能\"), length(a) }"
  逗号下标建出来的键，拿手写拼接的 k1 能查到吗 → 能 ｜ 数组里元素数=1（★ 它们本来就是同一个键）
[退出码 0]
```

手写拼接的 `k1 = "x" SUBSEP "1"` 去查用逗号下标建的 `a["x","1"]` —— **能查到**，且 `length(a)` = **1**。
判据：**awk 的「二维数组」是字符串键的把戏**，
所以「姓名里恰好带 `SUBSEP` 那个字节」就会撞成同一个键 —— 两个不同的 (人, 科目) 会合成一格。

```

  原行（cat -A：空格原样、制表符=^I、行尾=$）：
    ID1  name1   price9$

  → 直觉以为「我只补第 3 个字段，前两个字段凭什么跟着变」，屏幕上空白确实全变。
  ★ awk 改一行不是打补丁，是**整行重建**：给任意 $n 赋值后，$0 会按 OFS 重新拼一遍。
    「改一列结果 diff 炸一整行」的 awk 层原因就在这。
```

屏幕上为什么这一格要用 `cat -A`：原行 `ID1  name1   price9$`（两个空格、三个空格，行尾 `$` 标出边界），
**只动了第 3 个字段**之后，前两列之间的 2 空格、3 空格全塌成 awk 默认 OFS 的一个空格；

第 3 格，三种「拼接」：有没有逗号，字节数当场不一样。

```
=== 3. 三种「拼接」：有没有逗号，字节数当场不一样 ===
  print a,b（逗号 → 中间垫 OFS，默认一空格）: 输出[xy z]，5 字节

屏幕上为什么这三个字节数是三条路：`print a,b`（逗号 → 中间垫 OFS）输出 `[xy z]`、**5 字节**；
`print a b`（无逗号 → 直接贴一起）输出 `[xyz]`、**4 字节**（含换行）；

第 4 格，OFS 不是万能：同一个 `-v OFS=竖线`，两种写法对撞。

```
=== 4. OFS 不是万能：同一个 -v OFS=竖线，两种写法对撞 ===
  写法1 {print $0} → 输出[ID1  name1   price9]
  写法2 {print $1, $2} → 输出[ID1|name1]
  写法3 { $3="X" }1 → 输出[ID1|name1|X]

  ★ OFS 只在两处生效：① print 的逗号清单（写法2），② 字段被赋值后的 $0 重建（写法3）。
    没动过字段的整行输出（print $0 或光秃秃的 1）原样透传，OFS 管不着。
```

屏幕上为什么写法 1 最反直觉：设了 `OFS="|"` 之后，
`{print $0}` → `[ID1  name1   price9]`，**原样保留空格对齐、一个竖线没有**；
`{print $1, $2}` → `[ID1|name1]`；`{ $3="X" }1` → `[ID1|name1|X]`。

**没动过字段的整行输出（`print $0` 或光秃秃的 `1`）原样透传，OFS 管不着。**

第 5 格，空字段：`'a,,b'` 和 `'a:b:'` 各有几个字段（本机 mawk 实测数）。

```
=== 5. 空字段：'a,,b' 和 'a:b:' 各有几个字段（本机 mawk 实测数） ===

  [前后带空格的两词] → NF=2 —— 首尾空白不算字段

    只有默认 FS（空白）是「连续算一个、首尾不算」的宽松切法。

屏幕上三行给的是同一条公式：`[a,,b]` → **`NF=3`**，字段是 `[a] [] [b]`（两个逗号中间夹着空）；
`[a:b:]` → **`NF=3`**，字段是 `[a] [b] []`（末尾分隔符也多咬一个空字段）；

★ 最后一行的判据实用：同一份内容，逗号切出来 3 个字段、默认空白切可能只有 2 个 ——
**两个 NF 不是同一种货币，别混着比。**

第 6 格，NF 当现场判据：先让守卫响一次，它才可信。

```
=== 6. NF 当现场判据：先让守卫响一次，它才可信 ===
  探针轮：awk 'NF<3' 挑「字段不够的行」→ 挑中 1 行，退出码 0（守卫响了，证明它有牙）

```

屏幕上这格把本手册的守卫纪律搬进了 awk：
探针轮 `awk 'NF<3'` 挑「字段不够的行」→ 挑中 **1 行**、退出码 **0**（守卫响了，证明它有牙）；

**屏幕上和「真没短行」一模一样。**

第 7 格，收口：awk 的单位表 + 自建目录清场自证。

```
=== 7. 收口：awk 的单位表 + 自建目录清场自证 ===
  单位   = 一行里的字段：FS 决定怎么切，NF=这行的字段数，$n 可以赋值
  副作用 = 给任意 $n 赋值 → $0 按 OFS 整行重建（默认一个空格），原对齐阵亡

  退出码 = 除非 awk 自己出错，否则恒 0：挑没挑中、改没改到，与 rc 无关

  删之后在吗 → 不在 ｜ 当前目录里名叫 af 的条目 = 0（trap 只是备胎）
  ★ 一句话带走：sed 往「行」上打补丁，awk 拿「字段」重建整行；
    把空白对齐的行交给 awk 之前，先问两句：我的 OFS 接得住原空白吗？这行的 NF 和我想的一致吗？
[退出码 0]
```

屏幕上这张四行表是 awk 半区的总结：

副作用 = 给任意 `$n` 赋值 → `$0` 按 OFS 整行重建（默认一个空格），原对齐阵亡；
拼接 = `print` 逗号清单走 OFS、无逗号贴死、`printf` 逐字节自理（换行也要自己给）；
退出码 = **除非 awk 自己出错，否则恒 0**：挑没挑中、改没改到，与 rc 无关。
末尾那句和 sed 做了个对照：**sed 往「行」上打补丁，awk 拿「字段」重建整行**；
把空白对齐的行交给 awk 之前，先问两句：我的 OFS 接得住原空白吗？这行的 NF 和我想的一致吗？

## 19. 小证据：给越界的字段赋值，NF 自己长，空位用 OFS 垫

第 18 节讲的是「改现有字段」，这一节补「改到不存在的位置」—— 它会当场把行撑长。

```
$ printf "a b c\n" | awk "{ \$5=\"EE\"; printf \"NF=%s 重建=[%s]\n\", NF, \$0 }"
NF=5 重建=[a b c  EE]
[退出码 0]
```

屏幕上为什么 `NF=5` 是关键：`a b c` 只有 3 个字段，写 `$5="EE"` 之后 **NF 自己变成 5**，
重建出来的整行是 `[a b c  EE]`。第二遍用 `cat -A` 把空白显出来：

```
$ printf "a b c\n" | awk "{ \$5=\"EE\"; print \$0 }" | cat -A
a b c  EE$
[退出码 0]
```

`c` 和 `EE` 之间是**两个**空格 —— 第 4 个字段从来没存在过，重建时按 OFS 垫了一格。

```
$ printf "a b c\n" | awk "{ NF=2; printf \"砍到 NF=%s 之后整行=[%s]\n\", NF, \$0 }"
砍到 NF=2 之后整行=[a b]
[退出码 0]
```

反方向也成立：`NF=2` 之后整行 = `[a b]`，**当场丢掉后面的字段**。
这两条合起来是第 18 节第 2 格的完整形状 ——
**awk 手里的「一行」是字段列表，`$0` 只是它的显示形式，一动字段整个显示就重排。**

## 20. awkmawk.sh 完整跑：会叫的缺件与不会叫的缺件

一种当场报错、程序停下；另一种 `rc=0`、一句废话没有，而活根本没干。
后者才是本章最贵的判据，所以它单独占两格（第 3、4 格）。

屏幕上这三行是一条**证据链**，不是一句自我介绍：`awk --version` 首行 = `[mawk 1.3.4 20260129]`；

第 2 格，会叫的缺件：`gensub` / `asort` / `strtonum`，报错原文逐字上屏。

    程序当场死在这一行，不会带着错结果往下跑 —— 会叫的缺件其实是友善的。

**直觉以为「函数不存在大概就给个空值继续跑」**：程序当场死在这一行，不会带着错结果往下跑。

第 3 格，★★ 不会叫的缺件（一）：`FIELDWIDTHS` 固定宽度切分，**静默空转**。

第 4 格，★★ 不会叫的缺件（二）：awk 的 `/\s/` 匹配的是**字母 s**，不是空白。

这一格的设计就是「让探针响在错的东西上」：样本两行，第 1 行 `a b`（**有空白、没 s**），
第 2 行 `justs`（**有 s、没空白**）。三组数字并排列在屏幕上：

这一格也顺手解释了第 2 节探针为什么要「先故意弄响一次」—— 响了，但**响在错的东西上**，比不响更难发现。

第 5 格，别把 mawk 当残废：这一半全都能用（输出全是确定值）。

```

屏幕上五行都是**能直接复用的写法**，而且每条都配了一个确定值当证据：
`length(arr)` → **3**、`delete arr` 之后 → **0**；`ENVIRON["AMK_STABLE"]` → `[fixed-value-42]`
（值由脚本自己 export，恒定，所以敢印）；`"cmd" | getline x` → 拿到 `[from-mawk-cmd]`；
`strftime` **只验形状**（首行 4-2-2 位数字吗 → 是；总长 10 位）—— 日期值不上屏，因为它每天必变；
最后一行是纪律：读未定义变量 `${AMK_NOSET-}` → `[]`，空串、不报错。

**直觉容易走两个极端**：「mawk 是残废」或「和 gawk 全等」。屏幕上的答案是：数组、环境变量、
管道 getline、strftime **全都在**，缺的只是 gawk 的私有语法（第 2、3 格那些）。

第 6 格，awk 的数字走 double：`2^53` 的断崖上，数字骗你不吭声。

```
=== 6. awk 的数字走 double：2^53 的断崖上，数字骗你不吭声 ===
  直接打 2^53 → 9007199254740992（纯计算，每跑必同，才敢印出来）
  判据一：2^53+1 打印回来还等于 2^53 吗 → 是（★ +1 被吞了，rc 照样 0）
  判据二：2^53+2 等于 2^53 吗 → 否（这个坡上只剩下偶数，+2 恰好还站得住）
  判据三：2^60+1 等于 2^60 吗 → 是（数越大，坑越深）
  → 直觉以为「数字做算术不会骗人」，屏幕上 +1 整个被吃掉，无报错、无警告。
  ★ 所以别拿 awk 数雪花 ID、累加超大整数 —— 过了 2^53 和第 3、4 格同族：静静地错。
```

屏幕先给一个确定值打底：直接打 `2^53` → **9007199254740992**（纯计算，每跑必同，才敢印）。
然后三条判据全部由 awk 自己算、自己答：**`2^53+1` 打印回来还等于 `2^53` 吗 → 是**（+1 被吞了）；
**`2^53+2` 等于 `2^53` 吗 → 否**（这个坡上只剩偶数，+2 恰好还站得住）；
**`2^60+1` 等于 `2^60` 吗 → 是**（数越大，坑越深）。

**直觉「数字做算术不会骗人」**：屏幕上 +1 整个被吃掉，无报错、无警告、rc 照样 0。
★ 别拿 awk 数雪花 ID、累加超大整数 —— 过了 `2^53` 就和第 3、4 格同族：**静静地错**。
下一节（第 21 节）把「大整数从哪儿进来」的三条路各演一遍。

第 7 格，收口：「会叫 / 不会叫」两张清单并排 + 清场自证。

```
=== 7. 收口：「会叫 / 不会叫」两张清单并排 + 清场自证 ===
  --- 会叫的缺件（友善的那半：报错停下）---
    awk: line 2: function gensub never defined
    gensub/asort/strtonum 同款报错格式，rc 全 2（真出错档）
  --- 不会叫的缺件（危险的那半：rc=0 但活没干）---
    FIELDWIDTHS：整行塞进 $1、$2 空、NF=1，rc=0
    /\s/：被当字母 s 用（同机 grep/sed 却读成空白类），rc=0
    超大整数 +1：精度掉崖，rc=0，纹丝不响
  ★ 带走判据：grep/sed/awk 里「没报错」绝不等于「按你的意思生效了」；
    现场验收三件兵：数 NF、打出来对内容、先让探针响一次再信守卫。
  自证（现场清干净）：删之前 amk 在吗 → 在
  删之后在吗 → 不在 ｜ 当前目录里名叫 amk 的条目 = 0（trap 只是备胎）
[退出码 0]
```

屏幕上这张对账单是本节的骨头：**左边（会叫）**只有一条报错格式
`awk: line 2: function gensub never defined`，rc 全 2；
**右边（不会叫）**列了三件：`FIELDWIDTHS` 整行塞进 `$1`、`NF=1`、rc=0；
`/\s/` 被当字母 s 用、rc=0；超大整数 +1 精度掉崖、rc=0 **纹丝不响**。
三件的共同点是**码都是 0**。

★ 带走判据：grep/sed/awk 里「没报错」**绝不等于**「按你的意思生效了」。
现场验收三件兵：**数 NF**、**把内容打出来对一遍**、**先让探针响一次再信守卫**。
最后两行是本章一贯的清场自证：`amk` 删之前**在**、删之后**不在**，当前目录里同名条目 = **0**（trap 只是备胎）。

## 21. 小证据：一个 18 位整数走三条路，两条掉精度、一条原样保留

第 20 节第 6 格演了 `2^53` 的断崖，这一格把「大整数**从哪儿进来**」三条路摆全 ——
差别不在有没有报错，在**有没有被当成数**。

```
$ awk "BEGIN{ x=123456789012345678; printf \"  ① 字面量直接打：%s\n\", x }"
  ① 字面量直接打：123456789012345680
[退出码 0]

$ awk -v n=123456789012345678 "BEGIN{ printf \"  ② -v 传进来再 +0：%s\n\", n+0 }"
  ② -v 传进来再 +0：123456789012345680
[退出码 0]
```

① 字面量直接打、② `-v` 传进来再 `+0`：两条路的下场**一模一样** ——
`123456789012345678` 出来都是 **123456789012345680**，末两位 `78` 变成 `80`。
也就是说「用 `-v` 传参」救不了精度，它在入口那一刻就已经换成 double 了。

```
$ printf "123456789012345678\n" | awk "{ printf \"  ③ 从文件读进来、原样拼成串：%s\n\", \$1 \"\" }"
  ③ 从文件读进来、原样拼成串：123456789012345678
[退出码 0]

$ printf "123456789012345678\n" | awk "{ printf \"  ④ 同一个字段只做一次 +0：%s（★ 掉精度就发生在这一动）\n\", \$1+0 }"
  ④ 同一个字段只做一次 +0：123456789012345680（★ 掉精度就发生在这一动）
[退出码 0]
```

③ 从文件读进来、**原样拼成串** → **123456789012345678**，一个字节都没变；
④ 同一个字段只做**一次 `+0`** → **123456789012345680**。
这两格吃的是同一份输入，唯一的差别就是那一次 `+0` —— 屏幕上把「掉精度就发生在这一动」标得很直白。

```
$ awk "BEGIN{ x=123456789012345678; printf \"  ⑤ 和原始字面串比一下：%s（无报错、rc 照样 0）\n\", (x \"\" == \"123456789012345678\") ? \"相同\" : \"不同\" }"
  ⑤ 和原始字面串比一下：不同（无报错、rc 照样 0）
[退出码 0]
# 三条路的分水岭是「有没有被当成数」：①②④ 一旦进算术就换成 double，末两位 78 变 80；
#   ③ 之所以原样，是因为字段是「长得像数的串」，没被 +0、没被比较，就还是那串字符。
# 判据：雪花 ID、毫秒时间戳、订单号这类超过 15 位的整数，在 awk 里要么一路当串搬（不 +0、不比大小），
#   要么交给真能处理任意精度的一方 —— 本章不演后者（那是别的工具，且不在三剑客这一章的账上）。
```

⑤ 把①那个字面量和**原始字面串**比一下 → **不同**，而括号里补的是最阴的一句：**无报错、rc 照样 0**。
下面两行注释是本节的分水岭判据：**有没有被当成数**。
③ 之所以原样，是因为字段是「长得像数的串」，没 `+0`、没比大小，它就还是那串字符。

★ 雪花 ID、毫秒时间戳、订单号这类**超过 15 位**的整数，在 awk 里要么一路当串搬（不 `+0`、不比大小），
要么交给真能处理任意精度的一方 —— 本章不演后者（那是别的工具，不挂在三剑客这一章的账上）。

## 22. 综合演练：一份写死的脏日志，三连各就各位

前面 21 节是分科考试，这一节是综合题：**grep 选行 → sed 改形状 → awk 按字段汇总**，
三刀各干自己最擅长的那件事。日志每一行都是脚本现造的常量（时间戳写死，绝不用 `date`），
所以这一节的每一遍输出都相同。

```
# 三剑客串一遍：grep 负责选行、sed 负责改形状、awk 负责按字段汇总。
# 日志的每一行都是下面现造的常量，所以每一遍输出都相同（时间戳由脚本写死，绝不用 date）。

$ mkdir -p zz-drive
printf "%s\n" \
  "2026-10-14 07:12:01 ERROR disk quota uid=1001" \
  "2026-10-14 07:12:09 WARN cache miss uid=1002" \
  "2026-10-14 07:13:22 ERROR disk quota uid=1001" \
  "2026-10-14 07:14:05 INFO retry scheduled uid=1003" \
  "2026-10-14 07:15:41 ERROR network unreachable uid=1002" > zz-drive/app.log
printf "  现场：%s 行 ｜ 字节数 %s\n" "$(wc -l < zz-drive/app.log)" "$(wc -c < zz-drive/app.log)"
  现场：5 行 ｜ 字节数 242
[退出码 0]
```

现场：5 行、**242 字节**。五行内容里 3 行是 `ERROR`、1 行 `WARN`、1 行 `INFO`；
`uid=1001` 占两行（**两行都是 ERROR**），`uid=1002` 占两行（一行 WARN、一行 ERROR），`uid=1003` 占一行。
这个形状是为第三刀准备的：选完 ERROR 之后 1001 剩 2、1002 只剩 1。
另外每一行里 `ERROR` 这个词最多出现**一次**，好让第 5 节那对尺（行数 vs 次数）在这里再对一次账。

第一刀，grep 负责**选行**——守卫先响一次，它的 0 才算数。

```
# ── 第一刀 grep：选行。先让守卫响一次，它的 0 才算数。

$ printf "  守卫探针：挑 FATAL → 命中 %s 行，grep 自己的码=%s（★ 这一响证明它不是哑的）\n" \
  "$(grep -c FATAL zz-drive/app.log)" "$(grep -q FATAL zz-drive/app.log; echo $?)"
printf "  真要的：ERROR 行数=%s ｜ -o 数次数=%s（这道题里两个数刚好相等，因为一行只出现一次）\n" \
  "$(grep -c ERROR zz-drive/app.log)" "$(grep -o ERROR zz-drive/app.log | wc -l)"
  守卫探针：挑 FATAL → 命中 0 行，grep 自己的码=1（★ 这一响证明它不是哑的）
  真要的：ERROR 行数=3 ｜ -o 数次数=3（这道题里两个数刚好相等，因为一行只出现一次）
[退出码 0]
```

屏幕上先给探针：挑 `FATAL` → 命中 **0 行**，grep 自己的码 = **1**（这一响证明它不是哑的）。
真要的那格：`ERROR` 行数 = **3**、`-o` 数次数 = **3**。这两个数在这道题里**刚好相等**，
括号里也老实写了原因（一行只出现一次）—— 相等不是规律，是这份样本的形状。

第二刀，sed 把选出来的行洗成「时间 级别 uid」三列，**原文件一个字不动**。

```
# ── 第二刀 sed：把选出来的行洗成「时间 级别 uid」三列，原文件一个字不动。

$ grep ERROR zz-drive/app.log | sed -E "s/^([0-9-]+) ([0-9:]+) ([A-Z]+) .* (uid=[0-9]+)$/\2 \3 \4/" | tee zz-drive/cols.txt
printf "  洗出来 %s 行 ｜ 第一行现在只剩 [%s]\n" "$(wc -l < zz-drive/cols.txt)" "$(head -1 zz-drive/cols.txt)"
07:12:01 ERROR uid=1001
07:13:22 ERROR uid=1001
07:15:41 ERROR uid=1002
  洗出来 3 行 ｜ 第一行现在只剩 [07:12:01 ERROR uid=1001]
[退出码 0]
```

`sed -E "s/^([0-9-]+) ([0-9:]+) ([A-Z]+) .* (uid=[0-9]+)$/\2 \3 \4/"` 把日期整段丢掉，留下
`07:12:01 ERROR uid=1001` 这样的三列。洗出来 **3 行**，屏幕上第一行原样是 `[07:12:01 ERROR uid=1001]`。
注意这里用的是 `-E`（ERE），因为写法里有裸的 `+` —— 这正是第 3 节那条判据的正面用法。

第三刀，awk 按**最后一个字段**分组计数。

```
# ── 第三刀 awk：按最后一个字段分组计数。数组遍历顺序不保证，所以外接 sort。

$ sort -k1,1 -k2,2nr zz-drive/cols.txt | awk "{ c[\$NF]++ } END { for (k in c) printf \"%s %s\\n\", k, c[k] }" | sort -k2,2nr -k1,1
uid=1001 2
uid=1002 1
[退出码 0]
```

`{ c[$NF]++ } END { for (k in c) ... }`，输出 `uid=1001 2`、`uid=1002 1`。
这一行管道里出现了**两次 sort**：进去之前先按时间和次数排（`-k1,1 -k2,2nr`），出来之后再按
次数、uid 排（`-k2,2nr -k1,1`）。为什么要外接：awk 的**数组遍历顺序不保证**（第 16 节那条判据）。

三道刀之间还夹了一次对账，这是全节的验收单：

```
$ printf "  合计校验：awk 数出 %s 行，grep -c 数出 %s 行 → %s\n" \
  "$(grep ERROR zz-drive/app.log | awk "END{ print NR }")" "$(grep -c ERROR zz-drive/app.log)" \
  "$([ "$(grep ERROR zz-drive/app.log | awk "END{ print NR }")" = "$(grep -c ERROR zz-drive/app.log)" ] && echo 一样 || echo 不一样)"
  合计校验：awk 数出 3 行，grep -c 数出 3 行 → 一样
[退出码 0]
```

**awk 数出 3 行，grep -c 数出 3 行 → 一样**。这条比的是「sed 洗过之后 awk 看到的行数」和
「grep 一开始选出的行数」—— 中间那一刀如果误删或多留行，这两个数就会分家。

收尾再补一刀 sed，因为这一层是**就地改**，所以把第 11 节那条判据放在动手前面：

```
# ── 收尾再补一刀 sed：这一层是「就地改」，所以先把守卫数命中做在前面（第 11 节那条判据）。

$ cp zz-drive/app.log zz-drive/app2.log
before=$(grep -c "uid=1001" zz-drive/app2.log)
sed -i "s/uid=1001/uid=2001/g" zz-drive/app2.log
printf "  改前该模式命中 %s 处 ｜ 改后 uid=1001 还剩 %s 处 ｜ 新值有几处 %s 处\n" \
  "$before" "$(grep -c "uid=1001" zz-drive/app2.log)" "$(grep -c "uid=2001" zz-drive/app2.log)"
printf "  → 三件事分开数：动手前数一遍、动手后数一遍残留、再数一遍新值。只看 sed 的码（永远 0）等于没数。\n"
  改前该模式命中 2 处 ｜ 改后 uid=1001 还剩 0 处 ｜ 新值有几处 2 处
  → 三件事分开数：动手前数一遍、动手后数一遍残留、再数一遍新值。只看 sed 的码（永远 0）等于没数。
[退出码 0]
```

屏幕上三件事分开数：**改前该模式命中 2 处**、**改后 `uid=1001` 还剩 0 处**、**新值 `uid=2001` 有 2 处**。
括号里那句是全节最实用的一条：**只看 sed 的码（永远 0）等于没数** —— 2 处变 0 处 + 新值 2 处，
这三个数字才叫「改成功了」。

```
# 这一节的现场自己收（第 25 节要检查沙箱里除脚本外不留任何东西）：

$ rm -rf zz-drive; printf "  删掉之后，本目录里跟 zz-drive 有关的条目=%s 个\n" "$(ls -d zz-drive 2>/dev/null | wc -l)"
  删掉之后，本目录里跟 zz-drive 有关的条目=0 个
[退出码 0]
```

这一节的现场自己收：`rm -rf zz-drive` 之后，本目录里跟 `zz-drive` 有关的条目 = **0 个**。
下一节（第 25 节）要在整章结束时再检查一遍「沙箱外面一个条目都没多」。

## 23. 三张码表并排：同一件事 grep / sed / awk 各给什么码

第 22 节用了「三态」，这里把三个工具在**五种场景**下的退出码一次摊平 —— 每一格都当场跑，
屏幕上只印码不印原文，免得看错行。

```
# 第 22 节用了「三态」，这里把三个工具的五种场景一次摊平（每一格都当场跑，只印码不印原文）。

$ mkdir -p zz-codes; cd zz-codes
printf "error here\nplain line\n" > s.txt
code() { "$@" >/dev/null 2>&1; printf "%s" "$?"; }
printf "  %-22s %-7s %-7s %-7s\n" 场景 grep sed awk
printf "  %-20s %-7s %-7s %-7s\n" "命中/改成" \
  "$(code grep -q error s.txt)" "$(code sed "s/e/E/" s.txt)" "$(code awk 1 s.txt)"
printf "  %-20s %-7s %-7s %-7s\n" "没命中" \
  "$(code grep -q nosuch s.txt)" "$(code sed "s/nosuch/X/" s.txt)" "$(code awk "nosuch" s.txt)"
printf "  %-20s %-7s %-7s %-7s\n" "文件不存在" \
  "$(code grep -q error 没有这个.txt)" "$(code sed "s/a/A/" 没有这个.txt)" "$(code awk 1 没有这个.txt)"
printf "  %-20s %-7s %-7s %-7s\n" "自己的语法错" \
  "$(code grep -E "(" s.txt)" "$(code sed "s/a" s.txt)" "$(code awk "{" s.txt)"
printf "  %-20s %-7s %-7s %-7s\n" "空输入（管道里没东西）" \
  "$(code grep -q x </dev/null)" "$(code sed "s/a/A/" </dev/null)" "$(code awk 1 </dev/null)"
cd ..; rm -rf zz-codes
  场景                 grep    sed     awk    
  命中/改成        0       0       0      
  没命中            1       0       0      
  文件不存在      2       2       2      
  自己的语法错   2       1       2      
  空输入（管道里没东西） 1       0       0      
[退出码 0]
# 读表：第二行是全章最重要的一行 —— 「没命中」只有 grep 给你码，sed 和 awk 都是 0。
# 第四行是第二重要的一行：同样是「你的正则写错了」，sed 退 1、grep 和 awk 退 2（三家的档不同）。
# 所以本章的纪律：判「有没有」问 grep；判「改没改」动手前后各数一遍；码只用来判「工具自己有没有出事」。
```

这张表只有五行数据。下面这张是把它**连同屏幕上那三行注释**一起重排的，第四列「该怎么用」是本书的读法，
不在屏幕上；前三列的每一个数字都来自上面那次运行：

| 场景 | grep | sed | awk | 该怎么用 |
|---|---|---|---|---|
| 命中 / 改成 | 0 | 0 | 0 | 三家都「没事」，这一行没有信息量 |
| **没命中** | **1** | **0** | **0** | 只有 grep 把结果写进码里；sed/awk 的 0 是「我跑完了」，不是「我改到了」 |
| 文件不存在 | 2 | 2 | 2 | 三家一致：这是事故，必须去读报错原文 |
| **自己的语法错** | 2 | **1** | 2 | 同样叫「你写错了」，sed 退 **1**，和「没命中」共用一个码 |
| 空输入（管道里没东西） | 1 | 0 | 0 | 和「没命中」一模一样 —— 管道空转在码上是看不出的 |

第二行是全章最重要的一行：**「没命中」只有 grep 给你码，sed 和 awk 都是 0**。
第四行是第二重要的：**同样是「正则写错了」，sed 退 1、grep 和 awk 退 2**，三家的档位不同。

★ 本章的纪律由此落成一句话：**判「有没有」问 grep；判「改没改」动手前后各数一遍；
退出码只用来判「工具自己有没有出事」。**

## 一张表：三剑客的三本账 —— 单位、能不能就地改、码表不表结果

第 13 节第 8 格收了「管道三环」的账，第 18 节第 7 格收了 awk 的单位表。这一张把三家并到一起，
每一格都能在前面的屏幕上找到出处 —— 表里最后一列就是那一节：

| 这本账 | grep | sed | awk | 哪一节钉的 |
|---|---|---|---|---|
| **手里的单位** | 整行（`-o` 才给片段，`-l` 给文件名） | 模式空间里的**一行**，一动就整行重打 | 一行里的**字段**：FS 怎么切、NF 有几个、`$n` 可赋值 | 第 5、9、18 节 |
| **能不能就地改文件** | 不能，它只读 | 能：`-i`（但那是**换 inode**，不是原地涂） | 不原生；而且 `awk ... f > f` 会把自己的输入吃掉 | 第 11、15 节 |
| **退出码表不表结果** | **表**：0 有 / 1 没有 / 2 出错 | 不表：没命中照样 0；自己语法错退 **1** | 不表：除自己出错外恒 0 | 第 3、23 节 |
| **方言 / 实现有几套** | BRE、ERE、PCRE 三套，外加 `-F` 不算正则 | BRE、`-E`，GNU 的 `I`、`-z` 是自家扩展 | mawk 与 gawk 是**两个实现**，缺件不一样 | 第 3、9、20 节 |
| **最容易静默失效的一格** | `\|` 到了 ERE、`\d` 到了 ERE：0 行或**错答案**，都不报错 | 被换行劈开的文本：没换成、退 0、文件一字未动 | `FIELDWIDTHS`、`/\s/`、超大整数 `+1`：`rc=0` 空转 | 第 3、9、20 节 |
| **改坏了怎么发现** | 数行数（`-c`）与数次数（`-o \| wc -l`）两个都要，再看码 | 动手前后各数一遍命中 | 数 `NF`、把字段打出来对内容、外接 `sort` 再比 | 第 5、11、18 节 |

六行合起来就是本章的一句话：**这三家唯一相同的是「按行吃饭」，其余三本账（单位、能不能就地改、码表不表结果）
每家各记各的 —— 抄来的命令先问「这一句里谁在数、谁在决定成败」，别问「它看起来对不对」。**

## 一页纸（考前扫这半页）

- **不带开关的 grep 是 BRE**，反斜杠的含义和 `-E`（ERE）**正好相反**：`\|` ↔ `|`、`\+?{}` ↔ `+?{}`（第 3 节）。
- **跨方言最大的坑不是报错，是安静地给你 1 行/0 行**：`\d+` 到了 ERE 读成「字母 d 一个以上」，
  本机命中 1 行的**错答案**，rc 还是 0（第 3 节第 4 格）。
- **按字面找串就 `-F`，找整词就 `-w`**：`a.b` 用正则多命中 `axb`，`hello` 不加 `-w` 会把 `helloworld` 也算进来（第 3 节第 5 格）。
- **0/1/2 三态各撞一次**：0 是命中，1 是「确实没有」（答案），2 才要去读报错原文；
  报错文本跟着 locale 变，**码不变**，所以分支只写码（第 3 节第 6 格）。
- **grep 给的是整行**：要片段必须 `-o`，而 `-o` **不回头重叠**（第 5、6 节）。
- **`-c` 数的是行，`-o | wc -l` 数的是次数**，一行里出现两次就差 1（第 5 节第 2 格）。
- **问「有没有」用 `-q`**：`grep -c` 把数字打进 stdout，塞进 `[ ]` 或管道就是事故（第 7 节第 1 格）。
- **`grep -v` 滤干净了退 1**，还在管道里把上游的码吃掉（第 7 节第 3 格）。
- **递归时「挑哪些文件」是另一套开关**：`grep -r` **不会替你排 `.git`**；带空格的文件名交给下游必须 `-Z` 配 `-0`（第 7、8 节）。
- **模式自己以 `-` 开头**时用 `-e PATTERN` 或 `--`，别指望加引号（第 4 节）。
- **sed 每一行都过一遍流水线**：`p` 是「额外再打一遍」，不是「改成只打这个」（第 9 节第 1 格）。
- **不写 `g` 只换第一个**；`g` 全换；`2` 只换第二个；`&` 是整段命中（第 9 节第 2 格）。
- **被换行劈开的文本，sed 一眼看不到**：没换成、退 0、文件也一字未动；要跨行就自己 `N` 循环，或 `-z` 换分帧符（第 9 节第 3、4 格）。
- **地址范围打到「结束」那行就关门**，关门之后才会重新起算；等不到结束就一路打到文件尾（第 9 节第 5 格）。
- **`-i` 不是「改这个文件」，是「换个文件」**：改前改后**不是同一个 inode**，软链接与只读位的下场都在屏幕上（第 11 节第 2、3 格）。
- **没命中时 `-i` 照样退 0**：动手前先 `grep -c` 数一遍命中，这道守卫要先故意弄响一次（第 11 节第 5 格）。
- **经典自毁：`sed "s/a/A/" f > f` 把文件清空，而且退 0**（第 11 节第 7 格）。
- **管道的退出码默认由最后一环说了算**，前面所有的失败被它洗掉；同一根管道在 bash / `pipefail` / dash / busybox 里四个码（第 13 节第 3 格、第 14 节）。
- **换行符是传送带的分帧符**：谁漏了换行，下一环就把两行当一行（第 13 节第 2 格）。
- **awk 数组不用声明、下标是字符串、写一下就自己长出来**；`101`、`"101"` 是同一个键，`"0101"` 不是（第 16 节第 1、5 格）。
- **`NR==FNR` 是「正在读第一个文件」**，靠两台计数器在同一行相等；换文件时 `FNR` 回到 1（第 16 节第 2 格）。
- **判存在一律用 `k in arr`**：写 `arr[k]` 是**有副作用的读**，读一下就凭空多一个元素（第 16 节第 4 格：3 → 4）。
- **awk 没有二维数组**：`a[x,1]` 只是被 `SUBSEP`（长度 1）粘起来的字符串键（第 17 节）。
- **给任意 `$n` 赋值 = 整行按 OFS 重建**，原来的空格/制表符对齐当场阵亡；`print $0` 不受 OFS 管（第 18 节第 2、4 格）。
- **空字段也占坑**：显式 FS 时字段数 = 分隔符个数 + 1；默认空白是「连续算一个、首尾不算」—— 两个 `NF` 不是同一种货币（第 18 节第 5 格）。
- **「没报错 + rc 0」绝不等于「按你的意思生效了」**：`FIELDWIDTHS`、`/\s/`、超大整数三格全是 rc=0 空转（第 20 节第 3、4、6 格）。
- **超过 15 位的整数**：不 `+0`、不比大小就还是那串字符；动一次算术末两位就变（第 21 节）。
- **守卫必须先能响**：`NF>99` 的恒假守卫和「真没鱼」在屏幕上一模一样（第 18 节第 6 格、第 24、25 节）。

## 这章的坑（按代价从大到小）

1. **把抄来的一行命令原样跑。** 代价：方言不匹配时它**不报错**，只安静给你 0 行或**错的东西**。
   屏幕上最狠的一格是 `\d+` 到了 ERE（第 3 节第 4 格）：命中 1 行、rc=0，而中的是含字母 d 的那行 ——
   比 0 行更难发现，因为它**看起来像答案**。
2. **把「没报错」当成「生效」。** 代价：`FIELDWIDTHS` 静默空转（整行进 `$1`、`NF=1`、rc=0）、
   `/\s/` 在 mawk 里当字母 s、超大整数 `+1` 被吞（第 20 节第 3、4、6 格）。三条**码都是 0**。
3. **以为 sed 能看见跨行。** 代价：模式跨不过换行，没换成、退 0、**文件一字未动**（第 9 节第 3 格）；
   第 11 节第 5 格再补一刀：没命中时 `-i` 照样退 0，你以为改了，其实什么都没改。
4. **拿管道的退出码判断成败。** 代价：默认只有**最后一环**的码活着，前面全被洗掉（第 13 节第 3 格）；
   `grep -v` 还会把上游的码吃掉（第 7 节第 3 格）。同一根管道的码在四种 shell 下有四个值（第 14 节）。
5. **`sed "s/x/y/" f > f`。** 代价：文件被**清空**，而且退 0（第 11 节第 7 格）。重定向在命令读取之前
   就把目标截断了 —— 这一条是唯一能让人真的丢数据的坑，所以它排在写错正则之上。
6. **以为 `-i` 是「原地改」。** 代价：`-i` 新建文件再改名，**inode 变了**（第 11 节第 2 格），
   软链接指向、别的进程的可见性、mode/属主都会跟着变（第 3 格）。
7. **把空白对齐的文件交给 awk 改一列。** 代价：给任意 `$n` 赋值后 `$0` 按 OFS **整行重建**，
   2 空格、3 空格、制表符全塌成一个空格（第 18 节第 2 格）——「改一列，diff 炸一整行」。
8. **`if (arr[k])` 当存在性检查。** 代价：**读一下就创建**，后面所有 `length()`、`for (k in arr)`、
   累加全被这个假元素污染（第 16 节第 4 格）。
9. **两份文件的 key 不逐字节一致。** 代价：join 不上，而 awk **默认谁也不丢**，你不写分支就看不见它掉了
   （第 16 节第 3 格）；最常见的真实成因就是那个前导零 —— `0101` 命中 0、`101` 命中 1（第 5 格）。
10. **用 `grep -c` 问「有没有」。** 代价：数字进了 stdout，`[ "$(grep -c …)" ]` 把空串和 0 混在一起，
    管道里它又把码换成自己的（第 7 节第 1 格）。
11. **`.` 当成「这个点」。** 代价：静默多命中一堆（`a.b` 命中 `axb`）；按字面找配置项、版本号、
    `(fix me)`、`$HOME` 一律 `-F`（第 3 节第 5 格）。
12. **恒假守卫。** 代价：`awk 'NF>99'` 永远 0 行、退出码永远 0，屏幕上和「真干净」一模一样，
    比没有守卫更糟（第 18 节第 6 格）。本章每一条 0 前面都插了一根**注定会响**的探针（第 22、24、25 节）。
13. **相信 awk 的遍历顺序。** 代价：`for (k in arr)` 顺序不保证，同一份数据两次跑输出顺序可能不同 ——
    本章每一处都比对输出，所以**外接 `sort`**（第 16 节第 6 格、第 22 节）。
14. **按报错文本做分支。** 代价：文本跟着 locale 变（grep 中文、uutils 的 `wc` 永远英文），
    而**退出码不变**，所以脚本里只拿 0/1/2 分支（第 1 节、第 3 节第 6 格）。

## 自检问题

1. 不带任何开关的 `grep` 用哪套正则？`|` 是什么？—— BRE；`|` 是**字面竖线**，「或」要写 `\|`（第 3 节第 2 格）。
2. `grep -E 'ab\|axb'` 在本机命中几行、什么码？—— **0 行、rc=1**，一句报错都没有（第 3 节第 2 格）。
3. `\d+` 交给 `-E` 是「没匹配」吗？—— 不是，它读成「字母 d 一个以上」，本机命中 **1 行的错答案**，rc=0（第 3 节第 4 格）。
4. 要按字面找 `1.2.3` 该怎么写？—— `grep -F '1.2.3'`；用正则的话 `.` 会多命中一堆（第 3 节第 5 格）。
5. 命中行数 3、出现次数 5，怎么把两个数都拿到？—— `grep -c` 给行，`grep -o | wc -l` 给次数（第 5 节第 2、3 格）。
6. 「日志里有没有 ERROR」这句判断怎么写最省事？—— `if grep -q ERROR f`；别用 `-c`，那会把数字打进 stdout（第 7 节第 1 格）。
7. `grep` 退 1 是失败吗？—— 不是，1 是「确实没有」，是答案；**2 才是事故**，才需要去读报错原文（第 3 节第 6 格、第 7 节第 8 格）。
8. sed 一个字符都没改，退出码是多少？文件动了吗？—— 码 **0**；没命中时 `-i` 照样重写一遍但内容一字未动（第 9 节第 3 格、第 11 节第 5 格）。
9. `sed -i` 之后，文件还是原来那个文件吗？—— 不是。`-i` 新建再改名，**inode 变了**，改前改后 `ls -i` 两个号（第 11 节第 2 格）。
10. `sed 's/a/A/' f > f` 会发生什么？—— 文件被**清空**，退出码 0（第 11 节第 7 格）。
11. 一条管道的退出码是谁的？想看前面那一环怎么办？—— 默认**最后一个命令**的；要么 `set -o pipefail`，要么读 `PIPESTATUS`（第 13 节第 3 格、第 14 节）。
12. `awk 'NR==FNR{...; next}'` 凭什么认「第一个文件」？—— `NR` 是整个进程的总行号、`FNR` 是当前文件的行号，两个只在第一个文件里相等（第 16 节第 2 格）。
13. `a[101]` 和 `a["101"]` 是同一个键吗？`a["0101"]` 呢？—— 前两个**是**（第二次写把第一次盖掉，元素个数还是 1）；`"0101"` 是**另一个键**（个数变 2）（第 16 节第 5 格）。
14. 怎么判断数组里有没有键 k 而不改数组？—— `if (k in a)`；写成 `a[k]` 会**创建**它（第 16 节第 4 格）。
15. awk 里 `name["Ada",1]` 是真二维数组吗？—— 不是，键是 `"Ada" SUBSEP "1"` 拼出来的字符串，`SUBSEP` 长 **1** 字符（第 17 节）。
16. `-v OFS='|'` 之后 `print $0` 为什么没有竖线？—— OFS 只在两处生效：`print` 的逗号清单、字段被赋值后的 `$0` 重建；没动过字段的整行原样透传（第 18 节第 4 格）。
17. `'a:b:'` 用 `FS=:` 切出几个字段？—— **3 个**：`[a] [b] []`，末尾分隔符也多咬一个空字段（第 18 节第 5 格）。
18. 想用 `awk 'NF<3'` 挑坏行，怎么确认它不是哑的？—— 先喂一根**注定被挑中**的探针行，让它响一次（第 18 节第 6 格）。
19. 本机 `awk` 是 gawk 吗？`/\s/` 匹配什么？—— 屏幕上第 20 节第 1 格自证是 **mawk**；`/\s/` 匹配**字母 s**，正确写法是 `/[[:space:]]/`（第 20 节第 1、4 格）。
20. 订单号 18 位，在 awk 里怎么搬才不会变？—— 当**串**搬：不 `+0`、不做数值比较；`-v` 传参也救不了，入口那一刻就掉精度（第 21 节）。

## 本章没演 / 没验证（绝不编造，都在这）

第 25 节屏幕上那 2 行是本章自己承认的边界，这里把它摊开并补齐：

- **别的进程正打开着文件时 `sed -i` 的可见性**：第 11 节只证了 inode 变了，没演「读者会不会看到半个文件」。
- **属主不是自己的文件、只读位之外权限（ACL、immutable 位）**：第 11 节第 3 格只演了 chmod 沙箱内自建文件。
- **跨文件系统 `mv`、NFS 上的 `-i`**：本机没有可测的第二文件系统，所以「`-i` 靠 rename」这条只在同盘上演过。
- **耗时与内存**：本章所有样本都在几十行以内，任何「`grep -r` 快 / `awk` 省内存」之类的性能话一句都没写。
- **gawk 真装上以后 `FIELDWIDTHS` 的正解**：本机没装 gawk（第 20 节第 3 格那句「只标期待」就是这个意思），
  所以固定宽度切分只给了 mawk 的下场和 `substr` 替代，没给「gawk 上应该怎么写」的第二份证据。
- **`-P` 背后到底是 PCRE1 还是 PCRE2**、`-P` 与系统 libpcre 版本差异：第 3 节只证了「本机 `-P` 可用（rc≠2）」和几条实测行为。
- **二进制文件**：`grep -a`、`--binary-files=`、`sed`/`awk` 遇到 NUL 的行为，本章一律没演（第 18 节第 1 格的 `FS=''` 只演了逐字符切分）。
- **多字节文本的字节 vs 字符**：第 5 节第 7 格演了中文行里 `grep -o` 切出来是什么，
  但 sed 的 `s` 与 awk 的 `$n` 在多字节下的口径**没有**系统对过；第 1 节只钉住「本机 `wc -l` 数换行、`tr` 按字节切」这一条厂商差异。
- **`--group-separator`、`--label`、`-b`、`-h`、`--null-data`** 等长开关：只演了本章论题需要的 `-Z/-D/--include/--exclude`。
- **`getline` 的全部形态**：演了 `"cmd" | getline`（第 20 节第 5 格）和第 15 节里 awk 主动往下读那一格；
  `getline < file` 与管道 getline 的区别、`getline` 对 `NF` 的影响没有逐个验。
- **`CONVFMT`/`OFMT` 与科学计数法**：第 21 节只演了大整数走 double 的后果，没演格式化开关。
- **`awk` 里 `FS` 取多字符时按正则解释**：第 18 节第 1 格演了默认空白、逗号、空串三种，多字符 `FS` 没演。
- **符号链接上的 `-i`**：inode 那一格演的是普通文件。
- **shell 集成层面**（`set -e` 与管道、trap 与信号）：第 14 节只演到「同一根管道在四种环境下各退什么码」，
  完整的严格模式是**下一章**的题（见「本章之后」）。

## 怎么跑这一章

前置（本机实测，第 1 节屏幕上逐条钉过）：bash 5.3、GNU grep 3.12、GNU sed 4.9、
awk = **mawk 1.3.4**（没有 gawk）、`/bin/sh` 指向 dash、busybox 可用。

## 本章之后

**第 08 章《把脚本写结实》** 从本章停下的地方接：第 14 节只演到「同一根「前失败后成功」的管道，
四个环境四个码」，而 `set -e`、`set -u`、`set -o pipefail`、`IFS`、`trap ERR/EXIT` 的**组合行为**、
参数与文件名校验、`mktemp` 与竞态，是下一章六个取证脚本（`errescue`、`strictfour`、`trapsafe`、
`argscheck`、`filesafe`、`weirdnames`）的正题。本章教的「判据优先于印象、守卫必须先能响、
码只表工具自己有没有出事」，下一章会把它落成**脚本开头的几行开关**。

往回看，本章借了三章的债，也还了三章的债：

- **第 03 章《判断与退出码》**：三态（0/1/2）在那里是通用规则，在这里由 grep 具体兑现，
  而 sed/awk 是它的**反面教材**（第 23 节的表就是把这三章的账并排）。
- **第 04 章《管道与重定向》**：第 13 节的「最后一环洗掉前面」与第 11 节第 7 格的 `> f` 自毁，
  都是那章的 fd 与截断规则在三剑客身上的具体形状。
- **第 05 章《循环与控制》**：`while read` 逐行吃饭的写法，和这里 awk 的「按行」是同一件事的两种实现 ——
  管道里 read 的那个字节指针（第 13 节第 5 格）就是那章的作业控制留下的。
- **第 06 章《函数与返回》**：本章每个取证脚本里的 `cell()` / `show()` / `code()` 就是那章的函数，
  而那章最贵的「码与字节两条道」在这里变成了「`grep -c` 的数字是 stdout，不是码」（第 7 节第 1 格）。

再往后，第 09 章讲调试（`bash -x`、`set -n`、把这一段屏幕证据复现出来的最小办法），
第 10 章把本章的三连拼成真实作业（配置巡检、日志聚合、批量改名 + 回滚），
第 11 章是全手册的术语与码表合订。
