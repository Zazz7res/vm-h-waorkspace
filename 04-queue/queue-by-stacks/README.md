# 两个栈拼一个队列（用 in / out 两座小栈，外加一份均摊账本）

> 题目听起来像杂技：栈只能后进先出，队列要先进先出，方向正好相反，凭什么拼得出来？
> 拼法本身三十行就写完了，**这一节真正要教的是「均摊分析」**——为什么一个「最坏一次要搬 n 个」的
> 操作，摊到 n 次操作上还是 O(1)。本目录自包含：`istack.c` 就地写了一个极简 int 栈，没有 `malloc`，
> 也没有跨目录借代码。

---

## 一句话是什么

两个栈各管一头：**`in` 只管进队，`out` 只管出队**。想出队而 `out` 空了，就把 `in` 整栈**倒**进
`out`——倒一次就把「新到旧」翻成「旧到新」，于是 `out` 的栈顶正好是最早进队的那个。

```
   进队 ──push──▶ ┌─────┐            ┌─────┐ ──pop──▶ 出队
                  │ in  │  ── 一次「倒」──▶ │ out │
                  └─────┘            └─────┘
                 栈顶 = 最新         栈顶 = 最早
```

心脏就是这几句（`qsq.c` 的 `q_dequeue`，原文照抄）：

```c
if (istk_empty(&q->out)) {
    if (istk_empty(&q->in)) {
        q->dequeue_fail++;      /* 两个栈都空 = 队列真的空了 */
        return false;
    }
    note_pour(q, pour_stack(&q->in, &q->out, q));
}
bool ok = istk_pop(&q->out, out);
```

★ 结论**不是**「dequeue 是 O(1)」，而是：单次最坏 **O(n)**、均摊 **O(1)**；`q_enqueue` 才是每次 O(1)。

---

## 为什么需要它（不用它会怎样）

手上只有栈能用（LeetCode 232，或者某处只暴露了栈接口），却需要一个 FIFO：

| 做法 | 出队代价 | 结果对不对 |
|---|---|---|
| 每次出队把 `in` 倒进 `out`、取一个、再把剩下的**倒回 `in`** | 单次 **O(n)**，n 次 **O(n²)** | ✔ 完全正确 |
| 本节写法：`out` 空了才倒，倒完就从 `out` 连着取 | 单次最坏 O(n)，n 次 **O(n)**，均摊 O(1) | ✔ 完全正确 |
| 干脆别绕，直接写循环数组 / 链表队列 | 严格 O(1) | —— 那就没有这一节了 |

第一行不是稻草人，它就是 `qsq.c` 里的 `q_dequeue_naive()`，挂在 `--bug=naive` 后面真的在跑：
倒过去反转一次、倒回来再反转一次，两次反转互相抵消，元素在 `in` 里的相对顺序回到原样，所以输出
序列和正确版**逐位相同**，代价是每次出队搬 `2k-1` 个。这种 bug 单元测试永远查不出来，只有计数器
看得见——本目录因此内置一整套账本（`move_count` / `pour_ops` / `max_one_pour` / `max_one_deq`）。
★ 学习顺序：**先接受「单次确实可能 O(n)」，再证明「总账不超 O(n)」**。跳过第二步就写出第一行那种代码。

## 图解：一次「倒」为什么就把顺序翻回来了

栈只能从顶上拿，弹出顺序必然是**新 → 旧**；搬到对面去以后，新的先落底、旧的最后落，最老的那个
就停在了 `out` 的栈顶。这就是「倒一次 = 反一次序」的全部机理。

```
   进队 1、2、3 之后（全堆在 in 栈，栈顶在上）：      整栈倒过去之后（搬 3、搬 2、搬 1）：

        in(进队侧)     out(出队侧)                    in(进队侧)     out(出队侧)
        ┌──────┐       ┌──────┐                      ┌──────┐       ┌──────┐
        │     3│       │    --│ ← 栈顶               │     --│       │     1│ ← 栈顶：最早进队的
        ├──────┤       ├──────┤                      ├──────┤       ├──────┤   现在露头了
        │     2│       │      │                      │      │       │     2│
        ├──────┤       ├──────┤                      ├──────┤       ├──────┤
        │     1│       │      │ ← 栈底               │      │       │     3│ ← 栈底
        └──────┘       └──────┘                      └──────┘       └──────┘
        in 3 个，out 0 个                            in 0 个，out 3 个
        队头 1 卡在 in 的【栈底】，                    出队 1 → 2 → 3，FIFO 达成；
        栈动不了它 → 只能先把 3、2 搬走。              此后 out 里还剩 2、3，连着取一个都不搬。
```

**为什么 `out` 非空时绝不能倒**：`out` 里躺着的是「比 `in` 更早」的旧批次，序已经反好了。把新批次
倒进来就压到旧批次**上面**，晚来的反而先出队。`--bug=mix` 的真实输出：

```text
        in 有 2 个，out 有 2 个
        队列里（队头→队尾）：       2       3       4       5
  ★ 现在【故意违反纪律】：不看 out 空不空，把 in 整个倒进 out。
  接下来连着出队三次，看顺序：4 5 2  ← 规矩版这三步给的是 2 3 4
```

错得很安静：不崩、不报内存错误。第 7 幕的说法是『那句判空不是优化』，`--bug=mix` 的结尾写得更硬：
`→ 所以 q_dequeue 里那句 if (istk_empty(&q->out)) 是正确性要求，不是优化。`
顺带一个细节：这段反例是 `main.c` 里手写 `istk_pop`/`istk_push` 循环演的，所以它连账本都没涨
（`累计搬运 3 次` 一个数没变）；真的错误代码会走 `pour_stack`，搬运照记，只是顺序错。
还有一条判据别忘了：**队列为空 = 两个栈都空**（`istk_empty(&q->in) && istk_empty(&q->out)`）。

## 逐个操作拆解

### `istack.c`：先把原料立住

**1. `istk_init` / `istk_destroy`** —— `top = -1` 是**空栈的唯一判据**；destroy 把格子涂成 `-1`
当哨兵再复位。数组栈一个 `malloc` 都没有还写 destroy，是因为① 仓库规矩：有 init 就要有 destroy，
读的人不用先判断这个类型有没有堆内存；② 防止结构体复用时读到上次的残留。都 O(1)。

**2. `istk_push` / `istk_pop`** —— push：判满 → `s->top++` → `data[top] = v`；pop：判空 →
`*out = data[top]` → `top--`。★ `top` 指**栈顶元素自己**（第 2 幕实测：`连压 1、2、3：size = 3，top = 2`），
所以 push **绝不能先写再加**（`data[top]` 住的正是栈顶，先写就覆盖它），pop 反过来先读再退。判满写在
最前面守的是「失败时一个字节都不写」；空栈 pop 不动 `*out`，「忘判返回值」的 bug 至少不引入新垃圾。各 O(1)。

**3. `istk_top` / `istk_empty` / `istk_full` / `istk_at` / `istk_size`** —— 全 O(1)，`istk_size` 直接 `top + 1`
（`-1 → 0 个`，不用特判空栈）。`istk_at`（只读「从栈底数第 idx 格」）存在的唯一理由是 `q_dump` 要画整条栈，而
push/pop/top/empty 里没有任何一个能遍历；有了它，`qsq.c` 就不必知道 `data` 长什么样——**抽象边界保住了**。

### `qsq.c`：四个队列动作 + 那本账

**4. `q_enqueue(q, v)`** —— `enqueue_ops++`，然后**永远**只 `istk_push(&q->in, v)`。为什么不顺手压进
`out`：`out` 里是已经反好序的旧批次，新元素压到它们上面就会比它们先出队（和 mix 反例同一个病因）。
一次 push，最坏也是 O(1)——这里不是均摊，是每次。

**5. `q_dequeue(q, *out)` —— ★★ 本节心脏 ★★** —— 进函数先 `dequeue_ops++` 并记下
`before = move_count`（本次出队的代价从这一刻起算），然后就是开头那段代码：两栈都空 → `dequeue_fail++`
并返回 false；`out` 空但 `in` 有货 → `pour_stack` 整栈倒一次；最后 `istk_pop(&q->out, out)` 并用
`note_deq_cost(q, before)` 把「这一次到底搬了几个」记进账本。第 4 幕把这套账演透了：
`入队 5 次，出队 6 次（其中失败 1 次），倒栈 2 次，累计搬运 5 次`。

**6. `pour_stack(from, to, q)`（内部工具）** —— `while (!istk_empty(from))` 里一次 `pop` + 一次 `push`
算**一次搬运**，`q->move_count++`。中途 `to` 装满就停，但**不能直接 break**：元素已经从 `from` 弹出来了，
直接走就等于把它丢在两个栈之外，所以必须 `istk_push(from, v)` 原样塞回再走，让调用方从「返回值 <
原来的个数」看出没倒干净。这手「半途失败要还原」是**固定容量数组栈的税**（链表栈就没这个分支）。

**7. `note_pour` / `note_deq_cost`（两个不同的「最坏」，口径必须分清）** —— `max_one_pour` =
**一趟**倒栈搬了几个；`max_one_deq` = **一次出队**从头到尾搬了几个。反例版一次出队倒两趟（过去 k 个、
回来 k-1 个），真实代价 `2k-1`，只有后者记得到；用前者会报 64 而真实是 127（`main.c` 里专门有段注释
守这条），数字错了整段论证就废了。

**8. `q_peek(q, *out)`** —— 队头可能在 `in` 栈的**栈底**，栈只能看栈顶，唯一的正规解法就是**真的倒
一次**，所以它是本节唯一「看着只读、其实会动手」的函数，签名里**没有 `const`**。第 5 幕实测：
`q_peek() → true，队头 = 10，本次搬运 3 次`，再 peek 一次 `本次搬运 0 次`。代价和 dequeue 同一笔账，
但它**不改变队列内容**（只是没弹出那个元素）。

**9. `q_empty` / `q_size`** —— 两个栈都要看，第 5 幕原文：`现在 in = 0 个、out = 2 个 → q_size = 2，q_empty = false`。
只判 `in` 会漏掉「已经倒过去但还没出队」的那批，第 5 幕叫它「本节第一大笔误」。O(1)。

**10. `q_dequeue_naive`（反面教材）/ `q_reset_counters` / `q_dump`** —— naive 版无条件 `pour(in→out)`
→ `pop(out)` → `pour(out→in)`，两趟记进**同一次出队**的账。`q_reset_counters` **只清队列这一层的七个计数器**，
两个栈自己的 `n_push/n_pop` 保留（那才是这个栈真正被用过的历史，对比实验里不能伪造），要连数据一起清就
`q_destroy + q_init`。`q_dump` 把两个栈并排**竖着**画，格子里只放 ASCII（数字或 `--`）、中文留行尾，否则汉字两列宽会把框挤歪。

## 复杂度一览

`n` = 队列里的元素个数；「均摊」指**同一个元素一辈子只付一次钱**推出来的账，不是概率平均。

| 操作 | 均摊 | 最坏单次 | 说明 |
|---|---|---|---|
| `q_enqueue` | O(1) | **O(1)** | 只 push `in`，没有第二条路；`in` 满则拒收 |
| `q_dequeue` | **O(1)** | **O(n)** | `out` 非空时搬 0 个；实测 64 次出队里 63 次搬 0 |
| `q_peek` | **O(1)** | **O(n)** | 和 dequeue 同一笔账，只是不弹出 |
| `q_empty` / `q_size` / `q_dump` | O(1) / O(1) / O(n) | 同左 | 前两个各看一眼，画图靠 `istk_at` 遍历 |
| `q_dequeue_naive`（反例） | **O(n)** | O(n) | 单次 `2k-1`；n 次总账 O(n²)，实测 9 次出队搬 **67** 个 vs 正确版 **9** 个 |
| 空间 | O(C) | —— | 两个定长数组栈，`ISTK_CAP = 64`，全程零 `malloc` |

## 运行结果

复现（项目根目录）：

```bash
make one DIR=04-queue/queue-by-stacks
./build/04-queue/queue-by-stacks/main --bug=naive   # 反面教材一：结果对、代价 O(n)/次
./build/04-queue/queue-by-stacks/main --bug=mix     # 反面教材二：顺序错乱
```

默认跑 10 幕、319 行输出。第 6 幕「均摊」是全节主菜，`/tmp/qsq.txt` 第 235–248 行原文
（开头先把用词钉死：`元素进 in 栈 1 次 → 被倒进 out 栈最多 1 次 → 从 out 弹出 1 次`）：

```text
  ① 常规混合：6 步一循环（enq enq enq deq deq deq），跑 100 轮 = 600 次操作
     入队 300 次，出队 300 次，倒栈 100 次，总搬运 300 次，单次出队最大搬运 3 个
     每次出队搬了几个（分布）：搬 0 个 → 200 次   搬 3 个 → 100 次
     平均 1.00 个/次 → 均摊 O(1) 的实测含义就是这个数【不随规模增长】
     ★ 大部分出队搬 0 个（直接弹 out），少数出队一口气搬一坨 —— 这就是均摊的样子。

  ② 最坏形状：狂灌 64 个（in 栈装满），再一次性出队 64 个
     灌进去 64 个（in 栈 size = 64，out 栈 size = 0）
     第一次出队搬 64 个（全队一起搬家）→ 这一次真的是 O(n)
     其余 63 次出队全部搬 0 个（out 里已经排好队了）
     总搬运 64 次 / 出队 64 次 = 平均 1.00
     ★ 等式成立：搬运次数 64 == 成功出队次数 64 == 元素个数 64
       更一般的形式是：搬运次数 = 成功出队次数 + out 栈里还剩下的个数
       （此刻还剩 0 个，成功出队 64 次 → 64 + 0 = 64，和账本 64 对得上）
```

逐段解释：

1. **这里没有随机数，讲的不是平均复杂度，而是对抗式的上界**：对手再怎么构造序列，总搬运也超不过元素个数。
   凭据是「一个元素进 `in` 一次、被倒一次、被弹一次」——它一旦进了 `out` 就必须先出队才能回 `in`，而 `out`
   非空时禁止倒栈，所以不会有第二次搬运。
2. **① 是日常混合序列**：300 次出队、总搬运 300，分布却是「200 次搬 0 个 + 100 次搬 3 个」。均摊 O(1) 指的是
   这个平均数**不随规模增长**，不是「每次都很便宜」。注意分母：按出队算 1.00，按全部 600 次操作算 0.50。
3. **② 是故意造出来的最坏形状**：第一次出队真搬了 64 个（这一次就是 O(n)，别骗自己），其余 63 次一个都不搬，
   总账 64 = 元素个数。那句 `搬运次数 = 成功出队次数 + out 栈里还剩下的个数` 是全节最值钱的一行：它对
   **任意中途时刻**都成立，可以直接当断言写进测试，比「均摊 O(1)」这句口号强。

反面教材一的实测（`--bug=naive`，`/tmp/qsq_naive.txt` 第 9–20 行）：

```text
  ① 两边的【出队序列】一致吗？ 完全一致 ← 这就是它难发现的原因
     正确版：1 2 3 4 5 6 7 8 9
     反例版：1 2 3 4 5 6 7 8 9
     两边各成功出队 9 / 9 次，失败 0 / 0 次（失败的就是空队列那几次），
     顺序完全一样 → 这种性能 bug 单元测试永远查不出来。

  ② 但【搬运次数】是两回事：
     实现   出队次数   搬运次数  单次最大搬运     均摊(搬运/出队)
     正确版 9          9          6            1.00
     反例版 9          67         11           7.44
     对照：一趟倒栈的峰值 max_one_pour = 正确版 6 / 反例版 6（反例版一次出队要倒两趟）
     搬运次数之比 = 7.4 倍（同一串操作、同一个结果）
```

同一串操作、同一个结果，搬运 **9** 对 **67**（7.4 倍）；反例版 `max_one_deq = 11` 正是 `2×6-1`（当时队列里有
6 个元素），而两边 `max_one_pour` 都是 6 —— 拆解第 7 条那个口径差别就在这些列上，拿错列会把反例版代价低估近一半。

其余各幕一句话带过：第 1、2 幕立住 LIFO 规矩和自带数组栈（`top` 流派、`硬压 74 次 → 成功 64 次` 的撞墙演示）；第 3 幕单独演「倒」；
第 4 幕每步画两个栈并附账本；第 5 幕讲 `peek` 的副作用与 `empty`/`size` 的双栈判据；第 7 幕预告两段反例；第 8 幕演空队列不污染 `*out`、
`in` 满时拒收新元素但旧元素照出、destroy 后再用安全失败、`INT_MAX` 与重复值都能进；第 9 幕反推「两个队列拼栈」为什么**救不回**均摊；第 10 幕查账。

把规模推到装满再放干（`--bug=naive` 第 ③ 段，同一份输出文件里的后面几行）：

```text
  ③ 规模上去再看：狂灌 64 个，再一次性出队 64 个
     正确版 总搬运   64 次｜第一次出队搬  64 个｜搬 0 个的出队 63 次｜单次最大  64 个
     反例版 总搬运 4096 次｜第一次出队搬 127 个｜搬 0 个的出队  0 次｜单次最大 127 个
     同样是 64 次出队：正确版搬 64 次（= 出队次数 → 均摊 O(1)）；
                    反例版搬 4096 次 = 64^2 → 单次 O(n)，n 次就是 O(n^2)
     → 结论：两栈队列的全部价值就在那句『out 空了才倒』上。
```

这五行是本节最干净的对照：**同样 64 次出队，一个搬 64 次，一个搬 4096 次**。
`127 = 2×64-1` 是反例版第一次出队的代价（倒过去 64 + 倒回来 63），`4096 = 64²` 是
`Σ(2k-1)`（k 从 64 到 1）的结果 —— 旁白里那句 `= 64^2` 不是修辞，是可以手算对上的。
正确版那一行「搬 0 个的出队 63 次」也别放过：64 次出队里 63 次白拿，这正是均摊的来源。

> 另有一条口径要记住：第 2 幕「最多只能放 64 个元素」严格讲是「**连续入队** 64 个」——
> 倒过一次之后 `out` 里留着旧批次、`in` 是空的，还能再收 64 个。

## 常见的坑

1. **`out` 没空就把 `in` 倒进来。**
   错法：`pour_stack(&q->in, &q->out, q);` 前面不判空，理由是「让 out 随时是满的性能更好」。
   对法：`if (istk_empty(&q->out))`。后果见 `--bug=mix`：出队得到 `4 5 2` 而不是 `2 3 4`，不崩
   不报错，而且**只在特定交错下出错**——只要每次 `out` 都被取空了才入队，这行代码永远不出事。

2. **判空只看 `in` / 进队顺手压进 `out`。**
   错法：`return istk_empty(&q->in);` —— 已经倒进 `out`、还没出队的那批被当成不存在，明明有元素却说空，上层
   `while (!q_empty())` 提前退出、数据凭空少一截；或者「`out` 空就压 `out`，省一次倒栈」，新元素压到旧批次上面，
   序当场乱，症状和第 1 条一模一样。对法：`in`、`out` 一起判、`q_size` 取两者之和；**分工写死**——进队永远 `in`，出队永远 `out`。

3. **把「均摊 O(1)」当成「每次 O(1)」。**
   错法：拿它做实时/硬延迟预算——第 6 幕 ② 实测第一次出队搬了 **64** 个，那一次就是 O(n)。
   对法：记住两句话「n 次操作总账 O(n)」和「单次可能 O(n)」；真在乎最坏单次延迟就去用循环数组
   队列或链表队列。反方向也用错：把它说成「平均复杂度」，听着像依赖数据分布，这里其实不靠概率。

4. **给 `q_peek` 加 `const`。**
   错法：`bool q_peek(const TwoStackQueue *q, int *out)` —— 要么偷偷 cast 掉 const 改结构（撒谎），
   要么绕过栈的抽象直接读 `in` 栈的栈底（省掉搬运，但「队列只靠栈的四个动作拼出来」当场作废，
   均摊论证里的「搬」也就数不着了）。对法：本节的老实做法——签名不带 `const`，注释写明白
   「peek 有副作用，但只搬不改内容」。

5. **`pour_stack` 里目标栈满了直接 `break` / 搞混 reset 与 destroy。**
   错法：`if (!istk_push(to, v)) break;` —— 元素已从 `from` 弹出，两处都不在，**静默丢数据**（`ISTK_CAP = 64`
   是真会撞墙的，硬压 74 次只收 64 次）。对法：先 `istk_push(from, v)` 原样塞回再 break，调用方从「返回值 < 原来的
   个数」看出没倒干净。同理别指望 `q_reset_counters` 清数据（它只清七个计数器），也别 `#include "../array-stack/..."`。

## 自检问题

1. 一个元素从进队到出队总共被搬几次？`q_dequeue` 的最坏单次和均摊分别是多少，矛盾吗？
   答：最多搬 **1 次**——搬只发生在 `in → out`，进了 `out` 就得先出队才能回 `in`。所以最坏单次 O(n)
   （`out` 空、`in` 里有 n 个）、均摊 O(1)，不矛盾：均摊说的是 n 次操作的**总账**，实测见第 6 幕 ②。

2. 反例版一次出队搬多少？为什么是 `2k-1` 而不是 `k`？该看哪个计数器？
   答：`k` 个倒过去 + 取 1 个 + 剩下 `k-1` 个倒回来 = `2k-1`。所以要用 `max_one_deq`（一次出队的
   总搬运），不能用 `max_one_pour`（一趟的峰值）：实测 11 对 6。

3. `搬运次数`、`成功出队次数`、`out 栈里还剩下的个数` 三者的恒等式是什么？
   答：`搬运次数 = 成功出队次数 + out 栈里还剩下的个数`，任意中途时刻都成立，可以直接当断言。

4. `q_peek` 会改变队列内容吗？为什么签名没有 `const`？
   答：不改内容，但会改**内部布局**（`in` 整栈进 `out`）并产生搬运（实测第一次搬 3 个、第二次搬 0 个），所以不带
   `const`；硬加 `const` 只能二选一：偷偷 cast 掉（撒谎），或绕过栈抽象直接读 `in` 的栈底（拼法当场作废）。

5. 「两个队列拼栈」为什么拿不到均摊 O(1)？
   答：那里元素被搬是因为**别人比它新**，每来一个新人都要让一次路，每次 pop 搬 n-1 个；本节元素被搬是因为**它该
   出队了**，一辈子只有一次。第 9 幕原话：均摊分析的全部功夫，就在于数清楚「同一个元素付了几次钱」。
