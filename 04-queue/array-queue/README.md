# 朴素数组队列 array-queue

> 上一节 `03-stack/` 里栈只能一头进一头出。这一节要的是「先来的人先被服务」，于是必须把**入口和出口开在两端**。
> ⚠ 本节是**故意写成有毛病的**，毛病叫「假满」。看懂它，下一节的「取模」才有意义；看不懂它，循环队列就只是背一行公式。
> 证据：结构体里那个 `broken_by_design` 永远是 `true`。

## 一句话是什么

队列（queue）就是排队：队尾只能进人，队头只能出人，先进先出（FIFO）。数组队列把队伍摊在一排连续格子里，全部家当三样：

```
data[]   那一排格子（一整块连续内存，在堆上）
front    队头那个人在第几格 —— 出队从这里走
rear     下一个新人该站第几格 —— 入队写这里
```

本节的版本只记这两个下标，**出队只 `front++`，绝不搬数据、绝不绕回**。于是 `front` 和 `rear` 只会一路向右爬，
很快出现「右边没格子了，左边明明空着一堆格子」，程序却报「满了」—— 这就是假满。
文件分工：`aqueue.h` 是「菜单」（只有声明，注释写明本节的下标流派），`aqueue.c` 是实现（教学核心全在 `dequeue` 的第 ③ 步），`main.c` 是四幕演示。

## 为什么需要它（不用它会怎样）

**为什么需要队列。** 栈只会「最近那件事先办」，但大量任务是**按到达顺序**处理的：打印队列、消息队列、线程池派活、
BFS 逐层扩展、抢票排队。这些场景用栈就全乱套 —— 后进来的插队，先来的一直饿着。

**用裸数组当队列，你必须做一个选择。** 出队 10 之后 `[10,20,30]` 变成 `[·,20,30]`：

```
选择 A：把 20、30 整体往前搬一格   → 出队 O(n)
选择 B：不搬，只记「队头在第 1 格」 → 出队 O(1)
```

选择 B 才是队列该有的写法，而**本节就是选择 B 的极端形态**：只记 `front`，一挪不回头。代价（假满）就是本节要演示的东西 ——
它不是意外 bug，是选择 B 必然欠下的债。**为什么先写一个有毛病的版本**：假满只看定义会背，看一眼现场才算懂。
亲手看到这个队列只装了 1 个人却拒绝入队，下一节 `rear = (rear + 1) % capacity` 你才会觉得「对，就该这么救」；
反过来先学循环队列，那行取模就是凭空冒出来的口诀。

**数组版 vs 链表版**（`linked-queue`）：数组要预估容量、会有「满」这件事（本节还会假满），但一整块连续内存 cache 友好；
链表不要容量、永不满，代价是每个元素多背一个指针加一次 malloc/free。数组版唯一要解决的难题就是「格子用完了怎么办」——
本节答错了（报假满），下一节答对了（绕圈）。

## 图解：一整排格子 + 两个只会往右爬的下标

`capacity = 6`，依次入队 10、20、30，再出队两次之后（结构体 `q` 在 `main` 的栈上，`data` 指向堆上那一整块）：

```
  下标      0       1       2       3       4       5
        ┌───────┬───────┬───────┬───────┬───────┬───────┐
 q →    │  10   │  20   │  30   │   ·   │   ·   │   ·   │  ← data，一整块连续内存（堆上）
 data → └───────┴───────┴───────┴───────┴───────┴───────┘
   字段    作废    作废     ▲                       ▲
   front=2  ← 从这里开始算数                  rear=3 ← 下一个新人站这里
   size = rear - front = 1        capacity = 6
```

三句话读这张图：① **10、20 的数值还原封不动躺在内存里**，只是被 `front` 划到区间外面 —— 「作废」是逻辑上的，不是被清零；
② 活着的人住在**左闭右开区间** `[front, rear)`，所以人数 = `rear - front`，判空 = `front == rear`；
③ `front` 指在真实元素上、`rear` 指在空位上，两个下标「流派」不同，是刻意选的。

**为什么 `rear` 要指「队尾后面的空位」？** 如果 `rear` 也像栈的 `top` 那样指在真实元素上，空队列怎么表示？
`front = 0`、`rear = 0` 会同时意味着「头尾都是 0 号元素」—— 「只有一个元素」和「空队列」撞在同一个状态，两个下标分不开。
让 `rear` 当半开区间的右端，空队列自然就是 `front == rear`（区间长度 0）。本仓库后面几节（循环队列、双端队列）沿用同一套约定，方便对照。

**假满是怎么长出来的。** 继续往右推：入队 100、101、102，`rear` 走到 6；再放走 100、101，`front` 爬到 5：

```
  下标    0      1      2      3      4      5        （第 6 格不存在）
       ┌──────┬──────┬──────┬──────┬──────┬──────┐  ┆
       │  x   │  x   │  x   │  x   │  x   │ 102  │  ┆ ← rear=6 已站在墙外
       └──────┴──────┴──────┴──────┴──────┴──────┘  ┆
         ↑── 5 个格子空着，谁也占不到 ──↑       ↑ 无处可放
         队列里只有 1 个人（102），capacity = 6
```

此时 `enqueue(103)` 要写的格子是 `data[6]` —— 越界，必须拒绝。一笔账看懂浪费有多大：

```
size + 作废格子 + 右边可用 = capacity        1 + 5 + 0 = 6   ← 6 个格子里只有 1 个真正在用
```

**为什么栈没这个病**：栈的 `top` 前进和后退走同一条路，两端同向，弹栈就往回退；队列把入口和出口开在两端，
出口那头一路往前推，推过的格子就成了回不去的沉没成本。`aqueue_print` 用四个记号把这一切摊开：

```
 [ 0:  x] [ 1:  x] [ 2:  x] [ 3:  ·] [ 4:  ·] [ 5:  ·]   ← 左=老，右=新
 [      ] [      ] [  F   ] [  R   ] [      ] [      ]   ← F=front(队头元素) R=rear(下一个入队位)
   x=被 front 走过（作废但值还在） ·=空位 F=队头元素本人 R=新人要站的坑 FR=两指针重合=空队列
```

`rear == capacity` 时 R 站在墙外、那一格画不出来，代码会用文字补一句「rear 已经在最后一格的右边 = 指向墙外，
所以这一行画不出 R —— 正是「无处可放」的画面」。

## 逐个操作拆解

### `aqueue_init(AQueue *q, int capacity)` —— 建队，O(capacity)

`malloc` 出 `capacity` 个 int，`front = rear = 0`，四个统计字段归零。为什么传指针**就地初始化**而不返回 `AQueue`？
结构体里有指针字段，返回一份拷贝容易让人误以为是两块独立内存（和数组栈同一个理由）。一进门先复位全部字段，
再判 `capacity <= 0` 和 `malloc` 失败 —— 这样任何提前 `return` 的路径留下的都是**干净空壳**（`data=NULL`、`capacity=0`），
后续所有操作都走「没有内存」分支安全失败，绝不解引用空指针。`malloc` 的单位是字节所以写 `capacity * sizeof(int)`；
新格子里是残留垃圾值，但代码从不读 —— 规矩是「只有 `[front, rear)` 里的格子才算元素」。

### `aqueue_destroy(AQueue *q)` —— 销毁，O(1)

`free(q->data)`，然后 `data` 置 `NULL`、`capacity`/`front`/`rear` 归零。谁 `malloc` 谁 `free`，否则 ASan 报泄漏。
free 之后指针变量还在、指向的内存已不属于你 —— 这叫悬空指针。置 `NULL` 有两个好处：误用会**当场崩**
（比悄悄读垃圾好一万倍）；手滑再 `destroy` 一次时 `free(NULL)` 是合法空操作，不会 double free。

### `aqueue_enqueue(AQueue *q, int value)` —— 入队，O(1)

```c
if (q->rear >= q->capacity) { /* 拒绝；若 front > 0 顺手告诉你这是假满并计数 */ return false; }
q->data[q->rear] = value;   /* 先放进 rear 指的这一格 */
q->rear         += 1;       /* 再把「下一个空位」往右挪一格 */
```

**判满必须写在之前，顺序不能反**：先写再判，那次越界写已经把内存踩坏，状态永久损坏。拒绝时分两种话说清：
`front > 0` 就打印「这就是假满」并 `reject_by_fake++`；`front == 0` 才说「真满了（size==capacity，一个格子都没浪费）」。
空队列时 `front == rear`，入队正好写在那个重合点上、两者一起往右 —— 不用特判，这是半开区间送的红利。
⚠ 认清楚性质：假满**不是崩溃、不是越界**，程序老老实实拒绝了这次写入，内存是安全的；它是「明明能装却说不行」的
**逻辑缺陷**，ASan 抓不到，只能靠人脑想通。

### `aqueue_dequeue(AQueue *q, int *out_value)` —— 出队，O(1)（本节主角）

```c
if (q->front == q->rear) { /* 空队列：返回 false 且【不写】out_value */ return false; }
int v = q->data[q->front];   /* ② 先取值 */
q->front += 1;               /* ③ ★ 只挪指针：不抹值，绝不把后面的元素往前搬 ★ */
if (out_value != NULL) { *out_value = v; }
```

`out_value` 是**输出参数**：C 只有一个 `return` 口子，主结果（成功与否）走返回值，次要结果（谁走了）写进调用者给的地址；
传 `NULL` 表示「我只想让他走，不关心他是几」，所以才要判空再写。先取进局部变量 `v` 再挪指针，是为了顺手计数，也给「失败不写脏」留退路。
第 ③ 行是整节核心：**正因为不搬数据，`front` 才会一路向右把左边的格子作废**，攒够次数就撞上 `enqueue` 的 `rear >= capacity`。
改成 `for` 循环把元素往前挪就不会假满，但每次出队变成 `O(size)` —— 队列「两头都 O(1)」的灵魂就没了。
也就是说本节是**故意**用假满换来 O(1) 出队的。

### `aqueue_peek_front` / `aqueue_peek_rear` —— O(1)

一个读 `data[front]`，一个读 `data[rear - 1]`，队空返回 `false`。为什么要 peek：很多场景只想知道「现在该服务谁」
但还不能把他弹出（BFS 判重、调度器预览）。那个 `-1` 是新手最容易踩的点：`rear` 指的是坑不是人，写 `data[rear]`
读到的是垃圾值或作废格子；负数越界不用担心，因为判空之后 `rear > front >= 0`，所以 `rear - 1 >= 0`。
签名里的 `const` 是承诺「我只读不改」，误写编译器立刻报错。

### 查询组：`is_empty` / `is_full` / `is_fake_full` / `size` / `capacity` / `wasted_cells` —— 全 O(1)

```c
is_empty     → front == rear                    /* 半开区间长度为 0 */
is_full      → rear >= capacity                 /* 只看右墙到没到 —— 分不清真假满 */
is_fake_full → rear >= capacity && front > 0    /* 顶到墙【而且】前面还有空位 */
size → rear - front（空队列正好 0，不会出负数）   wasted → front（走过就废弃的前缀格子数）
```

`is_fake_full` 这一行就是本节所有故事的起因：**人数根本没到 `capacity`，却已经无法入队**。故意保留「分不清」的 `is_full`，
是为了让 demo 并排打印两者，把「容器真的没空间」和「下标到墙了」这两件常被混谈的事拆开。`q == NULL` 时
`is_empty`/`is_full` 返回 `true`（没内存 = 没内容 = 也没法写），`is_fake_full` 返回 `false`（连格子都没有，谈不上浪费）。
`wasted_cells` 是特意加的「废变量」，有了它 `size + wasted + (capacity - rear) = capacity` 一眼可见浪费多少。
注意 `size` **不占字段**、用两个下标现算 —— 少一个字段就少一处「忘了同步」的可能；下一节的循环队列没这个福分，
绕圈后 `rear - front` 可能为负，必须存 `size`。

### `aqueue_print` / `aqueue_stats` —— 教学辅助，不是队列操作

真正的队列**不提供**整排摊开（抽象上只准碰两头），打印只为让 FIFO 和假满看得见。一个排版细节值得学：
标 F/R 的第二行用的是**和第一行完全相同的循环、相同的格子宽度**（` [%2d:%3s]`，每格固定 9 列），
而不是「先打一串空格再把标记顶到第 i 格下面」—— 因为中文在终端里占 2 列，前缀一有中文，按列算位置就会把标记顶歪到隔壁格子。
用同一循环打同一格宽，宽度天然对齐、不用算列，这是最稳的办法。`aqueue_stats` 只把「入队 N 次、出队 M 次、size、被假满拒 K 次」复述一遍。

### `aqueue_compact(AQueue *q)` —— 治假满的笨办法，O(size)

把 `[front, rear)` 逐个搬回 `data[0]`，然后 `front = 0`、`rear = size`。为什么从前往后搬是安全的：源区间和目的区间会重叠，
但**目的地永远在源头左边**（`i <= front + i`），逐个「先读 `data[front+i]` 再写 `data[i]`」，读的时候那一格还没被覆盖；
反过来（目的地在右边）才需要从后往前搬。代价：一次搬 `size` 个元素。如果你每次出队都顺手 compact 一次，
出队就从 `O(1)` 退化成 `O(n)` —— 等于把假满欠的债换一种方式（时间）付回去。工程上不这么干。
这个函数存在的意义就是**反衬取模有多优雅**。

## 复杂度一览

| 操作 | 时间 | 空间 | 备注 |
|---|---|---|---|
| `init` | O(capacity) | O(capacity) | malloc 一整块；失败建空壳 |
| `enqueue` | **O(1)** | — | 会因 `rear` 顶墙被拒（可能是假满） |
| `dequeue` | **O(1)** | — | 只 `front++`，绝不搬数据 |
| `peek_front` / `peek_rear` | O(1) | — | 后者读 `rear - 1` |
| `is_*` / `size` / `wasted_cells` | O(1) | — | 三个判据各不相同 |
| `destroy` | O(1) | — | free + 置 NULL |
| `compact` | **O(n)** | O(1) | 救急可行，日常不可用 |
| `print` | O(capacity) | — | 教学用，非队列操作 |
| 稳态占用 | — | O(capacity) | 队里 1 个人也占着 6 个格子 |

一句话总结：**两头都 O(1) 这个目标守住了，代价是空间回收不彻底。** 队列的「先进先出」之所以值钱，
靠的就是入队 O(1) 与出队 O(1) **同时**成立；只要有一头退化（搬数据 → O(n)），排队这件事就不如直接排序后扫一遍了。

```text
  调用 aqueue_compact()：
      🔧 compact：把 1 个元素整体左搬 5 格，front 5 → 0，rear 6 → 1，右边腾出 5 个空格（注意：这次搬了 1 个元素 = O(n)，不是 O(1)）
  搬完之后：  size=1, front=0, rear=1, capacity=6, 浪费格子=0
```
```text
  enqueue(1)
      [失败] enqueue(1)：rear=6 已经顶到墙（capacity=6），但 data[0..5] 共 6 个格子其实是空的 → ⚠ 这就是【假满】！队列里只有 0 个元素，远没满
    → 这次 enqueue 没成功，上面的 [失败] 就是原因
    front=6、rear=6 一起躺在 capacity=6 上，两个指针都「退休」了：
```

逐段解释：
- **①** `size=0` 了，但 `front`/`rear` 停在 **3** 而不是回到 0；第二行 `FR` 重合在第 3 格说明「空」这个状态成立，第 0/1/2 格打上 `x` = 作废但值还在。浪费已经发生，只是还没撞墙，暂时看不出来。
- **②** 全节最关键一屏：队里只有 1 个人、容量 6、`front=5`，那笔账 `1 + 5 + 0 = 6` 说明 6 个格子只有 1 个在用。`is_full=true` 与 `is_fake_full=true` **同时**成立，正好把「下标到墙了」和「容器真的没空间」的差别摆在你面前。
- **③ 前** `compact` 确实把病治好了：`front 5 → 0`、`rear 6 → 1`，浪费归零，马上又能塞人。但它自己喊了「这次搬了 1 个元素 = O(n)」—— 这里只搬 1 个是因为队里恰好只有 1 个人，满队时它要搬 6 个。
- **③ 后** 是假满最离谱的形态：`front=rear=6`，队列**一个人也没有**却依然塞不进东西 —— 不是容量不够，是下标不会绕回来。

剩下共 229 行输出，一句话带过：第 1 幕三次入队（`rear` 一路 0→1→2→3）；第 4 幕的**真满**
（`[失败] enqueue(108)：真满了（size=6 == capacity=6，front=0，一个格子都没浪费）`，此时 `is_fake_full=false`）；
空队列上 `dequeue`/`peek` 都安全返回 `false` 且不写脏 `dummy`；非法 `capacity=0` 建空壳后所有操作安全失败；
最后两个队列都 `destroy` 并打印 `data=(nil)`。

## 常见的坑

**坑 1：把「`rear` 顶到墙」当成「满了」。** 错法：`if (rear == capacity) return false;` 写完就以为万事大吉 —— 队里只有
1 个人时它也报满，调用方收到 `false` 以为「装不下了」，于是丢任务 / 阻塞 / 扩内存，全是冤枉钱。
对法：判满要问**人数**不要问**下标**；真正的解法在下一节，`size == capacity` 才是满。

**坑 2：`peek_rear` 读 `data[rear]`。** 错法：`*out = q->data[q->rear];` —— `rear` 是「下一个入队位置」，此刻是**空的**，
读到垃圾值（`rear == capacity` 时直接越界）。对法：`*out = q->data[q->rear - 1];` 并且先判空再读。口诀：`front` 指人，`rear` 指坑。

**坑 3：为了不浪费格子而在出队时搬数据。** 错法：`dequeue` 里写 `for (int i = front; i < rear; i++) data[i-1] = data[i];`，
看着干净不浪费，但每次出队 `O(n)` —— 这已经不是队列，是「每次出队都重排一遍的数组」。
对法：出队只 `front++`；省时间必然欠空间，这笔债用**取模绕圈**还（下一节），而不是搬数据。

**坑 4：判空写成 `rear == 0`。** 错法：`if (q->rear == 0)` —— 入队过之后 `rear` 就不再是 0，空队列时它等于 `front`；
这个条件只在刚初始化那一刻成立。对法：空 = `front == rear`，人数 = `rear - front`，两者都来自半开区间 `[front, rear)`。

**坑 5：`dequeue` 不判空就读。** 错法：直接 `int v = q->data[q->front]; q->front++;` —— 指针退休在
`front == rear == capacity` 时读的是 `data[capacity]`，**数组越界**，还是那种「这次没崩、下次才崩」的越界。
对法：先 `if (front == rear) return false;`，且失败时**不写** `out_value`，让调用方拿原值当证据（demo 里 `dummy` 保持 0 就是这条的验收）。

**坑 6：`malloc` 后不判空，或 `free` 后不留 `NULL`。** 错法：`q->data = malloc(...);` 之后直接写 `data[0]`；
或者 `free(q->data);` 就完事。前者内存不够时解引用空指针，后者留下悬空指针、再 `destroy` 一次就是 double free。
对法：`init` 失败就把 `capacity` 留 0、`data` 留 `NULL`，让所有操作走安全分支；`destroy` 里 free 完立刻置 `NULL`。

**坑 7：想在结构体外面「复活」这个退休的队列。** 错法：看到 `front=rear=6` 后外面偷偷写 `q.front = q.rear = 0;` ——
手改确实能复活，但这是在**破坏不变量**，某处一旦以为 `size = rear - front` 还算得对，就出现
「明明有 3 个人、size 突然变 0」这类鬼 bug。对法：用旧了就 `destroy` 再 `init`，或者换下一节的循环队列 ——
它的下标本来就允许一直转，不需要「归零」这个动作。

## 自检问题

1. 出队后 `data[0]` 里的 10 还在内存里吗？还算队列元素吗？—— 数值还在（代码没抹它），但不算元素，只有 `[front, rear)` 里的格子才算；「作废」是逻辑概念，不是内存清零。
2. 为什么 `rear` 不指真实元素？—— 为了空队列能表示。两个下标都指真实元素时，「只有一个元素」和「空」撞在同一状态；`rear` 当半开区间右端，空就是 `front == rear`。
3. `is_full` 和 `is_fake_full` 何时同时为真、何时只有前者为真？—— `rear >= capacity && front > 0` 时同时为真；`front == 0 && rear == capacity` 时只有 `is_full` 为真，那才是真满（第 4 幕的 `enqueue(108)`）。
4. 等式 `size + wasted_cells + (capacity - rear) == capacity` 为什么能说明问题？—— 它把格子分成三堆：在用的、被 `front` 作废的、右边没用过的。假满时第二堆很大而第三堆是 0，于是「有空间」和「塞不进」同时成立。
5. 为什么栈没有这个问题？—— 栈 `top` 的前进与后退是同一条路来回走，两端同向，没有「回不去的前缀」；队列两端分开，出口那端推过去就留下沉没格子。
6. 每次出队都 `compact` 一次会怎样？—— 不假满了，但出队变 `O(size)`，队列退化成「每次出队都整体搬一遍的数组」。两头都 O(1) 是队列的全部价值，一头塌了就全塌。
7. `aqueue_peek_rear(q, NULL)` 会怎样，为什么允许？—— 什么都不写，只用返回值告诉调用者队列空不空。这是 C 里「一个函数带回两个值」的标准套路（见 `00-c-foundation/pointer-basics`）。
8. 本节哪个字段证明「毛病是故意的」？—— `broken_by_design`，初始化就置 `true` 且永远是 `true`；再加 `reject_by_fake` 专门数被假满拒了几次，好让 demo 把账算给你看。
