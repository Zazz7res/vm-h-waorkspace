# 双端队列 deque（double-ended queue，读作「deck」）

> 栈只开一个口，队列开两个口但每个口只干一件事，双端队列把两个口都放开：
> **头也能进、头也能出、尾也能进、尾也能出**。本节用**循环数组**实现，
> 所以它同时是 `04-queue/circular-queue` 那套取模技巧的加强版。

---

## 一句话是什么

一整块连续内存被当成**首尾相接的圈**来用，圈上只记两个下标，外加一个计数：
`front` = 队头元素**自己**住在哪一格；`rear` = 下一次从尾部塞东西时**要写**的那一格
（即「半开区间 `[front, rear)` 的右端」）；`size` = 当前有几个元素。
四个端操作各自只改一个下标 + 读写一格，所以全是严格的 O(1)。

最值钱的一句话：**栈和队列都是它「只开一个口」的特例。**

```
只用 push_back + pop_back   → 栈（后进先出）
只用 push_back + pop_front  → 队列（先进先出）
两头混着用                  → 单调队列 / 滑动窗口 / 撤销+重做 / 任务窃取
```

第 3 幕就是这么演的：同样塞进 1、2、3，换一头取就分别得到 `3 2 1`（栈）和 `1 2 3`（队列）。

---

## 为什么需要它（不用它会怎样）

手上只有栈和队列、不许写新结构时：

| 想干的事 | 只用栈 | 只用队列 | 双端队列 |
|---|---|---|---|
| 撤销历史（只看最近一步） | ✔ | ✘ 每次都要倒腾 | ✔ `pop_back` |
| 打印任务排队（先来先服务） | ✘ 顺序反了 | ✔ | ✔ `push_back`+`pop_front` |
| 滑动窗口最大值 | ✘ 只有栈顶一个口，过期的旧头弹不掉 | ✘ 只能弹最旧的，比新来者矮的弹不掉 | ✔ 头端踢过期、尾端踢必输 |
| 用普通数组存，还想两头都能进出 | 头部插入 = 整体后移 O(n) | 同左 | ✔ front 只退一格，O(1) |

最后一行是本节存在的核心理由。用**普通数组**做 `push_front`，得把后面所有元素整体搬一格：

```
普通数组 push_front(10)：            循环数组 push_front(10)：
[20][30][40][ ][ ]                    [20][30][40][ ][ ][ ]
   ↓ 全部后移（O(n)）                      ↓ front 退一格（O(1)）
[10][20][30][40][ ]                     往 5 号格写 10，front=5（数据一个都没动）
```

n 次操作下来普通数组是 O(n²)，循环数组还是 O(n) ——「不动数据、只动下标」是所有环形/链式结构的共同套路。
顺带回答「为什么非得是循环」：两头都能加人，下标同时朝两个方向跑，线性数组一会儿就两头顶到墙，弯成圈才绕得回来。

## 图解：环上的下标怎么推进

拿第 1 幕的真实过程（`capacity = 6`，依次 `push_back(20)`、`push_back(30)`、`push_front(10)`、`push_back(40)`）：

```
   下标:    0      1      2      3      4      5
           ┌──────┬──────┬──────┬──────┬──────┬──────┐
   data →  │  20  │  30  │  40  │  ·   │  ·   │  10  │
           └──────┴──────┴──────┴──────┴──────┴──────┘
                                        ▲             ▲
                                       rear          front
                                    (下一格写)   (10 是从头插进来的：
                                                   front 从 0 倒退到 5)

   逻辑顺序（头→尾）= 沿环从 front 走 size 步：
        data[5]=10 → data[0]=20 → data[1]=30 → data[2]=40
```

三个必须刻进脑子的认知：**① 元素能断成两段** —— `data[5]` 一段、`data[0..2]` 另一段，谁排第一跟下标大小
**毫无关系**，只跟「从 front 出发走 k 步」有关；**② `rear` 指的是空位**（下一个 `push_back` 的写入格），
队尾永远在 `rear` 的前一格；**③ 空和满都可能 `front == rear`**，所以只能靠 `size` 区分。

四个操作就是「两个指针各自正反挪一格」，合起来是**一套统一的下标推进规则**：

```
   push_front ：front 逆时针退 1 → (front - 1 + capacity) % capacity   ← 本节最难的一行
   pop_front  ：front 顺时针进 1 → (front + 1) % capacity
   push_back  ：rear  顺时针进 1 → (rear  + 1) % capacity
   pop_back   ：rear  逆时针退 1 → (rear  - 1 + capacity) % capacity
```

★ 为什么**倒退**必须 `+ capacity`？因为 C 的 `%` 是**向零截断**，不是数学同余：

```
   front = 0, capacity = 6
   ( 0 - 1 ) % 6      = -1   ← 负数！下一行 data[-1] = v 就是往数组左边越界写
   ( 0 - 1 + 6 ) % 6  =  5   ← 正确：环上的最后一格
```

一次 `+ capacity` 就够：`x ∈ [0, capacity-1]` ⇒ `x-1+capacity ∈ [capacity-1, 2capacity-2]`，必然非负且
小于 `2capacity`，取模一次就落回 `0..capacity-1`。加法不用抬正：`(5+1)%6 = 0`。
于是「先读还是先挪」只剩一句口诀：`pop_front` 先读 `data[front]` 再进一格（front 站在真实元素上）；
`pop_back` 先把 rear 退一格再读（rear 站在空位上）。

## 逐个操作拆解

对应 `deque.c` 每个函数。所有函数第一件事都是 `d == NULL || d->data == NULL`，于是哪怕 `malloc` 失败建成了
空壳，后续调用也只是返回 false，**绝不解引用空指针**。

**1. `deque_init(d, capacity)`** —— `malloc` capacity 个 int，`front = rear = size = 0`，四个计数器清零。
两指针重合并都指「下一个要写的位置」，是环上最自然的起点；`size` 单独存着，是为了让「空」有一个不会和「满」
混淆的判据。`malloc` 的单位是字节，所以写 `(size_t)capacity * sizeof(int)`。容量非法（`<= 0`）时打印警告并
**建成空壳**，让后面每次操作明确失败而不是带病运行。

**2. `deque_destroy(d)`** —— `free(d->data)` → 指针置 `NULL` → `capacity/size` 复位。整块内存只有一份，只 free
一次；置 NULL 是仓库铁律，误用**当场段错误**比读到残留垃圾好查，顺带解决 double free（`free(NULL)` 是空操作）。

**3. `deque_push_back(d, v)`** —— 判满 → `data[rear] = v` → `rear = (rear + 1) % capacity` → `size++`。
`rear` 本来就指空位，所以**先写后挪**；这一步和循环队列的 enqueue 一模一样，没有新东西。判满用
`size == capacity`，**跟 rear 有没有顶到墙完全无关**。O(1)；满了返回 false 且一个字节都不写。

**4. `deque_push_front(d, v)` —— ★★ 本节主角 ★★** —— 判满 → `front = (front - 1 + capacity) % capacity`
→ `data[front] = v` → `size++`。为什么**先退再写**：`front` 指的是当前队头元素自己，新元素要站在它前面，那个
空位是 front 的上一格。顺序颠倒（先写后挪）会把老队头覆盖掉，队列凭空少一个人、`size` 还照常 +1 —— 静默丢数据。O(1)。

**5. `deque_pop_front(d, out)`** —— 判空 → `v = data[front]` → `front = (front + 1) % capacity` → `size--`。
队头是真实元素所以**先读后挪**；加法不会出负数，直接取模就安全。`out` 是输出参数：结果走指针带出来，返回值
只表示成败（全仓库统一流派），传 `NULL` 表示「只要删、不要值」。O(1)。

**6. `deque_pop_back(d, out)`** —— 判空 → `rear = (rear - 1 + capacity) % capacity` → `v = data[rear]` → `size--`。
顺序和 pop_front **正好相反**：`rear` 是开区间右端、脚下是空位，队尾元素住在它的前一格，必须先退再读；
直接 `data[rear]` 读到的是一个不属于队列的格子。这里又出现一次 `+ capacity`。O(1)。

**7. `deque_peek_front` / `deque_peek_back` / 四个查询** —— peek 用各自 pop 完全相同的位置计算，只是**不挪指针、
不改 size**，所以能反复调；`peek_back` 要算「rear 的前一格」，于是再抄一遍 `(rear - 1 + capacity) % capacity`。
参数写 `const Deque *d`：承诺只读，误写编译器立刻报错；空队返回 false 且 `*out` 一个字都不改。`is_empty` =
`size == 0`、`is_full` = `size == capacity`，全 O(1)、一个都不遍历。⚠ `is_empty` 绝不能写 `front == rear`：
装满时它俩也重合（第 2 幕输出的 `FR` 那行就是现场证据）。

**8. `deque_print` / `deque_usage_hint`（教学辅助）** —— `deque_print` 把环摊平印三行：① 每格「下标:值」，
不在队里的印 `·`；② 同宽度只在 front/rear 写 `F`/`R`（重合写 `FR`）；③ 沿环走出来的**逻辑顺序** —— 第三行
最重要，它把「从头到尾到底是哪几格」直接念出来。格宽统一 `[%2d:%3s]` 纯 ASCII、中文留到行尾，否则框会被汉字
宽度顶歪。「这格在不在队里」的判据是 `(i - front + capacity) % capacity < size`（从 front 沿环数，i 的序号
小于 size 就还活着），**不能**写 `front <= i < rear`。`deque_usage_hint` 只印一句话，不动数据。

**9. 第 5 幕的单调队列 —— 本节唯一的应用演示，也是它最值钱的出口。** 滑动窗口最大值
（`heights = {9,5,3,7,2,8,1}`，`k = 3`）：暴力做每个窗口扫一遍是 O(n·k)；双端队列的写法是**队里存下标**，
并守住一条不变式 —— 从队头到队尾对应的高度**递减**。

```
① 尾端淘汰：新来的比队尾高 ⇒ 队尾那些「又矮又新」的当不了最大值 → pop_back
② 头端过期：队头下标掉出窗口 [i-k+1, i]                        → pop_front
③ 新下标 push_back 进队
④ peek_front 拿到的下标就是当前窗口的最大值
```

① 用的是**栈口**，② 用的是**队列口**。这正是单调栈做不到的地方 —— `03-stack/monotonic-stack` 只能从栈顶弹，
没法顺手踢掉过期的队头，所以解决不了带时间窗的问题。O(n) 的论证和单调栈同源：**每个下标最多进队一次、出队一次**，
所以那个 `while` 的总执行次数 ≤ n，不是「一次都不算」。这套「同一个元素一辈子只付一次钱」的算法，下一节
`queue-by-stacks` 会以**均摊分析**的名字再出现一次。

## 复杂度一览

`capacity` = 环上格子数，`size` = 当前元素个数。

| 操作 | 本实现 | 普通数组两头插删 | 说明 |
|---|---|---|---|
| `push_back` / `pop_back` | **O(1)** | O(1) | 写/读一格 + rear 挪一格 |
| `push_front` | **O(1)** | O(n)（整体后移） | front 退一格 + 写一格 |
| `pop_front` | **O(1)** | O(n)（整体前移） | 读一格 + front 进一格 |
| `peek_front` / `peek_back` / `is_empty` / `is_full` | **O(1)** | O(1) | 只读字段或算一格下标，不挪指针 |
| 遍历 / 取第 k 个逻辑元素 | O(size) / O(1)：`data[(front+k)%capacity]` | O(n) / O(1) | 不能直接 `data[k]`，也不能比下标 |
| 滑动窗口最大值（n 个元素） | **O(n)** | O(n·k) | 每个下标进出队各一次 |
| 空间 | O(capacity)，一次 malloc | O(n) | **定容量，不扩容**，满了就返回 false |

这几行到底在演什么：

1. **那行 `↺ 倒退绕圈`** 把正反两个结果都印出来了：正确的是 3（环上最后一格），错误写法得到 `-1`，也就是

2. **`rear` 全程是 0**：只从头端插、尾部一口没用，`R` 一直停在 `[0]` 而元素住在 `[3]`——正好印证「rear 指空位」。
3. **`front` 的轨迹 3 → 2 → 1 → 0**（节选跳过了 2 那一步）：四次倒退只有第一次触发绕圈，其余是普通减法。这说明
   `(x-1+cap)%cap` 在**不退圈时也完全无害**（`(3-1+4)%4 = 2`，多写的 `+4` 被取模吃掉了），不需要分支判断
   「这次要不要绕」，一律同一套推进规则 —— 这就是「统一」二字的含义。
4. **逻辑顺序那几行**一直是下标倒着、逻辑头尾却完全正确：判断先后只能沿环走，不能比下标。
5. **`[ 0: FR]` 那行的 ⚠** 就是坑 3 的现场反例；**`push_front(500)` 被拒**说明 4 格全满、一格没浪费 ——
   老式「牺牲一格换判满」的写法在这只能装 3 个。

其余几幕一句话带过：第 1 幕演四端各进各出（`data[5]=10` 那种断成两段的画面）；第 3 幕同一份 1、2、3 换一头取出
`3 2 1` 和 `1 2 3`；第 4 幕演 `pop_back` 先退再读、rear 绕回 0 时「队尾在 data[3] 而 rear 站在 0」；第 5 幕跑完
整个滑动窗口；第 6 幕是空队四端取、真满两端塞、`capacity=0` 非法 init —— 全部只打印失败并返回 false，一个都不崩。

> 负数区间；队列为空时也会印「① 尾端不用淘汰（新元素比队尾还矮，留着它有用）」。这是 demo 旁白偷懒，不是数据错。

## 常见的坑

1. **倒退写成 `(front - 1) % capacity`。**
   错法：`d->front = (d->front - 1) % d->capacity;` —— `front == 0` 时得到 `-1`，下一行 `data[-1] = v` 越界写，
   而且**往往当场不崩**、隔几步才在别处炸。对法：`(front - 1 + capacity) % capacity`，口诀：**减法先抬正再取模。**

2. **`pop_back` 写成「先读后挪」。**
   错法：`v = data[rear]; rear = (rear - 1 + cap) % cap;` —— rear 站的是空位，读到残留垃圾，症状是「弹出的值
   总比预期慢一个」或「最后一个元素永远弹不出来」。对法：先退再读（见 `deque_pop_back` 的 ②③）。
   同理 `push_front` 不能先写后挪，那会把老队头覆盖掉。

3. **判空写成 `front == rear`。**
   错法：`return d->front == d->rear;` —— 全满时它也成立，于是「满」被当成「空」，`while (!is_empty())` 一上来
   就退出。对法：`return d->size == 0;`。判满同理写 `size == capacity`，别写 `(rear + 1) % cap == front`
   （那要牺牲一格，容量白白少一个）。

4. **用下标大小判断先后。**
   错法：`for (int i = 0; i < size; i++) printf("%d", data[i]);` —— 绕圈后 `data[0]` 可能是队尾。
   对法：`int idx = (front + k) % capacity;`（`deque_print` 第三行、第 5 幕打印队里内容用的都是这个）。
   判某格活着也不能写 `front <= i < rear`，要写 `(i - front + capacity) % capacity < size`。

5. **`malloc` 后不判空 / 忘了 `deque_destroy` / 以为它会扩容。**
   错法：`d->data = malloc(...);` 直接用 —— 内存不够时它是 NULL，第一次读写就是空指针解引用；或者建了不拆，
   泄漏被 `make asan` 当场点名；或者以为满了会自动搬走 —— 本节是**定容量**循环数组，`size == capacity` 就返回
   false，绝不 `realloc`。对法：判空、失败建空壳；谁 malloc 谁 free，demo 结尾每个队列都 destroy；
   init 前先估上限（第 5 幕队里最多 n 个下标，就 `deque_init(&w, n)` 一次给够）。

## 自检问题

1. `capacity = 6`、`front = 0`，执行一次 `push_front` 后 `front` 是几？为什么不是 `-1`？
   答：**5**。`(0-1+6)%6 = 5`。不先 `+capacity` 的话 C 里 `(0-1)%6` 是 `-1`（向零截断），当下标就是越界写。

2. 为什么 `pop_front` 先读后挪，`pop_back` 先挪后读？
   答：两个指针**约定不同** —— `front` 指队头元素自己（先读），`rear` 指「下一次 push_back 的写入位置」
   （空位，先退一格才落到队尾上）。

3. `front == rear` 能说明队列为空吗？栈、队列、双端队列的关系怎么说才准确？
   答：不能，全满时它也成立；判空只能 `size == 0`、判满只能 `size == capacity` —— 这就是愿意多存一个 `size`
   的原因。关系上，双端队列是两者的**推广**：`push_back + pop_back` 就是栈，`push_back + pop_front` 就是队列。

4. 滑动窗口最大值为什么非得用双端队列，单调栈不行？
   答：这里有两个正交的淘汰动作 —— 尾端踢「又矮又新、当不了最大值」的（`pop_back`），头端踢「滑出窗口、已过期」
   的（`pop_front`）。栈只有一个口，做不了头端淘汰。

5. `capacity` 个格子最多同时装几个元素？想取「逻辑上第 k 个」怎么写？
   答：正好 `capacity` 个（判满是 `size == capacity`，没留路标格；第 2 幕四格全满、`push_front(500)` 被拒就是实测）。
   取第 k 个写 `data[(front + k) % capacity]`，`k ∈ [0, size)`，绝不能写 `data[k]`。

6. 双端队列能不能用双向链表实现？代价是什么？
   答：能，两头插删同样 O(1) 且没有容量上限。代价是每个节点多 16 字节（两根指针）、散落堆上 cache 不友好。
