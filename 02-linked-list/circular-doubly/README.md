# 循环双向链表 circular doubly linked list（哨兵节点版）

> 前两节各补了一块拼图：`02-linked-list/circular-singly` 把尾巴接回头上，
> `02-linked-list/doubly` 给每个节点加了 `prev`。
> 本节把两块**同时装上**，再外加一件很多人以为是"锦上添花"、其实才是主角的东西：
> 入口用一个不存数据的**哨兵节点**。
> 三件事叠起来的效果是：全节**一支"是不是第一个 / 是不是最后一个"的特判都不用写**，
> 而且上一章自检第 7 题留下的那个短板 —— "手里只有节点地址，删它却要 O(n)" —— 在这里变成 **O(1)，0 步遍历**。
> 这个数字不是嘴上说的，代码里带了一个计步器，实测打印在第 4 幕。

---

## 一句话是什么

一个 `int` + **两张纸条**（`prev` 写"上一个是谁"，`next` 写"下一个是谁"），
首尾相接成环，而环的入口是一个**永远在场、永远不存数据**的哨兵节点：

```c
typedef struct Node {
    int val;
    struct Node *prev;   /* 第一个元素的前驱是【哨兵】，不是 NULL */
    struct Node *next;   /* 最后一个元素的后继是【哨兵】，不是 NULL */
} Node;

typedef struct {
    Node *head;   /* ★ 它不是"第一个节点"，它是"第 0 个节点"（哨兵） */
    int   size;   /* 元素个数，不含哨兵 */
} CDList;
```

于是本节有两条要刻在脑子里的规矩（第一条是上一章带来的，第二条是本节新立的）：

> **环里没有终点站**：想停下来只能认出"我撞回哨兵了"，`p != NULL` 在这里永远为真。
> **空表不是 `head == NULL`**：空表是 `head->next == head && head->prev == head` —— 哨兵自己牵自己。

---

## 为什么需要它

先把三节摆在一起对齐，别把"循环"和"双向"和"哨兵"各自买到什么搞混：

| | 普通双向 `doubly` | 循环**单**链表 `circular-singly` | 循环双向 + 哨兵（本节） |
|---|---|---|---|
| 节点字段 | `val/prev/next` | `val/next` | `val/prev/next` |
| 每个节点占内存 | 24 字节 | 16 字节 | 24 字节 |
| 环里有没有 NULL | 两头各一个 NULL | **一个都没有** | **一个都没有**（被哨兵占了） |
| 空表标志 | `head == NULL` | `tail == NULL` | `head->next == head`（哨兵永远在） |
| 遍历终止条件 | `p != NULL` | `p != head` | `p != head`（撞回哨兵） |
| 反向遍历 | ✅ | ❌ 走不了回头路 | ✅ |
| 头插 | O(1)，但要**改 head 变量**（得传 `Node **`） | O(1)，只改一根线 | O(1)，`insert_after(head, v)`，**把手一个字都不改** |
| 尾插 | O(n)（除非自己额外存 `tail`） | O(1)（只存 tail） | **O(1)**，`head->prev` 就是尾巴，**连 tail 字段都不用存** |
| 弹尾 `pop_back` | O(1)，但要特判"弹完剩 0 个 → head 置 NULL" | ❌ O(n)（得绕一圈找尾巴的前驱） | **O(1) 且零特判** |
| **删"手里只有这个节点地址"的节点** | O(1)（有 `prev`） | ❌ **O(n)**（要绕圈找前驱） | **O(1)，实测 0 步遍历** |
| 头/尾/唯一/空 特判支数 | 4 支 | 2~3 支 | **0 支** |
| 死循环风险 | 无 | 有 | 有（同上一章那条税，一分不少） |

⚠ **诚实版归因**（很容易在这里把三件事说混）：

- "**删已知节点是 O(1)**" 是 **`prev` 这根线**买到的，跟"循环"无关 ——
  普通双向链表也做得到。所以本节的对照组不是隔壁那一节，而是"装作没有 `prev`"的
  `cdlist_erase_singly_style()`（见"逐操作拆解 5"），量出来的才是 `prev` 这一根线本身的价钱。
- "**零特判**" 才是 **循环 + 哨兵**买到的：第一个元素的前驱是哨兵、最后一个元素的后继是哨兵，
  于是"头"和"尾"从两种特殊位置退化成了两个普通字段（`head->next` / `head->prev`）。
- "**绕圈看全部数据**" 是**循环**买到的，普通双向链表走到 NULL 就断了。

真实需求场景：

| 场景 | 为什么非得是这套结构 |
|---|---|
| **LRU 缓存**（`09-others/lru-cache/`） | 哈希表里存的就是**节点地址**；命中后要把这个节点从队列中间**摘出来**挪到队头。`哈希表给地址 + prev 给前驱 = 整个操作 O(1)`。用单链表这里就退化成 O(n)，缓存越快、表越长、亏越大 |
| 浏览器前进/后退历史 | 后退=走 `prev`，前进=走 `next`，"到底了"=撞哨兵；新访问要**截断**游标之后的全部历史（本节第 7 幕） |
| 音乐播放列表"上一首/下一首/单曲循环" | 两头都能挪，而且没有"尽头"这个概念 |
| 双端队列（两头进出） | `head->next`/`head->prev` 各一步，四头操作全 O(1)，且**不需要预留容量** |
| 编辑器 undo 链表、多任务就绪队列、内存分配器的空闲块链 | 全是"任意位置摘除一个已知块 + 双向扫描"的组合 |
| 从**任意一个**节点出发要看完整个环 | 一旦成环，任何节点都是合法入口 |

反过来，**别用**它的场合：只需要单向遍历（那就单链表，省 8 字节和一次改线）、
按下标随机读为主（那是数组）、元素很小但数量巨大且要求 cache 友好
（每节点 24 字节 + 一次独立 `malloc`，节点头税很重，见"复杂度"末尾）。

### 图 2：空表长什么样 —— 哨兵自己牵自己（本节最重要的一格）

```
   cdlist_init 之后，一个元素都没有：

        head
          │
          ▼
      ┌────────┐
      │  哨兵  │◄──┐
      │ next ──┼───┘   head->next == head   ← 成立
      │ prev ──┼───┐   head->prev == head   ← 成立
      └────────┘   │
          ▲────────┘
        自己指自己，一个两根线的孤环

   空表判据： head->next == head        （❌ 不是 head == NULL）
   size    ： 0                          （哨兵不是元素，不计数）

   ★ 为什么这张图值整节的价钱：
     "空"在这一节里【不再是一种特殊情况】，它只是"环上只有哨兵一个人"。
     所以 is_empty / print / pop_front / push_back 在为空时都不用另开一支代码 ——
     它们跑的就是那条通用代码，撞到的正好是哨兵。
```

### 图 3：`insert_after(pos, v)` —— 全节唯一真正在改线的地方（4 根线，顺序有讲究）

```
   之前：  ... ⇄ [pos] ⇄ [X] ⇄ ...        （X = pos->next，此刻还在 pos 手里）

     ① n->prev         = pos;       新节点认前驱
     ② n->next         = pos->next; ★ 先把老后继抄到自己身上
     ③ pos->next->prev = n;         老后继回头认新节点当前驱
     ④ pos->next       = n;         ★ 最后一步才把 pos 的后继换掉

   之后：  ... ⇄ [pos] ⇄ [n] ⇄ [X] ⇄ ...

   ★★ ④ 为什么必须放最后：④ 一改，"老后继 X"这个地址就从 pos->next 里消失了。
      ② 和 ③ 都要读 X，所以必须先读后改 —— `00-c-foundation/pointer-basics`
      那条"覆盖之前先抄旧值"的铁律，在双向链表里要守**两次**。
      写反的症状：③ 变成 `pos->next->prev = n` 里的 pos->next 已经是 n 自己，
      于是 n->prev 被自己覆盖，X 及其后面整串失联 → 不崩，但 ASan 报 indirect leak。

   ★★ 这一支代码为什么【一支特判都没有】（= 哨兵存在的全部意义）：
      pos 是哨兵     → 插在哨兵后面 = 头插。改的是哨兵的 next，
                       哨兵不是"头元素"，没有任何把手要跟着挪
      pos 是尾元素   → pos->next 就是哨兵，②③ 天然把 n 接到末尾并让哨兵认它 = 尾插
      表是空的       → pos 只能是哨兵，它自己指自己，四步走完变成 哨兵 ⇄ n ⇄ 哨兵
      ⇒ "头 / 尾 / 空" 三种特例被合并成一种通例。少写代码就是少写 bug。
```

### 图 4：`erase(node)` —— 本节最大卖点，2 句赋值、0 步遍历

```
   传进来的只有这一个地址，别的什么都不知道：

                node
                  │
                  ▼
     ... ⇄ [A] ⇄ [X] ⇄ [B] ⇄ ...

     ① X->prev->next = X->next;     即 A->next = B    （前驱 A 就在 X 身上，零步拿到）
     ② X->next->prev = X->prev;     即 B->prev = A
     ③ free(X); size--;

     ... ⇄ [A] ⇄ [B] ⇄ ...          两根线各接一次，X 出局

   ★ 三种"可怕局面"在这里全是同一句话（这正是哨兵的红利）：
     X 是第一个元素 → X->prev 是【哨兵】→ ① 改的是哨兵的 next，不需要"更新 head"
     X 是最后一个   → X->next 是【哨兵】→ ② 改的是哨兵的 prev，不需要"更新 tail"
     X 是唯一元素   → X->prev == X->next == 哨兵 → 两句都落在哨兵身上 → 自动退回图 2 的自环
     普通双向链表在这三种局面要写 4 支 if；这里 0 支。

   ⚠ 唯一要挡的一支：node == head（想拆地基）。它不是"特判麻烦"，是语义边界：
     哨兵永远不属于数据，删了它整条表就散了。所以 erase 开头 `node == l->head` 直接 return 0。
```

### 图 5：`prev` 到底值多少钱 —— 计步器实测的口径

```
   同一件事（把 val=100 这个节点摘掉），两条算法：

   A) cdlist_erase_singly_style：装作没有 prev（= 上一章循环单链表的算法）
      从哨兵出发，一路往后问"谁的 next 是它？"
      head → 1 → 2 → 3 → ... → 99 ★ 找到"99 的 next 是 100"，前驱到手
      计步器：每挪一次 prev = prev->next 记 1 步  → 第 k 个节点要 k-1 步

   B) cdlist_erase：认 prev
      100 身上就写着 prev = 99 → 一步路都没走 → 0 步
      计步器：循环体一次都没进 → 0 步

   实测数字（main.c 第 4 幕，两边同一把尺子）：
   ┌──────────────┬────────────────────┬──────────────────┐
   │ 删的是谁     │ A 沿 next 走了几步 │ B 走了几步       │
   ├──────────────┼────────────────────┼──────────────────┤
   │ n=6   第 1 个│ 0（哨兵就是前驱）  │ 0                │
   │ n=6   第 4 个│ 3                  │ 0                │
   │ n=6   第 6 个│ 5                  │ 0                │
   │ n=200 第 100 │ 99                 │ 0                │
   │ n=200 第 200 │ 199                │ 0                │
   └──────────────┴────────────────────┴──────────────────┘
   ⇒ A = "前面有几个节点"，B = 恒定 0。表越长、删得越靠后，差价越大。

   ⚠ 计数口径（不写清楚就是耍赖）：只统计【循环体里挪 next/prev 的次数】，
     也就是真正决定 O(n) 的那个动作。读一下 node->prev 这种固定一步不算数；
     纯打印不计步（否则测出来的全是 printf 的开销）。

   ⚠ 别把结论吹过头：只有【值】没有【地址】时，还是得先 find（O(n)）。
     "O(1) 删"的完整说法是：**给定节点地址时，摘除动作本身 O(1)**。
     地址从哪来？push 时函数就把地址返回给你了（见 cdlist.h 里那行注释）。
```

### 图 7：浏览器历史 —— 游标在环上左右移动，新访问把后面截掉

```
   访问过 1 → 2 → 3，游标停在 3：

   [哨兵] ⇄ [1]◄cur ⇄ [2] ⇄ [3] ⇄ [哨兵]      按钮"后退"到这里就置灰

   前进一步（走 next）：
   [哨兵] ⇄ [1] ⇄ [2]◄cur ⇄ [3] ⇄ [哨兵]

   ★ 关键一幕：在 2 上访问一个全新页面 9 —— "前进"分支（页面 3）必须被扔掉：
       while (cur->next != head) erase(cur->next);     ← 终止条件又是"撞回哨兵"
   [哨兵] ⇄ [1] ⇄ [2] ⇄ [9]◄cur ⇄ [哨兵]              3 已被 free

   哨兵在这里兼任第二个角色：**历史范围的左右边界**。
   "前面还有历史吗" 和 "后面还有历史吗" 变成同一句 `== head`，
   不用再存 first/last 两个指针，也不用数下标。
```

## 逐操作拆解

### 0. 三条贯穿全节的心法

1. **传参铁律不变**（`00-c-foundation/pointer-basics`）：要改调用者手里的东西就传它的地址。
   本节把 `head`/`size` 打包进 `CDList`，参数一律 `CDList *l`；只读的用 `const CDList *l`。
2. **环上遍历的终止条件**：`p != l->head`（撞回哨兵），写成 `p != NULL` 就是死循环 —— 上一章那条税一分不少地照交。
3. **本节新增**：**先抄后改、改完再 free**。双向的改线动作是"两句赋值"，
   但只要顺序错一步，或者在 `free(node)` 之后还去读 `node->prev`，就是从已释放内存里读地址。

### 1. `cdlist_init`：造一个"自己和自己成环"的哨兵（图 2）

- 哨兵是一个**货真价实的节点**：要 `malloc(sizeof(Node))`，只是它不存数据、永不参与删除。
- 建好之后 `s->prev = s; s->next = s;`，`l->head = s; l->size = 0;`。
- `head->val` 全节永远不读，这里写 0 只是让它别留垃圾值（ASan 不管未初始化读，valgrind 管；填 0 是免费的保险）。
- `malloc` 失败时把 `l->head` 置 `NULL`：**后面每个函数开头都判一次 `l->head == NULL`**，
  宁可整条操作失败也不崩。这是"失败要有个统一的形状"的写法。

### 2. `cdlist_insert_after`：唯一真正在改线的地方（图 3）

- 4 根线，顺序 ①②③④ 不能换（④ 必须最后，见图中反例）。
- 返回**新节点的地址**。这不是顺手加的糖：拿着这个地址，日后才能"不给 key、不查表、不遍历"地删它 ——
  本节卖点的入场券就是这一句 `return n;`。
- `pos == NULL` 或表没建成 → 返回 `NULL`，链表原样不动（不能"改一半再失败"）。

### 3. `cdlist_insert_before` / `push_front` / `push_back`：全是一行皮

```c
insert_before(l, pos, v) → insert_after(l, pos->prev, v)
push_front(l, v)         → insert_after(l, l->head, v)        /* 在哨兵后面插 */
push_back(l, v)          → insert_after(l, l->head->prev, v)  /* 在最后一个后面插 */
```

- `insert_before` 没有第二套改线代码：`pos->prev` 白捡一步到位 —— 这就是双向链表的"对称性"。
- 头插和尾插的区别**只剩一个参数**（`head` 还是 `head->prev`）。
- 空表时 `head->prev == head`，所以"尾插"和"头插"在这一刻字面上是同一件事 —— 第 2 幕第一行输出就是这个。
- ⚠ 一个本节代码里真踩到过的小坑，值得单独记一条：
  `push_back` 传给 `insert_after` 的位置是 `l->head->prev`，而这句**在"取参数"时就已经解引用了** ——
  表没建成（`init` 里 `malloc` 失败）时它当场段错误，`insert_after` 开头那道 `l->head == NULL` 闸门**救不到它**。
  `push_front` 传的是 `l->head` 本身（不解引用），确实能被下游挡住，但"靠被调函数替我判空"这件事本身就很脆。
  所以两个 `push_*` 开头各自补了一句判空。结论：
  **判空必须判在解引用之前，而不是判在被调函数里。**

### 4. `cdlist_erase`：本节最大卖点（图 4）

- 2 句赋值 + 1 个 `free` + `size--`，**没有循环**。
- 挡三种非法输入：表没建成、`node == NULL`、`node == l->head`（想拆地基）。
- `X` 是唯一元素时，两句赋值都落在哨兵身上，环自动退回图 2 的自环 —— 不需要收尾特判。

### 5. `cdlist_erase_singly_style`：自己造的对照组

- 功能与 `cdlist_erase` 完全等价，唯一区别是**怎么找前驱**：沿 `next` 绕圈问，走 k 步。
- 为什么它收尾还要维护 `prev` 那根线？因为这条链**物理上就是双边的**，
  只改 `next` 会在 `prev` 链上留下一根指向已释放节点的脏线，反向遍历立刻变 use-after-free。
  所以两边唯一的公平差异就是**步数** —— 那正是我们要量的东西（图 5）。
- `while (prev->next != victim)` 里塞了一句 `if (prev == l->head) return 0;`：
  victim 不在这条表上时，绕满一圈就收工，绝不乱改线。**环上写循环，永远先想好"绕满一圈了没有"**。

### 6. `cdlist_pop_front` / `cdlist_pop_back`

- 都是"取 `head->next` / `head->prev` → 读值 → `erase`"三步。
- 空表判据写在开头（`head->next == head`），返回 0 且**一个字节都不往 `val_out` 里写**。
- `val_out` 允许传 `NULL`（"我只想弹掉，不关心值"）—— `pointer-basics` 里输出参数的老约定。
- ★ `*val_out = first->val;` 必须在 `cdlist_erase(l, first)` **之前**：`erase` 里就 `free` 了，之后读 `first->val` 是悬空读。
- `pop_back` 在循环**单**链表里做不到 O(1)（要绕一圈找尾巴的前驱），这里一步到位 —— 哨兵送的第二个好处。

### 7. `cdlist_find` / `cdlist_find_from_back` / `cdlist_remove_val`

- `find`：从 `head->next` 出发沿 `next` 走，撞回哨兵就说明全看过了 → `NULL`。
- `find_from_back`：从 `head->prev` 出发沿 `prev` 走。目标在后半段时更省（最少 `min(i, n-i)` 步）。
  **只有双向链表才有这条线** —— 单向那节想反向找只能从头再走一趟。
- `remove_val` = 找（O(n)）+ 摘（O(1)）。总账还是 O(n)，但"摘"这一半从此不再是负担。
- 这两个 find 都**计步**，第 3 幕会打印"从头往后走了 3 步才拿到地址"，
  和第 4 幕"摘除 0 步"并排看，才知道省的是哪一半。

### 8. `cdlist_size` / `cdlist_is_empty`

- `is_empty` 判 `head->next == head`，**不判 `size == 0`** —— 上一章的教训原样适用：
  拿账本判断事实，账一旦记错就全线崩盘。
- `size` 不含哨兵。这是最容易和 `push_back` 返回值搞混的地方，所以每个打印函数都把 `size` 打在行尾，
  和肉眼数出来的元素个数对账（本节的"对账工具"就是`print_forward` 本身：数一下几个 `<=>` 即可）。

### 9. 打印：`print_forward` / `print_backward` / `print_with_cursor`

- 反向打印**不是锦上添花，它是证据**：`prev` 链只要有一处没接对，
  反向就会提前撞回哨兵（少打几个）或者根本绕不回来（多打几个／死循环）。
  每次改完代码正反各看一眼，比写十个断言都直观。
- 三个打印函数都**不计步**（见 `cdlist.c` 里"打印"那一段开头的注释），否则会把第 4 幕的测量搅浑。
- `print_with_cursor` 是浏览器历史那一幕专用的：正向打印 + 在游标所在节点后面标 `◄当前`。
  游标停在哨兵上 = "还没打开任何页面"。
- `l->head == NULL`（表已拆掉）时打 `(未建表)`：第 8 幕 `cdlist_free` 之后再打印就是这条路径。

### 10. `cdlist_free`：拆光元素，最后**连哨兵一起**还掉

```c
Node *p = l->head->next;
while (p != l->head) {          /* ★ 撞回哨兵才停 */
    Node *nxt = p->next;        /* 先抄下一个，再 free —— 一个字不能改 */
    free(p);
    p = nxt;
}
free(l->head);                  /* ⚠ 哨兵也是 malloc 来的，漏这句 ASan 当场报泄漏 */
l->head = NULL;  l->size = 0;
```

- 循环条件里那个 `l->head` 指向的节点此时还活着（最后才 free），所以既不比悬空地址也不 UAF。
- 置 `NULL` 之后重复调 `cdlist_free` 完全安全（开头一句 return）—— 第 8 幕实测再 free 一次。
- "哨兵只是个工具人"不是不用还得理由：**它申请的，你得还**。很多教材代码就栽在这。

### 11. 应用 A：把它当**双端队列**（第 6 幕）

- 9 步脚本（push_back / push_front / pop_front / pop_back 混着来），每步之后打一次正向现状。
- ★ 实测"不需要预留容量"：接着连推 **20000** 个元素，`size = 20001`、
  队头 `10`、队尾 `20999` —— 两个都是一步从哨兵身上拿到的，全程**一次扩容/搬家都没有**。
  演示完立刻 `cdlist_free`（留着的话 ASan 当场报泄漏）。
- 和 `04-queue/deque/`（数组版循环双端队列）的区别：

| | 数组版 `04-queue/deque/` | 本节（链表版） |
|---|---|---|
| 容量 | 先 `malloc` 一整块 `capacity`，写满就**装不下**（或 `realloc` 整体搬家 O(n)） | 无 capacity 概念，来一个 `malloc` 一个，永不"写满" |
| 环的实现 | 下标**取模**：`rear = (rear + 1) % cap` | 指针**指回哨兵**：`p = p->next` |
| 每个元素内存 | 4 字节（int 本身） | 24 字节 + 一次堆分配的簿记开销（约 32 字节起） |
| cache | 元素紧凑，友好 | 节点散落在堆里，不友好 |
| 按下标读 | **O(1)** | O(n) |
| 摘除"手里已有的那个元素" | ❌ 做不到（数组里只有下标，且要整体挪） | **O(1)** |
| 两头进出 | O(1) | O(1) |
| 判空 | `front == rear`（还要多费一个位或一个计数） | `head->next == head` |

  **选型一句话**：数量有界、按下标读多 → 数组版；要频繁摘中间已知节点（LRU 那一类）→ 链表版。

### 12. 应用 B：浏览器前进/后退（第 7 幕）

- 一条历史表 + 一个游标 `cur`。`cur->prev` = 后退一格能到的页面，`cur->next` = 前进一格能到的页面。
- `hist_back` / `hist_forward`：各一句 `cur = cur->prev;` / `cur = cur->next;`，
  前置判断各一句 `== h->head`（撞哨兵 = 按钮置灰）。
- `hist_visit(page)` 两步：① `while ((*cur)->next != h->head) cdlist_erase(h, (*cur)->next);` 截断
  ② `insert_after(h, *cur, page)`，游标跟过去。头插/尾插/中间插在这一段里是**同一段代码**。
- ⚠ 截断那个循环的终止条件正是上一章那条：**撞回哨兵才停，绝不能判 NULL**。
  写成 `!= NULL` 的话，`cur->next` 走到哨兵之后还会继续 free 哨兵 —— 直接把地基拆了。
- ★ 诚实说明：这个应用里"循环"其实没用来绕圈，用的是**哨兵当左右边界**
  （`== head` 一句同时表达"前面到底了"和"后面到底了"）。
  真正为了绕圈而循环的是约瑟夫环和轮转发牌（上一章）。别把两节的卖点记串。

```text
  ↑ pop_back 在循环【单】链表里做不到 O(1)：得绕一圈找尾巴的前驱；
    这里 head->prev 就是尾巴，一步到位 —— 哨兵送的第二个好处。
  补两头 → 现在: [哨兵] <=> 5 <=> 20 <=> 30 <=> 45 <=> (回到哨兵)  size = 4
  remove_val(20) 返回 1: [哨兵] <=> 5 <=> 30 <=> 45 <=> (回到哨兵)  size = 3
  remove_val(999) 返回 0（没找到，链表原样）: [哨兵] <=> 5 <=> 30 <=> 45 <=> (回到哨兵)  size = 3

  删【哨兵本身】会怎样？
  cdlist_erase(&l, l.head) 返回 0（拒绝：哨兵是地基，抽掉整条表就散了）
  链表完好: [哨兵] <=> 5 <=> 30 <=> 45 <=> (回到哨兵)  size = 3

  一路弹到空：
    弹出 45  剩 [哨兵] <=> 5 <=> 30 <=> (回到哨兵)  size = 2
    弹出 30  剩 [哨兵] <=> 5 <=> (回到哨兵)  size = 1
    弹出 5   剩 [哨兵] <=> (回到哨兵)  size = 0
  空表：head->next == head ? 成立, head->prev == head ? 成立, size = 0
  → 弹掉最后一个元素之后，两句改线都落在哨兵身上，环自动退回『自己牵自己』。
    单链表在这里要写 if (head->next == NULL) head = NULL 之类的收尾，这里零支特判。

6. 循环双向链表当【双端队列】：两头进出，不需要预留容量
----------------------------------------
  操作序列（一共 9 步，每步之后都把正向现状打出来）：
    push_back 10 → push_front 5 → push_back 20 → pop_front → pop_back
    → push_front 1 → push_back 99 → pop_front → pop_back

  push_back 10   → [哨兵] <=> 10 <=> (回到哨兵)  size = 1
  push_front 5   → [哨兵] <=> 5 <=> 10 <=> (回到哨兵)  size = 2
  push_back 20   → [哨兵] <=> 5 <=> 10 <=> 20 <=> (回到哨兵)  size = 3
  pop_front      → 弹出 5  ；[哨兵] <=> 10 <=> 20 <=> (回到哨兵)  size = 2
  pop_back       → 弹出 20 ；[哨兵] <=> 10 <=> (回到哨兵)  size = 1
  push_front 1   → [哨兵] <=> 1 <=> 10 <=> (回到哨兵)  size = 2
  push_back 99   → [哨兵] <=> 1 <=> 10 <=> 99 <=> (回到哨兵)  size = 3
  pop_front      → 弹出 1  ；[哨兵] <=> 10 <=> 99 <=> (回到哨兵)  size = 2
  pop_back       → 弹出 99 ；[哨兵] <=> 10 <=> (回到哨兵)  size = 1

  ★ 实测『不需要预留容量』：接着往下连推 20000 个元素
    size = 20001，队头 = 10，队尾 = 20999（两个都是一步从哨兵身上拿到的）
    全程一次『扩容 / 搬家』都没有：每 push_back 一次就是一回独立 malloc。
    数组版在同一时刻要么已经报『满了』，要么正在 realloc 把两万个元素整体搬走。
    （演示完立刻 free 掉这两万个节点 —— 留着的话 ASan 当场报泄漏：谁申请谁负责）

  ★ 和 04-queue/deque/（数组实现的双端队列）的区别：
    数组版：先 malloc 一整块 capacity，front/rear 靠取模在环上跳，
            写满就【放不下】（或者搬家扩容 O(n)），元素紧凑、cache 友好，每个元素 4 字节。
    本节版：来一个 malloc 一个，没有 capacity 这个概念，永远不会『写满』；
            代价是每个元素多背 16 字节（两根指针）+ 一次堆分配，节点散落、cache 不友好；
            换来的是【手里有节点地址就能 O(1) 摘】—— 数组版做不到（数组里只有下标）。
    选型：数量有界、按下标读多 → 数组版；要频繁摘中间已知节点（LRU 那类）→ 链表版。
```

## 常见的坑

1. **空表判据写成 `head == NULL`。**
   哨兵**永远在场**，这一句建好表之后永远为假 —— 于是"空表"这件事在你的代码里从来没有被承认过，
   `pop_front` 会在只有哨兵的环上把哨兵当元素弹掉。正确写法：`l->head->next == l->head`。
   （`head == NULL` 只在"init 时 malloc 失败"或"已经 free 过"这两种**表不存在**的场合为真。）

2. **遍历终止条件忘了从 `p != NULL` 改成 `p != head`。**
   上一章那条税一分不少：链里没有 NULL，条件永真 → **死循环**，CPU 100%、日志不刷，
   连 core dump 都没有。而且这里更隐蔽一点：`head->next` 永远可读，所以它连"读越界"都不报，
   只会一直转。（`cdlist_erase_singly_style` 里那句 `if (prev == l->head) return 0;` 就是这条坑的解毒剂：
   环上写 `while`，永远先想好"绕满一圈了没有"。）

3. **`insert_after` 的第 ④ 步写早了**（先 `pos->next = n`，再读 `pos->next->prev`）。
   第 ③ 步读到的已经是新节点自己，于是 `n->prev` 被自己覆盖，老后继及其后面一串**全体失联**。
   症状是**内存泄漏而不是段错误**（ASan 报 `Indirect leak`），链表看起来还"能跑"。
   铁律还是 `pointer-basics` 那句：**覆盖之前先抄旧值**，在双向链表里要守两次。

4. **只改了 `next`，忘了 `prev`**（或反过来）。
   正向打印完全正常，程序一路跑到某次反向遍历 / `find_from_back` / `insert_before` 才炸，
   而且炸点在离 bug 很远的地方的。两种症状：反向**提前撞回哨兵**（少几个元素），
   或者反向绕不回来（**死循环**）。防法就是纪律：**每次改完代码，`print_forward` + `print_backward` 各看一眼**
   （第 2 幕那行"反向打印就是免费的自检工具"说的正是这件事）。

5. **忘了挡"删哨兵本身"：`cdlist_erase(&l, l->head)`。**
   地基被 `free`，`l->head` 变成悬空把手，下一句 `l->head->next` 就是 use-after-free。
   ASan 当场抓住（`heap-use-after-free`）。本节的 `erase` 开头有 `node == l->head` 这一挡，
   第 5 幕实测它返回 0 且链表完好。**防一手成本为零，不防就是全线崩。**

6. **`free(node)` 之后还去读 `node->prev` / `node->next`。**
   比如把 `erase` 写成"先 free 再改线"，或者 pop 时先 erase 再读值。
   正确顺序永远是：**读值 → 改两根线 → free**（`cdlist_pop_front` 里那句
   `*val_out = first->val;` 必须在 `cdlist_erase` 之前，注释里专门标了）。ASan 报 `heap-use-after-free`。

7. **`cdlist_free` 漏掉 `free(l->head)`，只拆元素不拆哨兵。**
   哨兵也是 `malloc` 来的，"它只是个工具人"不是不用还得理由。
   漏这一句就是**每建一条表漏 24 字节**，ASan 报 `leak`（很多教材代码就栽在这）。
   第 8 幕顺便演示了另一半：free 完把 `head` 置 `NULL`，再 free 一次是安全空操作，不会 double free。

8. **把"O(1) 摘除"吹成"O(1) 删除"或"O(1) 查找"。**
   只有【值】没有【地址】时，还是得先 `find`（O(n)）—— 第 3 幕实测 `find(30)` 走了 3 步。
   正确说法：**给定节点地址时，摘除动作本身 O(1)**。
   所以真实系统（LRU）是"哈希表存**节点地址** + 双向链表存顺序"，两边各拿所长；
   光有链表只能按值找，那个 O(n) 一点没省。

9. **截断/清理环时先存指针再 free，然后继续用被 free 的那个指针。**
   浏览器历史那一幕的正确写法是每次都重新读 `(*cur)->next`：
   ```c
   while ((*cur)->next != h->head) { cdlist_erase(h, (*cur)->next); }   /* ✅ */
   ```
   图省事写成下面这样就是 UAF（`erase` 里已经把 `p` free 掉了，`p->next` 读的是已释放内存）：
   ```c
   Node *p = (*cur)->next;
   while (p != h->head) { cdlist_erase(h, p); p = p->next; }            /* ❌ ASan 当场抓住 */
   ```
   原因很直白：`erase` **吃掉**了你手里那个"下一个"的地址。要么先抄 `nxt` 再 free（`cdlist_free` 就那么写），
   要么像上面那样每次现读。

10. **`size` 和真实节点数不同步。**
    任何一条 return 路径漏写 `size++` / `size--`，账本从此撒谎，但**不崩、只是长度不对**，最难查的一类。
    本节只有两处改线函数维护计数（`insert_after` 加、`erase` 减），
    其余全是它们的皮 —— 这正是"把改线收拢到一处"最实际的收益：**能对账的地方少，账才不容易错**。

11. **计步器是全局变量，这是教学妥协，别抄进项目。**
    `g_hops` 只在本节这一个编译单元里成立。真实项目要么把计数器放进 `CDList`（一表一个），
    要么用 profiler；多线程下这么写会互相污染，测出来的数字毫无意义。

## 自检问题

1. **哨兵存不存数据？空表时 `head` 是不是 `NULL`？**
   答：不存数据（`head->val` 永远不读），`head` 也**不是** `NULL` —— 它是一个真实节点，
   `malloc` 来的，自己 `next`/`prev` 都指着自己。空表判据是 `head->next == head`。
   `head == NULL` 只代表"表不存在"（init 失败或已 free）。

2. **结构体里为什么只有 `head`，不需要 `tail`？**
   答：`tail` 就是 `head->prev`，一步白捡。存了它反而多养一份要对账的账
   （上一章只存 `tail` 是因为 `head = tail->next` 同样白捡；这一节两头都白捡，
   那就一个把手都不多存）。这也是"为什么 `pop_back` 在这里是 O(1)"的答案。

3. **`insert_after` 四步里为什么 ④（`pos->next = n`）必须放最后？**
   答：②③ 都要读"老后继"这个地址，而它只存在于 `pos->next` 里。④ 一改，老后继就找不回来了，
   ③ 会把新节点自己当成老后继去改，后半串全体失联 → 内存泄漏。
   "覆盖之前先抄旧值"，双向链表里要守两次。

4. **给定节点地址 `erase` 为什么是 O(1)？只有值的时候呢？那个"199 步 → 0 步"是怎么量出来的？**
   答：因为前驱 `A` 就写在 `X` 自己身上（`X->prev`），两句赋值就把两根线接回来了，没有任何循环。
   只有值时必须先 `find`（O(n)），总账还是 O(n)。
   数字来自代码里的计步器 `cdlist_hops()`：只统计"循环体里挪 `next`/`prev` 的次数"，
   两边同一把尺子；对照组 `cdlist_erase_singly_style()` 故意装作没有 `prev`，沿 `next` 绕圈找前驱。
   n=200 删最后一个 → 199 步；`cdlist_erase` → 0 步。**量的是 `prev` 这一根线本身的价钱。**

5. **反向打印为什么能当 `prev` 链的自检工具？漏改一根 `prev` 会出现哪两种症状？**
   答：`print_backward` 全程只走 `prev`，所以它跑出来的顺序就是 `prev` 链的真实形状。
   漏改的后果要么是该节点被 `prev` 链**跳过**（提前撞回哨兵，少打几个元素），
   要么是 `prev` 指回了不该指的地方形成假环（绕不回来，死循环）。
   正向打印看不到这两个问题，因为 `next` 链是好的。

6. **循环双向链表当双端队列，和 `04-queue/deque/`（数组版）各自什么时候赢？**
   答：数组版赢在：数量有界、按下标随机读、内存紧凑 cache 友好、没有每节点 24 字节 + 一次堆分配的开销。
   链表版赢在：不需要预留容量（永不"写满"、不用 `realloc` 搬家 O(n)），
   以及**手里有节点地址就能 O(1) 摘掉**（数组里只有下标，中间删一个要整体挪）。
   所以"队列只从两头进"→ 数组版；"要频繁摘中间已知节点"（LRU、任务调度）→ 链表版。

7. **浏览器历史那一幕，"循环"到底买到了什么？只用双向不循环行不行？**
   答：行，但边界要写两支特判（`cur->prev == NULL` 和 `cur->next == NULL`），
   还得再存 first/last 两个指针才能知道"历史范围"。
   这一幕里**没有真的绕圈**（不像上一章的约瑟夫环），用正是用"哨兵兼任左右边界"：
   `== head` 一句同时表达"前面到底了"和"后面到底了"，截断循环的终止条件也顺势是 `!= head`。
   记住这个区别：**为"绕圈"而循环的是约瑟夫/轮转，为"零特判"而循环+哨兵的是这一节。**

8. **`cdlist_free` 为什么要 free 两回？**
   答：一回还元素（沿 `next` 走一圈，先抄 `nxt` 再 `free`，撞回哨兵停），
   一回还**哨兵本身**（它也是 `malloc` 的）。最后 `head = NULL; size = 0;`
   让误用当场崩而不是某天诡异崩。置 `NULL` 之后重复 free 是安全的。
