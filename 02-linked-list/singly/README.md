# 单链表 singly linked list

> 四种链表里最朴素的一种：每个节点只有一个 `next` 纸条，指向下一个节点。
> 它是所有链表玩法的地基，也是「反转链表」这道终身面试题的原型。

---

## 一句话是什么

一串用**指针**串起来的小盒子。每个盒子里装两样东西：一个 `int`（数据）+ 一张纸条 `next`（下一个盒子的地址）。最后一个盒子的纸条写 `NULL`，表示"到此为止"。

```c
typedef struct Node {
    int val;            /* 这格装的数据 */
    struct Node *next;  /* 这张纸条写着下一个节点的地址 */
} Node;
```

整条链只有一个"入口"：一个你自己攥着的指针变量 `head`，里面是第一个节点的地址。
**head 不是节点，head 是"我手里那张写着第一个节点门牌号的纸条"。**
纸条一丢，整条链再也找不回来 —— 这就是后面所有 bug 的根源。

---

## 为什么需要它

先想想不用链表怎么办。你手上只有一维数组：

| 场景 | 用数组的痛 | 链表怎么解决 |
|---|---|---|
| 已知要删中间某个元素 | 后面所有元素都得往前搬一格，O(n)；100 万个元素删第 2 个要挪 999,998 个 | 改两根线，O(1)（前提是已经走到那个节点） |
| 数据量事先不知道 / 会突然很大 | 得先估容量；写满了要么崩要么 `realloc` 搬家 O(n) | 来一个 malloc 一个，永远不搬家 |
| 频繁在头部插入（比如做栈、做撤销历史） | 头部插入 = 整体后移，O(n) | 头插 O(1)，只改两条线 |
| 内存零散、拿不到一大块连续空间 | 数组要求一整块连续内存，可能分配失败 | 每个节点各租各的小块，零散内存也能用 |
| 数组的好处 | O(1) 随机访问 `a[i]`、缓存友好、无指针开销 | ❌ 这些链表全都没有，下标访问 O(n) |

一句话：**数组用"连续"换来 O(1) 随机访问；链表用"零散 + 指针"换来 O(1) 插改线。**
需要频繁增删、不需要按下标跳着读，就该上链表。

## 内存布局图解

```
        head
         │
         ▼
   ┌─────────┬───────┐      ┌─────────┬───────┐      ┌─────────┬───────┐
   │  val=1  │ next───┼─────►│  val=2  │ next───┼─────►│  val=3  │ next───┼────┐
   └─────────┴───────┘      └─────────┴───────┘      └─────────┴───────┘    │
                                                                             ▼
                                                                            NULL
                                                                          （链表到此为止）
```

三个关键认知：

**① 节点在堆上，地址可以乱序。**
数组必须占一整块连续内存；链表的节点是一个个 `malloc` 出来的，可能一个在 `0x5000`、
下一个在 `0x2000`，完全靠 `next` 里的地址连起来：

```
   内存地址从低到高（示意）
   0x2000 ┌───────┬───────┐
          │ val 3 │  NULL │   ← 最后插的节点，地址反而最小
          └───────┴───────┘
   0x5000 ┌───────┬───────┐
          │ val 1 │0x6000 │──┐        head(在栈上) = 0x5000
          └───────┴───────┘  │             ▲
   0x6000 ┌───────┬───────┐  │             │
          │ val 2 │0x2000 │◄─┼─────────────┘（head 指向第一个节点，不是最小地址）
          └───────┴───────┘  │
              ▲              │
              └──────────────┘（next 里存的就是下一个节点的真实地址）
```

**② 空表 = `head == NULL`。**
不是"head 指向一个空节点"，而是 head 这个变量里就是 NULL。
所有函数的第一个动作都应该是想想：`head == NULL` 时会发生什么。

**③ 只有一个节点时，`node->next == NULL`**，它既是头也是尾。

```
   空表：      head ──► NULL
   单节点：    head ──► [42|∅] ──► NULL     （∅ 就是 NULL）
```

**④ 头插（push_front）的画面**——顺序绝不能反：

```
   之前：  head ──► [1|●] ──► [2|●] ──► NULL
   ①n->next = *head：  [9|●] ──┐
                                   ↓
                        head ──► [1|●] ──► [2|●] ──► NULL
   ②*head = n：        head ──► [9|●] ──► [1|●] ──► [2|●] ──► NULL
```
如果先做②，老链表的入口地址立刻被覆盖，`[1] [2]` 全体失联 —— 叫**断链**。

**⑤ 删节点（要摘掉 2）的画面**——注意必须改的是**前驱**的 next：

```
   prev        cur
    │           │
    ▼           ▼
  [1|●] ──► [2|●] ──► [3|●] ──► NULL
      prev->next = cur->next;   free(cur);
    │
    ▼
  [1|●] ──────────────► [3|●] ──► NULL      [2] 被摘下来还给了系统
```

## 核心操作逐个拆解

### 0. 贯穿全节的一条心法

`00-c-foundation/pointer-basics` 里那条铁律，到这里天天用：

> **C 语言传参永远是拷贝，想改到外面就得传地址。**

- `swap_by_value(int a, int b)` 改不到外面的 `x`、`y`；`swap_by_pointer(int *a, int *b)` 才改得到。
- 同理，`head` 是一个"存着节点地址的变量"。要改**这个变量**（头插、删头、反转、释放），
  就得传它的地址 → `Node **head`。
- 只是**路过读一读**整条链（求长度、查找、打印、找中间），传 `Node *head` 就够。

本节 `slist_push_front_bad()` 故意写成 `Node *head`，跑起来能亲眼看到
"函数内部已经插好了，外面纹丝不动"，跟 `swap_by_value` 是一模一样的错。

### 1. 造节点 `slist_make_node`

- **干什么**：在堆上租一个节点，填入 `val`，`next` 先置 `NULL`。
- **一步步**：`malloc(sizeof(Node))` → 判空 → 写 `val` → 写 `next = NULL` → 返回地址。
- **边界**：内存不够时 `malloc` 返回 `NULL`，返回给调用者判断；忘置 `next = NULL` 的话
  `next` 里是垃圾值，一往下走就段错误。
- **对应代码**：`slist.c` 里 `slist_make_node`。

### 2. 头插 `slist_push_front`（O(1)）

- **干什么**：新节点插到最前面，成为新的头。
- **一步步**：① `n->next = *head;`（新节点先牵住老链表）② `*head = n;`（头指针挪到新节点）。
- **边界**：空表时 `*head == NULL`，第①步等于 `n->next = NULL`，正好成为既成头又成尾的孤节点 —— 不用特判。
- **代价**：恒定两步，跟链表多长无关。
- **对应代码**：`slist.c` 的 `slist_push_front`；反面教材 `slist_push_front_bad`。

### 3. 尾插 `slist_push_back`（O(n)）

- **干什么**：插到最后面，保持插入顺序。
- **一步步**：① 空表特判 `*head = n` ② 否则 `cur = *head; while (cur->next != NULL) cur = cur->next;`
  ③ `cur->next = n;`（`n->next` 已经是 NULL，天然成为新尾巴）。
- **边界**：不判空表就会在 `NULL` 上执行 `cur->next` → 崩。循环条件是"停在最后一个**节点**"而不是
  "走到 NULL"，写成 `while (cur != NULL)` 会多走一步、然后解引用空指针，这是新手最常见的错。
- **对应代码**：`slist.c` 的 `slist_push_back`。

### 4. 在第 k 个位置插入 `slist_insert_at`

- **干什么**：插完之后新节点的下标是 k（下标从 0 数）。
- **一步步**：① `k < 0` 直接失败 ② `k == 0` 转调头插 ③ 否则把 `prev` 走到**第 k-1 个节点**
  ④ `n->next = prev->next;` ⑤ `prev->next = n;`
- **为什么必须"走到 k-1"**：链表只能往后牵线，要插到 k 前面，就得拿到 k-1 的地址。
- **边界**：`k == 长度` 等于尾插（合法）；`k > 长度` 越界，会走穿链表 —— 用 `prev == NULL` 挡住并报错，
  返回值 0，链表一根线都不动；有重复值不影响（按位置不按值）。
- **对应代码**：`slist.c` 的 `slist_insert_at`。

### 5. 查找 `slist_find` / `slist_get_at`

- **干什么**：前者按值找、返回**节点地址**；后者按下标找、把值写进输出参数。
- **一步步**：`while (cur != NULL) { if (命中) return cur; cur = cur->next; } return NULL;`
- **边界**：空表返回 `NULL`；值不存在返回 `NULL`（所以**不能**用返回 0 表示"没有"，0 也是合法地址值）；
  有重复值时返回最靠前的那个。`get_at` 里 `val_out` 传 `NULL` 表示"我只要知道存不存在"。
- **为什么返回地址而不是下标**：拿到地址就能直接对这个节点动手（比如删它），不用再遍历一遍。
- **对应代码**：`slist.c` 的 `slist_find`、`slist_get_at`。

### 6. 按值删除 `slist_remove_val`（本节最大考点）

**难点：删头节点和删中间节点，天生是两套代码。**

要摘掉一个节点，必须改**它前驱**的 `next`。可是单链表的节点只知道"下一个是谁"，
不知道"上一个是谁"，所以只能从 `head` 出发用 `prev`/`cur` 两个指针并排走，走到命中。

```
   删中间： prev ──► [A|●] ──► [B|●] ──► [C|●]     改 prev->next = cur->next  ← 第 1 套写法
                        prev       cur(要删)

   删头：   head ──► [B|●] ──► [C|●]               改 head = head->next        ← 第 2 套写法
                    head      ← 它压根没有前驱！
```

两套分支、两处指针写入，写漏一处就是 bug。

**统一办法：先造一个假头哨兵 `dummy`。**

```c
Node dummy;              /* 栈上的临时节点，不 malloc、不 free、不存有效数据 */
dummy.next = *head;      /* 它牵住真正的头 → 从此"头节点也有前驱" */
```

```
   挂哨兵之前：  head ──► [1|●] ──► [2|●] ──► [3|●] ──► NULL
   挂哨兵之后：  head ──► [dummy|●] ──► [1|●] ──► [2|●] ──► [3|●] ──► NULL
                               ▲          ▲
                              prev       cur     ← 删 1 和删 2、删 3 用的是同一行 prev->next = cur->next
```

摘完之后 `dummy.next` 里存的就是"最新的首节点"（可能已经不是原来那个了），
在函数最后一行 `*head = dummy.next;` 统一写回，外面永远不用关心刚删的是不是头。

- **一步步**：挂 dummy → `prev = &dummy, cur = dummy.next` → `while (cur != NULL && cur->val != val)` 同步前进
  → 若 `cur == NULL` 返回 0 → 否则 `prev->next = cur->next; free(cur); *head = dummy.next;` 返回 1。
- **边界**：空表（`dummy.next == NULL`，第一次循环条件就假，返回 0）；
  删唯一的节点（`*head` 被写回 NULL）；值不存在（一处 `free` 都没执行，链表原样）；重复值（只删最靠前那个）。
- **对应代码**：`slist.c` 的 `slist_remove_val`（哨兵版）与 `slist_remove_val_two_cases`（土办法，留作对比，
  `main.c` 第 5 幕会跑同一段删除序列，两种写法输出**逐行相同**）。

### 7. 求长度 `slist_length`

- **干什么**：数一共有几个节点。
- **一步步**：`count = 0; while (cur) { count++; cur = cur->next; }`
- **边界**：空表 → 循环不进 → 0，正确。
- **要点**：这个数**链表自己不知道**，问一次数一遍，O(n)。要 O(1) 拿长度必须自己维护 `size` 字段
  （双向链表那节就这么干）。

### 8. 反转 `slist_reverse_iter` / `slist_reverse_recursive`

- **干什么**：所有 `next` 箭头掉头，原来的尾巴变成头。
- **迭代版一步步**：三个指针 `prev = NULL, cur = *head, nxt`，每轮四小步：
  ① `nxt = cur->next`（**先抄住下一个！**）② `cur->next = prev`（掰箭头）③ `prev = cur`（已完成段扩一个）
  ④ `cur = nxt`（窗口前进）。循环结束 `*head = prev`。

```
   初始：  prev=NULL   cur=[1]→[2]→[3]→NULL
   轮1：   NULL◄[1]    prev=[1]  cur=[2]→[3]→NULL
   轮2：   NULL◄[1]◄[2]  prev=[2]  cur=[3]→NULL
   轮3：   NULL◄[1]◄[2]◄[3]  prev=[3]  cur=NULL → 退出，新头 = [3]
```

- **★★ `nxt = cur->next` 为什么必须写在第一行**：第②步要**覆盖** `cur->next` 这个格子。
  一覆盖，"下一个节点在哪"这条信息就永久消失，后半条链既走不到也 free 不掉（内存泄漏）。
  必须先把旧值抄到纸条上。这跟 `swap_by_pointer` 里 `int temp = *a;` 必须先做，是**同一条铁律**。
- **递归版一步步**：`reverse(head->next)` 把"除头以外"那段反转好并返回新头，
  然后 `head->next->next = head;`（让原来紧跟着我的节点回头指我）、`head->next = NULL;`（我变成尾巴）。
- **边界**：空表 / 单节点（迭代版走 0/1 轮结果不变；递归版靠 `head == NULL || head->next == NULL` 出口）。
- **注意**：递归深度 = 链表长度，十万个节点就十万层调用，**栈会爆**。工程上只用迭代版；
  递归版是用来练"敢不敢信递归"的。

### 9. 找中间节点 `slist_middle`（快慢指针）

- **干什么**：一趟遍历定位中间节点，不用先数长度。
- **一步步**：`slow` 每次走 1 步，`fast` 每次走 2 步，同步迈步；`fast` 到终点时 `slow` 正好在中点。

```
   n=5（下标 0..4）：迈步次数 t → slow 下标 t，fast 下标 2t
        t=0:  s@0        f@0
        t=1:      s@1        f@2
        t=2:          s@2        f@4   ← fast->next == NULL，退出。slow 在下标 2 = 正中间 ✔
```

- **为什么正好在中间**：两条腿同时迈步，`fast` 走过的距离永远是 `slow` 的两倍；
  `fast` 走完全程（≈n）时，`slow` 只走了 n/2。所以不需要知道 n。
- **边界**：`n == 0` → `fast == NULL`，条件短路，安全返回 NULL；`n` 偶数（4）→ `slow` 停在**中间偏右**
  那个（下标 n/2）；`n == 1` → 返回它自己。
- **顺序警告**：条件必须写 `fast != NULL && fast->next != NULL`，反过来的话 `fast` 为 NULL 时
  会去读 `NULL->next`，直接崩。

### 10. 打印 `slist_print` 与 释放 `slist_free`

- **打印**：一路 `printf("%d -> ", cur->val)`，最后补一个 `NULL`。空表也能打印（只出 `NULL`）。
- **释放一步步**：`while (cur) { nxt = cur->next; free(cur); cur = nxt; }` 最后 `*head = NULL;`
- **顺序铁律**：**先抄 next，再 free**。写成 `free(cur); cur = cur->next;` 就是读已释放内存
  —— 未定义行为，可能今天好好的，明天诡异地崩。
- **为什么参数是二级指针**：光 free 不够，还要把外面的 `head` 置 `NULL`，
  否则它成了悬空指针，后面再 print 一次就是访问已释放内存（ASan 立刻举报）。

## 复杂度表

n = 节点个数。括号里是"最坏"。

| 操作 | 单链表 | 数组（对比） | 双向链表（下一节） | 说明 |
|---|---|---|---|---|
| 按下标访问 | O(n) | **O(1)** | O(n) | 链表没有随机访问 |
| 按值查找 | O(n) | O(n)（有序可二分 O(log n)） | O(n) | 都一样要扫 |
| 头部插入 | **O(1)** | O(n) | **O(1)** | 数组头部插要整体后移 |
| 尾部插入 | O(n) | **O(1)**（容量够时） | **O(1)**（存了 tail） | 单链表没有"尾巴把手" |
| 第 k 个位置插入 | O(n) | O(n) | O(n)（找位置）+ O(1)（接线） | 找位置占大头 |
| 删除**已知地址**的节点 | **O(n)**（要找前驱） | O(n)（要搬家） | **O(1)**（有 prev） | 单链表最大的短板 |
| 按值删除 | O(n) | O(n) | O(n) | 先要找 |
| 求长度 | O(n) | **O(1)** | **O(1)**（维护 size） | |
| 反转 | O(n) 时间 O(1) 空间 | O(n) 时间 O(n) 空间 | O(n) | 链表反转不用额外数组，优势明显 |
| 找中间（快慢指针） | O(n) 一趟 | O(1) | O(n) | |
| 每个节点的额外内存 | 1 个指针 8 字节 | 0 | 2 个指针 16 字节 | 链表的固定税 |

  收尾释放完毕，main 里的 head 已被置成 NULL（不留悬空指针）

2. 头插 O(1) vs 尾插 O(n)
----------------------------------------
  依次头插 1 2 3：
  结果: 3 -> 2 -> 1 -> NULL
  → 头插是『后进来排在前面』，顺序反了；想保持插入顺序就得用尾插。

  依次尾插 1 2 3（每次都要从头走到尾巴，3 次共走 0+1+2 步）：
  尾插 1: 1 -> NULL
  尾插 2: 1 -> 2 -> NULL
  尾插 3: 1 -> 2 -> 3 -> NULL
  → 顺序保住了，代价是每次 O(n)。这就是链表『没有尾巴把手』的痛。

----------------------------------------
3. 在第 k 个位置插入（下标从 0 起）
----------------------------------------
  原始链表: 10 -> 20 -> 30 -> NULL
  插到 k=0（最前面）放 99: 99 -> 10 -> 20 -> 30 -> NULL
  插到 k=2 放 55: 99 -> 10 -> 55 -> 20 -> 30 -> NULL
  插到 k=5（= 长度，等于尾插）放 77: 99 -> 10 -> 55 -> 20 -> 30 -> 77 -> NULL
  故意插到越界位置 k=100：
      [错误] k=100 越界：当前长度 6，可插范围是 0 ~ 6
    返回值 = 0（0 = 失败），链表保持原样: 99 -> 10 -> 55 -> 20 -> 30 -> 77 -> NULL
  故意插到 k=-1：
      [错误] 插入位置 k=-1 不能为负
    返回值 = 0（0 = 失败）

----------------------------------------
4. 按值查找 & 按下标取值（都是 O(n)，链表没有随机访问）
----------------------------------------
  链表: 5 -> 8 -> 13 -> 21 -> NULL
  find(13): 找到了，返回的节点 val = 13（拿到地址就能直接删它）
  find(100): 没找到（返回 NULL）
  get_at(2) = 13（想拿第 3 个，必须从第 1 个开始走 2 步）
  get_at(99): 下标越界，返回 0；v 仍是调用前的 13（函数没往里写）
  长度 = 4

----------------------------------------
5. 按值删除：哨兵 dummy 统一『删头』和『删中间』
----------------------------------------
  ★ 难点回顾：单链表节点不知道自己的前驱是谁，
    所以要删一个节点，得改【它前驱】的 next；
    可头节点没有前驱，只能改 head 变量本身 —— 这就冒出了两套代码。
    造一个不存数据的假头 dummy 挂到最前面，头节点也就有了前驱，两套代码合成一套。

  【土办法 slist_remove_val_two_cases】分两种情况写：
    起始:               1 -> 2 -> 3 -> 4 -> NULL
    删 1（头节点）:      2 -> 3 -> 4 -> NULL
    删 3（中间节点）:    2 -> 4 -> NULL
    删 4（尾巴节点）:    2 -> NULL
    删 99（不存在）:     2 -> NULL
    删 2（最后一个）:    NULL
    现在链表是空的吗？   NULL

  【哨兵写法 slist_remove_val】dummy 挂前，一路 prev/cur：
    起始:               1 -> 2 -> 3 -> 4 -> NULL
    （内部画面：dummy -> 1 -> 2 -> 3 -> 4 -> NULL，每个节点都有前驱了）
    删 1（头节点）:      2 -> 3 -> 4 -> NULL
    删 3（中间节点）:    2 -> 4 -> NULL
    删 4（尾巴节点）:    2 -> NULL
    删 99（不存在）:     2 -> NULL
    删 2（最后一个）:    NULL
    现在链表是空的吗？   NULL
  长度 = 0
  → 两种写法的输出【一模一样】，但哨兵版只有一处 free、零个特判。

  有重复值时删一次: 7 -> 7 -> 7 -> NULL
  删掉一个 7 之后:    7 -> 7 -> NULL

----------------------------------------
6. 反转：迭代版 & 递归版
----------------------------------------
  反转前（原样）:          1 -> 2 -> 3 -> 4 -> 5 -> NULL
  迭代版反转之后:          5 -> 4 -> 3 -> 2 -> 1 -> NULL
  再拿递归版反转回来（等于原样）: 1 -> 2 -> 3 -> 4 -> 5 -> NULL
  只用递归版反转一次:      5 -> 4 -> 3 -> 2 -> 1 -> NULL
  再用迭代版反转回来:      1 -> 2 -> 3 -> 4 -> 5 -> NULL
  → 迭代版和递归版互为逆操作？不，反转两次才回到原样；两个版本结果必须相同。

  边界：空表反转
  空表迭代反转后:          NULL
  空表递归反转后:          NULL
  边界：单节点反转
  [42] 迭代反转后:         42 -> NULL
  [42] 递归反转后:         42 -> NULL

  ★ 为什么 nxt = cur->next 必须写在最前面？
    因为下一行 cur->next = prev 要【覆盖】cur->next 这个格子。
    不先抄住，后半条链就再也找不回来了（既走不到也 free 不掉）。
    跟 swap 前必须先 int temp = *a; 是同一条铁律：覆盖之前先存旧值。

----------------------------------------
7. 快慢指针找中间节点（一趟搞定，不用先数长度）
----------------------------------------
  链表（奇数个，n=5）:     10 -> 20 -> 30 -> 40 -> 50 -> NULL
  慢指针停在:             val = 30（第 3 个，正中间）

  链表（偶数个，n=4）:     10 -> 20 -> 30 -> 40 -> NULL
  慢指针停在:             val = 30（中间两个里【偏右】那个；想拿偏左的要自己记下前一站）

  链表（只有 1 个）:       1 -> NULL
  慢指针停在:             val = 1

  空表找中间:              NULL（安全，没崩）

=== 本节结束 ===
记住四句话：
  1) 要改到调用者的 head，就得传 &head（二级指针）；只传 Node* 改的是拷贝。
  2) 删头节点没有前驱、删中间节点要找前驱 —— 造个 dummy 假头，两件事变一件事。
  3) 指针要覆盖哪个格子，就先把它旧值抄到 temp/nxt 里存住（反转、释放全靠这句）。
  4) 链表换来换去都是 O(n) 遍历 + O(1) 改线；想 O(1) 拿到尾/长度，就多存字段。

## 常见的坑

1. **只传 `Node *head` 却想改头指针。**
   `void push_front(Node *head, int v) { head = n; }` 编译运行都不报错，但外面完全没变，
   新节点还漏了。要改 head 本身必须 `Node **`。跑 `main.c` 第 1 幕能亲眼看到。

2. **覆盖前没抄旧值 → 断链。**
   头插先写 `*head = n` 再写 `n->next`；反转不先存 `nxt`；释放先 `free(cur)` 再 `cur = cur->next`。
   三种写法都会让后半条链永久失联。**症状是"内存泄漏"而不是崩溃，最难查** —— 一定要跑 ASan。

3. **循环条件写成 `while (cur->next != NULL)` 但没先判 `cur` 非空。**
   空表时 `cur == NULL`，`cur->next` 直接段错误。
   正确姿势：`cur != NULL && cur->next != NULL`（`&&` 短路，顺序绝不能换）。

4. **忘 `free`，或者 `free` 之后继续用（悬空指针）。**
   链表节点是逐个 malloc 的，漏一个就漏一次。`slist_free` 完把 `*head` 置 `NULL`，
   误用会当场崩，比"读到垃圾值继续跑"好查一万倍。

5. **`malloc` 出来的节点没把 `next` 置 NULL。**
   `next` 里是内存里残留的垃圾地址，`print` 时看着"多打了好几个随机数"，
   或者直接段错误。造节点必须写 `n->next = NULL`。

6. **判断"值不存在"却用返回 0 / 返回 -1 混过去。**
   `slist_find` 没找到要返回 `NULL`（不是 0，也别返回什么 -1）；
   插入/删除这种"要不要我改过链表"的操作用 `int` 返回 1/0，调用方必须看一眼返回值。

7. **递归反转拿去处理十万个节点。**
   递归深度 = 链表长度，栈溢出（segmentation fault，且 ASan 报 stack-buffer-overflow / SEGV）。
   实际项目一律用迭代版。

## 什么时候用它 / 什么时候别用

**该用：**
- 频繁在**头部**增删：撤销栈、表达式求值、DFS 的工作列表。
- 需要在**已定位到的位置**廉价插入/删除，且不在乎按下标读。
- 数据量完全未知，或者内存碎片化、拿不到大段连续内存。
- 要实现别的结构的地基：链式栈、链式队列、拉链法哈希表、LRU、跳表 —— 全是它。
- 多路归并 / 合并有序链表：改线即可，不用搬数据。

**别用：**
- 需要**随机访问**（频繁 `a[i]`）：数组 O(1) vs 链表 O(n)，差得远。
- 元素数量已知且基本不变、只读多写少：数组完胜（缓存友好 + 无指针开销）。
- 内存敏感 / 追求极致吞吐：每个节点多 8 字节指针，而且节点散落各处，CPU 缓存次次 miss。
- 需要并发安全：链表改两根线不是原子操作，加锁粒度和一致性都很麻烦。
- 需要按下标二分/查找有序数据：考虑跳表（本节第 5 个目录）或平衡树。

## 自检问题

1. **为什么 `slist_push_front` 是 `Node **head`，而 `slist_length` 只是 `Node *head`？**
   答：头插要**改 head 这个变量的值**（换成新节点的地址），必须传它的地址才能改到外面；
   求长度只是顺着链读一遍，一个指针都不改，传一份 head 的拷贝反而更省事。
   判据永远是：**这个函数要不要修改调用者手里那个变量？**

2. **删头节点和删中间节点，为什么在单链表里是两套代码？哨兵怎么就把它们合成一套？**
   答：删除要改的是**前驱**的 `next`，而头节点没有前驱，只能改 `head` 变量本身。
   挂一个不存数据的 `dummy` 到最前面后，"头节点的前驱"就是 `dummy`，于是所有节点都有前驱，
   一行 `prev->next = cur->next` 通吃；最后 `*head = dummy.next` 把可能被换掉的头写回。

3. **反转链表里 `nxt = cur->next` 为什么必须写在 `cur->next = prev` 前面？释放时 `nxt = cur->next` 为什么必须在 `free(cur)` 前面？**
   答：两处都是同一个道理 —— 后一行要**覆盖 / 销毁**这个格子，里面那个"下一个节点的地址"
   是全世界唯一一份，不先抄出来就永远丢了，后半条链既走不到也 free 不掉。

4. **快慢指针找中间，为什么 `slow` 一定落在中间？链表 4 个节点时它停在第几个？**
   答：两指针同时迈步，`fast` 每轮 +2、`slow` 每轮 +1，`fast` 走过的路程永远是 `slow` 的两倍；
   `fast` 走完全程 n 时 `slow` 走了 n/2。n=4 时 `fast` 走到 NULL（下标 4），`slow` 在下标 2 =
   第 3 个，也就是中间两个里偏右的那个。

5. **`slist_free` 结束后为什么还要 `*head = NULL`？不写会怎样？**
   答：不写的话调用者的 `head` 还存着已经还给系统的地址 —— 悬空指针。之后误用它属于未定义行为，
   可能读到垃圾值、可能"看起来正常"，某天诡异崩溃。置 NULL 后误用会立刻段错误，当场暴露。
   顺带：`free(NULL)` 是合法空操作，所以再调用一次 `slist_free` 也不会 double free。
