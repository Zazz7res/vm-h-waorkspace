# 跳表 skip list

> 有序单链表查找为什么必须 O(n)？因为它只能一格一格走。
> 跳表做的事只有一件：**给链表加第二层、第三层……索引，让它跳着走。**
> 代价是"层数靠抛硬币决定"，收益是"期望 O(log n) + 全代码不到 200 行 + 范围查询天生就是顺着链走"。

---

## 一句话是什么

在**有序**链表上面，给一部分节点多挂几根 `next` 指针，形成"上层稀疏、下层稠密"的多层索引；
查找时从最上层大步跨，跨不动了就下沉一层继续走，**永远不回头**。

```c
typedef struct SkNode {
    int                key;      /* 数据，本节一律 int */
    struct SkNode    **forward;  /* ★ 指针的数组：forward[l] = 第 l 层的下一个节点 */
} SkNode;
```

一句话：**跳表 = 有序链表 + 多层索引链表**。它不是树，它就是若干条互相引用的链表摞起来。

---

## 为什么需要它

### 1. 出发线：有序单链表查找必须 O(n)，一格一格走

数组能二分，是因为 `a[mid]` 是 O(1) 随机访问。**链表没有这个能力**：手里只有一个 `next`，
站在节点上只能问"下一个是不是"，所以只能一格一格走。

```
  找 13（表已经是有序的！）

  head
   │
   ▼
  [1] ──► [3] ──► [5] ──► [7] ──► [9] ──► [11] ──► [13] ──► [15] ──► NULL
   ①       ②       ③       ④       ⑤       ⑥         ⑦
   看了     不是    不是    不是    不是    不是      就是它！   —— 一共问 7 次

  ★ "有序"能给的唯一好处是**提前刹车**：一旦发现下一个已经比目标大，就可以停，不用再往后看。
    但刹车只是让"查不到"少走一半，平均仍是 n/2 步 —— 复杂度一个字母都没变。
```

**没有随机访问，就没有二分。** 想在链表上做二分，就必须"提前"把随机访问的能力造出来 ——
造它的办法就是在部分节点上多挂几根指针。

### 2. 治疗办法：给链表加第二层索引，跳着走

先只加一层：让**每隔一个**节点再长出一根上层指针。

```
  第 1 层（索引层，稀疏）:  HEAD ─────────────────► 7 ─────────────────► NIL
                              │                     │
                              │  上层只管"跨大步"    │
                              ▼                     ▼
  第 0 层（数据层，全量）:  HEAD ─► 1 ─► 3 ─► 5 ─► 7 ─► 9 ─► 11 ─► 13 ─► 15 ─► NIL

  找 13：
    第 1 层：HEAD 的下一个是 7，7 < 13 → 跨过去；7 的下一个是 NIL → 本层到头，下沉 ↓
    第 0 层：从 7 出发，8... 7 的下一个是 9 → 跨；9 < 13 → 跨；11 < 13 → 跨；13 == 13 → 命中
    一共问 6 次（原来 7 次）。省得太少了？因为**只有一层索引**：
    上层把我扔在 7，剩下 7 格还得一格一格走 —— 代价变成 "n/2（上层跨）+ n/2（下层走）"？
    不是，是 "2（上层）+ 6（下层）"：**索引层每 2 个节点抽 1 个，就少问一半**。
```

关键一步：**再加一层**，每 4 个节点抽 1 个；再加一层，每 8 个抽 1 个……

```
  第 3 层:  HEAD ─────────────────────────────────────────────────────► NIL     每 8 个抽 1 个
  第 2 层:  HEAD ─────────────► 7 ──────────────────────────────────► NIL     每 4 个抽 1 个
  第 1 层:  HEAD ─────► 3 ─────► 7 ─────► 11 ──────────────────────► NIL     每 2 个抽 1 个
  第 0 层:  HEAD ─► 1 ─► 3 ─► 5 ─► 7 ─► 9 ─► 11 ─► 13 ─► 15 ─► ... ─► NIL     全量
                    └── 查找 13 的路径：0 层全量里，我只走了 4 步 ──┘

  层数 = log2(n)；每层平均只需走常数步（上层把我送到"离目标很近"的地方）。
  → 期望比较次数 ≈ (1/p) · log2(n)，p = 1/2 → **2 · log2(n)**。
```

**为什么不用"严格每 2 个抽 1 个"的规则分层，而要用抛硬币随机？**
因为规则分层在插入时会立刻破坏均匀性：新节点该不该进索引层？进了就把邻居的间隔挤乱了，
不进的化又留下空洞 —— 你不得不写一堆"旋转 / 分裂 / 合并"来维持间隔，那就变成树了。
随机分层的妙处在于：**新节点的层数只由自己的硬币决定，和邻居无关**，
所以插入永远是"找到前驱 + 改线"，不需要任何再平衡。这就是它比平衡树好写一百倍的根本原因。

## 图解（ASCII）

### 1. 一个节点在内存里长什么样（本节最容易写错的地方）

每个节点是**两次 malloc**：节点本体 16 字节 + 一根指针数组。

```
   sk_insert 内部：
   ┌─────────────┐   n = malloc(sizeof(SkNode))                 → 16 字节（int + 补白 + 一个指针）
   │ n           │   n->forward = malloc(sizeof(SkNode*) * (level + 1))  → 每层 8 字节，另一次分配
   └─────────────┘
          │
          ▼
   ┌───────────┬──────────────┐
   │ key =  13 │ forward ─────┼──┐   ← forward 本身只是【一个指针】（8 字节）
   └───────────┴──────────────┘  │
                                 ▼
                    ┌────────────┬────────────┬────────────┬ ─ ─
                    │ forward[0] │ forward[1] │ forward[2] │
                    └─────┬──────┴─────┬──────┴─────┬──────┘
                          ▼            ▼            ▼
                     第 0 层后继  第 1 层后继  第 2 层后继      ← 每格里装的是一个地址
                     （数组长度 = 这个节点的层数，一格都不能多）
```

### 2. `SkNode **forward`：「指针的数组」，不是「数组的指针」

这是本节被读错最多的一行声明。**读法只有一种正确**：`forward` 是 `SkNode *` 类型的数组的首地址。

```
   struct SkNode { int key; struct SkNode **forward; };
                                   ^^^^^^^^^^^^^^^^^
   拆开读：forward 的类型是 "struct SkNode **"
           = 指向 (struct SkNode *) 的指针
           = 一串 "SkNode*" 排在一起，forward 指着第 0 个
           → 所以 forward 是【指针的数组】：数组里每个元素本身是一个指针

   另一种（本节【不】用的）写法才叫【数组的指针】：
           SkNode *arr[4];
           SkNode *(*p)[4] = &arr;     ← p 指着"一整块 4 个指针"，p 的类型是"数组指针"
```

两者取第 `l` 个元素都能写成 `forward[l]` / `(*p)[l]`，**看起来一模一样**，所以极易看漏。
区别在 `sizeof` 和 `+1` 走多远（下面这两行是 main.c 第 3 幕真实打印出来的）：

```
   forward + 1  →  往前走  8 字节   = 一个格子（sizeof(SkNode*) == 8）
   p       + 1  →  往前走 32 字节   = 整块数组（sizeof(*p)      == 32）
```

**心法**：看到 `**` 先问一句 —— "数组里装的到底是啥？"
这里数组里装的是指针 ⇒ `**` ⇒ 叫它"指针的数组"。
如果数组里装的是 `int`，那才是 `int *p` 一个星号就够。

### 3. 三个必须认识的部件

```
  s->level = 6（有效层号 0 ~ 5）

        ┌──────────────────────────────────────── head 哨兵（key = INT_MIN）
        │  每一层都从它出发，所以"插到最前面"不用写特判
        ▼
  第 5 层 | HEAD ──────────────────────────────────────────────► 21 ─► NIL
  第 4 层 | HEAD ──────────────────────────────────────────────► 21 ─► NIL
  第 3 层 | HEAD ────────────────────────────────► 21 ───────► 29 ─► NIL
  第 2 层 | HEAD ──────────► 19 ───────────────► 21 ───────► 29 ─► NIL
  第 1 层 | HEAD ─► 1 ──► 17 ──► 19 ──► 21 ──► 23 ──► 27 ──► 29 ─► NIL
  第 0 层 | HEAD ─► 1 ─► 3 ─► 5 ─► 7 ─► 9 ─► 11 ─► 13 ─► 14 ─► ... ─► 31 ─► NIL
                                                                     ▲
                                     nil 尾哨兵（forward[l] = 自己）──┘
                                     每层走到头就是它，于是内层循环永远不用判 NULL
```

- `head`（key = `INT_MIN`）：所有层的入口。有了它，"插到第 0 个位置"和"插在中间"是同一段代码。
- `nil`（key = `INT_MAX`，`forward[l] = nil` 自环）：所有层的终点。有了它，内层循环写成
  `while (x->forward[l]->key < key) x = x->forward[l];`，**一句 NULL 判断都不需要**。
- 副作用要知道：`INT_MAX` 和 `INT_MIN` 被哨兵占了，**不能当真实数据用**（本节只在 `ordlist.c` 用了 `INT_MIN` 刹车）。

### 4. 查找路径：亲眼看到"跳"

`sk_search(13)` 在第 2 幕那张表上的真实轨迹（下面是 main.c 第 2 幕的真实输出，不是我手画的）：

```
  第 5 层: 从 HEAD 出发   ── 下一个是 21 ≥ 13，本层停，下沉 ↓（最高层 0 跨：HEAD 后面第一个就太大了）
  第 4 层: 从 HEAD 出发   ── 下一个是 21 ≥ 13，本层停，下沉 ↓
  第 3 层: 从 HEAD 出发   ── 下一个是 21 ≥ 13，本层停，下沉 ↓
  第 2 层: 从 HEAD 出发   ── 下一个是 19 ≥ 13，本层停，下沉 ↓
  第 1 层: 从 HEAD 出发 ──► 1   ── 下一个是 17 ≥ 13，本层停，下沉 ↓（本层跨了 1 格）
  第 0 层: 从 1 出发   ──► 3 ──► 5 ──► 7 ──► 9 ──► 11   ── 下一个是 13，第 0 层不能再沉了
  ✔ 第 0 层往前看一眼 = 13 → 命中

       │  ① 从不回头：每层只有"往前走"和"下沉"两个动作
       │  ② 下沉是【站在上一层停住的那个节点上】继续走 —— 这样目标一定还在我右边
       ▼  ③ 最终判定只看第 0 层的"往前一眼"，所以 NIL 必须在场
```

**为什么下沉不会漏？** 因为在第 `l` 层停住时，我站在 `x`，且满足
`x->key < key < x->forward[l]->key`：目标如果存在，一定落在 `x` 和 `x->forward[l]` 之间的**开区间**里。
下沉一层只是把这段区间拆得更细，我从 `x` 继续往右扫就行，永远不需要回头。

## 核心操作逐个拆解

### 0. 贯穿全节的一条心法

`insert`、`search`、`remove` 是**同一个下降过程**的三个用法：

```
   从 head 的最高层出发，每层"能跳就跳，跳不动就下沉"，
   每层停住的位置 x 满足：x 是本层最后一个 < key 的节点 = 本层前驱
                    │
        ┌───────────┼───────────┐
        ▼           ▼           ▼
    记录下来    沉到底看一眼   记录下来
   = update[]   是不是 key     = update[]
   = 插入位置    = search 结果  = 要摘掉的那个
```

所以本节三个操作的**搜索部分完全一样**，只有后半段不同。读懂一个就读懂三个。

### 1. `sk_random_level()`：抛硬币决定层数

```c
int sk_random_level(void)
{
    int lvl = 0;
    while ((rand() & 1) == 1) {        /* 50% 再升一层 */
        lvl++;
        if (lvl >= SK_MAX_LEVEL - 1) { /* 封顶：16 层足够放 3 万个节点 */
            break;
        }
    }
    return lvl;
}
```

- 为什么 `& 1` 而不是 `rand() / RAND_MAX * ...`：只要一个均匀比特位，取最低位最省事。
- 为什么必须封顶 `SK_MAX_LEVEL`：不设上限时层数是有限期望的无界变量，个别节点能抽很高；
  封顶之后 `update[]` 才能开在**栈上**（16 个指针 128 字节），不用 malloc 也就不用 free。
- **本项目里 `sk_init(s, seed)` 必须 `srand(seed)`**：README 要贴运行结果、`dump` 的形状要能复现，
  不固定种子就是"每跑一次图都不一样"，这一节的图全废。
- **真实系统为什么可以真随机**：Redis / LevelDB / SkiplistDB 都不固定种子（用时间或随机设备播种）。
  因为跳表的正确性**不依赖**随机数质量，随机只影响性能；而且它们的输入本身已经是乱序的，
  固定种子不会带来任何可复现性好处（日志重放、fuzzing 例外，那种场景恰恰要固定种子）。
  教学演示属于"要复现"的那一类，所以这里必须固定。

### 2. `sk_init()` / `sk_destroy()`：两个哨兵、两次 free

```
  init：head->key = INT_MIN（SK_MAX_LEVEL 格全指向 nil）
        nil ->key = INT_MAX（SK_MAX_LEVEL 格全指向【自己】）
  destroy：沿第 0 层走一遍，每个节点 free(n->forward) 再 free(n)
           最后两个哨兵也各 free 两次
```

★ 这里就是本节最容易漏的一行：**两次 malloc ⇒ 两次 free**。
只 free 节点本体会 100% 泄漏指针数组，ASan 会一条不落地报出来（见 `## 常见的坑` 第 1 条）。

### 3. `sk_insert()`：下降填 `update[]` → 判重 → 造节点 → 抬层 → 逐层改线

```c
/* 阶段一：一次下降，把每层前驱记进 update[]（这就是"查找路径已经给出插入位置"）*/
for (int l = s->level - 1; l >= 0; l--) {
    while (x->forward[l]->key < key) { x = x->forward[l]; }
    update[l] = x;                     /* ★ 停住的位置 = 本层前驱 */
}
/* 阶段二：判重 —— 第一个 >= key 的节点如果正好等于 key，就放弃本次插入 */
/* 阶段三：先 malloc 新节点（失败就一根线都不动）*/
/* 阶段四：新节点比当前最高层还高 → s->level 抬上去，新高层的 update[l] = head */
/* 阶段五：逐层改线，顺序不能反 */
for (int l = 0; l <= level; l++) {
    n->forward[l] = update[l]->forward[l];   /* ① 新节点先牵住右边的后继 */
    update[l]->forward[l] = n;               /* ② 前驱再改口接新节点 */
}
```

- **为什么判重放在造节点之前**：造了节点才发现重复，就得记得把 malloc 回收，最容易写漏。
- **为什么先 ① 后 ②**：②会把 `update[l]->forward[l]` 改掉，先做 ② 就丢了后继地址（新节点接了个 NULL，
  后半条链原地蒸发）。和单链表"断链之前先抄后路"是同一条纪律。
- **阶段四那行 `update[l] = s->head` 不能忘**：新高层从来没人走过，`update[l]` 还是栈上的垃圾值，
  忘填 = 往随机地址写指针。

### 4. `sk_search()` / `sk_remove()`

`sk_search` 的判定发生在最底下：`x` 停在最后一个 `< key` 的位置，所以
`cand = x->forward[0]; hit = (cand != nil && cand->key == key);` ——
**不存在的 key 和存在的 key 走的是完全一样的路径**，区别只在最后一眼。

`sk_remove` 拿到 `update[]` 后逐层判断"我是不是真的插在这个节点前面"：

```c
if (update[l]->forward[l] == victim) {     /* ★ 必须比较指针，不能只比较 key */    update[l]->forward[l] = victim->forward[l];
    unlinked++;
}
/* 最后：free(victim->forward); free(victim);  再收缩 s->level */
while (s->level > 1 && s->head->forward[s->level - 1] == s->nil) { s->level--; }
```

收缩层数为什么必要：不缩的话，删完再插会留下一堆"谁都不住的高层"，每次查找都要白问一句，
最坏能退化成"层数 16、每层只有 HEAD"的固定浪费。

### 5. `sk_dump()`：本节最重要的可视化

一行一层，从最高层打到第 0 层，**空层也照打**（打出来才知道层数收缩到底发生了什么）：

```
  跳表快照：size=17，层数=6（有效层号 0 ~ 5）
    第  5 层 | HEAD ──► 21 ──► NIL   （本层 1 个节点）
    第  4 层 | HEAD ──► 21 ──► NIL   （本层 1 个节点）
    第  3 层 | HEAD ──► 21 ──► 29 ──► NIL   （本层 2 个节点）
    第  2 层 | HEAD ──► 19 ──► 21 ──► 29 ──► NIL   （本层 3 个节点）
    第  1 层 | HEAD ──► 1 ──► 14 ──► 17 ──► 19 ──► 21 ──► 23 ──► 27 ──► 29 ──► NIL   （本层 8 个节点）
    第  0 层 | HEAD ──► 1 ──► 3 ──► 5 ──► ... ──► 31 ──► NIL   （本层 17 个节点）
```

读法：每一行都是**同一条有序链表**（同一个 head 到同一个 nil）；
行与行之间不是不同节点，而是同一批节点的**不同层指针**。第 0 行永远是全部成员，越往上越稀疏、跨度越大。

### 6. `ordlist.c`：为什么本目录自带一条"有序单链表"

对照实验必须**同口径**才可信：`ordlist.c` 里每个节点也带一个 `cmp_count` 计数器，
"看一眼某个节点的 key"在两种结构里都算**一次**比较（包括撞墙那一次）。
所以 `## 复杂度` 里那两张表里的数字，是同一把尺子量出来的。

## 复杂度表

`n` = 表里节点数，`b` = 1/p = 2（抛硬币的倒数）。"期望"指层数随机带来的平均，**不是**"最坏"。

| 操作 | 跳表（期望） | 跳表（最坏） | 有序单链表 | 平衡树（AVL/红黑） |
|---|---|---|---|---|
| 查找 | `O(log n)`，常数 ≈ b·log2 n | `O(n)`（硬币运气极差） | `O(n)`，平均 n/2 | `O(log n)` 严格成立 |
| 插入 | `O(log n)` | `O(n)` | `O(n)`（找位置）| `O(log n)` + 旋转 |
| 删除 | `O(log n)` | `O(n)` | `O(n)` | `O(log n)` + 再平衡 |
| 范围查询 `[lo,hi]` | `O(log n + k)`，k = 命中数 | `O(n + k)` | `O(n)` | `O(log n + k)`，但要多走中序回溯 |
| 空间（每节点） | 期望 **2** 根指针（实测 2.00） | 最坏 `SK_MAX_LEVEL` 根 | 1 根 | 2 根指针 + 颜色/高度 |
| 按下标访问 | `O(n)`（可以加 span 字段改） | `O(n)` | `O(n)` | `O(log n)`（order-stat 版） |

实测锚点（N = 2000，200 次查找平均）：

| 结构 | 平均比较次数 | 理论值 |
|---|---|---|
| 有序单链表 | 1004.00 | N/2 = 1000.5 |
| 跳表 | 23.16 | 2·log2 N ≈ 22 |

★ 报数字要诚实：**log2(2000) ≈ 11 是"层数"，不是"比较次数"**。
每层平均要走 1/p = 2 步，所以正确的期望是 `2·log2 n ≈ 22`。
拿 23.16 去跟 11 比然后说"比理论差一倍"，是没读懂那个 2 从哪来。

3. 解剖 SkNode：forward 是『指针的数组』，不是『数组的指针』
----------------------------------------
  节点定义：
      typedef struct SkNode { int key; struct SkNode **forward; } SkNode;

  sizeof 不会骗人：
      sizeof(SkNode)         = 16 字节   （int 4 + 补白 4 + 指针 8）
      sizeof(one->forward)   = 8 字节   ← forward 本身只是【一个指针】
      sizeof(*one->forward)  = 8 字节   ← 数组里【一个格子】是一个 SkNode*
      所以 forward + 1 只往前走 8 字节 = 一个格子；
      而 forward[l] 拿到的东西类型是 SkNode* —— 一句人话：
      『第 l 层的下一个节点在哪』。

  画出来（one 的 key = 1，它一共 2 层）：
      one ──► ┌───────────┬──────────────┐
              │ key =   1 │ forward ──────┼──┐   ← forward 只是一个指针
              └───────────┴──────────────┘  │
                                            ▼
                    forward 指着的这块内存 = 【指针的数组】
                    长度 = 这个节点的层数 = 最高层号 + 1（一格都不能多）
                    ┌────────────┬────────────┬────────────┐
                    │ forward[0] │ forward[1] │ forward[2] │ …
                    └─────┬──────┴─────┬──────┴─────┬──────┘
                          ▼            ▼            ▼
                   第 0 层后继   第 1 层后继   第 2 层后继  （每个格子里装的是地址）
                    实测值：forward[0]=3  forward[1]=17  

  【对照】什么叫『数组的指针』（本节【不】用这种写法）：
      SkNode *arr[4];   SkNode *(*p)[4] = &arr;
      sizeof(p)   = 8 字节（它自己也是个指针）
      sizeof(*p)  = 32 字节（它指向的是【一整块 4 个指针的数组】）
      p + 1 往前走 32 字节 —— 一步跨过【整块数组】
      one->forward + 1 往前走 8 字节 —— 一步只跨【一个格子】

      ★ 两者取第 l 个元素都能写 forward[l] / (*p)[l]，所以极容易看漏；
        差别全在 sizeof 和 +1 走多远上。看到 ** 先问一句：数组里装的到底是啥？

  ★ 为什么用『指针的数组』，而不是干脆定长 16 格？
    因为层数是抛硬币随机决定的：多数节点 1 层，少数 2 层，极个别 5 层以上。
    定长 = 每个节点都付 128 字节的指针钱，而平均只用 16 字节 → 白扔一倍内存。
    所以 forward 按实际层数现场 malloc。代价必须记住：
    每个节点【两次 malloc】（本体 + 指针数组）→ sk_destroy 里就得【两次 free】，
    少 free 任何一个，ASan 立刻报泄漏。这也是本节最容易写错的一行。

  1) 有序 ≠ 能跳。单链表只有 next，二分要靠 O(1) 随机访问，所以只能 O(n) 一格一格走。
  2) 跳表 = 在部分节点上多挂几层索引；每上一层少一半节点 → 层数 log2(n) → 期望 O(log n)。
  3) forward 是【指针的数组】：forward[l] = 第 l 层后继。层数随机 → 长度随机 → 每节点两次 malloc，也必须两次 free。
  4) 查找每层停住的位置正好是插入位置，所以 insert / search / remove 共用同一段『下降 + update[]』。
  5) 代价：空间期望翻倍、随机化意味着最坏仍是 O(n)、以及『要复现就必须固定 srand 种子』。

## 常见的坑

### 坑 1：只 free 节点，忘了 free 指针数组（本节第一大坑，100% 泄漏）

```c
/* 错 */
while (cur != NULL) { SkNode *nxt = cur->forward[0]; free(cur); cur = nxt; }
/* 对 */
while (cur != s->nil) { SkNode *nxt = cur->forward[0]; free(cur->forward); free(cur); cur = nxt; }
```

漏掉的正是"每个节点两次 malloc 里的第二次"。ASan 报出来长这样（真实踩过的现场）：

```
SUMMARY: AddressSanitizer: 32048 byte(s) leaked in 2003 allocation(s).
```

`2003` ≈ 节点数 + 2 个哨兵 + 1 个数组 —— 一眼就能反推出"漏的是每个节点一份的东西"。

### 坑 2：以为能靠"扫到 NULL"知道 `forward` 有多长（真会越界读）

`forward` 是按实际层数 `malloc` 的，**数组里没有长度、也没有 NULL 结尾**。
所以这样写是越界读，ASan 当场抓住：

```c
/* 错：读第 4 格时，这块内存只有 3 格 */
int slots = 0;
while (n->forward[slots] != NULL) { slots++; }
```

真实报错（本节第一版就是这么写的，然后把这行改回去又复现了一次）：

```
==106547==ERROR: AddressSanitizer: heap-buffer-overflow on address 0x7532db1f6140 ...
READ of size 8 at 0x7532db1f6140 thread T0
    #0 ... in node_layer_count main.c:71
0x7532db1f6140 is located 0 bytes after 16-byte region [0x7532db1f6130,0x7532db1f6140)
allocated by thread T0 here:
    #0 ... in malloc
SUMMARY: AddressSanitizer: heap-buffer-overflow main.c:71 in node_layer_count
```

`0 bytes after 16-byte region` 是这条报错的题眼：那块 16 字节就是"2 格的 forward 数组"，
而代码去读了第 3 格。

正确做法两条，本节都用了：
① `SkipList` 里记一个 `pointer_slots` 账本，插入 `+= level + 1`、删除 `-= 实际摘掉的层数`；
② 要知道某个节点几层，就**逐层走链表去数**（`main.c` 的 `node_layer_count`），而不是去问数组。

★ 顺带记一句：`sk_make_node` 里把每格先 `= NULL` 初始化，是为了 OOM 时能安全回收，
**NULL 不是结束标记** —— 填好后所有格子都非 NULL（要么指节点、要么指 `nil`）。

### 坑 3：`while (x->forward[l]->key < key)` 写成 `<=`

`<` 的含义是"停在最后一个 **严格小于** key 的节点"，也就是前驱。
写成 `<=` 之后，命中时会停在 key 本身，`update[]` 就不再是前驱，插入会插到**自己后面**，
链表顺序当场乱掉（而且只在"key 已存在"时发作，最难查）。

### 坑 4：改线顺序反了

```c
update[l]->forward[l] = n;               /* ✘ 先改前驱 → 后继地址丢了，后半条链蒸发 */
n->forward[l] = update[l]->forward[l];
```

和单链表"断链前先抄后路"是同一条纪律：**先接新，再断旧**。

### 坑 5：抬层数时忘了给新层填 `update[l] = head`

`update[]` 是栈上数组，未写过的格子是垃圾值；新高的那几层没有任何节点在上面走过，
不显式填 `head` 就等于"往随机地址接指针"。ASan 会报，但不报的时候更可怕（偶尔正常）。

### 坑 6：删除时只比 key 不比指针

```c
if (update[l]->forward[l]->key == victim->key)   /* ✘ */
if (update[l]->forward[l] == victim)             /* ✔ */
```

`allow_dup` 打开时（反例二）表里可能有多个同 key 节点，只比 key 会**跨节点拆线**：
把别的节点的层给摘掉了，自己的层还留着 —— 结构立刻不可用。

### 坑 7：不收缩 `s->level`

删空最高层后不退层，查找就要年年空层白问一句；反复"灌满再清空"能稳定退化出一个固定开销。
本节实测：删空后 `层数 = 1`，`dump` 里只剩 `HEAD ──► (空) ──► NIL` 一行。

### 坑 8：以为"随机分层"会破坏正确性

不会。**任何**层数分配都是正确的，均匀分布只影响性能：
反例一（全 0 层）就是一张"完全正确的跳表"，它只是退化成了一条链表 ——
结果全对，只是慢。这句话是理解跳表和 AVL/红黑树最大差别的关键：
**平衡树的结构约束是"正确性要求"，跳表的结构约束只是"性能建议"。**

## 跳表 vs 平衡树：什么时候用哪个

| | 跳表 | AVL / 红黑树 |
|---|---|---|
| 实现难度 | 插入/删除各 ~20 行，**没有旋转** | 四种旋转 + 再平衡，几百行且极易写错 |
| 复杂度保证 | 期望 O(log n)，**最坏 O(n)**（概率极小） | 最坏 O(log n) 严格成立（AVL） |
| 范围查询 | 天生就是"顺着第 0 层走"，`O(log n + k)` | 要中序遍历 + 栈/父指针回溯 |
| 并发 | 只需锁住局部几根指针，**无锁跳表好写**（跳表是内存数据库常见选择） | 旋转会同时改多个节点的父子关系，锁粒度极难设计 |
| 缓存 | 指针跳跃，但节点是普通 malloc，可做 slab 优化 | 连续数组版堆/树缓存更友好 |
| 空间 | 期望每节点 2 根指针（实测 2.00），**每节点两次 malloc** | 2 根指针 + 高度/颜色，一次 malloc |
| 按下标访问 | 不支持（可加 `span` 字段） | 支持（order-statistic） |

选跳表的信号：要**好写 + 好维护 + 范围查询多 + 可能要做并发**。
选平衡树的信号：要**最坏情况保证**（硬实时）、要**按下标/排名访问**、内存极紧（不接受随机化的空间开销）。

## 自检问题

1. **为什么有序单链表即使"提前刹车"也还是 O(n)？**
   答：刹车省的是常数（查不到时少走一半），不改变"平均要看 n/2 个节点"这件事。
   二分的本质是 O(1) 随机访问，链表只有 `next`，给不了；跳表用"预先挂好索引"把这个能力补回来。

2. **`struct SkNode **forward` 到底是谁的数组？`forward + 1` 和 `p + 1`（`SkNode *(*p)[4]`）分别走多少字节？**
   答：`forward` 是 **`SkNode *`（指针）的数组**，`forward + 1` 走 8 字节 = 一个格子；
   `p` 是**数组的指针**，`p + 1` 走 32 字节 = 整块 4 个指针。取元素写法相同，`sizeof` 和步长完全不同。

3. **为什么 `insert` 不需要"再找一遍位置"？`update[]` 是怎么白送给你的？**
   答：每层的下降都停在"本层最后一个 < key 的节点"，这就是本层前驱，正好是插入要改的那根线。
   一次下降同时给出 0..level 层的全部前驱，所以 insert/search/remove 共用同一段代码。

4. **为什么 `sk_random_level()` 要封顶 `SK_MAX_LEVEL`？不封会怎样？**
   答：不封顶时层数是几何分布，期望有限但无上界，个别节点能抽到很高；
   `update[]` 就没法开在栈上（不知道要多大），只能 malloc，且最坏路径长度不可控。
   封顶 16 之后 3 万个节点几乎碰不到顶，代码还更简单。

5. **为什么这个教学实现必须 `srand(固定种子)`，而 Redis 不需要？**
   答：这里要贴运行结果、要让 `dump` 的形状可复现，不固定种子图就对不上，教学价值直接归零。
   Redis 的输入本来就乱序、也不需要重放，跳表的**正确性不依赖随机数**（随机只影响性能），
   所以真随机更安全（避免构造输入让查找退化）。

6. **`sk_destroy` 里为什么每个节点要 free 两次？少一次会怎样？**
   答：因为每个节点 malloc 了两次（本体 + `forward` 数组）。少 free 数组就是稳定泄漏 n 块内存，
   ASan 报 `leaked in <节点数+若干> allocation(s)`。

7. **有办法从 `forward` 指针本身读出它有几个格子吗？**
   答：不能。数组不带长度、也不以 NULL 结尾，多读一格就是 heap-buffer-overflow。
   长度只能由外层记账（本节的 `pointer_slots`）或"逐层走链表去数"。

8. **跳表的最坏情况是 O(n)，这算 bug 吗？**
   答：不算，是随机化的代价。层数全抽 0 的跳表就是一条链表，结果依然正确，只是慢。
   反例一（`--bug=flat`）就是故意把这个"合法但退化"的状态钉出来给你看：平均比较 1004.00 次，
和"理论 N/2 = 1000.00"几乎重合 —— 它就是一条更占内存的链表。
