# 循环单链表 circular singly linked list（+ 约瑟夫环实战）

> 上一节 `02-linked-list/singly` 的链表走到尽头会写一个 `NULL`。
> 本节把那个 `NULL` 换成"回头指向第一个节点"，**只改一根线**，
> 却逼出一整套新规则：终止条件要换、判空要自己写、只存 tail 反而更快。
> 最后用约瑟夫环和轮转发牌两个应用，说明什么问题"天生就该用环来解"。

---

## 一句话是什么

节点定义和单链表**一个字都没改**：一个 `int` + 一张写着下一个节点地址的 `next` 纸条。
唯一的区别是**最后一张纸条上写的不是 NULL，而是第一个节点的地址** —— 一串盒子被接成一个圈。

```c
typedef struct Node {
    int val;
    struct Node *next;   /* 最后一个节点的 next 指向第一个节点，不指向 NULL */
} Node;
```

于是本节多了一条要刻在脑子里的规矩：

> **环里没有终点站。** 想停下来，只能自己认出"我已经走回出发点了"。

而"从哪儿出发"在环里纯粹是约定 —— 这就是为什么本节把入口设成 `tail`（尾巴）而不是 `head`：

```c
typedef struct {
    Node *tail;   /* 只存尾巴。head = tail->next，一步就到，不必单独存 */
    int   size;   /* 节点个数，增删时同步维护 */
} CList;
```

---

## 为什么需要它

先看它比单链表**多**了什么、又**少**了什么，别把两节混为一谈：

| | 单链表 `02-linked-list/singly` | 循环单链表（本节） |
|---|---|---|
| 最后一个节点的 `next` | `NULL` | 第一个节点的地址 |
| 遍历终止条件 | `p != NULL` | `p != head`（且必须 `do-while`） |
| 空表标志 | `head == NULL` | `tail == NULL` |
| 头插 | O(1)，但要**改 head 变量**（所以传 `Node **`） | O(1)，只改 `tail->next` 一根线，**连把手都不用换** |
| 尾插 | O(n) —— 每次都要从头走到尾 | **O(1)** —— tail 就在手里 |
| 求长度 | O(n) 现走 | O(1)（记 `size` 账本） |
| 删头节点 | 要特判"头没有前驱" | 不用特判：`tail` 天生就是 head 的前驱 |
| 从中间某个节点出发遍历全表 | 走到 NULL 就断了 | 天然能绕回自己 |
| 少写判空会怎样 | 通常立刻段错误（NULL 帮你兜底） | **不兜底**：要么死循环，要么自己撞 NULL 才崩 |
| 结构体的字段 | 一个 `Node *head` | `tail` + `size` |

一句话：**接一根"尾巴指回头"的线，买到的是"头尾对称"和"能绕圈"；代价是所有 `!= NULL` 的循环条件全部作废。**

真实需求场景：

| 场景 | 为什么非环不可 |
|---|---|
| 约瑟夫环、"围一圈"的模拟题 | 数到末尾要接回开头，数组得写 `% n`，环上走一根 `next` 就完了 |
| 时间片轮转（RR）调度 | 就绪队列排成环，`current = current->next` 就是"轮到下一个人"，不用判断"是不是队尾" |
| 音乐列表循环播放 / 轮播图 | 播完最后一首回到第一首，这个"回到"是结构自带的，不是 if 写出来的 |
| 频繁两头插入的缓冲 | 只存 tail 就能头插尾插都 O(1)，比单链表少一趟遍历 |
| 从**任意一个**节点出发要看到全部数据 | 链表一旦成环，任何节点都是合法入口 |

反过来，**别用**它的场合：需要在尾巴后面"接一段新链"（环里没有 NULL 出口，得先拆环）、
需要"这就是末尾"的语义（文件结束、字符串结束都得靠 NULL），以及只读数组能搞定的小数据。

## 图解（ASCII）

### 图 1：整节的所有变化，就是多这一根箭头

```
单链表：   head ──► [1|●] ──► [2|●] ──► [3|∅]
                                    ▲
                                    └── ∅ 就是 NULL：终点站，遍历到此为止


循环单链表：      [1|●] ──► [2|●] ──► [3|●] ──┐
                  ▲                            │
                  └────────────────────────────┘   ★ 就多这根箭头

        整条链里【一个 NULL 都没有】，从任何节点出发都能走回自己。
```

### 图 2：为什么"只存 tail"比"只存 head"划算

```
              head（结构体里没有这个字段，它是算出来的）
                │
                ▼
           ┌────────┐      ┌────────┐      ┌────────┐
     ┌────►│  1 │ next┼────►│  2 │ next┼────►│  3 │ next┼──┐
     │     └────────┘      └────────┘      └────────┘    │
     │                                                   │
     └───────────────────  tail ──────────────────────────┘
                            （尾巴牵回头，一圈闭合）

   head      = tail->next            零步到达 → 存它是浪费
   head 的前驱 = tail                白捡（单链表想拿头的前驱必须造 dummy 或特判）
   尾插       = 接在 tail 后面        O(1)
   头插       = 只改 tail->next 一根线 O(1)，而且 tail 一动不动

   ⚠ 只存 head 的版本：头插 O(1)、尾插 O(n) —— 每次都要从头走到尾才找到"插到哪"。
     这就是单链表那一节的痛；这里换个把手就治好了。
```

### 图 3：尾插的三步（顺序绝不能乱）

```
   插之前（tail = 3，3 的 next 指回 1）：      [1] ──► [2] ──► [3] ──┐
                                                 ▲                    │
                                                 └────────────────────┘

   ① n->next = tail->next   新节点先牵住老 head
   ② tail->next = n         老尾巴改指新节点
   ③ tail = n               把手挪到新节点

   插之后（插 9）：          [1] ──► [2] ──► [3] ──► [9] ──┐
                             ▲                               │
                             └───────────────────────────────┘

   ★ ①必须在前、②在后：一旦先写 tail->next = n，老 head（1）的地址就被覆盖丢了，
     [1][2] 那一串全体失联 —— pointer-basics 那条"覆盖之前先抄旧值"在这里照样管用。
```

### 图 4：头插 —— 只改一根线，连把手都不用换

```
   之前：  [1] ──► [2] ──► [3] ──┐        tail 停在 3
           ▲                      │
           └──────────────────────┘

   ① n->next = tail->next（新节点 9 牵住老 head 1）
   ② tail->next = n（尾巴的 next 换成 9 → 9 成为新的第一个）
   ③ tail 不动，size++

   之后：  [9] ──► [1] ──► [2] ──► [3] ──┐   ← 从 tail->next 重新数一圈
           ▲                              │
           └──────────────────────────────┘
             ↑ 新 head = 9，tail 还是 3

   这就是"只维护 tail 就能两头 O(1)"的真相：
   在环里，【插到最后一个的后面】和【插到第一个的前面】是同一个动作。
```

### 图 5：遍历终止条件的分水岭（本节最大考点）

```
   单链表的写法（搬到循环表上 = 死循环）：
       for (p = head; p != NULL; p = p->next)      ← p 永远碰不到 NULL，条件永真

   循环表的写法：
       p = head;
       do {
           用 p;                                    ← 起点必须被处理一次 → 只能 do-while
           p = p->next;
       } while (p != head);                         ← 比的是【地址】：走回出发点 = 全看过了

   终止条件的三种"事故写法"和后果：
   ┌────────────────────────────┬──────────────────────────────────┐
   │ while (p != NULL)          │ 死循环，CPU 100%，日志不刷        │
   │ while (p != head)（非 do） │ 一次都不进，整条表一个节点都没看    │
   │ 先 p = p->next 再处理 p    │ 起点被跳过、绕一圈多看一次起点      │
   └────────────────────────────┴──────────────────────────────────┘
   main.c 的 --bug 开关把前两种现场跑出来（受控，默认运行不碰）。
```

### 图 6：删除 —— 要改的还是"前驱"那根线（单链表的痛一点没减轻）

```
   prev      cur
    │         │
    ▼         ▼
   [1] ──► [2] ──► [3] ──► [4] ──┐
    ▲                             │
    └─────────────────────────────┘        （tail = 4，所以 head = 1 的前驱就是 4）

   prev->next = cur->next;   free(cur);   size--;

   四种局面（从 tail 起步走一趟，prev 永远停在 cur 前面）：
     A 删头 1   ：prev = 4 → 4 的 next 改成 2；tail 不动（head 是算出来的，没有变量要改）
     B 删中 3   ：prev = 2 → 2 的 next 改成 4；tail 不动
     C 删尾 4   ：prev = 3 → 3 的 next 改成 head；★ tail 必须 = prev，否则把手指向已释放内存
     D 删唯一   ：cur == prev → tail = NULL，环解散
   循环表只比单链表省掉一个特判（"头没有前驱"），改线动作一个都不能少。
```

### 图 7：约瑟夫环的一轮 —— 数到 m 的人出圈，把手一转下一轮就开始

```
   n = 7, m = 3。tail 停在"上一个出圈者的前驱"，于是 tail->next 就是本轮起点。

   初始（起点 = 1）：        [1] [2] [3] [4] [5] [6] [7]  围成圈
                             报1 报2 报3★
                 prev = [2]，cur = [3]   →   3 号出圈

        [1] ◄── [7]                      prev->next = cur->next
         │                               （2 直接牵住 4）
         ▼                                tail = prev = 2
   [2] ──► [3] ──► [4]                    ★ 于是 tail->next = 4 = 下一轮起点，
         ▲ 出圈，free                        一行特判都不用写

   剩下： 4 → 5 → 6 → 7 → 1 → 2 →(回到 4)，第 2 轮从 4 开始报数……

   ★ 循环表的红利：m 比剩下的人还大也不用处理（走过头自然绕回来）。
     数组版必须算 (pos + m - 1) % size；这里只有一句 cur = cur->next 的循环。
```

## 逐操作拆解

### 0. 贯穿全节的两条心法

1. **pointer-basics 那条铁律不变**：要改调用者手里的东西就传它的地址。
   本节把 `tail`/`size` 打包进 `CList`，所以参数一律 `CList *l`
   （写成 `CList l` 就是改拷贝，外面毫无变化 —— 和 `swap_by_value` 一模一样的错）。
2. **新增的那条**：环里没有 NULL 帮你兜底。
   单链表里"走到 NULL 就停""NULL 表示没有下一个"这些免费的好事全部消失，
   判空、终止、"有没有下一个"都得自己写。写漏的后果不是崩，而是**卡死**。

### 1. `clist_make_node` / `clist_init`

- 造节点和单链表完全一样：`malloc` → 判空 → 填 `val` → **`next = NULL`**。
  新节点还没接线，`NULL` 是"我暂时不属于任何环"的记号，挂进去时由接线函数改写。
- 空表状态：`tail = NULL, size = 0`。**"空"是唯一的、没有环可看的状态**，只能靠 `tail == NULL` 表示。
  这决定了每个函数的第一动作：想清楚 `tail` 是 `NULL` 时我这行会不会解引用它。

### 2. `clist_head`：head 是算出来的

```c
return (l->tail == NULL) ? NULL : l->tail->next;
```

这一行判空就是全节"空表安全"的总闸门：别的函数全都调它拿起点，所以谁都不会在空表上崩。
反面教材 `clist_head_val_unguarded()` 把这次判空省掉了 —— `--bug` 里 fork 出去让它真崩一次给你看。

### 3. `clist_push_back`：尾插 O(1)

- 空表：`tail = n; n->next = n;` —— **自己牵自己**，环的最小形态（单链表在这里只能写 `next = NULL`）。
- 非空：三步 ①`n->next = tail->next` ②`tail->next = n` ③`tail = n`，见图 3。
- 边界：`malloc` 失败直接返回 0，**不动**任何字段，链表保持原样（不能"改一半再失败"）。

### 4. `clist_push_front`：头插 O(1)，而且 tail 不动

- 空表：头插 == 尾插，转调 `clist_push_back` 一次搞定，不复制粘贴第二套代码。
- 非空：①`n->next = tail->next` ②`tail->next = n`，`tail` 一个字都不改 ——
  因为**尾巴还是那条尾巴**，只是它的下一个换了人（见图 4）。
- 对比单链表：那边头插要改 `head` 变量本身，所以必须传 `Node **head`；这里连把手都没换。

### 5. `clist_find`：按值查找，`do-while` + `p != head`

- 起点先取 `head = clist_head(l)`，为空直接返回 `NULL`。
- 循环体先看当前节点，再挪指针，条件 `p != head` —— **绕回出发点说明全部看过了**。
- 为什么必须 `do-while`：写成 `while (p != head)`，一开始 `p == head` 条件即假，一次都不进，
  整条表一个节点都没查 —— 这比终止条件写错还隐蔽。
- 找不到返回 `NULL`：这个 `NULL` 是我们造出来的"信号"，链表内部并没有 NULL。

### 6. `clist_size` / `clist_is_empty` / `clist_count_by_walk`：账本与对账

- `size` 是**抄下来的账**，O(1) 回答；`tail` 才是事实。
  所以 `is_empty` 判 `tail == NULL`，不判 `size == 0` —— 拿账本来判断事实，账一旦记错就全线崩盘。
- `tail` 和 `size` 必须**成对维护**，任何增删漏掉一个，就会出现"表是空的但 size=3"这种自相矛盾。
- `clist_count_by_walk` 是故意留的 O(n) 笨办法，用途只有一个：**对账**。
  `main.c` 每幕都打印"账本 vs 现数"，漏记账当场暴露（这类 bug 不崩，只是长度不对，最难查）。

### 7. `clist_remove`：按值删第一个匹配，O(n)

- 老毛病没治：要摘 `cur` 必须改**前驱**的 `next`，所以 `prev`/`cur` 手拉手走一趟。
- 唯一的便宜：**`head` 的前驱就是 `tail`**，所以直接 `prev = tail; cur = head;` 起步，
  不用像单链表那样造 dummy 或特判"删头"。
- 四支代码：`cur == prev`（唯一节点 → `tail = NULL`）、`cur == tail`（→ `tail = prev`）、
  删头（被通用的 `prev->next = cur->next` 天然覆盖）、没找到（返回 0）。
- 找到就 `free(cur); size--; return 1;`。**返回值必须看**：0 表示"根本没删"，别当没事发生。

### 8. `clist_print` / `clist_walk_ring`

- 打印：环里没有"最后一个节点"，所以打完结尾补一句 `-> (回到 1，绕成一圈)`，
  把"这根线去了哪"明确画出来，免得读者以为是断链。
- `clist_walk_ring(l, 2*n)`：从 **tail** 出发无脑走 2n 步，逐行标出哪一步是 tail、哪一步"绕回到 head"。
  这是全节唯一"许可不设终止条件"的函数 —— 因为它要演示的就是"没有终点"。

### 9. `clist_free`

```c
do { nxt = cur->next; free(cur); cur = nxt; } while (cur != head);
l->tail = NULL;  l->size = 0;
```

- 和单链表只差循环条件；**先抄 `nxt` 再 `free`** 这条铁律一个字不能改。
- 收尾必须把 `tail` 置 `NULL`、`size` 归零，否则调用者手里留着指向已释放节点的把手 → use-after-free。
- 循环条件里那个 `head` 指向的节点早就被 free 了，为什么安全？
  因为只比较**地址数值**，没有解引用；ASan 管读写，不管比大小。

### 10. 应用 A：约瑟夫环 `clist_josephus(n, m, out, cap)`

- 建圈：`1..n` 依次尾插，`tail = n`、`head = 1`。
- 每轮：`cur` 从 head 走 `m-1` 步就是"数到 m 的人"，`prev` 一路带着（单链表的老规矩）；
  起点 `prev = tail` —— 白捡的一环。
- 出圈：`prev->next = cur->next; free(cur); size--;`
- **★ 灵魂一句：`ring.tail = prev;`** —— 把手挪到出圈者的前驱，于是 `tail->next`
  正好是"他的下一个人"，下一轮起点自动接上。在环里"谁是头"是约定，**转把手 = 转圈**，零成本。
  （少了这句，每一轮都会从 1 号重新报数 —— 这就是本节实测出来的第一个 bug，见"常见的坑"第 6 条。）
- `m` 大于剩余人数时不用取模、不用特判：`cur = cur->next` 走过头自然绕回来。
- **对拍**：`main.c` 里另写了一份完全独立的数组版（`alive[]` + `(pos + 1) % n`），
  两套思路不同的实现给出同一个顺序，才算真写对。

### 11. 应用 B：轮转发牌 `clist_deal(nplayers, deck, ndeck)`

- 玩家 `1..k` 排成环，游标 `cur = clist_head(&players)`。
- 每发一张牌就 `cur = cur->next;` —— **轮转 = 走一根线**，没有 `(i + 1) % k`，
  也没有"是不是最后一个人"的特判。RR 调度、循环播放同理。
- 为了不把本节拖进动态二维数组，手牌用静态数组 + 上限（8 人 / 16 张）；超上限明确拒绝并说明原因，
  不偷偷截断。

### 12. 两个反面教材（只有 `--bug` 才会调用）

- `clist_count_broken_null(l, cap, &hit_null)`：把单链表的 `p != NULL` 原样搬来数长度，
  内部塞了个"最多走 cap 步"的刹车，所以本进程安全；它会报告"走够步数了，但还是没碰到 NULL"。
- `clist_head_val_unguarded(l)`：省掉判空的 `l->tail->next->val`，空表上必崩。
  `main.c` 用 `fork()` 把它送到子进程去崩，父进程 `waitpid` 收尸并报告死法，
  **整个程序退出码仍是 0、stderr 仍是 0 字节**。

## 复杂度

n = 节点个数。

| 操作 | 循环单链表（本节） | 单链表 | 数组 | 说明 |
|---|---|---|---|---|
| 按下标访问 | O(n) | O(n) | **O(1)** | 链表通病，成环不治这个 |
| 按值查找 | O(n) | O(n) | O(n) | 绕一圈才敢说"没有" |
| 头插 | **O(1)** | O(1)（要改 head 变量） | O(n) | 这里只改一根线，连把手都不动 |
| 尾插 | **O(1)** | ❌ O(n) | O(1)（容量够） | ★ 只存 tail 换来的最大红利 |
| 按值删除 | O(n) | O(n) | O(n) | 找 + 改线，谁都不便宜 |
| 求长度 | **O(1)**（账本） | O(n) | **O(1)** | 记 size 换来的 |
| 判空 | O(1) | O(1) | O(1) | 都是 `== NULL` |
| 换起点（"下一个当队头"） | **O(1)**（转 tail） | O(n)（得改一串指针） | O(1) 改下标 | 约瑟夫/RR 调度的命门 |
| 每个节点额外内存 | 1 个指针（8 字节） | 同 | 0 | 结构体本身只多 8 字节 |
| 死循环风险 | **有**（终止条件写错） | 无 | 无 | 本节独有的新税 |

## 常见的坑

1. **终止条件忘了从 `p != NULL` 改成 `p != head`。**
   编译不报错、启动不报错，跑起来 CPU 100%、日志一行不刷 —— 是**卡死**不是崩溃，
   所以连 core dump 都没有，最难查的一类。`--bug` 第 9 幕有受控现场。

2. **写成 `while (p != head)` 而不是 `do { ... } while (p != head)`。**
   循环一开始 `p == head`，条件直接为假，一次都不进 —— 整条表一个节点都没看，
   却"看起来很正常"地返回了"没找到 / 长度 0"。这是本节最阴的坑：症状是**结果错**，不是崩。

3. **尾插/头插的三步顺序写反**（先 `tail->next = n` 再 `n->next = tail->next`）。
   第二步读到的已经是新节点自己，老 head 的地址当场丢光，前面一串全体失联。
   症状是**内存泄漏而不是段错误**，只有 ASan 会举报（`Indirect leak`）。

4. **删尾巴节点忘了 `tail = prev`。**
   `free(cur)` 之后 `tail` 还存着那个已经还给系统的地址 —— 下一次 `clist_head()` 就是
   `tail->next`，即读已释放内存。ASan 会报 `heap-use-after-free`，当场抓住。

5. **唯一节点那种局面没特判。**
   `cur == prev` 时必须 `tail = NULL`（整个环解散）；
   如果照通用逻辑写 `prev->next = cur->next`，等于在**马上要被 free 的节点**身上改线 —— 白改，
   而且 `tail` 还留着，表就"看起来有一个节点但其实已释放"。

6. **约瑟夫环忘了转把手 `ring.tail = prev`。（本节实测踩到的第一个 bug）**
   少了这一句，环不会崩、`size` 也对，但**每一轮都从"当前的 tail->next"开始报数**，
   而 tail 从没挪过 → 永远从 1 号开始数，出圈顺序变成 `3 4 5 6 7 1 2`（错）。
   正确顺序是 `3 6 2 7 5 1 4`。这类"逻辑漏一句、结果静悄悄错"的 bug，
   唯一省心的抓法是**对拍**：本页第 10 小节里那份独立的数组版实现（`(pos+1) % n` 那套）
   和链表版思路完全不同，两者一比对，错了立刻显形。

7. **`size` 和 `tail` 没有成对维护。**
   任何一条 return 路径少写一句 `size++` / `size--`，账本从此撒谎，
   但程序不崩、只是"长度不对"。防法：`clist_count_by_walk()` 这个 O(n) 笨函数**永久留在代码里**，
   测试时把它和 `clist_size()` 并排打印对账（本页"逐操作拆解 6"说的就是这件事）。

8. **在环上想"接到末尾后面""倒着走""取最后 k 个"。**
   环没有出口：想接一段新链，得先 `拆环 → 接线 → 重新成环`；想倒着走，循环**单**链表做不到
   （节点不知道前驱），那是下一节 `circular-doubly` 的活。硬在单环上写反向遍历，
   只会写成"绕一圈找前驱"的 O(n²)。

9. **`clist_free` 之后忘记把手复位 / 再拿旧 `tail` 去 print。**
   `free` 完必须 `tail = NULL; size = 0;`，误用会当场段错误；不置 NULL 就是悬空把手，
   某天诡异崩。顺带：置 NULL 后重复调 `clist_free` 完全安全。

10. **（`--bug` 里的额外一课）`fork()` 之前不 `fflush(stdout)`。**
    子进程会连"父进程已经写进 stdio 缓冲区但还没落盘的文字"一起继承，然后原样再打一遍，
    屏幕上出现重复段落。终端下看不出（行缓冲），一旦把输出重定向到文件（全缓冲）就现形。

## 自检问题

1. **为什么结构体里只存 `tail`，不存 `head`？两个都存不行吗？**
   答：`head` 永远等于 `tail->next`，零步可得，存它就是**多养一份要对账的账**
   （历史上真有 head/tail 不同步导致的 bug）。只存 tail 换来的是：头插 O(1)、尾插 O(1)、
   以及"head 的前驱"免费（就是 tail）。只存 head 的版本尾插必须走一整趟，那就是单链表。

2. **循环表遍历为什么必须 `do-while`？**
   答：起点自己也是要被处理的一个节点。`while (p != head)` 一开始条件就是假，一次都不进。
   `do-while` 保证"先看当前、再挪指针、最后判断有没有绕回来"，正好一圈，不多不少。

3. **只有一个节点时 `tail->next` 是什么？删它需要改几根线？**
   答：`tail->next == tail`（自己牵自己）。删它**一根线都不用改**，直接把 `tail = NULL`、
   `size--`，再 `free` 掉那个节点 —— 环整体消失。这就是 `cur == prev` 那一支特判的存在理由。

4. **约瑟夫环里，为什么 `ring.tail = prev;` 一句话就能让下一轮从"出圈者的下一个人"开始？**
   答：因为在这个结构里"本轮起点"的定义就是 `tail->next`。出圈时已经做了 `prev->next = cur->next`，
   所以 `prev->next` 正好是出圈者的下一个人；把手挪到 `prev`，`tail->next` 立刻变成那个人。
   本质是：**环里"谁是头"只是约定，转约定 = 转圈**，一个节点都不用搬。

5. **`while (p != NULL)` 用在循环表上、`do{...}while (p != head)` 用在单链表上，各会怎样？**
   答：前者永远碰不到 NULL → **死循环**。后者在遇到 NULL 时条件仍为真（NULL ≠ head），
   会继续 `p = p->next`，直到 `p == NULL` 之后还进循环体解引用 → **段错误**。
   两种数据结构的两套终止条件**不能互换**，错了要么卡死要么崩，没有"看起来正常"的可能。

6. **你怎么在 30 秒内确认自己没把 `size` 记错？**
   答：调用留着的 O(n) 笨函数 `clist_count_by_walk()`，和 `clist_size()` 并排打印比对。
   一致就说明每条增删路径都记了账；不一致就说明某处 return 前漏了一句 —— 直接定位到那次操作。

7. **循环单链表能 O(1) 删掉"手里已经拿到地址的那个节点"吗？**
   答：不能。你还是得知道它的**前驱**，而节点不记前驱 → 只能从 tail 走一趟 O(n)
   （约瑟夫环里之所以快，是因为报数过程顺手把 `prev` 带在身上了）。
   想要"给定节点 O(1) 删"，就得每个节点多存一根 `prev` —— 见下一节。
