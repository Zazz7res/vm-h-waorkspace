# 非比较排序：计数排序 / 基数排序 / 桶排序

> 一句话定位：不比大小，改看「这个数到底是几」——用值域信息换掉比较次数，把 O(n log n) 的天花板一脚踢开。

## 一句话是什么

三个算法，同一招：**既然元素的值是 int，那就拿值当数组下标用**，让「谁大谁小」这件事由内存布局替你决定，而不是由 `if (a > b)` 决定。

- **计数排序**：开一个 `count[]`，下标代表「值」，`count[v]` 记「v 出现了几次」。数一遍、按号占座写回来，完事。时间 O(n + k)，k 是值域宽度。
- **基数排序**：值域太大 `count[]` 开不出来？那就**一位一位地排**。一位十进制数只有 0..9 十个取值，计数排序只需 10 格。从个位排到最高位，每轮都是一次**稳定**的计数排序。时间 O(d·(n + 10))，d 是位数。
- **桶排序**：数据在值域上**分布均匀**？那就把值域切成 nb 段，每个元素按值直接算出进哪个桶，桶内用小排序（这里用插入排序），最后按桶号倒回数组。平均 O(n)，最坏 O(n²)。

## 为什么需要它

先说清楚「天花板」是什么，不然看不出这三个算法珍贵在哪。

### 比较排序下界 O(n log n) 是怎么来的

只靠「比较两个元素谁大」来排序的算法（插入/归并/快排/堆排），执行过程可以画成一棵**决策树**：

- 每个内部节点是一次比较 `a[i] <= a[j] ?`，两条分支是两种答案；
- 每个叶子是一种最终排列，也就是算法在某种输入下交出的答案。

```
                     [3 1 2]                 ← 根：还没问任何问题
                 /             \
          a0<=a1? 是            否
             /        \           \
        [1 3 2] ...  [3 1 2] ...   ...        ← 第二次比较
         / \           / \
       ...            ...                    ← 叶子 = 一种确定的排列
```

要能正确排序，n 个互不相同的元素有 **n! 种**可能的输入顺序，算法必须每种都能给出正确答案 ⇒

1. 叶子数 ≥ n!；
2. 二叉树深度 h 最多容纳 2^h 个叶子 ⇒ 2^h ≥ n! ⇒ **h ≥ log2(n!)**；
3. 从根到叶的路径长度 = 这条输入上做的比较次数 ⇒ **任何比较排序，存在某组输入要花 ≥ log2(n!) 次比较**。

斯特林公式给个直觉（本仓库 `main.c` 里手算了真实数字，见第 6 幕）：

```
log2(n!) = log2(1) + log2(2) + … + log2(n)  ≈  n·log2(n) − 1.4427·n + O(log n)
```

所以 `O(n log n)` 不是「归并快排写得不够聪明」，是**数学上谁也过不去的墙**。n = 20000 时这道墙实测在 256909 次比较那里立着（下面第 6 幕会把这个数字跑出来）。

### 那这三个算法怎么绕过去的

它们**压根不在决策树里**。它们问的问题不是「谁比谁大」，而是「这个数**是几**」：

- 计数排序：`cnt[a[i] - mn]++` —— 这一行没有比较，是一次**寻址**。值直接当索引用了，等价于「查表」。
- 基数排序：`(work[i] / exp) % 10` —— 取出一位，还是查表，10 个格子够了。
- 桶排序：`idx = (offset * nb) / span` —— 按值算桶号，仍是查表；只有桶**内部**才恢复成比较排序。

代价是它们**多要一个前提**：值域得小（计数）、位数得少（基数）、分布得均匀（桶）。前提不成立，就只能回去老老实实比大小。这句话是本节的核心结论，后面所有演示都在验证它。

## 核心思路图解

### 图 1：计数排序的「下标 = 值」

输入 `[3, 1, 2, 1]`，值域 k = 4（1..3，加上线段 0 也占一格，这里为了看图清楚用 0..3）。

```
        扫一遍数组，逐个数数：
   值:    0    1    2    3
        ┌────┬────┬────┬────┐
 count  │  0 │  2 │  1 │  1 │   ← count[v] = v 出现的次数
        └────┴────┴────┴────┘
           ↑     ↑     ↑    ↑
        没人  1有俩   2一个  3一个

   展开写回：从下标小的开始，出现几次就写几个
   a = [ 1, 1, 2, 3 ]        ← 全程没问过「谁比谁大」
```

### 图 2：负数必须整体平移（第 1 幕的输入）

输入 `[-5, 3, -1, 3, 0, -5, 2, 1]`，`mn = -5, mx = 3, k = mx - mn + 1 = 9`。

```
   直接 cnt[a[i]]++ 会发生什么？
        a[i] = -5  ⇒  cnt[-5]  ⇒  数组下标为负 ⇒ 越界写 ⇒ 程序当场乱掉

   正确做法：下标用「减去最小值之后的值」
        原值   v:  -5  -4  -3  -2  -1   0   1   2   3
        下标 v-mn:  0   1   2   3   4   5   6   7   8
                   ↑                                    ↑
                 cnt[0]=2                            cnt[8]=2

   写回时再加回来： a[idx] = v + mn
```

### 图 3：前缀和 + 从后往前 ⇒ 稳定（这一步值得盯 30 秒）

还是 `[-5, 3, -1, 3, 0, -5, 2, 1]`，重点看两个 `-5`（下标 0 和下标 5）谁排在前面。

```
   ① 计数后求前缀和：cnt[v] = 「值 ≤ (v+mn) 的元素共有几个」= 值 v 这一段的【右边界】
        v(下标):   0   1   2   3   4   5   6   7   8
        计数:      2   0   0   0   1   1   1   1   2
        前缀和:    2   2   2   2   3   4   5   6   8
                            ↑                    ↑
                   「≤ -5 的有 2 个」    「≤ 3 的有 8 个」= 整个数组

   ② 从后往前扫原数组，每个元素放在 --cnt[它的下标] 上：

     i=7  a=1  → key=6, cnt[6]=5 → 占 4 号格，cnt[6]←4
     i=6  a=2  → key=7, cnt[7]=6 → 占 5 号格，cnt[7]←5
     i=5  a=-5 → key=0, cnt[0]=2 → 占 1 号格，cnt[0]←1     ← 后面那个 -5 先拿右边那格
     i=4  a=0  → key=5, cnt[5]=4 → 占 3 号格
     i=3  a=3  → key=8, cnt[8]=8 → 占 7 号格
     i=2  a=-1 → key=4, cnt[4]=3 → 占 2 号格
     i=1  a=3  → key=8, cnt[8]=7 → 占 6 号格
     i=0  a=-5 → key=0, cnt[0]=1 → 占 0 号格               ← 前面那个 -5 拿左边那格

     tmp = [ -5, -5, -1, 0, 1, 2, 3, 3 ]
              ↑i=0 ↑i=5                              ← 两个 -5 的原始顺序保住了 = 稳定
```

**为什么「从后往前」就稳定**：同分的两个元素 x（在前）、y（在后），倒着扫先碰到 y，它拿走这一段的**最后一格**；再碰到 x，拿前一格 ⇒ 排完 x 仍在 y 左边。

**展开版为什么不稳定**（第 2 幕实测：逆序处数 5 vs 0）：它按值分堆，堆里最省事的写法是「边扫边压栈」，而栈后进先出，吐出来时同分的人整个倒过来。

### 图 4：基数排序 LSD —— 每一轮都是「一次稳定计数排序」

输入 `[170, 45, 75, 90, 802, 24, 2, 66]`（`mn = 2`，平移后 `[168 43 73 88 800 22 0 64]`，最大 800 ⇒ 3 位 ⇒ 3 轮）。真实快照（下面第 4 幕的程序输出）：

```
   原始:      [ 168  43  73  88 800  22   0  64 ]      （已平移）

   第 1 轮：按个位（exp=1）   个位 0,0,2,3,3,4,8,8
            → [ 800   0  22  43  73  64 168  88 ]
              ↑ 个位相同的组里，保持原始次序（800 在 0 之前）

   第 2 轮：按十位（exp=10）  十位 0,0,2,4,6,6,7,8
            → [ 800   0  22  43  64 168  73  88 ]
              ↑ 关键！十位相同的 64/168 都是 6 —— 这一轮判定它们「相等」，
                于是【沿用上一轮个位排好的顺序】：64 的个位是 4，168 的个位是 8 ⇒ 64 在前。
                这一轮若不稳定，64/168 就可能互换 ⇒ 全盘报废。

   第 3 轮：按百位（exp=100） 百位 0,0,0,0,0,1,0,8
            → [   0  22  43  64  73  88 168 800 ]
              ↑ 最高位排完 = 最后一个「大决定」落下，低位次序被稳定性一路带到最后 ⇒ 有序

   平移回来： [   2  24  45  66  75  90 170 802 ]
```

**为什么必须从最低位开始**：越重要的位越要**最后**处理。反过来先按百位排，个位那一轮会把百位分好的组完全打散，最后数组只保证「按个位有序」，前面几轮白干。

### 图 5：桶排序的三步（以及它怎么退化）

```
   前提：数据在 [0, 9999] 上均匀分布 ⇒ 切 10 桶，每桶宽 1000

   ① 切桶：idx = (v - mn) * nb / span
        2 → 桶0     1853 → 桶1     3721 → 桶3     9987 → 桶9
   ② 桶内排序（这里用插入排序，因为每桶只有约 200 个，插入排序在这种规模最快）
   ③ 按桶号 0→9 依次倒回数组

   实测每桶大小（第 5 幕真实输出，均匀那组）：
        185 205 196 215 200 174 197 202 197 229     ← 每桶约 n/nb = 200 ⇒ 总比较 101238 次

   退化那组：1990 个数挤在 [0, 99]，再塞 10 个离群值到 9000 以上
     ⇒ 分桶是按【min..max】均分的，max 被离群值顶到 9900 ⇒ 桶宽 990
        1990  0  0  0  0  0  0  0  0 10             ← 0 号桶一个人干了 1990 个元素的插入排序
     ⇒ 比较次数 101238 → 967191，耗时 0.35 ms → 2.55 ms（同一批 n）
     ⇒ 而这批数据交给归并只要 18568 次比较。这就叫「前提不成立就得回去比大小」。
```

## 核心操作逐个拆解

### 1. `counting_sort_expand`：展开版计数

- **干什么**：把数组排成升序，实现最直白，但**不稳定**。
- **一步步**：
  1. `n <= 1` 直接返回 1（第 168 行往下第一句）。
  2. `arr_min_max` 求 `mn/mx`，`k = mx - mn + 1`。
  3. `range_too_big(n, k)` 判值域，超了**打印原因并返回 -1**（不 malloc、不崩溃）。
  4. `calloc(k, sizeof(int))` 开 count[]（`calloc` 自动清零，省一遍 memset）。
  5. 数数：`cnt[(int)((long)a[i] - (long)mn)]++`。
  6. 展开：`for v in 0..k-1: for c in 0..cnt[v]-1: a[idx++] = v + mn`。
  7. `free(cnt)`。
- **边界情况**：
  - 全负数 / 正负混合：靠 `v - mn` 平移，见第 1 幕；
  - `a[i] == INT_MIN` 且 `mn` 存在：必须先转 `long` 再减，否则 `a[i] - mn` 溢出（这是真 bug 温床）；
  - 值域巨大（第 3 幕：n=8 但值域 20 亿）：返回 -1 拒绝，转交基数或快排；
  - 重复值：`cnt[v] = c` 直接把 c 个 v 写回去，值不会丢，但**顺序信息丢了**（不稳定根源）。
- **对应代码行**：`nonsort.c` 第 168–217 行（数数 194–197，展开 207–214）。

### 2. `counting_sort_stable`：前缀和版计数

- **干什么**：同样 O(n+k)，**多保住稳定性**，一点额外代价没花。
- **一步步**：
  1. 前置检查与展开版一致（`n<=1` / 值域拒绝 / 开 `cnt[k]` 和 `tmp[n]`）。
  2. 数数（同前）。
  3. **前缀和**：`for v=1..k-1: cnt[v] += cnt[v-1]` ⇒ `cnt[v]` = 「值 ≤ v+mn 的个数」= 这一段右边界。
  4. **从后往前放人**：`for i=n-1..0: tmp[--cnt[key(a[i])]] = a[i]`。
  5. 拷回 `a`，`free` 两块。
- **边界情况**：
  - `key` 算出来必须是 `int`，但中间量是 `long` ⇒ 显式 `(int)((long)a[i] - (long)mn)`；
  - 前缀和最后 `cnt[k-1]` 必须 == n（可以拿来当自检，本节的 verbose 输出就把整列前缀和打出来了）；
  - `--cnt[...]` 先减后用：不减就用会越界写到自己数组外面。
- **对应代码行**：`nonsort.c` 第 237–298 行（前缀和 268–270，从后往前放人 278–287）。

### 3. `radix_sort_lsd`：基数排序（LSD）

- **干什么**：不卡值域，只卡位数。任意 int 都能排（除了跨度超 `INT_MAX` 的极端情况）。
- **一步步**：
  1. `arr_min_max`，`span = mx - mn`；若 `span > INT_MAX` 打印原因返回 -1。
  2. 开 `work[]`、`tmp[]`，`work[i] = a[i] - mn`（平移成非负）。
  3. `exp = 1` 起循环，一轮 = **按这一位跑一次稳定计数排序**：
     - `cnt[10]` 清零；`cnt[(work[i]/exp)%10]++`；
     - 前缀和；从后往前 `tmp[--cnt[d]] = work[i]`；`work[i] = tmp[i]`；
     - verbose 时打印这一轮之后的**整个数组快照**（第 4 幕的核心教学输出）。
  4. 终止条件 `if (exp > maxw/10) break;` —— 再往上的位全是 0，排了也不变；顺手防住 `exp *= 10` 溢出。
  5. `a[i] = work[i] + mn` 平移回来。
- **边界情况**：
  - 负数：整体平移，见第 4 幕第二组（`[-5, 42, -100, 7, 999]` ⇒ 4 轮）；
  - 全 0 / 全相同：`maxw = 0` ⇒ 只跑 1 轮，仍然正确；
  - 十进制位数怎么数：`num_digits`（第 35 行），别用 `log10`（无 `-lm`，且浮点边界不稳）。
- **对应代码行**：`nonsort.c` 第 324–404 行（每轮主体 363–393）。

### 4. `bucket_sort`：桶排序

- **干什么**：均匀分布前提下的分治：切桶 → 桶内插入排序 → 按桶号收集。
- **一步步**：
  1. `arr_min_max`；`calloc(nb, sizeof(Bucket))`。
  2. 分桶：`offset = a[i] - mn; idx = (int)((offset * nb) / span)`，`bucket_push` 进对应桶（内部 `realloc` 翻倍扩容）。
  3. verbose 打印**每桶大小**（退化与否一眼可见）。
  4. 每个桶做插入排序（`st->cmp` 记比较次数，这就是「桶内还在比大小」的证据）。
  5. 按桶 0→nb-1 倒回 `a`，**每个桶的 `v` 都要 `free`**，最后 `free(bs)`。
- **边界情况**：
  - `bucket_count < 1` 兜底为 1（否则除 0 / calloc(0)）；
  - `idx >= nb` 的取整保险；
  - 中途 `bucket_push` 失败：把已分配的桶逐个 `free` 再返回 0（ASan 盯这条路径）；
  - `span` 用 `long`，`(offset * nb)` 也可能爆 int ⇒ 全程 `long` 中间量。
- **对应代码行**：`nonsort.c` 第 448–532 行（分桶 472–483，桶内排序 499–519，收集与释放 520–531）。

### 5. 三个朴素验货函数（本节所有「正确性：通过」都靠它们）

- `is_sorted_ascending`：逐对检查 `a[i] <= a[i+1]` ⇒ 「排完确实升序」。
- `same_elements(a, expect, n)`：和**手写的期望数组**逐个比 ⇒ 「结果必须等于标准答案」。
- `same_multiset(a, b, n)`：开一个小计数表把两边按值数一遍再对齐 ⇒ 「排序没把元素弄丢/弄多」，不依赖任何被测算法自己。
- 交叉对拍：`merge_sort_ref` / `insertion_sort_ref`（第 681 / 697 行，各自带比较计数）——同一批数据四个算法两两结果必须逐个相同。

|---|---|---|---|---|---|
| 计数·展开版 | O(n+k) / O(n+k) / O(n+k) | O(k) | **否** | k 与 n 同量级 | **0** |

| 桶排序 | 平均 O(n) / 平均 O(n) / **最坏 O(n²)** | O(n + nb) | 取决于桶内排序 | **数据均匀分布** | 416759（桶内插入排序） |

| 插入（参照） | O(n) / O(n²) / O(n²) | O(1) | 是 | 无 | 100690443 |

## 常见的坑

1. **忘了减最小值，直接 `cnt[a[i]]++`**。遇到负数就是写负下标，越界；遇到 `INT_MAX` 就是申请天文数字内存。正确写法 `cnt[(a[i] - mn)]++`，并且 `mn` 必须真的扫出来（不能假设是 0）。

2. **`a[i] - mn` 在 int 里算 ⇒ 溢出**。`a[i] = INT_MAX, mn = -1` ⇒ `a[i] - mn` 溢出为负数，写 count[] 越界。必须先升 `long`：`(long)a[i] - (long)mn`。基数排序同理，`mx - mn` 超 `INT_MAX` 时**平移本身就错了**，代码里直接拒绝（第 3 幕数据 B 就撞在这）。

3. **把计数排序的展开版当成稳定版用**。展开版写回的是「值」，同分元素的原次序在 `cnt[v]++` 那一刻就已经**永久丢失**；想用稳定就得写前缀和 + 从后往前，而且要像第 2 幕那样带 tag 实测一遍（逆序处数 5 vs 0），别凭感觉。

4. **基数排序从最高位开始排（当成 MSD 写了 LSD）**。跑出来「看起来有序了一部分」，实际完全错。判据很简单：LSD 必须**排完最高位就结束**；如果你最后处理的是个位，结果一定是错的。

5. **基数某轮的子排序不稳定**（比如图省事用了快排或展开版计数）。这一轮把上一轮的成果打散，症状是「大方向对了、同高位的小位次序乱了」。所以子排序**只能**是前缀和计数（或稳定归并）。

6. **桶排序按「桶数 = 元素数」盲目套**，或者忘了 `idx` 可能等于 `nb`（`offset == span` 时取整越界）。更隐蔽的是**分布假设根本没人验证**：真实业务数据（成绩、年龄、价格）几乎都是挤在一起或有离群值的，一个离群值就能把桶宽拉大到全部落一进桶。上线前先打一次「每桶大小」（本目录 verbose 就打了），不均匀就别用。

7. **`O(n+k)` 里的 k 被当成常数**。n = 10 万、k = 42 亿时 k/n = 4 万倍，算法直接不可用；k = 100 万时 16 字节/格变 4 MB 计数数组，缓存命中率暴跌。第 6 幕的 k-影响表就是让这条曲线被你亲眼看见。

8. **动态桶 / 临时数组忘了 `free`**。`bucket_sort` 里两层释放（每桶 `bs[b].v` + 桶数组 `bs`）少一个就是泄漏；本目录的 ASan 干净退出就是这条的验收证据。

## 什么时候用它 / 什么时候别用

**该用：**

- **值域明显小于等于 n 的整数**：成绩 0..100、年龄 0..150、字符 ASCII/UTF-8 单字节、日期分量的年月日、颜色通道 0..255 ⇒ 计数排序，O(n+k)，快到不像话。
- **整数但值域很宽、位数很少**：`int` 最大 10 位十进制 ⇒ 基数排序 O(10·(n+10))，跟 n 线性，且不惧分布。手机号、身份证号、定长编码这类特别适合。
- **浮点/时间在 [min, max] 上确实均匀**：直方图预处理、外部排序的分桶阶段、按时间戳分段 ⇒ 桶排序能把总代价压到接近 O(n)（桶内用小排序）。
- **要做「按值分组统计」的副产品**：计数排序顺手就把频次表建好了，别的排序做不到。

**别用：**

- **值域是完整 32 位整数且 n 不大**：16 GB 的教训（第 3 幕），直接快排/归并。
- **元素不是 int，或没法把值映射成小整数下标**：本仓库约定不用 `void*`，一旦需要「自定义类型 + 比较器」，正确选择是把键**编码成 int**（比如按字典序排名），编不出来就别硬上。
- **要稳定且值域宽**：用归并或基数（前缀和版计数也行，前提是 k 小）。
- **数据分布未知或有离群值**：桶排序最坏 O(n²)，快排/introsort 更稳。第 5 幕那 10 个离群值就是「未知分布的代价」的实物证据。
- **n 很小**（几十到几百）：这些算法的常数（清 count[]、开桶、逐轮拷贝）比插入排序的 O(n²) 还贵。小数组永远是插入排序的天下（见 `../comparison-basic/`）。

## 自检问题

**Q1：为什么比较排序逃不出 O(n log n)，而计数排序可以？它到底「省」掉了什么？**

A：比较排序的信息来源只有「a 和 b 谁大」这一种二元答案，n 个元素有 n! 种排列，所以决策树至少 n! 个叶子，树高 ≥ log2(n!) ≈ n log n。计数排序的信息来源是「a 的值是几」——一次内存寻址就拿到了**log2(k) 比特**的信息（不是 1 比特），相当于把「比大小」换成了「查表」，所以下界管不到它。代价是多花 O(k) 空间和时间。

**Q2：计数排序的两个版本，哪一行决定了稳定与否？为什么？**

A：前缀和版那一行 `tmp[--cnt[key]] = a[i]` 配合**从后往前**的循环方向。展开版是「按值吐出 c 个 v」，v 对应的原始元素是谁、谁在前，在 `cnt[v]++` 时已经丢光了。差别就在这里：前缀和版把每个元素**单独定位**到它该占的那一格，而同分段的格子是按「后来者拿右边」分配的，于是原始次序被保住。

**Q3：基数排序为什么必须「从低位到高位」且「每一轮都稳定」？两个条件少一个会怎样？**

A：结论是——少排完个位先百位：个位那一轮会把百位分好的组彻底打散，最终数组只保证按个位有序；某轮不稳定：该轮判定「相等」的那些元素（同一位相同）顺序随机化，而这些元素的整体次序恰恰完全依赖上一轮的成果，于是高位相同、低位乱序。第 4 幕的输出可以逐轮对上：第 2 轮里 64 和 168 十位都是 6，靠第 1 轮个位给出的 4 < 8 才定下前后。

**Q4：桶排序的每桶大小为什么要打出来？看到什么就该放弃桶排序？**

A：桶排序的全部优势都建立在「每桶约 n/nb 个」这一个期望上。每桶大小是**这个假设的体检报告**。看到某一桶的 size 接近 n（本目录退化例子是 1990/2000），说明数据挤在一起或被离群值拉平了，总代价直接退化成那个大桶的 O(m²)；第 5 幕实测比较次数从 10 万涨到 96 万、耗时 0.35 → 2.55 ms，而同批数据归并只用 18568 次比较。这时改快排/归并，或先做分位数切桶。

**Q5：三个算法各自「多要」的前提是什么？用一句话分别说。**

A：计数——值域 k 得跟 n 同量级（否则 16 GB 那课）；基数——位数 d 得小，且 `mx - mn ≤ INT_MAX`（否则平移自己就溢出）；桶——数据在值域上得**真的均匀**（否则一个离群值毁掉全部）。非比较排序不是「更高级」，是「多要一个前提」，前提不成立就得回去比大小。
