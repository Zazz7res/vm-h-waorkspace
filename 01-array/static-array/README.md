# 静态数组 static-array —— 顺序表：后面所有结构的地基

> `01-array` 的第一节，整个仓库第一种「数据结构」。它一个 malloc 都没有，
> 却把后面每一节都要用的三件事一次讲清：**连续内存为什么能 O(1)**、
> **长度信息为什么一进函数就丢**、**插入删除为什么要挪格子**。

---

## 一句话是什么

静态数组就是**编译期把格子数量写死的一排连号内存**。`int a[5];` 这一行，编译器当场决定
「在栈上圈 20 字节、连号、一次到位」，运行时没有任何商量余地，想变 6 格只能改源码重编译。
给这排格子配一个 `length` 字段记账，就是教科书里的**顺序表**（本节全程零 `malloc`、零 `free`）：

```
data[]  = 房子有几间（编译期定死，SARRAY_CAPACITY = 8）
length  = 现在住了几个人（运行时可变，合法范围 0..8）
```

---

## 为什么需要它（不用它会怎样）

**「连续」买到的东西：按下标 O(1)。** `a[i]` 不是「从 0 号一家一家问过去」，而是
一次乘法算出来的地址 `首地址 + i*sizeof(int)` —— 内存地图那几行输出就是它的实证。链表做不到
（要一个个 `->next` 跳），树做不到（要往下走）。只要需要「按位置随机访问」，就必须有连续内存。

**它买不到的东西，本节同样演给你看：** ① 不能变大 —— 装满 8 个再插只能失败（第 8 幕实测），
这是下一节动态数组存在的全部理由；② 中间插入/删除要挪整排格子，平均 `n/2` 次；
③ 语言不查越界，`a[i]` 只有「算地址 → 照办」两步，没有第三步「i 超没超」（数组变量本身不存长度，
每次访问补边界比较又要收你的钱），于是 `a[100]` 静悄悄读走隔壁内存 = 未定义行为；
④ 长度信息只在数组出生的地方存在，一当参数就退化成指针，`sizeof` 立刻作废。

**「不用它」会怎样：整个仓库塌掉。** 后面的结构全是「这一节 + 一点改动」：

| 后面的章节 | 它其实就在这节基础上加了什么 |
|---|---|
| `01-array/dynamic-array` | 格子换成堆内存 + 一个 `capacity` 记账，于是能变大 |
| `03-stack/array-stack`、`04-queue/*` | 数组 + 只许尾部增删 / 头尾两个下标环着走 |
| `06-heap/binary-heap`、`07-graph/adjacency-matrix` | 数组 + 父子下标关系 / 二维数组 |
| `10-sorting`、`11-searching` | 排序和二分的前提就是「O(1) 访问任意下标」 |

## 图解（ASCII 图 + 内存/结构布局）

### 1. `int a[5]` 在栈上的摆法（第 1 幕实测）

```
  a 的首地址 = 0x7fff341f54a0      ← 地址每次运行都变，但相邻两格永远差 4
   ┌────────┬────────┬────────┬────────┬────────┐
   │   10   │   20   │   30   │   40   │   50   │
   └────────┴────────┴────────┴────────┴────────┘
  +0        +4       +8       +12      +16        ← 相对首格的字节偏移
  a[0]      a[1]     a[2]     a[3]     a[4]
  *(a+0)    *(a+1)   *(a+2)   *(a+3)   *(a+4)     ← 完全等价的另一套写法

  a[i] 的地址 = a + i*4     ← 一次乘法，没有循环，所以随机访问 O(1)
```

同屏的局部变量 `neighbour` 实测比 `a` 低 64 字节（栈向低地址长），但 C 标准**不保证**局部变量之间的相对顺序；一定保证的只有：**同一个数组内部的格子必须连续**。

### 2. 结构体布局：`sizeof` 恰好 40 字节，一个 malloc 都不用

```
  StaticArray sa （main 的局部变量 → 整个住在栈上，地址 0x7fff341f54e0）
  ┌──────────────────────────────┬─────────┬─────────────┐
  │ int data[8]  （32 字节）      │ int     │ int         │
  │ 内嵌数组，不是指针！          │ length  │ moved_cells │
  └──────────────────────────────┴─────────┴─────────────┘
   ↑ = 0x7fff341f54e0                4 字节     4 字节     = 40 字节，编译期锁死

  &sa == &sa.data[0]  —— C 保证成员按声明顺序排、第一个成员贴紧结构体开头
```

`data` 是**内嵌数组**而不是 `int *data`，这一个决定就定义了「静态」两个字：结构体在哪格子就在哪，
结构体被回收格子跟着被回收 —— 所以 `destroy` 里**故意没有 free**。

### 3. 边界线 `‖`：把「看不见的那条线」画出来

`[  15|  20|  30|  40|  50 ‖ -1000|-1001|-1002]` —— `‖` 左边是元素（`length` 认账），右边是空位：格子还在，
但已经不属于本表。空位里躺的是初始化时故意涂的垃圾（`-(1000+i)`，每格不同）或插入删除剩下的残留值（如 `-1099`）。
「格子总数」和「元素个数」是两个数字，混起来后面 `size` / `capacity` 就永远学不明白。

### 4. 插入：整排右移一格，而且必须倒着搬

```
往 index=1 插 99（length 5 → 6）：从 1 号位起全部右移一格
倒着搬（对） data[5]=data[4] → … → data[2]=data[1]，最后 data[1]=99
┌────┬────┬────┬────┬────┬────┐
│ 15 │ 20 │ 30 │ 40 │ 50 │ 50 │ ← 每读一格，它自己都还没被改过
└────┴────┴────┴────┴────┴────┘
正着搬（错） data[2]=data[1] → data[3]=data[2] → …
┌────┬────┬────┬────┬────┬────┐
│ 15 │ 20 │ 20 │ 20 │ 20 │ 20 │ ← 20 像病毒传染整排，数据毁了
└────┴────┴────┴────┴────┴────┘
删除反过来：目标在源的【左边】，所以必须正着搬（data[i] = data[i+1]）。
口诀：往「不会踩到自己新家」的方向搬。memmove 内部正是按这条规则自己判断该正抄还是倒抄。
```

## 逐个操作拆解（对应 static-array.c 里每个函数）

### `poison_cells`（文件私有）+ `static_array_init` / `static_array_fill` —— 建表与灌初值

填 0 会把「这格没用过」和「这格存着数值 0」混成一件事，所以涂 `-(1000+i)`：每格都不一样，挪到哪都认得出。
`static` 修饰 = 只在本文件可见（相当于私有方法），不写进 `.h` 是为了让菜单保持干净。
init 不申请内存，所以没有「申请失败」这种状态；唯一正经事是 `length = 0` —— 忘了它，后面所有操作都会拿一堆脏格子当「已有元素」处理。
fill 里 `values` 已经是退化后的指针，必须连 `n` 一起传（第 00 节的老规矩）；`n > SARRAY_CAPACITY` 时**整体失败、一个都不写**：
宁可什么都不做，也不留「写一半」的半截状态，否则后面的演示就看不懂了。

### `static_array_destroy(sa)` —— 重点在于「里面没有 free」

这不是偷懒，是静态数组的本质：没有任何一块堆内存归它管，所以没有任何东西需要归还。它只把账面抹平
（`length = 0`、格子涂回垃圾），让「结构体还在但已经没内容」可见。接口故意和动态数组同名套路（`xxx_destroy`），
以后换成动态数组时 `main.c` 结尾一行都不用改。

### `size` / `capacity` / `is_empty` / `is_full` + `get` / `set`

`static_array_capacity(void)` **不需要 sa 参数**：容量是编译期常量，跟「哪一个数组」毫无关系，问谁都是 8；
下一节动态数组的 capacity 就必须传结构体，因为每个数组的容量可以不一样 —— 这一个参数之差，
就是「静态」和「动态」最直观的照面。`get`/`set` 返回 `bool` 表示「这次访问合法吗」，值走输出参数带出来 ——
合法的数组值可能是任何 int（包括 -1、0），没法同时当状态码用，必须把「成不成功」和「值」分两条通道带回。
上界用 `length` 而不是 `SARRAY_CAPACITY`：下标落在 `[length, CAPACITY)` 虽然是合法格子，里面却是垃圾，
当元素读出来一样是 bug，这两层要分得清。这是静态数组**唯一**的自我保护手段 —— 语言不拦，就得函数拦。

### `static_array_find(sa, value)` —— 按值找，O(n)

按下标访问 O(1) 和按值找 O(n) 特别容易被混：下标是「我直接告诉你第几格」，值要「一格一格比对才知道」。
数组只保证连续、不保证有序，所以只能线性扫，命中立刻 return，平均扫一半；找不到返回 `-1` 而不是 `0`，因为 `0` 是合法下标
（若数组已排序就能二分 O(log n)，见 `11-searching/binary-search`）。

### `static_array_insert_at(sa, index, value)` —— memmove 工程写法，O(n)

`index` 允许等于 `length`（插到最末尾），合法范围 `0 <= index <= length`；满容量时返回 `false` ——
静态数组在这里没有退路，不能像动态数组那样「再租一块大的」。核心三行：

```c
memmove(&sa->data[index + 1], &sa->data[index], (size_t)tail_cells * sizeof(int));
sa->data[index] = value;
sa->length++;                 /* 忘了这行是顺序表第一大 bug */
```

- `tail_cells = length - index`：插最前挪 `length` 次、插最后 0 次，平均 `length/2` → O(n)，记进 `moved_cells` 好打印。
- **为什么 memmove 不是 memcpy**：源 `[index, length)` 与目标 `[index+1, length+1)` **重叠**，`memcpy` 遇重叠
  是未定义行为（上面那排「全是 20」就是它的下场）。口诀：区间可能重叠就用 memmove，绝不许重叠才用 memcpy。
- `memmove` 第三参单位是**字节**，所以是「格数 × sizeof(int)」。`tail_cells == 0` 时它搬 0 字节，合法且什么都不做，
  所以「插到末尾」不需要特判。

### `insert_at_stepwise` / `remove_at_stepwise` —— 逐格打印版

和 memmove 版功能完全一样，只是把那一次 memmove 拆成看得见的循环，每搬一格打印一次整排格子。
插入版 `i` 从 `length-1` 递减到 `index`（**故意倒着**），删除版 `i` 从 `index` 递增（**故意正着**）—— 跑一遍就亲眼看见 O(n) 里那个 n 次。

### `static_array_remove_at(sa, index, &value_out)` —— 整排左移，O(n)

`0 <= index < length`，空表直接 false。两个细节：先把要删的值存进局部变量（一挪就被覆盖），最后再通过输出参数带出去；
`length--` 之后把尾巴那格涂成 `-1099`，让它一眼看得出「这不是元素」—— 但逻辑上**必须靠 length 划界**，
不能靠「这格是不是垃圾」，涂垃圾只为调试好看。挪动次数 `length - index - 1`，与插入合起来就是「数组适合读多写少」的全部理由。

### `static_array_push_back(sa, value)` —— 数组唯一「不用搬家」的插入，O(1)

```c
sa->data[sa->length] = value;   /* 先写在「下一个空位」 */
sa->length++;                   /* 再承认它 —— 顺序不能颠倒 */
```

数组的「尾部」是它最便宜的位置。下一节动态数组的整个设计（容量翻倍）就是围绕「只从尾部加」建立的。

### `print` / `print_memory_map` / `sizeof_inside_function` / 两个 `sum_*`

`print` 把 8 个格子**全部**打印，`‖` 画在第 `length` 格**左边**（`length == 0` 时边界贴在开头，装满时自然没有 `‖`）。
`print_memory_map` 是本节的「看图识字」：下标 / 地址 / 相对偏移 / 数值 / 身份五行严格对齐，让你亲眼看见
「`a[i]` 的地址 = 首地址 + i*4」；地址每次都变，但相邻两格永远差 4 —— **会变的是数字，不变的是规律**。

`sizeof_inside_function` 是退化事故现场：参数写成 `const int *arr` 而不是 `const int arr[]`，两者编译出来是同一个东西，
但写成 `[]` 时 gcc 会警告 `sizeof` 拿到的是指针大小 —— 那条警告本身就在说「你以为你是数组，其实你早就只是指针了」；
本仓库要求零警告，所以诚实地写成指针，教训一个字不少。两个 `sum_*` 证明 `a[i]` 就是 `*(a+i)` 的语法糖，
都用 `long long` 累加（有符号整数溢出是未定义行为）；`cursor++` 一次跳 `sizeof(int)=4` 字节而不是 1 字节 —— 指针加法的「单位」是元素。

## 复杂度一览

| 操作 | 时间 | 为什么 |
|---|---|---|
| `get` / `set` 按下标、`size`/`capacity`/`is_empty`/`is_full` | O(1) | 地址 = 首地址 + i*sizeof，一次乘法；其余读字段 / 读编译期常量 |
| `init` / `fill` / `destroy` | O(容量) 或 O(n) | 涂垃圾、逐个拷贝 |
| `find` 按值 / 遍历求和 | O(n) | 无序只能逐格比对，平均 n/2 |
| `push_back` | **O(1)** | 写在 `data[length]`，谁也不用搬；满了 false |
| `insert_at` | **O(n)** | 后半排右移 `length-index` 格 |
| `remove_at` | **O(n)** | 后半排左移 `length-index-1` 格 |
| 头部连续插 n 次 | **O(n²)** | 0+1+…+(n-1) = n(n-1)/2，第 7 幕实测 |
| 空间 | 固定 40 字节 | 编译期锁死，不能长大 |

## 运行结果

复现（项目根目录）：`make one DIR=01-array/static-array`

节选真实输出（全文 210 行，取 5 处关键段落）：

```text
  sizeof(a) = 20，sizeof(a[0]) = 4，相除 = 5 个元素
      [函数内部] sizeof(arr)      = 8  ← 这是【指针】的大小，不是数组的
      [函数内部] 用它算出的"长度" = 2  ← 8/4=2，看着像模像样，其实完全错
  sizeof(StaticArray) = 40 字节 = data(8*4) + length(4) + moved_cells(4)
  初始化后      : [ ‖ -1000|-1001|-1002|-1003|-1004|-1005|-1006|-1007]  元素 0 / 格子 8  上次挪 0 格
  灌入 5 个初值 : [  10|  20|  30|  40|  50 ‖ -1000|-1001|-1002]  元素 5 / 格子 8  上次挪 0 格
  读第 5 格（只有 5 个元素，合法下标 0..4）：      [拒绝] index=5 不在 [0, 5) 里 —— 语言不拦你，函数拦你
  插入后        : [  15|  99|  20|  30|  40|  50 ‖ -1001|-1002]  元素 6 / 格子 8  上次挪 4 格
      逐格演示：往 index=0 插 1，需要挪 6 格（倒着搬！）
        第 1 步：data[6] = data[5] = 50
          现在: [  15|  99|  20|  30|  40|  50 ‖   50|-1002]  元素 6 / 格子 8  上次挪 4 格
        第 6 步：data[1] = data[0] = 15
          现在: [  15|  15|  99|  20|  30|  40 ‖   50|-1002]  元素 6 / 格子 8  上次挪 4 格
        写新值并 length++ 后: [   1|  15|  99|  20|  30|  40|  50 ‖ -1002]  元素 7 / 格子 8  上次挪 6 格
  结论：插到最前面挪了 6 格 —— 元素越多挪得越多，这就是 O(n) 里的那个 n。
  尾部插入后    : [   1|  15|  99|  20|  30|  40|  50|  77]  元素 8 / 格子 8  上次挪 0 格
  挪 0 格 —— 插到末尾谁也不用搬。push_back 就是这个特例，所以它是 O(1)。
    第 6 次：插完表里有 6 个元素 → 这次挪 5 格（累计 15 格）
  合计挪 15 格 = 0+1+2+...+5 = 6*(6-1)/2 —— 「在头部做 n 次插入」整体是 O(n^2)。
  再往头部插一个试试：      [失败] 已满（8/8），静态数组不会自己变大，插入无处安放
  要突破天花板只有两条路：① 改 #define SARRAY_CAPACITY 重新编译；② 换下一节的动态数组。
      ⚠ 这里【故意没有 free】：格子内嵌在结构体里，跟着结构体一起活、一起死；
         写 free(sa->data) 就是释放栈地址，是非法释放，程序会当场 abort。
```

逐段读：**第一段**是退化的数字证据 —— 同一个数组，在 `main` 里 `sizeof(a)` 是 20，一进函数参数就变成 8，相除得 2，
程序还「像模像样」地把它当长度用；所以本节的函数要么自带 `length`，要么额外收 `n`，绝无第三种可能。
**第二段**是 `‖` 那条线：`length = 0` 时边界贴在 `[` 后面（八格全空位），灌了 5 个初值后右移到第 5 格，右边三格的
`-1000 -1001 -1002` 是垃圾不是数据；`get` 读 `index=5` 被当场拒绝，裸写 `sa->data[5]` 却会照样把 `-1000` 给你。
**第三段**最有价值：`需要挪 6 格`、`第 1 步 data[6] = data[5] = 50`…`第 6 步 data[1] = data[0] = 15` 把「倒着搬」
原样打印出来，且每一步 `现在:` 行里元素数仍是 6 —— 搬的过程中表还没承认新长度，直到最后一行才变 `元素 7`；
紧接着尾部插入那行 `上次挪 0 格`，就是 O(1) 与 O(n) 的同屏对照。**第四段**：`累计 15 格` 与 `6*(6-1)/2` 严丝合缝 ——
头部增删的平方级代价不是背出来的，是数出来的；上一行撞墙 `[失败] 已满（8/8）` 正是下一节的开场白。
收尾处重复三次的「故意没有 free」，是静态数组与动态数组最硬的分界。

其余输出：第 1 幕逐格地址表（间隔恒为 4 字节）、第 2 幕 `(a+1)` 跨 4 字节而 `(&a+1)` 跨 20 字节；
第 9 幕的越界演示默认不触发 —— 要带 `--show-oob` 且用 ASan 编译才会真的越界读，仓库规矩是默认运行必须干净。

## 常见的坑

1. **在函数里用 `sizeof(arr)/sizeof(arr[0])` 算长度。**
   错法：`void f(int arr[]) { int n = sizeof(arr)/sizeof(arr[0]); }` → 得到 2，一声不响。
   对法：长度当参数传（`sum_by_index(arr, n)`），或像本节把 `length` 内嵌进结构体随身带。
2. **插入/删除后忘了同步 `length`。**
   错法：memmove 挪完直接 return；或 `push_back` 把 `length++` 写在赋值之前，让 `length` 指着没数据的格子。
   对法：插入 = 挪 → 写值 → `length++`；`push_back` = 先 `data[length] = value` 再 `length++`。
3. **用 `memcpy` 挪重叠区间。**
   错法：`memcpy(&data[index+1], &data[index], n)` —— 源目标重叠，未定义行为，可能整排变成同一个值。
   对法：`memmove`，且第三参单位是字节：`tail_cells * sizeof(int)`。
4. **插入正着搬 / 删除倒着搬。**
   错法：`for (i = index; i < length; i++) data[i+1] = data[i];` → 前一个值传染后面全部。
   对法：右移（插入）从右往左，左移（删除）从左往右；拿不准就直接调 `memmove` 让它自己判断。
5. **把格子数当元素数遍历。**
   错法：`for (i = 0; i < SARRAY_CAPACITY; i++) sum += sa.data[i];` → 把 `-1099`、`-1002` 当数据加进去。
   对法：`i < static_array_size(&sa)`，永远用 `length` 划界。
6. **指望语言拦越界，或拦截时上界写错。**
   错法：`if (index < SARRAY_CAPACITY) value = sa.data[index];` —— 落在 `[length, CAPACITY)` 时读到垃圾。
   对法：走 `static_array_get(&sa, index, &value)`（上界是 `length`），写完跑 `make asan` 兜底。
7. **给静态数组写 free，或满了还硬插。**
   错法：`free(sa.data)` —— 释放的不是 malloc 返回的堆地址，ASan 报
   `attempting free on address which was not malloc'd`，glibc 多半直接 abort；满了当没事发生。
   对法：`static_array_destroy` 只清账面，内存由作用域自动回收；满了返回 `false` 并明说「改 `#define` 重编译或换动态数组」，
   `find` 找不到返回 `-1`（`0` 是合法下标，不能当「没有」用）。

## 自检问题

1. `int a[5];` 里的「5」存在哪里？运行时能改吗？
   **答：** 存在**类型** `int[5]` 里，编译器据此圈 20 字节；内存里没有任何地方记着「5」。要改只能重编译。
2. `sizeof(a)` 在 `main` 里是 20，在 `void f(int a[])` 里是 8，为什么？哪三个场合数组名**不**退化？
   **答：** 传参只拷走首地址这一个数字，长度从来没上路。三个场合：`sizeof(数组)`、`&数组`、用字符串初始化数组。
3. 为什么 `static_array_capacity(void)` 不收参数，下一节的动态容量却必须传结构体？
   **答：** 静态容量是编译期常量，对每个数组都是 8；动态数组每个实例容量可以不同，必须问那一个具体的。
4. 为什么合法下标上界是 `length` 而不是 `SARRAY_CAPACITY`？
   **答：** `[length, CAPACITY)` 的格子物理存在但语义上不是元素，里面是垃圾/残留值，读出来一样是 bug。
5. 往 `index=0` 插一个元素（`length=n`）要挪几格？往末尾插呢？头部连续 n 次插入总共多少代价？
   **答：** 挪 n 格（O(n)）；末尾挪 0 格（O(1)）；n 次累计 n(n-1)/2 = O(n²)，第 7 幕实测「累计 15 格」= 6*5/2。
6. `destroy` 里没有 free，那 `StaticArray` 的 40 字节谁回收了？为什么 free 它反而致命？
   **答：** 编译器 —— 它是 `main` 的栈上局部变量，作用域结束栈帧一退就没了；free 一个栈地址是非法释放，当场 abort。
