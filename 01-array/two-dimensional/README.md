# 二维数组 two-dimensional —— C 里没有"二维"，只有一维格子 + 一个换算式

> 前置：`00-c-foundation/pointer-basics/`（指针、退化、`sizeof`）。本节不引入新算法，只把一件事钉死：
> **`int m[2][3]` 在内存里到底是怎么躺的**。这块没吃透，后面 `07-graph/adjacency-matrix/`、图像/矩阵代码会一路踩坑。

---

## 一句话是什么

二维数组就是**一整块连续内存 + 一套"行优先"的读法**。

`int m[2][3]` 编译出来是 6 个 int 挨着排的平地，中间**没有任何行分隔线**。「第 r 行第 c 列」是编译器把
`m[r][c]` 翻译成 `*(base + r*cols + c)` —— 乘的那个 `cols`（列数）是全部秘密。麻烦在于这块内存要进函数、
要 malloc、要 free，于是"列数由谁知道"分成三条路：

1. 进函数：**列数必须写在类型里**，行数只是记账；
2. 动态申请：一次 malloc 一整块（`FlatMatrix`，真连续）vs rows+1 次 malloc（`TableMatrix`，指针表 + 每行一条）；
3. 遍历顺序：同样 O(rows*cols)，顺着内存读和横着读，常数差好几倍。

---

## 为什么需要它

| 场景 | 不懂"行优先"会怎样 |
|---|---|
| 把二维传进函数 | 写成 `void f(int **m)` 接 `int m[2][3]`：编译不过，硬转之后读出来全是乱的 |
| 动态开矩阵 | 只会 `int **m = malloc(...)`，free 顺序搞反 → 泄漏 + use-after-free |
| 图像 / 邻接矩阵遍历 | 内层循环写成"跳列"，慢几倍却查不出原因（复杂度一模一样） |
| 每行长度不同的数据 | 硬用 `int m[][3]` 表达不出来；用连续块又想整块 memcpy，两头都错 |
| 读到 `int (*p)[3]` | 不认识这个类型，也不敢省那对括号 |

`00` 节讲了 `a[i] ≡ *(a+i)`，这一节把它推到二维，并让你亲眼看到 `m+1`、`&m+1`、`m[0]+1` 各走多远。

## 图解

### 1. 行优先：二维被摊平成一维（本节最重要的一张图）

```
源代码写法                 内存真实形状（一整块 6 格，中间没有分隔线）

int m[2][3] = {            相对入口地址   +0     +4     +8    +12    +16    +20
    {1, 2, 3},                        ┌──────┬──────┬──────┬──────┬──────┬──────┐
    {4, 5, 6}                         │  1   │  2   │  3   │  4   │  5   │  6   │
};                                  └──────┴──────┴──────┴──────┴──────┴──────┘
                                       └── 第 0 行 ──┘  └── 第 1 行 ──┘
                          （"行"只是"每 cols=3 格一组"的读法，不是物理边界）

              换算规则（唯一的真相）：
                    m[r][c]  ≡  *( (int *)m + r*cols + c )
                                          ↑ 乘的是【列数】，所以列数必须被知道
```

推论（代码注释里明说）：**C 的二维数组必须是矩形** —— 换算式里只有一个乘数，装不下"每行不一样长"。

### 2. 四个地址相同、类型不同的表达式

```
                  四个地址数字完全相同（第 2 幕实测 0x7ffdf97b0190）
                                 │
   &m[0][0]  int *            ───┤  +1 → +4  字节   一个格子
   m[0]      int *（第 0 行退化）┤  +1 → +4  字节   它本来就是第 0 行首格
   m         int (*)[3]        ───┤  +1 → +12 字节   一整行 = cols*sizeof(int)
   &m        int (*)[2][3]     ───┘  +1 → +24 字节   整个矩阵 = 下一块地皮

   记法：地址看「指向哪儿」，类型看「走一步多大」—— 两件事，别混。
```

### 3. `int **` 指针表：内存里其实是**两段东西**

```
  栈上的 TableMatrix m        堆·第一段：指针表（3 格，每格 sizeof(int*) = 8）
  ┌─────────────────┐       ┌────────────┬────────────┬────────────┐
  │ row  ───────────┼──────► │ row[0]     │ row[1]     │ row[2]     │
  │ rows = 3        │        └─────┬──────┴─────┬──────┴─────┬──────┘
  │ cols = 4        │ 表里存的【不是数据】，是地址 ↓            ↓
  └─────────────────┘              ↓
               堆·第二段：三条各自 malloc 的行 —— 行内连续，行间不保证相邻
                          ┌───────────────────────┐
                          │ 10   11   12   13     │ ← 行内 +4 一格
                          └───────────────────────┘
                            ↕ 实测两行首地址差 32 字节，而"一行"只有 4*4 = 16 字节
                          ┌───────────────────────┐
                          │ 20   21   22   23     │ ← 中间夹着别的东西（分配器记账）
                          └───────────────────────┘
                                    ↕   ……第 3 行再往后另起一块
                          ┌───────────────────────┐
                          │ 30   31   32   33     │
                          └───────────────────────┘

  读一格要走【两跳】：先查表拿 row[r]，再按列偏移；连续版只有一跳。
  代价换来回本：每行长度可以不一样（锯齿数组），连续版做不到。
```

## 逐个操作拆解（对应 `two-dimensional.c` 里每个函数）

### 1. `byte_delta()` —— 本节所有"走了几字节"都出自它

```c
static long long byte_delta(const void *from, const void *to)
{
    return (long long)((const char *)to - (const char *)from);
}
```

这行为什么存在：**指针减指针只在同一个数组里有定义，而且减出来的是"元素个数"不是字节数**。
本节反复问"`m+1` 走了多远"，最稳的写法是先看成字节再相减。

### 2. `flat_matrix_init()` —— 一次 malloc 租下整块地皮

```c
    size_t cells = (size_t)rows * (size_t)cols;
    m->data = malloc(cells * sizeof(int));
```

三个刻意的设计：① 先转 `size_t` 再相乘，因为 `rows*cols` 用 int 乘，大方阵会**先溢出**；
② `rows <= 0 || cols <= 0` 直接拒绝（`malloc(0)` 的返回值是实现定义的）；
③ 租回来立刻**涂毒** `m->data[k] = -9000 - (int)k;` —— "忘了 set 就读"时打出来一眼是假数字，而不是运气好的 0。

### 3. `flat_matrix_index()` / `flat_matrix_set()` / `flat_matrix_get()`

```c
int flat_matrix_index(const FlatMatrix *m, int r, int c)
{
    return r * m->cols + c;
}
```

这一行就是"二维不存在"的证据，故意做成独立函数让 `main` 验算，比藏进下标里更有教学价值。
`set/get` 是越界检查版：`r < 0 || r >= m->rows || c < 0 || c >= m->cols` 就打印 `[拒绝]` 并返回 `false`，
且拒绝时 **`*out` 原样不动**、`out == NULL` 时只回状态不写值（`00` 节"输出参数可传 NULL"的同款约定）。
对照事实：`pass_2d_flat()` 里的 `data[r * cols + c]` **完全不设防** —— 外层 API 用检查版，热点内循环用不设防版。

### 4. `flat_matrix_print()` 与 `flat_matrix_print_cell_map()`

前者排成表格，**看不出内存形状**；后者按**物理顺序**每格打一行（线性下标 / `m[r][c]` 身份 / 地址 / 相对入口 / 值），
核心是把线性下标反解回行列：`int r = (int)(k / (size_t)m->cols);` 和 `int c = (int)(k % (size_t)m->cols);`。
看这张地图就懂"行优先"：**先变的是列**，行每 `cols` 格才进一位。

### 5. 两种求和 + `bench_row_vs_col_major()`

```c
    for (int c = 0; c < m->cols; c++) {          /* 外层换成列 */
        for (int r = 0; r < m->rows; r++) {      /* 内层换成行 → 每次访问跳一整行 */
            sum += m->data[r * m->cols + c];
        }
    }
```

两个求和读的格子**一模一样多**，只有顺序不同：行优先地址 +4 顺着走，列优先每步跳 `cols*sizeof(int)` 字节。
缓存行通常 64 字节 = 16 个 int，行优先装一次白嫖 15 次，列优先基本每格 miss —— **常数之争，不是复杂度之争**。
`bench` 里三处"这行为什么存在"：`#define _POSIX_C_SOURCE 200809L` 必须写在**所有 `#include` 之前**
（`-std=c11` 严格模式，不声明就看不见 `clock_gettime`）；计时前先把整块内存填满真实值，让缺页成本发生在填数阶段；
用 `CLOCK_MONOTONIC` 并**取 rounds 轮里最快的一轮**，因为第一轮的成本会盖过缓存效应。

### 6. `table_matrix_init()` —— rows+1 次 malloc，以及失败回滚

```c
    m->row = malloc((size_t)rows * sizeof(int *));   /* 表里存的是指针，不是 int */
        m->row[i] = malloc((size_t)cols * sizeof(int));
        if (m->row[i] == NULL) {
            for (int j = 0; j < i; j++) {
                free(m->row[j]);
                m->row[j] = NULL;
            }
            free(m->row);
            m->row = NULL;
```

这里是 `int **` **最容易写错**的地方：租到第 3 行失败时前两行已经是你的了，不还就是泄漏。
前面那句"先把每格置 `NULL`"不是洁癖 —— 它保证回滚路径上的 `free(NULL)` 一定是合法空操作。

### 7. `table_matrix_free()` 与 `table_matrix_free_wrong_order()` —— 顺序不是审美问题

```c
    for (int i = 0; i < m->rows; i++) {
        free(m->row[i]);
        m->row[i] = NULL;    /* 顺手置空：万一后面出错，也不会读到废地址 */
    }
    free(m->row);
    m->row = NULL;
```

为什么**先每行、再表**：指针表是"找到各行"的唯一线索。表先没了，行再也找不回来（泄漏）；行先没了，
表里立刻是几枚废地址 —— 但只要马上把表也还掉，就没机会误用。
`table_matrix_free_wrong_order()` 是**反面教材专用**：先 `free(m->row)`，再留一份地址去读那张废表里的
`row[0]` → use-after-free，而各行仍在堆上没人认领 → 泄漏。它只在 `main` 第 9 幕靠开关 `--show-wrong-free`
才调用，默认路径绝不经过（交付闸门要求默认 ASan 0 泄漏）。里面那句 `fflush(stdout);` 也是必需的：
ASan 一报错就当场终止，先把话说完再死。

### 8. `table_matrix_print_row_table()` —— 把"表"和"行"分开画

打印三件事：表的地址与每格大小、每格里存的行首地址、**相邻两行首地址的字节差**。最后一项是杀手锏：
本次实测差 32 字节而一行只有 16 字节 → 两行之间夹着别的东西，**跨行整块 `memcpy` 在这版里是错的**。
代码里的三元判断说得很明白：刚好等于 `cols*sizeof(int)` 是"分配器凑巧"，不是语言保证。

### 9. 三种把二维传进函数的签名

| 函数 | 签名要点 | 实测 `+1` |
|---|---|---|
| `pass_2d_row_pointer` | `const int (*m)[DEMO_COLS]` + `rows` | 12 字节（一整行） |
| `pass_2d_omitted_rows` | `int m[][DEMO_COLS]`（行数留空）+ `rows` | 12 字节，**与上面同一个类型** |
| `pass_2d_flat` | `const int *data` + 运行时 `rows, cols` | 4 字节，跨行自己乘 `cols` |

前两种 `m[r][c]` 写起来很自然（列数写在类型里，编译器替你算换算式）；第三种签名最简单，代价是每个下标
手写 `r*cols+c`，**写错就是错一整片**。第 2 种里有个技巧值得抄：`int (*decay)[DEMO_COLS] = m;` ——
直接写 `sizeof(m)` 会吃 gcc 的 `-Wsizeof-array-argument` 警告（数组当参数就退化成指针了），
**而那条警告本身就是本节的一条结论**，换个写法既拿到数字又不破坏零警告闸门。
结果是 `sizeof(decay) = 8`（指针），但 `sizeof(m[0]) = 12`（一整行还没退化，列数仍在类型里）。

### 10. `show_row_pointer()` vs `show_array_of_pointers()` —— 长得像，意思相反

```c
void show_row_pointer(const int (*p)[DEMO_COLS], int rows);   /* 走一步 = 跨一行（12 字节） */
void show_array_of_pointers(int *p[DEMO_COLS]);               /* 退化成 int**，走一步 = 8 字节 */
```

`int (*p)[3]` 是"指向 3 个 int 那一排的指针"，天生用来遍历二维；`int *p[3]` 是"3 个 `int *` 的数组"
（`[]` 优先级比 `*` 高，所以括号不能省）。后者打印出来是三个互不相干的地址：它是"指针的集合"不是"一整块"，
而且 `parr[1][0]` **不能**写（`parr[1]` 已是 `int`，再 `[0]` 就是拿 int 当下标）。
函数体里 `p[i] ? *p[i] : 0` 是防空指针解引用的护栏：数组是别人给的，不能假设每格都指得好。

### 11. `main.c` 的九幕

1 摊平静态数组 → 2 四个表达式对照表 → 3 行指针 vs 指针数组 → 4 三种签名 → 5 连续版 → 6 指针表版 →
7 账单对比 → 8 缓存实测 → 9 free 顺序反例（**开关才触发**）。`print_identity_row()` 只为第 2 幕服务：
连着问四个"同一个地址"，排成表格才一眼看出**值全一样、只有类型不一样**。

## 复杂度

`R = rows`，`C = cols`，`N = R*C`。

| 操作 | 连续版 `FlatMatrix` | 指针表版 `TableMatrix` | 说明 |
|---|---|---|---|
| `init` | `O(N)`，malloc **1** 次 | `O(N + R)`，malloc **R+1** 次 | 都要涂毒，至少 O(N) |
| `set` / `get` | `O(1)`，1 跳地址 | `O(1)`，2 跳（先查表） | 指针表多一次间接寻址 |
| `print` / `cell_map` | `O(N)`，后者还输出 `O(N)` **行** | `O(R + R*C)` | 大方阵别调 cell_map |
| `sum_row/col_major` | `O(N)` | — | 复杂度相同，**常数不同** |
| `bench` | `O(rounds * n^2)` | — | 本节 `n=1000, rounds=3` |
| `free` | `O(1)`，顺序无所谓 | `O(R)`，顺序**必须**先每行再表 | 反了 = UAF + 泄漏 |
| 空间实测（3×4） | 48 字节 | 72 字节 | 差 24 = 3 行 × 8 字节，即"表本身" |

本次实测常数差：1000×1000 上列优先比行优先**慢 1.55 倍**（最快轮 1.463 ms vs 2.261 ms），两个和必然相等。

## 常见的坑

1. **行/列写反，或下标越界**。`m[c][r]` 在**方阵**上常常"看起来对"，到 3×4 上直接越界；`r*cols+c` 里那个
   乘数永远是**列数**，这是本节最贵的一处笔误。检查版会拦（见 `[拒绝] set(0,4)`），而 `data[r * cols + c]`
   不设防 —— 越界读写的是别人的内存，只有 ASan 抓得到。
2. **把 `int **` 当成"二维数组的指针"传**。`int m[2][3]` 退化后是 `int (*)[3]`，**不是** `int **`；硬转之后
   `mm[1]` 读的是"第 4 个 int"而不是第 1 行，因为中间缺了"一层真实存在的指针表"。这是二维上排名第一的坑。
3. **进函数后想用 `sizeof` 把维度算回来**。行数可以省、列数绝对不行：`int m[][3]` 合法、`int m[2][]` 非法。
   维度信息只在**数组出生的作用域**里存在，出了那道门就只剩 `sizeof = 8` 的指针。
4. **malloc 回来不判空 / 多块申请失败不回滚**。连续版判一次空就够；`table_matrix_init` 有 `rows+1` 次申请，
   第 i 行失败时必须把 0..i-1 行**和表**一起还掉并把字段归零 —— 少一步就是泄漏。
5. **`int **` 的 free 顺序搞反**（先 free 表，再按行归还）：读 `row[i]` 时表已还不回去 → use-after-free；
   各行还在堆上但线索全断 → 泄漏。`main` 里那句解释最扎心：free 之后那块地址**还在指针里**，数字看起来
   完全正常，读它不会立刻崩。修法就是 `free` 完立刻置 `NULL`，重复 `free` 于是变成幂等空操作。
6. **相信"行与行是连续的"**：实测相邻行首地址差 32 字节 ≠ 一行 16 字节；就算某次凑巧相等也是分配器帮忙。
   `int **` 版的"整块 memcpy / 整块排序"是错的，只能逐行搬。
7. **忘了 init 里先转 `size_t` 再乘**：`rows*cols*sizeof(int)` 用 int 相乘，大方阵会先溢出成小数字，
   `malloc` 反倒"成功"，然后写越界 —— 比直接失败更难查。
8. **误读第 8 幕的比值**，或在大矩阵上调 `flat_matrix_print_cell_map`（每格一行，1000×1000 就是一百万行）。

## 这一节实现到什么程度（诚实说明）

- 两个结构都**只支持矩形**：`table_matrix_init(m, rows, cols)` 每行按同一个 `cols` 申请。锯齿数组只在第 6 幕
  用文字说明"结构上做得到"，**本节没实现锯齿版 API**（真锯齿要每行单独传长度）。
- 没做转置、矩阵乘法、reshape、按行排序 —— 不是本节目标，本节目标是把内存形状和函数签名讲透。
- `table_matrix_free_wrong_order()` 是**故意写错**的演示函数，正式代码绝不要调用，默认运行不经过它。
- 缓存实测用的是 `make one` 的 `-g` 构建（`.c` 注释还提醒 ASan 会把比值稀释）。换机器换选项数字会变，
  结论（行优先更快、这是常数之争）不变。
