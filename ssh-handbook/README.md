# SSH 大白话手册

> 一本「先跑起来、再懂为什么」的 ssh 手册。全书只认一件事：**每条命令的真实输出**。
> 报错原文在这里不是提示，是证词 —— 它告诉你这条命令已经走到了第几步、死在哪一步。
> 所有输出都出自这台机器（OpenSSH_10.2p1 Ubuntu-2ubuntu3.6 + OpenSSL 3.5.5），没有一行是手写的。

---

## 这本书是什么、写给谁

写给正在学 C 语言和数据结构、迟早要自己连服务器 / 配 git 远程 / 隧道到内网的人。
大多数人的 ssh 知识是这么攒起来的：抄一条命令、报错、再抄一条、再报错。这本手册反过来做：

- **先把分层图立起来**（01 章）：客户端、服务端、传输层、认证，各管什么、谁给谁发话；
- **再逐层塞零件**：密钥（02）、配置文件（03）、agent 与连接复用（04）、端口转发（05）；
- **最后按报错原文重排一次**（06）：你屏幕上那行字，对应上面哪一层死了。

一句话前提：**全书只看一个仓库不够，得跑。** 尤其这本 —— ssh 的所有知识点都是
"屏幕上出现了哪句话"，光读段落读不出来。每条命令你都该在沙箱里敲一遍，看输出对不对得上。

## 全书主线：一条 `ssh` 命令必然经过的三段路

```text
你敲：ssh -F <沙箱配置> <别名> <命令>
   │
   ├─ 第 0 步  读配置：-F / 命令行 -o / ~/.ssh/config / /etc/ssh —— 同一个关键字第一个赢
   │            ↓                                    （03 章整章在讲这一步）
   ├─ 第 1 段  TCP 连上了没有                          死了 → Connection refused / timed out / Could not resolve
   │            ↓                                                     （06 实战 1，跟密钥一点关系没有）
   ├─ 第 2 段  密钥交换 + 主机指纹认不认                死了 → kex_exchange_identification / HOST IDENTIFICATION CHANGED
   │            ↓                                                     no matching key exchange method（01、06）
   └─ 第 3 段  认证：publickey / password / agent       死了 → Permission denied (publickey) / Too many authentication failures
                                                                  （02、04、06）
```

**先定位在哪一段，再谈怎么修** —— 这是全书反复在用的一套动作，也是 06 章的编排方式。

### 边界与缺口（先说清楚）

- **全书六章收口，没有第 07 章。** 原本想单开的"隧道进阶 / 服务端配置"两章并进了 05 和 06。
- **一次"登录成功"都没演过。** 这是红线决定的（见下面），不是能力问题：本机那个 `127.0.0.1:22`
  是真实的系统 sshd，我们只被动观察它，不往里装 `authorized_keys`、不猜密码。
  因此凡是"必须认证成功之后才看得到的输出"（登录后画面、服务端门真正建立、`sshd` 侧配置生效），
  各章一律标 **「未验证」**，并给出你自己有服务器时怎么验。
  05 章对此的替代做法值得先看一眼它的开头：用一个真跑的中转进程把 `ssh -L` 的机制复现出来。
- **`~/.ssh/config` 的真实文件不读不写。** 03 章用 `-F <沙箱配置>` 和 `ssh -G` 演同一套规则，
  章里明确写了哪些结论只能这样演、不能怎样演。

## 怎么跑

每章一个目录，里面固定是 **一份 `demo.sh` + 一份 `README.md`**。

```bash
cd ssh-handbook/03-config-file
bash demo.sh                     # 把全章证据跑一遍，跑完自动删沙箱
bash demo.sh --keep              # 保留沙箱并打印路径，进去自己接着敲
bash demo.sh > /tmp/s03.txt 2>&1 # 重定向时自动关颜色，拿到纯文本
```

现在在场的清单（在 `ssh-handbook/` 目录下敲，真输出如下）：

```text
$ ls */demo.sh
01-how-it-works/demo.sh
02-keys/demo.sh
03-config-file/demo.sh
04-agent-and-multiplexing/demo.sh
05-port-forwarding/demo.sh
06-troubleshooting/demo.sh
```

跑之前知道这几件事，能省你很多困惑：

- 沙箱目录是 `/tmp/sshNN-XXXXXX`（例如 `/tmp/ssh03-4oSkKl`），**随机后缀每次都变**，
  假端口也是每次随机挑的 —— 这两处不必和 README 对齐，其余内容应当一字不差。
- 每章 `demo.sh` 收尾都会打一次 `ss -lnt`，**证明它自己起的监听全部释放了**。
  这一行是给你看的验收章，不是装饰。
- 章 README 里标了"demo 第 N 节 / 场景 N"，可以按编号回 `demo.sh` 找那段命令。

## 全书约定与安全红线

**这些实验全在 `mktemp -d` 的沙箱里做，读者可以照抄。** 但照抄之前，请先看懂我们为什么这么约束自己：

| 红线 | 具体做法 | 后果（如果不守） |
|---|---|---|
| **绝不读写 `~/.ssh/`** | 所有 key、`known_hosts`、config、agent socket 全在沙箱目录里 | 教程替你生成了密钥、覆盖了你的 `config`，你还不知道 |
| **绝不改 `/etc/ssh/`** | 那台机器上 `22` 端口是**真实服务**，只能被动观察；**绝不重启 / 停止 / 修改 `sshd` 或 `ssh.socket`** | 在正在被使用的机器上把远程通道关掉，人可能被锁在外面 |
| **每条 `ssh` 都带 `-F /dev/null` 或沙箱配置** | 不读你真实的 `~/.ssh/config`；`ProxyJump`、`IdentityFile` 之类全部指向沙箱 | 一条演示命令顺着你真配置里的跳板机连到了公司网络 |
| **绝不尝试登录成功** | 不装 `authorized_keys`、不猜密码、不爆破、不枚举用户名 | 对着一台真实 sshd 猜口令 = 攻击行为，本机也一定会留日志 |
| **绝不连外部主机** | 只用 `127.0.0.1` / `localhost`（文档里出现的 `10.x` 地址全是配置样例，从不真连） | 手册变成别人机器的流量来源 |
| **私钥内容绝不进文档、绝不 `cat` 私钥** | 全书记录只有 `.pub` 那几行、指纹、字节数和 `ls -l` 的权限位 | 一份"看起来无害"的教程里躺着可用的私钥 |
| **收尾证明干净** | `trap` 统一 `kill` 后台进程 + 删沙箱（只删自己刚建的那个）+ `ss -lnt` 复核没有遗留监听 | 你的机器上多出一堆无人认领的转发端口 |
| **验不了就写"未验证"** | 需要真服务器的场景明确标注，不编造输出 | 读者按编造的输出对不上，然后开始怀疑自己 |
| **屏幕上不出现真实身份** | 被尝试登录的远端用户名统一用中性名 `learner`（本书每个连接都是故意失败的演示，用不存在的用户结论不变）；只能来自本机的身份 —— 本地用户名 `%u`、`Match localuser`、本机主机名 `%L`、`~/.ssh` 展开出来的真实家目录 —— 在 README 里写成 `<本机用户>` / `<主机名>` / `<家目录>` | 一本讲登录的手册里印着你的登录名，等于把这本书变成一张你的身份名片；`known_hosts` 的哈希行、`%C` 哈希这类**派生值一律用重跑后的真值**，绝不手改 |

另外三条软规矩：`BatchMode=yes` 让任何"要人输密码"的路径直接失败（绝不挂在那里等输入）；
`StrictHostKeyChecking` 只在沙箱里的临时 `known_hosts` 上放宽；脚本一律 `LC_ALL=C.UTF-8`，
不然报错被翻译成中文就没法逐字核对了。

## 建议阅读顺序

**01 → 02 → 03 → 04 → 05 → 06**，顺序基本不可换，理由是硬性的：

- 不先立 01 的分层图，02 之后所有报错你都没地方归置；
- 04（agent）依赖 02 的"私钥有口令"这件事，03 的 `-G` 是 04/06 的工具；
- 05（转发）需要你已经能"连上"，所以它其实是全书最靠后的一章；
- 06 不产生新知识，它把前五章的报错重排一遍 —— 但**它是最该被反复翻的一章**。

**可以跳的：**

- 只是想让 `git clone git@...` 能跑：读 02（第 1~6 节）+ 06（实战 11）就够，03/04/05 先跳。
- 只有一台自己的服务器、从不跳板：05 整章可以先放着。
- 03 的 `Include`、`Match` 那几节，配置没超过 50 行的可以先不看。
- 不要跳 01 第 3 节（指纹与 TOFU）—— 那是唯一一处"看懂了能避免被中间人"的内容。

## 这本书没覆盖什么

- **真登录、真服务器**：全书没有任何一次成功认证（见红线）。服务端侧行为全部由客户端报错倒推。
- **`sshd_config` 的调法**：哪些选项能禁密码、哪些能限用户、`AllowTcpForwarding` 怎么放开 ——
  只讲"它拒绝你的时候你会看到哪句话"，不改任何服务端配置。
- **不碰 `~/.ssh`**：所以也不会教你"把这段贴进 `~/.ssh/config` 就行"。给你的是同一套规则的沙箱版，
  你要落地时自己决定贴到哪。
- **证书登录只到"读得懂"**：02 第 9 节签了一张并把它各字段读出来，CA 部署、`TrustedUserCAKeys` 那套工程化不讲。
- **Kerberos / GSSAPI / LDAP、FIDO2 与 security key、跳板机的产品化方案（堡垒机）全部没写。**
- **`scp` / `sftp` / `rsync` 的用法**不讲，只在 03 里说明它们为什么会继承你的 `ProxyJump`。
- **Windows 上的 OpenSSH、`plink`、其他实现**没有；测的是 Linux 上 Ubuntu 打包的 OpenSSH 10.2p1。
- **性能与网络诊断**（MTU、代理链路、IPv6 优先）只在 05 里撞到过一次（`localhost` 解析成 `::1`）。
