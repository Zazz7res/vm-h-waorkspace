# 第 K 小 / 顺序统计量（kth-smallest）

## 一句话是什么

**在不排序的前提下，拿到「从小到大第 k 个位置上的那个值」。**

```
a = 7 2 9 1 5 3 8        排好序 →  1 2 3 5 7 8 9
                                     ↑
                                  第 3 小 = 3
```

排序要 O(n log n)，而这件事**平均只要 O(n)** —— 甚至只要 O(k)、只要 O(log) 内存、
或者"一行都不许改我的数据"。这一节就是把这五种活法各自讲清楚，并告诉你**哪一站该下哪个车**。

---

## 为什么需要懂它（只会排序会错过什么）

1. **"只要一个答案"和"要全部排名"是两个不同的代价。**
   你想知道全班第 5 名多少分，不需要把整张成绩单排好。快选就是这个直觉的算法化。
2. **它是 Top-K / 中位数 / 分位数报表的地基。**
   `06-heap/top-k`、监控里的 P50/P99、机器学习里的阈值分位 —— 全是这一节的问题换了层皮。
3. **它是"平均 O(n) 但最坏 O(n²)"这个概念最好的载体。**
   随机化不是装饰：换一种 pivot 取法，同一份**已排序**的输入就能把你的线性算法打成平方级。
   第 5 幕把这个塌方**量出来**给你看（理论和实测逐行相等）。
4. **它是"二分答案"第一次真正落地。**
   `11-searching/binary-search` 里埋的那条线（二分的对象可以是"值"而不是"下标"）在这里接上：
   值域上二分 + 一个单调判据 = 不改数据、不排序、不需要额外内存的 O(n log R) 解法。

---

## 先把语义钉死：第 k 小是"按位置"，不是"按不同值"

```
a = 5 5 5 9 1 3     排好序 →  1 3 5 5 5 9
第 1 小 = 1   第 2 小 = 3   第 3 小 = 5   第 4 小 = 5   第 5 小 = 5   第 6 小 = 9
```

- ★ 重复值**各占一个位置**。"第 3、4、5 小"都是 5，这不是 bug，是定义。
- ★ k 从 **1** 开始数；下标从 0 开始数；`k-1` 是这两套约定之间的那座桥，别省。
- ★ 两个免费验收点：**第 1 小 = 最小值，第 n 小 = 最大值**。每个函数都该先拿这两条自测。
- ★ "第 k 个**不同**的值"是另一道题（要先去重），本节不做。

---

## 图解：五种方法各自长什么样

### ① 排序取下标 —— 最省心，也最费

```
拷贝一份 → 插入排序（十行就写完，还能看到"排到一半"） → 直接 a[k-1]
```
为了一个 k，把 n 个数全排了。**唯一优势**：顺手把所有排名都知道了。

### ② 大小为 k 的大顶堆 —— 内存只有 k 格

```
      堆里始终装着「目前见过的最小的 k 个」
                堆顶 = 这 k 个里最大的 = 最可能被淘汰的那个
      新元素 x：  x < 堆顶 ? 换掉堆顶并下沉 : 直接丢弃（连看第二眼都不给）
      扫完：      堆顶就是第 k 小
```

为什么是**大顶**堆（这是本节最高频的口误点）：要淘汰的是"k 个里最大的"，
大顶堆让你 **O(1) 看到它**；用小顶堆的话堆顶是 k 个里最小的，你根本不知道该踢谁，
得把整堆扫一遍 ⇒ 每次 O(k) ⇒ 总共 O(nk)。

### ③ 快速选择 —— 本节主角

```
partition 一趟：把 pivot 放到它**最终的排名位置** p 上
      a[lo..p-1] ≤ a[p] ≤ a[p+1..hi]
然后只问一句：p 和 target = k-1 谁大谁小？
      p == target → 答案就是 a[p]，收工
      p <  target → 答案在右半，左半整段扔掉
      p >  target → 答案在左半，右半整段扔掉
```

复杂度推导（这一段要能默写）：

```
T(n) = T(n/2) + n
     = n + n/2 + n/4 + n/8 + …   <   2n        ← 等比级数，公比 1/2
```

**快排和快选的唯一区别就是"递归一边还是两边"**：两边 ⇒ n log n，一边 ⇒ n。
而"一边"的前提是 pivot 大致把区间切匀 —— 这就是下一张图。

### ③′ 塌方现场：pivot 选烂

```
输入已升序 1 2 3 … n，pivot 固定取区间首元素：
   每轮 partition 只能保证"最小值归位"，规模只减 1
   第 r 轮比较 (n-1-r) 次 ⇒ 总共 Σ = k(n-1) − k(k-1)/2 = Θ(n²)
随机 pivot：每轮期望砍掉一半 ⇒ 回到 2n
```

**随机化 pivot 不是"锦上添花的优化"，它是这一算法成立的前提。**

### ④ 值域计数 / ⑤ 值域二分答案 —— 不比大小

```
④ 计数：cnt[值-最小值]++ ，再从最小值往上累加，累到 ≥ k 的那个值就是答案
        O(n + R)，R = 值域宽度。R 爆炸 ⇒ 内存爆炸 ⇒ 此路不通
⑤ 二分答案：判据 = 「≤ x 的数有几个」（扫一遍 O(n)，关于 x 单调不减）
        在值域 [min, max] 上找"第一个让个数 ≥ k 的 x"，lower_bound 模板
        O(n log R)：值域从 36 涨到 180 万，轮数只从 5 涨到 21
```

⑤ 的三条隐性优点值得单独记：**不改动数组、零额外内存、判据可以流式重放**。

### ⑥ 附加题：两个有序数组的第 k 小

```
A: a[0..i-1] | a[i..na-1]        左半块合起来正好 k 个数
B: b[0..j-1] | b[j..nb-1]        且 j = k - i（切一刀，另一刀就定了）
合法条件：a[i-1] ≤ b[j]  且  b[j-1] ≤ a[i]      （谁都没伸过界）
满足则答案 = max(a[i-1], b[j-1])
只在**短**数组上二分 ⇒ O(log(min(m,n)))
```

边界用**哨兵**破：`i == 0` 时 `a[i-1]` 不存在 ⇒ 填 `INT_MIN`；`i == na` 时 `a[i]` 不存在 ⇒ 填 `INT_MAX`。
于是"不存在的那一侧"在比较里自动输/赢，**整个函数一个额外的 if 都不用写**。

## 逐个操作拆解（对应 kth.c）

| 函数 | 在干什么 | 为什么这么写 | 复杂度 |
|---|---|---|---|
| `kth_dump` | 打印下标/数值两行 | 列宽给到 `%8d`：第 6 幕要看 ±90 万的数组，四格宽会挤成一串 | O(n) |
| `kth_by_sorting` | 方法① | **先拷贝**再排（承诺不改调用者数据）；用插入排序是为了短、且能看到"排到一半" | O(n log n)／这里是 O(n²) |
| `kth_by_heap` | 方法② | 前 k 个建堆，之后"比堆顶小才换堆顶+下沉"；`top_before` 先存下淘汰前的堆顶，否则打印出来的是换完之后的值 | O(n log k) |
| `sift_up` / `sift_down` | 堆维护 | 大顶堆：父 < 子就上浮。下沉时先取三个里最大的孩子 | O(log k) |
| `partition_lomuto` | 快选的心脏 | pivot 先换到末尾，循环里就不用再管它；`a[j] <= pivot` **带等号**，重复值统一甩左边；结束后 pivot 落在**最终位置** | 单趟 O(m) |
| `kth_quickselect` | 方法③ | **就地打乱数组**（这是它便宜的原因：省一次拷贝），所以接口注释必须写明副作用 | 平均 O(n) |
| `kth_quickselect_bad_pivot` | 故意写坏 | pivot 固定取区间首 ⇒ 配已排序输入必然塌方；内部拷贝，方便同一个数组反复试 | 最坏 O(n²) |
| `kth_rand_below` | 随机 pivot | **自写 xorshift32 + 固定种子**，不用 `rand()`：libc 的序列换台机器就变，README 的数字就对不上 | O(1) |
| `kth_by_counting` | 方法④ | 先算值域宽度，**超过 `KTH_COUNT_MAX_RANGE` 就返回 0**（此法不适用），而不是硬开数组 | O(n + R) |
| `count_less_equal` | 判据 | 一遍扫描；关于 x **单调不减** ⇒ 可二分。这个"单调"是用二分的唯一资格 | O(n) |
| `kth_by_value_binary_search` | 方法⑤ | lower_bound 模板 `while (lo < hi)` + `hi = mid`；`mid` 用 `long long` 算，因为值域可能是 INT_MIN..INT_MAX | O(n log R) |
| `kth_two_sorted` | 附加题 | 先把 a 换成较短的那个（换指针+换长度），再二分开点 i；边界靠 INT_MIN/INT_MAX 哨兵 | O(log(min(m,n))) |
| `kth_two_sorted_linear` | 对拍基准 | 归并弹出第 k 个，O(k)，显然正确 ⇒ 用来验收划分法 | O(k) |
| `kth_median_lower` / `_upper` | 中位数 | 偶数时两种约定分道扬镳，所以**两个都给**；取哪个是接口约定问题 | 同方法① |
| `kth_all_agree` | 总验收 | 五种思路各异的实现给出同一个答案，比任何单测用例都可信（它们不会朝同一个方向错） | O(n²) 一次跑完五法 |

## 复杂度一览（k 固定、n 很大、R = 值域宽度）

| 方法 | 时间 | 额外内存 | 改不改原数组 | 适用的信号 |
|---|---|---|---|---|
| ① 排序取下标 | O(n log n)（本实现插入排序 O(n²)） | O(n) | 不改（内部拷贝） | 要**所有**排名 |
| ② 大小 k 的大顶堆 | O(n log k) | **O(k)** | 不改 | **数据流 / 内存装不下** |
| ③ 快速选择（随机 pivot） | **平均 O(n)** | O(1) | **会打乱** | 只问一个 k，数据在内存里 |
| ③′ 快速选择（pivot 选烂） | **最坏 O(n²)** | O(1) | 会打乱 | ← 第 5 幕实测的塌方 |
| ④ 值域计数 | O(n + R) | O(R) | 不改 | **值域小**（分数、年龄、字符） |
| ⑤ 值域二分答案 | O(n log R) | O(1) | 不改 | 数据只读 / 流式 / 值域大 |
| ⑥ 两有序数组划分 | O(log(min(m,n))) | O(1) | 不改 | 输入**已经各自有序** |

## 运行结果（真跑出来的）

复现：

```
make one DIR=11-searching/kth-smallest
```

默认输出 253 行，八幕，ASan 干净（本节零 malloc）。节选三处最值钱的。

**第 4 幕 —— 快选逐轮：pivot 每轮都落到自己的最终位置，然后扔掉一边：**

```
      partition 之后：
    数值        2       1       5       3       7       8       9
      第 1 轮 区间[0..6]  pivot 落点 p=4  a[p]=7
              p > 2 ⇒ 答案在左半，扔右半：hi = 3
      partition 之后：
    数值        2       1       3       5       7       8       9
      第 2 轮 区间[0..3]  pivot 落点 p=3  a[p]=5
              p > 2 ⇒ 答案在左半，扔右半：hi = 2
      第 3 轮 区间[0..2]  pivot 落点 p=2  a[p]=3
              p == 目标下标 2 → 答案就是它，不用再看任何一边

    → 答案 3，总共比较 11 次（排序法要 14 次）
```

**第 5 幕 —— 毒输入塌方，理论值和实测逐行相等：**

```
    n    k     理论值      坏pivot实测   坏/n²    随机pivot实测   随机/n
    10   5     35          35            0.350    15            1.50
    20   10    145         145           0.362    49            2.45
    40   20    590         590           0.369    103           2.58
    60   30    1335        1335          0.371    251           4.18
```

读法：`坏/n²` 四行稳在 0.35~0.37 ⇒ 比较数 ∝ n²，这是平方级的指纹；
随机 pivot 的 `÷n²` 那一列会一路掉向 0 ⇒ 线性量级。
（⚠ 随机列是**单次样本**，有噪声，别把 4.18 当常数 —— 结论只到"线性 vs 平方"这个量级。）

**第 6 幕 —— 值域一撑开，计数法当场阵亡，二分答案只多几轮：**

```
    ④ 计数法   ：第 5 小 = 77（值域 36 ≤ 256，可用）
    ⑤ 二分答案 ：第 5 小 = 77，值域上二分 5 轮 ⇒ 扫数组 5 遍 ≈ 60 次比较量级
    ...
    数值        5  900000 -900000       7       3
    ④ 计数法   ：**不适用**（返回 0，交回调用者换方法）  ← 值域约 180 万 > 256，硬开 cnt[] 就是白烧内存
    ⑤ 二分答案 ：第 3 小 = 5，只用了 21 轮（log2(180 万) ≈ 20.8 ⇒ 轮数只跟值域走）
```

其余五幕一句话交代：第 1 幕用 `5 5 5 9 1 3` 把"重复值按位置算"钉死并检查 k=0/k=8 两个非法边界；
第 2 幕给出排序法的比较次数和它"顺手知道所有排名"的定位；第 3 幕逐元素打印大顶堆的淘汰过程
（最后堆里是 `3 1 2 0`，正是最小的 4 个，堆顶 3 = 第 4 小）；第 7 幕穷举 11 个 k，
划分法与归并对拍**不一致 0 处**；第 8 幕先给下/上中位数（偶数时 30 / 40 分道扬镳），
再对含大量重复值的数组 `4 4 1 9 4 9 2 7` 的每个 k 跑五法，八行全部 `五法一致 ✓`。

## 常见的坑（错法 vs 对法）

**1. 用"大小为 k 的小顶堆"求第 k 小**
```
错：小顶堆 → 堆顶是 k 个里最小的，你不知道该淘汰谁，只能整个扫一遍 → O(nk)
对：大顶堆 → 堆顶就是"k 个里最大的"，看一眼就知道淘汰它 → O(n log k)
```
记法：**求第 k 小用大顶堆，求第 k 大用小顶堆**（堆顶永远是"最配被踢出去的那个"）。

**2. 以为快选是"最坏 O(n)"**
它是**平均** O(n)、最坏 O(n²)。取首元素当 pivot + 已排序输入是最经典的毒输入（第 5 幕实测到 1335 次）。
对法：随机 pivot（本节做法），或者接受"输入可能被对手构造"这个前提并换方法⑤。

**3. 忘了快选会打乱数组**
`kth_quickselect(int a[], ...)` 是非 const 的，这不是随手写的：它**就地 partition**。
后面还要用原数组？先拷贝 —— `kth_all_agree` 里就老老实实拷了一份。

**4. `partition` 里写成 `a[j] < pivot`（不带等号）**
带 `<=` 时重复值统一甩到左边，循环不变量干净。写成 `<` 会让等于 pivot 的元素全堆到右边，
在"全是同一个值"的输入上退化成 O(n²)。**重复值就是这类 Off-by-one 的显微镜。**

**5. 把带 out 参数的函数调用和读该 out 参数写在同一个 `printf` 实参列表里**
```c
错： printf("%d 轮", kth_by_value_binary_search(wide,5,3,&st7), st7);  // gcc 从右往左算实参
对： int v = kth_by_value_binary_search(wide, 5, 3, &st7);  printf("%d 轮", v, st7);
```
这是我在写第 6 幕时**真的踩到的**：值域二分明明跑了 21 轮，打印出来是 `0 轮`，而且零警告零报错。
**C 不规定实参求值顺序**，这类 bug 不崩、不报警、只在数字上讲不通 —— 只能靠"先算完再打印"的纪律躲开。

**6. 值域二分的 `mid` 用 int 算**
`lo = INT_MIN`、`hi = INT_MAX` 时 `(hi - lo)` 直接溢出。本节写成
`(int)((long long)lo + ((long long)hi - lo) / 2)`。
值域上的二分比下标上的二分**更容易撞溢出**，因为下标不会到 21 亿，值会。

**7. 两有序数组划分法为边界写一堆 if**
`i == 0`、`i == na`、`j == 0`、`j == nb` 四种切法各有特判 ⇒ 16 个分支且必漏一个。
对法：哨兵 `INT_MIN` / `INT_MAX` 让"不存在的一侧"自动输赢，主循环保持四行。

**8. 只在 n 很小的时候测一次就交付**
本节所有断言（第 5 幕的公式、第 7 幕的 11 个 k、第 8 幕的 8×5 法对拍）都是**穷举式**的。
二分类算法的错常常只在某个具体下标上发作，测两三个案例极易"全对"。

   （答：不是，等比级数公比 3/4 求和是 4n，仍是线性。**只要砍掉固定比例就是线性**。）
