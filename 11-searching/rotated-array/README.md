# 旋转数组查找（rotated-array）

## 一句话是什么

**一份已经排好升序的数组，从中间剪一刀、两段左右对调之后，怎么用 O(log n) 继续查。**

```
升序：      0  1  2  3  4  5  6
在 3 处剪开：[0 1 2] [3 4 5 6]
对调拼接：   3  4  5  6  0  1  2     ← 旋转数组，"旋转了 3 次"
```

它不是一种新的数据结构，还是那个数组。它考验的是**二分的思维**：
当"整个数组有序"这个前提被破坏了一半，你还剩什么信息可用？

---

## 为什么需要懂它（不会它会怎样）

1. **它是二分查找的"压力测试"。** 普通二分太顺了，顺到很多人其实是背下来的。
   把数组剪开一挪，`if (a[mid] < target) left = mid + 1;` 这句话立刻不成立 ——
   这才逼你回到二分的底层原理：**每一次扔掉一半，凭什么敢扔？**
2. **它是"旋转/环形"这一大类问题的原型。** 排班表轮转、环形缓冲区里的有序数据、
   版本号绕回（`... 998 999 0 1 2 ...`）、按天分区的日志表 —— 都是同一个形状。
3. **它有一个必须亲手撞过的坑**：判据写成 `a[mid] vs a[left]` 也能跑、也能过一半用例，
   但在特定输入上静默给错答案。本节第 2 幕就是专门把它演出来。
4. **它顺带告诉你"信息量决定代价"**：同一道"第 k 小"，无序数组要 O(n)（见 `kth-smallest`），
   旋转数组只要 O(log n)（本节第 8 幕）—— 因为这里"其实已经排过序"。

---

## 图解：结构特征决定一切

### ① 数组长什么样

```
下标：   0   1   2   3   4   5   6
数值：   3   4   5   6 | 0   1   2
         └─ 大值段 ─┘   └─ 小值段 ─┘
                    ↑
                 唯一的断崖（a[i] > a[i+1]）
                       ↑
                   断崖右边第一格 = 最小值 = 旋转点 pivot
```

三条必须刻进脑子的结构事实：

- ★ 数组由**两段各自升序**的段拼成；
- ★ **有且只有一个下降点**（没旋转时 0 个）；
- ★ **最小值下标 == 旋转次数**，找到它就找到了一切。

这就是为什么所有代码的心跳都是同一个函数 `ra_min_index`：找到断崖，问题就退化成普通二分。

### ② 心跳：为什么判据是 `a[mid] vs a[right]`

```
if (a[mid] > a[right])  left = mid + 1;   // mid 在大值段 ⇒ 断崖在它右边
else                    right = mid;      // mid 已在小值段/无断崖 ⇒ 答案 ≤ mid，mid 还得留着
```

直觉：`a[right]` 是"当前窗口最后一格"。拿 mid 和它比，问的是
**「mid 之后有没有掉下去」** —— 掉了，说明 mid 还在前面那段大值里；没掉，说明 mid 已经在尾段。

而和 `a[left]` 比会**输掉信息**：`a[mid] > a[left]` 这一件事在两种完全相反的局面下都成立：

```
A: 1 2 3 4 5   a[left]=1  a[mid]=3   → 3>1 成立，可最小值在 mid 左边（下标 0）
B: 3 4 5 1 2   a[left]=3  a[mid]=5   → 5>3 成立，可最小值在 mid 右边（下标 3）
```

**同一个条件对应两种相反结论 ⇒ 这个条件不足以决策。** 用它写出来的算法必错一种，
而且错得很安静（返回值看着也像是个下标）。第 2 幕实测：错版在两个数组上**都错**。

> 附带一条血泪教训（代码注释里也写了）：错版的 `else` 如果写成看似更保守的 `left = mid`，
> 当窗口只剩两格时 `mid == left`，赋值什么都没推进 —— **直接死循环**。
> 错误算法的两种结局：答错、跑飞。所以本节的"错版"被单独关在一个函数里，并保证它一定停机。

### ③ 写法 A：判半区（一次二分搞定）

```
每轮先回答："mid 所在的哪一半是干净的有序段？"
  a[left] <= a[mid]  →  左半 [left..mid] 有序
        target ∈ [a[left], a[mid]) ？ 是→扔右半 : 否→扔左半
  否则               →  断崖在左半，右半 [mid..right] 必然有序
        target ∈ (a[mid], a[right]] ？ 是→扔左半 : 否→扔右半
```

关键认知：**每一轮总有一半是干净的有序段**。二分的底气来自这一句，而不是"整个数组有序"。

### ④ 写法 B：先找 pivot，再用取模"把旋转洗掉"

```
真实下标 = (虚拟下标 + pivot) % n
```

在脑子里把它当回升序数组，跑一份**一字不改的标准二分**，只在每次读 `a[]` 前套一层 `%n`。
好处：二分部分零新代码，读者能直接看出"旋转"这个障碍是被 `%n` 消掉的，不是被更聪明的判断绕过的。

## 逐个操作拆解（对应 ra.c）

| 函数 | 在干什么 | 为什么这么写 | 复杂度 |
|---|---|---|---|
| `ra_dump` | 打印下标行/数值行/断崖行/最小值 | 断崖**看图就会**，先看图再看代码；最小值用**线性扫**，故意不用被测算法，才能当对拍基准 | O(n) |
| `ra_min_index` | 找旋转点 | `while (left < right)` + `right = mid`：lower_bound 那一族模板，**绝不能写 `right = mid - 1`**（会把答案跳过去） | O(log n) |
| `ra_min_index_wrong` | 故意写错的对照组 | 判据换成 `a[mid] vs a[left]`；保证停机，只让它答错 | O(log n) 但**答案错** |
| `ra_min_value` | 只要值 | 内部还是 `ra_min_index`，别写两遍逻辑 | O(log n) |
| `ra_max_index` | 最大值下标 | `(pivot + n - 1) % n`：未旋转时 pivot==0，`pivot-1` 会算出 -1 越界，取模后正好落到 n-1 | O(log n) |
| `ra_rotations` | 旋转了几次 | 就等于最小值下标，**不新写逻辑** | O(log n) |
| `ra_search` | 写法 A 查找 | 见上面图解 ③；`verbose` 打印每轮 left/right/mid/判据/往哪扔 | O(log n) |
| `ra_search_by_offset` | 写法 B 查找 | 先 pivot 再 `%n`；和写法 A 结果必须一致（第 4 幕互验） | O(log n) |
| `ra_search_dup` | 含重复值 | 判据失效时 `left++` / `right--` **扔一个一定不是答案的格子** | 平均 O(log n)，**最坏 O(n)** |
| `ra_search_linear` | 笨办法 | 对拍基准 + 小 n 时它其实更快（无分支预测失败） | O(n) |
| `ra_is_rotated_sorted` | 数下降点 | ≥2 个就不可能是旋转数组；校验器要的是**显然正确**，所以写 O(n) 不写 O(log n) | O(n) |
| `ra_is_strictly_rotated_asc` | 严格版 | `ra_search` 的前置条件：既要不降，又要相邻不等 | O(n) |
| `ra_kth_smallest_index` | 第 k 小 | `a[(pivot + k - 1) % n]`；`k-1` 是"第 1 小"这个人类约定和 0 起点下标之间的桥 | O(log n) |
| `ra_demo_why_left_fails` | 招牌演示 | 两个数组让 `a[left] < a[mid]` 同时成立，把"条件不够用"演成事实 | O(n) |

### 关于"敢不敢扔 `a[left]`"这一句（含重复版的核心）

```c
if (a[mid] == a[left]) { left++; continue; }
```

为什么这一扔**不丢解**？因为这一轮已经确认 `a[mid] != target`，而 `a[left] == a[mid]`，
所以 `a[left]` 也必然 `!= target` —— 扔掉的格子本来就不可能是答案。
这是"信息不足时，先扔一个一定不是答案的元素"的标准套路。

代价：全数组同值、目标不在其中时，每轮只扔一格 ⇒ 轮数 ≈ n ⇒ **退化到 O(n)**。
这不是代码写得烂，是**问题本身的信息量不够**（三个数相等这件事什么也没说）。

## 复杂度一览

| 操作 | 无重复 | 有重复 | 说明 |
|---|---|---|---|
| 找旋转点 / 最小值 / 最大值 / 旋转次数 | O(log n) | O(n) | 重复值让判据失效 |
| 查找目标（写法 A / 写法 B） | O(log n) | O(log n) 平均、**O(n) 最坏** | 写法 B 多一次求 pivot，同数量级 |
| 第 k 小 | O(log n) | O(n) | 对比 `kth-smallest` 的 O(n)：这里"已经排过序" |
| 线性查找（对照组） | O(n) | O(n) | 永远不受重复值影响 |
| 空间 | O(1) | O(1) | 全节不 malloc |

## 运行结果（真跑出来的）

复现：

```
make one DIR=11-searching/rotated-array
```

默认输出 197 行，八幕。节选最能说明问题的三处。

**第 2 幕 —— 判据之争，错版两个数组全错：**

```
    判据「a[mid] vs a[left]」：A 里 3>1 成立，B 里 5>3 也成立 ——
      同一个条件在两个数组上都为真，可答案一个在左（下标 0）一个在右（下标 3）。
      ⇒ 这个条件**不含足够信息**。用它写出来的错版函数跑一下：
        错版 A → 返回下标 1（值 2），正确答案是下标 0（值 1）  ✗ 错！
        错版 B → 返回下标 1（值 4），正确答案是下标 3（值 1）  ✗ 错！

    判据「a[mid] vs a[right]」（本节采用的正确写法）：
        正版 A → 返回下标 0（值 1），3 轮
        正版 B → 返回下标 3（值 1），2 轮
```

**第 4 幕 —— 写法 A 逐步打印，和写法 B 结果必须一致：**

```
    ── 查找目标 1 ──────────────────────────────────
    写法 A（一次二分，边判半区边收缩）：
      第 1 轮  left=0 right=6 mid=3  a[mid]=6  ≠ 1
              a[left]=3 <= a[mid]=6 → 左半 [0..3] 有序，取值 [3..6]
              目标 1 不在 [3, 6) → 扔左半：left = mid+1
      第 2 轮  left=4 right=6 mid=5  a[mid]=1 == 目标 1 → 命中，返回 5
      → 返回下标 5，2 轮
    写法 B（先找旋转点，再 (虚拟+pivot)%7 换算）：
      先花 3 轮找到旋转点 pivot=4（a[4]=0 是最小值），此后按升序虚拟下标二分
      第 1 轮  虚拟[0..6] mid=3 → 真实 (4+3)%7=0  a=3 > 目标 1 → right=mid-1
      第 2 轮  虚拟[0..2] mid=1 → 真实下标 (4+1)%7=5  a=1 == 目标 → 命中
      → 返回下标 5
    两种写法一致吗？ 一致 ✓
```

**第 5 幕 —— 重复值把复杂度打回线性（轮数是实测的）：**

```
      第 6 轮  a[mid]=2 == a[left]=2 → 无法判断 mid 在哪段，扔一格 left++
      第 7 轮  a[mid]=2 == a[left]=2 → 无法判断 mid 在哪段，扔一格 left++
      第 8 轮  a[mid]=3 == a[left]=3 → 无法判断 mid 在哪段，扔一格 left++
      → 99 不存在，返回 -1，但花了 8 轮

    ★ 看这两个轮数：n=5 时轮数=4，n=8 时轮数=8 —— 已经是**线性**的了。
```

其余五幕在说什么，一句话交代：
第 1 幕把三种旋转形态画出来（断崖位置 = 旋转点）；第 3 幕在 `3 4 5 6 0 1 2` 上一次拿到最小值/最大值/旋转次数；
第 6 幕跑六个边界（单元素、未旋转、旋转 n 次、`n=0`/`NULL`、根本不是旋转数组、全相同）；
第 7 幕**穷举 63 组**（7 种旋转形态 × 9 个目标值）拿线性查找对拍，输出 `不一致 0 组 → 全部通过 ✓`；
第 8 幕把第 1..8 小列成一列，值依次是 `1 2 3 4 5 7 9 11` —— 升序，证明"旋转点 + 取模"真的把数组复原了。

## 常见的坑（错法 vs 对法）

**1. 判据用 `a[left]`**
```c
错： if (a[mid] > a[left]) right = mid - 1;     // 一个条件两种结论，静默答错
对： if (a[mid] > a[right]) left = mid + 1;     // 找最小值
```

**2. 把"找最小值"的模板写成"精确查找"的模板**
```c
错： while (left <= right) { ... right = mid - 1; }   // 窗口可能把最小值 itself 扔出去
对： while (left <  right) { ... right = mid;     }   // mid 有可能是答案，必须留在窗口里
```
这两套模板的区别是二分最核心的分水岭，见 `11-searching/binary-search` 那节。

**3. 有重复值时仍然用 `a[left] <= a[mid]` 判半区**
`1 0 1 1 1` 里 `a[left]==a[mid]`，"左半有序"这个推论不成立 ⇒ 可能漏掉 0。
对法：先 `left++` / `right--` 把相等的端点扔掉，再判。并且要接受"最坏 O(n)"。

**4. 忘了 `%n` 的用途，直接 `pivot - 1`**
未旋转时 `pivot == 0`，`pivot - 1 == -1` 越界读。**最大值下标必须是 `(pivot + n - 1) % n`**。
（`+ n` 再取模是为了避免 C 里负数取模的坑：C 的 `%` 结果符号跟被除数，`-1 % 7` 是 `-1` 不是 `6`。）

**5. 不对输入做前置检查就上二分**
`ra_search` 只对"旋转过的**严格**升序数组"有意义。喂进 `3 1 4 1 5` 它照样返回个数字，但那数字没意义。
第 6 幕第⑤条演示了 `ra_is_rotated_sorted` 的作用。工程里：要么先校验，要么在接口注释里写清前提。

**6. 以为"旋转 n 次"和"没旋转"能区分**
两者产生的数组**一模一样**（都是升序），任何算法都区分不了。所以 `ra_rotations` 返回 0 表示
"当前就是升序形态"，不表示"没人转过它"。

**7. 只用两三个用例就宣布写对了**
二分的错通常是**某个具体下标才触发**的。第 7 幕那种穷举对拍（几十行、几秒钟）才是交付标准；
这也是本仓库 `make check` 闸门存在的理由。

**8. 拿 `(left + right) / 2`**
本节数组小，看不出问题；但二分那节用 `INT_MAX-3 .. INT_MAX` 实测过有符号溢出。
统一写 `left + (right - left) / 2`，不用思考，永不吃亏。
