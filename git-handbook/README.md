# Git 大白话手册

> 一本「先跑起来、再懂为什么」的 git 手册。每一章都是同一个套路：**你遇到了什么现场 →
> 该敲哪几条命令 → 屏幕上真实出现了什么 → 背后的机制是什么**。
> 全书输出都是这台机器（git 2.55.0）上真跑出来的，没有一行是手写的、没有一行是"示意"。

---

## 这本书是什么、写给谁

写给正在学 C 语言和数据结构、同时被 git 反复教育的人：命令你抄过不少，但每次报错都靠猜。
这本手册不打算让你背命令，它只做一件事 —— **把「一条 git 命令下去，磁盘上哪几个文件变了」演给你看**。

所以每一章都会出现这些东西：

- `cat-file -p` 打出来的提交对象本体（原来一个 commit 就 4 行）；
- `ls-files -s` / `rev-parse :1: :2: :3:` 打出来的暂存区和冲突三个阶段；
- `.git` 目录里那几根 ref、那个 `index` 文件、那些 objects 的真实样子；
- **命令失败的原文**（含退出码），因为报错原文是证词，不是噪音。

一句话前提：**全书只看一个仓库不够，得跑。** 你读完 05 章觉得自己懂了 rebase，
和你在沙箱里把一条提交 rebase 丢了再用 `reflog` 捞回来，是两种完全不同的会。

## 全书主线：东西在哪三个地方之间移动

```text
   你的编辑器                 git add                  git commit
 ┌──────────────┐  ────────► ┌───────────────┐ ──────► ┌───────────────┐
 │  工作区       │            │  暂存区 index  │         │  仓库 objects  │
 │  磁盘上的文件  │  ◄──────── ┤  一个二进制文件 ├ ──────► │  + refs + HEAD │
 └──────────────┘   restore   └───────────────┘  压缩    └───────────────┘
        ▲
        └── 要撤销/找回的东西在哪一层，决定了该用哪条命令
```

01 章把这三格摆在你面前；02 只管往右搬；03/04/05 管搬错了怎么退；06 管"还没搬的东西先寄存到哪"；
07 管第三格怎么和别人的第三格对齐；08 反过来，从仓库往回查是谁、哪一步、什么时候弄的。
后面每章都遵守同一条问法：**这次要撤销的，在工作区、暂存区、还是仓库里？**

## 怎么跑

每章一个目录，里面固定是 **一份 `demo.sh` + 一份 `README.md`**（README 补写中的章只有 `demo.sh`）。

```bash
cd git-handbook/03-undo
bash demo.sh              # 按 README 小节顺序把全章证据跑一遍，跑完自动删沙箱
bash demo.sh --keep       # 保留沙箱并打印路径，进去自己接着敲
bash demo.sh > /tmp/g03.txt 2>&1   # 重定向时自动关颜色，拿到和 README 一模一样的纯文本
```

现在在场、可以直接跑的清单（在 `git-handbook/` 目录下敲，真输出如下）：

```text
$ ls */demo.sh
01-mental-model/demo.sh
02-daily-commit/demo.sh
03-undo/demo.sh
04-branch-merge/demo.sh
05-rebase-history/demo.sh
06-stash-and-ignore/demo.sh
07-remote-collab/demo.sh
08-investigation/demo.sh
09-submodule-worktree/demo.sh
10-troubleshooting/demo.sh
```

十个全在场。哪一章的 `demo.sh` 不见了，就说明那章还没法复现 —— 这个清单比任何广告词都实在。

`demo.sh` 的设计约定（全书统一）：

- 每段先打 `$ 你要敲的命令`，再打真实输出，最后打 `[退出码 N]` —— 退出码本身是教学内容。
- **故意不加 `set -e`**：一半篇幅是失败现场（`non-fast-forward`、`unmerged files`、`did not match any file`）。
  加了 `-e` 脚本会在第一个故意失败处停住，你就看不到"报错原文 + 后面继续跑"的完整因果。
- 提交时间用一个固定时钟递进，数据是定值，所以**同一台机器重复跑哈希一致**；
  唯一每次都变的是沙箱绝对路径（`/tmp/git-handbook-NN-XXXXXX`）和对象哈希里的路径成分。
- README 里标了"demo 第 N 节"，可以按编号回 `demo.sh` 找到那段命令。

学习节奏建议：**跑 demo → 对着 README 找"哦，这行是这个意思" → 做章末自检问题**。
反过来先读 README 会丢掉"亲眼看到"的效果。

## 全书约定与安全红线

这三本手册（git / ssh / cmake）的实验规矩是一样的：**都在沙箱里，读者可以照抄**。

| 红线 | 具体做法 | 为什么要这样 |
|---|---|---|
| **所有 git 写操作只在 `mktemp -d` 的沙箱里** | 脚本开头 `SB=$(mktemp -d ...)`，`trap` 收尾只删自己刚建的那一个 | 你本机可能有正在干活的仓库；手册绝不碰它，也不碰本手册自己的目录 |
| **绝不写全局配置** | 脚本里没有任何一条写全局的 `git config`（09 章第 0 节里那句 `git config --global --list` 是**只读**，而且 `HOME` 已指向沙箱 `fakehome/`）；`git config` 只带 `--local` 或 `-f .gitmodules`。10 章更进一步：`GIT_CONFIG_SYSTEM` 指到 `/dev/null`，连 `/etc/gitconfig` 都不读 | 你真实的 `~/.gitconfig` 一个字节都不该被教程改到 |
| **不碰 `~/.gitconfig`、不碰 `~/.ssh`** | `HOME` 改写到沙箱里的 `fakehome/`，git 读不到也写不到真的家目录 | 配一次 git 身份看着无害，实际上是在改你所有仓库的行为 |
| **提交身份统一且是假的** | 名字一律 `学习者`，邮箱是占位值（01~09 用 `learn@example.com`，10 用 `learn@example.invalid`）。身份通过每条命令的 `-c user.name=... -c user.email=...` 或环境变量传，**不落任何配置文件** | 手册里的历史是沙箱历史，不该带上真名真邮箱 |
| **绝不联网** | 不 `clone` 远程、不 `push`、不 `fetch` 任何外部地址；需要"远程"时，用 `git clone --bare` 在沙箱里造一个假远程 | 一是复现不依赖网络，二是防止误推。副作用是本地路径会撞上 git 的 file 协议限制，脚本用一次性的 `-c protocol.file.allow=always` 顶开，**这只在沙箱里成立** |
| **文档不出现真实用户名 / 邮箱 / 主机名** | 路径一律写成 `仓库根/章节/文件` 或沙箱里的相对路径；`ls -l` 的属主列、`/home/<用户>`、`uname -a` 的主机名统一替换成 `<用户>` / `<家目录>` / `<主机名>`。第 10 章讲「没配身份就提交」时举的例子也是占位名，不是你机器上的名字 | 手册是要给人抄的，抄进去的东西不该含隐私。注意这是**全书唯一对真输出的替换**，所以引文校验器会在这些行各报 1 行「未匹配」，属预期 |

补一句实话：`git clean -fd`、`git reset --hard`、`git push --force` 这三条在本手册里**只在沙箱里演示**。
06 章讲 `clean` 时甚至只让它报名单（dry-run）不真删。你自己机器上照抄之前，先想清楚
"我删的是不是只有沙箱"。

## 建议阅读顺序

**主线：01 → 02 → 03 → 04 → 05**。这个顺序是硬性的，不是排版习惯：

- 01 不跑，02 的 `MM` `AD` 这些字母就是天书；
- 02 不跑，03 的"撤销到哪一层"没法判断；
- 03 的 `reflog` 是 05 全部实验的安全网 —— 05 章要你故意把历史搞坏再救回来；
- 04 的三方合并和 ours/theirs 是 05 冲突现场的直接前置。

**可以跳的：**

- 只写自己一个人看的笔记仓库：**07、08、09 可以先不看**，但 03 不能跳，10 也不能跳
  （10 讲的就是一个人也会撞上的那六种坏法：游离 HEAD、`index.lock`、身份没配、误删分支、冲突收场、仓库变胖）。
- 从来不改历史，只想别丢代码：**05 可以只读场景 ㉑㉒㉓**（`reflog` 复原），其余回头再看。
- 已经会 stash 的人：06 直接看第 8、9、10 节（忽略规则那部分是全书最容易写错的地方）。
- 08 是工具章，出事了再来查也来得及 —— 但 `bisect` 那一节建议提前跑一遍，因为临场学不会。
- 10 的 README 补完之前：它的 `demo.sh` 现在就能跑，脚本每节开头的注释就是本节要演的事故，
  可以先当"半章"用。

## 这本书没覆盖什么

诚实清单，别指望在这里找到：

- **不联网**，所以 GitHub / GitLab 的网页操作、PR 评审流程、CI 配置一律不讲。
  07 章只讲"远程在 git 层面是什么"，并明确说清 PR 的 squash 在命令层面是哪几步。
- **不讲图形客户端**，不讲 `git gui`、不讲编辑器内置的 git 面板。
- **不碰凭据**：`~/.ssh`、credential helper、token、`insteadOf` 一条都不讲（同系列 ssh 手册另说，
  而且那边同样不写 `~/.ssh`）。
- **不讲大仓库性能**：commit-graph、multi-pack-index、partial clone、`git gc` 调参都只在
  05/08 里作为"对象什么时候真没了"的背景出现一次。
- **不讲钩子**（`pre-commit` 那一套）、**不讲 LFS**、**不讲 `git replace` / grafts**。
- **submodule 只到"够用"**：09 章讲 gitlink、三种脏状态、`update --init`、`deinit` 和 subtree 对比，
  不讲子模块在 CI 里的复杂矩阵。
- 故障自救只到 10 章那八个现场。**浅克隆（`--depth`）、`dubious ownership` 报错、
  objects 真的丢了（`git fsck --full` 报缺对象）、仓库重建、`gc` 卡住、大小写冲突文件名**
  都不在书里；10 章 README 也还在补（见上）。
