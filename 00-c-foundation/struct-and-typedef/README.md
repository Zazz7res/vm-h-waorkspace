# 结构体与 typedef struct-and-typedef

> 上一节你学会了"指针是一张写着门牌号的纸条"。这一节学"盒子"：怎么把好几个数据装进同一个格子组里，
> 怎么用 `typedef` 给盒子起个好记的名字，以及最重要的一件事 —— **怎么造出一个"里面装着下一个盒子地址"的盒子**。
> 最后这个东西就是链表节点、树节点，是后面所有章节的地基，别跳过。

---

## 一句话是什么

结构体 `struct` 就是**把几个相关的变量捆成一组，给这组东西起一个名字**。
`typedef` 是**给类型再起一个好念的外号**，从此 `struct Node` 可以简写成 `Node`。
`.` 和 `->` 是**两把开盒子的钥匙**：手里是盒子本身用 `.`，手里是盒子的地址用 `->`。

一句话串起来：

```c
typedef struct Node { int val; struct Node *next; } Node;
/*   ↑外号        ↑标签    ↑数据字段  ↑指向下一个同类的纸条  ↑外号生效 */
```

这一行写完，单链表的一半难度就消失了。

---

## 为什么需要它

**不用结构体时的痛**（真实会遇到的）：

| 痛处 | 具体长什么样 |
|---|---|
| 一个点要两个变量 | `int x1, y1, x2, y2, x3, y3;` —— 传参时得 `f(x1, y1)`，稍有手滑就写成 `f(y1, x1)`，编译器还不报错 |
| 数据散着，容易漏 | 链表节点要"值 + 下一个地址"两样东西。分开管就是两个数组，插入时要同步挪两个数组，永远有一个忘了挪 |
| 函数只能 return 一个值 | 想同时带回"最大值和下标"？只能造一个全局数组或者塞一堆输出参数，读代码的人一脸懵 |
| 看不懂别人写的链表 | `cur = cur->next;` 这句如果不理解"结构体里有个指针字段"，就完全是在背咒语 |

**用了结构体之后**：

```c
Point p = {3, 1};              /* 一个名字 = 一对数据，整体传递、整体赋值、整体打印 */
move_point_by_pointer(&p, 10, 20);   /* 要改就传地址，不改就传值，意图写在类型上 */
```

而自引用结构让我们能做到 C 里最漂亮的一件事：**用有限大小的盒子，串起无限长的数据**。
节点在内存里东一个西一个都没关系，因为每个盒子里都揣着"下一个盒子的门牌号"。

## 内存布局图解

### 1. 结构体在内存里是"紧挨着的一排格子"（可能有空隙）

```
Point p = {3, 1};                 sizeof(Point) = 8

地址:   +0     +1     +2     +3     +4     +5     +6     +7
      ┌──────┴──────┴──────┴──────┐┌──────┴──────┴──────┴──────┐
      │            p.x = 3        ││            p.y = 1        │
      └───────────────────────────┘└───────────────────────────┘
        &p.x == &p  （首地址）        &p.y == &p + 4
```

**第一个字段的地址永远等于结构体的地址**（C 语言规定），这一点后面算偏移时会反复用到。

### 2. 编译器会"塞垃圾"（padding），所以大小不等于字段相加

```
CharInt  { char c; int n; }        sizeof(CharInt) = 8，不是 5！

地址:   0     1     2     3     4     5     6     7
      ┌─────┬─────┬─────┬─────┬─────────────────────┐
      │  c  │垃圾 │垃圾 │垃圾 │        n            │
      └─────┴─────┴─────┴─────┴─────────────────────┘
        1 字节  ↑ 这 3 格什么都不存，纯粹为了让 n 摆在 4 的倍数地址上
```

为什么要摆 4 的倍数？因为 CPU 读一个 int 时，如果它跨越了 4 字节边界，
某些平台要读两次、慢，另一些平台直接报错。编译器统一按"对齐"排，图快也图安全。

### 3. `.` 与 `->`：一个拿盒子，一个拿纸条

```
    Point origin = {0, 0};          Point *po = &origin;

   po 自己住在 0xB00                origin 住在 0xA00
   ┌───────────────┐                ┌──────────┬──────────┐
   │    0xA00      │ ─── 指向 ───>  │  x = 0   │  y = 0   │
   └───────────────┘                └──────────┴──────────┘
    它是"地址"                        它是"东西"
    所以写 po->x                      所以写 origin.x

   po->x  ←→  (*po).x      完全等价，箭头只是省了括号
   origin->x ❌ 编译错误（origin 不是地址）
   po.x      ❌ 编译错误（po 是指针，它里面只有地址，没有叫 x 的字段）
```

### 4. 结构体数组：肩并肩排

```
   Point pts[5];                 每个 Point 8 字节，所以相邻元素地址差 8

   pts ─> ┌────────┬────────┬────────┬────────┬────────┐
          │(0,0)   │(1,2)   │(2,4)   │(3,6)   │(4,8)   │
          └────────┴────────┴────────┴────────┴────────┘
          +0       +8       +16      +24      +32        总大小 = 5 × 8 = 40
```

### 5. 自引用结构：这才是本节的主角

```
   Node 里装一个 int 和一个 struct Node * —— 用指针而不是 Node 本身，才没有无限套娃

   sizeof(Node) = 16：  int(4) + 垃圾(4) + 指针(8)
                        ↑ 指针必须摆在 8 的倍数地址上，所以 val 后面补了 4 格

   build_node_chain(3, 10) 的结果：

     head
       │
       ↓
   ┌───────┬────────┐      ┌───────┬────────┐      ┌───────┬────────┐
   │val =10│ next   │─────>│val =11│ next   │─────>│val =12│ next   │─────> NULL
   └───────┴────────┘      └───────┴────────┘      └───────┴────────┘
    堆地址 …f020             堆地址 …f040             堆地址 …f060
    （三块 malloc 出来的内存，地址不连续也完全正常，链表不需要连续）

   为什么不能写 struct Node next;（不带星号）？
     Node 里有 Node，Node 里又有 Node……永远算不出 sizeof，编译器直接报错。
   为什么写 struct Node *next; 就可以？
     不管指向多大的东西，指针本身永远是 8 字节，大小能算出来。
   为什么必须写 struct Node 而不能写 Node？
     读到这一行时 typedef 还没结束（别名要等右花括号才生效），
     但标签 struct Node 在左花括号那一刻就登记了，可以先用。
```

## 核心操作逐个拆解

### 操作 1：定义结构体并初始化（`main.c` 第 1 幕）

**干什么**：造出一个"点"这个新类型，并给它塞初值。

**一步步**：
1. 在头文件里写清字段顺序 —— 顺序就是内存里的摆放顺序。
2. 声明时初始化：`Point a = {3, 1};` 按顺序填。
3. 想更清楚就指定成员：`Point b = { .y = 7, .x = -2 };`（顺序随便写，不容易错位）。
4. 想全清零就写 `{0}`：`Point c = {0};`（第一个字段给 0，其余字段 C 语言保证也是 0）。

**边界情况**：
- 不初始化（`Point d;`）在栈上就是垃圾值，本节故意演示，正式代码禁止。
- 初始化时少写几个值（`Point e = {5};`）是合法的：后面的字段自动为 0。
- 字段类型只能是"能算出大小的东西"；结构体内部不能包含自己（见操作 6）。

**对应代码**：`main.c` 第 1 幕，以及 `.h` 里 5 个 `typedef struct ...`。

### 操作 2：用 `sizeof` 量出真实大小（`struct-and-typedef.c` 开头）

**干什么**：别看教程猜，直接问编译器。

**一步步**：`size_of_point()` 之类的函数里 `return sizeof(Point);`，`main` 打印出来。

**边界情况**：`sizeof` 的结果类型是 `size_t`（无符号），打印要用 `%zu`，用 `%d` 会错位。

**对应代码**：`.c` 顶部 `size_of_char_int / size_of_point / size_of_rect / size_of_node`。

### 操作 3：`typedef` 到底省了什么（`main.c` 第 2 幕）

**干什么**：对比"不带别名"和"带别名"两种声明同一个东西要写多少字。

**一步步**：
1. 定义两种：`struct TagPoint { int x; int y; };`（无别名）和 `typedef struct { int x; int y; } Point;`（有别名）。
2. 声明变量、数组、指针、const 指针四件套，各写一遍。
3. 打印 `sizeof` 证明两者在内存里一模一样 —— typedef **不产生任何运行时开销，也不改变布局**，纯粹是给编译器看的名字。

**边界情况**：
- `typedef Point MyPoint; MyPoint x, *y;` —— 展开后是 `Point x; Point *y;`。别名代替的是"类型名"那几个字符，不是整条声明。别以为 `y` 也是点。
- 加了 typedef 之后想改类型（比如 int 换 long），只改定义一处，全项目不动。这是它最大的工程价值。

**对应代码**：`.h` 的 `struct TagPoint` / `Point`，`main.c` 第 2 幕。

### 操作 4：`.` 与 `->`（`main.c` 第 3 幕）

**干什么**：同一块内存，从"东西"和"地址"两个视角访问。

**一步步**：
1. `Point origin = {0,0}; Point *po = &origin;`
2. `po->x = 42;` —— 顺着地址进屋改 x。
3. 打印 `origin.x`，发现也变成 42 —— 因为是同一块内存。
4. 打印 `(*po).x`，和 `po->x` 相同 —— 箭头只是简写。

**边界情况**：
- `po` 是 NULL 时 `po->x` 直接段错误。所有接收指针的函数第一行都是判空，本节函数全都这么写。
- `&origin` 和 `po` 的值相同，但 `&po` 不同 —— 指针自己也住在某个格子里。这一点是二级指针的入口，下一节专门练。

**对应代码**：`main.c` 第 3 幕；`move_point_by_pointer` 里的 `p->x += dx;`。

### 操作 5：结构体数组与整体赋值（操作函数 `init_point_array` / `print_point_array` / `swap_points`）

**干什么**：批量造 n 个点、批量打印、交换两个点。

**一步步**（`init_point_array`）：
1. 参数 `Point pts[]` 会被编译器偷偷改成 `Point *pts`，长度必须额外传 `int n`。
2. 循环 `pts[i].x = i;` —— 因为 `pts[i]` 是"东西"，所以用点。
3. `print_point_array` 里同时用 `pts[i].x` 和 `(pts + i)->x` 打一遍，证明两种写法取到同一个值。

**边界情况**：
- `swap_points` 里 `Point temp = *a;` 是整块 8 字节拷贝。**如果结构体里有指针字段（例如 Node 的 next），这就是浅拷贝**：两个结构体指向同一块内存，随后谁 free 谁埋雷。本节的 Point/Rect 全是 int，所以浅拷贝等同深拷贝。
- `pts == NULL || n <= 0` 直接返回，不做任何事。

**对应代码**：`.c` 的 `init_point_array`、`print_point_array`、`swap_points`；`main.c` 第 4 幕。

### 操作 6：自引用结构 —— 手工搭链、量长度、拆链

**干什么**：`build_node_chain(3, 10)` 造出 `10 -> 11 -> 12 -> NULL`。

**一步步**（`build_node_chain`）：
1. `head = NULL; tail = NULL;`（空的，先立两个指针当"手"）。
2. 循环里 `Node *fresh = malloc(sizeof(Node));` —— **注意是 `sizeof(Node)`，不是 `sizeof(Node *)`**：要装下整个节点，不是装下地址。
3. 判空。失败时先把已经搭好的部分 `node_chain_free(head)` 还回去，再返回 NULL（不还得泄漏）。
4. `fresh->val = ...; fresh->next = NULL;` —— **新节点的 next 必须先置 NULL**，否则它是个随机值。
5. `head == NULL` 说明这是第一个节点，head 和 tail 都指向它；否则 `tail->next = fresh; tail = fresh;`（接到尾巴后面，尾巴往前挪）。

**一步步**（`node_chain_length`）：`for/while` 用 `cur` 往前走，`cur = cur->next`，遇到 NULL 停。
不直接动 `head` 是因为：`head` 是入口，动了就回不去了（虽然是参数拷贝不影响调用者，但函数自己后面就没法再从头走）。

**一步步**（`node_chain_free`）—— 本节最重要的一个技术细节：
```
  cur = head
  每一轮：先把 cur->next 抄到 next_to_keep 里 → free(cur) → cur = next_to_keep
```

**边界情况**：
- 顺序写反（先 `free(cur)` 再 `cur = cur->next`）= 从已归还的内存里读地址 → 悬空指针，ASan 报 `heap-use-after-free`。
- `count <= 0` 返回 NULL；`node_chain_length(NULL)` 返回 0；`node_chain_free(NULL)` 是安全的空操作（循环一次都不进）。
- 尾节点 next 忘了置 NULL：遍历会一路跑到野地址上崩溃。这是链表第一大 bug。

**对应代码**：`.c` 末尾 `build_node_chain` / `node_chain_length` / `print_node_chain` / `node_chain_free`；`main.c` 第 5 幕。

### 操作 7：传整个结构体 vs 传结构体指针（`main.c` 第 6 幕）

**干什么**：一个失败示范 + 一个成功示范 + 一个成本对比。

**一步步**：
1. `move_point_by_value(mv, 10, 20)`：8 字节整块抄进栈，函数里改的是复印件 → main 里的 mv 不动。
2. `move_point_by_pointer(&mv, 10, 20)`：只抄 8 字节的地址，但地址指向同一块内存 → main 里的 mv 真的变了。
3. 成本对比：`Rect` 有 16 字节。`rect_area_by_value(room)` 每次抄 16 字节，`rect_area_by_pointer(&room)` 每次只抄 8 字节。

**边界情况**：
- 传指针必须判空：`move_point_by_pointer(NULL, 1, 1)` 演示了判空保护，不加这一句就段错误。
- 只读的大结构体应该传 `const Rect *`：既省拷贝又写清"我不改"。

**结论一句话**：**能不能改到原件，取决于传没传地址；省不省字节，只是顺带的收益。**

**对应代码**：`.c` 的 `move_point_by_value` / `move_point_by_pointer` / `rect_area_by_value` / `rect_area_by_pointer`。

### 操作 8：嵌套结构（`main.c` 第 7 幕）

**干什么**：`Window` 里装 `Rect`，`Rect` 里装两个 `Point`，三层。

**一步步**：
1. 初始化：`Window win = { { {10,10}, {80,50} }, 7, 1 };` —— 花括号必须一层层对上。
2. 访问：`win.frame.top_left.x`，从左往右读就是"一层层往里开门"，全是点。
3. 取内层的地址：`Point *corner = &win.frame.top_left; corner->x = 999;` —— 指针可以只指向结构体里的**一小块**，合法且常用。

**边界情况**：
- 少写一层花括号：编译器会按顺序把数字往字段里灌，塞错位置，而且经常不报错。用指定成员初始化最保险。
- `sizeof(Window) = 24 = 16(Rect) + 4(id) + 4(layer)`，嵌套不额外收费，就是各部分相加。

**对应代码**：`.h` 的 `Rect` / `Window`；`.c` 的 `print_rect`（演示 `r->top_left.x` 这种"箭头加点"连写）。

## 复杂度表

数据结构这一节还不是"算法"，所以这里的"复杂度"是**内存与拷贝成本**的横向对比。
本机：`int` 4 字节、指针 8 字节。

| 操作 | 成本 | 说明 |
|---|---|---|
| 声明结构体变量（栈上） | O(1)，占 sizeof(类型) 字节 | `Point p;` = 栈上 8 格 |
| 结构体赋值 `b = a` | O(字段总字节数)，整块拷贝 | **有指针字段时是浅拷贝，危险** |
| 访问字段 `p.x` / `p->x` | O(1)，偏移是编译期算好的 | 两者速度完全一样 |
| 传结构体（按值） | O(结构体大小)，每次调用全抄 | `Rect` 每次抄 16 字节 |
| 传结构体指针（按地址） | O(1)，永远抄 8 字节 | **且能改到原件**，一举两得 |
| 结构体数组随机访问 | O(1) | 地址 = 首地址 + i × 8 |
| malloc 一个节点 | O(1)（摊还） | 16 字节；比栈上多一次系统层面记账 |
| 遍历整条链（n 个节点） | O(n) | 每步顺着指针跳，**不能随机访问**，这是链表的代价 |

**和"不用结构体/不用链表"的横向对比**：

| 方案 | 存 3 个点 | 中间插入一个点 | 随机访问第 k 个 | 内存开销 |
|---|---|---|---|---|
| 一堆散装变量 `x1,y1,x2,y2…` | 能，但传不动 | 手动挪一堆 | 靠下标硬记 | 无 |
| 两个并行数组 `int xs[], ys[]` | 尚可 | O(n)，两个数组都要挪 | O(1) | 无指针 |
| `Point pts[]` 结构体数组 | 干净 | O(n)，只挪一处 | O(1) | 无指针 |
| `Node *` 链表 | 干净 | O(1)（已知位置时，只改指针） | O(n)，要顺着走 | 每节点多 8 字节指针 |

（第 2 行的"两个数组永远要同步挪"就是结构体存在的理由；最后一行的取舍就是"01-array 之后为什么要学链表"。）

    sizeof(Node *)  = 8   指针大小和它指向谁无关，64 位机上永远是 8
  ⚠ 顺序会影响大小：把大字段先写、小字段后写，通常能少补几格。

2. typedef：给结构体起个外号，从此不用写 struct
----------------------------------------
  不用 typedef: struct TagPoint tp1 = (1,2)，声明时 struct 关键字必须带着
  用了 typedef: Point p1 = (1,2)，短一半
  没别名时声明一堆名字要写 3 遍 struct：arr_a（24 字节）/ ptr_a=0x7ffca4454298 / readonly_a=0x7ffca44542a0
  有别名后同样三个声明：arr_b（24 字节）/ ptr_b=0x7ffca44542a8 / readonly_b=0x7ffca44542b0，清爽多了
  两种写法在内存里完全一样：sizeof(struct TagPoint)=8, sizeof(Point)=8
  坑：`typedef Point MyPoint; MyPoint x, *y;` —— 这两个一个是点、一个是指针，
      和 `int x, *y;` 一模一样。别名代替的是 Point 那两个词，不是整个声明。
      实测：pr1->x=9（箭头取到的就是 r1.x=9），*pr1 和 r1 是同一块内存
  typedef 另一个价值：以后想给 Point 加个字段，只改定义那一处，
  全项目几十处 `Point p;` 一个字都不用动 —— 这就是“把类型名字”的意义。

3. `.` 用点还是用箭头：看手里拿的是东西还是地址
----------------------------------------
  声明：Point origin;  Point *po = &origin;
  origin 的地址 = 0x7ffca44542c0，po 里存的值 = 0x7ffca44542c0（两者相同），po 自己住在 0x7ffca4454238

     内存里长这样：
       po (在 0x7ffca4454238)          origin (在 0x7ffca44542c0)
       ┌──────────┐        ┌──────┬──────┐
       │ 0x7ffca44542c0 │ ─────> │  0   │  0   │
       └──────────┘        └──────┴──────┘
        它是地址，所以用箭头   它是东西本身，所以用点

  执行 po->x = 42; 之后：
    origin.x        = 42   ← 用点访问原件（main 手里的东西）
    (*po).x         = 42   ← 先解引用拿到东西，再用点：完全等价
    po->x           = 42   ← 箭头就是 (*po).x 的简写，编译器帮你展开
  反过来 origin.y = 7; 之后 po->y = 7 —— 一块内存两个名字，改哪边都算数

  两种写反法（编译器都会拦下来，不会带到运行时）：
    origin->x  ❌ origin 是东西不是地址，箭头没意义
    po.x       ❌ po 是指针，点会被当成"指针自己有个叫 x 的字段"
    po->x 和 (*po).x 二者相同；写哪个看哪个读起来顺，正式代码几乎都用箭头。

## 常见的坑

1. **`typedef struct Node { int val; Node *next; } Node;` —— 少了 `struct` 三个词，编译直接报错。**
   别名 `Node` 要等右花括号之后才存在，定义内部还不认识它。必须写 `struct Node *next;`。
   这是自引用结构第一大坑，几乎每个人第一次都会踩。

2. **`malloc(sizeof(Node *))` —— 只申请了一个指针的大小（8 字节），却要往里塞 16 字节的节点。**
   越界写堆，ASan 会报 heap-buffer-overflow。正确写法是 `malloc(sizeof(Node))`，
   或者更抗改的 `malloc(sizeof *fresh)`（拿指针指向的东西的大小，以后类型换了也不用改代码）。

3. **新节点的 `next` 忘了置 NULL。** 它里面是上一块内存留下的随机值，
   遍历时会一路飞到野地址上崩溃。规则：**造节点的三件套 = 申请、填值、断尾**，一步都不能少。

4. **`free` 之后继续 `cur->next`。** 拆链时把顺序写反（先 free 再读 next）就是悬空指针。
   永远"先把下一个地址抄下来，再拆当前"。

5. **以为赋值是复制内容，结果复制的是地址（浅拷贝）。**
   `Node a = b;` 之后 `a.next` 和 `b.next` 指向同一个节点；`Rect`、`Point` 里全是 int，
   赋值才是真的整块复制。判断标准：**结构体里有指针字段，赋值就得想清楚深浅。**

6. **`typedef Point MyPoint; MyPoint x, *y;` 以为 `y` 也是点。**
   `typedef` 代替的只是类型名，`*` 是那条声明自己带的。一个声明里混写变量和指针，永远容易看错 ——
   好习惯：**一行只声明一个变量**。

7. **传结构体想改原件。** 见第 6 幕反面教材：`move_point_by_value` 在函数里改得热火朝天，
   main 里的值一动不动。结构体再小也是拷贝，改必须传指针。

8. **靠"字段大小相加"猜 `sizeof`。** `char + int` 不等于 5，等于 8。
   要算内存占用、要做序列化、要 `malloc` 自定义结构，一律以 `sizeof` 为准。

## 什么时候用它 / 什么时候别用

**该用结构体的场合**：
- 好几个数据天生成一组，总是一起传递（点、矩形、边、树节点、栈的 `data+size+capacity`）。
- 需要"自引用"来做链表 / 树 / 图的邻接表。
- 一个函数想带回多个结果 —— 打包成一个结构体 return，比一堆 `_out` 参数好读。

**别用（或别急着用）的场合**：
- 只有一个数：用 `int` 就好，包一层 struct 只是给自己加 `.`。
- 只是临时算几个值：局部变量比"造一个类型"更直白。
- 想追求极致缓存命中、又要传很大块数据：先考虑"传数组 + 长度"这种朴素形式，
  别一上来就设计几十层嵌套结构（本节 `Window` 三层已经是极限演示）。
- 现阶段**不要**在结构体里塞 `void *` 想做泛型 —— 本仓库刻意不做泛型，元素类型一律 int。

## 自检问题

1. `typedef struct Node { int val; struct Node *next; } Node;` 这一行里，`struct Node` 一共出现两次，各起什么作用？
   **答：** 第一次（`struct Node {`）是给这个结构体登记"标签"，同时开始定义内容；
   第二次（`struct Node *next;`）是在内容里引用"同一个标签"，因为此时别名 `Node` 还不存在。
   第三次出现的 `Node`（右花括号后面）才是 typedef 造的别名。

2. 为什么 `struct Node { struct Node next; };` 编译器会拒绝？
   **答：** 大小无法确定：Node 里有一个完整的 Node，里面又有一个完整的 Node……无穷递归。
   改成 `struct Node *next;` 之后，字段大小固定是 8 字节，`sizeof(Node)` 立刻能算出来。

3. `p->x = 1;` 和 `(*p).x = 1;` 有区别吗？手里是结构体变量时能不能写 `p->x`？
   **答：** 两句完全等价，箭头就是"先解引用再取成员"的语法糖。
   手里是变量（东西）时**不能**用箭头，`origin->x` 是编译错误；反过来 `po.x` 也是错误（除非 po 本身真是结构体）。

4. `void f(Point p)` 与 `void f(const Point *p)`，哪个能改到调用者的变量？哪个更省？
   **答：** 两个都不能改（第一个改复印件；第二个 `const` 承诺不改）。
   想改必须是 `void f(Point *p)`。省不省看结构体大小：`Point` 8 字节时差距不明显，`Rect` 16 字节时指针版本只抄 8 字节。

5. 拆链表时为什么必须"先记下 `cur->next` 再 `free(cur)`"？
   **答：** `free(cur)` 之后，`cur` 指向的那 16 字节已经还给堆管理器，`cur->next` 是从归还的内存里读值 ——
   悬空指针 / 未定义行为。ASan 会报 `heap-use-after-free`。

6. `sizeof(CharInt)` 为什么是 8 而不是 5？
   **答：** `int` 要求自己的地址是 4 的倍数，所以 `char` 后面被塞进 3 格 padding；
   同时整个结构体大小还要是最大对齐值（4）的整数倍，8 正好。
