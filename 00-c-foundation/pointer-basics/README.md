# 指针基础 pointer-basics

> 这是整个项目的**第一节**。链表、树、图全都建立在指针之上。
> 这一节不写任何数据结构，只把「指针到底在干什么」讲透。讲透之后，后面每一章都会顺很多。

---

## 一句话是什么

指针就是一个**存着地址的变量**。地址是内存格子的编号，指针就是那张写着编号的纸条。

有了它，函数之间就能做到两件本来做不到的事：
1. **改到调用者自己的变量**（而不是复印件）
2. **把一块可以随意增删的内存交给别人继续用**（堆内存）

---

## 为什么必须先懂它

后面这些代码，看不懂指针就完全看不懂：

| 后面的章节 | 它其实只是在干这件事 |
|---|---|
| 单链表 `node->next = new_node;` | 把"下一个节点的地址"写进当前节点的纸条里 |
| 动态数组 `realloc(arr, ...)` | 换一块更大的堆内存，把老数据搬过去 |
| 二叉树 `insert(Node **root, int v)` | 要用二级指针，因为"根节点地址"本身也得被改到 |
| 图的邻接表 | 一堆指针数组，每个格子里是一个链表头 |
| 并查集 / 哈希表 | 本质都是数组 + 指针 |

**所以现在多花 30 分钟，等于给后面所有章节 prepaid。**

## 背景知识：内存分三块地

程序运行时，内存大致被切成三块，理解它们的**生命周期**是避免 bug 的关键：

```
高地址 ┌─────────────────────────┐
       │  栈 stack               │  ← 局部变量、函数参数活在这里
       │  · 函数调用时自动分配    │     函数一返回，自动销毁
       │  · 函数返回时自动回收    │     ⚠ 所以不能返回局部变量的地址
       ├─────────────────────────┤
       │  ↓ 越用越小              │
       │                         │
       │  ↑ 越用越大              │
       ├─────────────────────────┤
       │  堆 heap                │  ← malloc 申请的内存在这里
       │  · 你自己 malloc         │     你不 free，它就一直占着
       │  · 你自己 free           │     ⚠ 忘了 free = 内存泄漏
       ├─────────────────────────┤
       │  全局 / 静态区           │  ← 全局变量、static 变量
       │  · 程序结束才消失         │
       ├─────────────────────────┤
低地址 │  代码段（指令本身）      │
       └─────────────────────────┘
```

一句话记忆：**栈是临时工位，堆是租来的仓库，全局是自家院子。**
仓库租了要还，不还就欠费（泄漏）；临时工位下班自动清，你留的东西会被保洁扔掉（悬空指针）。

## 核心概念逐个拆

### 1. `&` 取地址，`*` 解引用

```c
int x = 3;
int *p = &x;    // &x：拿 x 的地址；p 是指针，存着这个地址
*p = 10;        // *p：顺着地址找到那个格子，把 10 写进去
printf("%d", x); // 打印 10 —— x 被真的改了
```

三个符号的读法，**永远这么念就不会错**：

| 写法 | 念法 | 含义 |
|---|---|---|
| `&x` | "x 的地址" | 拿到门牌号 |
| `p`   | "p 里存的地址" | 纸条上的门牌号 |
| `*p`  | "那个门牌号里的东西" | 顺着地址进屋拿东西 |

⚠ 注意 `int *p` 里的 `*` 是**声明**用的，表示"p 是指针"，和 `*p` 的"解引用"是两回事，只是共用了符号。

### 2. 值传递：函数拿到的是复印件

C 语言**所有**参数传递都是拷贝。这一点必须刻进脑子里：

```
main:      x = 3        y = 5
             │            │
             ↓ 拷贝值      ↓ 拷贝值
函数内:     a = 3        b = 5
```

在函数里把 `a`、`b` 交换得再开心，`main` 里的 `x`、`y` 纹丝不动。
代码里 `swap_by_value()` 就是这个错误的活标本，跑起来能亲眼看到"函数内换了，函数外没换"。

### 3. 指针传递：把门牌号告诉函数

```
main:      x = 3 (地址 0x100)      y = 5 (地址 0x200)
             ▲                       ▲
             │ 传的是地址             │ 传的是地址
函数内:     a = 0x100               b = 0x200
            *a 就是 x 本身           *b 就是 y 本身
```

地址本身也是被拷贝了一份，但**拷贝的地址仍然指向同一块内存**，所以 `*a = ...` 直接改到外面。
这就是为什么链表插入函数长这样：`insert(Node **head, int value)` —— 它要改的是"头指针"，那就得传头指针的地址。

### 4. 输出参数：一个函数想带回两个值

`return` 只有一个口子。C 语言的标准做法：主结果用 `return`，次要结果让调用者**先给一个地址**，函数往里写。

```c
int remainder;                        // 我提供一间空屋子
int q = divide_with_remainder(17, 5, &remainder);  // 函数往屋子里写了 2
// q = 3，remainder = 2
```

约定：参数名后缀写成 `_out` 表示"这是我往里写的出口"，`NULL` 表示"这个结果我不要"。

### 5. 数组名会"退化"成指针

```c
int data[] = {1, 2, 3, 4, 5};
data[i]        // 人话：第 i 个
*(data + i)    // 机器视角：从首地址往后走 i 格
```

**两者完全等价**，`[]` 只是 `*( + )` 的语法糖。

由此产生 C 语言最经典的陷阱：

```c
void bad(int arr[]) {
    printf("%zu", sizeof(arr));   // ❌ 打印 8（指针大小），不是数组总字节数
}
```

数组一旦作为参数传递，就只剩下"首地址"，长度信息全丢了。
所以 **传数组必须连长度一起传**，`sum_array(const int *arr, int n)` 的第二个参数就是这么来的。
`const` 是承诺："我只读不改"，写错了编译器立刻报错。

在数组出生的地方才能算长度：

```c
int n = (int)(sizeof(data) / sizeof(data[0]));   // 5 —— 只在 main 里有效
```

### 6. malloc / free：堆内存归你管

想让函数造一个数组、返回给外面继续用，**绝对不能**这样：

```c
int *wrong() {
    int local[10];     // ❌ 栈上的，函数一返回就被回收
    return local;      //    返回的是"已被保洁收走"的工位地址 → 悬空指针
}
```

正确做法是去堆上租：

```c
int *arr = malloc((size_t)n * sizeof(int));  // 申请 n 个 int 的字节数
if (arr == NULL) { /* 租不到，必须判空 */ }
...
free(arr);      // 用完还回去
arr = NULL;     // 还完立刻把纸条撕掉，防止再拿旧地址去买菜
```

`free` 之后指针变量还在，但它指向的内存已经不属于你了 —— 这叫**悬空指针（dangling pointer）**。
继续使用是"未定义行为"：可能读到垃圾值，可能崩溃，可能看起来没事但某天诡异出错。
把它置 `NULL` 之后，误用会**立刻崩溃**，问题当场暴露，比"悄悄算错"好一万倍。

## 图解：一次 swap 的完整过程

```
调用 swap_by_pointer(&x, &y) 之前          调用之后
┌──────┬──────┐  ┌──────┬──────┐           ┌──────┬──────┐  ┌──────┬──────┐
│  x   │  y   │  │  a   │  b   │           │  x   │  y   │  │  a   │  b   │
│  3   │  5   │  │ 0xA  │ 0xB  │           │  5   │  3   │  │ 0xA  │ 0xB  │
└──▲───┴──▲───┘  └──┬───┴──┬───┘           └──▲───┴──▲───┘  └──┬───┴──┬───┘
   │0xA   │0xB      │      │                  │0xA   │0xB      │      │
   └──────┼─────────┘      └────────┐         └──────┼─────────┘      │
          └───────────────┐         │                └───────────────┐│
                       temp=3     *a=*b → x=5                     temp=3
                       *a=*b → x=5                                 *a=*b → x=5
                       *b=temp → y=3                               *b=temp → y=3
```

关键：`temp` 那一行**必须先做**。如果先写 `*a = *b`，原来 `*a` 里的 3 就被覆盖丢了。

## 五个必踩的坑

1. **忘记加 `*`**：`int *p; p = 100;` 把 100 当地址存进去了，随后 `*p` 直接段错误。
2. **返回局部变量地址**：函数一返回，栈帧就被回收，返回的指针指向垃圾。
3. **malloc 后不判空**：内存不够时返回 `NULL`，不判空就是解引用空指针。
4. **free 后继续用**：悬空指针。修不干净时先 `p = NULL`，让它当场崩，别让它潜伏。
5. **free 两次（double free）**：`free(p); free(p);` 会破坏堆管理器，程序直接 abort。
   第 4 条的置 `NULL` 顺便解决了这条，因为 `free(NULL)` 是合法的空操作。

这五个坑，`make asan`（AddressSanitizer）能全部抓到。以后每写完一个数据结构，先跑一遍 `make asan`。

## 自检问题

1. `void f(int *p) { p = malloc(sizeof(int)); }` 这样调用后，`main` 里的指针能拿到内存吗？
   **答：不能。** `p` 是拷贝，改 `p` 本身改不到外面。要改外面指针得传 `int **pp`。
2. 为什么链表删除函数常写成 `void delete_node(Node **head, int value)` 而不是 `void delete_node(Node *head, int value)`？
   **答：** 因为删的可能是头节点，头指针本身要变。要改到"头指针"，就得传它的地址。
3. `sizeof(arr)` 在 `int arr[10]` 的 `main` 里是 40，在 `void f(int arr[])` 里却是 8，为什么？
   **答：** 参数里的数组退化成指针，长度信息没传进来，`sizeof` 只能看到指针本身。
4. `malloc(10)` 能存 10 个 int 吗？
   **答：不能。** `malloc` 的单位是字节，10 字节只够 2 个 int（在 4 字节 int 的平台上）。要写 `malloc(10 * sizeof(int))`。
5. `free(p)` 之后 `p` 的值还在吗？
   **答：** 还在（地址数值没变），但它已经是非法地址了。这就是悬空指针。
