# 单调栈 monotonic-stack

> 给栈加一条「栈内必须保持单调」的纪律，于是很多「每个元素都要往两边看」的题目变成一次遍历 O(n)。

---

## 一句话是什么

**单调栈 = 普通栈 + 一条纪律：从栈底到栈顶，值必须一路递减（或一路递增）。**
纪律不是靠检查维持的，而是靠 **push 之前不停地弹栈** 维持的：新元素一来，
凡是「比它小（大）的栈顶」全部弹掉，弹到纪律恢复为止，再压入新元素。
妙处在于：**被弹出去的那一刻，正好就是它的 answer 被确定的那一刻。**

本节的两大应用：
1. **下一个更大元素**：对每个位置 i，求它右边第一个严格比 `nums[i]` 大的数，没有就填 -1。
2. **柱状图接雨水（简单版）**：给定每根柱子的高度，求雨后方格总共有多少水、每根柱子上各有几格。

---

## 为什么需要它

先看**不用单调栈**（暴力法）的痛，本节的运行结果里把两种方法的**操作次数真的数出来**了：

| 输入（n=10） | 暴力法比较次数 | 单调栈操作次数 |
|---|---|---|
| 递减序列 `10 9 … 1`（暴力最坏） | **45** = n(n-1)/2 | 10（只入栈，0 次出栈） |
| 乱序 `5 3 8 1 4 7 2 6 9 0` | 17 | 18 |
| 递增序列 `1 2 … 10` | 9 | 19 |

看第 1 行就够了：暴力法在递减输入下要把 45 对数字比完，n=1000 时是 **50 万次**，
而单调栈的上界永远只有 **2n**。这就是「需要它」的全部理由：
**暴力法把「这个数还没等到答案」这件事重复检查了很多遍，单调栈把它存进了栈里，只等一次。**

| 场景 | 不用的痛 | 用单调栈 |
|---|---|---|
| 「每个元素的下一个更大元素」 | 每个 i 往右扫，O(n²) | 一次遍历，O(n) |
| 「柱状图接雨水」 | 要么每个位置求左右最大值（O(n) 但另开两个数组），要么双指针绕来绕去 | 一个栈顺带把「左右两堵墙」都记住了 |
| 「柱状图里最大的矩形」 | 枚举每条边界 O(n²) 起 | 递增栈一次扫描，LeetCode 84 的标准解 |
| 「每日温度：等几天才升温」 | 双重循环 | 递减栈，弹出时 `i - j` 就是天数 |
| 「数组里最小的子数组…、下一个更小…」 | 排序 + 额外结构 | 递增栈，把比较号反过来 |

**不用它时真正的问题不是「慢」，而是「想不出怎么下手」**：暴力法没有"待办清单"的概念，
而单调栈就是这个待办清单 —— 栈里的每个下标都是一个「还没等到答案的问题」。

## 内存布局图解

普通数组栈的图是「一摞盘子」；单调栈还要在盘子旁边写上「这些是我还没答案的问题」：

```
  nums = [5, 3, 8, 1, 4, 7, 2]      栈里存【下标】，纪律：nums[值] 从底到顶递减

  i=0 来了 5    栈: [ (0:5) ]                         待办：下标0 还没等到更大的
  i=1 来了 3    栈: [ (0:5) (1:3) ]     ← 3 < 5，可以放进来；待办 +1
                栈底→                 栈顶
                 值一路变小 ✔

  i=2 来了 8    ① 8 > 3 → 弹 (1:3)，ans[1] = 8   ✔ 下标1 的问题解决了
                ② 8 > 5 → 弹 (0:5)，ans[0] = 8   ✔ 下标0 的问题解决了
                ③ 栈空，压 (2:8)
                栈: [ (2:8) ]

  i=3 来了 1    压入 → 栈: [ (2:8) (3:1) ]
  i=4 来了 4    ① 4 > 1 → 弹 (3:1)，ans[3] = 4
                ② 4 < 8 → 停，压 (4:4) → 栈: [ (2:8) (4:4) ]     ← 还是递减 ✔
  i=5 来了 7    ① 7 > 4 → 弹 (4:4)，ans[4] = 7
                ② 7 < 8 → 停，压 (5:7) → 栈: [ (2:8) (5:7) ]
  i=6 来了 2    压入 → 栈: [ (2:8) (5:7) (6:2) ]

  扫描结束，栈里还剩 3 个（下标 2、5、6）→ 它们右边确实没有更大的，ans 保持 -1
  ans = [8, 8, -1, 4, 7, -1, -1]

  ★ 画面记忆法：栈里躺着的都是「还在排队等问题的人」，
    新来的数一次能把排在前面的好几个人的问题一起解决（连着弹栈），
    而被解决过的人绝不会再回来排队 —— 这就是「每个元素最多进出各一次」。
```

### 接雨水的内存图（为什么栈里要留「左墙」）

```
  height = [4, 2, 0, 3, 2, 5]，递减栈存「柱子下标」，比较的是高度

   4 █
     |  ██                 下标 0(高4) 1(高2) 2(高0) 一路压进栈（递减成立）
   3 █  ███
     |  █████              i=3 来了高 3 的柱子 → 栈顶 2(高0) 比它矮 → 有槽！
   2 █  █████
     |  ███████            结算①：弹出槽底 2(高0)；新的栈顶 1(高2) 就是【左墙】；i=3 是右墙
   1 ██████████               宽 = 3-1-1 = 1，深 = min(2,3) - 0 = 2 → 水 2，落在柱子 2
     0  1  2  3  4  5
                            结算②：栈顶 1(高2) 还是比 3 矮 → 再弹：槽底=1，左墙=0(高4)，右墙=3
                               宽 = 3-0-1 = 2，深 = min(4,3) - 2 = 1 → 水 2，落在柱子 1、2
                            结算③：栈顶 0(高4) >= 3 → 停，压 3

  ★ 弹完再看一眼栈：新的栈顶就是「左边的墙」，当前的 i 就是「右边的墙」。
     如果弹完栈空了 → 左边没有墙，水会从左边流光，这一槽直接作废（代码里 break）。
     所以「水槽」这个二维信息（宽度、左边界）全靠栈里剩下的下标提供，
     这就是【为什么存下标不存值】最硬的证据。
```

（运行结果里每根柱子的水量、以及 `█=柱子 ░=水` 的分层示意图都打印出来了。）

## 核心操作逐个拆解

### 1. `MiniStack`（本目录自带的极小 int 栈）

**干什么**：给单调栈提供 5 个动作 —— `mini_init / mini_push / mini_pop / mini_peek / mini_destroy`（外加 `mini_is_empty / mini_size`）。

**为什么在本地再写一份，而不是 `#include "../array-stack/astack.h"`**：
**硬性约定：每个叶子目录必须自包含。** Makefile 是按目录独立编译的（`gcc <目录>/*.c`），
没有 `-I..`，跨目录 include 会直接编译失败。栈和队列、单调栈和普通栈常常互相配合，
所以本仓库的做法统一是「在自己目录里复制一份需要的最小实现」。
这里复制的代价只有 40 行，换来两件事：① 能编译；② 不需要扩容（栈最多同时装 n 个下标，
一次 `malloc(n)` 到位，从此没有「栈满」这个失败分支，读代码时更聚焦单调性本身）。

**`top` 的表示**：`top = -1` 表示空栈 —— 和 `array-stack` 的流派 A 保持一致。

**对应代码**：`mstack.c` 顶部到 `mini_print_with_values` 为止。

---

### 2. `mini_print_with_values(s, nums, label)` —— 为什么打印要连值一起打

**干什么**：把栈里的下标连同 `nums[下标]` 一起打成 `(下标:值)` 序列。
**为什么必要**：单调纪律是加在【值】上的，我们存的却是【下标】；只打下标看不出「是不是真的递减」，
每步打印值就是在自动验证纪律。
**边界**：空栈打印 `(空)`。这是教学辅助，正式实现里没有。

---

### 3. `mstack_next_greater(nums, n, ans_out)` —— 应用①

**干什么**：对每个 i，把「右边第一个严格更大的数」写进 `ans_out[i]`，找不到保持 -1。

**一步步**（对每个 i）：
1. **清理**：`while (栈非空 && nums[栈顶] < nums[i])` → 弹出栈顶 j，写 `ans_out[j] = nums[i]`，并打印"ans[j] 是怎么来的"。
2. **压入**：把 i 压栈（它的答案暂时是 -1，等着后面有更大的来认领）。
3. **收尾**：扫完后栈里剩下的下标全部保持 -1，并把这些"欠着的"打印出来。

**边界情况**：
- `nums == NULL` / `ans_out == NULL` / `n <= 0`：直接返回（静默版还会把计数置 0）。
- `ans_out` 先全部填 -1：这是「找不到」的默认值，被弹到才覆盖。
- 数组递减：`while` 一次都不进，栈长到 n，答案全 -1（第 2 幕专门演示）。
- 相等：条件用的是严格 `<`，所以相等**不弹** → 求的是「严格更大」。想改成「≥」把符号换成 `<=` 即可。

**复杂度**：时间 O(n)（入栈恰好 n 次、出栈 ≤ n 次），空间 O(n)。

**对应代码**：`mstack.c` 的 `nge_core`（真实现）+ `mstack_next_greater` / `mstack_next_greater_counted` 两个外壳。

---

### 4. `mstack_next_greater_counted(...)` —— 静默计数版

**干什么**：同一个 `nge_core`，`verbose = false`，只把入栈/出栈次数通过输出参数带出来。
**为什么要它**：第 4 幕要和暴力法比次数，刷屏会把表格冲掉；而「演示版」和「计数版」必须是同一份代码，
否则读者会怀疑你比的是两套逻辑。`push_count_out` / `pop_count_out` 允许传 NULL（C 里"这个结果我不要"的标准写法）。

---

### 5. `mstack_trapping_rain_water(height, n)` —— 应用②

**干什么**：逐层结算水槽，打印每层水落在哪几根柱子上，最后给出每根柱子的水量 + 总量 + 示意图。

**一步步**（对每个 i）：
1. `while (栈非空 && height[栈顶] < height[i])`：
   - `bottom = 弹出栈顶`（槽底那根柱子）；
   - **弹完先看栈是不是空了**：空了 → 左边没有墙，水从左边流光，`break`；
   - `left = 新的栈顶`（左墙），`i` 是右墙；
   - `宽度 = i - left - 1`，`水深 = min(height[left], height[i]) - height[bottom]`；
   - 本层水量 `= 宽度 × 水深`，累加到总量，并把 `水深` 这一格加到 `left+1 … i-1` 每根柱子的头上；
   - 继续 while（可能叠好几层，像上楼梯）。
2. `mini_push(i)`。

**边界情况**：
- 弹完栈空 → 无左墙，接不住（代码里明确打印这一情况）。
- 水深可能为 0（左墙和槽底一样高的平台）→ 不加水，但要打印说明。
- 宽度为 0（左墙和右墙紧挨着）→ 不加水。
- 最后留在栈里的柱子不用再算：它们右边没有墙。
- `n == 1` / `n == 0`：不可能有水，函数照走完流程并打出 0。
- 总量用 `long` 累加：`宽度 × 水深` 连加可能超 int，顺手示范"算总数前先想想会不会溢出"。
- **自检**：函数最后把「逐根相加的水量」和「结算时累加的总量」两个数都打出来，两者必须相等。

**对应代码**：`mstack.c` 的 `mstack_trapping_rain_water`。

## 复杂度表

| 做法 | 时间 | 额外空间 | 备注 |
|---|---|---|---|
| 暴力：每个 i 往右扫（下一个更大元素） | 最坏 **O(n²)**，最好 O(n) | O(1) | 递减输入就是最坏，实测 n=10 时 45 次比较 |
| **单调栈：下一个更大元素** | **O(n)** | O(n)（栈 + 答案数组） | 入栈 n 次、出栈 ≤ n 次 |
| 暴力：每个位置求左右最大值（接雨水） | O(n²)（不优化） | O(1) | |
| DP 预处理左右最大值（接雨水） | O(n) | **O(n)×2**（leftMax/rightMax 两个数组） | 也很好，但学不到「栈存待办」这个思路 |
| **单调栈：接雨水** | **O(n)** | O(n)（栈）+ O(n) 水量数组（教学打印用） | 逐层结算，宽×深 |
| 普通数组栈（`array-stack`）单操作 | O(1) | O(capacity) | 没有「弹栈即答案」的语义 |
| 链表栈（`linked-stack`）单操作 | O(1) 严格 | O(n) 节点 | 单调栈不用它：遍历打印/取值都更方便 |

**为什么单调栈是 O(n)** —— 用一句话讲完，再用运行结果里的数字验证：
> 外层 for 固定 n 步；内层 while 只在弹栈，而每个下标一生最多入栈 1 次、出栈 1 次，
> 所以全部 while 加起来 ≤ n 次。**总操作 ≤ 2n**，这就是 O(n)。
> 数「总操作次数」而不是「数两层循环」是分析单调栈的唯一正确姿势。

运行结果第 4 幕的表格里：`入栈次数永远 = n`，`出栈次数 ≤ n`（递减序列那一行出栈是 0，
因为没有任何新元素比栈顶大，谁也没被弹出去）。

## 运行结果

```text

第 1 幕：应用①「下一个更大元素」（逐步打印栈的变化）
========================================
  输入 nums = [5, 3, 8, 1, 4, 7, 2]，栈里存【下标】，保持 nums[下标] 从底到顶【递减】

  ── 第 0 步：来了 nums[0] = 5 ─────────────────

  ── 第 2 步：来了 nums[2] = 8 ─────────────────

      把下标 4 压入栈（它的答案暂时是 -1，等后面有更大的来认领）
    压入后  size=2：栈(底→顶) (2:8) (4:4)

    压入后  size=2：栈(底→顶) (2:8) (5:7) 

  ── 第 6 步：来了 nums[6] = 2 ─────────────────
      栈顶是下标 5（值 7），7 >= 2 → 递减纪律还在，停止弹栈
      把下标 6 压入栈（它的答案暂时是 -1，等后面有更大的来认领）
    压入后  size=3：栈(底→顶) (2:8) (5:7) (6:2) 

  扫完了。栈里还欠着答案的下标有：2(值8) 5(值7) 6(值2) → 它们的 ans 保持 -1。

  最终答案 ans = [8, 8, -1, 4, 7, -1, -1]
  操作计数：入栈 7 次 + 出栈 4 次 = 11 次（n=7，最多 2n=14）→ 这就是 O(n) 的来历
  注意：出栈次数 4 最多等于元素个数 7，扫完还留 3 个在栈里没被弹出。

  对着上面重讲一遍这幕的三个看点：
    1) 栈里存的永远是【下标】。弹出下标 j、写入 ans[j] = 新来的值 —— 位置必须靠下标。
    2) 「一个元素被弹出去」的那一刻，就是它的下一个更大元素被找到的那一刻。
    3) 扫完还留在栈里的元素，答案保持 -1：它们右边确实没有更大的了。

========================================
第 2 幕：极端情况：数组一路递减（栈会涨到最长，答案全是 -1）
========================================
  这种输入下 while 一次都不会执行（新值总比栈顶小），栈从 1 个涨到 5 个：

第 4 幕：单调栈凭什么是 O(n) —— 和暴力法数同样的输入
========================================
  两种做法都跑同样的输入（静默版，不打印过程），把操作次数数出来：
  输入长度 n = 10

    输入形状    暴力比较次数   单调栈入栈  出栈   合计   答案是否一致
    ---------  ------------  --------  ----  -----  ----------
    递减序列       45 次          10       0      10   一致 ✔
    递增序列        9 次          10       9      19   一致 ✔
    乱序序列       17 次          10       8      18   一致 ✔

  读这张表的三个要点：
    1) 【递减序列】是暴力法的最坏情况：每个数都要一路看到数组末尾才发现没有更大的，
       比较次数 = n(n-1)/2 = 45，正好是 n=10 时的理论上限；单调栈只做了 10 次入栈、0 次出栈。
    2) 【一路递增】反过来：暴力法每次看一眼就 break，比较 n-1 = 9 次；
       单调栈要把前一个全部弹光才压新的，出栈 n-1 次 → 合计 19 次。所以「比大小」不是重点，
       重点是【上界】：暴力的最坏是 n²/2 量级，单调栈永远是 2n 量级，谁都会被谁压住。
    3) 入栈次数【永远等于 n】（每个下标恰好被压一次），出栈次数【永远 ≤ n】。
       n=1000 时：暴力最坏约 50 万次比较，单调栈最多 2000 次操作。

  把道理说透：
    · 外层 for 一定走 n 步 —— 这是固定的。
    · 内层 while 只在【弹栈】，而每个下标一生最多被弹 1 次（弹掉就再也不回来了）。
    · 所以内层「总共」最多执行 n 次。单次可能弹好几个，但全局有上限 —— 这就叫【摊还 O(1)】，
      合起来就是 O(n)。数「总操作次数」而不是数「两层循环」，是分析单调栈的唯一正确姿势。

  为什么栈里必须存下标而不是值？
    如果存值，弹出时只知道「这个数有了答案」，却不知道它原来在第几格，
    ans[] 就没法写；接雨水那题更极端，宽度 = i - left - 1 全靠下标相减。
    值随时能用 nums[idx] 取回来，下标一丢就彻底找不回来 —— 所以存下标。

  递减栈 / 递增栈怎么选？
    求「右边第一个更大」→ 递减栈（新值大就弹小的，本幕演示的）
    求「右边第一个更小」→ 递增栈（把比较号反过来写 nums[top] > nums[i] 就行）
    求「左边第一个更大」→ 还是递减栈，从右往左扫；或者柱状图最大矩形那种双向用法

=== 本节结束 ===
记住四句话：
  1) 单调栈 = 普通栈 + 「栈内保持单调」这条纪律；纪律是靠 push 前不停地弹栈维持的。
  2) 弹栈那一下通常就是答案诞生的那一下（谁被弹出，谁就找到了它要的答案）。
  3) 栈里存【下标】不存值：位置和宽度都要靠下标算，值可以 nums[idx] 现取。
  4) 每个下标最多进出各一次 → 总操作 ≤ 2n → O(n)。别盯着两层循环就喊 O(n²)。
```

## 常见的坑

1. **栈里存值而不是下标**。存值的话弹出时只知道"这个数有答案了"，却不知道它在第几格，
   `ans[]` 没法写；接雨水那题宽度 `i - left - 1` 更是全靠下标相减。
   **口诀：值随时能 `nums[idx]` 现取，下标一丢就永远找不回来。**

2. **把「严格大于」写成「大于等于」**（或反过来）。`nums[top] < nums[i]` 决定相等时弹不弹：
   现在的写法相等不弹，求的是「严格更大」；想求「不小于」就要改成 `<=`。
   这一改还会影响接雨水里平台的处理，一定要用具体输入（比如 `[2,2,2]`）验证。

3. **接雨水时忘了"弹完再看栈空不空"**。`bottom` 弹出来后必须先判断栈是否已空：
   空了就没有左墙，水从左边流光，此时若还去 `mini_peek` 拿 `left`，
   拿到的是上一次遗留的旧值（本节代码里 `left` 未初始化就会踩这个雷），水量直接算错。

4. **接雨水时把左墙取成 `bottom` 弹出之前的栈顶**。左墙必须是**弹出槽底之后**的新栈顶，
   因为它才是"槽底左边第一根更高的柱子"。写成弹出前先 peek，左墙就成了槽底自己，宽度变 0。

5. **看到两层循环就喊 O(n²)**。单调栈的分析要数"总入栈/出栈次数"：
   内层 while 每执行一次就少一个栈元素，全局有上限。这是本节最容易在面试里说错的一点。

6. **每次 push 都扩容 / 用动态数组当栈**。栈里最多同时装 n 个下标，`malloc(n)` 一次到位最省事；
   写扩容代码只会分散你对单调性的注意力。

7. **忘了 `ans` 先填 -1**。单调栈只覆盖"被弹到"的那些位置，剩下的必须靠初值 -1 兜底。
   没初始化就返回，答案数组里全是垃圾值。

8. **暴力法 break 的位置写错**：`if (nums[j] > nums[i]) { ans = nums[j]; }` 少了 `break`，
   拿到的是「最后一个更大的」而不是「第一个更大的」—— 用它来验证单调栈时会误判单调栈写错了。

## 什么时候用它 / 什么时候别用

**适合：**
- 问题形如「对每个元素，求它**左边/右边第一个比它大/小**的元素（或距离）」→ 单调栈的标准场景。
- 需要「一段连续的、被某个更高边界夹住」的量：接雨水、柱状图最大矩形、最小值之和这类。
- 数据是**一次性静态数组**（不是边插入边查询的活数据）。
- 想省掉「预处理左右最值数组」的额外空间：单调栈常常能一边扫一边把答案写完。

**不适合：**
- 需要「下一个更大且要能删中间元素 / 要按值查询」→ 单调栈只保证栈内有序，不是搜索结构，考虑平衡树/堆。
- 数据流式到达、还要随时回答历史问题：单调栈弹掉就回不来了（它是有损的）。
- 只要「全局最大/最小」而不是「第一个」→ 一个变量扫一遍就够，别上栈。
- 需要「右边第一个更大**值 ≥ 我**」这类边界暧昧的变体时：先拿 3~5 个小例子手动推一遍比较号，
  再决定 `<` 还是 `<=`，否则差一个等号整题就错。

## 自检问题

1. **单调栈的「单调」是什么意思？这条纪律靠什么动作维持？**
   答：栈里从底到顶的值一路递减（或递增）。纪律靠 **push 之前不断弹栈** 维持：
   新元素比栈顶大就把栈顶弹掉，弹到不破坏单调性才压入。不是 push 之后再排序或检查。

2. **为什么「下一个更大元素」用递减栈？弹栈那一下发生了什么？**
   答：递减栈意味着"栈里每一个都还在等一个比它大的数"。新来的 `nums[i]` 若比栈顶大，
   它就是栈顶右边第一个更大的数 → 弹出栈顶 j 的同时写下 `ans[j] = nums[i]`。
   弹栈 = 答案诞生，这是单调栈最核心的一句话。

3. **两层循环为什么是 O(n) 而不是 O(n²)?**
   答：外层固定 n 步；内层每次执行都对应一次弹栈，而每个下标一生最多入栈 1 次、出栈 1 次，
   所以内层总共 ≤ n 次。总操作 ≤ 2n。运行结果第 4 幕真的数出来了：入栈次数恒等于 n，出栈次数 ≤ n
   （递减序列那一行是 10 次入栈 + 0 次出栈，暴力法却要 45 次比较）。

4. **接雨水时，弹出槽底后如果发现栈空了，说明什么？该怎么办？为什么？**
   答：说明槽底左边没有更高的柱子，也就是**没有左墙**，水会从左边流走，这一槽接不住水。
   处理办法是直接 `break` 结束本层结算（然后照常把 i 压栈）。若继续用旧的 `left` 值算，就会凭空造出水量。

5. **接雨水的一层水量 `width = i - left - 1`、`depth = min(h[left], h[i]) - h[bottom]`，各自为什么是这个式子？**
   答：宽：夹在左墙 `left` 和右墙 `i` **之间**的柱子根数，不含两墙自己，所以 `-1`。
   深：水面高度受短板限制（`min`），再减去槽底那根柱子自己的高度（槽底上面才能存水）。
   运行结果里这两个式子都被原样打印出来（"宽度 = i - left - 1 = 3 - 1 - 1 = 1"），可以逐条对照。

6. **想求「右边第一个更小的元素」，代码怎么改？**
   答：把栈的纪律反过来，改成**递增栈**：弹栈条件由 `nums[top] < nums[i]` 改成 `nums[top] > nums[i]`，
   这样新来的更小的数会把栈里比它大的都弹掉并认领答案。求「左边第一个更大」则保持递减栈但从右往左扫。
