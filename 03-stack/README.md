# 03 · 栈 stack

> 一摞盘子：最后放上去的最先被拿走。整个章节只有这一句话，但它是"嵌套"和"待办清单"的通用解法。

---

## 本类总览

**栈（stack）= 只允许在同一端进出的线性结构。** 那一端叫"栈顶"，用一条规矩换来了两件事：
① 所有操作 O(1)；② 「最晚出现的最先处理」这个顺序被结构性地保证了 —— 不用你自己去记。

为什么这个看似土的规矩这么有用？因为**"嵌套"这件事天生就是栈**：
越内层的东西越先结算（括号里层先闭合、函数里层先返回、撤销最近一步先取消、
搜索最近走的一步先回溯）。只要问题里有"当前最要紧的那层"，就该想到栈。

栈的三个必背事实（本章节目录就是围绕它们排的）：

1. **怎么实现都行**：数组（连续内存 + 一个下标）或者链表（一堆节点 + next）。
   两者都 O(1)，差别只在"要不要预估容量""要不要每个节点多背一个指针"。
2. **栈顶只能放在"能快速增删的那一端"**：链表必须放头部；放尾部单链表就退化成 O(n)。
3. **纪律 + 栈 = 更强的工具**：给栈加一条"里面必须保持单调"就是单调栈（O(n) 解决"下一个更大"），
   加一条"只放开括号"就是括号匹配，加一条"只放还没输出的运算符"就是调度场算法。
   —— 后三个是本章真正的重点：**栈的价值在于它是"悬而未决的事情清单"。**

## 各实现对比表

| 目录 | 是什么 | push | pop | 判空/size | 容量 | 内存开销 | 这一节真正教你什么 |
|---|---|---|---|---|---|---|---|
| `array-stack/` | 数组 + `top` 下标 | O(1)（扩容那次 O(n)，摊还 O(1)） | O(1) | O(1) | 固定 或 翻倍自动扩 | 4 字节/元素，另有多占一倍的空位 | `top=-1` vs `top=0` 两派；`realloc` 换地址；摊还分析 |
| `linked-stack/` | 链表，栈顶在**头部** | O(1) 严格 | O(1) | O(1)（靠 size 字段） | 不会满 | 每元素 4 + 8 指针 + malloc 管理头 | **为什么必须头部操作**；改 head 本身要 `Node**` 或"结构体包 head" |
| `monotonic-stack/` | 普通栈 + 单调纪律（存下标） | O(1) 摊还 | O(1) 摊还 | O(1) | 一次 malloc(n) 到位 | 栈 O(n) + 答案数组 O(n) | 整体 O(n) 的**摊还证明**（每人最多进出一次）；"弹栈 = 答案诞生" |
| `expression-eval/` | 栈的两个应用（不是新结构） | — | — | — | — | 一两个辅助小栈 | 括号匹配（"最近的先闭合"）、调度场三条规则、后缀为何不需要括号 |

再横向放一起看"选哪个"：

| 你的情况 | 选哪个 | 为什么 |
|---|---|---|
| 元素数量能估个大概、追求速度和 cache 友好 | `array-stack` | 连续内存，一次 malloc；扩容只在真不够时发生 |
| 数量完全估不出 / 不能容忍任何一次 O(n) 抖动 | `linked-stack` | 永远 O(1) 且不搬数据，永远不"栈满" |
| 求"下一个更大/更小""接雨水""最大矩形" | `monotonic-stack` | 暴力 O(n²) → 一次遍历 O(n)，这是它的独门价值 |
| 要算表达式 / 校验括号 | `expression-eval` | 栈的用法示范，不需要挑实现，抄一个小栈就够 |

## 「栈和队列其实是同一件事的两种方向」

这一节请务必读完再进 `04-queue/` —— 它是本章最重要的直觉总结。

**它们是同一种东西：一个"只允许在一端进"的容器，唯一区别是出队口开在哪一端。**

```
                 进（永远在这一端）              出
   栈    ─────────┤ ▲  │◀─────────────────────────── 进出同一端 → 后进先出 LIFO
                  │ │ │
        ┌─────────┴─┴─┴─────────┐
        │  元素挤在同一端排队    │   最后进来的那个正好挡在最外面
        └───────────────────────┘

   队列   进 ──────────────────────┐   ┌────────────────────── 出
        ┌──────────────────────────┴───┴────────────────────────┐
        │  元素排成一条队，front 在前面等出口，rear 在后面新来   │
        └───────────────────────────────────────────────────────┘
                                    先进先出 FIFO
```

三件事把它们的联系钉死：

1. **底层实现完全复用**：数组 / 循环数组 / 链表，两套结构用的是同一批技巧
   （`front`/`rear` 就是"两个 top"；链表队列就是"把头尾两端各挂一个指针"）。
2. **可以互相模拟**：`04-queue/queue-by-stacks/` 用**两个栈**做出一个队列（LeetCode 232），
   反过来用两个队列也能做出一个栈。顺序被"反转两次"就复原了 ——
   这件事只有把两者都写熟的人才看得懂。
3. **差别只在"你在乎哪一个"**：
   - 在乎**最新**的那件事（撤销、回溯、括号里层、DFS）→ 栈；
   - 在乎**最早**的那件事（排队、公平调度、BFS、逐层处理）→ 队列。

```
   压入顺序 1 → 2 → 3，两种结构弹出的顺序：

   栈:     push 1 2 3        弹出：3 2 1      ← "刚才那一步最先反悔"
   队列:   enqueue 1 2 3     弹出：1 2 3      ← "先来的人先服务"

   同一堆数据，两种取出方向 —— 数据结构的全部差异就在这里：
   不是"存什么"不同，而是"以什么顺序放回去"不同。
```

所以学习时可以把它们当**一对**记：
`array-stack ↔ array-queue`（数组实现，队列那个还有"假满"这个栈不会遇到的问题，
因为栈两端同向、`top` 单调后退即可，队列两端分开，`front` 一路往前推会浪费前面的格子 ——
这正是 `04-queue/array-queue/` 和 `04-queue/circular-queue/` 两节的主题）；
`linked-stack ↔ linked-queue`（链表实现，一个指针 vs 两个指针）；
`monotonic-stack ↔ deque`（都是"在某一端做清理"，单调栈只在栈顶弹，双端队列两头都能进出）。

## 栈的通用注意事项（四个目录共有）

1. **一定要判空再弹**：空栈 `pop`/`peek` 是栈的头号事故（对应现实里"一路退回到关程序"）。
   本仓库统一做法：返回 `false`，并且**不写脏**调用者给的输出变量。
2. **一定要提供销毁函数并且调用**：`astack_destroy` / `lstack_destroy` / `mini_destroy` / `cst_destroy`。
   谁 `malloc` 谁 `free`；`main` 结尾必须调，ASan 才干净。
3. **失败分支也要收尾**：`realloc` 失败要保住老内存；
   两次 malloc 第二次失败要 free 第一次；返回 NULL 前要 free 已到手的那块。
4. **`top` 的表示要全程一致**：本仓库统一"流派 A：`top` 是栈顶元素下标，空栈 `top = -1`"。
5. **想清楚"栈里到底放什么"**：放元素值？放下标？放还没闭合的括号？放还没输出的运算符？
   放"悬而未决的事情"。这四个目录的差别全在这一个问题上。
