# 数组栈 array-stack

> 用「一段连续数组 + 一个下标 top」实现栈：最省内存、最快、也最接近 CPU -cache 友好的栈写法。

---

## 一句话是什么

**栈就是只能从同一头进出的那一摞盘子**，最后放上去的最先被拿走（后进先出 / LIFO）。
数组栈的具体做法：开一个 `int data[capacity]`，再准备一个整数 `top` 记住「最上面那格的下标」。
`push` 就是 `top` 往上挪一格再写值，`pop` 就是读 `data[top]` 然后把 `top` 往下挪一格。**永远只动 `top`，不动别的数据**，所以所有操作都是 O(1)。

---

## 为什么需要它

先看**不用栈**时的痛，再对照就明白栈到底省了什么心：

| 场景 | 不用栈会怎么写（痛在哪） | 用栈怎么写 |
|---|---|---|
| 撤销操作 Ctrl+Z | 自己开一个数组 `hist[]` + 一个 `n`，每次撤销要记得「最新那条在 `hist[n-1]`」，还要防 `n` 变负数 | `astack_push` / `astack_pop`，判空逻辑被封装在函数里，误用只返回 false |
| 括号匹配 | 从左往右扫，遇到闭括号要「找最近一个没用过的开括号」——手写就得倒着扫数组，还要标记哪个用过，代码一坨 | 开括号压栈，闭括号弹栈比对，10 行搞定（见 `expression-eval`） |
| 函数递归 / DFS 改非递归 | 递归靠系统帮你维护调用栈；想自己写「待办路径」，就得手工模拟「最后发现的先处理」 | 显式栈，把系统干的事自己写出来，顺便理解递归 |
| 求「下一个更大元素」 | 每个元素往后扫一遍，O(n²) | 单调栈 O(n)（见 `monotonic-stack`） |
| 计算器算 `(3+4)*5-6` | 得先找最里层括号、算完再回填字符串，写起来极其别扭 | 转成后缀表达式再求值，不需要括号 |

**核心痛点就一句话：很多算法都要求「最晚处理的那个最先处理」，而数组本身没有「当前最新位置」的概念。**
栈做的事，就是把「最新位置」正式变成一个变量 `top`，并把「只准碰最新」变成规矩。

顺带一句：数组栈和链表栈（下一节）比，优势是**内存连续、没有每个节点 extra 的指针、不碰 malloc**；代价是**要么固定容量、要么偶尔扩容搬一次**。

## 内存布局图解

⚠ 记住规矩：**下标越小越靠栈底，下标越大越靠栈顶。栈是从下往上长的。**

```
  astack_init(&s, 4, false);     // 一开始 4 格，空栈

        data →  ┌────────┬────────┬────────┬────────┐   ← 堆上一块连续内存（malloc 4*sizeof(int)）
                │  垃圾  │  垃圾  │  垃圾  │  垃圾  │      malloc 不清零，但只有 <= top 的格子才算数
                └────────┴────────┴────────┴────────┘
  下标             0          1          2          3
                栈底 ←────────────────────────→ 栈顶方向
                top = -1                        （空栈：top 掉到 0 以下，一格都不算）


  push(10)  ：top++ 到 0，data[0] = 10
                ┌────────┬────────┬────────┬────────┐
                │  10    │  垃圾  │  垃圾  │  垃圾  │        top = 0，size = top+1 = 1
                └────────┴────────┴────────┴────────┘
                  ▲ top


  push(20)  ：top++ 到 1，data[1] = 20
                ┌────────┬────────┬────────┬────────┐
                │  10    │  20    │  垃圾  │  垃圾  │        top = 1，size = 2
                └────────┴────────┴────────┴────────┘
                         ▲ top


  push(30) → push(40) → push(50)：top 一路爬到 3（= capacity-1），满了
                ┌────────┬────────┬────────┬────────┐
                │  10    │  20    │  30    │  50    │        top = 3 == capacity-1 → is_full
                └────────┴────────┴────────┴────────┘
                                                        ▲ top   （第 4 格被占了，没有空位）
                push(60) → 失败返回 false（没开扩容开关，只能报错）


  pop()  ：读出 data[3] = 50，然后 top-- 回到 2
                ┌────────┬────────┬────────┬────────┐
                │  10    │  20    │  30    │ [50]   │        top = 2，size = 3
                └────────┴────────┴────────┴────────┘
                  ▲ 栈底            ▲ top        ↑ 50 还在内存里，只是「作废」了
                                                    再 push 就直接把它盖掉
                                                    ⚠ 这就是「pop 不等于清空」：敏感数据要手动抹


  动态扩容版（auto_grow = true）：满了以后 realloc 换一块 2 倍大的，把老数据搬过去
   capacity=2                    capacity=4（搬 2 个）              capacity=8（搬 4 个）
  ┌────┬────┐                  ┌────┬────┬────┬────┐              ┌────┬────┬────┬────┬────┬────┬────┬────┐
  │ 10 │ 20 │                  │ 10 │ 20 │    │    │              │ 10 │ 20 │ 30 │ 40 │    │    │    │    │
  └────┴────┘                  └────┴────┴────┴────┘              └────┴────┴────┴────┴────┴────┴────┴────┘
    ▲top                          top→第 1 格                        top→第 3 格
  push(30) 时满 → 搬 10、20 到新内存；**data 指针地址变了**，旧指针当场作废（悬空）。
```

`top` 的两种流派（本项目统一用**流派 A**）：

```
流派 A（本项目）：top = 栈顶元素自己的下标            流派 B：top = 下一个要写入的空位下标
  空栈      top = -1                                  空栈      top = 0
  push      data[++top] = v                           push      data[top++] = v
  pop       v = data[top--]                           pop       v = data[--top]
  元素个数  top + 1                                   元素个数  top
  判满      top == capacity - 1                       判满      top == capacity
```
两种都对，**混着用必错**（典型症状：明明没满却报满、peek 读到刚弹出的旧值）。
本仓库选 A，因为「空栈 = -1」在图上很直观：一个格子都不指向。

## 核心操作逐个拆解

### 1. `astack_init(AStack *s, int init_capacity, bool auto_grow)` —— 建栈

**干什么**：申请 `init_capacity` 个 int 的堆内存，把 `top` 置成 -1。

**一步步**：
1. `s == NULL` 直接返回（防御，虽然 demo 里传的都是 `&fixed`）。
2. `init_capacity <= 0`：不 malloc，建成 `data=NULL, capacity=0, top=-1` 的「空壳」，之后所有操作安全失败。
3. `malloc((size_t)init_capacity * sizeof(int))`：单位是**字节**，必须 `个数 × sizeof(int)`。
4. 判 `NULL`：malloc 失败时不能继续，把 `capacity` 置 0 当「没内存」的标记。
5. 成功则 `capacity = init_capacity; top = -1; grow_count = 0;`。

**边界情况**：容量非法、内存不足、`auto_grow` 只影响 push 不影响 init。

**对应代码**：`astack.c` 里 `astack_init`（搜 `s->top = -1;` 那行，注释里标了 ⚠）。

---

### 2. `astack_push(AStack *s, int value)` —— 压栈

**干什么**：把 `value` 放到栈顶。

**一步步**：
1. 检查 `s->data != NULL`，否则失败退出。
2. 检查 `s->top + 1 >= s->capacity`（即「下一格已经越界」）：
   - 没开 `auto_grow` → 打印原因并 `return false`；
   - 开了 → 调 `astack_try_grow`：`realloc` 到 2 倍，成功就更新 `data/capacity/grow_count` 并**打印这次扩容**，失败就保持原样返回 false。
3. `s->top += 1;`（流派 A：**先挪指针**）
4. `s->data[s->top] = value;`（**再写数据**，顺序反了就会先越界后知后觉）

**边界情况**：满 + 不扩容 = false；满 + 扩容失败 = 栈原样不动（老数组、老 top 都没被破坏）；`capacity*2` 溢出成负数时直接放弃扩容。

**为什么判满写成 `top + 1 >= capacity` 而不是 `top == capacity - 1`**：`capacity == 0` 时后者是 `top == -1`，会把空壳栈误判成「满了」，然后走扩容分支，逻辑乱掉；写成 `top+1 >= capacity` 各种情况都统一。

**对应代码**：`astack.c` 的 `astack_push` 与内部函数 `astack_try_grow`。

---

### 3. `astack_pop(AStack *s, int *out_value)` —— 弹栈

**干什么**：拿走栈顶元素，值通过 `out_value` 带回来。

**一步步**：
1. `top < 0` → 空栈，打印失败原因，返回 false，**不碰 `out_value`**（保证「失败就别写脏调用者的变量」）。
2. `int v = s->data[s->top];` —— 先存到局部变量（一挪 top 那格就不算数了）。
3. `s->top -= 1;` —— 只改指针，不清内存。
4. `if (out_value != NULL) *out_value = v;` —— 传 NULL 表示「我不要值，只想扔掉栈顶」。
5. 返回 true。

**边界情况**：空栈 pop；`out_value` 传 NULL；destroy 之后 top=-1 且 data=NULL，pop 会走「没内存」分支，安全。

**对应代码**：`astack.c` 的 `astack_pop`。

---

### 4. `astack_peek(const AStack *s, int *out_value)` —— 只看栈顶

**干什么**：读栈顶但不拿走，size 不变。

**一步步**：判 `data == NULL || top < 0` → false；否则 `*out_value = s->data[s->top]`（和 pop 同一个位置，只是不 `top--`）。

**为什么签名带 `const`**：函数指针承诺只读；写了 `s->top = ...` 编译器立刻报错。

**边界情况**：空栈 peek 返回 false；peek 不改变任何状态，可以随便反复调。

**对应代码**：`astack.c` 的 `astack_peek`。

---

### 5. 查询：`astack_is_empty` / `astack_is_full` / `astack_size` / `astack_capacity`

**干什么**：把「流派 A 的换算关系」收在一处，避免外面到处写 `top == -1`。

- `is_empty`：`s == NULL || top < 0`
- `size`：`top + 1`（top<0 时返回 0，不能返回 -1）
- `is_full`：没开扩容时 `top == capacity - 1`；开了扩容时永远 `false`（因为满了还能翻倍，报「满」反而误导）

**边界情况**：`size` 一定要在空栈返回 0，别把 `top+1` 直接暴露（top=-1 会得到 0，其实这里刚好对，但 NULL 情况要挡）。

**对应代码**：`astack.c` 中「下面几个查询函数都是一行」那一段。

---

### 6. `astack_print(const AStack *s, const char *label)` —— 教学打印

**干什么**：把栈里**全部**元素一行摊开打印，栈底在左、栈顶在右，再画一行 `^` 标出 top 落在哪格。

**为什么正式 API 里没有它**：栈的规矩是「只准碰栈顶」，全倒出来是违反抽象的。它是为了让你亲眼看见 LIFO 才加的辅助函数。
**小技术**：第二行（`^` 那一行）用的是**完全相同的循环和格子宽度**，不是「数空格数把箭头顶下去」——因为前缀里有中文（占 2 列），数列会算歪。

**对应代码**：`astack.c` 末尾。

---

### 7. `astack_destroy(AStack *s)` —— 销毁

**干什么**：`free(s->data)`，然后把 `data` 置 NULL、`top` 复位、`capacity` 归 0。

**为什么置 NULL**：free 之后指针里的地址数值还在，但内存已还给别人 → 悬空指针。置 NULL 后再误用会**当场崩**，比「悄悄读到垃圾值」好一万倍；而且 `free(NULL)` 是合法空操作，重复 destroy 不会 double free。

**对应代码**：`astack.c` 的 `astack_destroy`；`main.c` 收尾一幕真的四个栈全部 destroy 掉了（ASan 0 leak 就是证据）。

## 复杂度表

横向对比：**数组栈 / 链表栈 / 循环队列**（同规模操作放在一起看差异）。

| 操作 | 数组栈（本节） | 链表栈 `linked-stack` | 循环队列 `circular-queue` |
|---|---|---|---|
| push / 入队 | **O(1)**（扩容时那一次是 O(n)，但摊还仍是 O(1)） | O(1)（头插） | O(1) |
| pop / 出队 | **O(1)** | O(1) | O(1) |
| peek / 看队头 | **O(1)** | O(1) | O(1) |
| 判空/判满 | O(1) | O(1) | O(1) |
| 随机访问 `data[i]` | **O(1)**（但栈的语义禁止你这么干） | O(n) | O(1) |
| 单个元素占的内存 | 4 字节（只有 int 本身） | 4 + 8 = 12 字节（还要对齐到 16~32，含 malloc 管理头） | 4 字节 |
| 额外总内存 | capacity 个格子（可能比 size 大一倍） | size 个节点 | capacity 个格子 |
| CPU cache 友好度 | **极好**（连续内存，顺序访问） | 差（节点散落在堆各处，每次 next 都可能 cache miss） | 极好 |
| 容量能否无限增长 | 固定版不能；开了 `auto_grow` 可以（翻倍） | 只要堆够就是一直能加 | 取决于实现，本节是固定 capacity |
| 会不会内存泄漏 | 需要 destroy 一次 free | 每个节点都要 free，最容易漏 | 需要 destroy 一次 free |

一句话选择：**追求快和省内存、且能接受偶尔多一倍空间 → 数组栈；元素数量完全不可预测 / 要求「任何一次操作都严格 O(1) 不搬数据」 → 链表栈。**

在项目根目录（仓库根，不是本节目录）执行：

```bash
make one DIR=03-stack/array-stack

# 内存安全检查（本项目要求每个 demo 都干净）
gcc -Wall -Wextra -Wshadow -std=c11 -g -fsanitize=address -static-libasan \
```

`-Wall -Wextra -Wshadow -std=c11` 是硬标准：本节代码 0 警告 0 错误，ASan 含泄漏检查 0 报告。

## 常见的坑

1. **`top` 流派混用**：`init` 写 `top = 0`（流派 B 的空栈），`push` 又写 `data[++top]`（流派 A 的写法）→ 第一个元素被写到 `data[1]`，`data[0]` 永远是垃圾；`size` 也多数一个。**改的时候必须五个地方（init/push/pop/peek/判满）一起改。**

2. **`pop` 之后以为格子里的值没了**：`pop` 只把 `top` 往下挪，`data[top+1]` 里的旧值还在内存里，被下一次 `push` 覆盖之前都能读到。写了密码/token 之类的东西要主动抹掉（`memset`），也别把「读到的旧值」当「当前栈顶」。

3. **`realloc` 直接写回原指针**：`s->data = realloc(s->data, n);` —— 失败时返回 NULL，`s->data` 被覆盖成 NULL，**老内存再也找不回来**（永久泄漏），而栈看起来还「有数据」。正确写法：`int *nd = realloc(...); if (nd != NULL) { s->data = nd; }`。

4. **以为 `data == NULL` 检查就够了，忘了 `capacity == 0`**：init 失败后 `top = -1`，此时 `push` 若不检查内存直接 `data[++top] = v` 就是 `data[0] = v` → 解引用空指针，段错误。本节 `push` 第一件事就是查 `data == NULL`。

5. **用 `sizeof(s.data)/sizeof(int)` 算容量**：`data` 是指针，`sizeof` 只能得到 8，容量信息只在 `s->capacity` 字段里。数组一旦退化成就只剩首地址（`00-c-foundation/pointer-basics` 的第 5 节讲过）。

6. **忘了 `destroy`**：数组栈只有一块内存要 free，看着不起眼，但一个循环里建几百个栈不就 free，ASan 立刻报 `xxx byte(s) leaked`。规则：**谁 malloc 谁 free，init/destroy 成对写。**

7. **固定容量栈遇到「没想到会满」的输入**：真实项目里栈满往往发生在深层嵌套（括号套一万个、DFS 深度爆炸），线上表现为「随机失败」。要么开 `auto_grow`，要么把栈大小当作参数显式传给调用者并说明上限。

## 什么时候用它 / 什么时候别用

**适合：**
- 数量级能估计出来（哪怕是「最多 10 万层」这种粗略估计）→ 用固定容量版，一次 malloc，永不再搬。
- 需要 cache 友好、追求最快速度：单调栈、表达式求值、括号匹配这类「一次性大量小操作」的场景，数组栈明显优于链表栈。
- 需要「顺便能看全栈内容」调试：数组栈一遍 for 就打完，链表栈得一路 `next`。
- 数量级估不准：开 `auto_grow`，用摊还 O(1) 换掉「栈满」这个错误分支。

**不适合：**
- **要求每一次 push 都严格 O(1) 且绝不搬内存**（实时系统、内核中断路径之类）：扩容那一次是 O(n) 的，哪怕摊还是常数，最坏的一次就是会慢 —— 这种场合用链表栈。
- 需要「既像栈又像队列」、两头都要频繁进出 → 用双端队列 `04-queue/deque`。
- 需要「栈里第 k 个元素」这种查询 → 栈的抽象本来就不该有这需求，考虑直接用数组或别的结构。
- 想要「一个栈存很多类型」：本仓库故意不做 `void *` 泛型，只有 int 栈；要存字符串得自己复制一份改类型。

## 自检问题

1. **空栈时 `top` 是几？为什么本节不用 `top = 0`？**
   答：`top = -1`。因为流派 A 定义 `top` 是「栈顶**元素**的下标」，空栈没有栈顶元素，只能用一个「不在数组范围内」的值表示，那就是 -1。若写成 0，`data[0]` 会被当成一个值随机的栈顶元素（`peek` 读到垃圾、`size` 变成 1）。

2. **`push` 和 `pop` 里，`top` 的加减分别放在「读写数据」之前还是之后？写反会怎样？**
   答：流派 A 下 push 先 `top++` 再写（`data[++top]=v`），pop 先读再 `top--`（`v=data[top--]`）。写反就会少用一个格子或多用一个格子：pop 反了会读到下一个元素（错一个位置），push 反了会先覆盖旧栈顶再往上挪（元素丢了 + 越界风险）。

3. **容量 4 的固定栈，最多能存 4 个元素。存第 5 个时程序做了什么？为什么不是崩溃？**
   答：`push` 检查 `top + 1 >= capacity` 成立，打印失败原因并返回 `false`。不会越界写内存是因为**写之前**就挡住了；返回 false 而不是自己 malloc 新的，是因为 `auto_grow` 关着 —— 这就是「固定容量栈满了怎么办」的答案：告诉调用者失败，让他决定。

4. **翻倍扩容后，原来那个 `data` 指针还能用吗？为什么「摊还 O(1)」？**
   答：不能用，它是悬空指针 —— `realloc` 可能把数据搬到新地址，老地址已被释放。摊还 O(1) 的意思是：把扩容搬数据的开销除以它撑住的 push 次数；容量 1→2→4→8 分别搬 1、2、4 次，压 n 个元素总搬运约 2n 次，平均每次 push 是常数。

5. **数组栈和链表栈各自多花在哪？**
   答：数组栈多花「可能浪费一半空间」和「扩容时的一次 O(n) 搬运」；链表栈多花「每个节点一个 8 字节指针 + 每次 malloc 的管理开销」和「cache 不友好」，但每次操作都是严格 O(1) 且不需要预估容量。

6. **`astack_pop(&s, NULL)` 合法吗？代表什么意思？**
   答：合法。表示「我只想把栈顶扔掉，不关心它是几」，函数内部 `if (out_value != NULL)` 会跳过写入。这就是 C 语言用指针做可选输出参数的标准写法。
