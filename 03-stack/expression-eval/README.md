# 表达式求值 expression-eval

> 栈的两个最著名的应用：括号匹配校验 + 「中缀转后缀（调度场算法）→ 后缀求值」。这一节不引入新数据结构，只把栈用熟。

---

## 一句话是什么

两件事，都用「后进先出」这一个机制解决：

1. **括号匹配**：从左往右扫，遇到开括号压栈，遇到闭括号就把栈顶那个开括号配对弹出。
   扫完栈空 → 合法；否则报出「多余的闭括号 / 类型不符 / 没闭合」中的哪一种错、错在第几个字符。
2. **中缀 → 后缀 → 求值**：
   - 转换用**调度场算法**（Shunting-yard）：数字直接输出，运算符先压栈，
     遇到优先级比自己低的就弹出来，括号当"墙"处理；
   - 求值更简单：从左往右扫后缀串，数字压栈，运算符就**弹出两个数算完把结果压回去**。
     最后栈里剩的那一个数就是答案。

本节目的限制（刻意做小）：操作数只支持**个位数 0-9**，运算符只有 `+ - * /`，
括号只有 `( )`（括号匹配那一半支持 `()[]{}` 三种），空格忽略。

---

## 为什么需要它

| 场景 | 不这么写的痛 | 用栈怎么写 |
|---|---|---|
| 校验用户输入/代码文本里的括号 | 只能「数左括号和右括号各几个」——但 `([)]` 左右数量完全相等，却是错的写法，数量法根本查不出来 | 栈里只放"还没闭合的开括号"，配对只看栈顶，交叉立刻暴露 |
| 计算器 / 命令行求表达式 | 递归下降要写文法、函数、多个返回变量；或者反复"找最里层括号→算完→把结果塞回字符串"，字符串越改越乱，还容易越界 | 调度场一个循环 + 一个运算符栈；求值一个循环 + 一个数栈 |
| 编译器/解释器把表达式变成指令 | — | 后缀（逆波兰）就是最小版的中间表示：JVM 字节码、PostScript、Excel 内部都用它 |
| 判断"先算哪个" | 中缀要同时靠**括号**和**优先级**两套规则，人都会看错 | 后缀把先后关系写进位置本身，只剩一条规则：见到运算符就把它前面两个数用掉 |

**核心痛点**：中缀表达式里"谁先算"是**隐式**的（要靠外部规则推断），
而栈的作用就是把这个隐式顺序**显式**地存起来 ——
括号匹配时存的是"还没闭合的开括号"，调度场里存的是"还没输出的运算符"，求值时存的是"还没被用掉的操作数"。
**三处都是"当前悬而未决的事情清单"，这就是栈能算表达式的根本原因。**

## 内存布局图解

### 图 A：括号匹配 —— 栈是"待闭合清单"

```
  表达式： ( [  ] )            下标 0 1 2 3

   读 '(' → 入栈        栈(底→顶): (              ← "下标 0 的 '(' 在等人来关"
   读 '[' → 入栈        栈(底→顶): ( [            ← 栈顶永远是【最近】那个没关的
   读 ']' → 看栈顶 '['，正好该配 ']' → 弹出     栈: (
   读 ')' → 看栈顶 '('，该配 ')' → 弹出         栈: (空)
   结束且栈空 → ✅ 合法


  反例： ( [ ) ]
   读 '(' → 栈: (
   读 '[' → 栈: ( [
   读 ')' → 看栈顶是 '['，但 ')' 该配 '(' → ❌ 类型不符，判不匹配（位置 2）

   ★ 如果这里用队列（先进先出），第一个要配对的会是 '('，')' 刚好能配上 '(' → 误判合法。
     「最近一个最先闭合」= 后进先出 = 只有栈能做到，这也是"为什么栈能做括号匹配"的标准答案。


  栈里还多带一个「位置数组」，两个数组平行、下标同步：
      chars[]     = '('  '['
      positions[] =  0     1
   这样报"没闭合"时能说出是第几个字符，而不是只说"少了括号"。
```

### 图 B：调度场算法 —— 栈是"还没输出的运算符清单"

```
  中缀 (3+4)*5-6    →  后缀 34+5*6-

  字符 │ 输出串 │ 运算符栈(底→顶) │ 干了什么
  -----┼--------┼----------------┼------------------------------------------
   (   │ ""     │ (              │ 左括号：一堵墙，直接压栈
   3   │ "3"    │ (              │ 数字：直接进输出
   +   │ "3"    │ ( +            │ 栈顶是墙 → 不弹，压 '+'
   4   │ "34"   │ ( +            │
   )   │ "34+"  │ (空)           │ 右括号：一路弹到 '('，'(' 丢弃、不进输出
   *   │ "34+"  │ *              │ 栈空 → 压 '*'
   5   │ "34+5" │ *              │
   -   │ "34+5*"│ -              │ 栈顶 '*' 优先级(2) >= '-'(1) → 弹出 '*'，再压 '-'
   6   │ "34+5*6"│ -             │
  结束 │ "34+5*6-"│ (空)         │ 把栈里剩下的运算符全倒进输出

  ★ 两个关键位置：
     · 为什么弹到 '(' 就停？—— '(' 在栈里是一堵墙，墙里的运算符属于括号内那个子表达式，
       墙外的绝不能比墙里的先输出。
     · 为什么比较用 `>=` 不用 `>`？—— 因为 + - * / 全靠左结合。8-3-2 要算成 (8-3)-2，
       第二个 '-' 出现时必须把相等优先级的栈顶先输出。写成 `>` 就会变成 832-- = 8-(3-2) = 7（错）。


  栈在内存里的样子（存的是字符 + 它在原串的位置，位置用来报错时指出第几个字符）：
      chars[]     = '('  '+'
      positions[] =  0     2        ← 例如报错 "'(' 一直没有闭合" 就能说清是第 0 个字符
```

### 图 C：后缀求值 —— 栈是"还没被用掉的操作数"

```
  后缀 34+5*6-

   读 '3'  压入        数栈(底→顶): 3
   读 '4'  压入        数栈: 3 4
   读 '+'  先弹 4（右），再弹 3（左）→ 3+4=7 → 压回     数栈: 7
   读 '5'  压入        数栈: 7 5
   读 '*'  先弹 5，再弹 7 → 7*5=35 → 压回              数栈: 35
   读 '6'  压入        数栈: 35 6
   读 '-'  先弹 6，再弹 35 → 35-6=29 → 压回            数栈: 29
   结束：栈里恰好剩 1 个数 → 答案 = 29 ✔（和中缀人工算的 (3+4)*5-6=29 对上）

  ★ 先弹出的是【右】操作数！因为 '+' 作用的是"它前面紧挨着的两个已完成子表达式"，
    最后压进去的那个才是右边的。顺序写反 → 8/2 变成 2/8（整数除法 = 0，还特别隐蔽）。
    加和乘满足交换律看不出问题，所以测试必须包含 - 和 /。

  ★ 后缀为什么不需要括号（一句话）：
    后缀里每个运算符都排在【它所作用的两个数】之后，
    「谁先算」= 「哪个运算符在串里出现得更早」，位置本身就是顺序，
    不需要任何外部规则（括号）再去人为制造先后 —— 括号这个负担自然被取消了。
```

## 核心操作逐个拆解

### 1. `CharStack`（本节自带的小字符栈：`cst_*`）

**干什么**：给括号匹配和运算符栈用；同时存字符和它在原串里的位置。
**一步步（init）**：两次 `malloc`（`chars` 和 `positions`）；
**⚠ 关键边界**：**第二次 malloc 失败时必须先 `free` 掉第一次**，否则那块内存永远回不来。
这类"申请了两样、第二样失败"的清理路径是 C 里最容易漏的泄漏点，`cst_init` 里专门演示了一遍。
**push/pop**：两个数组用同一个 `top` 同步移动；`pop` 的两个输出参数都可以传 NULL（"我只要丢掉，不要读"）。
**对应代码**：`expr.c` 第一部分。

---

### 2. `IntStack`（本节自带的小 int 栈：`ist_*`）

**干什么**：后缀求值用，存"还没被运算符用掉的数"。
**边界**：`ist_init` 里如果容量非法就至少给 1 格，避免后面到处判空；
`ist_pop` 空栈返回 false 且不写 `out_value`。
**对应代码**：`expr.c` 第三部分。

---

### 3. `expr_check_brackets(expr)` —— 应用① 括号匹配

**干什么**：判断 `()[]{}` 混用是否合法配对，返回 `true/false`，并打印逐字符扫描过程。

**一步步**：
1. 取 `len = strlen(expr)`，把栈容量开成 `len`（最多同时压 len 个开括号，绝对够；`len==0` 时给 1）。
2. 逐字符：
   - **开括号** → `cst_push(&st, i, ch)`，打印"入栈，等待闭合"；
   - **闭括号** → 先看栈空不空：
     - 空 → ❌ 原因：**多余的闭括号**（位置 i）；
     - 非空 → `cst_peek` 拿栈顶（**只看，先不弹**，因为可能配不上）：
       - 栈顶 != `matching_open(ch)` → ❌ 原因：**最近的开括号类型不符（括号交叉）**；
       - 配上了 → 弹栈，打印"第 a 个 X 与第 b 个 Y 闭合"；
   - **其它字符** → 忽略，不进栈（数字/运算符跟配对无关）。
3. 循环因失败 `break` 出来就报失败；否则**收尾再检查一次栈是否为空**：
   非空 → ❌ 原因：**扫描结束时还有开括号没被闭合**，并把剩下的位置和字符逐个报出来。
4. 打印总结论 + 原因 + 出问题的大致位置。

**边界情况**：空串（合法）、整串没有括号（合法）、开头就是闭括号（失败在"栈空"分支）、
只有开括号（失败在收尾分支）。
**对应代码**：`expr.c` 的 `expr_check_brackets`，`is_open_bracket` / `is_close_bracket` / `matching_open` 三个小工具。

---

### 4. `expr_infix_to_postfix(expr, ok_out)` —— 应用② 转换

**干什么**：中缀 → 后缀。返回 `malloc` 出来的字符串，**调用者必须 free**；失败返回 NULL。

**一步步**（三条规则 + 收尾）：
1. `out = malloc(len + 1)`（后缀最多和输入一样长，括号会被丢掉；多留 1 格给 `'\0'`）。
2. 逐字符：
   - 空白 → 跳过；
   - **数字**（规则①）→ `out[out_len++] = ch;` 并补 `'\0'`（补 0 只是为了能 `%s` 打印出来给你看）；
   - **`(`** → 压栈当墙；
   - **`)`**（规则③）→ 一路弹到 `(` 为止；`(` 弹掉丢弃、不进输出；
     **如果弹到栈空都没找到 `(`** → ❌ "右括号找不到配对的左括号"，释放全部内存后返回 NULL；
   - **运算符**（规则②）→ `while (栈非空 && 栈顶不是 '(' && precedence(栈顶) >= precedence(当前)) 弹出并写进输出;` 然后压入当前；
   - **其它字符** → ❌ 不支持的字符，释放全部内存返回 NULL。
3. 输入读完 → 把栈里剩下的运算符全倒进输出；**倒的时候如果发现 `(`** → ❌ "左括号一直没闭合"，释放后返回 NULL。
4. `out_len == 0`（输入里一个数字都没有）→ 也算失败，释放返回 NULL。
5. 返回 `out`。

**为什么 `>=`**：见上面图 B 的说明（左结合）。
**为什么 `ok_out` 允许 NULL**：C 里"这个额外结果我不要"的标准写法；`return` 只能带回指针，
成功与否用一个可选的输出参数带出。
**边界情况（每条失败路径都做了两件事：释放 `out` + `cst_destroy(&ops)`）**：
`(3+4`（没闭合）、`3+4)`（找不到左括号）、`3+a4`（非法字符）、`""`（空串）、malloc 失败。
**对应代码**：`expr.c` 的 `to_postfix_impl`（内部真实现）+ `expr_infix_to_postfix`（带打印外壳）。

---

### 5. `expr_eval_postfix(postfix, result_out)` —— 应用② 求值

**干什么**：算出后缀表达式的整数值。

**一步步**：逐字符：数字 → `ist_push(ch - '0')`（字符变数字：减去 `'0'` 的 ASCII，C 的固定套路）；
运算符 → **先 pop 右操作数 b，再 pop 左操作数 a** → 算 `a op b` → 结果压回。
扫描结束后：pop 出一个数当结果，且**此时栈必须正好空**，否则说明表达式结构不对。

**边界情况**：
- 运算符前面不足两个数（`"3+"`）→ 失败，`result_out` 不被写脏（保持调用前原值）。
- **除数为 0**（`"533-/"`，即 `5/(3-3)`）→ 提前挡住并报错；整数除 0 在 C 里是未定义行为，会当场崩。
- 数字太多、运算符太少（`"34"`）→ 扫完栈里剩 2 个数 → 判结构不合法。
- 后缀串里有非法字符 → 报错。

**对应代码**：`expr.c` 的 `eval_postfix_impl` + `expr_eval_postfix`。

---

### 6. `expr_eval_infix(expr, result_out)` —— 一步到位（静默）

**干什么**：转换 + 求值，只打一行结论。用来批量演示（第 4 幕的表）。
**⚠ 内存责任链（本节最容易漏的一处）**：
`to_postfix_impl` 内部 `malloc` 出后缀串 → 交回给 `expr_eval_infix` →
**用完必须在这里 `free`**。规则永远是"谁最终持有谁负责"，而不是"谁写的 malloc 谁 free"——
这里 malloc 写在被调用函数里，但内存的所有权已经随返回值转移给调用者了。
**对应代码**：`expr.c` 末尾。

## 复杂度表

| 操作 | 时间 | 空间 | 和"不用栈"的对比 |
|---|---|---|---|
| 括号匹配 | **O(n)**（每个字符进栈/出栈各最多一次） | O(n)（最坏全是开括号，如 `((((`） | 数量对比法 O(n) 但**判不出交叉**，是错的；反复扫描找最里层 = O(n²) |
| 中缀→后缀（调度场） | **O(n)**（每个字符最多入栈一次、出栈一次） | O(n)（输出串 + 运算符栈） | "找最里层括号→算→回填字符串" 写法 O(n²) 且极难写对 |
| 后缀求值 | **O(n)** | O(n)（数栈，最多 n 个操作数） | 中缀直接求值要递归/多次扫描，同样 O(n) 但实现复杂得多 |
| 整条流水线（`expr_eval_infix`） | O(n) | O(n) | |

和别的"顺序处理"结构横向对比：

| | 栈（本节） | 队列 `04-queue/*` | 堆 `06-heap` |
|---|---|---|---|
| 拿出的顺序 | 最后放进去的 | 最早放进去的 | 最"极端"的那个（最大/最小） |
| 适合 | 嵌套、待办清单、需要"回到最近一层" | 排队、BFS、公平调度 | 优先级、Top-K |
| 表达式这件事上 | 后缀求值天生用栈 | 用不了（顺序不对） | 只能做"按优先级取任务"，不能算表达式 |

## 编译与运行

在项目根目录执行：

```bash
make one DIR=03-stack/expression-eval

# 内存安全检查：这一节的 malloc/free 链条最绕，务必跑
gcc -Wall -Wextra -Wshadow -std=c11 -g -fsanitize=address -static-libasan \
    03-stack/expression-eval/*.c -o /tmp/asan_a3 && /tmp/asan_a3
```

`-Wall -Wextra -Wshadow -std=c11`：0 警告 0 错误。
ASan 含泄漏检查：无任何报告。内存责任清点：
`expr_check_brackets` 的 2 次 malloc → `cst_destroy` 的 2 次 free；
`expr_infix_to_postfix` 的成功返回值在 `main.c` 里逐个 `free`；
它的所有**失败路径**内部自己 `free(out)` 后返回 NULL（`free(NULL)` 合法，main 里也再 free 一次保险）；
`expr_eval_postfix` 的数栈在末尾 `ist_destroy`；
`expr_eval_infix` 内部持有的后缀串用完立刻 `free`。

## 常见的坑

1. **求值时弹出顺序写反**：应该「先弹右操作数 b，再弹左操作数 a」。
   反了以后 `8-3` 变 `3-8`、`8/2` 变 `2/8=0`（整数除法截断，错得最隐蔽）。
   `+ *` 有交换律看不出问题 —— **所以测试一定要带 `-` 和 `/`**。

2. **调度场里比较优先级用 `>` 而不是 `>=`**：`8-3-2` 会被转成 `832--`，读作 `8-(3-2)=7`，
   而正确答案是 `(8-3)-2=3`。一个符号决定整题的结合性。想改成右结合才用 `>`。

3. **遇到 `(` 忘了停止弹栈**：规则②的 while 里必须先判 `栈顶 == '('` 就 `break`。
   忘了就会把括号里的运算符连同 `(` 一起弹出去，输出串彻底乱掉。

4. **`)` 一路弹之后没检查"到底有没有 `(` "**：`3+4)` 这种多余右括号，会一路弹空栈然后继续跑，
   最后输出一个语法错乱的后缀串。必须先判 `found_open`。

5. **报错只说"括号不匹配"，不说为什么**：本节特意把三类原因分开：
   栈空遇到闭括号 = 多余闭括号；栈顶类型不符 = 交叉/写错；扫完栈非空 = 有开无闭。
   少了位置信息（`positions` 数组）就只能让用户自己数字符。

6. **忘了 free 转换出来的后缀串**：`expr_infix_to_postfix` 把 `malloc` 的内存通过返回值交给你，
   接手的人常常以为"函数内部会清理"，于是每次调用漏一串。看 `expr_eval_infix`：
   它用完立刻 `free(postfix)`，这就是标准收尾。**失败路径同理** ——
   返回 NULL 之前也要把已经 malloc 到的 `out` 释放掉。

7. **`cst_init` 里第二次 malloc 失败时忘了 free 第一次**：`chars` 那块就永久泄漏。
   两样东西一起申请时，"第二样失败要回滚第一样"必须写。

8. **以为 `char` 存的就是数字**：`ch - '0'` 才是 int 值 7；直接 `ist_push(ch)` 压进去的是 ASCII 码 55。

9. **整数除法与截断**：`1/2 = 0`，`-3/2 = -1`（C 是向 0 截断）。本节刻意只做 int，
   想支持小数要换 `double` 并处理 `%.Nf` 输出，完全是另一套代码。

10. **多位数被拆开**：`"10-2*3"` 里的 `1` 和 `0` 被当成两个操作数，直接判"结构不合法"。
    这是本节刻意设的限制（第 4 幕实测了）；真要多位数，要么读中缀时 `while` 攒 `val = val*10 + (ch-'0')`，
    要么让后缀串 token 之间留空格（`"10 2 3 * -"`）。

## 什么时候用它 / 什么时候别用

**适合：**
- 任何「括号/嵌套是否配对」的校验：代码编辑器、公式输入框、模板引擎。
- 计算器、简单脚本语言、Excel 类公式：调度场 + 后缀求值是最小可用的完整方案。
- 把「隐式的优先级规则」变成「显式的串」：一旦转成后缀，求值就不再需要知道优先级，
  也方便顺手做优化（比如统计运算次数、常量折叠）。
- 递归改写：中缀求值天然是"处理子表达式"的递归结构，用栈把递归摊平就是本节做的事。

**不适合：**
- 需要函数调用、变量、右结合幂运算、一元负号、多位数、小数 → 直接上「递归下降 + 词法分析」，
  调度场只适合"运算符 + 单字符操作数"这种平面文法。
- 表达式要**反复求值但变量在变**（比如公式表格）：应该把中缀编译成一棵树/字节码缓存起来，
  每次改的是叶子值，而不是每次都重新转换。
- 需要"按优先级取任务"而不是"按结构算数" → 那是堆 / 优先队列（`06-heap`）的活。

## 自检问题

1. **括号匹配为什么必须用栈，用队列会怎样？**
   答：要配对的永远是"最近一个还没闭合的开括号"，最后出现的最先闭合 = LIFO。
   用队列（FIFO）时，`([)]` 会拿最早的 `(` 去配 `)`，居然配上，于是把非法写法判成合法。

2. **调度场算法的三条规则是什么？`(` 和 `)` 各自怎么处理？**
   答：① 数字直接进输出；② 运算符先把栈里优先级 `>=` 自己的全部弹出进输出，再压自己；
   ③ `(` 直接压栈当"墙"（弹栈遇到它就停），`)` 则一路弹出到 `(` 为止，`(` 本身丢弃、不进输出。
   输入读完再把栈里剩下的全部倒进输出。

3. **后缀表达式为什么不需要括号？**
   答：后缀把"谁先算"编码进了**位置**：每个运算符都排在它所作用的两个操作数之后，
   从左往右扫时，运算符一出现，它要的两个数必然正好是栈顶那两个，没有第二种解释。
   括号在中缀里的作用就是人为制造这个先后关系；后缀已经有了，自然不需要。

4. **求值时为什么"先弹出的是右操作数"？写反了什么情况下看不出来？**
   答：栈是后进先出，`a b op` 里 `b` 最后压入，所以第一个弹出的是 `b`（右操作数）。
   写反时 `+ *` 因为交换律结果相同，看不出来；但 `- /` 会全错，而且 `8/2` 反成 `2/8` 在整数除法下得 0，
   错得最隐蔽 —— 所以测试必须包含减法和除法。

5. **`>=` 改成 `>` 会引发什么错误？为什么？**
   答：`8-3-2` 会被转成 `832--`，读作 `8-(3-2)=7`，而不是 `(8-3)-2=3`。
   因为 `+ - * /` 都是**左结合**：优先级相等的两个运算符要先算左边那个，
   所以遇到第二个 `-` 时必须把栈顶那个 `-` 先弹出输出。右结合（如幂运算 `^`）才用 `>`。

6. **这一节里哪一处内存最容易泄漏？函数返回 NULL 的失败路径要注意什么？**
   答：`malloc` 出来的后缀串。两处要盯：
   ① `expr_infix_to_postfix` 成功时把内存交给调用者，调用者（`main` 或 `expr_eval_infix`）必须 `free`；
   ② 失败时（括号不匹配、非法字符）函数自己必须 `free(out)` 并 `cst_destroy(&ops)` 再返回 NULL，
      否则错误分支跑一次就漏一次。另外 `cst_init` 里两次 malloc，第二次失败要回滚第一次。
