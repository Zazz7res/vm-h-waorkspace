# 树状数组 binary-indexed-tree（BIT / Fenwick 树）

> 六行代码，让"单点修改"和"前缀和查询"**同时**变成 O(log n)。

---

## 一句话是什么

再开一条数组 `tree[]`，让 **`tree[i]` 负责存原数组一小段连续区间的和**，
这段的长度恰好等于 `lowbit(i) = i & (-i)`（i 的二进制里最低位那个 1）。

于是任何一个前缀 `[1..i]` 都能被**不超过 log n 块**这样的小区间拼出来：

- 查询：`i -= i & (-i)` —— 一块一块往左吃（跳到"上一个覆盖点"，parent 方向）
- 修改：`i += i & (-i)` —— 沿路通知所有"含我这个元素"的格子（next 方向）

---

## 为什么需要它

需求：一个数组，**改**某个位置的值 + **查**某段区间的和，两件事交替大量出现。

| 做法 | 查区间和 | 改单点 | 痛在哪 |
|---|---|---|---|
| 只存原数组，现场累加 | **O(n)** | O(1) | 查询一多就崩：1e5 次查询 × 1e5 长度 = 10^10 次加法，直接超时 |
| 提前存好前缀和数组 `pref[]` | O(1) | **O(n)** | 改一个数，它右边所有 `pref` 全得重算；数据一动就废 |
| **树状数组** | **O(log n)** | **O(log n)** | 两头都快（代价：只能"加"不能"乘"，且查询得能拆成前缀相减） |

**生活化比喻**：一本书想知道"第 1 页到第 200 页共多少字"。
- 笨办法一：从第 1 页数到 200 页（查得慢）。
- 笨办法二：把每一页到第 1 页的累计字数全抄在书边（改一个错字要重抄一大片）。
- 树状数组：只在**第 1、2、4、8、16… 页**边各记一小段累计（"第 5~8 页共 1200 字"），
  要拼 200 页时按二进制拆成几段，查只跳几跳；改一个字也只改那几段。

本节第 1 幕就把这张表**跑出来**给你看：查 `a[1..7]`，方案 A 碰 7 格、方案 B 碰 1 格但要改 6 格、
树状数组查和改都只碰 3 格。

## 内存布局图解

**这就是整个结构需要记住的一张图**（n = 8；▓ 的右端一定对齐到自己的下标）：

```
    原始下标 :   1     2     3     4     5     6     7     8
                ─────────────────────────────────────────────
    tree[1]  :   ▓                                         盖 a[1..1]   长 1
    tree[2]  :   ▓     ▓                                   盖 a[1..2]   长 2
    tree[3]  :         ▓                                   盖 a[3..3]   长 1
    tree[4]  :   ▓     ▓     ▓     ▓                       盖 a[1..4]   长 4
    tree[5]  :               ▓                             盖 a[5..5]   长 1
    tree[6]  :               ▓     ▓                       盖 a[5..6]   长 2
    tree[7]  :                     ▓                       盖 a[7..7]   长 1
    tree[8]  :   ▓     ▓     ▓     ▓     ▓     ▓     ▓     ▓  盖 a[1..8]  长 8
```

三条铁律，全从这张图里读出来：

1. **`tree[i]` 的右端点永远是自己的下标 i**，左端点是 `i - lowbit(i) + 1`，长度 = `lowbit(i)`。
2. **拼前缀 `[1..i]`**：`i → i-lowbit(i) → …` 一路往左。查 `a[1..7]` 用 `tree[7] + tree[6] + tree[4]`
   = `a[7] + a[5..6] + a[1..4]`，**不重不漏**，跳的次数 = `i` 的二进制里 1 的个数（7 = 111 ⇒ 3 次）。
3. **`a[i]` 被哪些格子记着**：`i → i+lowbit(i) → …` 一路往右。`a[3]` 在 `tree[3]、tree[4]、tree[8]`
   里都有份 ⇒ 改 `a[3]` 就改这三格。

内存里就两条 int 数组（外加一个 n 和统计字段）：

```
   BIT
  ┌──────────┬──────────────────────────────────────────────┐
  │ tree ────┼─→ [ 空 ][ 2 ][ 3 ][ 1 ][ 7 ][ 2 ][ 5 ][ 4 ][ 17 ]  ← 下标 0 空着不用！
  ├──────────┤                                                ← 数据 {2,1,1,3,2,3,4,1}
  │ a ───────┼─→ [ 空 ][ 2 ][ 1 ][ 1 ][ 3 ][ 2 ][ 3 ][ 4 ][  1 ]  ← 原值副本，给朴素对拍用
  ├──────────┤
  │ n = 8    │   trace = 0/1（要不要打印跳格）  touches = 累计碰了几格
  └──────────┘
   手算核对：tree[4] = 2+1+1+3 = 7 ✔   tree[6] = 2+3 = 5 ✔   tree[8] = 全部 = 17 ✔
```

`i & (-i)` 为什么正好算出这段长度（补码 = 取反加一，最低位的 1 被保留）：

```
      i       = 6  = 0000 0110
      ~i      =      1111 1001     （按位取反）
      ~i + 1  = -6 = 1111 1010     （这就是补码里的 -6）
      i & -i  =      0000 0010 = 2 ✔ 只剩最低位那个 1
```
原因：取反加一会把**最低位 1 右边的 0 全部变成进位链**，最低位那个 1 本身不变、
它左边的位全部翻转 ⇒ 两数相与，左边全灭，只剩它自己。

## 核心操作逐个拆解

### 1. `bit_init(b, src, n)` —— 建树

**干什么**：把 `src[0..n-1]`（注意是 C 的 0 起点）装进 1 起点的 `tree[]`。

**一步步怎么做**：
1. `calloc(n+1, sizeof(int))` 两条数组 —— **多申请 1 格就是为了空出下标 0**。
2. `a[]` 保持全 0，把每个 `src[i-1]` 当作"要加的量"交给 `bit_update`：
   一趟下来 `a[i] == src[i-1]`，`tree[]` 也同时建好，两份数据绝不会互相打脸。
3. 复杂度 O(n log n)。想 O(n) 建树有个技巧：先令 `tree[i]=a[i]`，再
   `for (i=1..n) { j=i+lowbit(i); if (j<=n) tree[j] += tree[i]; }`（"把自己这份和交给下一个需要我的大格子"）。
   本节为了少一个容易看错的循环，用了朴素建法。

**边界情况**：`src == NULL` ⇒ 全 0 起步（逆序对那幕就靠它开"频率表"）；`n <= 0` 或 malloc 失败返回 -1，
且失败时把已申请的那块 free 掉。

**对应代码**：`bit.c` 的 `bit_init()`。

### 2. `bit_update(b, i, delta)` —— 单点加，`i += i & (-i)`

**干什么**：`a[i] += delta`，并同步所有"含 a[i]"的格子。

**一步步怎么做**（以 n=8、改 `a[3] += 5` 为例，第 5 幕把这个过程逐格打印出来）：
```
   p = 3  tree[3]（负责 a[3..3]） += 5    下一个 p += lowbit(3)=1 → 4
   p = 4  tree[4]（负责 a[1..4]） += 5    下一个 p += lowbit(4)=4 → 8
   p = 8  tree[8]（负责 a[1..8]） += 5    下一个 p += lowbit(8)=8 → 16 > n ⇒ 停
   最后 a[3] += 5（副本也要跟着改，不然对拍会假）
```
**为什么这样跳一定对**：`tree[j]` 管 `a[j-lowbit(j)+1 .. j]`；
"i 落在不在 j 管的那段里"这件事，**恰好等价于**"从 i 一路 `+= lowbit` 会不会踩到 j"。这不是巧合，
lowbit 的定义就是为了构成这棵树（每格往上指向"下一个需要我的人"）。

**边界情况**：
- `i` 越界（<1 或 >n）：打印错误直接返回，绝不越界写。`i = 0` 特别危险，必须挡住（见第 4 条）。
- 题目说"把 `a[5]` **改成** 9"而不是"加 delta"：`bit_update(b, 5, 9 - bit_get(b, 5))`。第 5 幕演示了。
- `delta = 0` 白跑一趟，无害。

**对应代码**：`bit.c` 的 `bit_update()`、`bit_get()`。

### 3. `bit_query(b, i)` —— 前缀和，`i -= i & (-i)`

**干什么**：返回 `a[1] + … + a[i]`。

**一步步怎么做**（查 `a[1..7]`）：
```
   p = 7  吃 tree[7] = a[7]        剩 a[1..6]，p -= lowbit(7)=1 → 6
   p = 6  吃 tree[6] = a[5..6]     剩 a[1..4]，p -= lowbit(6)=2 → 4
   p = 4  吃 tree[4] = a[1..4]     剩 a[1..0] = 空，p -= lowbit(4)=4 → 0
   p = 0  循环条件 p > 0 不成立 ⇒ 停（tree[0] 从来没被读，天然就是"空地"）
```
**为什么是 O(log n)**：每跳一次就把 `p` 的**最低那个 1 抹掉**，二进制里最多 log n 个 1 ⇒ 最多跳这么多次。
n = 8 时最多 4 格；n = 100000 时最多 17 格（对拍那一幕能亲眼看到 BIT 只碰 2~5 格，朴素要加 8 次）。

**边界情况**：
- `query(0)` 必须返回 **0**：这是"空区间"的定义，而 `range_query(1, r)` 正是要用 `query(1-1)`。
  写错这条，所有从 1 开始的区间全错。
- `i > n`：打印提示并截断成 `n`（等价于"查全部"），不读数组外的内存。
- `i < 0`：非法，返回 0 并打印错误。

**对应代码**：`bit.c` 的 `bit_query()`。

### 4. `bit_range_query(b, l, r)` —— 区间和 = 前缀相减

```
     a[l..r] = query(r) - query(l-1)

               a[1] … a[l-1] │ a[l] … a[r]
             ←── query(r) 全长 ─────────→
             ← query(l-1) →        ⇒ 一减就剩中间那段
```
一趟查询要走**两趟** `bit_query`，所以 `touches` 是两趟之和（这就是它做成"累计"而不是"上次"的原因）。

**边界情况**：`l == r` 得到单点值（可以用来替代 `bit_get`，不用额外存副本）；
`l < 1`、`r > n`、`l > r` 都会打印错误并返回 0。

### 5. `bit_lowbit(i)`、`bit_reset_touches(b)`、`bit_print_cells()`、`bit_print_coverage_chart()`

- `bit_lowbit(i)`：`i & (-i)`。**`lowbit(0) = 0` 是"下标必须从 1 开始"的唯一原因**（第 6 幕专门演示）。
- `bit_reset_touches(b)`：把"碰了几格"的累计清零，统计完再比才有意义。
- `bit_print_cells(b, tag)`：把 `a[]`、`tree[]`、`lowbit` 三行并排打出来，再逐格写清"你负责哪一段"。
- `bit_print_coverage_chart(n)`：把上面那张灵魂覆盖图**用代码画出来**，第 3 幕的输出就是它。

### 6. `bit_count_inversions(freq, src, n, max_value)` —— 应用：逆序对

**为什么"逆序对"能翻译成"每个元素右边有几个比它小"**：
每一对逆序关系都有唯一的"左边那个"和"右边那个"。所以对每个位置 j 数一遍
"在它右边、值比 `a[j]` 小的元素个数"，加起来正好把每对数了一次，不重不漏。

**树状数组怎么帮忙**：**从右往左**扫，`freq` 里存的是"某个值出现过几次"（把值当下标，叫频率树）：
```
   扫到位置 j 时，freq 里恰好只有 j 右边那些元素
   query(a[j] - 1) ⇒ 右边比我小的有几个        ← 累加到答案
   update(a[j], +1) ⇒ 把 a[j] 登记，继续往左
```
第 8 幕把 8 个元素的累计过程逐行打印，最后和朴素 O(n²) 的答案 14 完全一致。

**边界情况**：值必须落在 `1..max_value`（因为要拿值当 1 起点下标）；有 0 或负数要先整体平移，
值域太大要先**离散化**（排序去重后换成名次）—— 那是另一个话题，这里用 1..6 的小数组绕开。

## 复杂度表

| 操作 | 树状数组 BIT | 原数组 + 现场累加 | 前缀和数组 | 线段树 |
|---|---|---|---|---|
| 单点修改 | **O(log n)**，实测碰 2~4 格 | O(1) | O(n) | O(log n) |
| 前缀和 / 区间和 | **O(log n)** | O(n) | O(1) | O(log n) |
| 区间修改 + 区间查询 | ✖ 不擅长（要套两层 BIT 才行，很难懂） | O(n) | ✖ | **O(log n)**（懒标记）→ 见 `09-others/segment-tree/` |
| 建表 | O(n log n)（有 O(n) 技巧） | — | O(n) | O(n) |
| 额外空间 | O(n)，一条 int 数组（本实现多存一份原值，仍 O(n)） | O(1) | O(n) | O(4n) |
| 常数 / 代码量 | 极小：查询和修改各 3 行 | — | — | 递归、pushdown，几十倍代码量 |

一句话：**能在 BIT 和线段树之间选，就选 BIT**（快 3~5 倍、短 10 倍、几乎不会写错）。
只有"区间修改 + 区间查询"这种 BIT 别扭的活才上限段树。

在项目根目录：

```bash
make one DIR=09-others/binary-indexed-tree
# 内存安全检查：
gcc -Wall -Wextra -Wshadow -std=c11 -g -fsanitize=address -static-libasan \
    09-others/binary-indexed-tree/*.c -o /tmp/bit && /tmp/bit
```

对拍那 24 步用的是**自己写死的 LCG 伪随机**（`seed = seed*1103515245 + 12345`），不是 `rand()`：
`rand()` 的序列由各 C 库自己定，换平台就变，README 里贴的输出就没法复核了。

## 常见的坑

1. **下标用了 0**。`lowbit(0)=0` ⇒ `p += lowbit(p)` 原地打转、`p -= lowbit(p)` 永远出不去，
   程序假死。症状是"跑起来没输出"。解法：数组开 `n+1`，`tree[0]` 永不使用，0 起点的数据进 BIT 前 `+1`。
2. **`query(0)` 没返回 0**。所有 `range_query(1, r)` 都错，而且错得很有规律（只有从 1 开始的区间不对），
   很难一眼看出来。循环条件写 `p > 0` 而不是 `p >= 0` 就是为这个。
3. **建树时把 a[i] 加了两遍**。先 `a[i]=src[i]` 再 `bit_update(b,i,a[i])`（它内部还会 `a[i]+=delta`）
   ⇒ 副本变成双倍值。我自己写完就在这儿翻的车：覆盖图和 tree[] 全对，
   但 `a[i]` 那行是原数组的两倍，第 1 幕查询结果当场从 16 变成 23。
   **教训：朴素对拍必须留在 demo 里，它比任何自我检查都狠。**
4. **`tree[i]` 里存的是"一段的和"，不是"第 i 个值"**。想拿 `tree[5]` 当 `a[5]` 用必错。
   要单点值：`range_query(i,i)`，或者像本实现这样自己留一份 `a[]` 副本。
5. **忘记 `bit_update` 是"加 delta"不是"设成 v"**。题目说"把 a[5] 改成 9"，要自己算差
   `9 - bit_get(5)`。直接 `bit_update(5, 9)` 会把 9 加上去变成 11。
6. **拿它做区间修改**。BIT 天生只擅长"单点改 + 前缀查"。硬做区间改要"差分 BIT"（两层套娃），
   代码难度暴涨还容易错 —— 这种需求请直接去用线段树（`09-others/segment-tree/`）。
7. **溢出**。前缀和会随 n 线性增长，`int` 在 2×10^9 附近就炸。本 demo 数据很小，
   真实题目里 `tree[]` 建议用 `long long`。
8. **`touches` 是累计值不是"本次值"**。所以统计前必须先 `bit_reset_touches()`，
   否则数字会越加越大，第 7 幕的对比就不准了。

## 什么时候用它 / 什么时候别用

**适合**：
- 单点修改 + 前缀和/区间和查询（最标准的场景）
- 数逆序对、"第 k 小的数"（值域上建树，把值当下标）、扫描线类计数问题
- 静态数据 + 频繁动态微调；或作为更复杂解法的前置预处理
- 内存吃紧的场合：一条 int 数组就搞定，线段树要 4n 且常数大

**别用**：
- 需要**区间修改 + 区间查询**（线段树的主场，见下一节）
- 查询的东西**不能拆成前缀相减**：比如"区间最大值"没法用 `pref[r]-pref[l-1]` 反推
- 数组下标从 0 开始且值域稀疏（要先离散化，多一层心智负担）
- 数据基本不变、只查一次 ⇒ 前缀和数组更直白

## 自检问题

1. `tree[6]` 负责的是哪几个原始元素？为什么不是 `a[1..6]`？
   **答**：`lowbit(6)=2` ⇒ 负责 `a[5..6]`。负责 `a[1..6]` 的是 `tree[4] + tree[6]` 两格合起来。
   每格只管"长度 = lowbit"的一小段，右端点是自己的下标。
2. 为什么 `i & (-i)` 能得到最低位的 1？
   **答**：`-i` 是"取反加一"。加一会让最低位 1 右边的 0 全变成 1、最低位那个 1 保持不变、
   它左边全部翻转。原数与它相与：左边互相抵消为 0，右边原本是 0 也抵消，只剩最低位那个 1。
3. 查 `a[1..13]` 需要读几个格子？
   **答**：13 = 1101₂，3 个 1 ⇒ 3 格：`tree[13](a[13]) + tree[12](a[9..12]) + tree[8](a[1..8])`。
   一般地，跳的次数 = i 的二进制里 1 的个数，上界 log n。
4. 为什么下标必须从 1 开始？给出两种跳法各自失败的准确原因。
   **答**：`lowbit(0)=0`。`p += lowbit(p)` 让 p 永远停在 0（修改死循环），
   `p -= lowbit(p)` 让 p 永远回不到正数（查询死循环）。所以申请时多开一格、`tree[0]` 空置，
   查询循环写成 `p > 0`。
5. 有了 BIT，为什么本实现还额外存一份普通数组 `a[]`？不加行不行？
   **答**：加它是为了两件事：打印当前值、给朴素版当"标准答案"的来源（`bit_naive_range_sum` 就是加它）。
   不加也能活：单点值可以用 `range_query(i,i)` 拿到（O(log n)）。教学上"能被朴素算法逐格验证"更值钱。
6. 树状数组和线段树，该选哪个？
   **答**：能表达成"前缀相减"的查询 + 单点修改 ⇒ BIT（代码短、常数小、快 3~5 倍）。
   需要区间修改、或者查询不能拆成前缀（区间最大值、最小值、GCD 等）⇒ 线段树。
