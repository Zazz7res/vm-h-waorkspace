# 连通分量与判环 connected-components —— 一趟 DFS，把「这几块」和「有没有圈」都问完

> 这是 `07-graph/dfs` 那节留的坑的正式填法：上一轮 DFS 从 0 出发只覆盖了 `{0,1,2,3}`，
> `{4,5,6}` 和 `{7}` 一个没碰到，而且**程序一声不响、返回值也正常**。
> 当时口头补的那句「外层再扫一遍」，写出来就是本节的算法：**一轮 DFS = 一个连通分量**。
> 顺手把判环也收了：无向图用「带父亲的 DFS」，有向图用「白/灰/黑三色法」。

---

## 一句话是什么

给无向图的**每个顶点发一个「分量编号」**：`comp_id[u]` 表示 u 属于第几块。
做法只有一句：外层扫每个还没编号的点，见到就**以它为根起一轮 DFS**，这轮碰到的点全写上当前编号 k，然后 k++。
一轮 = 一块，所以**最后的 k 就是连通分量的个数**。

于是白送两个结论：

- 整张图连通吗 ⟺ `k == 1`
- u 和 v 连通吗 ⟺ `comp_id[u] == comp_id[v]`（比一次数组，O(1)）

## 为什么需要它（不用它会这样）

先算一笔账。假设你要在一堆「这两个人是不是同一个朋友圈？」的查询里找答案：

```
不用预处理：每问一次 (u,v) 就从 u 起一轮 DFS/BFS 看能不能碰到 v → 单次 O(V+E)，问 Q 次花 Q × O(V+E)
用本节：    先跑一次 cc_find_all()（O(V+E)，矩阵版 O(V²)）预处理，之后每次查询只比两个 int，O(1)
```

关键在「**visited 数组本来就要写**」这件事。DFS 为了不去重，一定会给每个点盖一个
「我来过」的章；本节只是把这个章从 `1` 换成了「我是第 k 轮发的 1」——**同一个数组多带了一份信息**，
一点额外开销都不花。`cc.c` 里甚至没再单独开 visited，`comp_id[]` 本身就是 visited：
`-1` = 没来过，`>= 0` = 来过、并且知道是哪一轮来的。两个数组反而会有「不同步」的 bug 空间。

不这么干会怎样？代码里备好了反面教材：`cc_has_cycle_undirected_from()` **只起一轮**，
拿它查图 C2（环藏在第二个分量里），它一本正经回答「无环」——不报错、退出码正常、
答案就是错。上一节「漏掉一整个分量」的 bug，本质是同一个：**一轮遍历只对这一轮负责，不对全图负责。**

## 图解（ASCII 图 + 内存/结构布局）

本节主角图 G：8 个顶点、7 条边，长这样（`cc_sample_undirected()` 硬编码，无向）：

```
   分量 0（带一个三角环）      分量 1（又一个三角环）    分量 2
                                                        ┌───┐
      0 ───── 1                                         │ 7 │  ← 孤立点
      │ ╲   ╱ │                                         └───┘     自己就是一块
      │   ╲ ╱  │ 2 ─ 3          4 ─── 5                 
      └─── 2 ──┘                  ╲ ╱                     
                                   6                       ← 两个三角环
    边表：0-1  1-2  0-2  2-3 | 4-5  5-6  4-6 |（7 谁也不连）
```

跑完 `cc_find_all()` 之后得到的 comp_id，摊在内存里就是一行 8 个 int：

```
        下标 u：  0   1   2   3   4   5   6   7
    comp_id[u]：  0   0   0   0   1   1   1   2
                 └─ 分量 0 ─┘   └分量 1─┘   └孤立点自成一分量 2
```

图的容器（`cc.h` 里的 `CCGraph`）是一张固定大小的矩阵 + 一个类型标记：

```
  CCGraph（整块住在调用者的栈上）
  ┌──────────────────────┬─────┬─────┬─────────────┐
  │ int edge[8][8]        │ v=8 │ e=7 │ directed=0  │ ← 造图时定死，之后只读
  │ （64 个 int 按行连续） │     │     │             │
  └──────────────────────┴─────┴─────┴─────────────┘
   无向边 = 对称涂两格：edge[a][b] = edge[b][a] = 1
   顶点 7 那一行全 0 = 孤立点（不是「空行没意义」，它照样是一个分量）
```

外层扫描的流程（对照真实输出，第 1 幕）：

```
u=0 未编号 → 起一轮收 {0,1,2,3} 写 k=0，k++      u=4 未编号 → 收 {4,5,6} 写 1，k++
u=7 未编号 → 收 {7}      写 2，k++              return k=3   ← 轮数就是答案
（途中 u=1,2,3,5,6 都已归队，外层直接跳过——一轮 DFS 替它们答过了）
```

三色法的状态机（有向判环 `cyc_dir_go()`，全图就三个颜色）：

```
     白色 CC_WHITE ：压根没来过
       │ 进入（涂灰）
     灰色 CC_GRAY  ：来过但**还没走完** = 还压在递归栈里 = 还站在「当前这条路上」
       │ 所有邻居处理完（涂黑）
     黑色 CC_BLACK ：走完了，已出栈

     碰到白 → 钻进去        碰到灰 → ★有环（它在我路上，我又指回它 = 闭合）
     碰到黑 → 完全正常（只是「有人比我先下班」，不构成回路）
```

## 逐个操作拆解（对应 cc.c 里每个函数）

### `adjacent_on(g, u, j)` —— 「u 和 j 算不算相邻」的唯一口径

静态小工具。无向图看 `edge[u][j]` 就够；有向图算**弱**连通时额外倒过来看 `edge[j][u]`——
这一眼就是在「无视箭头」。★ 全仓库只有连通分量这一组函数允许用它：`cc_reachable` 和判环
都必须严格顺箭头，一旦也「两边都看」，无环的 DAG 会被判成有环。复杂度 O(1)。

### `cc_sample_*()` 五张固定图 + `cc_print()`

G（3 分量有环）、T（树，阴性对照）、C2（环藏在第二个分量）、DAG（有向无环）、CYC（有向含环 + 孤立点 0）。
全部硬编码——每个判据都要**一正一反两个对照**：判环函数光在有环图上说「有」不值钱，
还得在老实树上说「没」才算被验证过。`cc_print()` 打矩阵 + 每行出边（有向图还打入边），O(V²)。

### `comp_go()` + `cc_find_all()` —— 本节的心脏

`comp_go` 就三拍：进门第一件事 `comp_id[u] = id`（打标记必须在循环外，否则环上会无限递归）；
逐个邻居看 `adjacent_on`，`j == u`（自环）直接跳过；邻居还 -1 就递归进去，
已归队就打印「不重复收」。`cc_find_all` 套上外层 for，返回轮数 k。

- **为什么 comp_id 能兼职 visited**：见上面那笔账，`-1` 和 `>=0` 天然两态。
- **孤立点**：外层照样以它为根起一轮，一轮收 1 个点，k++ 照样发生——
  千万别写「度为 0 就跳过」，那样 `{7}` 就不是一个分量了（代码在打印里专门标注了这点）。
- **自环**：对分量毫无影响（它就一个点），`j == u` 的跳过保证不会自己咬自己递归。
- **有向图进来先轰一条警告**：这里算出来的是**弱连通分量**，不是 SCC，输出里那条 ⚠ 就是它。
- 复杂度：矩阵版每个点扫一行 **O(V²)**；换成邻接表就是 **O(V+E)**。最坏递归深度 O(V)。

### `cc_print_components()` —— 把 comp_id 翻译成人话

按编号分组列出每个分量、顺手数点数（n==1 就注明「孤立点也算一个分量」），
再打印「两个白送的结论」。复杂度 O(V·k)，k 是分量数。

### `cc_component_stats()` —— 免费的交叉验证

对每个分量数出 V_k 和 E_k，用无向图经典结论：`E == V-1` ⇒ 是树（必无环）；`E >= V` ⇒ 必有环。
环的存在性被 DFS 判了一次，又被边数判了一次，两个答案**必须一致**，不一致就是代码有 bug。
有向图明确拒绝套用（DAG 7 点 8 弧 E>V 却无环）。实现是分量数 × 每点扫一行，O(k·V²)。

### `cyc_und_go()` + `cc_has_cycle_undirected()` —— 无向判环（正确版）

判据一句话：**碰到「已访问且不是父亲」的邻居 ⇒ 有环。**
- 为什么必须带 father 参数：无向边在矩阵里涂两格，从 u 钻到 v，v 一回头必看见已访问的 u。
  不排掉父亲，一棵树会被判成「处处有环」。
- 为什么排掉父亲之后「已访问」就真的是环：它已访问、又不是父亲 ⇒ 它是当前路上**更早的祖先**，
  它 → … → 我 →（这条边）→ 它，闭合。
- **自环进门先查对角线**：`edge[u][u]` 自己就是环（长度 1）。
- 外层照样扫全图：环可能藏在第二个分量（C2 就专门干这个）。
- 图类型不对（directed==1）直接**打印原因并拒绝**，返回 -1。
- 复杂度 O(V²)（矩阵版），辅助 visited/parent 各 O(V)。

### `cc_has_cycle_undirected_from()` —— 故意只起一轮的反面教材

和正确版共用 `cyc_und_go`，只是没有外层 for。输出里它会对着 C2 回答「0（无环）」，
main.c 紧跟着补一句「← 错！这一片确实没环，可整张图有环」。**错得很安静**是这类 bug 的招牌。

### `build_cycle()` + `cc_print_cycle()` —— 把环从 parent 链里拽出来

命中坏边 u→j 时（j 是灰色/已访问的祖先），从 u 沿 `parent[]` 往上爬到 j，
倒序接在 j 后面，得到 `j → … → u`；打印时再补一个首点闭合成 `0 -> 1 -> 2 -> 0`。
`parent[j] = u` 必须在递归前写，`build_cycle` 全靠它。O(V)，且防了 parent 链断裂的死循环。

### `cyc_dir_go()` + `cc_has_cycle_directed()` —— 有向三色法

进门涂灰；邻居白的钻、灰的★命中（同样沿 parent 挖出环）、黑的无视；所有邻居处理完涂黑。
外层扫全图（CYC 第一个点 0 是孤立点，只起一轮又会漏）。颜色数组**跨轮不清零**。
无向判据为什么在这不够：0→1、0→2、2→1 的菱形里，2 碰到「已访问且非父亲」的 1 会误报——
三色的价值就是把「访问过」细分成「还在路上（灰）」和「已经下班（黑）」。
拿三色查无向图同样会误判（每条边都是反向弧，秒命中），所以函数看到 directed==0 就拒答。
复杂度 O(V²)，颜色数组 O(V)。

### `cc_reachable()` —— 演示「单向可达」用的一次遍历

严格只看 `g->edge[u][j]`（不许用 `adjacent_on`），数组当下推队列边展开边扩集合。
从 6 出发能到 6 个点，从 0 出发只能到 {0}——对比一出，「我能到你 ≠ 你能到我」就不用讲了，
这正是 SCC 要解决的问题。复杂度 O(V²)（每个点扫一行），结果集和 DFS 一模一样，只是顺序不同。

## 复杂度一览

| 函数 | 时间（矩阵版） | 邻接表版 | 额外空间 |
|---|---|---|---|
| `cc_find_all` | O(V²) | **O(V+E)** | O(V)（递归栈 + comp_id） |
| `cc_print_components` | O(V·k) | O(V) | O(1) |
| `cc_component_stats` | O(k·V²) | O(V+E) | O(1) |
| `cc_has_cycle_undirected` / `_from` | O(V²) | O(V+E) | O(V)（visited/parent） |
| `cc_has_cycle_directed` | O(V²) | O(V+E) | O(V)（color/parent） |
| `build_cycle` | O(V) | O(V) | O(V) |
| `cc_reachable` | O(V²) | O(V+E) | O(V) |

（k = 分量数，k ≤ V；V=8 的小示例里这些数字都小到看不见，讲的是渐进。）

逐段读：第 0 轮的缩进就是递归深度，`0 已经归队了` 出现多次——那些是三角环 0-1-2 的反向重复边，

这就是孤立点的处理方式：**照样起一轮、照样算一个分量**。最后 comp_id 那行就是上面图解的实物。

  返回 1（1=有环）
  挖出来的环：1 -> 2 -> 3 -> 1

「命中即快照」很值钱：0 已经黑（第一轮孤立地进出过），1/2/3 全灰——灰就是还压在栈上的当前路径，
3→1 这条边从路尾指回路中，环闭合。其余输出：第 2 幕 E/V 交叉验证表（分量 0、1 报
`E >= V ⇒ 必有环`，与 DFS 挖出的两个三角环一一吻合；树 T 报 `E == V-1` 阴性对照通过）、
第 3 幕 C2 的「只起一轮答复 0（错）」vs 全图扫描答复 1（对）、三色法查 DAG 全程
「碰到黑色 → 正常」、算法用错图类型被 `✗ 拒绝` 的两段，以及第 5 幕可达集对比。

## 常见的坑

1. **只起一轮 DFS**。
   错法：`dfs(0)` 完事，把「从 0 到不了」当成「不存在」。对法：外层 for 扫每个未访问点——
   连通分量、判环都逃不掉，本节 `cc_has_cycle_undirected_from` 就是专门留的活标本。
2. **无向判环不带父亲**。
   错法：见 `visited[j]` 就喊有环。对法：`visited[j] && j != father`。
   少排父亲，最老实的一棵树（T 图）都会被判成「处处有环」，因为它每条边都撞得回来路。
3. **两套判环互相搬用**。
   错法：拿 visited 两态查有向图（菱形分叉误报），或拿三色查无向图（反向弧秒命中）。
   对法：图类型和算法必须匹配；本节代码直接 `return -1` 拒答，把原因打出来。
4. **把孤立点踢出统计**。
   错法：`if (度为 0) continue;`，`{7}` 凭空蒸发，分量数少 1。
   对法：孤立点也是一个分量（V=1，E=0=V-1，平凡树）——`cc_print_components` 特意注明。
5. **有向图上把弱连通当强连通讲**。
   错法：`cc_find_all` 对 DAG 返回 1 块，就宣布「这图连通」。对法：那只是「无视箭头」的弱连通；
   「互相可达」的 SCC 本节没实现（代码已大声警告），别拿它当答案——DAG 的 SCC 其实是 7 个（每点一块）。
6. **自环不当环**。
   错法：邻居循环里没排 `j == u` 的分支意识，分量统计里把对角线重复计数。
   对法：判环进门先查 `edge[u][u]`（长度 1 的环）；分量遍历里跳过它（自己到自己不改变归属）。

## 自检问题

1. 为什么 `cc_find_all` 不需要单独的 visited 数组？
   **答：** comp_id 本身就两态：-1 没来过，>=0 来过且知道哪轮。一个数组兼职，还免了「两数组不同步」。
2. 一张 1000 点 10000 边的无向图，要回答 10 万次「两点是否连通」。给最优方案与代价。
   **答：** 预处理一次 O(V+E)，查询每次比一次 int，共约 10000 + 10⁵×O(1)；逐次 DFS 则是 10⁵×O(V+E)。
3. 孤立点算不算一个连通分量？代码在哪验证了这一点？
   **答：** 算，V=1 的平凡树。G 图顶点 7、CYC 图顶点 0 都是专门留的对照。
4. 无向判环里「已访问且非父亲」为什么一定是环？
   **答：** 已访问说明它在当前路径上（DFS 只访问当前路径及其已完成分支的点；对无向连通块，
   非父亲的已访问邻居必是祖先），它是祖先 ⇒ 它→…→我→它闭合。
5. 三色法里碰到黑色为什么不报错？
   **答：** 黑色表示「它和它能到的一切早就办完出栈了」，从当前路径出发不可能再回到它；
   那条边只是复用，不成环。DAG 里全是这种复用。
6. 自环在分量和判环里的待遇分别是什么？
   **答：** 分量：跳过，不影响归属（它本来就在某块里）。判环：它是长度 1 的环，进门先查对角线。
7. `cc_reachable` 和 `comp_go` 长得几乎一样，唯一本质差别在哪？
   **答：** 看的边不同：前者只顺箭头看 `edge[u][j]`，后者用 `adjacent_on`（有向图倒着也看）。
   一行之差，一个是「可达」，一个是「弱连通」。
