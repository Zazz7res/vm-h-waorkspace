# Floyd 全源最短路 floyd —— 五行三重循环，一次问完「任意两点」

> `07-graph/dijkstra` 和 `bellman-ford` 都是【单源】：固定一个起点，算它到所有点。
> 本节换成【多源】：一趟算出 **V×V 所有点对**之间的最短距离。
> 全部核心代码就 5 行，唯一的硬核要求是**循环顺序 k 必须在最外层**——
> 这一节不仅把正确版跑通，还现场跑一个「k 放最内层」的错版，让你看清它错得多安静。

---

## 一句话是什么

`dist[i][j]` 先填「i 到 j 的直接边权」，然后三重循环：

```
for (k = 0; k < n; k++)            ← k 是【中转站许可证】，必须在最外层
    for (i = 0; i < n; i++)
        for (j = 0; j < n; j++)
            if (两段都不为 ∞ 且 dist[i][k] + dist[k][j] < dist[i][j])
                dist[i][j] = dist[i][k] + dist[k][j];
```

k 的含义**不是「第 k 步」**，而是「只允许把编号 ≤ k 的点当中转站」。第 k 轮结束时：

```
dist[i][j] =「从 i 到 j，只准借道 {0,1,...,k} 当中转，能走出的最短路」
```

许可证一张张发到 k = n-1，中转权限全部放开，得到的就是真·全图最短路。

## 为什么需要它（不用它会怎样）

**需求是「任意两点都要答案」时**，手里的牌有这几张：

| 方案 | 干什么 | 代价 |
|---|---|---|
| 跑 V 次 Dijkstra（堆版） | 每个点当一次源 | O(V·E·logV)，稀疏图快 |
| 跑 V 次 Bellman-Ford | 同上，能带负权 | O(V²·E)，慢 |
| 每问一次现走一遍 BFS/DFS | 无权图可以 | 带权就答不了 |
| **Floyd** | 一次填满整张表 | **O(V³)，代码 5 行** |

V 小的时候（几百以内）O(V³) 和 O(V·E·logV) 根本分不出胜负，而 Floyd 的**实现复杂度是碾压性的低**：
没有优先队列、没有定稿逻辑、没有松弛轮数的推理——三行循环体，写不出 bug 的一方反而值得选。
另外两点独门优势：**能直接吃负权边**（Dijkstra 不行），以及**跑完看对角线就知道有没有负环**。
不用它、把 k 放到最内层会怎样？本节实测：矩阵照样填满、程序一声不吭，只是 `d[1][0]` 从 7 变成 13——
**错得很安静**，这是本节能给你上的最狠一课。

## 图解（ASCII 图 + 内存/结构布局）

演示图①（4 点有向带权，`mat_build_demo()`）：

```
   边（权值）： 0->1 = 3    0->2 = 8    1->2 = 2
               1->3 = 9    2->3 = 1    3->0 = 4

                3              2
    (0) ──────────> (1) ──────────> (2)
     ^   ╲           ╲              │
   4 │     ╲ 8         ╲ 9          │ 1
     │       ╲           ╲          v
     + <──────╲──────── (3) <───────┘

    大环 0->1->2->3->0 兜底，任意两点都可达，矩阵里没有 ∞
```

存图和算路都靠「表」，本节用 `typedef int Table[MAX_V][MAX_V];` 起了名字。内存里它就是按行连续的一片 int：

```
  Matrix（栈上，MAX_V = 8）                Table dist / next（同样是栈上的 8×8）
  ┌────────────────────────┐               w[0][0] w[0][1] ... w[0][7] | w[1][0] ... | ... 
  │ int n                  │               └───────── 第 0 行（8 个）────────┘ 第 1 行
  │ int w[8][8]  ← 64×4=256 字节连续块      &w[i][j] == (int*)&w + i*8 + j   ← 「行宽×行号+列」
  └────────────────────────┘               所以传参必须写 int m[][MAX_V]：编译器得知道一行多宽
                                           写成 int **m 是【错的】——那是指针数组，排布完全不同
```

「许可证」逐轮放宽，每轮只有个别格子变小（数字取自真实输出）：

```
k=-1 初始   d 就是直接边表：d[0][2]=8（直连），d[1][0]=∞（没有这条直接边）
k= 0 借道{0}   [3][1] ∞→7  [3][2] ∞→12          ← 3->0->1、3->0->2
k= 1 借道{0,1} [0][2] 8→5  [0][3] ∞→12  [3][2] 12→9   ← 0->1->2 比直连 8 近！
k= 2 借道{0..2}[0][3] 12→6 [1][3] 9→3            ← 顺环再推进
k= 3 借道全图  [1][0] ∞→7  [2][0] ∞→5  [2][1] ∞→8   ← 1->2->3->0 = 2+1+4，绕了三个中转才成形
```

看 `d[1][0]`：它要到 **k=3** 才变对——它依赖的零件 `d[1][3]`（k=2 轮才降到 3）和 `d[3][0]`。
零件必须在本轮开始前加工好，这就是 k 必须在外层的全部理由。

## 逐个操作拆解（对应 floyd.c 里每个函数）

### `mat_init()` / `mat_add_arc()` / `mat_add_edge()` / `mat_print()` —— 邻接矩阵存图

Floyd 天生配矩阵：它的状态就是一张 `dist[i][j]` 表，初值恰好就是「直接边权表」。
`mat_init` 填 ∞、对角线写 0（**一步不走的距离是 0，这一格绝不能 ∞**）。
`mat_add_arc` 里最关键的一行是 `if (weight < g->w[u][v])`——**重边取较小者**，
直接覆盖会把短边丢掉，初值表就失真了。`mat_add_edge` 就是对称调两次 `mat_add_arc`。
越界顶点、超上限 n 都会打 `[错误]` 并拒绝。建图 O(V²)（memset 级），加边 O(1)。

### 五张演示图 `mat_build_demo/negative/neg_cycle/dag/shared()`

全部硬编码：① 4 点主图（专门造了 `d[1][0]` 这条「绕三个中转」的路给错版陪葬）；
② 含负权无负环（DAG，天生没有环）；③ 3 点负环（1-1-1 = -1）；④ 链状 DAG 给传递闭包；
⑤ 全仓库共用的 6 点无向图，专门和 dijkstra 节的输出对拍。

### `table_print()` / `table_diff_note()` —— 打印与「本轮改了哪些格子」

`table_print` 手工补空格而不是 `%4s`，因为 ∞ 是 UTF-8 三字节但只显示一列，`%4s` 会算错宽度。
`table_diff_note` 拿本轮开跑前的备份和结束后对比，逐格列出变小的——这就是每轮 k 干活的凭证。

### `floyd_all_pairs()` —— 主算法

骨架就是开头那 5 行，另有四件事值得看：

1. **两道防溢出**：`INF_DIST` 取 1e9 而不是 INT_MAX（INT_MAX 一加必溢出成负数，「负数 < 任何值」会污染整张表）；
   循环里再对 `dist[i][k]`、`dist[k][j]` 判 `>= INF_DIST` 就 continue——前者防事故，后者防无意义比较，
   大图上 i 行先判一次能整行跳过，省掉 n 次内层循环。
2. **next 表同步维护**：`dist[i][j]` 被绕 k 改小时，`next[i][j] = next[i][k]`
   ——从 i 去 j 现在要先走去 k，那第一步就是「去 k 的第一步」。一张表给距离，一张表给走法。
3. **快照教学**：`show_snapshots` 为 1 时，每轮 k 结束打整张矩阵 + diff 清单（README 下面引用的就是它）。
4. **收尾查对角线**：任何 `dist[i][i] < 0` ⇒ 有负环，返回 1（此时整张表不可信）。

复杂度：时间 O(V³)（三重循环，i 行跳过优化只减常数不改渐进），空间 O(V²)。

### `floyd_wrong_loop_order()` —— 故意写错的对照版

把 k 塞到最内层：`for(i) for(j) for(k)`。看起来「反正三重循环都跑了」，其实算 (i,j) 时
拿来当零件的 `dist[i][k]` 可能是【还没轮到更新】的旧值——旧 = 偏大 = 该松弛的没松弛。
演示图①上 `d[1][0]` 用旧零件 `d[1][3]=9` 算出 9+4=13，正确是 2+1+4 那一路的 7。
正确的可接受顺序只有 k 在前的（k-i-j、k-j-i）；本函数只有教学价值，别在真实项目里调用。

### `floyd_negative_cycle_vertex()` —— 对角线抓负环

初值 `dist[i][i] = 0`（原地不动）；它变负只能是因为「从 i 绕一圈回 i」这条路是负的 ⇒ 圈即负环。
找到就返回那个顶点，没有返回 -1。O(V)。

### `floyd_reconstruct()` —— 用 next 表走完整路径

`cur = next[cur][dst]` 一跳一跳走到 dst。三个边界：src==dst 直接返回；
`next[src][dst] < 0` 不可达返回 -1；**步数被 max_len 封顶**——有负环时 next 会在环上打转，
宁缺毋滥也不死循环。O(路径长度)。

### `floyd_transitive_closure()` —— 换一对运算符就是另一个算法

```
最短路：  d[i][j] = min(d[i][j],  d[i][k] + d[k][j])
可达性：  r[i][j] =  r[i][j]   | (r[i][k] && r[k][j])
```

min→或、+→与，骨架一行不动——这就是「Floyd 是 (min,+) 半环上的算法，换个半环换个用途」。
本节对角线初始化成 0（「站在原地不动」不算可达；有的教材写 1，那是自反闭包，两种都有人用，
**关键是别一处 0 一处 1**）。复杂度同样 O(V³)。

## 复杂度一览

| 操作 | 时间 | 空间 |
|---|---|---|
| `floyd_all_pairs` | O(V³) | O(V²)（dist + next；快照版多一张 before 备份） |
| `floyd_wrong_loop_order` | O(V³) | O(V²) |
| `floyd_negative_cycle_vertex` | O(V) | O(1) |
| `floyd_reconstruct` | O(路径长度) | O(V) |
| `floyd_transitive_closure` | O(V³) | 原地，O(1) |
| 建图（mat_init/add） | O(V²) / 加边 O(1) | O(V²) |
| 对比：V 次堆版 Dijkstra | O(V·E·logV) | O(V+E) |
| 对比：V 次 Bellman-Ford | O(V²·E) | O(V·E) 边表 |

## 常见的坑

1. **k 不在最外层**。
   错法：`for(i) for(j) for(k)`，指望「三重循环都跑了就对」。
   对法：k 永远压最外（k-i-j、k-j-i 可换）；本节错版实测把 7 算成 13 且不报任何错。
2. **INF 相加溢出**。
   错法：`#define INF INT_MAX`，松弛式一加溢出成负数，整张表被污染。
   对法：本节双保险——INF 取 1e9，且加之前先判 `>= INF` 跳过。
3. **建图时重边直接覆盖**。
   错法：`g->w[u][v] = weight;`，后加的长边吃掉先加的短边。
   对法：`mat_add_arc` 的 `if (weight < g->w[u][v])`：初值必须是「所有直接边里最短的那条」。
4. **对角线忘了 0**。
   错法：`mat_init` 把 `w[i][i]` 也填 ∞。i 借道自己这种松弛全废，负环检查也永远触发不了。
   对法：`(i == j) ? 0 : INF`。
5. **以为有负权就用 Floyd 万事大吉**。
   错法：负环图照用 dist 结果。对法：跑完先查对角线（本节 `return 1` + 警告）；
   有负环时「最短距离」根本没有定义，整张表作废。
6. **只存 dist 不存 next，事后打不出路径**。
   错法：问「怎么走」只能干瞪眼；或改了 dist 忘了同步 next，还原出半真半假的路。
   对法：松弛 dist 的同一条分支里写 `next[i][j] = next[i][k]`。
7. **二维数组传参写成 `int **m`**。
   错法：`void f(int **m)` 接 `int w[8][8]`——编译可能过，运行时按「指针数组」跳行，全盘错位。
   对法：写出第二维（`int m[][MAX_V]`），或像本节一样 `typedef int Table[MAX_V][MAX_V];`。

## 自检问题

1. 第 k 轮结束时 `dist[i][j]` 的准确含义是什么？i、j 算不算「中转」？
   **答：** 只准借道编号 ≤ k 的点的最短路；i、j 是端点，不计入中转权限。
2. 为什么 k= 最外层时，用到的 `dist[i][k]`、`dist[k][j]` 一定是上一轮的正确值？
   **答：** 最短路不重复经过点，i~>k 和 k~>j 两段的内部中转都 < k，第 k-1 轮已结束，值已定。
3. 错版为什么恰好把 `d[1][0]` 算成 13？
   **答：** 算 (1,0) 时 `d[1][3]` 还没被本轮 j 扫到，仍是旧值 9，9+4=13；之后 (1,3) 降到 3 也没人回头看 (1,0)。
4. `INF_DIST` 为什么取 1e9？光靠它够吗？
   **答：** 防 INT_MAX 加法溢出变负；但 1e9+1e9=2e9 逼近 int 上限，所以代码还加了 `>= INF` 判断双保险。
5. 怎么一眼判断图里有负环？为什么这招成立？
   **答：** 看对角线。`dist[i][i]` 初值 0，变负只能来自「绕一圈回 i」的负权圈。
6. 什么时候选 Floyd、什么时候选 V 次 Dijkstra？
   **答：** 点数小（几百内）/ 要全点对 / 有负权边 ⇒ Floyd；大图 + 只要少数几个源 ⇒ 堆版 Dijkstra。
7. 把 `min/+` 换成 `或/与` 得到什么？本节示例图的对角线初始化成 0 还是 1，为什么？
   **答：** 传递闭包（可达性）。本节初始化为 0：问的是「走一条路能不能到」，原地不动不算；写 1 是另一派（自反闭包），选哪种都行但要全程一致。
