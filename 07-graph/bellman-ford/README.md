# Bellman-Ford 单源最短路（07-graph/bellman-ford）—— 不定稿，所以负权也不怕

> 一句话定位：Dijkstra 的"反面教材式互补选手"。核心只有**一行比较**，
> 却能干成两件 Dijkstra 干不了的事：**处理负权边**、**查出负环**。
> 代价是 `O(V·E)`。这一节还会把 SPFA 讲清楚（实现留在隔壁目录的队列那节，思路在这里给全）。

---

## 一句话是什么

**Bellman-Ford**：固定起点 `src`，`dist[src] = 0`，其余 `∞`，然后

```
for (round = 1; round <= V - 1; round++)
    for (每条边 u -> v，权 w)                    ← 【所有边】，不是"某个点的邻居"
        if (dist[u] != ∞ && dist[u] + w < dist[v])
            dist[v] = dist[u] + w,  parent[v] = u;
```

**没有任何"定稿"概念**：一个点的 `dist` 可以被改很多次，改到最后一轮为止。
跑完 `V-1` 轮后再**多跑一轮**：还能松弛 ⇒ 图里有**负环**。这一轮是 BF 的独门兵器。

| 关键词 | 含义 |
|---|---|
| 松弛 relax | 发现一条更短路，就把 `dist[v]` 下调 |
| 一轮 pass | 把边表里**每一条弧**都试一遍 |
| 收敛 | 某一轮一处都没改 ⇒ 后面再怎么跑也不会改 ⇒ 可提前结束 |
| 负环 | 一圈走下来总权为负 ⇒ 每绕一圈距离更小 ⇒ 最短路**不存在** |

---

## 为什么需要它

Dijkstra 的命门是"**已定稿不再修改**"。这个前提一旦被负权边打破，它就会
**安静地给出错误答案**（隔壁 `dijkstra` 第 5 幕实测：正确答案 1，它给 2，格式整齐、毫无异常）。

现实里负权并不罕见：

- 机票返现、优惠券、惩罚项 —— 建模成"走这条边倒扣钱"就是负权。
- 汇率套利检测：把 `-log(rate)` 当边权，**存在负环 ⇔ 存在套利机会**。
- 差分约束系统（`x_j - x_i <= w` 一类不等式）求解，天生就要跑 BF。

而且很多场合需要的**不是最短路，而是"有没有负环"这个判断**（套利、调度可行性、
游戏里的"无限刷分"检测）。BF 是这些场景的标准工具，Dijkstra 完全做不了。

BF 还有一项隐藏价值：**它是对拍基准**。
本目录第 4 幕就在共用图上把 BF 和 Dijkstra 的 `dist` 逐格对照，
两边都对上才敢说自己写对了 —— 两个独立实现互为验证，是图算法调试的基本功。

## 内存布局图解

BF 只需要**一张边表**，这是它比 Dijkstra 更"朴素"的地方 —— 不需要邻接矩阵，也不需要堆：

```c
typedef struct { int from, to, weight; } Edge;
typedef struct {
    int n;                 /* 顶点数 0..n-1 */
    int directed;          /* 1 = 有向；0 = 无向（一条边存成两条弧） */
    int m;                 /* 弧数 */
    Edge e[MAX_E];         /* ← 全部家当就在这 */
} Graph;
```

共用图（6 点、9 条无向边 ⇒ 18 条弧）：

```
  e[]:  [ {0,1,7} {1,0,7} {0,2,9} {2,0,9} {0,5,14} {5,0,14} ... 共 18 条 ]
   下标      0        1        2        3         4         5

  注意：一轮 pass = 从 e[0] 扫到 e[17]，一条不落。
        这就是为什么"边表里的顺序"会影响【第几轮收敛】（不影响最终答案）。
```

两个工作数组（长度 `n`，这就是算法的全部状态）：

```
  图①（有负权无负环）逐轮快照，起点 0：

  下标 v ：     0      1      2      3
  开局      [   0,    ∞,    ∞,    ∞ ]
  轮 1 末   [   0,     4,     1,    ∞ ]     ← 本轮改了 2 处
  轮 2 末   [   0,    -2,     1,     6 ]     ← 2->1 那条负权边生效，dist[1] 从 4 掉到 -2
  轮 3 末   [   0,    -2,     1,     0 ]     ← 顺着 1->3 又掉下来：1-3+2 = 0
  轮 4（第 V 轮） 一处都改不动 ⇒ 没有负环，答案可信 ✓

  parent： [  -1,     2,     0,     1 ]
              ↑      ↑
        起点没有来路  dist[1] 是从 2 号点松弛来的 ⇒ 路径 0 -> 2 -> 1
```

**关键点：`dist[1]` 从 4 变成 -2，发生在第 2 轮。**
第 1 轮扫到 `0 -> 1` 时先把 4 写进去，之后扫到 `0 -> 2`（更靠后？不 —— 本目录的边表
**故意倒着写**，`0->2` 排在 `0->1` 前面），再到 `2 -> 1(-3)` 时 `dist[2]` 还是 ∞，
所以那次没能立刻生效 —— 这正是"轮数"的意义：**信息每轮最多沿边表方向传播一格。**

含负环时 `dist` 的样子（图②，环是 `1 -> 2 -> 1`，总权 `-4`）：

```
  轮 0   [  0,    ∞,    ∞ ]
  轮 1   [  0,   -3,   -2 ]   ← 每绕一圈少 4
  轮 2   [  0,  -11,   -6 ]
  轮 3   [  0,  -11,  -10 ]   (真实数值见运行结果)
  轮 4   还能松弛！dist[2] 从 -10 掉到 -14  ⇒ 报负环
  ⇒ 这些数字【全部作废】：它们只是"跑到第 V-1 轮结束时恰好停在哪算哪"
```

## 核心操作逐个拆解

### 操作 1：松弛（唯一的一行逻辑）

```c
if (dist[u] >= INF_DIST) continue;            /* ★ 必须先挡住 ∞ */
if (dist[u] + w < dist[v]) {
    dist[v]   = dist[u] + w;
    parent[v] = u;
}
```

**为什么 `dist[u] != ∞` 这个判断在 BF 里是生死线，在 Dijkstra 里只是省点力气？**
因为 BF 会扫**所有**边，包括那些从不可达点出发的边。一旦不挡：

```
  dist[u] = INF_DIST = 1e9,  w = -3
  dist[u] + w = 999999997 < INF_DIST ⇒ "松动了"
  ⇒ dist[v] = 999999997，一个明明到不了的点被赋上了"有限距离"
  ⇒ 更糟的是它 next 轮还能继续往外传染，整张图的不可达全被污染
```

Dijkstra 靠"挑最小"就自然避开了 ∞ 点（∞ 永远排最后，而且 `u == -1` 就 break 了），
**BF 没有这道天然屏障，必须自己写。** 这是本节坑第 1 条。

### 操作 2：为什么 V-1 轮一定够

> 最短路不会绕环：绕环要么让路更长（那就该删掉），要么等长（删掉不亏）；
> 真有负环时最短路压根不存在。所以**存在一条不带重复顶点的最短路**。
> `V` 个点、点不重复的路径最多 `V-1` 条边。
>
> 归纳：第 1 轮结束后，所有"1 条边就到"的点的 `dist` 已经正确
> （因为起点 `dist=0` 开局就位，扫一遍边就把 1 步能到的点全刷新了）。
> 假设第 `k-1` 轮后"≤ k-1 条边"的最短路都正确，那么真实值为 `d` 的 k 边最短路
> `src → … → u → v` 里，`dist[u]` 已正确，第 `k` 轮扫到边 `(u,v)` 时必然把 `dist[v]` 打到 `d`。∎

所以 `V-1` 是**最坏情况的上界**，不是"必须跑满"。

**边序会影响收敛速度**（运行结果里有活生生的对比）：

```
  图①：负权边 2->1 排在 0->2 后面吗？本目录故意把边表倒着写，
        结果"信息"传得慢一点，用了 3 轮（= V-1，最坏情况）才收敛。
  共用图③：边序刚好顺 ⇒ 第 1 轮就打出全部正确答案，第 2 轮 0 处改动，提前结束。
  ⇒ "V-1 轮"是保险上限；"某一轮 0 改动 ⇒ 已收敛"是提前收工的依据。
```

### 操作 3：提前结束（early exit）

```c
int changed = 0;
... 一轮里任何一次成功松弛都 changed++;
if (!changed) break;      /* 一处都没动 ⇒ 已经收敛 ⇒ 后面几轮一定也不动 */
```

**为什么"一轮没动"就能断定"以后都不会动"？** 因为下一轮做的比较和这一轮**一模一样**
（边表没变、`dist` 没变），结果必然也一样。这是不动点论证，很干净。

顺带还得到一个结论：**能提前结束 ⇒ 一定没有负环**（有负环时每轮必然还在变小）。

### 操作 4：第 V 轮判负环 + 证据边

```c
/* V-1 轮跑完后，再单独扫一遍所有边 */
for (每条边 u -> v)
    if (dist[u] != ∞ && dist[u] + w < dist[v]) {
        /* ★ 还能松弛 ⇒ 负环 */
        bad_from = u; bad_to = v;      /* 记下"证据边"，报错时得指出是哪条边 */
        return 1;
    }
return 0;
```

为什么"第 V 轮还能松弛"⇔ 有负环？
"还能松弛"说明存在一条**用了 `V` 条边却比任何 `V-1` 边路径更短**的路。
`V` 条边连接 `V+1` 个点 ⇒ 由鸽巢原理必有重复顶点 ⇒ 路径里含环；
去掉这个环会变得更短或相等，与"带环更短"矛盾 ⇒ **这个环总权为负**。∎

程序要打印证据边（`bad_from -> bad_to`）而不是只 return 一个布尔，
否则用户拿到"有负环"三个字却不知道该去看哪。

### 操作 5：找出负环上的所有点（扩展，本 demo 未实现）

只知道"有负环"通常不够。标准做法：

```
  1) 第 V 轮里找出那条还能松弛的边 (u -> v)
  2) 令 x = v，沿 parent 走 V 步：x = parent[x] 重复 V 次
     ⇒ x 一定落在负环上（因为 v 被环"污染"了，走够步数就掉进环里）
  3) 从 x 出发再沿 parent 走一圈回到 x，就把环上的点收集齐了
```

如果只想报告"哪些点的最短路没有意义"，再做一次 BFS/DFS：把所有能从那 条证据边到达的点
都标为"负环影响域"，它们的 `dist` 一律视为 `-∞`。

### 操作 6：路径回溯

`parent[v] = u` 的语义和 Dijkstra 完全一样。
**但只有在"没有负环"时 `parent` 才真的构成一棵树**：有负环时 `parent` 里会出现环，
`while (v != src) v = parent[v]` 会**死循环**。所以回溯代码必须带步数上限（`<= V` 步）
或者干脆在返回值为 1 时直接拒绝回溯。

### 操作 7：SPFA（队列优化的 Bellman-Ford）

BF 的浪费在哪：每一轮把 18 条弧全试一遍，但其中大多数弧的 `dist[u]` 这一轮**根本没变过**，
拿没变过的 `u` 去松弛 `v`，结果必然还是"不动" —— 白比较。

SPFA 的思路（和 BFS 一个味道）：

```
  队列里只放「dist 刚刚被改过、因此有可能让邻居变短」的点
  while 队列非空:
      u = 队首出队, in_queue[u] = 0
      for u 的每条出边 (u -> v, w):
          if dist[u] + w < dist[v]:
              dist[v] = dist[u] + w, parent[v] = u
              if !in_queue[v]: v 入队, in_queue[u→v] = 1     ← 只有"不在队里"才入队，防重复
```

参考实现（伪代码，照抄成 C 只需一个 `int q[MAX_V*某个倍率]` 的环形队列 + 一个 `in_queue[]`）：

```c
void spfa(Graph *g, int src, int dist[], int parent[])
{
    int q[1024], head = 0, tail = 0;           /* 环形队列；本 demo 图很小，够用 */
    int inq[MAX_V] = {0};
    for (int v = 0; v < g->n; v++) { dist[v] = INF_DIST; parent[v] = -1; }
    dist[src] = 0;
    q[tail++] = src; inq[src] = 1;
    while (head != tail) {
        int u = q[head++]; inq[u] = 0;         /* ← 出队时清标记：它以后再被改小还能再进来 */
        for (每条 u 的出边 (u,v,w)) {
            if (dist[u] + w < dist[v]) {
                dist[v] = dist[u] + w; parent[v] = u;
                if (!inq[v]) { q[tail++] = v; inq[v] = 1; }
            }
        }
    }
}
```

| | Bellman-Ford | SPFA |
|---|---|---|
| 每轮做什么 | 扫全部边 | 只处理"刚变小的点"的出边 |
| 平均时间 | `O(V·E)` | `O(k·E)`，`k` 通常 2~4 |
| 最坏时间 | `O(V·E)`（可预期） | **`O(V·E)`，且很容易被构造出来** |
| 判负环 | 第 V 轮扫一遍，天然给出 | 要靠"某点入队次数 ≥ V"或单独计数 |
| 实现 | 5 行，不会写错 | 要维护队列 + `in_queue[]`，多处易错 |

**为什么竞赛里 SPFA 常被"卡"**：它的上界和最坏情形是 `O(V·E)`，
而构造一张让某个点反复进队的图非常轻松（网格图、随机负权边、专门的"卡 SPFA"数据）。
所以业内共识是：**"SPFA 是平均快、最坏烂"的典型**。
数据不可控或需要可预期耗时时，用老实 BF；负环判定这类需要严谨性的场合，也优先 BF。
（小优化如 SLF/LLL 能救一点，但改变不了最坏复杂度。）

## 复杂度表

| 项 | 值 | 说明 |
|---|---|---|
| 时间 | `O(V · E)` | `(V-1) 轮 × 每轮扫 E 条边`；提前结束会快很多，最坏不变 |
| 判负环 | 额外 `O(E)` | 就是多扫一轮 |
| 空间 | `O(V + E)` | 边表 + `dist[]` + `parent[]`；**不需要堆、不需要矩阵** |
| SPFA | 平均 `O(k·E)`，最坏 `O(V·E)` | 见操作 7 |

| 算法 | 时间 | 负权 | 负环检测 | 依赖的前提 |
|---|---|---|---|---|
| BFS | `O(V+E)` | 无权图 | ✗ | 边权全为 1 |
| Dijkstra | `O(V²)` / `O((V+E)logV)` | **✗ 会算错** | ✗ | 边权非负 |
| **Bellman-Ford（本节）** | `O(V·E)` | **✓** | **✓** | 无 |
| Floyd-Warshall | `O(V³)` | ✓ | ✓（对角线 < 0） | 无（但 `V` 要小） |
| DAG 最短路 | `O(V+E)` | ✓ | ✗（前提是无环） | 图必须是 DAG |

**`V = 10^5` 时 BF 直接出局**（`V·E` 上溢天际）：这种规模要么保证非负权用 Dijkstra，
要么问题本身有额外结构（DAG、分层、小整数权 → 用桶/0-1 BFS）。
BF 的主场是 `V` 几百到几千、且**必须**处理负权的场合。

幕 5 · SPFA（队列优化的 Bellman-Ford）是什么
==================================================
  BF 的浪费：某一轮里，只有少数几条边的 dist[u] 刚刚变过，
            但我们把 18 条弧全试了一遍 —— 大量比较是白做的。
  SPFA 的改造：只把「dist 刚被改过、因此有可能让邻居变短」的点丢进队列，
            每次取一个点 u，只松弛 u 的出边，邻居被改小了就把邻居入队。
            这本质就是 BFS 版的 Bellman-Ford，平均很快，代码见 README「扩展」一节。
  为什么竞赛里它常被卡：最坏复杂度是 O(V*E)，而构造一张「一个点反复进队」的图
            非常轻松（网格图、随机负权边都是常见卡法）。所以判负环 / 数据不可控时，
            宁可用老老实实的 BF，或者用 SLF 等小优化，但别指望它一定能过。

本节小结
==================================================
  1) BF = 「不定稿，把所有边重复松弛 V-1 轮」。它敢处理负权，就是因为它从不过早宣布定稿。
  2) 第 V 轮还能松弛 ⇒ 负环 ⇒ 最短路没有意义。判负环是 BF 的独门能力。
  3) 松弛前必须判 dist[u] != ∞，否则「∞ + 负数」会凭空造出一条到不可达点的路。
  4) 复杂度 O(V*E)：比 Dijkstra 慢。没有负权时该用 Dijkstra，别因为 BF 好写就用它。

## 常见的坑

### 坑 1：忘了 `dist[u] != ∞` 守卫 —— "∞ + 负数"凭空造路

```c
if (dist[u] + w < dist[v])        /* ✗ */
if (dist[u] < INF && dist[u] + w < dist[v])   /* ✓ */
```

有负权边时这个洞必被踩：`1e9 + (-3) < 1e9` 成立，于是**一个从起点根本走不到的点**
被赋上"有限距离" `999999997`，还继续向邻居传染。症状是"一堆 ∞ 突然变成了大数"。
（`INF` 取 `INT_MAX` 时更惨：加法直接溢出成负数，全图完蛋。）
Dijkstra 靠"挑最小 + `u == -1` 就 break"天然躲开了这一发，**BF 必须自己挡**。

### 坑 2：只跑 V-1 轮就宣布"没有负环"

负环检测靠的是**第 V 轮还能不能松弛**。少跑这一轮，你就把一个"最短路不存在"的图
当成"最短路算完了"上报，而 `dist` 里装的是一串毫无意义的中间值
（运行结果第 3 幕里那几个 -11、-10）。**判负环不是可选功能，它和求最短路一样重要。**

### 坑 3：检测到负环之后还用 `dist[]` / 回溯 `parent[]`

返回值 1 时 `dist` 全部作废（本目录明确打印了这句话）。
更危险的是 `parent[]`：有负环时它**成环**了，
`while (v != src) v = parent[v];` 就是**死循环**。回溯必须带步数上限（`<= V`）或者干脆拒绝执行。

### 坑 4：把无向图当成"两条方向相反的弧"来跑 BF

**无向图里一条负权边 = 一个负环**（`u -v-> w` 加回来 `v -u-> w`，一圈 `2w < 0`）。
所以 BF 在有负权的无向图上其实等价于"检测这条负边是否可达" ——
很多资料干脆说"BF 用于负权时默认是有向图"。
本目录的共用图③是无向但**全正权**，正权无向边来回走只会让路变长，无害。
真要处理"无向 + 负权"，先想清楚题意是不是允许来回走。

### 坑 5：以为"边表顺序无关"

最终 `dist` 确实与边序无关，但**轮数**高度相关：顺边序可能 1 轮收敛，逆边序要跑满 `V-1` 轮。
副作用有两个：

1. 性能：你以为 `O(V·E)` 的上界很松，实际最坏就是它。
2. `parent`：并列最短路的"选哪一条"由更新顺序决定 ⇒ 输出边序一变，路径打印就变，
   README 就不能复现了。**本目录把边序固定写死，正是为了输出可逐字核对。**

### 坑 6：拿 BF 去和 Dijkstra 比速度然后到处用 BF

"BF 更通用所以更好"是错觉。非负权时两者结果**必须一致**（第 4 幕逐格验证过：
`[0, 7, 9, 20, 20, 11]`），但 BF 是 `O(V·E)`，Dijkstra 堆版是 `O(E log V)`。
`V = 10^4` 时 BF 就是 10^8 次比较。**没有负权就用 Dijkstra，别因为 BF 好写就用它。**

## 什么时候用它 / 什么时候别用

**该用 Bellman-Ford 的场景**

- **有负权边**的单源最短路（这是它的本职）。
- 需要判断**是否存在负环**：套利检测、差分约束可行性、调度冲突检查。
- **边表在手**、`V` 不大（几百到几千）：BF 代码 5 行，不需要堆、不需要邻接表，最省事。
- 需要**可预期的耗时上界**（比如在线服务）：最坏 `O(V·E)` 是硬上界，SPFA 给不了。
- 当作**对拍基准**验证自己写的 Dijkstra / SPFA / Floyd。

**别用的场景**

- **边权全非负** → Dijkstra（快一到两个量级）。
- **大图**（`V ≥ 10^4` 且边不多）→ `V·E` 太大；先想清楚能不能保证非负。
- **DAG** → 拓扑排序 + 一遍松弛，`O(V+E)`，还允许负权，比 BF 快得多。
- **任意两点对** → `V` 小的话 Floyd 5 行；`V` 大的话老老实实跑多次 Dijkstra。
- **无权图** → BFS，`O(V+E)`。

|---|---|---|---|---|

## 自检问题

**Q1：为什么 V-1 轮一定收敛，第 V 轮却一定能查出负环？**
收敛性：最短路可以取成"不重复经过顶点"的路（绕环只会更长或相等），这种路最多 `V-1` 条边；
第 `k` 轮结束时"不超过 k 条边"的最短距离全部正确（对 `k` 归纳：第 k 轮扫到那条最后一条边时
它前缀已经正确了）。所以 `V-1` 轮够。
反之，如果第 `V` 轮还能松弛，说明存在一条 `V` 条边却更短的路 —— `V+1` 个点、`V` 条边里
必有重复顶点 ⇒ 含环 ⇒ 而"带环比不带环短"只能是**负环**。

**Q2：BF 松弛前为什么必须判 `dist[u] != ∞`？Dijkstra 为什么可以不判？**
BF 每轮扫**所有**边，一定会扫到"从不可达点出发"的边。不挡的话 `∞ + (-3) < ∞` 成立，
不可达点被凭空赋上有限距离，还会继续向邻居传染。
Dijkstra 挑的是"未定稿里 `dist` 最小且 `< ∞`"的点，`u == -1` 就 break，
不可达点的出边压根不会被扫到 —— 前提是它没有负权（有负权时这个结论也一起崩了）。

**Q3：第 V 轮还能松弛，能说明"所有点"的距离都不可信吗？**
不能，这句话说重了。严格结论是：**那条证据边所影响的点**（从它出发能到达的所有点）
的最短路是 `-∞`，没有意义；其余点可能仍然正确。
实际工程里通常两种做法：① 直接把整张图判负、全部作废（本 demo 采用，简单诚实）；
② 精确一点，把证据边终点沿 `parent` 走 `V` 步定位到环上，再 BFS 标出"负环影响域"，
只让这些点的 `dist` 记为 `-∞`。

**Q4：SPFA 和 BF 谁更快？为什么竞赛里常说"SPFA 是错题答案"？**
BF 是"每轮无差别扫全边"，SPFA 是"只处理刚变小的点"。随机数据下 SPFA 平均快好几倍。
但 SPFA 的**最坏复杂度仍是 `O(V·E)`**，而且**构造最坏数据的门槛极低**
（让一个点反复进出队列即可，网格图、随机负权都是常见卡法）。
所以在数据不可控的评测里，"用 SPFA"约等于"赌出题人没卡我"。
需要负环检测时 BF 也更规矩：跑满 `V-1` 轮 + 第 `V` 轮扫一遍，逻辑封闭。

**Q5：同一张没有负环的图，BF 和 Dijkstra 的答案会不同吗？**
距离不会。第 4 幕把两个数组逐格打印在一起对比，全部 ✓（共用图 `dist = [0,7,9,20,20,11]`）。
**路径**可能不同：并列最短路上"选哪一条"取决于更新顺序，BF 按边表顺序、
Dijkstra 按定稿顺序。所以本节的自检只强制要求 `dist` 一致，`parent` 允许有差异 ——
这也是"用两个独立实现互相对账"时应该采用的判据：**比数值，不比结构。**
