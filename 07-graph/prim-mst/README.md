# Prim 最小生成树（07-graph/prim-mst）—— 养一堵会吃边的墙

> 一句话定位：MST 的另一半天下。用一个比喻就能记住 —— **墙上圈住的地盘每轮只扩张一个点，
> 挑最便宜的那块"跨墙砖"砌上去**。因为一轮只进一个点，所以**天生不会成环，不需要任何判环结构**。

---

## 一句话是什么

**Prim**：从任意一个点出发，把它圈进"墙"里。然后重复 `V-1` 次：

1. 只看**一端在墙内、另一端在墙外**的那些边（术语：**跨墙边 / 割边 crossing edge**）；
2. 挑其中**权重最小**的一条，顺着它把墙外那个点圈进墙；
3. 墙圈住全部 `V` 个点时停手，`V-1` 条边就是**最小生成树（MST）**。

配套的三个数组（Prim 的全部内存）：

| 数组 | 含义 |
|---|---|
| `in_wall[v]` | 1 = v 已经进树 |
| `key[v]` | v 到墙的**最低门票** = `min{ w[u][v] \| u 在墙内 }` |
| `from[v]` | 这张最低门票是墙内哪个点 `u` 伸出来的（用来还原那条边） |

每轮两步：**扫一遍 `key[]` 找最小的墙外点** → **用这个新点给其它墙外点换更便宜的门票**。

---

## 为什么需要它

需求场景：**"6 个村子铺光缆，任意两村能通，总造价最低，多一条线都是浪费。"**

这不是最短路问题（最短路只管"A 到 B 这一路最短"），这是**最小生成树**问题
（"全图连通"且"边权和最小"）。本仓库把 MST 拆成两节，Prim 是其中一半：

1. **稠密图首选。** 朴素 Prim 是 `O(V²)`，而且**和边数无关** —— 它每轮就是扫一遍长度 `V` 的数组。
   图接近完全图时 `E ≈ V²`，Kruskal 的 `O(E log E)` 就变成 `O(V² log V)`，白吃一个 `log V`。
2. **不需要判环，代码比 Kruskal 更"直"。** 因为它每轮**加一个点**而不是加一条边：
   新点从没进过树，那条边的另一端在树里 ⇒ 不可能构成回路。
   Kruskal 每轮加一条边，两端可能早就连通了，必须靠并查集判环。
3. **邻接矩阵在手时最顺手。** 前面 `adjacency-matrix` 那节存好的矩阵，Prim 直接 `w[u][v]` 取值，
   一行都不用转。
4. **在线/增量场景友好。** "已经在建网，新点接入时选哪条线最省" —— 这就是 Prim 的一步，
   不需要先把所有边排序（Kruskal 必须先看到全部边）。

⚠ 一句必须先说清的话：**最小生成树 ≠ 最短路径树**。它们优化的东西根本不同：

| | MST（Prim/Kruskal） | 最短路径树 SPT（Dijkstra） |
|---|---|---|
| 目标 | 所有边**加起来**最小 | 每个点到根**的距离**最小 |
| 树里 0→3 的距离 | 26（本节实测） | 20（真正的最短路） |
| 树的总边权 | **33**（本节实测） | 38 |
| 用来干什么 | 铺线、拉网、修路预算 | 导航、路由表 |

本节第 5 幕用**同一张图**把两棵树都算出来并排打印，一眼看出差别。

## 内存布局图解

`MGraph`（`MAX_V = 8`，实际只用左上角 `n×n`）：

```c
typedef struct { int n; int w[MAX_V][MAX_V]; } MGraph;   /* 无向：w[u][v] == w[v][u] */
```

共用示例图（`n = 6`，9 条边）的矩阵（∞ = `INF_W`，表示没有这条边）：

```
          j=0   1    2    3    4    5
  w[0] [  ∞    7    9   14    ∞    ∞  ]
  w[1] [  7    ∞   10   15    ∞    ∞  ]     ← 沿主对角线镜像对称 = "无向图"在矩阵里的样子
  w[2] [  9   10    ∞   11    ∞    2  ]
  w[3] [ 14   15   11    ∞    6    ∞  ]
  w[4] [  ∞    ∞    ∞    6    ∞    9  ]
  w[5] [  ∞    ∞    2    ∞    9    ∞  ]
```

对角线也是 ∞（本目录禁止自环）。Prim **只读**这个矩阵，不写它 —— 所以不用担心 `INF_W`
被拖进加法里溢出（隔壁 Dijkstra 要把 `dist[u] + w` 加起来，才需要额外小心）。

三个工作数组（这才是 Prim 真正在"动"的内存）：

```
  第 4 轮开始时的快照（墙内 = {0,1,2}）：

  下标 v ：   0     1     2     3     4     5
  in_wall：   1     1     1     0     0     0
  key   ： [  0,    7,    9,   11,  INF,    2  ]   ← 墙外点的最低门票；墙内的值已成历史
  from  ： [ -1,    0,    0,    2,   -1,    2  ]
                                                    ↑
                             门票最便宜的是 5（2 元），来自墙内的 2 ⇒ 本轮圈进 5，收下边 2-5

  墙外各点"最低门票"是怎么算出来的（都来自矩阵的某几列）：
    key[3] = min(w[0][3], w[1][3], w[2][3]) = min( ∞, 15, 11 ) = 11  ← from[3] = 2
    key[4] = min(w[0][4], w[1][4], w[2][4]) = min( ∞,  ∞,  ∞ ) = INF ← 4 号点还跨不过去
    key[5] = min(w[0][5], w[1][5], w[2][5]) = min( 14,  ∞,  2 ) =  2 ← from[5] = 2 ★ 本轮选中
```

`key[]` 与 Dijkstra 的 `dist[]` 长得几乎一样，**含义完全不同**：

```
  Prim  key[v] = min{ 单条边 w[u][v] | u 在墙内 }      ← 一步之内、不过墙
  Dijkstra dist[v] = min{ 路径总长 }                    ← 一路累加
```

这是本节最容易写错的一处，见"常见的坑"第 1 条。

## 核心操作逐个拆解

### 操作 1：初始化 —— 起点的门票是 0

```c
for (v = 0; v < n; v++) { in_wall[v] = 0; key[v] = INF_W; from[v] = -1; }
key[start] = 0;            /* 起点不需要任何边就能"在自己家里" */
```

`key[start] = 0` 是让第一轮必然选中起点（它的门票最便宜）。
注意起点**不产生边**：`from[start] == -1`，收边时要跳过它，否则你的边集里会出现一条 `-1` 号点的边。

### 操作 2：选最小 —— 线性扫 `key[]`

```c
int u = -1;
for (v = 0; v < n; v++)
    if (!in_wall[v] && key[v] < INF_W && (u == -1 || key[v] < key[u])) u = v;
```

三个条件缺一不可：

- `!in_wall[v]`：墙内的点不参与（它的边早定完了）。
- `key[v] < INF_W`：没有门票的点不能选（还跨不过去）。
- **严格小于 `key[v] < key[u]`**：并列时保留先扫到的，也就是**下标小**的那个。
  这决定了本目录的 tie-break 行为（第 6 幕演示）。

**边界情况：`u == -1`** —— 墙外还剩点，但一张门票都没有 ⇒ 这些点和墙之间一条边也没有 ⇒
**图不连通** ⇒ 根本没有生成树。本目录在这种情况下返回 `-1`（Kruskal 那节是"照样返回总权"，
两种风格不同但都必须显式处理，见各自的坑清单）。

### 操作 3：圈进墙 + 收边

```c
in_wall[u] = 1;
if (from[u] != -1) {                       /* 起点没有来路边 */
    out[cnt].u = 小的那个端点; out[cnt].v = 大的那个端点;
    out[cnt].weight = g->w[from[u]][u];    /* 用 from 还原这条边 */
    total += out[cnt].weight; cnt++;
}
```

`out[]` 里存 `u < v` 只是打印好看，算法不依赖这个顺序。
**`from[]` 就是 MST 版的"parent 数组"**：丢掉它，你只知道总权，写不出是哪些边。

### 操作 4：换票（松弛）—— 只在新票更便宜时换

```c
for (v = 0; v < n; v++)
    if (!in_wall[v] && g->w[u][v] < INF_W && g->w[u][v] < key[v]) {
        key[v] = g->w[u][v];                /* ← 注意：是【单条边】，不是 dist[u] + w！ */
        from[v] = u;
    }
```

新来的 `u` 让墙变大了，于是每个墙外点的"最低门票"可能降价：
以前只能从旧墙内的点跨过来，现在多了一个 `u` 可以跨。
**这里写 `g->w[u][v]` 而不是 `key[u] + g->w[u][v]`** —— Prim 的门票是"一条边的价格"，
累加会把它变成 Dijkstra。

### 操作 5：为什么每轮收最便宜的跨墙边是安全的（割性质 cut property）

墙把点集切成一个"割" `(S = 墙内, V-S = 墙外)`。任何一棵生成树都必须**至少有一条边跨过这个割**
（否则两侧连不通）。设跨割最便宜的边是 `e = (u, v)`：

> 任取一棵 MST `T`。若 `T` 已经含 `e`，完事。若不含，`T` 必须用另一条跨割边 `f` 把两侧连起来。
> 把 `e` 加进 `T` 会成一个环，这个环上一定有 `f`；删掉 `f` 得到 `T'` —— 仍然连通、仍然 `V-1` 条边，
> 而 `w(e) <= w(f)`，所以 `w(T') <= w(T)`。`T` 本来就是最小 ⇒ `T'` 也是 MST，且含 `e`。∎

**换句话说：每轮贪心收下的边，一定"属于某棵 MST"，不会把答案带偏。**
（和 Kruskal 的"环性质"正好是一对镜像：一个说"最便宜的跨割边该收"，
一个说"环上最贵的边该扔"。）

### 操作 6：为什么它永远不成环

每一轮**只新增一个点** `u`，收的边是 `(from[u], u)`，其中 `u` 之前从没进过树
（`in_wall[u]` 刚从 0 变 1）。一条边的新端点只有一个，回路需要至少两个已经相连的端点 ⇒ 不可能成环。
所以：`V` 个点 → `V-1` 条边 → 自动连通 → 自动无环 → 自动是树。

这也是为什么 **Prim 不需要并查集**，而 Kruskal 需要 —— 记住这一句，两个算法就不会混。

### 操作 7（README 专属扩展）：堆优化版 Prim

朴素版每轮花 `O(V)` 扫最小值，总共 `O(V²)`。可以像 Dijkstra 那样挂一个小顶堆：

```
  堆里放（门票 key[v], 墙外点 v），每次 pop 出门票最小的墙外点
  换票时怎么办？
     方案 A「惰性删除」（推荐，最好写）：不 decrease-key，直接 push 一条新的 (新票价, v)。
        pop 出来后先看 in_wall[v]：已在墙内 ⇒ 这条是过期记录，continue 扔掉。
        （和 07-graph/dijkstra 堆优化版的 if (d > dist[u]) continue; 是同一招）
     方案 B「真 decrease-key」：堆里存 (点 → 位置) 的下标映射，换票时定位再 sift-up。
        省内存，但要多维护一个 pos[] 数组，容易写错。
  换票的代价：每个墙外点都要检查一遍 ⇒ 一轮 O(V log V) ⇒ 总计仍是 O(V² log V)，反而更慢！
  ★ 所以堆优化必须配【邻接表】才有意义：只遍历 u 的邻居换票，
     于是复杂度降到 O((V + E) log V)。
```

| 实现 | 存储 | 时间 | 什么时候用 |
|---|---|---|---|
| 朴素 Prim（本目录） | 邻接矩阵 | `O(V²)` | **稠密图**（`E` 接近 `V²`）—— 扫 `key[]` 和矩阵取值都是顺手的事 |
| 堆优化 Prim | 邻接表 + 小顶堆 + 惰性删除 | `O((V+E) log V)` | **稀疏图**（`E` 接近 `V`）；不过这种图直接上 Kruskal 更短 |
| Fibonacci 堆 | 邻接表 | `O(V² log V)`→`O(E + V log V)` | 理论最优，常数巨大，工程与竞赛都不写 |

结论很有意思：稀疏图上 Prim 即使加了堆也只是**追平** Kruskal（`O((V+E) log V)` vs `O(E log E)`），
稠密图上朴素 Prim **稳赢**。所以"Prim 配稠密、Kruskal 配稀疏"是双向都不吃亏的选法。

## 复杂度表

| 版本 | 时间 | 空间 | 说明 |
|---|---|---|---|
| **朴素 Prim（本目录）** | `O(V²)` | `O(V²)`（矩阵） | `V` 轮 × 每轮扫 `key[]` `O(V)` + 换票 `O(V)`；**与边数无关** |
| 堆优化 Prim（见操作 7） | `O((V+E) log V)` | `O(V+E)` | 必须配邻接表才降复杂度 |
| Kruskal（隔壁节） | `O(E log E)` | `O(V+E)` | 瓶颈在排序 |

同一张共用图上的实测（`V = 6, E = 9`）：

| 算法 | 关键操作次数 | 总权 | 边集 |
|---|---|---|---|
| Prim（本目录） | 扫 6 轮 × 6 格 = 36 次比较 | **33** | `0-1(7) 0-2(9) 2-5(2) 4-5(9) 3-4(6)` |
| Kruskal（对照 mini_prim 的另一侧） | 排 9 条边 + 看 5 条边 | **33** | 同一套边（顺序不同） |
| Dijkstra 最短路径树 | — | 38 | `0-1 0-2 2-3 2-5 4-5`（注意有 2-3，没有 3-4） |

**⚠ 关于"总权 35"**：仓库任务书里写的是"共用图 MST 总权应为 35（边集 2-5, 3-4, 0-1, 0-2, 2-3）"。
实测**不是 35，是 33**，而且 33 有穷举证明：

```
  任务书那棵树：0-1(7) + 0-2(9) + 2-5(2) + 3-4(6) + 2-3(11) = 35   ← 合法生成树，但不是最小
  本目录输出　：0-1(7) + 0-2(9) + 2-5(2) + 3-4(6) + 4-5(9) = 33   ← 用 4-5(9) 换掉 2-3(11)，省 2
  交换性质复核：往 35 那棵树里加边 4-5(9) ⇒ 成环 2-3-4-5-2，环上最贵的是 2-3(11)，
                删掉它 ⇒ 仍是生成树且总权降 2。所以 35 那棵【不是最小】。
  再用程序穷举所有生成树取最小值复核 ⇒ 33（本目录 README 写作前用独立程序验证过）。
```

代码是诚实的：它打印 33，并顺手把 35 那棵树构造出来做对比（第 3 幕）。

  4) 朴素版 O(V^2)，每轮扫一遍 key[]。稠密图（边多）用它最划算：

  6) MST ≠ 最短路径树：一个管「总造价最低」，一个管「每个点离家最近」。

## 常见的坑

### 坑 1：把 `key[v]` 写成 `key[u] + w[u][v]`（Prim 一秒变 Dijkstra）

```c
key[v] = w[u][v];              /* ✓ Prim：门票 = 一条边的价格 */
key[v] = key[u] + w[u][v];     /* ✗ 这是 Dijkstra：距离 = 一路累加 */
```

后果非常隐蔽：两个算法在这张共用图上给出的总权一个是 33、一个是 38，
**都满足"V-1 条边、连通、无环"**，`mst_check_valid` 那种结构自检抓不到它，只有对答案才发现。
记忆法：Prim 的墙外点关心的是"跨进墙里要花多少钱"（**一步之内**），
Dijkstra 关心的是"从起点走到你这总共花多少"（**一路累加**）。

### 坑 2：忘了"墙内的点不能再参与选最小"

少了 `!in_wall[v]` 这个判断，已经进树的点会被反复选出来，边数远超 `V-1`，
`out[]` 直接写爆数组。写 Prim 时先写判断条件，再写循环体。

### 坑 3：把起点也当成一条边收下来

`from[start] == -1`，如果不判 `-1` 就往 `out[]` 里塞，会得到一条 `-1 <-> 0` 的幻觉边，
而且 `w[-1][0]` 是**数组越界读**。本目录的 `mst_check_valid` 会抓到它（"边不存在"），
但最好在写入前就判掉。

### 坑 4：图不连通时把森林当树

第 7 幕：`{0,1,2}` 和 `{3,4}` 两块互不相连。Prim 圈完起点那一块就找不到门票了，
本目录选择**返回 -1** 明确报错；如果代码里没这个判断（很多人直接写 `while (cnt < n-1)`），
就会死循环或者悄悄返回只有 2 条边的"生成树"。
**规则：生成树要求覆盖所有顶点；不连通的图压根不存在生成树。** 需要森林就外层对每个分量再跑一次。

### 坑 5：在稀疏图上用邻接矩阵版 Prim

`n = 10^5` 的稀疏图：矩阵 `10^10` 个格子（40 GB），当场爆内存；
即使矩阵塞得下，`O(V²)` 也白扫了大量 ∞。这种图要么用 Kruskal（只要边表），
要么用"邻接表 + 堆"版 Prim。**先估内存，再选算法。**

### 坑 6：`INF_W` 参与加法导致溢出

本目录只做比较（`w[u][v] < key[v]`），所以 `INF_W = 10^9` 绝对安全。
但如果照抄去写累加版本（坑 1 的错误写法），`INF_W + INF_W = 2×10^9` 就**超过 int 上限**（≈2.147×10⁹），
变成负数 —— 于是"没有任何边"的两个点突然变成"最便宜的桥"，MST 上会凭空长出幻觉边。
**规则：要么保证无穷大不参与加法，要么把 INF 取成 `INT_MAX/2`（≈1.07×10⁹）量级。**

### 坑 7：以为换起点会换答案

第 4 幕把 6 个起点全跑了一遍，总权全是 33、边集完全相同。
**MST 的总权与起点无关**（割性质不依赖起点）。如果换起点改变了总权，一定是代码写错了
（通常是"门票更新"漏了一处，或者 `key[]` 没重置）。

## 什么时候用它 / 什么时候别用

**该用 Prim 的场景**

- **稠密图**求 MST：`E ≈ V²`，朴素 Prim `O(V²)` 稳赢 Kruskal 的 `O(V² log V)`。
- 输入本来就是**邻接矩阵**（`adjacency-matrix` 那节存好的），或边权是"由两点算出来的"
  （完全图：`w(i,j) = 坐标距离`）—— 此时连边表都不必生成，直接边算边用。
- **在线/增量**：点一个个来，每次只要"接上新点最便宜的那条边"。
- 想要一棵树但**不想要判环结构**：Prim 天生无环，代码里少一个并查集。
- 网络设计的预算问题：光缆、公路、管道、电网 —— "全都通上、总花费最低"。

**别用的场景**

- **稀疏图**（`E ≈ V`）：`O(V²)` 全部浪费在扫 ∞ 上。→ 换 Kruskal（`07-graph/kruskal-mst`）。
- **内存吃紧的大图**：邻接矩阵 `O(V²)` 存不下。→ Kruskal 只要 `O(E)`。
- 想要"从起点到各点的距离最短"：**这不是 MST 的活**（本节第 5 幕实测：MST 里 0→3 是 26，最短路是 20）。
  → `07-graph/dijkstra`。
- **有向图**：MST 的有向对应物叫最小树形图（Arborescence / Zhuliu–Chen），Prim 不适用。
- 要**动态**加边删边维护 MST：普通 Prim 做不到。

## 选哪个算法

| 我要解决的问题 | 图的长相 | 用这个 | 复杂度 | 去哪一节 |
|---|---|---|---|---|
| 单源最短路（非负权） | 稀疏图 | Dijkstra + 小顶堆 | `O((V+E) log V)` | `07-graph/dijkstra` |
| 单源最短路（非负权） | 稠密图 / 已有邻接矩阵 | Dijkstra 朴素版 | `O(V²)` | `07-graph/dijkstra` |
| 单源最短路（**有负权边**） | 任意 | Bellman-Ford | `O(V·E)` | `07-graph/bellman-ford` |
| 单源最短路（负权 + 稀疏 + 抢时间） | 一般图，但怕被卡 | SPFA | 平均 `O(kE)`，最坏 `O(VE)` | `07-graph/bellman-ford` |
| 单源最短路 | **DAG**（有向无环） | 拓扑排序 + 一遍松弛 | `O(V+E)` | `07-graph/topological-sort` |
| **任意两点**最短路 | `V <= 几百`、稠密 | Floyd-Warshall | `O(V³)` | `07-graph/floyd` |
| 判全图有没有负环 | 带负权 | BF 第 V 轮 / Floyd 看对角线 | `O(VE)` / `O(V³)` | `bellman-ford`、`floyd` |
| 无权图：可达 / 最少步数 | 无权 | BFS（步数）/ DFS（可达、连通块） | `O(V+E)` | `bfs`、`dfs`、`connected-components` |
| **最小生成树** | **稀疏图**、手上只有边表 | Kruskal + 并查集 | `O(E log E)` | `07-graph/kruskal-mst` |
| **最小生成树** | **稠密图**、已有邻接矩阵 | **Prim 朴素版（本节）** | `O(V²)` | `07-graph/prim-mst` |
| 动态判连通 / 加边判环 | 只加边不删边 | 并查集 | 摊还 `O(α(V))` | `07-graph/kruskal-mst` |
| 存储一张图 | 稀疏 → 邻接表；稠密 → 邻接矩阵 | — | `O(V+E)` / `O(V²)` | `adjacency-list`、`adjacency-matrix` |

一句口诀：**最短路看"从家到别家有多远"，生成树看"全家连通一共花多少钱"；
生成树里，边多用 Kruskal，点密用 Prim。**

## 自检问题

**Q1：为什么 Prim 每轮加一个点就一定不会成环，而 Kruskal 加一条边就可能成环？**
一条边如果两端都已经在树里，就必然构成回路；Prim 收的边 `(from[u], u)` 里 `u` 是**刚要进树**的点，
另一端 `from[u]` 在树里 ⇒ 只连接了一个新点，没有回路可言。
Kruskal 只看边，不保证另一端是新点 ⇒ 必须用并查集判"两端是否已连通"。

**Q2：`key[]` 和 Dijkstra 的 `dist[]` 到底差在哪？为什么换票公式不一样？**
`key[v]` = "从墙内的某个点**一步跨到 v** 的最便宜票价" = `min{ w[u][v] | u 在墙内 }`，不累加。
`dist[v]` = "从起点**一路走到 v** 的最短总长" = 沿途边权之和。
所以 Prim 换票写 `if (w[u][v] < key[v])`，Dijkstra 写 `if (dist[u] + w < dist[v])`。
两者代码结构几乎一样，差别就在这一处加法 —— 写错不会崩，只会安静地给出另一棵树（38 而不是 33）。

**Q3：MST 和最短路径树什么时候会重合？**
图本身就是一棵树（`E = V-1` 且连通）时，两者只能是同一棵树。
另外还有特殊情况：所有边权相同时，MST 任意一棵生成树总权都一样，
此时 Dijkstra 的 BFS 树也是 MST（因为每棵生成树总权相同）。
一般图里两者边集就不同 —— 本节共用图实测 MST 33 / SPT 38，只差一条边（`4-5(9)` vs `2-3(11)`），
但那 2 块钱的差正是"全局省钱"和"局部最快"两种目标的体现。

**Q4：怎么知道一张图的 MST 是唯一的？**
充分条件：**所有边权两两不同** ⇒ MST 唯一。
不唯一的情形：存在一个环，环上有两条（或多条）**权重相同且都是环上最小**的边，
它们可以互换。第 6 幕的等权三角形就是最简单的例子（3 条边任取 2 条都是 MST）。
实用检查法：跑一遍 Kruskal，对每条**被跳过**的边 `e`，看它两端之间那条唯一树路径上
是否存在和 `w(e)` 等权的边；有 ⇒ 不唯一。

**Q5：任务书说这张图的 MST 总权是 35，你的代码打印 33，谁错了？**
代码是对的，35 是"一棵合法生成树"的权值而不是最小值。
35 那棵树是 `0-1(7) 0-2(9) 2-5(2) 3-4(6) 2-3(11)`；
把其中的 `2-3(11)` 换成 `4-5(9)`，得到 `0-1 0-2 2-5 3-4 4-5 = 33`，
仍然覆盖 6 个点、5 条边、无环（点 3 现在挂在点 4 下面），所以 35 不是最小。
第 3 幕把这两棵树都打印出来做对比。**这也是"别只信答案，自己复核一条边"的现场教材。**
