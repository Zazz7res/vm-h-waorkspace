# 深度优先搜索 DFS (Depth-First Search)

> 用**栈**（或者干脆交给递归）一条路走到黑、撞墙再回头的遍历。
> 这一节最值钱的地方：把"递归就是系统在帮你维护栈"这句话**写成能跑的代码，逐格比对验证给你看**。

---

## 一句话是什么

**站在一个点上，挑一个没来过的邻居就钻下去；钻到没路了，就退一步，看看刚才那个点还有没有别的岔路。**

实现口诀只有四行：

```
进入 u → 立刻打标记（记前序）
    对 u 的每个邻居 v（顺序固定）：v 没来过就 dfs(v)      ← 先干完 v 的整棵子树
u 的邻居全看完了 → 离开 u（记后序），退回父亲
```

它和 BFS 的**全部**区别就一处：BFS 的待办用**队列**（先进先出 → 一圈一圈扩），
DFS 的待办用**栈**（后进先出 → 最新的先处理 → 一路钻到底）。
一行数据结构之差，行为、能算出的东西、适合的场合全变了。

---

## 为什么需要它

**不用它的话**，你只有 BFS。BFS 是"先把近的全部铺开"，可很多问题要的是"先钻到底再说"：

```
  问题：这张图里有没有环？
  BFS：一层层铺开，同层的点互相也有边，你得额外小心才能判出来。
  DFS：钻到 2 时发现邻居 0 已访问、而且 0 不是我父亲 → 有环。一句话搞定。
       （下一节 connected-components 就是这么干的）

  问题：一门课的先修课链条，谁该先上？
  BFS：只能给你"离起点几层"。
  DFS：给我**后序** —— 子先父后，倒过来就是拓扑序。这正是下一节 topo 的 DFS 解法。

  问题：走迷宫 / 八皇后 / 数独 / 列举所有方案（回溯法）
  BFS：把每一步的所有局面都存进队列，内存直接爆。
  DFS：只存"当前这一条路"，走不通就撤销最后一步换一条 —— 回溯法就是 DFS 骨架 + 撤销操作。
```

| 你想干的事 | 只有 BFS | 有了 DFS |
|---|---|---|
| 判图里有没有环 | 别扭，要额外记录 | 顺手（后向边 / 三色标记） |
| 拓扑排序 | 只能走 Kahn 入度那条路 | 后序反转，一条递归搞定 |
| 连通分量 / 强连通分量 | 能用，但要多存一层 | 一轮 DFS = 一个分量，天然计数 |
| 列举所有路径 / 回溯搜索 | 队列存不下所有局面 | 只存一条路径，走不通就退 |
| 求无权图最短距离 | **BFS 唯一正解** | ❌ DFS 给不了（本节实测 depth[3]=3，真最短是 2） |
| 判断"谁是谁的祖先" | 没有这个信息 | 进出时间戳（括号定理）直接比 |

一句话：**要"最短"用 BFS，要"结构"用 DFS。**
本节还会顺手解决另一个常见困惑：递归到底在干什么 —— 看完第 3 幕你会知道，
递归里那个看不见的栈长什么样，我们甚至能自己把它写出来，结果**一模一样**（程序自动比对，见运行结果）。

## 内存布局图解

### 共用示例图 G（和邻接矩阵、邻接表、BFS 那几节是**同一张图**）

```
       0 ───── 1                      4 ───── 5
        \     / \                      \     /
         \   /   \                      \   /
          2 ──────                      6          7 ← 孤零零
           \
            3

  分量一：0-1, 1-2, 2-0, 2-3     （0,1,2 成环 + 挂着 3）
  分量二：4-5, 5-6, 6-4          （另一个环）
  孤立点：7
  边 7 条，顶点 8 个。矩阵第 u 行按 j 升序扫 = 本节统一的"邻居顺序"。
```

### 递归版的内存：那个"看不见的栈"长这样（从 0 钻到 3 的那一刻）

```
   ┌──────────────────────────────┐
   │ dfs_go(3)  u=3 par=2 dep=3   │ ← 栈顶：j 扫到 2，是父亲 → 没别的邻居了 → return
   ├──────────────────────────────┤
   │ dfs_go(2)  u=2 par=1 dep=2   │   j 停在 4（3 已经处理过，回来接着扫就到底了）
   ├──────────────────────────────┤
   │ dfs_go(1)  u=1 par=0 dep=1   │   j 停在 3（2 之后）
   ├──────────────────────────────┤
   │ dfs_go(0)  u=0 par=-1 dep=0  │ ← 栈底：j 停在 2（1 之后）
   └──────────────────────────────┘
        系统调用栈（越往下越早进入）

   每一帧里装的不是"顶点"一个数，而是【u + 我的 for 循环走到第几个邻居 j + 我的父亲 + 我的深度】。
   ★ 记住"每帧各自记着 j 走到哪" —— 这是递归和"只存顶点的栈"最本质的差别，第 4 幕的全部差异都来自这里。
```

程序里同一时刻的 `trail[]`（当前路径）= `0 -> 1 -> 2 -> 3`，
它和帧栈里的内容一一对应；回溯一层就短一格。运行结果第 2 幕能一行行看到它变长变短。

### 手写栈要存什么：帧栈（Frame Stack）

```
   下标 →   0          1          2          3
          ┌────────┬────────┬────────┬────────┐
   data   │ v=0    │ v=1    │ v=2    │ v=3    │  ← 栈顶在右
          │ next=2 │ next=3 │ next=4 │ next=0 │
          └────────┴────────┴────────┴────────┘
            top = 4                     ▲
                                        └── 下一个要处理的邻居下标 = "游标"

   一帧 = Frame{ int v; int next; } = 8 字节
   next 就是递归里那个 for 循环的 j。**只存顶点的话，回溯回来会从头重扫邻居** —— 那就是朴素版。
```

### DFS 独有的两张顺序表 + 两个时间戳

```
   进入 = 签到，离开 = 签退。每个顶点各签到一次、签退一次，所以时钟走 2V 格。

   0 进 ───────────────────────────────────── 0 出（刻度 1 → 8）
      1 进 ───────────────────────────── 1 出（2 → 7）
         2 进 ──────────────────── 2 出（3 → 6）
            3 进 ─────── 3 出（4 → 5）

   前序（进的时刻排序）：0 1 2 3
   后序（出的时刻排序）：3 2 1 0        ← 子先父后；无环有向图里把它倒过来 = 拓扑序
   括号定理：v 在 u 的子树里 ⟺ 进[u] < 进[v] ≤ 出[v] < 出[u]
             例：进[0]=1 < 进[3]=4 ≤ 出[3]=5 < 出[0]=8 ✔
```

## 核心操作逐个拆解

### 1. `dfs_graph_sample(g)` / `dfs_graph_print(g)` —— 造出要遍历的图（gdfs.c:156 / gdfs.c:186）

**干什么**：把共用图 G 摆进一个 `int edge[8][8]` 矩阵，并把"每个点的邻居顺序"打出来。

**一步步**：全表清 0 → `v=8, e=0` → 按固定边表 `(0,1)(1,2)(0,2)(2,3)` 和 `(4,5)(5,6)(4,6)`
逐条把对称两格都涂 1（无向）→ 顶点 7 什么都不加。
打印时每行后面附上"邻居按固定顺序：1 2"，让人先看清楚一会儿要按什么顺序扫。

**边界情况**：栈上的二维数组不请自来的垃圾值必须自己清 0；
顶点 7 是**故意**留白的，专门用来演示"一轮 DFS 覆盖不到它"。

**对应代码行**：gdfs.c:149~213

### 2. 就地重写的两种栈：`IntStack` 与 `FrameStack`（gdfs.c:44~152）

**干什么**：叶子目录必须自包含，所以不引用第 03 章的文件，这里各写一个极简版：
`IntStack` 只存顶点（朴素版 DFS 用），`FrameStack` 存"帧 =（顶点，邻居游标）"（帧模拟版用）。

**一步步**：`s_push` 写到 `data[top]` 再 `top++`；`s_pop` 先 `top--` 再读 `data[top]`。
帧栈同理，只不过每格放 8 字节（两个 int），并且多一个 `fs_top()` 用来"偷看栈顶但不弹"。

**边界情况 / 容量怎么定**（这是本节的一个小考点）：
- 帧栈：栈里最多同时躺着"从根到当前点的一条简单路径"，长度 ≤ V ⇒ 开 `V+1` 格。
- int 栈 + 入栈即标记：一个点最多进栈一次 ⇒ 也只要 V+1。
- int 栈 + 出栈才标记：同一个点会被它的每个邻居各压一次 ⇒ 压栈总次数 ≤ `1 + Σdeg = 1 + 2E`，
  完全图时 `1 + 2E = V(V-1) + 1 < V²` ⇒ 所以 `GDFS_STACK_CAP = V*V = 64`。
  **先证上界，再定数组大小**，跟上一节"队列开到 V+1 就够"是同一类推理。

**对应代码行**：gdfs.c:37~146

### 3. 记账三件套 `res_reset / res_enter / res_leave`（gdfs.c:229 / 248 / 261）

**干什么**：把"前序、后序、parent、depth、进/出刻度、当前路径"这七件事收进三个函数。

**为什么单独抽出来**：本节有**四种**跑法（递归、帧模拟、朴素栈、全图），
如果各写各的记账代码，四份就会长出四个细微不同 —— 而我们正要拿它们互相核对。
统一走同一块"计价表"，比对才有意义（`main.c` 里的 `diff_count` 就靠这个）。

**一步步**：
`res_enter(u,par,depth)`：把 u 追加进 `order[]` → 写 parent/depth → `++clock` 记进刻度 → 把 u 挂到 `trail[]` 末端。
`res_leave(u)`：把 u 追加进 `post[]` → `++clock` 记出刻度 → `trail_len--`（把自己从当前路径擦掉 = 回溯）。

**边界情况**：`res_reset` 把按顶点索引的数组全填 **-1**，不能填 0 ——
起点深度就是 0、起点前序就是第 0 个，0 是合法值，只有 -1 "绝不可能出现"，才配当"没访问到"。
这和邻接矩阵用 -1 表示"无边"是同一个套路。

**对应代码行**：gdfs.c:216~289

### 4. `dfs_go` + `dfs_recursive` —— 递归版（gdfs.c:327 / gdfs.c:384）

**干什么**：最自然的 DFS。缩进打印每一步"进入 / 邻居判定 / 回溯"，把"走到底再回头"画出来。

**一步步（以 G、起点 0 为例，运行结果第 2 幕逐行对应）**：
1. `dfs_go(0)`：打标记、记前序（第 1 个）、进刻度 1、trail=`0`。
2. 扫 0 的邻居：j=1 没来过 → 打印"钻进去！"→ **递归调用**。
3. `dfs_go(1)`：前序第 2 个、刻度 2、trail=`0->1`；邻居 0 是父亲（跳过），邻居 2 没来过 → 再钻。
4. `dfs_go(2)`：前序第 3 个、刻度 3、trail=`0->1->2`；
   邻居 0 **已访问且不是父亲 → 后向边（这就是环的证据，下一节拿它判环）**；
   邻居 1 是父亲；邻居 3 没来过 → 再钻。
5. `dfs_go(3)`：前序第 4 个、刻度 4、trail=`0->1->2->3`；唯一邻居 2 是父亲 → 没路了。
6. 回溯：`res_leave(3)` → 后序第 1 个、出刻度 5 → 回到 2；2 的 j 从 4 继续扫到 7 都没边 → 离开 2（刻度 6）
   → 离开 1（刻度 7）→ 回到 0，0 的游标停在 2，看到"邻居 2 已访问不是父亲 → 后向边" → 离开 0（刻度 8）。

**边界情况**：
- **进函数第一件事就是 `visited[u]=1`**。图里有环，晚一步标记就是无限递归 → 栈溢出 → 段错误
  （注意症状是"崩"，不是"卡住"，很多人第一次遇到会以为是死循环）。
- `j == u` 要跳过（示例图没有自环，但代码不能赌）；`par` 传 -1 表示"我是这一轮的根"，
  根的邻居再"已访问"也不可能等于 -1，所以根那里只会打"后向边"，不会误判成父亲。

**对应代码行**：gdfs.c:292~399

### 5. `dfs_stack_frames` —— 帧模拟版：把系统藏起来的栈摆到桌面上（gdfs.c:432）

**干什么**：不用递归，自己压帧，做出和递归版**结果完全一致**的实现。这一版是"递归=系统帮你维护栈"的证据。

**对照翻译表**（本节的核心知识点，就这 6 行）：

| 递归里的东西 | 手写版里的东西 |
|---|---|
| 调用栈上的一个栈帧 | `Frame{v, next}` |
| 帧里的局部变量 `u` | `Frame.v` |
| 帧里的 for 循环游标 `j` | **`Frame.next` ← 不存它就模仿不像** |
| `dfs_go(v)` 这次函数调用 | `fs_push(v, 0)` |
| `return`（回溯） | `fs_pop()` |
| 最外层返回、整轮结束 | `fs_is_empty()` → 退出 while |

**一步步（一次循环只做三件事）**：
1. 偷看栈顶：它站在 `u` 上，游标停在 `next`。
2. 从 `next` 往后找第一个没访问过的邻居 `v`：
   找到 → **先把游标推到 `v` 之后并写回栈**（不写回就会回来重复看 `v`），再把 `(v, 0)` 压成新栈顶
   —— 下一轮 while 自然就在 `v` 上继续，这就是"钻进去"。
3. 找不到 → `u` 办完了 → 弹栈（= return）、`res_leave` 记后序。

**边界情况**：
- 弹栈之后必须回到 `while` 开头**重新看新栈顶**，不能顺手把新栈顶的邻居也扫完，
  那样就变成"一次处理多层"，深度优先的味道就散了。
- `fs_top()` 返回的是**值拷贝**，不能拿指针存着再用 —— 下面 `fs_push` 会改 `top`（这里数组存储不会挪内存，
  但按值取更保险，读者照抄到别的容器上也不会踩坑）。
- 深度怎么算：`res_enter` 时 `depth = fs.top`（压新帧**之前**的帧数），别写反。

**对应代码行**：gdfs.c:402~538；`main.c` 里第 3 幕用 `diff_count` 逐格比对了 6 张表，结果 **0 处不同**。

### 6. `dfs_stack_naive` —— 朴素栈版，以及"为什么顺序会不一样"（gdfs.c:594）

**干什么**：写教科书里最短的那版 DFS（弹一个点，把它的邻居一次全压进去），
并用两个开关把 4 种写法跑成一张对照表，看清每个细节各自改变了什么。

**骨架（8 行）**：
```
start 入栈
while 栈非空:
    u = 出栈
    if u 已经记过前序: continue        ← 出栈去重
    记 u 的前序
    for u 的每个邻居 v（方向由开关决定）: 若没进过栈则 v 入栈   ← 一压全压
```

**两个开关、四种组合的实际结果**（G、起点 0；运行结果第 4 幕原样可核对）：

| 组合 | 前序 | parent | 后序 | 重复出栈 |
|---|---|---|---|---|
| 递归版（参照） | 0 1 2 3 | -1 0 **1** 2 | 3 2 1 0 | — |
| A 升序压栈 + 入栈即标记 | **0 2 3 1** | -1 0 **0** 2 | 空 | 0 |
| B 降序压栈 + 入栈即标记 | 0 1 2 3 ✔同 | -1 0 **0** 2 ✘不同 | 空 | 0 |
| C 升序压栈 + 出栈才标记 | 0 2 3 1 | -1 **2** 0 2 | 空 | 1 |
| D 降序压栈 + 出栈才标记 | 0 1 2 3 ✔同 | -1 0 1 2（这张图碰巧同） | 空 | 1 |

**三条结论**：
1. **压栈方向决定前序**：栈是后进先出，按升序压 → 栈顶是大的 → 先处理 2，前序变 `0 2 3 1`；
   想要和递归一致必须**反着压**（降序压入，于是升序弹出）。
2. **打标记时机决定树**：B 的前序和递归版完全相同，可 `parent[2]` 是 0 而不是 1 ——
   因为 0 一出场就把 1、2 **全都**压进栈并标记了，"发现权"被抢答；
   递归版是 0 先看 1，1 一路钻到 2，2 才是被 1 带进来的。
   ⇒ **前序对得上 ≠ 实现等价**。要 DFS 树（父子关系、深度、后序）必须用递归版或帧模拟版。
   出栈才标记（C/D）更乱：同一个点被多个邻居重复压栈，`parent` 归"最后一个压它的人"（C 里 `parent[1]=2`）。
3. **朴素版给不出后序**：它没有"离开 u"这一刻（弹出即结束），所以 `post[]` 全空、`tick_out[]` 全 -1。

**边界情况**：
- "出栈时的去重"和"入栈时的去重"是**两件事**，不能共用一个数组：
  出栈看 `r->tick_in[u] >= 0`（前序记过没有），入栈看 `marked[j]`（进过栈没有）。
  混用会出现"起点一出场就被判成已处理"的怪事 —— 见坑 ④。
- 出栈去重那句 `continue` 在两种模式下都必须留着：mark_on_pop 时它负责去重，
  mark_on_push 时它是防御性检查（正常永远为 0 次，`dup_pops` 就是它的仪表）。

**对应代码行**：gdfs.c:541~701

### 7. `dfs_all` —— 全图遍历（gdfs.c:724）

**干什么**：一轮 DFS 只覆盖一个连通分量，所以要外层扫每个还没访问过的点。

**一步步**：
```
for 每个顶点 u:
    if u 没被访问过:
        以 u 为根起一轮 DFS      ← 这一轮覆盖的就是一个新的连通分量
```
`visited[]` 放在**外层**，跨轮共享；`dfs_go` 只负责把这一轮钻完。

**边界情况**：
- 图 G 有三个分量 `{0,1,2,3}` `{4,5,6}` `{7}` ⇒ 起了 **3 轮**，所以"轮数 = 连通分量数"
  （这正是下一节 `connected-components/` 的做法）。
- 孤立点 7 度为 0，也要单独占一轮：度 0 也是一个分量。
- 跑完 `dfs_all`，`parent` 里会有 0、4、7 三个 -1。此时 **-1 不再等于"没访问到"**，
  它表示"我是某轮的根"；要区分这两者得看 `tick_in`（还是 -1 才是真没访问到）。

**对应代码行**：gdfs.c:705~751

### 8. `dfs_print_result(g, r)` —— 把四张表摊开 + 和"最短距离"当面对质（gdfs.c:772）

**干什么**：打印前序、后序、每点 `parent/depth/进刻度/出刻度` 表、把 parent 链从每个点往上追到根
（DFS 树的形状），最后用顶点 3 说明 **DFS 的 depth 不是最短距离**。

**为什么要把父子链打出来**：`parent[]` 只是一堆数字，
"3 的父亲是 2、2 的父亲是 1、1 的父亲是 0"连起来读，才看得出 DFS 走的是**一条深链** `0-1-2-3`，
而上一节 BFS 给的是**矮胖树**（0 直接管着 1 和 2）。两种遍历的区别一眼可见。

**边界情况**：`post_len == 0`（朴素版）时要显式说明"这一版没有离开时刻"，不能只印一行空白；
追 parent 的 while 带了 `guard` 上限，万一 parent 被写成环也不会死循环。

## 复杂度表

V = 顶点数，E = 边数。本节示例用邻接矩阵，所以是左列；真做工程要换邻接表（右列）。

| 实现 | 时间（矩阵版） | 时间（邻接表版） | 额外空间 | 能给出什么 |
|---|---|---|---|---|
| DFS 递归版 | **O(V²)** | **O(V+E)** | 调用栈最坏 O(V) 帧 | 前序+后序+parent+depth+时间戳，全套 |
| DFS 帧模拟版 | O(V²) | O(V+E) | 自己栈 O(V) 帧 = 8V 字节 | 与递归版**完全一致**（本节实测 0 处不同） |
| DFS 朴素栈版 | O(V²)，重复出栈最坏 O(E) 次 | O(V+E) | 栈最坏 2E+1 个 int | 只有前序 + parent（且可能"塌成矮树"）；**没有后序** |
| BFS（上一节） | O(V²) | O(V+E) | 队列 O(V) | 访问顺序 + **dist（无权图最短距离）** + parent |
| 暴力枚举所有路径 | 指数级 | 指数级 | — | 全部路径（只有判环/回溯搜索逼不得已才用） |

**为什么矩阵版是 O(V²)**：每个顶点被"进入"一次，进入时扫它那一整行（V 格）→ V·V。
**为什么邻接表版是 O(V+E)**：每个顶点扫一次自己的链表（合计 Σdeg = 2E）→ O(V+E)。
E 很小时（稀疏图）两者差几十倍，这是大图必须用邻接表的根本原因。

**空间两个细节**：
1. 递归版的 O(V) 栈空间是**系统给的**，但系统栈有上限（Linux 默认 8 MB 量级）。
   一百万个点的链状图 → 一百万层帧 → 必爆栈。这就是显式栈版存在的唯一理由。
2. 帧模拟版的栈是自己 `malloc`/数组，想开多大开多大，不受调用栈限制。

## 常见的坑

### 坑 ①：忘了 visited —— 症状是"崩"，不是"卡"

图里有环。0-1-2-0 这一圈，不打标记就会走成 `0→1→2→0→1→2→…` 永远不回头的递归。
它不会转圈卡住，而是**调用栈一直长，撑爆后段错误（Segmentation fault）**。
很多人第一次见这个错误会去查"数组越界"，其实凶手是无界递归。
**规则：进入顶点的第一件事就是 `visited[u] = 1`。**

### 坑 ②：把 DFS 的 depth/dist 当最短距离

本节实测：`depth[3] = 3`（0 钻到 1、1 钻到 2、2 钻到 3），
而上一节 BFS 的 `dist[3] = 2`（0 直接找 2、2 再找 3）。**DFS 的层号只是"这次运气走到的深度"。**
它不保证最短，因为 DFS 的哲学就是"先钻到底"，压根不按距离排序。
要最短距离：无权图用 BFS，带权图用 dijkstra。

### 坑 ③：手写栈只存顶点，不存"邻居游标"

这样写出来的是**另一套算法**（本节的朴素版），会得到不同的前序和不同的 DFS 树：
`parent[2]` 从 1 变成 0，DFS 树从"深链"塌成"矮胖树"，而且**完全没有后序**。
需要后序（拓扑排序）、需要精确复刻递归行为（判环的细节、括号定理）的场合不能用它。
要么用递归，要么老老实实存 `Frame{v, next}`。

### 坑 ④：把"入栈去重"和"出栈去重"共用一个数组

实现朴素版时本节真的踩过：入栈时写了 `visited[start]=1`，出栈时又写
`if (visited[u]) continue;` —— 结果**起点一出场就被判成"已处理"，整轮 DFS 从根就开始漏**，
而且漏的偏偏是根，症状是"前序少一个、parent 全乱"，非常难联想到是这一行。
正确做法是两个检查管两头：出栈看 `tick_in[u] >= 0`（前序记过没有），入栈看 `marked[j]`（进过栈没有）。

### 坑 ⑤：出栈时才打标记，却忘了在出栈处判重

`mark_on_pop=1` 时同一个点会被它的多个邻居分别压栈（本节实测重复出栈 1 次）。
弹出后不判 `continue`，就会**同一个顶点处理两遍、前序里出现重复**，
parent/depth 也会被"最后一个压它的人"覆盖掉（C 行里 `parent[1]=2`，可 1 明明是 0 先发现的）。
**要么入栈即标记，要么出栈必判重，两件事必须做一件。**

### 坑 ⑥：邻居顺序不固定，结果"每天不一样"

DFS 的解**本来就依赖邻居顺序**（这不是 bug，是它的本性）。
如果同一份代码今天用邻接表插头（顺序反）、明天用排序后的链表，输出就对不上，测试也没法断言。
本节统一规定：**扫矩阵第 u 行，列号 j 升序**，一次例外都没有，所以 README 能逐行核对。
（对照看 `07-graph/adjacency-list/`：那里的 `glist_add_edge_front` 会让邻居顺序反过来，
  从而让遍历顺序跟着变 —— 这两个现象是同一件事。）

### 坑 ⑦：只起一轮 DFS 就当"全图遍历完了"

从 0 出发只覆盖 `{0,1,2,3}`，`{4,5,6}` 和 `{7}` 一个都没碰到，
而**栈正常走空、返回值正常、零报错**。"结果少了一坨但毫无异常"是最难查的 bug。
全图遍历必须外层扫：
```
for 每个顶点 u: if u 没访问过: 从 u 起一轮 DFS     ← 轮数 = 连通分量数
```
跑完 `dfs_all` 之后 `parent` 里会有多个 -1（各轮的根），
此时 **-1 不再表示"没访问到"**，要判断可达性得看 `tick_in`（或单独维护 visited 数组）。

### 坑 ⑧：在超深图上无脑用递归

递归版的深度 = 从根到当前点的**最长**路径长度。8 个点无所谓，
但一百万个点的链状图（或者一条 10 万深的迷宫搜索）就是一百万层帧 → 爆栈。
竞赛/工程里给线程栈设了小限额（几百 KB 到几 MB）时尤其容易触发。
这时换成**帧模拟版**：栈在自己手里，想开多大开多大。

### 坑 ⑨：拿跑完之后的 `trail[]` 做文章

`trail[]` 是**过程中**的"从根到我"，`res_leave` 会把它缩掉。
整轮跑完 `trail_len == 0`，此时读它就是读垃圾。
要事后还能回溯路径，请用 `parent[]` 往上追（`dfs_print_result` 里就是这么做的）。

## 什么时候用它 / 什么时候别用

**该用 DFS：**

| 场景 | 为什么是 DFS |
|---|---|
| 判环（无向图后向边 / 有向图三色标记） | 只有"还在往下钻"的栈能告诉你"我撞回了自己" → 下一节 |
| 连通分量、强连通分量（Kosaraju / Tarjan） | 一轮 DFS = 一个分量；后序是 Kosaraju 的第二遍顺序 |
| 拓扑排序 | 后序反转即拓扑序 → 下一节两种解法之一 |
| 回溯搜索：迷宫、八皇后、数独、全排列、子集 | 只存当前这条路，走不通撤销最后一步，空间 O(深度) |
| 判断谁是谁的祖先、子树区间 | 进出时间戳 + 括号定理 |
| 找一条"任意"通路（不要求最短） | DFS 往往几步就撞到底，比 BFS 铺开一整层更省 |
| 生成迷宫 / 生成随机连通图 | "钻到底再回头"天然长出又长又绕的路径 |

**别用 DFS：**

| 场景 | 该用什么 |
|---|---|
| 无权图最短距离 | **BFS**（上一节）—— DFS 的 depth 不保证最短，本节实测过 |
| 带权最短路 | dijkstra / bellman-ford / floyd（本章后面几节） |
| 图极深、可能爆栈（百万级链状） | 帧模拟版 DFS（本节就给了）或 BFS |
| 需要"离起点几层"这种分层信息 | BFS |
| 只要遍历一遍、不关心结构 | 两者皆可，选代码短的（通常是递归 DFS） |

## 自检问题

**1. 为什么递归版 DFS 的 for 循环"回来之后能接着上次的位置继续走"？**

因为每一层 `dfs_go(u)` 都有自己的**栈帧**，循环变量 `j` 是这个帧里的局部变量。
调用 `dfs_go(v)` 期间，`u` 的那个帧没被销毁，`j` 静静地躺在调用栈更靠下的一格里。
这也是为什么"只存顶点的手写栈"模仿不像：它没有地方放这个 `j`。
本节 `dfs_stack_frames` 把 `j` 明写成 `Frame.next`，结果 6 张表和递归版**逐格相同**。

**2. 帧模拟版和朴素栈版，哪一个能替代递归？为什么？**

**帧模拟版**。区别只有一处：帧模拟版存了 `Frame{v, next}`（顶点 + 邻居游标），
所以它复现了"每个点扫到第几个邻居"这个状态，前序、后序、parent、depth、进出时间戳全部一致。
朴素版只存顶点、一发现邻居就全压进去，于是 ① 邻居处理顺序会被栈反过来，
② DFS 树会塌（`parent[2]` 被 0 抢走），③ 根本没有"离开"时刻 ⇒ **给不出后序**。

**3. 本节 `depth[3] = 3`，上一节 BFS `dist[3] = 2`。谁错了？**

都没错，量的不是同一个东西。`dist[3]=2` 是"最少 2 步"，因为 BFS 按步数排序访问，
第一次到达一定最短。`depth[3]=3` 是"这一次钻到第 3 层"，因为 DFS 先钻 0→1→2，
到 2 时顺手就看见 3 没访问过，于是继续钻 —— 它压根不考虑"有没有更近的路"。
**结论：要最短距离用 BFS/dijkstra，DFS 的深度不可当距离用**（坑 ②）。

**4. 为什么全图遍历要 `for 每个顶点 u: if 没访问过: 起一轮`？只起一轮会怎样？**

一轮 DFS 的可达范围 = u 所在的连通分量。从 0 出发只覆盖 `{0,1,2,3}`，
`{4,5,6}` 和 `{7}` 完全碰不到，而且**不报错、返回值正常**（栈正常走空）。
外层扫描把剩下两个分量补齐，G 上一共起 **3 轮** —— 顺带得到"轮数 = 连通分量个数"，
这就是下一节算连通分量的方法（坑 ⑦）。

**5. 后序（postorder）到底有什么用？为什么朴素栈版给不出来？**

后序记录的是"这个点**连同它下面整棵子树**都办完了"的时刻，
所以它天然满足"子的后序在父之前"。
在**无环有向图**上把后序倒过来，父一定排在子之前 —— 这就是拓扑序（下一节 DFS 解法）。
判环、算子树大小、括号定理也要靠"离开时刻"。
朴素版弹出顶点就算处理结束，从来没有"它办完了"这个时刻，所以 `post[]` 是空的（坑 ③）。

**6. 什么时候必须把递归 DFS 换成显式栈？**

当**最长路径可能上千/上万**的时候：递归深度 = 路径长度，
每层帧几十~上百字节，一百万层就是几百 MB → 爆栈（段错误）。
竞赛或工程里线程栈被限制成几 MB 时特别容易踩到。
这时换成 `dfs_stack_frames`，栈放在自己手里（数组或堆），容量自己定（坑 ⑧）。
