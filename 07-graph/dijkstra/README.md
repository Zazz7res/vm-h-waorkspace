# Dijkstra 单源最短路（07-graph/dijkstra）—— 每轮"定稿"一个点

> 一句话定位：图这章的主角。用**朴素 O(V²)** 和**小顶堆 O((V+E)logV)** 两种写法把同一张图跑两遍，
> 逐轮打印 `dist` 数组怎么变；最后用一张 4 点负权图，**亲眼看它安静地算错**。

---

## 一句话是什么

**Dijkstra**：固定一个起点 `src`，一次算出**从 src 到图上每一个点**的最短距离（这叫"单源"）。

一句话算法：

1. `dist[src] = 0`，其它点 `dist = ∞`（"还不知道怎么去"）。
2. 重复 `V` 轮：**在未定稿的点里挑 `dist` 最小的那个 `u`，把它"定稿"**（此后不再修改）。
3. 用 `u` 松弛它的所有出边：`if (dist[u] + w(u,v) < dist[v])` 就更新 `dist[v]`，并记 `parent[v] = u`。

两个数组分工明确：`dist[]` 给**距离**，`parent[]` 给**路径**（只留前者就回不了路径）。

本目录的两个版本：

| 版本 | 挑最小怎么挑 | 时间 | 用途 |
|---|---|---|---|
| `dijkstra_naive` | 扫一遍 `key` 数组 | `O(V²)` | 稠密图 / 讲清楚原理 |
| `dijkstra_heap` | 从小顶堆弹一个 | `O((V+E) log V)` | 稀疏图 / 真正的工程写法 |

---

## 为什么需要它

导航、路由、游戏寻路、任务调度的代价估算 —— 全是"从这儿到那儿最少要多少"。

朴素做法（DFS 枚举所有路径）在稍大一点的图上就是指数爆炸：
共用图 6 个点还能暴力算，50 个点的路网暴力枚举会跑到宇宙热寂。

Dijkstra 的价值在于：**只要边权非负，一个贪心就能把指数级问题压到 `O((V+E) log V)`。**
贪心的直觉是"眼前最近的未处理点，它的最短距离已经定了" —— 这个直觉对不对？
对，但**前提是边权非负**。第 5 幕会把它违反前提时的错误结果现场跑出来，
这也是本目录存在的教学意义：知道一个算法**什么时候不能用**，比会用更重要。

## 内存布局图解

```c
typedef struct { int from, to, weight; } Edge;      /* 一条【弧】：有方向 */
typedef struct {
    int n;                    /* 顶点数 0..n-1 */
    int directed;             /* 1 = 有向，0 = 无向 */
    int m;                    /* 当前弧条数 */
    Edge e[MAX_E];            /* 边表：堆优化版用它，"只看 u 的出边" */
    int w[MAX_V][MAX_V];      /* 邻接矩阵：朴素版用它，O(1) 判断两点有没有边 */
} Graph;
```

同一张图存两种表示，是为了让两个版本各用擅长的：无向边 `0-1(7)` 在边表里存成**两条弧**，
在矩阵里**对称写两格**：

```
  边表（共用图 9 条无向边 ⇒ 18 条弧）        矩阵 w[u][v]（∞ = 没有边）
  e[0] = {0,1,7}  e[1] = {1,0,7}                     j=0  1   2   3   4   5
  e[2] = {0,2,9}  e[3] = {2,0,9}             w[0] [  ∞   7   9  14   ∞   ∞ ]
  ...                                              w[1] [  7   ∞  10  15   ∞   ∞ ]
  （有向图就只存一条）　                            ...
```

两个工作数组（这才是算法在"动"的内存）：

```
  第 4 轮开始时的快照：

  下标 v ：    0      1      2      3      4      5
  dist  ： [   0,     7,     9,    20,   INF,    11  ]   ← 到 v 目前【已知的最好成绩】
  parent： [  -1,     0,     0,     2,    -1,     2  ]   ← 这个成绩是从谁那儿松弛来的
  done  ： [   1,     1,     1,     0,     0,     0  ]   ← 定稿 = 不再修改
                                                 ↑
                              第 4 轮挑未定稿里 dist 最小的 = 5（11）→ 定稿 5，然后松弛 5->4
```

`parent[]` 连起来就是**最短路径树**：

```
        0
       / \
      1   2
         / \        ← parent[3]=2, parent[5]=2
        5   3
        |           ← parent[4]=5（不是 3！绕 5 更便宜：20 < 26）
        4
```

堆优化版还多一个堆（自己写的极简小顶堆，`HeapItem{vertex, dist}`）：

```
  数组下标和树的关系：节点 i 的左孩子 = 2i+1、右孩子 = 2i+2；父亲 = (i-1)/2
  （所以"完全二叉树"不需要指针，数组下标就把父子关系说清楚了）

  把真实输出里第 4 步之后的那一行堆内容画成树（值写成 顶点:距离）：
      堆里的历史快照: [5:14 4:20 3:20 3:22]   （共 4 条，堆顶在数组第 0 格）

                 5:14                ← 下标 0：堆顶永远是距离最小的那条
                /    \
            4:20      3:20          ← 下标 1、2 = 2*0+1、2*0+2
            /
        3:22                        ← 下标 3 = 2*1+1，只有左孩子（4 号位置空着）

        检查堆性质：14 <= 20, 14 <= 20（根 ≤ 两子）✓；20 <= 22（下标 1 ≤ 它的孩子）✓
        注意它【不是】排序后的数组：4:20 排在 3:20 前面，兄弟之间不分大小，只保证"爹不大于儿"。

        5:14 就是「历史照片」—— dist[5] 早就降到 11 了，这条是旧的，弹出即丢弃
```

**`INF_DIST` 为什么取 `1000000000` 而不是 `INT_MAX`**：松弛要算 `dist[u] + w`，
如果 `dist[u]` 是 `INT_MAX`，加一下就溢成负数，比较全乱。`1e9` 加上任何正常边权都不会溢出。

## 核心操作逐个拆解

### 操作 1：松弛（relax）—— 整个算法的心脏

```c
if (dist[u] >= INF_DIST) return;                 /* u 不可达就别往外扩（本目录靠挑最小那步规避） */
if (dist[u] + g->w[u][v] < dist[v]) {
    dist[v]   = dist[u] + g->w[u][v];            /* 刷新最好成绩 */
    parent[v] = u;                              /* ★ 必须同时记，否则回不了路径 */
}
```

"松弛"这个词的意思：`dist[v]` 本来是"上界"，每发现一条更短的路，上界就**松**一点、变小一点。

**`<` 还是 `<=`？** 用 `<`：并列时保留先到的那条路，路径输出才稳定可复现。

### 操作 2：朴素版挑最小 —— 线性扫

```c
int u = -1;
for (int v = 0; v < n; v++)
    if (!done[v] && dist[v] < INF_DIST && (u == -1 || dist[v] < dist[u])) u = v;
if (u == -1) break;      /* ★ 边界：未定稿里已经没有可达点了 ⇒ 剩下的点不可达，提前结束 */
done[u] = 1;             /* 定稿 */
for (int v = 0; v < n; v++) relax(u, v);
```

`O(V)` 挑 + `O(V)` 松弛 = 一轮 `O(V)`，共 `V` 轮 ⇒ **`O(V²)`**。
注意它**和边数无关**：图再稀疏也照扫 `V²` 个格子 —— 这是它的短板，也是它在稠密图上反而最快的原因。

### 操作 3：为什么"定稿"是安全的（正确性证明）

> 设 `u` 是当前未定稿里 `dist` 最小的点。断言：`dist[u]` 已经是真正的最短距离。
> 反设还有一条更短的路 `P` 到 `u`。`P` 从定稿区出发，必然在某处跨过边界，
> 设第一个未定稿的点是 `x`，则 `dist[x] <= `（`P` 走到 `x` 的那段长度）`<= w(P) < dist[u]`。
> 可是 `u` 是未定稿里最小的，`dist[x] >= dist[u]` —— 矛盾。∎

关键在最后那句不等式 `dist[x] <= w(P)` 能不能成立：它依赖**从 `x` 继续走到 `u` 不会变短**，
也就是**边权非负**。第 5 幕的反例正是从这里崩掉的。

### 操作 4：为什么要堆（以及"为什么要扔过期记录"）

朴素版每轮花 `O(V)` 只为找一个最小值。堆把这个动作变成 `O(log V)`：

```
  为什么要堆？
     V = 10^5 时 V² = 10^10 —— 直接超时。堆版是 E log V ≈ 10^6 × 17 ≈ 1.7×10^7。
     稀疏图（E ≈ V）里"扫全图找最小"绝大部分力气花在 ∞ 上，纯浪费。
```

但堆有个尴尬：**它不支持"降低某个元素"（decrease-key）**。两种解法：

```
  方案 A（本目录采用）「惰性删除 / 塞新快照」：
      dist[v] 变小了，就在堆里【再塞一条 (v, 新距离)】，旧那条不动。
      ⇒ 堆里同一个点可能有好几条记录，距离各不相同 —— 它们全是"历史照片"。
      ⇒ 弹出时必须判断：if (d > dist[u]) continue;   ← 这一行是本节的灵魂
         （d 是入堆时的快照，dist[u] 是现在的最好成绩；d 更大说明这条已经作废）
      ⇒ 还要判断：if (visited[u]) continue;          ← 同一张快照被弹第二次（重复入堆）也扔掉

  方案 B「真 decrease-key」：
      额外维护 pos[v] = v 在堆数组里的下标，换距离时就地 sift-up。
      省内存（堆大小 ≤ V），但下标数组 + 交换时要同步更新两处，极易写错。
```

方案 A 的堆大小可能到 `O(E)`（每条边最多塞一条），弹出次数 `O(E)` 次，每次 `O(log E)` ⇒ 仍是 `O(E log E)`。
**"塞记录很便宜，代价延后到弹出时结算"** —— 这叫延迟删除（lazy deletion）。

本目录第 4 幕实测：共用图 `V=6, E=9`，堆版一共丢弃了 **2 条过期记录**
（`5:14` 和 `3:22`），输出里逐条点名了。

### 操作 5：手写小顶堆（40 行，只用 int）

```
  push（上浮）：放到数组末尾，然后 while (比父亲小) 和父亲交换
  pop （下沉）：把最后一个元素填到堆顶，然后 while (比两个孩子都大) 和【较小的孩子】交换
```

- `heap_create` 只 `malloc` **一次**（结构体和数组连在一起：`h->item = (HeapItem *)(h + 1)`），
  `heap_destroy` 对应 `free` **一次** —— 一对一，ASan 查不出泄漏。
- 比较规则写死在代码里（距离小的排前面），**不用函数指针**，所以它不是通用堆，但一眼能看懂。
- 下沉时必须和**较小的孩子**换，否则堆性质会破（"父 ≤ 两子"变成了"父 ≤ 大子"）。

### 操作 6：回溯打印路径

```c
/* parent[v] = u 表示到 v 的最后一步从 u 来 ⇒ 从 dst 往回串，再倒过来打印 */
0 -> 2 -> 5   (11)
```

实现细节：往回走的循环带了三重保险 —— `cur != src`（正常终止）、`cur != -1`（撞到根/孤点）、
`len < MAX_V`（**步数上限**：万一 `parent` 被写错成互相指向，形成环，这里也能停住，
绝不给死循环机会）。回溯完再倒序打印，就是 `0 -> 2 -> 5`。

### 操作 7：暴力法当"标准答案"

`shortest_by_brute_force` 用 DFS 枚举从 `src` 出发的**所有简单路径**（不走重复点），取最小值。
它**能处理负权**，所以用来给 Dijkstra 的错误答案做对照。复杂度是指数级，只在 4 点反例上用。
（有负环时"简单路径"这个限制也顺便避免了无限绕圈。）

## 复杂度表

| 版本 | 时间 | 空间 | 适合 |
|---|---|---|---|
| 朴素（数组扫最小） | `O(V²)` | `O(V²)`（矩阵） | **稠密图**（`E ≈ V²`） |
| 堆优化（惰性删除） | `O((V+E) log V)`，堆大小 `O(E)` | `O(V+E)` | **稀疏图**（`E ≈ V`） |
| Fibonacci 堆 | `O(V log V + E)` | `O(V+E)` | 理论最优，常数巨大，工程上没人写 |
| 暴力枚举所有路径 | 指数级 | `O(V)` | 只对拍用 |

`V = 10^5, E = 2×10^5` 时的数量级对比（这决定了"该写哪个"）：

| 写法 | 大约操作数 | 结果 |
|---|---|---|
| 朴素 `O(V²)` | `10^10` | 超时 |
| 堆 `O(E log V)` | `3.4×10^6` | 毫秒级 |

横向对比整节图算法：

| 算法 | 管什么 | 时间 | 能处理负权 | 能处理负环 |
|---|---|---|---|---|
| **Dijkstra（本节）** | 单源最短路 | `O(V²)` / `O((V+E)logV)` | ✗ 会**安静地算错** | — |
| Bellman-Ford | 单源最短路 | `O(V·E)` | ✓ | ✓ 能查出来 |
| Floyd-Warshall | 任意两点 | `O(V³)` | ✓ | ✓（对角线 < 0） |
| BFS | 无权图单源 | `O(V+E)` | — | — |
| Prim / Kruskal | 最小生成树 | `O(V²)` / `O(E log E)` | 不关心 | 不关心 |

## 常见的坑

### 坑 1：有负权边还硬用 Dijkstra —— 而且它不报错

第 5 幕实测：`A→B=2, A→C=5, C→B=-4`，正确答案到 `B` 是 `1`（走 `A→C→B`），
Dijkstra 给出 **2**，打印得整整齐齐、毫无异常。因为它在第 2 轮就把 `B` **定稿**了，
之后 `C` 那条能让 `B` 变短的边再也进不去。
**症状是"结果看起来完全合理"** —— 这种 bug 最难查。
有负权就换 `07-graph/bellman-ford`。本目录 `dijkstra_naive` 开头会扫一遍负权边并打印警告，
但**警告不是保护**，它照样跑完给你错答案（故意的，为让你看见"错成长什么样"）。

### 坑 2：堆版漏掉 `if (d > dist[u]) continue;`

后果：**结果不一定错，但可能把已定稿的点再松弛一遍，把 `parent[]` 改坏**，
甚至让同一点被"定稿"两次；如果 `parent` 被写成互相指向，回溯打印就会在环里绕
（本目录的 `print_shortest_path` 用 `len < MAX_V` 这个步数上限兜底，不会真死循环，但打印出来的路径是断的）。
写堆版时，这两行缺一不可：

```c
if (d > dist[u]) continue;   /* 过期快照（历史照片） */
if (visited[u])  continue;   /* 同一个点重复弹出 */
```

### 坑 3：`INF` 取成 `INT_MAX`，一加就溢出变负数

`INT_MAX + 5 = -2147483644`，于是"不可达"变成"全图最便宜"，算法会在不可达的点上继续扩展。
**取 `INF = 1e9`（≈ `INT_MAX/2`）量级**，或者干脆在松弛前判 `if (dist[u] == INF) continue;`。

### 坑 4：只维护 `dist[]`，忘了 `parent[]`

问"最短距离多少"能答，问"路径怎么走"就傻了。两个数组必须同时更新。
（另一处易错：`parent[start]` 要显式设成 `-1`，否则回溯时不知道在哪停，
可能一路读到别的点的 parent 而绕圈。）

### 坑 5：无向图只存一条弧

`graph_add_edge(g, u, v, w)` 在 `directed = 0` 时要**自动补一条 `v -> u`**。
漏了就是"单向能通、反向不能通"，`dist` 出现一堆莫明其妙的 ∞。
检查方法：跑完打印一遍边表，看弧数是不是边数的 2 倍（本目录第 1 幕就是这么自检的）。

### 坑 6：忘了 `u == -1` 就 break —— 非连通图上空转

未定稿里已经没有可达点时（`dist` 全是 ∞），`u` 是 `-1`，
不 break 就会拿 `-1` 当数组下标去读 `dist[-1]` ⇒ **越界访问**（`print_shortest_path` 里也有同款兜底：
先判 `dist[dst] >= INF_DIST` 就直接打印"不可达"并返回，不去回溯一条不存在的路）。
剩下的点保持 `dist = ∞, parent = -1`，这是**正确的**语义："到不了"。

### 坑 7：把 Dijkstra 用在最小生成树上（或反过来）

结构极其相似（都是"维护一个 key/dist 数组 + 每轮挑最小"），很多人会写混：
**Dijkstra 松弛 `dist[u] + w < dist[v]`（累加），Prim 松弛 `w < key[v]`（不累加）**。
写错不报错，只是答案从"最短路"变成"生成树"（或反之）。详见 `prim-mst` 的坑 1。

## 什么时候用它 / 什么时候别用

**该用 Dijkstra 的场景**

- 单源最短路 + **边权全部非负**（这是硬前提）。
- 需要起点到**所有**点的距离（要路由表、要"到每个点多久"）。
- 稀疏大规模图 → 堆版；稠密小图 / 已有邻接矩阵 → 朴素版。
- 只需要到某一个终点：可以跑到"终点被定稿"就 `break`（本目录没做这个优化，留给你）。

**别用的场景**

- **有负权边** → `07-graph/bellman-ford`（`O(V·E)`，能处理负权还能报负环）。
- **有向无环图 DAG** → 拓扑排序 + 一遍松弛，`O(V+E)`，比 Dijkstra 更快且允许负权。
- **任意两点都要**且 `V` 很小（≤ 几百） → `07-graph/floyd`（5 行代码，别跑 V 次 Dijkstra）。
- **无权图**（边权都是 1） → BFS 就是 Dijkstra 的特化，`O(V+E)`，用堆纯属浪费。
- **有负环** → 最短路根本不存在（绕一圈就更便宜），任何算法都给不出距离；
  Bellman-Ford 至少能**报告**"有负环"，Dijkstra 只会沉默地错。

## 自检问题

**Q1：Dijkstra 为什么要求边权非负？负权到底破坏了哪一步？**
破坏的是"定稿"那一步的正确性证明。证明里要用到
`dist[x] <= (更短路 P 到 x 的那一段) <= w(P)`，
第二个 `<=` 的含义是"从 `x` 继续往 `u` 走不会让总长变短" —— 只有边权非负时才成立。
第 5 幕的 `C→B = -4` 正好相反：`B` 定稿成 2 之后，走 `C` 再回来能降到 1，
但"已定稿不再修改"这条规矩把更正挡在门外，于是错误被冻结。

**Q2：堆版里 `if (d > dist[u]) continue;` 在防什么？不加会怎样？**
防的是"过期快照"。我们做 decrease-key 的方式是**塞一条新的**、旧的留着不管，
所以同一个点可能在堆里躺好几条，`d` 是入堆那一刻的历史值。
弹出时如果 `d > dist[u]`，说明这条已经被更好的记录取代，直接丢弃。
不加这一行：可能把同一个点"定稿"两次，第二次会以一个偏大的 `dist[u]` 去松弛邻居，
把 `parent[]` 改坏，路径就不最短了 —— 而且不一定每次都错，属于"偶发"型 bug。

**Q3：`V = 10^5`、`E = 2×10^5` 的图用哪个版本？为什么不是"堆更快"就一律用堆？**
`E` 只有 `V` 的两倍，是稀疏图 ⇒ 堆版 `O(E log V) ≈ 3.4×10^6`，
朴素版 `V² = 10^10`，只能选堆版。
但反过来，**稠密图**（`E ≈ V²/2`）时堆里要塞 `O(E)` 条记录、弹出 `O(E)` 次，
`E log V` 比 `V²` 还大一截 ⇒ 朴素版反而更快，而且不用 malloc。
**结论：朴素版配稠密 + 矩阵，堆版配稀疏 + 邻接表。**

**Q4：为什么 `dist` 数组能算对，`parent` 数组却可能"不止一种答案"？**
最短**距离**是唯一的，最短**路径**不唯一（并列时选谁都可以）。
本目录的规则是"只在严格更短时更新"（`<` 而非 `<=`），所以并列时保留先扫到的那条，
输出稳定可复现。但换了图的存储顺序、换了朴素/堆版本，`parent` 就可能不同 ——
这也是第 4 幕的对照表只强制要求 `dist` 逐格相同、`parent` 允许有差异的原因
（本例两者恰好全部一致）。

**Q5：共用图里 `0 → 5` 直连只要 14，Dijkstra 为什么第 1 轮就把 14 记进 `dist[5]`？它不算错吗？**
不算错，那正是算法的设计：`dist[5] = 14` 是**当前已知的上界**，不是最终答案。
第 3 轮松弛 `2 → 5`（`9 + 2 = 11 < 14`）就把它改到 11，`parent[5]` 也从 0 换成 2。
**`dist` 里 5 被改了一次，所以堆里留下了两条 5 的快照（14 和 11）** —— 第 4 幕丢弃的那条
`5:14` 就是这么来的。"眼前最便宜的边不一定给出最短的路"这件事，
在数组上的表现就是：`dist[v]` 会被反复下调，直到 `v` 定稿为止。
