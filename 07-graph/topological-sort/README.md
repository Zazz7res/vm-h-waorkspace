# 拓扑排序（topological sort）

## 一句话是什么

给一张**有向无环图**（DAG）吐出一个顶点序列，满足：**只要图里有边 `u → v`，`u` 就必须排在 `v` 前面**。

它排的不是「大小」，是「先后」。

## 为什么需要它

有些活天生有依赖：必须先学完《程序设计》才能选《数据结构》；必须先「编译」才能「链接」。
把这些依赖画成有向图（`A ──► B` 读作「A 做完了 B 才可以开始」），你要的答案就是：
**一个不违反任何一条依赖的执行顺序。**

排序算法（第 10 章那些）在这里完全没用 —— 顶点编号是随便起的，`0` 不比 `1` 「小」，
它们之间只有边才是真约束。所以这是另一类问题，得专门的算法。

它同时还是**判环**的免费赠品：

> **拓扑排序存在 ⇔ 图是 DAG（有向无环图）**

这句话在本节出现三遍都不过分。跑一遍拓扑排序，排不出全部顶点 = 图里有环。
包管理器、构建系统报「循环依赖」时用的就是这一招，并没有专门的找环算法。

## 图解：入度表就是整个算法的真相

`indeg[v]` = 还有几个人压着 v（v 有多少条入边）。规矩只有一条：**入度清零才能上场。**

```
   本节示例 DAG：边 = 4→0  4→1  5→0  5→2  2→3  3→1

        4 ──┬──────────► 0 ◄───────┬────── 5
            │                      │
            │                      │
            └──► 1 ◄─── 3 ──► 2 ───┘
                       （3→1）（2→3）

   顶点  出边（我做完解锁谁）  入度  出度
     0   （无）                 2     0     ← 被 4 和 5 压着
     1   （无）                 2     0     ← 被 4 和 3 压着
     2   3                     1     1     ← 被 5 压着
     3   1                     1     1     ← 被 2 压着
     4   0, 1                  0     2     ← 起点，谁都不要求它先做
     5   0, 2                  0     2     ← 起点，谁都不要求它先做

   ★ 入度为 0 的是 4 和 5，而编号最小的 0 反倒被两个人压着 —— 编号是随便起的，
     只有边才是真约束。这正是「拓扑排序」存在的理由。
   ★ 4 和 5 是两条互不相干的起点链（图不连通），所以「所有」入度 0 的点都得入队。
```

Kahn 算法跑这张图的每一步，真相全写在这两行里（`-` 表示已输出）：

```
   起点集：容器（FIFO 队列）：[ 4 5 ]
   顶点:0   1   2   3   4   5
   入度:2   2   1   1   0   0

   取出 4，解锁 4→0、4→1        → 入度:1   1   1   1   -   0   （新入队 0 个）
   取出 5，解锁 5→0、5→2（双双清零 ★ 都进容器）→ 入度:0   1   0   1   -   -
   取出 0，无出边                → 入度:-   1   0   1   -   -
   取出 2，解锁 2→3              → 入度:-   1   -   0   -   -
   取出 3，解锁 3→1              → 入度:-   0   -   -   -   -
   取出 1，无出边                → 入度:-   -   -   -   -   -
   容器空，结果长度 6 == 顶点数 6 → 无环
   拓扑序：4 5 0 2 3 1
```

## 逐操作拆解

### `topo_create(v)` / `topo_add_edge(g, from, to)` / `topo_free(g)`

图用**有向邻接表**存：`heads[i]` 是顶点 i 的**出边**链表，节点是 `ENode { int dest; struct ENode *next; }`。

- 为什么必须是**有向**：拓扑排序只对 DAG 有意义。一条无向边等于同时提了 `A→B` 和 `B→A`
  两个互相矛盾的约束 —— 立刻构成 2-环，所以**无向图谈不上拓扑排序**。
- 有向图一条边只挂 **1 个**节点（无向图要挂 2 个），所以链表节点总数 `== e`。
- 用**尾插**：邻居顺序 == 加边顺序，输出可复现，才能和本文贴的运行结果逐行核对。
- 本节的内存责任田只有一处：`topo_create` / `topo_graph_*` malloc，`topo_free` 全部还回去。

### `topo_kahn(g, fifo, verbose, order_out, stuck_out, stuck_len_out)` —— 方法 A

就是「**入度为 0 的 BFS**」。和第 07-graph/bfs 的骨架一字不差，只把资格条件换掉：

```
   BFS:                          拓扑（Kahn）:
   起点入队                       所有 indeg==0 的顶点入队   ← 注意是「所有」
   while 容器非空:                while 容器非空:
     u = 取出                      u = 取出，写进结果表
     for u 的邻居 v:                for u 的每条出边 u→v:
       if v 没访问过:                 indeg[v]--              ← u 这条「债」还清了
         标记 v，入队                 if indeg[v] == 0: 入队   ← 债还清才轮得到它
```

- 共同点：都是「**入队那一刻就把这个点定下来**」。
- 不同点：BFS 用「有没有被碰过」当资格，Kahn 用「入度有没有清零」当资格。
- 返回值 = 真正排出的顶点个数。`== g->v` 无环；`< g->v` **有环**，剩下的都卡在环里。
- 第二个参数 `fifo`：1 用队列、0 用栈。第 3 幕就是拿它做对照实验。

### 拓扑序不唯一（第 3 幕的实测）

算法只规定「入度清零才能上场」，**同时有几个点入度为 0 时先取谁，算法完全没规定** ——
这份自由留给了容器。所以同一张图：

```
   FIFO（队列）→ 4 5 0 2 3 1
   LIFO（栈）  → 5 2 3 4 1 0
```

两份**不一样**，但**都合法**。考试题问「拓扑序列唯一吗」，答案就在此：**不唯一**，
除非每一时刻恰好只有一个入度为 0 的点（那时这张 DAG 其实就是一条链）。

### 判环之二：卡住的人分两种（第 4 幕）

带环图 `0→1 1→2 2→3 3→1 3→4 0→4 5→6`（环是 `1→2→3→1`），Kahn 只排出 `0 5 6` 三个，
卡住 `1 2 3 4` 四个。⚠ **这四项并不都在环上**：

- **坐在环上的**：1、2、3 —— 各自被环里那条边永久占住 1 点入度，永远等不到 0。
- **只是被连累的**：4 —— 它自己不在环上，但它的前驱 3 卡住了（所以特意把 4 设计成
  3 和 0 两个前驱，让 0 排出后它的入度只从 2 降到 1，停在「差一个」的状态）。

`topo_report_stuck()` 把两类分开列出。这个区分不是洁癖：**误报成环就会拆错地方** ——
你去拆 4 那条边，环照样存在。

### 方法 B：`topo_dfs_postorder` + `topo_reverse` —— DFS 后序逆序

前序是「进门就记」，**后序是「收摊才记」**。收摊意味着我的所有下游都已经收摊完毕，
所以后序里我比所有下游**晚**出现；而拓扑序要求我比所有下游**早**出现。
两者正好相反 ⇒ **后序表整个反转就是拓扑序**。

```
  后序表（收摊顺序）：0 1 3 2 4 5
    反转后 = 拓扑序：5 4 2 3 1 0   ← 合法性验收：合法 ✓
```

第 5 幕还当场验了反面：**忘了反转**直接把后序表当拓扑序 → `topo_order_is_valid` 判「违规 ✗」。
这一步绝不能省。

DFS 版有一个必须记住的细节：图可能不连通，所以外层要
「对所有还没访问过的顶点各起一次 DFS」，只从 0 出发会漏掉整个分量。

### 判环之三：`topo_dfs_color` 三色标记

白 = 还没碰过；**灰 = 正在我的调用栈上**（邻居还没走完）；黑 = 收摊了。

- 某条边指向**灰色**顶点 = 「绕回了还在栈上的自己人」= **回边（back edge）**= 有环。
- 指向**黑色**顶点是安全的：那是处理完的旁支，不构成环。

本节的带环图里，DFS 走到 `3` 时发现出边 `3→1` 指向灰色的 1，当场判定有环 —— 打印里能看到栈的纵深。

### `topo_order_is_valid(g, order, len)` —— 我怎么知道自己写对了

**不要**去比较两份序列是否逐位相同（那只会因为容器选得不同而误报）。
正确判据是：**逐条边检查「前驱的位置 < 后继的位置」**，一次 O(V+E)，通吃所有合法答案。
第 9 幕拿一个「看着挺像」但把 `1` 排在 `3` 前面的序列，让这只手当场抓住它。

### 拓扑排序 + 一趟 DP = 分层 / 关键路径（第 8 幕）

有了拓扑序，就能安全地做一件否则没法做对的事：**按拓扑序遍历，给每个顶点算 depth**
（`depth[v] = max(depth[所有前驱]) + 1`）。必须按拓扑序走，乱序一定算错 —— 这是这个套路的命门。

同一层的顶点之间**没有依赖**，所以可以并行；层数就是最短总耗时：

```
   第 0 层：下载依赖
   第 1 层：生成代码
   第 2 层：编译核心 编译插件     ← 这俩互不依赖，能同时开跑
   第 3 层：链接
   第 4 层：跑测试
   第 5 层：打包
```

从第 0 层到第 5 层那条最长的链叫**关键路径**：就算给你无限个 CPU，总时间也不可能短过它。

## 复杂度

| 操作 | 邻接表 | 说明 |
|---|---|---|
| Kahn | **O(V + E)** | 每个顶点出队一次，每条边被看一次 |
| DFS 后序 / 三色 | **O(V + E)** | 同上 |
| `topo_order_is_valid` 验收 | O(V + E) | 逐条边查位置 |
| 空间 | O(V) | 入度表 + 容器 + 结果表 |

矩阵版要 O(V²)，大图上必须用邻接表 —— 所以本节特意用邻接表写，好让这张表不是空口白话。

## 常见的坑

1. **只把一个起点入队。** 图常常不连通（有好几条互不相干的起点链），必须把**所有** `indeg == 0`
   的顶点全部入队，否则整片分量漏排。和第 07-graph/bfs「只从 0 出发」是同一种病。
2. **`indeg` 被就地改掉了，第二次跑就错。** Kahn 是把入度减到 0 来推进的，跑完入度表已经全变。
   想再跑一次必须**重算入度**（本节的 `topo_kahn` 每次开头都调 `topo_indeg` 现算，就是为了这个）。
3. **以为拓扑序唯一，于是拿「和标准答案逐位比较」来判对错。** LIFO 也是一份正确答案，
   比位置会误报。判据只有一个：逐条边检查前驱位置 < 后继位置。
4. **DFS 版忘了反转。** 后序是「我比所有下游晚被记录」，拓扑序要的正好相反。
   第 5 幕把这个错误直接验给你看了：不反转 → 违规。
5. **DFS 后序版判环要单独加三色。** 只用 `visited` 布尔标记的 DFS 后序法**发现不了环**
   （有环时它会静默漏点）。要判环就用 `topo_dfs_color`：指向灰色顶点才是回边。
6. **把「没排出的点」全当成环上的点。** 被环连累的下游也在「没排出」里 —— 第 4 幕的 4 号就是。
   照着这份名单去拆边会拆错。
7. **拿拓扑排序去排无向图。** 无向边 = 两条方向相反的边 = 立刻成环，任何无向图都排不出拓扑序。
8. **改 depth 时乱序遍历。** 第 8 幕的分层 DP **必须按拓扑序**走，否则某个点的深度还是旧的，
   算出来偏小，层数就骗了你。

## 自检问题

1. 一张 DAG 有 6 个顶点，Kahn 跑完只输出了 4 个 —— 结论是什么？另外 2 个是什么关系？
2. 为什么 Kahn 必须一开始把**所有**入度为 0 的点入队，而 BFS 只需要一个起点？
3. 同一张图，队列版给出 `4 5 0 2 3 1`，栈版给出 `5 2 3 4 1 0`。谁错了？怎么证明？
4. DFS 后序表和拓扑序只差一步，是哪一步？为什么？
5. 三色 DFS 里，指向**黑色**顶点的边为什么不算环？指向灰色的为什么算？
6. 「拓扑排序存在 ⇔ 图是 DAG」，把这句话用 Kahn 的行为解释一遍。
7. 要算「并行构建的最短总时间」，光有拓扑序够吗？还差哪一步？（提示：第 8 幕）
