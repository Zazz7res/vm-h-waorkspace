# 广度优先搜索 BFS (Breadth-First Search)

> 用**队列**一圈一圈往外扩的遍历。
> 它真正值钱的地方不是"能遍历图"，而是：**在无权图里，它顺手就把最短路算出来了。**

---

## 一句话是什么

**从起点出发，先把"1 步能到的"全走完，再走"2 步能到的"，再走"3 步能到的"……**
像水波纹、像喊一嗓子传开的回声、像传染病传播：同一圈的人同时被感染。

实现上只有一句口诀：
```
出队一个点 → 把它所有"没见过的邻居"标记 + 记距离 + 排到队尾
```
队列的先进先出保证了"近的先处理完，远的才轮到" —— 这就是 BFS 的全部。

---

## 为什么需要它

**不用它的话**，你只能靠 DFS（或者瞎走）来访问图。DFS 的画面是"一条路走到黑再回头"，
它完全不管远近：

```
  图：  0 ─ 1 ─ 2 ─ 3 ...        同时 0 ─ 9        （9 是 0 的直接邻居）

  DFS 从 0 出发：0 → 1 → 2 → 3 → ... 一头扎进深巷，绕了 5 步才回来
  BFS 从 0 出发：第 1 层就把 1 和 9 一起收掉

  如果这时有人问："0 到 9 最少几步？"
  DFS 给你的答案是"我第一条路撞到的那条，5 步" —— 而且它不知道自己撞到的不是最短的。
  BFS 给你的答案是"1 步" —— 而且它**有资格**这么说，因为它就是按步数排序访问的。
```

| 你想干的事 | 不用 BFS | 用 BFS |
|---|---|---|
| 无权图两点最少几步 | 只能 DFS 全枚举所有路径再挑最短，指数级 | **dist[] 直接就是答案**，O(V²)/O(V+E) |
| 求"从起点到所有点的最短路" | 每对点单独搜一次 | 一轮 BFS 全部搞定 |
| 迷宫最少转弯/最少步数 | 写不出来 | 就是 BFS，模板题 |
| 社交网络"几度分隔"、局域网跳数 | 说不清 | 就是它的 dist[] |
| 逐层扩散（病毒传播模拟、地图洪水填充） | 需要额外代码 | 出队顺序天然分层 |

DFS 也能遍历图（下一节就写），但**"最短"这两个字只有 BFS 给得起**。
代价是必须用队列，多 O(V) 空间。

## 内存布局图解

### 共用示例图 G（和邻接矩阵、邻接表那两节是**同一张图**）

```
  无向图 G：8 个顶点 0..7，7 条边，故意不连通
  分量一：0-1, 1-2, 2-0, 2-3      分量二：4-5, 5-6, 6-4      孤立点：7

        0 ───── 1                     4 ───── 5
         \     / \                     \     /
          \   /   \                     \   /
           2 ──────                     6          7 ← 孤零零
            \
             3

  本节容器还是邻接矩阵（叶子目录自包含，不想把邻接表那套 malloc/free 再抄一遍），
  所以"扫 u 的邻居" = "扫矩阵第 u 行"，顺序必然是 j = 0,1,2,... 升序 → 输出可复现。
```

### BFS 的"波纹"：一层一层往外扩（从 0 出发）

```
   第 0 层        第 1 层         第 2 层
   ┌──────┐      ┌──────┐       ┌──────┐
   │  0   │ ───► │  1   │       │      │
   │dist=0│      ├──────┤       │  3   │
   └──┬───┘      │  2   │ ───►  │dist=2│
      │          │dist=1│       └──────┘
      └────────► └──────┘

   第 3、4、5、6、7 号：不管多少层都到不了 → dist 保持 -1（它们在别的连通分量里）

  同一层内部谁先谁后 = 邻居扫描顺序（这里是编号升序）。
  层的边界是"真"的：BFS 处理完第 d 层的最后一个点，才会轮到第 d+1 层的第一个点。
  这一条性质就是"最短路"的全部来源。
```

### 每一步的数据结构：队列 + 三张表

```
  时刻：刚出队 2，把 3 收进队列之后

  队列（先进先出，队头在左）
  ┌───┬───┐
  │ 3 │   │  head=2, tail=3
  └───┴───┘
   ▲
   └ 下一个出队的是 3（它是目前队列里"最老"的）

  visited[]  ┌───┬───┬───┬───┬───┬───┬───┬───┐
             │ 1 │ 1 │ 1 │ 1 │ 0 │ 0 │ 0 │ 0 │   ← 1 = 已发现（不再接受第二次发现）
             └───┴───┴───┴───┴───┴───┴───┴───┘
  dist[]     │ 0 │ 1 │ 1 │ 2 │-1 │-1 │-1 │-1 │   ← 到起点的最少步数；-1 = 还没轮到/到不了
  parent[]   │-1 │ 0 │ 0 │ 2 │-1 │-1 │-1 │-1 │   ← "我是被谁发现的"

  parent[] 画出来就是一棵树（BFS 树 / 最短路树）：

        0
       ╱ ╲
      1   2
          │
          3

  三张表各司其职：
    visited —— 挡重复入队（正确性 + 性能）
    dist    —— 答案本体（无权最短路长度）
    parent  —— 路径本体：从任意点顺着 parent 回溯到起点，倒过来就是具体走法
```

### 队列在内存里：一个只往前走、不回绕的数组

```
  typedef struct { int data[9]; int head; int tail; } IntQueue;

  进队：data[tail] = x; tail++;      ← 永远往高地址写
  出队：x = data[head]; head++;      ← 永远往高地址读，空出来的格子**不回收**

  ┌───┬───┬───┬───┬───┬───┬───┬───┬───┐
  │ 0 │ 1 │ 2 │ 3 │   │   │   │   │   │
  └───┴───┴───┴───┴───┴───┴───┴───┴───┘
    ▲               ▲
    head            tail              head==tail 即空；tail==9 即"写满"

  ⚠ 第 04 章 `array-queue/` 说过这个朴素写法会"假满"（head 前面的空间浪费掉），
    正解是循环队列（取模绕回）。那 BFS 这里为什么敢用朴素版？

  ★ 因为**一个顶点最多进队一次**（入队的同时就打 visited 标记，
    后来想把同一点推进来的边全被拦掉了）。
    于是整场 BFS 的进队总次数 ≤ V，tail 单调递增也永远不超过 V。数组开 V+1 就绝对够。

    一般化成一句话：**证明了一个操作最多发生 N 次，就能用"只往前走"的简单结构，
    把环形缓冲那套复杂度省掉。**
    反过来警告：如果哪天你把打标记改成"出队时才打"，这个前提立刻崩，
    队列长度能冲到 O(E)，朴素数组就会真溢出。
```

## 核心操作逐个拆解

### 1. `bfs_graph_sample(g)` —— 造出要遍历的图（gbfs.c:104）

**干什么**：把共用的示例图 G 填进邻接矩阵。
**为什么这么写**：无向图加边仍要对称写 `edge[a][b] = edge[b][a] = 1`（漏一格 = 图断一半，
那节的老规矩，见 `adjacency-matrix/README.md`）。栈上的 int 数组必须逐格清 0，
否则垃圾值会被当成"有条边"。

---

### 2. 队列五件套 `q_init / q_is_empty / q_push / q_pop / q_dump`（gbfs.c:45~80）

**干什么**：给 BFS 提供"先进先出"。
**一步步**：见上面那张队列内存图。
**边界情况 / 为什么这么写**：
- `q_pop` 空队列时返回 0 且不动 `*out`，调用方靠 `q_is_empty` 保证不出错，
  两层防护而不是只靠一层。
- `q_push` 满了返回 0（**不越界写**）。注释里写清了"真走到这里说明前提被破坏了" ——
  保留这个检查不是为了功能，是为了**让 bug 当场暴露**。
- `q_dump` 是把队列打印出来的函数。BFS 的教学价值一半靠它：
  能看见"队列里此刻排着谁"，就理解了"为什么会分层"。
- 数组大小写成 `BFS_MAX_V + 1` 而不是 `BFS_MAX_V`：留一格余量，
  免得"V 个点全进队 + tail 走到 V"时刚好踩在边界上纠结。

---

### 3. `bfs_run(g, start, dist, parent, order, &len, verbose)` —— 一轮 BFS（gbfs.c:223）

**干什么**：从 start 出发扩到扩不动为止，填三张表；`verbose` 非 0 就一步一打。

**骨架（背下来这 8 行）**：
```
把 start 入队，立刻标记 visited，dist[start] = 0
while 队列非空:
    u = 出队
    把 u 记进 order
    for u 的每个邻居 w:                 ← 矩阵版：扫第 u 行，j 升序
        if w 没被访问过:
            visited[w] = 1              ← ★ 在入队这一刻标记，不是出队时
            parent[w] = u               ← 记下"是谁发现了你"
            dist[w] = dist[u] + 1       ← ★ 最短路性质的落点
            w 入队
```

**为什么 `dist` 就是最短距离**（本节核心，务必想通）：
1. 队列 FIFO ⇒ 入队顺序的 dist 值**单调不减**（新点只可能是 `dist[u]` 同层或 `dist[u]+1` 下一层，
   绝不会比队头更小）。
2. 所以所有"距离 d"的点必然在所有"距离 d+1"的点**之前**处理完 ⇒ **不会跳层**。
3. 反证：假设某点 v 第一次被到达时是 d 步，但其实存在 d' < d 的更短路。
   那条路上 v 的前驱 u 在第 d'-1 步就被到达 ⇒ 按第 2 条，u 早于任何第 d 层的点被处理 ⇒
   处理 u 时就会把 v 收进来 ⇒ v 应该在第 d' 步到达，矛盾。
4. 所以**第一次到达一定最短**。后面再从别的边撞上它，只会是同样长或更远 ⇒
   "已访问就不再访问"不是偷懒，而是**正确性的来源**：扔掉重复发现毫无损失。

**三个设计点，每一个都有对应 bug**：
| 设计 | 做错的后果 |
|---|---|
| 入队即标记 | 出队才标记 ⇒ 同点重复入队 ⇒ order 有重复、队列可能溢出、dist/parent 被后来的路覆盖，最短性丢掉 |
| `dist[w] = dist[u] + 1` | 写成 `dist[w] = dist[w] + 1` 或忘记 ⇒ 距离全错 |
| `parent[w] = u` | 不给 parent ⇒ 只有"几步到"没有"怎么走"，无法回溯路径 |

**边界情况**：
- `start` 越界：打印错误、`*order_len_out = 0`、返回 0，绝不越界读内存。
- `start` 是孤立点（7 号）：入队→出队→扫一整行全 0→队列空，本轮只访问 1 个点。
  **这不是 bug**，这就是"该连通分量只有一个点"。
- 三张表**函数内部全部重写**（含填 -1），调用者不用自己预置 ——
  少一个"忘了初始化 parent 结果读到垃圾"的坑。
- 图不连通时，其他分量里的点 dist 保持 -1 ⇒ 需要 `bfs_run_all` 补齐。

---

### 4. `bfs_run_all(...)` —— 对每个未访问点都起一轮（gbfs.c:372）

**干什么**：外层依次看每个顶点，只要它还没被访问过，就以它为起点再起一轮 BFS。
**返回值**：起了几轮 == 有几个连通分量。本图 = 3（`{0,1,2,3}`、`{4,5,6}`、`{7}`）。

**为什么必须有它**（本节最重要的认知升级）：
单次 `bfs_run` 只覆盖 start 所在的那个连通分量。
从 0 出发只碰到 `{0,1,2,3}`；如果你以为"跑完一次 BFS 就遍历了全图"，
4、5、6、7 被你整片漏掉，而**程序不会报任何错**：队列正常清空、返回值正常。
"结果少一坨但毫无异常"是最难发现的一类 bug。

所以凡是要处理整张图的算法（连通分量、判环、拓扑排序、最小生成树……），
骨架都必须长这样，记住这个形状：
```
for 每个顶点 u:
    if u 没被访问:
        从 u 起一次遍历          ← 这一轮覆盖一个新的连通分量
```

**为什么这里没直接复用 `bfs_run`？**
因为 `visited / dist / parent` 三张表要**跨轮保留**，而 `bfs_run` 每次进来都把表重置，
会抹掉之前几轮的结果。所以这里把循环体内联了一遍。
教学代码宁可有 30 行相似逻辑，也不要为了"复用"把语义绕弯。
（工程做法：把 `bfs_run` 改成接受一张**外部传入的** visited 表，
或者每轮只返回自己那批点、由调用者合并。诚实标注：**这是本节的取舍，不是最佳实践。**）

**⚠ 注意跑完之后 `dist` 的含义变了**：它不再是"到全局起点的距离"，
而是"到**本轮那个起点**的距离"（每轮自己的起点 dist=0）。
`parent` 里会出现多个 -1（每轮起点各一个），所以**判断可达性要看 dist 而不是只看 parent**。
"复用同一张表"必然带来语义漂移，这是要自己盯住的地方。

---

### 5. `bfs_print_result(...)` —— 把结果摊开 + 回溯路径（gbfs.c:484）

**干什么**：打印访问顺序、`dist`/`parent` 两张表、可达点数，
再顺着 `parent` 回溯出起点到每个可达点的**具体最短路径**。

**回溯怎么做的**：
```
从目标 u 开始：path[len++] = u; u = parent[u]; 一直走到 parent == -1
于是 path 里是 [目标 ... 起点]（反的）→ 再从 len-1 倒着打回来
```
为什么要在数组里倒一手而不是直接打印：**parent 只能从孩子找爹，不能从爹找孩子**，
所以要先把整条链收集起来再反向输出。这个"用数组当下标栈"的套路
就是第 03 章"用数组模拟栈"的同一个思路。

**边界情况**：不可达的点（dist=-1）跳过，不去回溯（否则 parent 也是 -1，会写出垃圾）。
`samples/` 里"起点是孤立点 7"这一轮，可达点只有自己，会打印一行提示而不是空表。

## 复杂度表

V = 顶点数，E = 边数。

| | 本节矩阵版 BFS | 邻接表版 BFS | DFS（矩阵 / 邻接表） |
|---|---|---|---|
| 时间 | **O(V²)** | **O(V+E)** | O(V²) / O(V+E) |
| 额外空间 | O(V)（visited + dist + parent + 队列） | O(V+E) 含图本身 | O(V) 递归栈 / 显式栈 |
| 单点判边 | O(1) | O(度) | — |
| 枚举邻居 | O(V) 扫整行 | **O(度)** | O(V) / O(度) |
| 求无权最短路 | ✅ | ✅ | ❌ 顺序不对，不保证最短 |
| 递归深度风险 | 无（非递归） | 无 | 有（链状图会 V 层深，可能爆栈） |

**矩阵版为什么是 O(V²)**：每个顶点出队一次（V 次），每次扫**一整行** V 格 → V²。
换成邻接表，出队 V 次、每次只扫它那条链，链长总和 = 2E → **O(V+E)**。
V=8 时 64 vs 22 无所谓；V=10 万、E=20 万时是 **100 亿 vs 30 万**，必须换。
所以本节的 O(V²) 是**教学便利**，不是推荐做法，README「什么时候别用」里写清楚了。

**队列的空间最坏是多少**：第 d 层可能有 O(V) 个点，所以队列 O(V)。
（比如星型图，起点一入队就把 V-1 个叶子全推进队列。）

## 常见的坑

1. **visited 标记打在"出队时"而不是"入队时"**（头号坑，而且很难察觉）。
   ```
   错误：q_pop 之后才 if (visited[u]) continue; visited[u]=1;
   ```
   后果链：一个点被多个邻居同时"发现" ⇒ 队列里出现重复顶点 ⇒
   ① `order` 有重复 ② 进队次数从 O(V) 涨到 O(E)，本节这种朴素数组会真溢出
   ③ `dist`/`parent` 被后到的、更长的路覆盖 ⇒ **最短性丢掉**。
   正确写法永远是"入队那一刻就标记"，一进队就没人能再进它。

2. **忘了打 visited，直接遍历**。
   无向图里 0 的邻居有 1、1 的邻居有 0 ⇒ 0 和 1 互相推进队列，**死循环**。
   图不是树，**没有"父亲"帮你挡住回头路**（树才有），所以 visited 是必需品。
   这也是图和树在遍历代码上最大的差别。

3. **只起一次 BFS 就以为遍历完了全图**。
   本节的第 4 幕专门演示：从 0 出发只能覆盖 `{0,1,2,3}`，
   而程序**不会报错**。全图处理必须是两层骨架（外层扫每个未访问点）。
   自检法：`order_len == g->v`？不等就说明漏了。

4. **把 BFS 当成"能算带权最短路"**。
   BFS 数的是"几步"，不是"多远"：
   ```
   A ──100──► C            A ──1──► B ──1──► C
   ```
   BFS 会选 1 步的 A→C（权 100），而真正最短是 2 步的 A→B→C（权 2）。
   **只有所有边权相同（=无权）时 BFS 才给最短路。** 带权要用 dijkstra / bellman-ford / floyd。

5. **`dist` 初值给 0 而不是 -1**。
   0 是"起点自己"的合法距离，拿 0 当"没访问过"就和起点撞车。
   本节用 -1 当哨兵（道理同邻接矩阵那节讲的"哨兵必须是业务上不会出现的值"）。

6. **回溯路径忘了倒序**。
   `parent` 只能从孩子找爹，顺着走出来的顺序是"目标 → 起点"，
   必须收集到数组里再倒着打印才是"起点 → 目标"。

7. **`bfs_run_all` 跑完后拿 `parent[u] == -1` 判断"不可达"**。
   每一轮的起点 parent 都是 -1，但它显然可达（到自己 0 步）。
   跑完多轮之后，**可达性看 `dist[u] == -1`，别看 parent** ——
   这就是运行结果里那段"语义漂移"的警告。

8. **`q_dump` 打印时把 head 当成"队尾"**。
   head 在左是"最先出队"，tail 在右是"最后进队"。方向搞反会让你对
   "为什么这样分层"产生完全错误的直觉 —— 打印队列时一定标清哪端是头。

## 什么时候用它 / 什么时候别用

**该用 BFS：**
- **无权图 / 边权全相同的最短路**：迷宫最少步、最少操作数、"几度分隔"、网络跳数。
- **需要"离起点多远"这个信息**：分层、按距离圈出范围（"找 2 步以内能到的所有人"）。
- **要最短路径的具体走法**：BFS + `parent[]` 回溯。
- **状态空间搜索**：八数码、字谜变换、魔方 —— 把每个状态当顶点、一次变换当边，
  天然无权，BFS 直接给"最少几步"。
- **网格洪水填充 / 连通块大小**：二维数组上的 BFS 比 DFS 不爆栈（见下）。
- **需要"同一层"的概念**：病毒传播第几天感染谁、按层输出二叉树（层序遍历就是 BFS）。

**别用 BFS：**
- **边有权值**：BFS 完全失效，换 dijkstra（非负权）/ bellman-ford（有负权）/ floyd（多源）。
- **只需要"可达性 / 有没有路"**：DFS 代码更短（递归三行），而且不用维护队列。
- **要探索到底、找一条可行解就行**（数独、走迷宫的所有路径、拓扑排序内部）：
  DFS 更自然，剪枝也只在 DFS 上做。
- **图特别宽**（一层就有几十万个点）：BFS 队列要吃 O(V) 内存，
  而且同一层的所有点都得同时存住；DFS 只需要 O(路径长度)。
- **大图 + 用邻接矩阵**：O(V²) 扫行会把时间全花在跳过 0 上。
  **本节用矩阵是为了教学自包含，真实大图请换邻接表 → O(V+E)。**

## 自检问题

1. 把 `if (visited[w])` 的判断和 `visited[w] = 1` 的赋值**分开**：
   判断放在入队前（正确），赋值却放到出队时才做，会怎样？
   **答**：错的。同一个点可能在被出队之前，被多个已在处理的邻居各自看到一次，
   因为它们检查时该点还没标记 ⇒ 重复入队。后果见坑 1（order 重复、队列暴涨、最短性丢失）。
   规则和代码要**绑在一起**：发现即标记，标记即入队。

2. 从 0 出发的 BFS，`dist[2]=1`；但 `0 → 1 → 2` 明明是 2 步。为什么答案还是 1？
   **答**：因为 `0 → 2` 本身就有一条直连边（我们的图里 0-2 是成环那条边），
   所以 2 在第 1 层就被 0 直接发现了。BFS 报的是**最少**步数，
   不是"DFS 第一条撞到的路"。这也说明为什么"第二次碰到 2（经 1，2 步）"要扔掉：
   它不比第一次更优，扔掉毫无损失。

3. 本节为什么能用"只往前走不回绕"的朴素数组队列，不需要循环队列？
   **答**：因为证明了"一个顶点最多进队一次"（入队即标记），
   所以进队总次数 ≤ V，`tail` 单调递增也超不过 V，数组开到 V+1 就绝对够用。
   前提是"入队即标记"。哪天改成出队时标记，进队次数能到 O(E)，朴素数组立刻溢出 ——
   所以那个防御性的"满了返回 0"的检查要留着，它能让这个隐藏依赖被破坏时当场暴露。

4. BFS 能算"无权图最短路"，那它能算"最短路径有几条"吗？
   **答**：能，只要多维护一个 `ways[u]`：发现新点时 `ways[w] = ways[u]`；
   再次遇到且 `dist[w] == dist[u]+1`（说明是**同样短**的另一条路）时
   `ways[w] += ways[u]`。注意必须"仍然在下一层"才累加，
   这就是"不更优就扔掉"要改成"同样优就都记下来"。
   —— 这道题说明 BFS 的价值不止是"一个距离"，它给的是一整套"按层推进"的框架。

5. 为什么本节代码是 O(V²)，而教材都说 BFS 是 O(V+E)？
   **答**：O(V+E) 的前提是用**邻接表**。本节用邻接矩阵，
   "枚举 u 的邻居"要扫一整行 V 格（其中大多数是 0，白扫），
   所以是 O(V²)。V=8 时差别看不出来；V=10 万、E=20 万时是
   100 亿步 vs 30 万步。真实工程必须换邻接表；这里换是为了让
   叶子目录自包含、且邻居顺序天生固定好核对。**复杂度要连着表示法一起报，
   只说算法不说容器的复杂度表都是耍流氓。**
