# Kruskal 最小生成树 + 并查集（07-graph/kruskal-mst）

> 一句话定位：把边按权重从小到大排一遍，能收就收 —— 判断"能不能收"这件事，交给本目录
> 顺手写的那份**带路径压缩 + 按秩合并的并查集**。这一节是"图算法"和"并查集"两条线的交汇点。

---

## 一句话是什么

**Kruskal**：把所有边按权重**从小到大**排序，然后从最便宜的开始一条条试 ——
"这条边的两个端点现在连通了吗？"
没连通就**收下**（顺手把它们并成一个集合），已经连通就**跳过**（收了就成环）。
收满 `V-1` 条就得到**最小生成树（MST）**。

三个词必须钉牢：

| 名词 | 含义 |
|---|---|
| 生成树 | 挑出 `V-1` 条边，覆盖**所有**顶点且**不成环**（= 把全图连起来且一条边都不多余） |
| 最小生成树 | 所有生成树里**边权总和最小**的那一棵 |
| 最小生成森林 | 图不连通时，每个连通分量各得一棵 MST，合起来叫森林 |

和最短路的区别（本仓库反复强调）：**MST 不管两点之间绕了多远，只管总花费最省。**
详细对照在 `07-graph/prim-mst/README.md` 第 5 幕，本目录的运行结果里也顺手复算了一次。

---

## 为什么需要它

需求场景换了：**"给 6 个村子铺光缆，任意两村都要能通，造价最低。"**

最短路算法帮不上忙 —— 它们优化的是"A 到 B 这一段最短"，而这里要的是"全网连通且总花费最低"。
这正是 MST。

那已经有 Prim 了，为什么还要 Kruskal？

1. **它只碰边表。** Prim（朴素版）要邻接矩阵，`V²` 个格子；Kruskal 只要一个边的数组。
   图很稀疏（`E` 和 `V` 同量级）时，Kruskal 的 `O(E log E)` 远小于 `O(V²)`。
2. **判环这件事太优雅了。** "加一条边会不会成环" 等价于 "这两个端点是不是已经连通了"，
   而在一片森林里，"已连通" 就是 `find(u) == find(v)`。**一行代码**替代了本来要 DFS 一遍的判环。
   这也是并查集最经典的用武之地。
3. **它天然适合"边是一条条来的"场景。** 比如流式建图、或者要回答"至少加到多重量的边全图才连通"
   （= 最后收下的那条边的权重），Kruskal 的顺序处理直接给答案，Prim 不行。
4. **顺便学并查集。** 并查集本身是第 4 高频的数据结构（连通性、LCA、Kruskal、并查集离线题），
   借这一节把它写一遍最划算。

## 内存布局图解

### 1. 图：一个边表，没有别的

```c
typedef struct { int u, v, w; } WEdge;
typedef struct { int n; int m; WEdge e[MAX_E]; } Graph;
```

```
  g.n = 6, g.m = 9

  g.e[]:  [ {0,1,7} {0,2,9} {0,5,14} {1,2,10} {1,3,15} {2,3,11} {2,5,2} {3,4,6} {4,5,9} ]
   下标       0        1        2         3         4         5        6       7        8
```

注意：无向边在这里**只存一条**（不像邻接矩阵要对称写两格）。因为并查集判的是"两端是否已连通"，
和方向无关。这一条边 = 2 个 int + 1 个 int = 12 字节，9 条边 108 字节，比 `6×6` 矩阵还小。

### 2. 并查集：两个长度 n 的数组

```c
typedef struct { int fa[MAX_V]; int rnk[MAX_V]; int n; } DSU;
```

```
  初始（n = 6，每个点自己一堆）：
  下标 x ：    0     1     2     3     4     5
  fa[x] ： [   0,    1,    2,    3,    4,    5  ]     ← fa[x] == x ⇒ x 就是根（代表元）
  rnk[x]： [   0,    0,    0,    0,    0,    0  ]

  union(0,2) 之后（把 2 挂到 0 下面）：
  fa[x] ： [   0,    1,    0,    3,    4,    5  ]     ← 2 的父亲变成 0
  rnk[x]： [   0,    0,    0,    0,    0,    0  ]     ← 两棵秩都是 0，挂完高度没涨

  逻辑上看是一棵"树"，但内存里【只有一个 fa 数组】，没有任何孩子链表：
        0
       / \      ← 这就是 fa[1]=0, fa[2]=0 的含义
      1   2
```

"谁是一家人" = "顺着 fa 往上爬，爬到同一个根"。这就是全部。

### 3. 运行到一半的并查集（真实输出里的第 3 轮）

收下了 `2-5`、`3-4`、`0-1` 三条边之后：

```
  fa[]  :    0    0    0    3    4    0     ← 逻辑上有三堆：根 0（含 1,2,5）、根 3（含 4）、还有谁？
  rnk[] :    1    0    1    1    0    0
  ⇒ find(5) = 0，find(2) = 0 ⇒ 2、5 同堆（它们确实被边 2-5 连过）
  ⇒ find(4) = 3，find(5) = 0 ⇒ 4、5 不同堆 ⇒ 边 4-5 收下不成环 ★ 这就是算法的下一步
```

## 核心操作逐个拆解

### 操作 1：`dsu_init` —— 每个点自己成一堆

```c
for (i = 0; i < n; i++) { d->fa[i] = i; d->rnk[i] = 0; }
```

`fa[i] = i` 是"我是我自己的代表"。别写成 `-1`，那样 find 的循环条件要多一个判断，没有好处。

### 操作 2：`dsu_find` —— 先爬到店，再拆掉绕路（路径压缩）

```c
int dsu_find(DSU *d, int x)
{
    int root = x;
    while (d->fa[root] != root) root = d->fa[root];   /* 第一段：爬到根 */

    int cur = x;
    while (d->fa[cur] != cur) {                        /* 第二段：路上全挂到根上 */
        int next = d->fa[cur];
        d->fa[cur] = root;
        cur = next;
    }
    return root;
}
```

图解一次 `find(0)`，起点是一张链 `0→1→2→3→4`：

```
  压缩前   fa: 0→1→2→3→4(根)              find(0) 要爬 4 跳
           第一段循环：root = 1 → 2 → 3 → 4，fa[4]==4 停 ⇒ 根 = 4

  第二段（关键）：cur = 0 开始，一路上把 fa 改成 4
           cur=0: next=1, fa[0]=4, cur=1
           cur=1: next=2, fa[1]=4, cur=2
           cur=2: next=3, fa[2]=4, cur=3
           cur=3: next=4, fa[3]=4, cur=4 → fa[4]==4 停

  压缩后   fa: 0→4, 1→4, 2→4, 3→4, 4 是根  ⇒ 以后谁再问都是 1 跳
```

为什么要写两段循环而不是常见的递归一行版
（`return fa[x]==x ? x : fa[x]=find(fa[x]);`）？
递归版把压缩藏在回溯里，看不出"到底改了哪些点"；两段循环可以一行行指给你看，
而且链特别长时不会爆栈。两种写法效果完全一样。

### 操作 3：`dsu_union` —— 矮树挂到高树下面（按秩合并）

```c
int dsu_union(DSU *d, int a, int b)
{
    int ra = dsu_find(d, a), rb = dsu_find(d, b);
    if (ra == rb) return 0;                  /* ★ 已经是一家人 —— Kruskal 里这就是"会成环" */
    if (d->rnk[ra] < d->rnk[rb])      d->fa[ra] = rb;      /* 矮的挂到高的下面，高度不涨 */
    else if (d->rnk[ra] > d->rnk[rb]) d->fa[rb] = ra;
    else { d->fa[rb] = ra; d->rnk[ra]++; }   /* 一样高：只能涨 1 */
    return 1;
}
```

**为什么"秩"要写成高度上界**：合并时只有两棵**同秩**的树并起来，新树才会长高。
所以 `rnk` 最大也就是 `log2(n)`，`n = 10^6` 时它不超过 20 —— 一个 int 数组绰绰有余。
（严格讲 `rnk` 是"高度的上界"而不是"当前真实高度"，因为路径压缩会削矮这棵树，但 `rnk` 不回退。
这不影响正确性，教科书统一这么叫，本仓库也沿用。）

**`dsu_union` 的返回值就是 Kruskal 的判据**：返回 0 = 白并 = "这条边不能收"。

### 操作 4：手写插入排序（为什么不能用 qsort）

`qsort` 的原型是：

```c
void qsort(void *base, size_t n, size_t sz, int (*cmp)(const void *, const void *));
```

它要你交出一个**函数指针**当比较器，还得配合 `void*` 强转 —— 本项目三条硬约定
（只用 int、不用 `void*`、不用函数指针）一次违反两条半。所以只能手写。

```c
void insertion_sort_edges(WEdge a[], int n)
{
    for (int i = 1; i < n; i++) {
        WEdge key = a[i];                       /* 手里这张新牌 */
        int j = i - 1;
        while (j >= 0 && a[j].w > key.w) {      /* 注意是 >，不是 >= —— 稳定的来源 */
            a[j + 1] = a[j];                    /* 比 key 大的统统往后挪一格 */
            j--;
        }
        a[j + 1] = key;                         /* 插到最后一个"不比它大"的边后面 */
    }
}
```

```
  [ {0,1,7} {0,2,9} {2,5,2} 3-4(6) ]
  i=1: key=0-2(9)，左边 0-1(7) 不比它大 ⇒ 原地不动
  i=2: key=2-5(2)，0-2(9)、0-1(7) 依次后挪 ⇒ 插到最前 [ 2-5(2) 0-1(7) 0-2(9) 3-4(6) ]
  i=3: key=3-4(6)，0-2(9)、0-1(7) 后挪，2-5(2) 不动 ⇒ [ 2-5(2) 3-4(6) 0-1(7) 0-2(9) ]
```

`O(E²)`，本节 `E = 9`，跑 36 次比较，快到不用考虑。
想上规模就把这段换成手写归并排序（仍然不需要函数指针：比较规则写死在循环里）。
**"用 `>` 而不是 `>=`"让排序稳定**：同权边保持边表原有顺序 ⇒ 运行结果可逐字复现，
也让"边表顺序会影响 MST 选哪条边"这件事变得可控（见第 6 幕）。

### 操作 5：Kruskal 主循环（整个算法 8 行）

```c
sort_edges_copy(g, sorted);          /* ① 排序 */
dsu_init(&dsu, g->n);                /*    每个点各自一堆 */
for (i = 0; i < g->m; i++) {         /* ② 从便宜的边开始逐条试 */
    if (dsu_union(&dsu, u, v)) {     /*    能并 ⇒ 不成环 ⇒ 收下 */
        out[cnt].u = u; out[cnt].v = v; out[cnt].w = w; cnt++; total += w;
        if (cnt == g->n - 1) break;  /*    ③ 收满 V-1 条，停手 */
    }
}
```

演示里为了把 `find` 结果打印清楚，先分别 `dsu_find(&dsu, u/v)` 打印，再决定要不要 `union`；
生产代码直接 `if (dsu_union(...))` 一步到位。

**为什么"跳过成环的边"是安全的（环性质 / cycle property）**：
若把边 `e` 收下会成环，且 `e` 是**当前这条环上最贵**的（因为我们按权重升序处理，
环上其它边都是更早收下的、都不比 `e` 贵），那么 `e` 一定不属于任何 MST ——
想去掉 `e`？环上随便留一条别的边一样连通，而且不会更贵。
反过来，"收下的边"是此刻连接两棵子树的最便宜的桥。两个方向一起保证了贪心正确。

### 操作 6：为什么 MST 只有 V-1 条边

- 连通：`V` 个点至少要 `V-1` 条边才可能连成一片（每加一条边最多让连通块少一个）。
- 无环：`V` 个点的树，边数正好 `V-1`；多一条必成环。

所以"收满 `V-1` 条"既可以当**终止条件**，也可以当**结果自检**：
收不满 `V-1` 条 ⇒ 图不连通 ⇒ 你拿到的是森林（本目录第 8 幕专门演示这个坑）。

## 复杂度表

| 阶段 | 时间 | 说明 |
|---|---|---|
| 排序 | `O(E log E)`（用 `qsort`/归并）；本目录插入排序 `O(E²)` | **瓶颈就在排序**，边数一样时它决定一切 |
| 逐条边并查集 | `O(E · α(V))`，α ≈ ≤4 | 每条边一次 union（内含两次 find），摊还近乎常数 |
| 合计 | `O(E log E)`（正确排序时） | `E log E ≈ E log V`，因为 `log E ≤ 2 log V` |
| 空间 | `O(V + E)` | 边表 `E` 条 + 并查集两个长度 `V` 的数组 |

横向对比（同一张图，`V = 6, E = 9`）：

| 算法 | 时间 | 需要存什么 | 稀疏图(E≈V) | 稠密图(E≈V²) | 有向图 | 负权边 |
|---|---|---|---|---|---|---|
| **Kruskal**（本节） | `O(E log E)` | 边表 | ★ 最合适 | 吃亏 | — | 无所谓 |
| Prim 朴素（`prim-mst`） | `O(V²)` | 邻接矩阵 | 稍亏 | ★ 最合适 | — | 无所谓 |
| Prim + 堆 | `O((V+E) log V)` | 邻接表 + 堆 | ★ 好 | 不如朴素 | — | 无所谓 |
| Dijkstra | `O((V+E) log V)` | 邻接表 | ★ | ★ | 要 | ✗ 会算错 |

**MST 类算法完全不关心边权正负**：生成树只看"加起来最小"，把 `-100` 的边优先收下正是它该干的事。
这一点和"负权会打崩 Dijkstra"形成对照 —— 别忘了 Dijkstra 崩的是"已定稿不再修改"这个前提，
Kruskal 没有任何"定稿"的概念。

```
    MST 的定义只要求【总权最小】，从没要求【边集唯一】。只要图里存在两条权重相同、

    推论：题目若问「MST 是否唯一」，就去看有没有【可互换的同权边】；
    一条判据：把所有边权看成「同权分组」，若某组边在某一个环上都是该组最小 ⇒ 不唯一。

本节小结
==================================================
  1) Kruskal = 排序 + 逐条边试 + 并查集判环。收满 V-1 条就停。
  2) 判环为什么优雅：「加边会成环」等价于「两端已连通」，后者就是 find(u)==find(v)，一行。
  3) 复杂度 O(E log E + E·α(V))，瓶颈在排序；内存只要一张边表 ⇒ 稀疏图首选。
     稠密图（E ~ V^2）它就吃亏了：排序要 O(V^2 log V)，比 Prim 的 O(V^2) 还慢 ⇒ 用 Prim。
  4) 排序必须手写（本项目禁函数指针 ⇒ 不能用 qsort 比较器），且要用稳定排序，
     这样同权边按边表顺序处理，输出可复现。
  5) 总权唯一、边集未必唯一；Kruskal 与 Prim 总权必须相等，可以互相验证。
  6) MST ≠ 最短路径树（见 prim-mst 第 5 幕的对照：33 vs 38）。
  7) 图不连通时 Kruskal 安静地返回森林 ⇒ 一定要检查边数 == V-1。
```

## 常见的坑

### 坑 1：图不连通时 Kruskal 不报错，只给你一片"森林"

第 8 幕里 `V = 5`，它只收了 3 条边（`V-1` 应该是 4），但函数照样返回总权 12。
**必须自己检查 `cnt == n - 1`**，否则你会把"两块互不相通的网"当成"一张连通的网"报上去。
（隔壁 `prim-mst` 的写法是显式返回 `-1`；两种风格都得在调用侧看一眼。）

### 坑 2：忘了 `break` 或者忘了"跳过"，边就收超了

正确姿势是"收满 `V-1` 条立即停"。少写这个判断，循环会一路把边表跑完，
`out[cnt]` 越界写爆数组（`cnt` 可能超过 `V-1`）。
反过来说，`MAX_E` 这么小的数组，边界一定要靠 `V-1` 兜住。

### 坑 3：并查集忘了初始化，或者 `find` 写死了一层

`dsu_init` 必须在每次 `kruskal_mst` 开头调一次。
上一轮的 `fa[]` 残留会让这一轮"两端已连通"的判断全线出错 —— 表现为"少收了几条边"，
而且**不崩、不报错**，只给一个偏大的总权。
（本目录第一次写这份代码时就踩过：`dsu_print` 在 `dsu_init` 之前被调用，
打印出来的是栈上的垃圾值。把初始化提到前面才对。）

### 坑 4：只用递归压缩、不写按秩合并（或反过来）

两个优化各治一种病：
- **只按秩不压缩**：`O(m log n)`，够用但重复查同一个点每次都要爬 `log n` 跳。
- **只压缩不按秩**：也是 `O(m log n)`，第一次构造时可能把树挂得很深。
- **两个都不要**，而且写成"固定让 `fa[rb] = ra`"：可以退化出 `0→1→2→…→n-1` 一条链，
  单次 `find` 就是 `O(n)`。第 7 幕手搓的那条链就是在演示这个：`find_probe(0)` 爬 4 跳。

结论：两个一起写，摊还 `O(α(n))`，代码量只差 5 行。

### 坑 5：用 `qsort` + 函数指针"顺手一下"

本项目硬约定禁函数指针（见根目录 `README.md` 的三条硬约定）。
而且 `qsort` 的比较器写错方向（`return b->w - a->w;` 变成降序）是很常见的静默 bug ——
降序的 Kruskal 会给出**最大**生成树（本节图上是 33 变成 46），
结果照样"合法"（V-1 条边、连通、无环），只是不是最小。自检 `mst_check_valid` 也抓不到它。
所以：**排序方向必须肉眼确认**，本目录的做法是先把"排序前 / 排序后"两行都打出来。

### 坑 6：以为"MST 唯一"

只要图里有**同权且可互换**的边，MST 就不唯一（第 5 幕的三角形、第 6 幕的四元环）。
判分一般只卡总权；但如果题目要输出边集，标准答案往往要求"按字典序最小"之类，
那就得在排序的 tie-break 上动手脚（比如先把边按 `(w, u, v)` 排）。
本节用的是插入排序 ⇒ 同权边按边表顺序，输出稳定可复现。

### 坑 7：把 MST 当成最短路树用

同一张共用图，Kruskal 的 MST 总权 33，Dijkstra 的最短路径树总权 38，
**而且 MST 里 0 到 3 的距离是 26，最短路是 20**。
铺线用 MST，"从总部到各分部最快到达"必须用最短路。详见 `prim-mst` 第 5 幕的对照。

## 什么时候用它 / 什么时候别用

**该用的场景**

- 稀疏图求 MST（`E` 接近 `V` 或 `V log V`）：`O(E log E)` 完胜 `O(V²)`。
- 图本来就以**边表**形式在手（读题就是 `m` 行三元组），转成邻接矩阵纯属浪费。
- 需要"按边权顺序逐步看连通性变化"的问题：
  比如"加到第几条边时图第一次连通"、"最后被选中的那条边的权重"（= MST 的瓶颈边）、
  或者"要求最大边权尽量小"这类目标 —— Kruskal 的处理顺序天然给出答案。
- 需要**最小生成森林**（多个连通分量各一棵）：Kruskal 不用改代码就顺手给出来了。
- 想顺便把并查集练熟。

**别用的场景**

- **稠密图**（`E ≈ V²`）：排序要吃 `O(V² log V)`，比朴素 Prim 的 `O(V²)` 慢一个 `log V`；
  而且矩阵在手时用 Prim 更短。→ 去 `07-graph/prim-mst`。
- **有向图**：MST 在带权有向图上的对应物叫**最小树形图（Arborescence）**，
  Kruskal/Prim 都不适用（那是 Zhuliu–Chen 算法的领域，本仓库不覆盖）。
- 想求"最短路"：MST 和优化单点距离毫无关系（见坑 7）。
- 图**动态加点加边**、要在线回答 MST：普通 Kruskal 做不到，需要 LCT / 分治等工具。
- 只要"连通性"而**不要最小**：那用并查集就够了，别排序 —— 排序纯属多余。

## 选哪个算法

| 我要解决的问题 | 图的长相 | 用这个 | 复杂度 | 去哪一节 |
|---|---|---|---|---|
| 单源最短路（非负权） | 稀疏图 | Dijkstra + 小顶堆 | `O((V+E) log V)` | `07-graph/dijkstra` |
| 单源最短路（非负权） | 稠密图 / 已有邻接矩阵 | Dijkstra 朴素版 | `O(V²)` | `07-graph/dijkstra` |
| 单源最短路（**有负权边**） | 任意 | Bellman-Ford | `O(V·E)` | `07-graph/bellman-ford` |
| 单源最短路（负权 + 稀疏 + 抢时间） | 一般图，但怕被卡 | SPFA | 平均 `O(kE)`，最坏 `O(VE)` | `07-graph/bellman-ford` |
| 单源最短路 | **DAG**（有向无环） | 拓扑排序 + 一遍松弛 | `O(V+E)` | `07-graph/topological-sort` |
| **任意两点**最短路 | `V <= 几百`、稠密 | Floyd-Warshall | `O(V³)` | `07-graph/floyd` |
| 判全图有没有负环 | 带负权 | BF 第 V 轮 / Floyd 看对角线 | `O(VE)` / `O(V³)` | `bellman-ford`、`floyd` |
| 无权图：可达 / 最少步数 | 无权 | BFS（步数）/ DFS（可达、连通块） | `O(V+E)` | `bfs`、`dfs`、`connected-components` |
| **最小生成树** | **稀疏图**、手上只有边表 | **Kruskal + 并查集（本节）** | `O(E log E)` | `07-graph/kruskal-mst` |
| **最小生成树** | **稠密图**、已有邻接矩阵 | Prim 朴素版 | `O(V²)` | `07-graph/prim-mst` |
| 动态判连通 / 加边判环 | 只加边不删边 | 并查集（本节自带） | 摊还 `O(α(V))` | `07-graph/kruskal-mst` |
| 存储一张图 | 稀疏 → 邻接表；稠密 → 邻接矩阵 | — | `O(V+E)` / `O(V²)` | `adjacency-list`、`adjacency-matrix` |

一句口诀：**最短路看"从家到别家有多远"，生成树看"全家连通一共花多少钱"；
生成树里，边多用 Kruskal，点密用 Prim。**

## 自检问题

**Q1：为什么"收下这条边会成环"能等价于 `find(u) == find(v)`？**
因为 Kruskal 每一步保留的边集是一片**森林**（每次都只收不成环的边，归纳可知无环）。
在无环图里，"u、v 已经连通"当且仅当它们在同一棵树里。而并查集的"同一个根"就是"同一棵树"的定义。
所以 `find(u) == find(v)` ⇔ 已连通 ⇔ 再加 `(u,v)` 会形成环。反过来，如果允许边集有环，
这个等价就断了 —— 所以"森林"这个前提是循环不变量，不能破。

**Q2：Kruskal 和 Prim 在同一张图上结果一定相同吗？**
**总权一定相同**（都等于 MST 的最小总权，这是图的固有属性；两算法总权不一致就是有一方写错了，
本节第 4 幕把这两个数摆在一起对账，`33 == 33`）。
**边集未必相同**：第 5 幕的等权三角形里 Kruskal 给 `0-1、1-2`，Prim 给 `0-1、0-2`，都是总权 2 的 MST。
边权两两互不相等时，两者边集必定相同（因为那时 MST 唯一）。

**Q3：不排序，直接把边按任意顺序喂给"能并就并"的规则，得到的是 MST 吗？**
不是。得到的是**某个**生成树（如果图连通），但一般不是最小的。
反例（本节共用图）：按边表原顺序 `0-1(7), 0-2(9), 0-5(14), 1-2(10), 1-3(15), 2-3(11), 2-5(2), 3-4(6), 4-5(9)`
跑一遍"能并就并"，会收 `0-1、0-2、0-5、2-3、3-4` = 7+9+14+11+6 = **47**，比 33 大得多。
排序是 Kruskal 正确性的**必要前提**，不是锦上添花。
顺带一提：把边按**降序**排，得到的就是**最大**生成树（第 6 幕那两条权 9 的边会被优先收）。
它不报错、结果照样"合法"，所以排序方向一定要打印出来核对 —— 本节就是把"排序前/后"两行都打出来。

**Q4：并查集里 `rnk[]` 能不能删掉，只留 `fa[]`？**
能跑，但会退化。没有按秩合并时，"总是 `fa[rb] = ra`"的写法可以造出 `0→1→2→…→n-1` 一条链，
单次 `find` 变成 `O(n)`；即便有路径压缩，第一次构造过程的代价也可能到 `O(m log n)` 甚至更差。
`rnk[]` 只是一个长度 `V` 的 int 数组（`V=10^6` 时 4 MB），换来"树高 ≤ log V"的硬保证。
本仓库的结论：**两个优化一起写，多 5 行，别省。**

**Q5：这一节的实现里哪一处"看着对其实危险"，你踩到了吗？**
第 8 幕那个：图不连通时 `kruskal_mst()` **不返回失败信号**，它照样给出总权 12、边数 3。
调用侧不检查 `cnt == n - 1` 就会把"森林"当成"树"上报。
写出来的教训：**返回总权的函数，一定要同时把边数交出来，并在外面比对 `V-1`。**
