# 二叉搜索树 bst

> 给普通二叉树加一条铁律「左 < 根 < 右」，从此查找每走一步就砍掉一半候选 —— 但也因此背上了"会退化"的毛病。

## 一句话是什么

**BST = 二叉树 + 一条永远不许破坏的规矩：任何一个节点的左子树里所有值都比它小，右子树里所有值都比它大。**

结构（节点定义）和上一节**一模一样**，变的只是"值怎么摆"：

```
              50                        插入顺序：50 30 70 20 40 60 80 35
             /  \
           30    70       ← 30 的整棵左子树(20,35,40) 全部 < 50
          / \    / \                      而 30 的右子树 40 里的 35 也必须 > 30
        20  40  60  80                    —— 规矩是对【每个节点】都成立
            /
           35

   中序遍历 → 20 30 35 40 50 60 70 80   （自动升序，一个排序都没做）
```

---

## 为什么需要它

**不用它的时候有多痛：**

| 做法 | 查找 | 插入 | 删除 | 痛在哪 |
|---|---|---|---|---|
| 无序数组 | O(n) | O(1) | O(n) | 查一个值要扫全表 |
| 有序数组（二分） | **O(log n)** | **O(n)** | O(n) | 查得快，但插一个数要把后面全部往后挪 |
| 有序链表 | O(n) | O(n) | O(1)（已知前驱） | 插入不用挪，但查找退化回线性，二分也用不了 |
| 哈希表 | O(1) 平均 | O(1) | O(1) | 最快，但**完全没有顺序**：拿不到"最小值""第 k 小""范围查询" |
| **BST** | 平均 **O(log n)** | 平均 **O(log n)** | 平均 **O(log n)** | 又快**又保持有序**，还能问最大最小、按序输出、找前驱后继 |

BST 的独门价值就是"**有序 + 能高效增删**"这两件事同时做到：
- 求第 k 小、求某个值的排名、区间 `[a,b]` 内所有元素 → 哈希表做不到，BST 一次中序/递归就出来；
- 数据库索引、`std::map` / Java `TreeMap` 的内部原理，本质都是"会自平衡的 BST"。

**它的毛病也很实在**：树形由插入顺序决定，顺序一歪就退化成链表，O(log n) 立刻变 O(n)。
本节第 7 幕会**现场把这条链表造出来**，这就是 AVL / 红黑树存在的唯一理由。

## 内存布局图解

### 1. 节点结构：和普通二叉树 100% 相同

```
   ┌──────────┬───────────┬───────────┐
   │ val: 40  │ left ─────┼──► 节点 35 │      ← 左子树所有值 < 40（铁律）
   │          │ right     │  NULL      │      ← 右子树所有值 > 40（这里没有右子树）
   └──────────┴───────────┴───────────┘
```

**结构没变、字段没变、指针画法没变** —— 变的只是"值不能随便写"。
这一点非常重要：所有 BST 的算法复杂度、递归套路、`free_tree`，都可以直接沿用上一节。

### 2. 整棵树在内存里：地址照样不连续，靠指针牵

以演示用的树为例（地址是假装的，`print_tree` 画出来才是真的）：

```
   0xA: [50 | ────────┬ ────────┐ ]   ← root
   0xB: [30 | ────────┼ ────────┤ ]   30 的左 = 20，右 = 40
   0xC: [70 | ────────┼ ────────┤ ]   70 的左 = 60，右 = 80
   0xD: [20 |  NULL   |  NULL   ]     叶子
   0xE: [40 | ────────┼  NULL   ]     40 只有左孩子 35
   0xF: [60 |  NULL   |  NULL   ]     叶子
  0x10: [80 |  NULL   |  NULL   ]     叶子
  0x11: [35 |  NULL   |  NULL   ]     叶子，挂在 40 的左边

   关系图（把它压扁就是 README 开头那个三角树）：
   root ─► 0xA(50) ─┬─ left  ─► 0xB(30) ─┬─ left  ─► 0xD(20)
                    │                     └─ right ─► 0xE(40) ── left ─► 0x11(35)
                    └─ right ─► 0xC(70) ─┬─ left  ─► 0xF(60)
                                          └─ right ─► 0x10(80)

   检查铁律：35 在 50 的左子树里 → 35 < 50 ✔；35 在 40 的左子树里 → 35 < 40 ✔
             60 在 50 的右子树里 → 60 > 50 ✔；60 在 70 的左子树里 → 60 < 70 ✔
```

### 3. `print_tree` 把同一棵树画成这样（屏幕上真实长这样）

```
50
├─30
│ ├─20
│ └─40
│   └─35          ← 40 只有左孩子，所以前缀里已经没有竖线了
└─70
  ├─60
  └─80
```

**退化那一幕画出来是这样的**（把结构变化"演"给人看，第 7 幕真实输出）：

```
1
└─2
  └─3
    └─4
      └─5
        └─6
          └─7      ← 每层只有 1 个节点，高度 7 == 节点数 7：这就是一条链表
```

## 核心操作逐个拆解

每个操作按 **干什么 → 一步步怎么做 → 边界情况 → 对应代码** 讲。

### 1. 插入 `bst_insert(root, val)` / `bst_insert_pp(&root, val)`

- **干什么**：把一个值放进唯一合法的位置，并保持铁律。
- **为什么必然落在一片"叶子空位"上**：
  插入的过程 = 拿新值从根往下走一遍查找。每到一个节点比一次大小，决定钻左还是钻右；
  一直走到**纸条是 NULL** 才停。而 NULL 只可能出现在叶子（或独苗节点）的下面，
  所以新节点永远"挂在某个空指针位上"，绝不会插到两个已有节点中间，
  **也不需要像有序数组那样把别人往后挪**。

  ```
  插入 35（树：50 的左子树是 30，30 的右子树是 40，40 的左孩子 NULL）
       50            35 < 50 → 左
      /              35 > 30 → 右
    30               35 < 40 → 左 ← 这里是 NULL！就插在这
      \
      40             内存里只发生一件事：40->left = 新节点地址（写一张纸条）
      ▲
      空的左纸条
  ```
- **一步步（版本 B：返回新根，最常用）**：
  1. `root == NULL` → `return node_new(val)`（新节点生在这里，交给上一层去接）；
  2. `val < root->val` → `root->left = bst_insert(root->left, val)`；
  3. `val > root->val` → `root->right = bst_insert(root->right, val)`；
  4. 相等 → 本节约定忽略（打印一行提示）；
  5. `return root`（这棵子树的根没换，原样交回去）。
- **一步步（版本 A：二级指针）**：
  `bst_insert_pp(Node **root_in_out, val)` —— 读出 `cur = *root_in_out`；
  `cur == NULL` 时 `*root_in_out = node_new(val)`（**星号 = 往调用者的指针变量里写**）；
  否则递归传 `&cur->left` / `&cur->right`（还是二级指针）。
  这跟 `00-c-foundation/pointer-basics` 里 `swap_by_pointer(&x, &y)` 是**同一个道理**：
  要改"指针"这个变量本身，就得传它的地址；`Node **` 就是"指针的地址"。
- **两个版本选哪个？为什么 B 更常用**：
  - B 只用一级指针，读起来不用在 `*` 和 `->` 之间来回翻译；
  - B 的签名 `Node *f(Node *, ...)` 天生表达"**我会换根，新根还给你**"，
    删除要用、下一节 AVL/红黑树的**旋转必须用**（旋转会把子树的根换成别人）；
  - A 的好处是不用写 `root = ...`（不会出现"忘了赋值"的低级错误），且面试常考。
  本仓库两个都实现，第 2 幕用同一组数据 `40 20 60 10 30` 各建一棵，打印出来形状完全相同。
- **边界情况**：
  - 空树插入：版本 B 靠返回值把 root 从 NULL 变过来；版本 A 靠 `*root_in_out = ...`。
  - 重复值：本节直接忽略（真要存重复，常见做法是节点里加 `count` 字段）。
  - `malloc` 失败：`node_new` 返回 NULL，树保持原状，不会留下半截节点。
- **代码**：`bst.c` 搜 `Node *bst_insert` / `void bst_insert_pp`（注释里有完整指针图解）。

### 2. 查找 `bst_find` / `bst_find_iter` / `bst_find_counted`

- **干什么**：判断某个值在不在，在就返回节点地址。
- **一步步**：`root == NULL` → 没有；`val == root->val` → 命中；
  `val < root->val` → **只往左走，右边整片看都不看**；否则只往右走。
- **为什么快（也是本节最重要的一句话）**：每比一次就排除掉一整棵子树，
  理想情况下候选数量每层减半 → 比较次数 ≈ 树高 = O(h)。
  第 3 幕实测：8 个节点的树查不存在的 45 只比了 **3 次**（45<50 → 45>30 → 45>40 → NULL）。
- **边界情况**：
  - 找不存在的值：最后走到 NULL 才返回，步数 = 深度 + 1；
  - **树退化时 O(h) = O(n)**：第 7 幕查 7 比了 7 次，剪枝一点没省。
- **代码**：`bst.c` 搜 `const Node *bst_find` / `bst_find_iter` / `bst_find_counted`
  （第三个用 `int *steps_out` 输出参数告诉你比了几次 —— 输出参数的老约定）。

### 3. 最小值 / 最大值

- **干什么**：全树最小 = 从根一路 `left` 走到底；最大 = 一路 `right` 走到底。
- **为什么这样一定对**：铁律说"左子树全都比我小"，那我左子树里的最左那个，
  就是"比我还小的里面最小的"，一路下去就是全局最小。
- **一步步**：`while (cur->left != NULL) cur = cur->left;` 三行完事。
- **边界情况**：空树返回 `NULL`；`bst_min(root, &out)` 这种便捷版返回 0 表示"没值可给"。
  退化树走到底要 n 步 —— 求最小值也会变慢。
- **代码**：`bst.c` 搜 `const Node *bst_min_node` / `bst_max_node` / `int bst_min`。

### 4. 删除 `bst_delete(root, val)`（全节最难点）

- **干什么**：把值为 val 的节点摘掉，`free` 它的内存，且**摘完铁律依然成立**。
- **为什么签名还是"返回新根"**：被删的可能正好是某棵子树的根，摘掉后
  "这棵子树的新根是谁"必须告诉父亲 → `node->left = bst_delete(node->left, val);`。
- **三种情况**：

  ```
  情况 1：叶子（没孩子）        ——  直接摘，父亲的纸条变 NULL
       30                     30
        \                      \
       [20]        →            NULL

  情况 2：只有一个孩子          ——  孩子提上来顶替（等价于链表摘节点）
       30                     30
        \                      \
       [40]        →            35
       /
      35

  情况 3：左右孩子都在          ——  不能真摘！用【后继】顶替，再去删那个后继
  ```

- **情况 3 一步步（配两棵树的对照图，就是第 5 幕删根节点 50 的真实过程）**：

  ```
  删除前（要删的是根 50，左右孩子都在）：
            50
           /  \
         30    70
          \    / \
          35  60  80

  ① 找后继 = 右子树最小 = bst_min_node(50->right)：
     从 50 向右一步到 70，再一路向左 → 60。60 在 70 的最左，所以 60 自己没有左孩子。

  ② 只抄值、不动指针：把 60 写进 50 那个格子里
     ┌───── 替换前 ─────┐         ┌───── 替换后 ─────┐
     │       50         │   →     │       60         │   ← 60 出现了两次！
     │      /  \        │         │      /  \        │      上面这个是"冒名顶替"的
     │    30    70      │         │    30    70      │      下面那个是待删的真身
     │     \    / \     │         │     \    / \     │
     │     35 60  80    │         │     35 60  80    │
     └──────────────────┘         └──────────────────┘

  ③ 递归去右子树里删掉重复的那个 60：
     root->right = bst_delete(root->right, 60)
     在子树 70(左=60, 右=80) 里删 60 → 60 是叶子 → 退回【情况 1】，一步搞定
     ┌───── 最终结果 ─────┐
     │       60           │   ← 根"换人"了：内存里还是原来那个节点盒子，
     │      /  \          │      只是 val 从 50 改成了 60
     │    30    70        │      真正 free 掉的是原来那个 60 的小盒子
     │     \      \       │
     │     35     80      │
     └────────────────────┘

     校验：中序 = 30 35 60 70 80，仍然严格升序 ✔ 铁律守住了
  ```

- **为什么后继（右子树最小）能顶上去**：它要同时满足两条
  ① 比左子树所有值都大 → 它本来就在右子树里，天然 > 根 > 左子树全部 ✔
  ② 比右子树剩下的所有值都小 → 它是右子树里**最小**的那个 ✔
  所以只有它放上去不破坏任何关系。（取"左子树最大 = 前驱"是**对称**的另一种合法写法，本节约用后继。）
- **为什么问题不会失控**：后继在最靠左，它**不可能有左孩子** → 它自己必然落在情况 1 或情况 2，
  递归只会往简单方向走一步，不会再来一次情况 3。
- **边界情况**：
  - 删不存在的值（第 5 幕演示删 999）：一路走到 NULL，`return NULL`，树原样、不崩、不误删；
  - 删的正是根：因为"返回新根"，`tree = bst_delete(tree, 50)` 之后根自然换人；
  - 代码把"没左孩子"和"叶子"合并在同一个分支里（`root->left == NULL` 时把 `root->right` 提上来，
    右孩子可能是 NULL，正好覆盖叶子）。
  - **free 之前一定先把孩子地址抄进局部变量**：`Node *replacement = root->right; free(root); return replacement;`
    反过来写就是 use-after-free（上一节 free_tree 讲过的同一条规矩）。
- **代码**：`bst.c` 搜 `Node *bst_delete`，注释里有三情况对照图和完整 ASCII 推演。

### 5. 中序遍历 `bst_inorder`：有序性的证明

- **干什么**：左 → 自己 → 右，把值依次写进数组。
- **为什么 BST 的中序一定升序**：铁律保证"左子树全部 < 我 < 右子树全部"，
  中序正好是"先把左子树整个吐完，再吐我，再吐右子树" —— 递归套下去就是整树升序。
- **一步步**：普通二叉树的中序递归，一行都不用改。
- **边界情况**：空树什么都不输出。第 1 幕每插一个数就打印一次中序，8 次全部 `→ 严格升序 ✔`，
  main.c 里是让程序**自己检查**是否升序（不是我用眼睛看的）。
- **代码**：`bst.c` 搜 `void bst_inorder`。

### 6. 校验是否合法 BST：`bst_is_valid`（以及一个故意的错误示范）

- **干什么**：判断一棵手连出来的树是否满足铁律。
- **正确做法**：**中序必须严格升序**。实现上不必开数组，只记住"上一个访问到的节点 `prev`"，
  每次访问新节点时检查 `prev->val < node->val`；`prev` 要在递归层间共享更新，所以传 `const Node **`
  （又是"想改外面的变量就得传地址"）。O(n) 时间、O(h) 栈空间。
- **错误示范 `bst_is_valid_local_only`**：只比"我和亲生孩子"的大小，看起来很有道理，
  但会被这棵树骗过去（第 6 幕现场打印）：
  ```
          10
         /  \
        5    15
            /  \
           6    20    ← 6 < 15：跟亲爹比合法 ✔ 局部检查一路放行
     ```
  可 6 待在 **10 的右子树**里，按铁律必须 > 10，它却比 10 小 → 整棵树非法。
  中序吐出来是 `5 10 6 15 20`，10 后面接了个更小的 6，升序当场断裂 → 正确版抓到了。
- **边界情况**：空树 / 单节点树合法；有重复值的树在"严格升序"判定下**不合法**（本节约定不存重复）。
- **代码**：`bst.c` 搜 `static int inorder_check` / `int bst_is_valid` / `bst_is_valid_local_only`。

### 7. 退化演示 `bst_build_from_array` vs `bst_build_balanced`

- **干什么**：同一批数据 1..7，两种建法，对比查找代价。
- **一步步**：
  - 按升序逐个插入 → 每个新值都比所有已有值大 → 永远挂在最右边 → 右斜链表，高度 7，查 7 比 7 次；
  - 取中间当下根递归建 → 高度 3，查 7 只比 3 次（4 → 6 → 7）。
- **边界情况**：退化不只是"难看"，它让**查找/插入/删除/求最小值全部变 O(n)**；
  n = 100 万时平衡树高约 20、退化树高 100 万，是"20 次比较"和"50 万次平均"的差距。
- **一句话结论**：**从 BST 到 AVL 到红黑树，全都是在解决这一个"退化"问题。**
- **代码**：`bst.c` 搜 `Node *bst_build_balanced`、`main.c` 第 7 幕。

### 8. 树高 `bst_height` / 打印 `print_tree` / 销毁 `free_tree`

- **树高**：`1 + max(h(左), h(右))`，空树 0。它是性能的晴雨表：所有操作的步数都是 O(h)。
- **打印**：横着画（规则三条见上一节 README），BST 里"每做一次操作就打印一次"全靠它，
  结构变化不用想象，屏幕上直接看到。
- **销毁**：**必须后序** —— 先删左子树、再删右子树、最后 `free` 自己。
  因为孩子的地址存在父亲身体里，先 free 父亲再去读 `root->left` 就是 use-after-free。
  一句话记：**纸条上写着储物柜钥匙，先把柜子清空，再扔纸条。**
- **边界情况**：`free(NULL)` 安全；free 完把外部指针置 NULL；本节所有树（含第 5 幕 free 掉的后继节点）
  在第 8 幕一次性清完，ASan 报 0 泄漏。
- **代码**：`bst.c` 搜 `int bst_height` / `static void print_tree_rec` / `void free_tree`。

## 复杂度表

n = 节点数，h = 树高。平均按"随机顺序插入"估，最坏按"升序/降序插入"估。

| 操作 | BST 平均 | BST 最坏（退化） |  AVL（下一节） | 哈希表 | 有序数组 | 无序链表 |
|---|---|---|---|---|---|---|
| 查找 | O(log n) | **O(n)** | O(log n) | O(1) | O(log n) | O(n) |
| 插入 | O(log n) | **O(n)** | O(log n) | O(1) | O(n) | O(1) 头插 |
| 删除 | O(log n) | **O(n)** | O(log n) | O(1)* | O(n) | O(n) |
| 求最小/最大 | O(log n) | O(n) | O(log n) | **O(n)** | O(1) | O(n) |
| 按序输出全部 | **O(n)** | O(n) | O(n) | O(n log n) | O(n) | O(n log n) |
| 范围查询 [a,b] | O(log n + k) | O(n) | O(log n + k) | 做不到 | O(log n + k) | O(n) |
| 找第 k 小 | O(h)，子树计数可 O(log n) | O(n) | O(log n) | 做不到 | O(1) | O(n) |
| 空间 | O(n) 节点 + O(h) 递归栈 | 同 | 同 | O(n) | O(1) 原地 | O(n) |

**读表要点**
- BST 相对哈希表的价值：② 按序输出、③ 范围查询、④ 前驱后继、⑤ 第 k 小 —— 这四件哈希全都做不到或很慢。
- BST 相对 AVL 的价值：代码量小一个数量级（本节 19 个函数，AVL 还要加旋转和高度维护）。
- "查找 O(log n)"这句话必须带前提：**树是平衡的**。裸 BST 给不了这个保证。

## 常见的坑

1. **把铁律理解成"左孩子 < 根 < 右孩子"**
   差一个字，整棵树的判定就废了。铁律管的是**整棵左子树 / 整棵右子树**。
   第 6 幕那棵 `10 → (5, 15 → (6, 20))` 就是专门用来打这个错觉的：
   6 < 15 看着没毛病，但它在 10 的右子树里，必须 > 10。

2. **插入时忘了把新节点"接"到父亲上**
   `bst_insert(root->left, val);` 不接返回值 = 新节点造出来了但没人指它 → 当场内存泄漏，
   而且树看起来"什么都没发生"。**必须写 `root->left = bst_insert(...)`**，
   或者改用二级指针版本 `bst_insert_pp(&root->left, val)`。ASan 能抓到这条（泄漏）。

3. **删除情况 3 里"直接 free 掉被删节点"**
   摘掉之后左右两棵子树没人管了，要么丢一整片（泄漏），要么乱接（破坏铁律）。
   正确做法是**只抄值、不摘盒**，真正 free 的是下面那个后继。

4. **抄完值忘了去右子树删掉那个重复的后继**
   结果是树里出现两个 60，中序变成非严格升序，`bst_is_valid` 立刻返回 0。
   这也是"每次操作后打印中序"这个习惯的价值。

5. **先 `free(root)` 再读 `root->left` / `root->right`**
   `bst_delete` 和 `free_tree` 都有这条：必须**先把孩子地址抄进局部变量**再 free。
   反过来写是 use-after-free，可能"看起来正常但漏了一整支子树"。

6. **用递归写完不检查 `malloc` 返回值**
   `node_new` 失败返回 NULL，`root->left = NULL` 这种赋值是安全的，
   但别在 NULL 上继续 `->val`。本节的写法是"失败就当这个孩子不存在"，不崩。

7. **忘了 BST 会退化，把它当"永远 O(log n)"用**
   数据是按序进来的（时间戳、自增 ID、排好序的日志），裸 BST 直接变链表，
   插入还退化到 O(n)、n 次插入总耗时 O(n²)。要么打乱插入顺序，要么用 AVL/红黑/跳表。

8. **以为 BST 能替代哈希表**
   平均 O(log n) vs 平均 O(1)，纯"按 key 取值"这件事哈希更快。
   BST 的价值在**有序**：范围查询、最大最小、第 k 小、前驱后继。

## 什么时候用它 / 什么时候别用

**适合用：**
- 既要"增删快"又要"始终有序"：有序集合 `TreeMap` / `std::map` 的实现原理就是它。
- 需要范围查询 `between(a,b)`、排名（第 k 小）、前驱/后继 —— 哈希表给不了。
- 数据库索引、文件系统目录（但工程上用的是它的多路亲戚 **B 树**，见 `05-tree/b-tree/`）。
- 数据到达顺序未知、且能接受一次 O(log n)（或自己先打乱再插入）。

**别用：**
- 只要"按 key 存取"、完全不在乎顺序 → **哈希表**（O(1) 且代码更简单）。
- 数据基本静态、只有查询 → **有序数组 + 二分**（缓存友好，实测常比树快）。
- 只关心"最大/最小"、不关心中序 → **堆**（数组存储，无指针开销）。
- 插入顺序可能有序、又不想写旋转代码 → **跳表**（`02-linked-list/skip-list/`，随机化保平衡）。
- 必须保证最坏 O(log n) → 别用裸 BST，用 **AVL / 红黑树**（本节第 7 幕就是它的反面教材）。

## 自检问题

1. **为什么 BST 插入的新节点一定落在某个"叶子空位"上，而不会插在两个节点中间？**
   **答：** 插入就是照着查找的路线走，每到一个节点比一次大小决定左/右，
   直到遇到一张空白纸条（NULL）为止。NULL 只可能挂在叶子或独苗节点下面，
   所以新节点必然是"挂上去"的，不需要挪动任何已有节点 —— 这就是它比有序数组插入快的原因。

2. **`bst_insert(Node *root, int v)` 返回 `Node *`，和 `bst_insert_pp(Node **root, int v)` 返回 `void`，为什么都能正确挂好？**
   **答：** 前者把"这棵子树处理完之后的新根"用 return 交回给上一层，上一层写
   `node->left = bst_insert(node->left, v)` 就完成接线；空树时返回值就是新节点，
   `root = bst_insert(root, v)` 自然把根挂上。后者直接把"要被改的那个指针变量的地址"
   （`Node **`）拿到手，需要换根时写 `*root_in_out = 新节点`，走的是"输出参数"的路子。
   两条路只是"新根怎么交回调用者"的差别。

3. **删除一个左右孩子都在的节点，为什么后继一定落在"情况 1 或情况 2"里？**
   **答：** 后继是右子树里最小的 = 从右孩子一路向左走到的那个，它**不可能还有左孩子**
   （有的话它就不是最小了）。没有左孩子的节点要么是叶子，要么只有右孩子 —— 正好是情况 1/2。
   所以递归删它一定一击致命，不会又跳回情况 3。

4. **为什么"只检查 node->left->val < node->val < node->right->val"不能判定 BST？举个反例。**
   **答：** 它只保证和亲孩子的关系。反例（本节第 6 幕）：
   ```
        10
       /  \
      5    15
          /  \
         6    20
   ```
   6 < 15 局部合法，但 6 在 10 的右子树里，必须 > 10 → 全局非法。
   必须用"中序严格升序"或"给每个节点带一个 (min,max) 允许区间"来判。

5. **按 1,2,3,4,5,6,7 依次插入，最后树高多少？查找 7 比几次？这算平均还是最坏？**
   **答：** 树高 7，比 7 次 —— 这是**最坏情况**。因为每次插入都往右边走，
   树成了一条链表，剪枝无效（每步只排除 1 个候选）。平衡建树的话高度 3、只比 3 次。

6. **BST 里查找 5，能比哈希表快吗？既然不能，为什么还要学 BST？**
   **答：** 一般不能，哈希平均 O(1) 更快。学 BST 是为了"**有序**"这件事：
   中序一次遍历就是升序输出、能问最小/最大、能做区间 `[a,b]` 查询、能找前驱后继和第 k 小，
   这些哈希表要么做不到要么得先把全部 key 排一遍序。
