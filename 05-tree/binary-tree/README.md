# 二叉树 binary-tree

> 所有树结构的地基：每个节点最多两个孩子，靠两个指针连着。本节把「怎么建、怎么走、怎么量、怎么拆」四件事一次讲完。

## 一句话是什么

**二叉树 = 一堆用两个指针（left / right）串起来的盒子，每个盒子最多再牵出两个盒子。**

本节研究的是**不带顺序规则**的普通二叉树：值随便摆，不要求左小右大。
我们要解决的只有一个问题 —— **这些指针到底在指谁，我怎么把整棵树走一遍。**

```
             1                     ← 根（root）：唯一的入口地址
           /   \
          2     3                  ← 第 2 层
         / \     \
        4   5     6                ← 第 3 层（4、5、6 是叶子）
```

建树、遍历、求高度、销毁，全部围绕这一棵树展开（`make one` 的真实输出见文末，
所以 README 里写的每个数字都能在屏幕上核对）。

---

## 为什么需要它

**不用它的时候有多痛：**

| 场景 | 用数组/链表 | 用二叉树 |
|---|---|---|
| 表示"目录套子目录"、"公司组织架构"、"HTML 标签嵌套" | 线性结构表达不了"一对多"，只能靠字符串前缀 hack | 天生就是树，`node->left/right` 就是"我的孩子" |
| 表示表达式 `a + b * c` | 要先写优先级判断、括号处理 | `+` 在上、`*` 是它的右孩子，中序打印就是原式，后序打印就是 `a b c * +` |
| 想按大小快速找（下一步 BST） | 有序数组插入要整体往后挪 O(n)；链表找要 O(n) | 加了"左<根<右"规矩后，每下一层砍掉一半 |
| 前缀检索、语法解析、决策分支 | 一堆 if 嵌套写成人肉面条 | 树本身就是分支结构 |

**关键认知**：普通二叉树本身查找是 O(n)，不快。它的价值是——
① 它是**理解一切树结构的模板**（BST / AVL / 红黑 / 堆 / Trie / 线段树的节点定义和递归套路全都一样）；
② 遍历（前中后层）是**递归思维最好的练兵场**，把这四种顺序想明白，后面所有树的题都不慌。

## 内存布局图解

### 1. 一个节点 = 一个结构体，两个指针是两张"纸条"

```
       Node（本机 24 字节：4 字节的 int + 两个字段的对齐填充 + 2×8 字节指针）
       ┌────────────┬─────────────┬─────────────┐
       │  val: 2    │  left       │  right      │
       │   （数据）  │   （纸条①）  │   （纸条②）  │
       └─────▲──────┴──────┬──────┴──────┬──────┘
             │             │             │
        谁的地址？      写着左孩子地址   写着右孩子地址
                        没有就写 NULL(0)
```

- `node->left` 读作"顺着 left 这张纸条上的地址，进那个屋子"。
- **`NULL` 不是"0 号房子"，是"这张纸条是空白的"**：所有递归函数第一句 `if (root == NULL) return;` 就是在看纸条是不是空的。

### 2. 整棵固定树在堆上长什么样

6 次 `malloc` → 堆上 6 个独立格子（**地址不连续**，跟数组最大的区别！），全靠指针牵着：

```
  地址(假装)   内存内容                      含义
  ──────────────────────────────────────────────────────────
   0xA:  [ 1 | ────────┼ ────────┐ ]        ← root 指向这里
   0xB:  [ 2 | ────────┼ ────────┤ ]
   0xC:  [ 3 │  NULL   | ────────┤ ]        ← 3 没有左孩子，纸条①是空白
   0xD:  [ 4 │  NULL   |  NULL   ]          ← 叶子：两张纸条都空白
   0xE:  [ 5 │  NULL   |  NULL   ]
   0xF:  [ 6 │  NULL   |  NULL   ]

  指针关系全展开（这就是"树"的全部信息）：
  root ─► 0xA ─┬─ left  ─► 0xB ─┬─ left  ─► 0xD (4) ─ 两张纸条都空
               │                └─ right ─► 0xE (5) ─ 两张纸条都空
               └─ right ─► 0xC ─┬─ left  ─► NULL
                                └─ right ─► 0xF (6) ─ 两张纸条都空
```

**只要拿到 root 这一个地址，全树可达。** 所以二叉树的所有 API 都长成
`func(root, ...)`：不需要传"树"，一个指针就是整棵树。

### 3. 栈帧视角：递归遍历到底在干什么

`preorder(1)` 执行到中途时，调用栈大概是这样（这就是"系统在帮你用栈"）：

```
  高地址 ┌──────────────────────────────┐
         │ main 的栈帧                  │
         ├──────────────────────────────┤
         │ preorder(1)  ← 已经访问 1，  │
         │                正等左子树返回 │
         ├──────────────────────────────┤
         │ preorder(2)  ← 已经访问 2，  │
         │                正等左子树返回 │
         ├──────────────────────────────┤
         │ preorder(4)  ← 正在这里，    │  ← 栈顶：最深处
         │   左右都是 NULL，马上返回      │
         └──────────────────────────────┘
  低地址          ↑ 每 return 一层，就"回头"一次
```

"回头"这个动作不是代码写的，是栈帧自动帮你存的。
迭代版要自己准备 `const Node *stack[...]` 把这件事写出来 —— 本节两套都实现了。

## 核心操作逐个拆解

下面每个操作都按 **干什么 → 一步步怎么做 → 边界情况 → 对应代码** 四段来讲。

### 0. `node_new(val)`：造一个孤立节点

- **干什么**：在堆上要一块节点大小的内存，填上值，两张纸条写 NULL。
- **一步步**：`malloc(sizeof *node)` → 判空 → `node->val = val` → `left = right = NULL` → 返回地址。
- **边界**：`malloc` 失败返回 `NULL`，调用者必须判；`left/right` **必须显式置 NULL**，
  否则里面是垃圾值，遍历时会顺着垃圾地址跳进野地里。
- **代码**：`btree.c` 搜 `Node *node_new`。

### 1-A. `build_fixed_tree()`：手工连指针（做法 A）

- **干什么**：把上面那棵固定树用 6 行赋值接出来，适合 demo / 测试用例。
- **一步步**：先 `node_new` 造 6 个孤立节点 → 再逐条 `n1->left = n2;` 接线 → 返回根 `n1`。
- **边界**：
  - 接线之前所有节点都是光杆，`node->left = x` 只是"写纸条"，不复制任何东西；
  - `n3->left` 保持 NULL，**"没有左孩子"必须靠 NULL 表达，图上画不出来**；
  - 任何一个 `node_new` 失败就别再接线了（本函数直接返回，避免解引用 NULL）。
- **代码**：`btree.c` 搜 `Node *build_fixed_tree`，注释里画了完整内存图。

### 1-B. `build_tree_from_marks(marks, n)`：递归建树（做法 B）

- **干什么**：读一段"带空标记的前序序列"，把树还原出来。适合从文件/网络读树。
- **序列**：`1, 2, 4, -1, -1, 5, -1, -1, 3, -1, 6, -1, -1`（13 个数 = 6 个节点 + 7 个空标记；
  n 个节点的树正好有 n+1 个空指针位，所以空标记永远是 n+1 个）。
- **一步步**：
  1. 读一个数，是 `-1` → `return NULL`（这个位置没孩子）；
  2. 不是 `-1` → `node_new` 造节点；
  3. `node->left = 递归()` —— 递归自己会继续往后读数组；
  4. 左子树读完了，`node->right = 递归()`；
  5. 返回 node。
- **边界**：
  - **为什么必须带 `-1`？** 只给 `1,2,4,5,3,6`，"4 有没有右孩子"无从判断，树形不唯一。
    把"空"也显式写出来，序列才唯一。
  - `pos` 这个"读到哪了"必须**传地址**（`int *pos_in_out`），
    否则每层递归各拿一份拷贝，左子树读掉的个数父层不知道，右子树就会读到重复数据 ——
    跟 `00-c-foundation/pointer-basics` 里 `swap_by_value` 失败是**同一个道理**。
  - 数组读完（`*pos >= n`）当作空孩子返回 NULL，递归自然收敛。
- **代码**：`btree.c` 搜 `static Node *build_rec` 和 `Node *build_tree_from_marks`。

### 2-A/B/C. 递归 前序 / 中序 / 后序（本节重点）

- **干什么**：按某种顺序把每个节点的值写进调用者给的数组。
- **三个函数的代码只有 3 行，区别只是 `visit` 那一行写在第几位**：

  ```c
  前序: visit(自己); 递归(左); 递归(右);
  中序: 递归(左); visit(自己); 递归(右);
  后序: 递归(左); 递归(右); visit(自己);
  ```

- **"前/中/后"指的是"访问自己这个节点"的时机排在哪里，左右子树的相对顺序永远不换**（左一定在右前面）。
  所以"前中后序"其实是"自己在孩子们的前/中/后"，不是"先处理左还是先处理右"。
- **手算对照**（对着上面那棵树，一层层推）：

  ```
  前序 根→左→右：
    1                     喊 1，扎进左边
      2                   喊 2，扎进左边
        4                 喊 4，左右都 NULL，返回
        5                 喊 5，返回
      （2 完）
      3                   喊 3，左 NULL，去右
        6                 喊 6
    => 1 2 4 5 3 6

  中序 左→根→右：
    一路钻到最左下 4 → 喊 4 → 回头喊 2 → 去 2 的右 5 → 喊 5
    → 回头喊 1 → 去 1 的右 3 → 3 的左 NULL，喊 3 → 去 3 的右 6 → 喊 6
    => 4 2 5 1 3 6

  后序 左→右→根：
    4、5 都喊完才喊 2；6 喊完（3 的左是空）才喊 3；两个孩子都完才喊 1
    => 4 5 2 6 3 1              ← 检查口诀：后序最后一个一定是根，前序第一个一定是根
  ```

  程序真实输出（第 3 幕）：`1 2 4 5 3 6` / `4 2 5 1 3 6` / `4 5 2 6 3 1`，
  main.c 里还写了 `seq_matches` 自动核对，跑起来直接打 ✔。

- **边界**：`root == NULL` 直接 return，这是递归的地板，也是叶子节点两次空递归的来源。
- **代码**：`btree.c` 搜 `void preorder` / `void inorder` / `void postorder`。

### 2-D. 迭代版三种遍历（用本目录自带的显式栈）

- **干什么**：不用递归，自己拿数组当栈，产出和递归版一模一样的序列。
- **为什么能这么干**：递归之所以能自动回头，就是系统在帮你维护一个栈。自己写栈 = 把系统做的事搬到明面上。
- **一步步（前序）**：把 root 压栈 → 循环 { 弹一个 → 立刻访问 → **先压右、再压左** }。
  先压右是为了让左孩子待在栈顶，下一轮先弹出左，符合"先左后右"。
- **一步步（中序）**：`cur` 一路向左钻，沿途节点全入栈；钻到 NULL 就弹栈顶、访问它、`cur = cur->right`。
  第 3-C 段注释里把这棵树 8 步的栈内容变化完整列了一遍，照着走一次就会。
- **一步步（后序，双栈法）**：先造"根 → 右 → 左"（把压栈顺序对调即可），把弹出的节点丢进第二个栈，
  最后从第二个栈往外弹 —— 栈自动把顺序反过来，就得到"左 → 右 → 根"。
- **边界**：栈容量写死 `TREE_HELPER_CAP = 128`，满了会打印"栈溢出"而不是踩内存；
  `st_pop` 在栈空时返回 NULL，所有调用点都当退出信号处理。
- **代码**：`btree.c` 搜 `static int st_push` / `st_pop`（自带小栈）、
  `preorder_iter` / `inorder_iter` / `postorder_iter`。

### 2-E. 层序遍历 `level_order(root)`（用本目录自带的队列）

- **干什么**：一层一行，从左到右打印，即 BFS。
- **为什么必须是队列**：第 k 层的孩子正好是第 k+1 层，且左右顺序和父母入队顺序一致 —— 要"先发现的处理完再处理后发现的"，即先进先出。用栈立刻变成 DFS，就不是层序了。
- **一步步**：
  1. 根入队；
  2. **进循环先记 `level_size = tail - head`**（此刻队里有多少个，就是这一层有多少个）；
  3. for 循环精确处理 `level_size` 个：出队 → 打印 → 左孩子入队 → 右孩子入队；
  4. 这一轮 for 结束正好下一层全在队里，打印换行、层号 +1。
- **边界**：空树直接打印"（空树）"；`head == tail` 即队列空，退出。
  本目录的队列实现是 head/tail 只往前不回绕的数组 —— 一棵 n 个节点的树最多入队 n 次，
  所以容量够就绝不溢出（回绕复用空间是 04-queue 的主题，这里刻意不做，越简单越好）。
- **代码**：`btree.c` 搜 `static int qu_push` / `qu_pop`、`void level_order`。

### 3. 求高度 / 节点总数 / 叶子数

- **树的高度 `tree_height`**：空树 0，单根 1；公式 `1 + max(h(左), h(右))`。固定树 = 3。
- **节点总数 `tree_count`**：空树 0，否则 `1 + count(左) + count(右)`。固定树 = 6。
- **叶子数 `tree_leaf_count`**：**左右都为 NULL 才算叶子**；只有一个孩子的节点（比如 3）不算。固定树 = 3。
- **边界**：全 NULL（空树）三个函数分别返回 0/0/0；单节点树返回 1/1/1。
- **代码**：`btree.c` 搜 `int tree_height` / `tree_count` / `tree_leaf_count`。

### 4. 查找 `tree_find(root, val)`

- **干什么**：全树扫一遍找值，命中返回节点地址，没中返回 NULL。
- **一步步**：空 → NULL；自己就是要找的 → 返回自己；否则先问左、左找到了就别去右边；最后问右。
- **边界**：普通二叉树**没有顺序可剪枝，最坏 O(n)** —— 这正是下一节 BST 存在的理由。
  返回 `const Node *` 表示"我把它给你看，但别改"。
- **代码**：`btree.c` 搜 `const Node *tree_find`。

### 5. 判断平衡 `tree_is_balanced(root)`

- **干什么**：每个节点的左右子树高度差都不超过 1，才叫平衡。
- **一步步**：空树返回 1 → 算 `h(左)`、`h(右)` → 差绝对值 > 1 直接返回 0 → 否则递归要求左右子树内部各自也全都平衡。
- **边界**：只看根不够，**必须每个节点都满足**（代码里用 `&&` 短路，一发现歪的就停）。
  本实现每判一个节点都重算高度，是朴素的 O(n log n)；想 O(n) 得让递归"顺便"把高度带回来
  （用一个 `height_out` 输出参数），AVL 那一节会正式写。
- **代码**：`btree.c` 搜 `int tree_is_balanced`。

### 6. 判断两棵树相同 `tree_is_same(a, b)`

- **干什么**：形状一样 **且** 对应位置的值也一样 → 1，否则 0。
- **四种入口情况**：NULL/NULL → 1；NULL/非 NULL → 0；非 NULL/NULL → 0；都有 → 比值 + 比左 + 比右。
- **边界**：值集合相同但形状不同（`1 的左孩子 2` vs `1 的右孩子 2`）算**不同**，别只比值。
- **代码**：`btree.c` 搜 `int tree_is_same`。

### 7. 可视化打印 `print_tree(root)`（本章教学支柱）

- **干什么**：把树顺时针转 90° 打印出来，一眼看清谁是谁的孩子。

  ```
  1
  ├─2            ← 2 是 1 的左孩子
  │ ├─4          ← "│" 表示上面那条分支还没画完，竖线要继续往下延伸
  │ └─5          ← 5 是 2 的最后一个孩子，用 └；之后这根竖线消失
  └─3            ← 3 是 1 的最后一个孩子 → └
    └─6          ← 3 下面没有兄弟了，所以前缀是空格不是竖线
  ```

- **规则只有三条**：
  1. 我是父亲的最后一个孩子吗？是 → `└─`，否 → `├─`；
  2. 给"我的孩子"用的前缀 = 我的前缀 + (我是最后一个 ? `"  "` : `"│ "`)；
  3. **左孩子是否"最后一个"，取决于有没有右孩子**；右孩子永远是最后一个。
- **一步步**：一个递归函数带三个参数 `(node, prefix, is_last, is_root)`，
  先印自己这一行，再拼出 `next_prefix`，然后递归左、递归右。根不印连接符。
- **边界**：空树打印"（空树）"；前缀用 `snprintf` 写进固定大小数组，超长会被截断而不是溢出。
- **代码**：`btree.c` 搜 `static void print_tree_rec` 和 `void print_tree`。

### 8. 销毁整棵树 `free_tree(root)`（安全性重点）

- **干什么**：把 `n` 次 `malloc` 的内存 `n` 次 `free` 干净（ASan 报 0 leak）。
- **必须后序，理由**：孩子的地址就存在父亲身体里。

  ```
  ❌ 前序释放：
     free(root);              ← root 这块内存已经还给系统了，可能被别的 malloc 复用
     free_tree(root->left);   ← 这一步还要【读】root->left 才能拿到左孩子地址
                                = use-after-free（读已归还的内存）
                                后果：要么段错误，要么读到垃圾值，把子树永久漏掉
  ✅ 后序释放：
     free_tree(root->left);   ← 趁父亲还活着，先把左子树整支归还
     free_tree(root->right);  ← 再把右子树归还
     free(root);              ← 最后才扔这张写着孩子地址的"纸条"
  ```

  一句话记：**纸条上写着储物柜钥匙，得先把柜子清空，才能扔纸条。**
- **边界**：`free(NULL)` 是合法空操作，所以空树直接返回也没问题；
  调用者手里那个指向根的指针 free 完会变悬空，务必 `root = NULL`。
- **代码**：`btree.c` 搜 `void free_tree`，注释里有逐层调用展开图。

> **为什么本目录自己写了队列和栈？**
> 因为 Makefile 是按目录独立编译的，跨目录 `#include` 会直接编译失败。
> `btree.c` 顶部的 `st_push/st_pop`（只存 `const Node *` 的小栈）和
> `qu_push/qu_pop`（只存 `const Node *` 的小队列）就是为此存在的极简内部工具，
> 学完 03-stack / 04-queue 之后回头看它们，你会发现就是同一个东西的 20 行版本。

## 复杂度表

n = 节点数，h = 树高（平衡时 h ≈ log n，退化（链表状）时 h = n）。

| 操作 | 普通二叉树 | 对比：链表 | 对比：数组 | 对比：BST（下一节） |
|---|---|---|---|---|
| 按"下标"访问 | 不支持（没有顺序） | 不支持 | **O(1)** | 不支持 |
| 查找某个值 | O(n) | O(n) | O(n)（无序） | 平均 O(log n) / 最坏 O(n) |
| 插入 | 位置随意，找空位 O(n)；已知父亲 O(1) | 头插 O(1) | 尾插摊还 O(1) | O(h)，最坏 O(n) |
| 删除某个节点 | 得先找到它 O(n)，再摘掉 | 找前驱 O(n) | 挪动 O(n) | O(h)，最坏 O(n) |
| 遍历全部节点 | O(n)（四种都是） | O(n) | O(n) | O(n)，中序即升序 |
| 求高度 / 计数 | O(n) | —（无"高度"概念） | — | O(n) |
| 额外空间（迭代/递归） | O(h)（栈或队列） | O(1) | O(1) | O(h) |
| 层序遍历的空间 | O(最宽一层的节点数)，最坏 O(n) | — | — | — |
| 销毁整棵树 | O(n)，**必须后序** | O(n) | O(1)（一次 free） | O(n) |

**一句话总结**：普通二叉树不为了"快"，是为了**把"用指针组织的递归结构"这件事讲清楚**。
加了顺序规矩 → BST；再加自动平衡 → AVL/红黑；换成完全二叉树塞进数组 → 堆。

## 常见的坑

1. **`node->left` 没初始化就接线**
   `malloc` 回来的是垃圾值，不显式写 NULL 的话，它"看起来有个左孩子"，
   第一次遍历就段错误。**永远在 `node_new` 里把 left/right 写成 NULL。**

2. **递归忘了写 `if (root == NULL) return;`**
   空树也是树！没有这一句，就会去读 `NULL->val` → 段错误。
   写树函数的手序永远是：先判空、再处理自己、再递归左右。

3. **把"叶子"和"只有一个孩子的节点"搞混**
   固定树里的节点 3 只有右孩子，它**不是叶子**。
   叶子的严格定义是 `left == NULL && right == NULL`，数叶子时先判这个再递归。

4. **前序/中序/后序背成"先左还是先右"**
   三种顺序里**左永远在右前面**，换的只是"自己"的位置。
   背错导致写出的 `inorder` 和 `preorder` 一模一样，还不报错 —— 只能靠打印发现。

5. **销毁用前序 → use-after-free**
   `free(root); free_tree(root->left);` 是在读已归还的内存。
   后果不一定当场崩，可能"看起来跑对了但漏了几百字节"。
   `make asan` 能当场抓出来，所以每写完一个结构就跑一遍。

6. **`free` 完不把自己手里的指针置 NULL**
   `root` 还在，值还是那个地址，但已经是野指针；后面误用一次就崩。
   养成 `free_tree(root); root = NULL;` 两行连着写的习惯。

7. **迭代版里压栈顺序写反**
   前序要"先压右再压左"（栈后进先出，才能让左先出）；
   后序的双栈法要"先压左再压右"。顺序写反不报错，只是输出不对 ——
   这就是 main.c 里非要把递归版和迭代版逐位比对的原因。

8. **拿普通二叉树当"查找结构"用**
   无序 → 查找只能 O(n)。想快就得要么先排序（→BST），要么换哈希表。

## 什么时候用它 / 什么时候别用

**适合用：**
- 数据本身就是层级关系：目录树、组织架构、XML/HTML DOM、菜单。
- 表达式 / 语法解析：`a + b * c` 画成树之后，求值就是后序遍历，改写形式就是换一种遍历。
- 需要"每个节点最多两个分支"的决策流程（是/否二叉判定树）。
- 当作学习载体：练指针、练递归、练"结构 + 指针"的心智模型。

**别用：**
- 要按键值快速查 → 用 **BST / AVL / 红黑树 / 哈希表**；无序二叉树查找是 O(n)。
- 要频繁按下标访问 → 用 **数组**（O(1)）；树不支持随机访问。
- 数据是"一个父亲很多孩子"（文件系统实际形态）→ 用**多叉树 / 邻接表**，硬塞进二叉树要写成"左孩子-右兄弟"，绕。
- 只要"最大/最小值随时取" → 用**堆**，比二叉树简单且没有指针开销。
- 磁盘/数据库场景 → 用 **B 树**：二叉树太"瘦高"，一次 IO 只读回 1 个节点，太亏。

## 自检问题

1. **一棵有 n 个节点的二叉树，一共有多少个"空指针位"（NULL 的 left/right）？为什么？**
   **答：n + 1 个。** n 个节点共有 2n 张纸条，其中被用掉的是"连孩子的纸条" = n - 1 条
   （除根以外每个节点恰好被一根纸条指到），所以剩 2n - (n - 1) = n + 1 张空白。
   这就是第 2 幕那段 13 个数的序列里为什么有 7 个 `-1`（6 个节点 + 1）。

2. **已知前序 `1 2 4 5 3 6`，能唯一还原出树形吗？那已知"前序 + 中序"呢？**
   **答：单靠前序不能** —— 它只告诉你"谁先被访问"，不告诉你 4 是 2 的左孩子还是右孩子。
   加上中序就能：前序第一个是根 `1`，在中序里 `1` 左边的 `4 2 5` 全在左子树、右边的 `3 6` 全在右子树，
   然后对两个部分递归地重复同样的切分。"前序 + 中序"或"后序 + 中序"都可以，
   但"前序 + 后序"不行（分不出只有一个孩子的情况）。所以本节建树序列要带空标记。

3. **为什么层序遍历不能用栈代替队列？**
   **答：** 层序要求"先把第 k 层从左到右处理完，才能开始第 k+1 层"，这是先进先出。
   栈会把最后入队的孩子立刻弹出来 —— 那就变成了深度优先（沿着一条路钻到底），输出顺序就错了。

4. **`free_tree` 为什么必须后序？前序会发生什么？**
   **答：** 左右孩子的地址存在父节点里。前序先 `free(父)`，紧接着要读 `父->left` 才能递归删左子树 ——
   这是读已归还的内存（use-after-free）。值可能被覆盖成垃圾，导致子树被永久漏掉或当场崩溃。
   后序先把两个孩子各自处理干净，最后才扔父节点，永远在读自己还活着的时候读。

5. **本节代码里的队列和栈为什么不 `#include 04-queue` 的文件？**
   **答：** 每个叶子目录独立编译（Makefile 只把这个目录下的 `.c` 一起编译），
   跨目录 include 会找不到文件 / 找不到实现而编译失败。所以本目录内自带只存 `Node *` 的 20 行小工具，
   反而更贴合"只放需要的能力"的教学目的。

6. **一棵树高度等于节点数，说明什么？**
   **答：** 它退化成了一条链表（每个节点最多只有一个孩子）。
   此时查找/插入的 O(h) 就是 O(n)，平衡性完全丧失。第 8 幕那棵右斜树就是这个样子。
