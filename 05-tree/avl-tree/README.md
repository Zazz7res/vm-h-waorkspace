# AVL 树 avl-tree

> 给二叉搜索树装一根"高度尺"：每插一个节点就从下往上量一遍，左右差到 2 就当场旋转压回去 —— 树高被死死钉在 `1.44·log2(n+2)`，从此再有序的数据也压不垮它。

## 一句话是什么

**AVL = BST + 每个节点的左右子树高度差最多 1。**

差值有个名字叫**平衡因子**（balance factor，代码里写 `bf`）：

```
bf(节点) = 左子树高度 - 右子树高度        ← 本项目的符号约定：左重为正

允许的取值只有三个： -1 / 0 / +1
出现 +2 或 -2      ：这里"塌了"，必须旋转才能继续当 AVL 树
```

三种树放在一起看同一批数据（`1 2 3 4 5 6 7 8` 顺序插入）：

```
   裸 BST（05-tree/bst/）        AVL（本目录）           完全平衡树
   1                              4(h=4,bf=-1)           4
    └─R 2                       ┌──┴──┐                ┌───┴───┐
       └─R 3                   2      6(h=3,bf=-1)     2       6
          └─R 4               ┌┴┐   ┌─┴─┐             ┌┴┐     ┌┴┐
             └─R 5            1   3  5   7(h=2,bf=-1)  1 3   5 7
                └─R 6                     └─R 8          └─R 8
                   └─R 7
                      └─R 8
   高度 = 8（一条链）            高度 = 4                高度 = 4
   查 8 比 8 次                 查 8 比 4 次            查 8 比 4 次
```

**本目录就是把这个差别做成可以一行一行看清的实验**：第 1 幕并排对比、第 2 幕把四种旋转单独开刀、
第 3 幕让插入自动触发它们、第 5 幕看删除怎么把祖先压塌、第 6 幕灌 32 个数验证高度贴着 `log n`。

## 为什么需要它

**BST 的致命伤（`05-tree/bst/` 第 7 幕已经现场制造过）**：树形由插入顺序决定。
真实数据里"按顺序到达"是常态而不是意外 —— 自增 ID、时间戳、排好序的日志、增量同步的 diff。
裸 BST 遇到这批数据就退化成链表，查找、插入、删除全部从 `O(log n)` 掉回 `O(n)`。

| 做法 | 查找（最坏） | 插入（最坏） | 删除（最坏） | 代价 |
|---|---|---|---|---|
| 裸 BST | **O(n)** | **O(n)** | **O(n)** | 代码最简单，但没人保证数据不乱序 |
| 打乱顺序再插 BST | O(log n) 概率高 | 同左 | 同左 | "打乱"这件事本身要额外成本，而且只是概率上侥幸 |
| 跳表（`02-linked-list/skip-list/`） | O(log n) 期望 | O(log n) 期望 | O(log n) 期望 | 随机化保平衡，**最坏仍是 O(n)**，只是概率极低 |
| **AVL 树** | **O(log n) 保证** | O(log n) | O(log n) | 节点多存 1 个 `int height`；写对旋转要费点劲 |
| 红黑树（`05-tree/red-black-tree/`） | O(log n) 保证 | O(log n) | O(log n) | 只存 1 bit 颜色；平衡没那么严格，查询略慢于 AVL |

AVL 的取舍非常明确：**用最严的平衡条件（`|bf| <= 1`）换最矮的树**。
树矮 ⇒ 查找快，这是 AVL 相对红黑树的唯一硬优势；
代价是一旦失衡就必须真的旋转，所以**写入密集的场合反而不划算**（详见"AVL vs 红黑"一节）。

**本目录实测到的数字**（都是运行结果里的原话）：

```
8 个顺序数据：裸 BST 高 8 ；AVL 高 4
32 个顺序数据：裸 BST 高 32（彻底一条链）；AVL 高 6，且 avl_is_valid() 仍然通过
32 个乱序数据：AVL 高 6，理论上限 1.44·log2(34) ≈ 7.7，实际没顶到
找最大值 32：AVL 往下走 6 步；同一批数据喂裸 BST 要走 32 步
```

## 内存布局图解

### 1. 节点比 BST 多了一个 `height`

```
   ┌──────────┬────────┬────────┬──────────┐
p ─▶│ value    │ left   │ right  │ height   │
   └──────────┴───┬────┴───┬────┴──────────┘
                  │        │        └── 以【我自己】为根的子树高度：空 = 0，叶子 = 1
             左子树     右子树        ← 这个字段就是 AVL 的"高度尺"
             (都 < value) (都 > value)
```

对应 `avl.h`：

```c
typedef struct AVLNode {
    int             value;   /* 存的元素：本项目约定全部是 int，不搞 void* 泛型 */
    struct AVLNode *left;
    struct AVLNode *right;
    int             height;  /* 以我自己为根的子树高度：空 = 0，叶子 = 1 */
} AVLNode;
```

### 2. 为什么必须存 `height`，而不是每次现算

| | 不存（现算） | 存（本实现） |
|---|---|---|
| 读一个节点的高度 | 递归下去 ⇒ **O(n)** | 读字段 ⇒ **O(1)** |
| 一次插入要检查 O(log n) 个祖先 | O(n)·O(log n) ⇒ **退化成 O(n log n)** | **O(log n)** |
| 换到的东西 | 省 4 字节 | 4 字节换回整棵树的复杂度保证 |

这就是典型的"用 4 字节空间换时间"。还有半句很关键：**存的必须是子树高度，不能存深度**。
深度从根往下数，插一个节点要改一整片的深度；高度只依赖亲孩子，
`h = 1 + max(h(左), h(右))`，递归回头那一行改一次就够。

### 3. 打印出来到底长什么样（屏幕上真实输出）

`avl_print_tree()` 每个节点写成 `8(h=4,bf=1)`：`h` = 存的高度，`bf` = 现算的平衡因子。

```
15(h=6,bf=0)
   ├─L 6(h=5,bf=-1)
   │  ├─L 3(h=3,bf=0)
   │  │  ├─L 2(h=2,bf=1)
   │  │  │  └─L 1(h=1,bf=0)
   │  │  └─R 5(h=2,bf=1)
   │  │     └─L 4(h=1,bf=0)
   │  └─R 11(h=4,bf=1)
   ...
```

读这张图的正确姿势：
- 任意一行，把它的两个孩子（`├─L` / `└─R`）的 `h` 相减，应当等于这一行自己的 `bf`；
- 任何一行的 `|bf|` 都不许超过 1 —— 超了就是实现写错了，`avl_is_valid()` 会当场指出来；
- 任何一行的 `h` 应当等于 `1 + max(孩子 h)`，叶子永远是 `h=1`。

## 核心操作逐个拆解

代码分成 8 组，顺序就是"由小到大、由静到动"：

| 组 | 内容 |
|---|---|
| 第 1 组 | `avl_height` / `avl_balance` / `avl_update_height` / `avl_count` |
| 第 2 组 | 树形打印（内部递归 + `avl_print_tree`） |
| 第 3 组 | `avl_new` 造节点 |
| 第 4 组 | **四种旋转**，每个都是独立函数 |
| 第 5 组 | `avl_rebalance`：该用哪一种旋转的"裁判" |
| 第 6 组 | `avl_insert` |
| 第 7 组 | `avl_remove` |
| 第 8 组 | `avl_search` / `avl_print_inorder` / `avl_is_valid` / `avl_destroy` |

### 1. 三个小工具

```c
int  avl_height(const AVLNode *node);          /* NULL 返回 0 */
int  avl_balance(const AVLNode *node);         /* h(左) - h(右)，NULL 返回 0 */
void avl_update_height(AVLNode *node);         /* h = 1 + max(avl_height(左), avl_height(右)) */
```

`avl_height(NULL) == 0` 这条约定非常重要：它让"空树高度 0"只在**一个地方**定义，
上层代码从此不用写 `node ? node->height : 0` 这种三连。
`avl_balance(NULL) == 0` 同理 —— 空树是平衡的。

### 2. 四种旋转：为什么刚好是四种

一个节点失衡，必然是"某一侧被压高了 2"。压高的路径进去还有两条分支，2 × 2 = 4：

| 名字 | 谁的哪一侧变高了 | 怎么治 | 旋转函数 |
|---|---|---|---|
| **LL** | 失衡点的**左孩子的左边** | 一次**右旋** | `avl_rotate_right` |
| **RR** | 失衡点的**右孩子的右边** | 一次**左旋** | `avl_rotate_left` |
| **LR** | 失衡点的**左孩子的右边** | 先左旋左孩子（掰成 LL）→ 再右旋 | `avl_rotate_lr` |
| **RL** | 失衡点的**右孩子的左边** | 先右旋右孩子（掰成 RR）→ 再左旋 | `avl_rotate_rl` |

记法：**第一个字母 = 从失衡点第一步往哪边走，第二个字母 = 第二步往哪边走。**
名字里带 L 结尾（LL/LR）的失衡点在左边（`bf = +2`），带 R 开头的（RR/RL）在右边（`bf = -2`）。

#### 右旋（治 LL）

```
        y                             x
       / \                           /   \
      x   C     右旋 y        →     A     y
     / \                                / \
    A   B                              B   C
```

- `x` 上位当根，`y` 降级成 `x` 的右孩子；
- `x` 原来的右孩子 `B`"改嫁"给 `y` 当左孩子 —— 因为大小关系是 `A < x < B < y < C`，
  `B` 比 `y` 小、比 `x` 大，挂 `x` 右边或 `y` 左边都合法，而 `x` 的右边给了 `y`，所以 `B` 只能去 `y` 左边。

```c
AVLNode *x = y->left;      /* 要上位的左孩子 */
AVLNode *b = x->right;     /* 唯一需要搬家的那棵子树，先存住 */
x->right = y;              /* 上位 */
y->left  = b;              /* 改嫁 */
avl_update_height(y);      /* ★ 先下后上：y 的高度先对，x 才能算对 */
avl_update_height(x);
return x;                  /* 新根交回调用者 */
```

#### 左旋（治 RR）—— 右旋的镜像

```
      x                                  y
     / \        左旋 x           →     /   \
    A   y                            x     C
       / \                          / \
      B   C                        A   B
```

#### LR 双旋：为什么不能一步到位

```
        y                            y
       / \     直接右旋 y      →    ┌─┐ \
      x   C                          x  C    ← 形状更难看，x 还多了一条右腿
       \                              \
        B                              B
```

`B` 挂在 `x` 的**右边**，直接右旋后 `B` 会跟着 `x` 一起跑到 `y` 的左子树里，压不下去。
所以先给左孩子 `x` 来一次**左旋**，把"拐着"的形状掰直成标准 LL，再右旋：

```
     y                           y                          B
    / \   先左旋 x（左子树）     / \      再右旋 y         / \
   x   C           →           B   C          →         x   y
    \                          /                          \
     B                        x                            C
```

代码就两行，全部复用单旋：

```c
y->left = avl_rotate_left(y->left);   /* 第一步：把左子树掰成 LL 形状 */
return avl_rotate_right(y);           /* 第二步：整体右旋 */
```

RL 是 LR 的镜像：`x->right = avl_rotate_right(x->right); return avl_rotate_left(x);`

#### ★ 全章第一大坑：旋转函数返回的是【新根】

旋转之后根换人了（`y` 变成 `x` 的孩子）。父节点手里攥着的还是老地址，
不接返回值 = 整棵子树跟树断连，节点没 free 但再也到不了（内存泄漏 + 数据丢失）。
所以**永远**写成：

```c
root       = avl_rotate_right(root);
root->left = avl_rotate_left(root->left);   /* 子树同理：谁的位置被换，就接回谁 */
```

### 3. `avl_rebalance`：该用哪种旋转的裁判

```c
static AVLNode *avl_rebalance(AVLNode *root);   /* 输入：已更新高度的子树根；输出：修好的子树根 */
```

判断只看两个数字：失衡点自己的 `bf`，和**高那一侧孩子**的 `bf`。

```
bf > +1（左重）  ：左孩子 bf >= 0 → LL → 右旋；左孩子 bf < 0 → LR → 双旋
bf < -1（右重）  ：右孩子 bf <= 0 → RR → 左旋；右孩子 bf > 0 → RL → 双旋
|bf| <= 1        ：原样返回（最常见的分支）
```

**为什么不用"刚插入的值 v 和谁比"来判断？**
因为删除时根本没有 `v` 可参考；而且重复值被忽略时也会误判。
用孩子的 `bf` 符号判断，插入和删除能共用同一段裁判代码 —— 这是本实现里最值得学的一个设计决定。
孩子的 `bf == 0` 只可能出现在删除场景（本实现把它归到单旋那一档，够用）。

### 4. 插入 `avl_insert`

三步全在递归的"回头路"上做：

```
① 按 BST 规矩递归找到空位挂新节点（avl_new 出来的节点 height 已经是 1）
② 回头路上先更新我的高度（此时孩子的高度已经是最新的）
③ 再让 avl_rebalance 检查我，把（可能换了人的）新根返回给上一层
```

以"往 `30(左:10)` 里插 20"为例，调用栈展开：

```
insert(30)
  ├ 30 > 20 → 去左边：insert(10)
  │            ├ 10 < 20 → 去右边：insert(NULL) → 造出节点 20
  │            ├ 更新 10 的高度 → h=2
  │            └ 10 的 bf = 0 - 1 = -1，不塌，返回 10
  ├ root->left = 10            ← 返回值必须接回去！
  ├ 更新 30 的高度 → h=3
  └ 30 的 bf = 2 - 0 = +2，左孩子 bf = -1 → LR → 双旋 → 新根是 20
```

**为什么"每层只检查自己这一个节点"就够？**
插入只让一条"叶子→根"的路径变高，别的分支高度没变，本来合法的节点不会突然失衡。
所以**一次插入整棵树最多只有一个节点需要旋转**（最多 2 次旋转动作，即双旋），
而且转完这一支的高度就恢复成插入前的高度，往上不必再动。
（删除完全相反，见下一节。）

重复值策略：`value == root->value` 时**忽略**，返回原根 —— 树里没有重复元素，删除逻辑也更干净。

### 5. 删除 `avl_remove`（比插入麻烦，麻烦在哪要讲清）

第一步和裸 BST 一模一样，三种情况：

| 情况 | 做法 | 为什么合法 |
|---|---|---|
| (a) 叶子 | `free` 掉，自己的位置变 NULL | 没有子树要安置 |
| (b) 只有一个孩子 | 孩子提上来顶替自己，`free` 自己 | 那棵子树整个比我大（或都比我小），提到父亲位置后大小关系照样成立 |
| (c) 两个孩子 | 找**后继** = 右子树最小，把它的**值**抄进我这边，再去右子树里删掉那个后继 | 后继一定没有左孩子，所以递归下去必然落到 (a) 或 (b)，最多两层就终止 |

```
       10
      /  \      删 10（双孩子）：右子树最小 = 15 → 后继
     5    15    把 15 的值抄到根，再去右子树删掉"值为 15 的那个节点"
         / \              ↓
        12  20          15（15 原来的位置被它的右孩子 20 顶掉）
                       /  \
                      12   20
```

第二步才是 AVL 的事：回头路上 `avl_update_height` + `avl_rebalance`。

**★ 插入和删除在这里的本质区别（第 5 幕 (d) 现场演示）**：
"变矮"和"变高"一样能造成 `|bf| = 2`，但旋转后这一支的高度可能比原来**更矮**，
于是爸爸又可能失衡 ⇒ **删除必须把一路上每个祖先都检查一遍，最坏 O(log n) 次旋转**。
插入最多修一处，删除一路都可能要修 —— 这也是 AVL 在写入密集场合输给红黑树的根本原因。

单孩子分支里有个小防御动作值得学：

```c
root->left = NULL;      /* 顶替前先把被弃用的腿置 NULL */
root->right = NULL;
free(root);
return child;           /* free(NULL) 是合法空操作，这样万一将来代码写错也不会 double free */
```

### 6. 校验 `avl_is_valid`：给自己的"作弊检测器"

```c
int avl_is_valid(const AVLNode *root);   /* 1 = 合法，0 = 有问题（并把坏在哪个节点打出来） */
```

它递归检查两件事，缺一不可：

1. **每个节点 `|bf| <= 1`** —— AVL 的定义本身；
2. **存的 `height` 和按孩子重算出来的高度一致** —— 专抓"旋转/删除后忘了 `avl_update_height`"。

第 2 条特别容易被忽略却最要命：`height` 陈旧时 `bf` 是用假数字算的，
树可能已经塌了却"看起来"合法。每次操作后调一次，实现错误绝对藏不住。

### 7. `mini_bst.c`：本目录自带的反面教材

叶子目录必须自包含（Makefile 按目录独立编译，跨目录 include 编不过），
所以这里不引用 `05-tree/bst/`，而是自己写了个最小版：只有插入、现算高度、比较次数、中序、打印、销毁。

```c
typedef struct MiniBSTNode {
    int value; struct MiniBSTNode *left, *right;
    /* 注意：这里【没有】 height —— 算高度只能每次现递归 */
} MiniBSTNode;
int mini_bst_compare_count(const MiniBSTNode *root, int value);  /* 找 value 比了几次 */
```

它和 AVL 的唯一区别就是"没有 height、插完什么都不检查"。
就这一个小改动，喂 `1..8` 会高 8，AVL 高 4 —— 两棵树并排打出来，就是 AVL 存在的全部理由。

## 复杂度表

设 `n` = 节点数。AVL 的定义直接给出高度上界：

```
h(n) <= 1.44 · log2(n + 2)        （严格常数 ≈ 1.4404，来自斐波那契式的最"瘦"AVL 树）
```

| 操作 | 平均 | 最坏 | 为什么 |
|---|---|---|---|
| 查找 `avl_search` | O(log n) | **O(log n) 保证** | 树高被钉死，每步扔掉一半 |
| 插入 `avl_insert` | O(log n) | O(log n) | 下降 O(log n) + 回头检查 O(log n) + **最多 2 次旋转** |
| 删除 `avl_remove` | O(log n) | O(log n) | 下降 + **最多 O(log n) 次旋转** |
| 求最大/最小 | O(log n) | O(log n) | 一路往右/左走到底 = 树高 |
| 中序遍历 | O(n) | O(n) | 每个节点访问一次 |
| 读某个节点高度 | **O(1)** | **O(1)** | `height` 字段存在节点里（裸 BST 要 O(n) 现算） |
| `avl_is_valid` | O(n) | O(n) | 全树扫一遍（自检用，不在热路径上） |
| 空间 | O(n) | O(n) | 每节点比 BST 多 1 个 `int` |
| 递归栈 | O(log n) | O(log n) | 因为平衡，栈深 = 树高，不会爆到 O(n) |

> 最后一行是裸 BST 拿不到的好处：n 很大且退化时，裸 BST 的递归会**栈溢出**，AVL 永远只占 O(log n) 栈。

## 常见的坑

1. **忘了接旋转的返回值**
   写了 `avl_rotate_right(root);` 而不是 `root = avl_rotate_right(root);`。
   编译不报错、树"看起来"还在，但新根已经和树断连：查不到的节点全在泄漏的内存里。
   **AVL 第一大坑，没有之一。**

2. **高度更新顺序写成"先上后下"**
   必须 `avl_update_height(下面的那个)` 再算上面的。反过来时上面用到了旧高度，
   `bf` 就跟着错，接下来该不该旋转全判错。`avl_is_valid()` 第 2 项检查就是专门抓这个的。

3. **把 `height` 和 `depth` 搞混**
   `height` 只依赖亲孩子（局部可更新），`depth` 依赖到根的路径（一改一大片）。
   存深度 = 每次插入要更新一整条路径，白折腾。

4. **空树高度约定不统一**
   有的资料约定"空 = -1，叶子 = 0"。本实现约定 **空 = 0，叶子 = 1**，`avl_height(NULL)` 返回 0。
   两套约定混用（比如抄了别处的 `1 + max(...)` 却用另一套约定）会让 `bf` 永远偏 1，
   表现是"明明平衡却一直旋转"。

5. **用"刚插入的值 v"判断 LL/LR**
   `if (v < root->left->value)` 这种写法在插入时勉强对，删除时直接失效（没有 v），
   重复值被忽略时也会误判。正确做法是看**孩子的 bf 符号**，见 `avl_rebalance`。

6. **以为"插入后整棵树要挨个检查一遍"**
   一次插入最多只有**一个**节点需要旋转（祖先们的高度已经恢复原值）。
   反过来说删除就不行：删除要一路检查到根，最坏 O(log n) 次旋转。

7. **`avl_destroy` 之后再碰那个指针**
   `destroy` 是后序释放，函数返回后传进去的 `root` 已经是野指针。
   `main.c` 里每次销毁后都写了 `tree = NULL;` —— 照抄这个习惯。

8. **以为 AVL 里可以放重复值**
   本实现在插入处明确"相等就忽略"。要支持重复，得把 `value` 换成 `key + 计数`，
   删除时先减计数、减到 0 才真删 —— 那是另一套代码，别在没改的情况下塞重复值。

## AVL vs 红黑树：为什么这里选 AVL

（完整的"三分钟决策表"在 `05-tree/red-black-tree/README.md`，这里只摆 AVL 的立场。）

| 维度 | AVL | 红黑树 |
|---|---|---|
| 平衡条件 | 每个节点 `|bf| <= 1`（严格） | 最长路径 <= 2 × 最短路径（大致） |
| 树高上界 | **1.44·log2(n+2)** | 2·log2(n+1) |
| 同规模实测 | 第 6 幕：n=32 时高 6（上限 7.7） | 第 7 幕：n=52 时高 7（上限 12） |
| 每节点额外字段 | `int height`（4 字节） | 1 bit 颜色（常和指针挤在同一字里） |
| 插入旋转 | 最多 2 次 | 最多 2 次 |
| 删除旋转 | **最多 O(log n) 次** | **最多 3 次** |
| 查找 | **更快**（树更矮，比较次数少） | 稍慢 |
| 典型使用者 | 内存数据库索引、只读/查多写少的字典 | `std::map`、`TreeMap`、内核 CFS、epoll |

一句话：**读多写少走 AVL，写多读少走红黑。**
本项目里两个目录都完整实现了，可以拿同一批数据两边跑，亲眼看树高和旋转次数的差别。

## 什么时候用它 / 什么时候别用

**适合用 AVL：**
- 需要**最坏情况也保证** O(log n) 的有序集合 —— 裸 BST 给不了这个保证。
- 查询远多于插入/删除：更大的查找量、只读或低频写的字典、索引、命名空间表。
- 对**树高敏感**的场景：每层一次磁盘/网络往返时，矮一层就少一次往返（虽然真做磁盘索引更该上 B 树）。
- 递归栈深必须可控：AVL 保证栈深 O(log n)，裸 BST 退化时会栈溢出。

**别用 AVL：**
- 增删非常频繁（写多读少）：删除要 O(log n) 次旋转，红黑树只用 ≤3 次，工程上通常更划算。
- 只要"按 key 取值"、完全不在乎顺序 → **哈希表**，O(1) 且代码量小一个数量级。
- 数据基本静态、只有查询 → **有序数组 + 二分**，缓存友好，实测常常比指针树快。
- 只关心最大/最小 → **堆**（`06-heap/`），数组存储、没有指针开销。
- 不想手写旋转、能接受随机化 → **跳表**（`02-linked-list/skip-list/`）。
- 数据在硬盘上、一页能装几十个键 → **B 树 / B+ 树**（`05-tree/b-tree/`）。

## 自检问题

1. **`bf = 左高 - 右高`。bf = +2 时为什么第一反应是"往左看"，还要再看第二眼？**
   **答：** `+2` 只说明"左边被压高了 2 层"，但压高的路径有两条：左孩子的**左边**（LL）
   或左孩子的**右边**（LR）。前者一次右旋就够，后者直接右旋转不动（`B` 会跟着 `x` 一起跑），
   必须先左旋左孩子掰直。第二眼看的就是"左孩子的 bf 符号"。

2. **为什么一次插入最多只需要旋转一处，而删除可能要旋转 O(log n) 次？**
   **答：** 插入让一条叶子→根的路径**变高**，第一次旋转后这一支的高度恢复成插入前的值，
   祖先看到的子树高度没变 ⇒ 祖先不可能因此新失衡。
   删除让路径**变矮**，旋转后这一支可能比删除前更矮，于是爸爸的高度视图变了、
   爸爸可能失衡，只能一路上去逐个检查。

3. **`avl_rotate_right(y)` 里为什么 `b = x->right` 必须先存进局部变量？**
   **答：** 紧接着要写 `y->left = b`，而 `y->left` 此刻正是 `x`；先写 `y->left = x->right`
   这种"看起来等价"的形式，一旦顺序稍错就会把 `x` 的地址覆盖掉、整棵左子树丢失。
   先把唯一要搬家的子树存住，再动手改指针，是所有旋转的通用套路。

4. **为什么旋转一定要"先 `update_height(y)` 再 `update_height(x)`"？**
   **答：** 旋转后 `y` 是 `x` 的孩子。`x` 的新高度 = `1 + max(h(左), h(y))`，
   要用到 `y` 的**新**高度。先算下面那个，上面那个才算得对 —— 自底向上。

5. **`height` 存成"陈旧值"会发生什么？怎么抓住它？**
   **答：** `avl_balance` 用的是 `height`，`bf` 就跟着错：可能该转的不转（树悄悄退化），
   也可能不该转的乱转。`avl_is_valid()` 的第二项检查专门把"存的 height"和
   "按孩子现算的 height"对比，不一致就报在哪个节点。

6. **同一批 1..32 顺序数据，AVL 高 6，完全平衡树高 5。为什么不做到 5？**
   **答：** AVL 只要求 `|bf| <= 1`，不要求"完全平衡"。高 5 的满树只有 31 个节点位（`2^5 - 1`），
   32 个节点必须到第 6 层。`1.44·log2(n+2) ≈ 7.7` 是最坏上界，实际这棵树只用到 6 层 —— 
   "允许比满树胖一点，但绝不变链"就是 AVL 的定位。

7. **为什么本实现判 LL/LR 时把"孩子 bf == 0"归到单旋那一档？**
   **答：** 孩子 bf 为 0 只可能来自删除（插入造成的失衡里孩子 bf 不会是 0）。
   此时 LL 单旋即可恢复平衡，双旋反而多余。这是删除路径上常见的边界情况。

8. **AVL 相比红黑树查找更快，代价花在哪？**
   **答：** 平衡条件更严 ⇒ 树更矮 ⇒ 但每次操作更"贵"：删除最坏要 O(log n) 次旋转，
   而红黑树删除 ≤3 次旋转（靠变色把冲突往上推）。读多写少走 AVL，写多读少走红黑。
